## Repair Review Fixes

Post-implementation review found artifact-layer issues, not rating-math issues.
The branch was repaired before merge:

- `tests/game/benchmarkRatingComparisonArtifacts.test.ts` had an undefined
  `bundle` variable in the absolute-path safety test. The test now builds a
  real comparison bundle and the snapshot bundle test asserts `report.md`
  content is preserved.
- `ledger.json` initially preserved stale snapshot hashes and used an empty
  `reportMdHash`. The comparison CLI now upserts snapshot entries with hashes
  read from the actual `ratings.json` and `report.md` files, then writes a
  deterministic sorted ledger.
- `readSnapshotInfo` now reads and hashes `report.md`, and snapshot bundles
  preserve report markdown instead of writing an empty report.
- `runComparisonPipeline` now delegates comparison construction to the pure
  `compareRatingOutputs(...)` helper instead of duplicating comparison logic in
  the artifact layer.
- The CLI now auto-creates the named `cFp46` snapshot from `ratings/latest`
  when that baseline snapshot is missing. Other missing snapshot names still
  fail with a clear usage error.

After repair, both suite ledgers contain the correct non-empty `ratingsJsonHash`
and `reportMdHash` values for `cFp46` and `latest`, and both
`cFp46-vs-latest` comparison artifacts still contain 22 common entries with
zero deltas and `signal: "no_change"`.

## Risks/Follow-ups

- The CLI script uses `tsx` which may have known spawn issues on some Windows
  platforms. The spec already notes this; the npm scripts use `tsx` and tests
  avoid spawning `tsx` directly.
- Future phases that update ratings (e.g. re-running benchmarks) will need to
  invoke the comparison pipeline to generate a new snapshot and recompute
  deltas. The ledger will accumulate snapshots incrementally.
