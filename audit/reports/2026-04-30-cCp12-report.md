# Cluster C Phase 12 Report — Linked Ability Invariant Audit And Regression Coverage

This phase is an audit plus regression-coverage phase per `docs/spec/2026-04-30-cCp12-specs.md`. No production engine, catalog, UI, AI, simulation, or route behavior was changed. The cCp12 work is limited to new tests, this report, and a `docs/PROJECT_STATE.md` update.

## 1. Executive Summary

cCp12 hardens the catalog/engine boundary for every card effect that depends on `linkedSourceIds`, generated side-deck cards, or directional summon groups. The earlier cCp10 audit confirmed the general `linkedSourceIds` mechanism, but missed the reverse Gaunter case (`Gaunter O'Dimm: Darkness` could pull base Gaunter via name-prefix matching in the legacy helper). Commits `b195da7` and `59ceacf` fixed the live bug; cCp12 now adds active invariant suites so the same class of error cannot regress silently.

### Findings summary

- **0 P0 / P1 issues.** Every active preset's linked effect resolves to the right card in the right zone.
- **0 P2 issues.** All known directional cases are covered by active assertions.
- **3 P3 documentation/coverage notes** (Arachas Behemoth ambiguous symmetry, Light Longship deferred Muster group, planned `summon` resolver) recorded as `it.todo` placeholders rather than active failing tests.

## 10. Reporting Notes

- **Why cCp10 missed Gaunter/Darkness.** cCp10 audited the engine resolver (`linkedSourceIds`-driven) and noted it pulled correctly for Crones, Vampires, Arachas, etc. It did not separately audit the **legacy** `findMusterCards` helper in `src/hooks/useGameLogic.ts`, which uses **name-prefix matching** (`candidate.name.startsWith(\`${card.name}:\`)`). That code path silently pulled base Gaunter when Darkness was played, because Darkness's name is a prefix of nothing — but the inverse case worked. The catalog audit also did not enumerate the explicit reverse expectation `Darkness → Darkness only`, so the asymmetric bug stayed hidden until product testing uncovered it.
- **How cCp12 prevents the recurrence.** Three layers: (a) catalog invariants explicitly assert `gaunter-odimm-darkness.linkedSourceIds === ["gaunter-odimm-darkness"]` and never contains base Gaunter; (b) engine regressions explicitly play Darkness and assert base Gaunter remains in hand; (c) legacy regressions extend to multi-base scenarios. Any future change that re-introduces the asymmetric pull will fail at least one of the three layers before reaching production.
- **Linked groups whose directionality remains ambiguous.** `monsters.arachas-behemoth` reciprocal pull (one-way today; full symmetry deferred to product confirmation).
- **Legacy Muster helper limitations.** The legacy helper still uses name-prefix matching and does not consume `linkedSourceIds`, so it cannot represent catalog-specific groups beyond name variants (Crones, Vampires, etc., are name-only groups and happen to work). The pure engine path uses `linkedSourceIds` exclusively; the cCp12 report does not expand the legacy helper into a catalog resolver — that scope belongs to a separate spec.
- **Side-deck-only orphans.** None.
- **Active presets with insufficient copies to exercise a linked effect.** None for forward Gaunter, Cerys, Crones, Avenger, or Berserker. `muster_roach` cases (Geralt/Cirilla) lack Roach in active presets, so the visible pull is always empty in real matches. Light Longship's deferred Muster also no-ops in the official Skellige starter.
- **Tests intentionally `todo`.** Three: Arachas Behemoth full symmetry, `summon` resolver, placeholder leader tutor/restore effects.
