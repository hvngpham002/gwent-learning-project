# Cluster C Phase 13 Report — Linked Muster Cleanup And Starter Visibility

This phase resolves the three confirmed low-severity follow-ups recorded in cCp12 without broadening into a general ability implementation phase. It implements `docs/spec/2026-05-01-cCp13-specs.md`.

## 1. Executive Summary

cCp12 found no `P0`/`P1`/`P2` issues but surfaced four player-visible or documentation-risk gaps:

- `skellige.light-longship` printed `muster` with empty `linkedSourceIds`, so it no-opped in the official Skellige starter.
- `neutral.geralt-of-rivia` and `neutral.cirilla-fiona-elen-riannon` correctly resolved `muster_roach` to `neutral.roach`, but no current preset shipped a Roach copy, so the printed effect was invisible in normal starter play.
- The Arachas Behemoth → Arachas relationship was one-way in the catalog but tracked as an `it.todo` rather than active coverage.
- The Crone and Vampire family Musters worked through explicit `linkedSourceIds`, but the title-prefix shape was undocumented and the legacy helper still relied on name-prefix matching.
- Hemdall is a stat-stick hero summoned only via Kambi's Avenger; this contract was not asserted.

cCp13 makes the official starter experience faithful and locks the rule taxonomy down with active assertions so future agents do not reintroduce brittle name-prefix Muster behavior. No engine rule logic, AI policy, simulation engine, UI, route, or asset code changed.

## 4. Behavior Changed

### 4.1 Light Longship same-source Muster

`skellige.light-longship.linkedSourceIds` is now `["skellige.light-longship"]`. The existing `resolveMusterLike` resolver in [src/game/core/abilities.ts](src/game/core/abilities.ts) — which iterates `linked` over `[...hand, ...deck]` — automatically resolves the same-source group with no engine code change. Active in `official-skellige-starter` (3 copies); playing one Light Longship now pulls the remaining two from hand+deck instead of emitting `outcome: "no_linked_sources"`. Board and discard Light Longships are unaffected because the resolver only inspects hand and deck, matching §17.11 of the rules.

### 4.2 Roach starter visibility for `muster_roach`

Every current preset that contains Geralt or Cirilla now also contains one `neutral.roach`:

- `current-northern-realms`: 35 → 36 cards (Geralt; Roach added).
- `current-nilfgaard`: 33 → 34 cards (Cirilla; Roach added).
- `official-northern-realms-starter`: 28 → 29 cards (Geralt; Roach added).
- `official-nilfgaard-starter`: 28 → 29 cards (Cirilla; Roach added).
- `official-scoiatael-starter`: 31 → 32 cards (Geralt; Roach added).
- `official-monsters-starter`: unchanged (no Geralt/Ciri).
- `official-skellige-starter`: unchanged (no Geralt/Ciri).

Roach itself remains non-recursive — `neutral.roach.linkedSourceIds` stays empty and its `abilities` stays `["none"]`, so the resolver never tries to summon Geralt or Cirilla.

### 4.3 Documentation tightening

`docs/gwent-rules.md` §17.11a now enumerates the Muster categories and reaffirms that the production engine path uses explicit `linkedSourceIds` rather than runtime name-prefix matching. The legacy helper at `src/hooks/useGameLogic.ts` still uses name-prefix matching (intentionally; it covers the legacy default UI path) and was not changed in this phase.

### 4.4 No production rule changes

The engine resolver, scoring pipeline, command transactions, legal-move generation, AI policy, headless simulation, export validation, and Redux adapter are unchanged. The cCp13 changes are purely catalog data, documentation, and tests.

## 8. Risks / Follow-Ups

- **None new.** cCp13 closes all three cCp12 P3 follow-ups (Light Longship deferred Muster, Roach starter visibility, Arachas Behemoth ambiguous symmetry) and adds the Hemdall ability-less contract.
- **Deferred (unchanged from cCp12):** generic `summon` discard-trigger resolver remains `planned` ability metadata, and 21 of 22 leader records still print placeholder ability metadata. cCp13 does not change either.
- **Hemdall stat-stick caveat (unchanged):** if Hemdall ever grows an on-summon ability, `resolveAvengerForCard` will need to invoke `resolveCardAbilities` on the replacement. cCp13's invariant locks the current ability-less contract, so any change must update the test as well.
- **Legacy Muster helper (unchanged):** `src/hooks/useGameLogic.ts:findMusterCards` still uses name-prefix matching. The pure engine path uses `linkedSourceIds` exclusively. The legacy helper is exercised only by the legacy default UI path and is covered by `tests/game/legacyMuster.test.ts`. Replacing the legacy helper with a catalog resolver is out of scope for cCp13.

The resolver flow goes through the existing `resolveMusterLike` helper which inspects only `[...hand, ...deck]`.

The only count assertions touched are in `tests/catalog/currentCatalogData.test.ts` (current-northern-realms 35→36, current-nilfgaard 33→34) and `tests/game/coreSetup.test.ts` (deck shrink to 26 / 24).
