# Cluster E Phase 1 Report - Authentic UI Foundation

## Summary

Established the production UI substrate for the selected `docs/ui-handoff/`
Direction A design behind a new opt-in route variant. No engine rules, legal
moves, scoring, prompts, AI policy, simulation, export contract, or default
route changed.

`cEp1` adds:

- production Direction A design tokens scoped under a `.gwent-authentic`
  wrapper;
- catalog-aware faction, row, ability, leader-ability, and card-kind display
  metadata with deterministic fallbacks for unknown ids;
- an authentic card view-model helper, deterministic `SvgCardArt` SVG fallback,
  `AuthenticCard` and `AuthenticCardBack` components;
- an opt-in `?engine=1&ui=authentic` route variant that mounts an authentic UI
  harness/gallery without replacing the legacy default route or the existing
  diagnostic engine shell;
- focused unit tests for the route helper, display metadata, and card view
  model;
- Playwright Chromium browser smoke for the new authentic route at desktop and
  mobile viewports;
- forbidden-import scan coverage for the new product UI path;
- documentation updates and the required phase report.

## Implementation Summary

The new UI foundation is intentionally additive. The legacy Redux UI continues
to mount by default, and the existing `EngineGameManager` continues to mount
when `?engine=1` is set without `ui=authentic`.

Routing is handled in `src/App.tsx` via the existing `shouldUseEngineUi` plus a
new `getEngineUiVariantFromSearch` helper. Following the spec's
recommendation, `ui=authentic` without `engine=1` falls through to the legacy
UI rather than acting as a route switch on its own.

The card visual path is a new `src/components/gwent/` module rather than a
variant on `GwentCard.tsx`. Reasoning: `GwentCard.tsx` imports
`@/utils/gameHelpers` to compute legacy display strength, and extending it
in-place would either drag legacy rule assumptions into the new product UI or
require a much larger refactor than `cEp1` justifies. Keeping the new path
isolated also lets the forbidden-imports check guard it directly.

Display metadata is data-only. It maps catalog ids onto display strings,
glyphs, and palette swatches, and falls back to title-cased placeholders for
unknown ability or leader ability ids without throwing. The harness exercises
implemented and known placeholder ability ids so the chip path is visible.

The card view model is a thin remap from `CatalogCardSource` plus shared
size/strength helpers. `AuthenticCard` accepts the view model directly so it
does not need access to a card instance, runtime instance ids, or engine state.

Image handling: `AuthenticCard` renders the catalog `image` URL through a plain
`<img>` and swaps to `SvgCardArt` if `onError` fires or the image field is
missing. The harness includes an explicit missing-image example
(`/images/__missing-on-purpose__.png`) so the fallback is visible during
review and covered by the smoke. The harness does not preload images.

Hidden information: `AuthenticCardBack` accepts only `size`, an optional faction
sleeve hint, and an optional aria label. It cannot receive a card view model,
so it cannot leak hidden card identity by construction. The harness is a static
catalog-driven gallery and never consumes engine state, so hidden hand contents
cannot be rendered through it at all.

## Hidden-Info Review

- `AuthenticCardBack` does not accept card identity. There is no prop path that
  could carry a hidden card view model into a back-rendered element.
- The harness consumes only catalog source data. It does not reach engine
  state, AI hand state, prompt state, deck state, discard state, or runtime
  instance ids.
- The browser smoke asserts that the rendered harness text does not contain
  internal patterns such as `instanceId`, `sourceId` literally in visible text,
  or generated `seat_a:000:` / `seat_b:000:` instance ids.
- Existing engine shell smoke continues to validate the same hidden-info
  guarantees for `/?engine=1` and remains passing.

## Deviations / Limits

- The font stack uses a Google Fonts `@import` rather than vendoring fonts.
  Production deployments without external font access fall back to the
  documented serif/monospace stacks. No font binaries were committed.
- The authentic harness is a gallery, not a playable match screen. The
  diagnostic engine shell remains the engine UI default.
- The legacy `GwentCard.tsx` was deliberately left untouched to avoid pulling
  legacy rule helpers into the new UI path.
- Card art is still missing by design; the SVG fallback is exercised during
  smoke.
- No screenshots or visual regression artifacts were committed.
- `npm run ci` may flag `check:worktree-clean` when implementation files are
  unstaged at report time; per the spec this is acceptable as long as every
  preceding constituent passes.

## Risks And Follow-Ups

- The authentic match table (`cEp2`) must consume engine selectors and legal
  moves rather than reading match state directly, and must continue to render
  hidden zones as backs/counts only.
- When real card art is added, the catalog `image` paths must continue to
  match the `/images/<faction>/...` convention used by the catalog sources.
- The harness's metadata chips include known placeholder ability ids; future
  phases that surface these to players should label them explicitly so users
  understand they are not yet playable.
- The `@import` for Google Fonts is a single network call at first paint;
  future phases should consider self-hosting if offline use cases matter.
