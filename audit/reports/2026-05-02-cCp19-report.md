# Cluster C Phase 19 — Row-Wide Horn-Like Leader Passives

- Spec: `docs/spec/2026-05-02-cCp19-specs.md`
- Branch: `dev`
- Date: 2026-05-02

## Summary

cCp19 implements **Tranche 1** of the cCp18 Leader Ability Matrix: the four
row-wide horn-like passive leader effects. The leader ability IDs
`double_siege`, `double_close`, and `double_ranged` are promoted from
`placeholder` to `implemented`, and four leader records become mechanically
playable through the pure scoring pipeline as ongoing passive row modifiers:

- `northern-realms.foltest-the-siegemaster` — `double_siege`
- `monsters.eredin-commander-of-the-red-riders` — `double_close`
- `scoiatael.francesca-findabair-queen-of-dol-blathanna` — `double_close`
- `scoiatael.francesca-findabair-the-beautiful` — `double_ranged`

The implementation mirrors cCp15's King Bran passive: a pure helper
(`getRowHornPolicyBySeat`) derives a per-seat row-horn policy from leader
identity, and `calculateScores` reads the policy to apply a horn-equivalent
×2 multiplier to non-hero units on the matching friendly row at the existing
horn stage. Physical Commander's Horn (special card or unit/hero
`commanders_horn` source) on the row suppresses the leader horn — horn
effects do not stack.

The passive surfaces are intentional: no `use_leader` move, no `leaderUsed`,
no `leader_used` event, and no UI route/layout changes.

## Behavior Changed

Engine scoring:

- `calculateScores` now derives a per-seat row-horn policy from leader
  identity through `getRowHornPolicyBySeat(state, leaders)` whenever a
  `catalogLeaders` array is supplied. The derived policy can be
  overridden by an explicit `rowHornPolicyBySeat` argument, mirroring
  the cCp15 weather override pattern.
- Non-hero unit cards on the friendly mapped row receive a ×2 horn
  multiplier when:
  - the seat's leader ability is `double_close` (close), `double_ranged`
    (ranged), or `double_siege` (siege); **and**
  - no Commander's Horn (special card in the row's horn slot or any
    unit/hero on the row carrying `commanders_horn`) applies on that
    row.
- Heroes are unaffected as receivers and their `modifiers` continue to
  carry `hero_immune`.
- The score breakdown's `modifiers` list distinguishes physical horn
  (`"commanders_horn"`) from leader horn (`"leader_horn"`). When a
  physical horn applies, the leader horn is suppressed and only
  `"commanders_horn"` is recorded.
- Self-exclusion behavior for unit/hero physical horn sources is
  preserved (the source itself does not horn itself; allies on the row
  do).
- The `multiple_horn_sources` diagnostic continues to describe **only**
  physical row horn sources. A suppressed leader policy never emits a
  spurious diagnostic.
- All score-dependent paths inherit the policy automatically because
  they go through `calculateScores`:
  - Round resolution / round winner / Nilfgaard tie / gem loss /
    `roundHistory.scoreBySeat`;
  - Special Scorch target evaluation (uses effective strength per the
    cCp7 pipeline);
  - Unit row-Scorch target evaluation (`scorch_close` / `scorch_range` /
    `scorch_siege` on Toad / Schirru / unit-source whole-board Scorch);
  - Foltest row-Scorch leaders (`Foltest: Son of Medell` /
    `Foltest: The Steel-Forged`) — already use `calculateScores` per
    cCp16.

Engine legal moves and commands:

- `getLeaderMove` continues to return `[]` for the four cCp19 leaders.
  Their ability is implemented as a passive scoring derivation; no
  `use_leader` move is emitted (mirrors King Bran).
- `executeLeader` falls through to the existing
  `unsupported_command` `EngineRuleError` for manual `UseLeader`
  attempts on these leaders. `seat.leaderUsed` is never flipped and no
  `leader_used` event is emitted under normal play.

## Deviations From The Spec

None of substance. Two notes:

1. **Helper signature.** The spec recommended
   `getRowHornPolicyBySeat(state, catalogLeaders)` with `catalogLeaders`
   typed as `ReadonlyMap<string, CatalogLeaderDefinition> | readonly
   CatalogLeaderDefinition[]`. The cCp15 King Bran helper accepts only
   `readonly CatalogLeaderSource[]`, so cCp19 follows the existing local
   convention and exposes the helper with the simpler array signature.
   This is consistent with the spec's "Exact signatures may vary to fit
   existing local types" allowance and keeps `getRowHornPolicyBySeat`
   directly callable everywhere `getWeatherPolicyBySeat` is.
2. **Helper export surface.** `getRowHornPolicyBySeat` is exported from
   `src/game/core/scoring.ts` and reaches the public surface via the
   existing `export * from "./scoring"` in `src/game/core/index.ts`. No
   new entry was added to `src/game/core/index.ts` — the same wildcard
   re-export already covers `getWeatherPolicyBySeat`.

No other deviations. Out-of-scope behaviors (`cancel_leader`,
`double_spies`, `random_medic`, `restore_discard_to_hand`,
`draw_opponent_discard`, `discard_two_draw_one_from_deck`,
`optimize_agile_rows`, `draw_extra_card`, `shuffle_discards_into_decks`,
`look_three_cards`, leader prompt UI, reaction/cancel UI,

## Risks / Follow-Ups

- **Inspector UI may want both horn modifiers.** Code reading
  `CardScoreEntry.modifiers` to render horn provenance should consider
  both `"commanders_horn"` and `"leader_horn"` — the existing cEp5.3
  inspector renders the modifiers list verbatim, so it is unaffected,
  but new UI surfaces that hard-code the old single-modifier check may
  miss the leader horn case.
- **Cancel-leader interaction deferred.** The row-horn helper is
  structured so a future `seat.leaderCancelled` flag can short-circuit
  the policy without touching scoring math, but cCp19 does not
  implement the cancel state. When `cancel_leader` lands (Tranche 4),
  the helper's first guard should check the cancel flag.
- **Double-spies composition.** `double_spies` overlaps with the
  cCp19 row-horn passives only when a Spy occupies the leader's mapped
  row. Both modifiers compose through the standard scoring pipeline
  once `double_spies` is implemented; no special-case is needed in
  cCp19.
- **Other §C entries from cCp18.** §C-3 (`random_medic` ID misnomer
  description), §C-5 (`look_three_cards` description count), §C-6 /
  §C-9 (Nilfgaard leader source description gaps), §C-8 (Game8 staging
  provenance note), and §C-10 (Witcher Fandom scrape coverage gap)
  remain documentation-only follow-ups for the relevant later tranche.
- **Pre-existing lint warning.** `src/hooks/useReduxAI.ts` still
  reports a `react-hooks/exhaustive-deps` warning. Unrelated to cCp19;
  not surfaced to the cCp19 scope.

## Recommended Next Step

Proceed with **cCp20 — Tranche 2 (active score modifier / single-step
prompt)**. Recommended ordering inside Tranche 2 based on the cCp18
audit and the post-cCp19 settled product decisions:

1. `double_spies` — single snapshot at fire time, single new event,
   no prompt.
2. `optimize_agile_rows` — auto-place per the settled product decision
   (catalog wording wins; no row-choice prompt).
3. `restore_discard_to_hand` — single-step `choose_card` prompt over
   the acting seat's discard pile.
4. `random_medic` — passive Medic mutation (random non-hero unit
   selection on Medic effects).
5. `shuffle_discards_into_decks` — bulk discard-to-deck recycle with a
   deterministic seeded shuffle, unusable when both discards are
   empty.
6. `draw_opponent_discard` — single-step `choose_card` prompt over the
   opponent discard pile (catalog interpretation wins per the settled
   decision).

Defer multi-step / hidden-info / suppression leaders
(`discard_two_draw_one_from_deck`, `draw_extra_card`,
`look_three_cards`, `cancel_leader`) to Tranche 3 / 4 because they
introduce engine surfaces (multi-stage prompts, observation manifests,
suppression flags) that should not be bundled into cCp20.
