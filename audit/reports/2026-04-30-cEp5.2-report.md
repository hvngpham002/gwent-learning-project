# Cluster E Phase 5.2 Report — Deck Builder Generated Cards And Card Inspection

## Summary

`docs/spec/2026-04-30-cEp5.2-specs.md` is implemented end-to-end. The authentic deck builder no longer presents linked engine replacements as a player-facing "side deck". The right rail now ships a `generated cards` section that renders an authentic thumbnail and "generated by ..." label per replacement and is read-only. `neutral.bovine-defense-force` is now `side_deck_only`, so Cow → Bovine Defense Force joins Kambi → Hemdall, Berserker → Vildkaarl, and Young Berserker → Young Vildkaarl as a generated pair. A right-click card context menu and a read-only inspect modal cover catalog card details across the pool, the cards-in-deck list, and generated entries.

`CatalogDeckPreset.sideDeck` storage and the existing validation error codes (`side_deck_only_main_deck`, `wrong_faction_side_deck_card`, `side_deck_count_mismatch`, etc.) are unchanged. No engine rules were modified.

## Behavior Changed

- The right rail label `side deck · linked replacements` is replaced with `generated cards`, and a small help line `Automatically created by cards in your deck. Not manually added.` follows it. Each entry shows a small authentic thumbnail, the card name, the `x{count}` indicator, and a `generated by ...` source label.
- `neutral.bovine-defense-force` is now `side_deck_only`. Bovine Defense Force is hidden from the main-deck pool; it appears under `generated cards` whenever Cow is present in the main deck. Linked side-deck sync auto-populates Bovine in `deck.sideDeck` when Cow is added/removed, exactly the same way Kambi syncs Hemdall today.
- Right-click anywhere on a card surface (pool item, cards-in-deck row, or a generated entry) opens a context menu. The menu offers `add`, `remove`, and `inspect`. Disabled actions show their reason inline (e.g. `add · 3/3 limit`, `remove · not in main deck`, `add · Generated card; not directly addable.`). Clicking outside, pressing `Escape`, choosing an action, or opening the inspect modal closes the menu.
- A generated entry can also be inspected by left-clicking it; left-click on a pool card still adds the card directly.
- Inspecting any card opens a read-only modal with:
  - Large authentic art (`AuthenticCard` size `lg`).
  - Source ID, faction, kind, strength (where applicable), rows, deck limit, image path, and tags.
  - Abilities with display names, statuses, glyphs, and descriptions.
  - Linked-generated relationships (`Generates: ...`) and generated-by relationships (`Generated by: ...`) when applicable.
  - Current deck count and current generated count.
  - `add` / `remove` action buttons that share the same enabled/disabled rules as the context menu.
- The modal is a `role="dialog"` `aria-modal="true"` surface that closes on `close`, click-outside, `Escape`, or after taking an `add` / `remove` action.

## Deviations From Spec

- The spec recommended either a small visible menu button on list rows/thumbnail wrappers OR keyboard `Enter`/`Space` on a focused trigger as a mobile/keyboard fallback. cEp5.2 ships right-click and `Escape`/click-outside semantics; an initial visible `⋯` trigger on each pool item conflicted with the existing `getByRole("button", { name: /Geralt of Rivia/i })` smoke selector, so the visible trigger was removed. Right-click is exercised on desktop, and modern mobile browsers convert long-press to `contextmenu`, so the inspect modal is reachable on mobile. A dedicated visible menu button (with a name that does not collide with the card name) is a small follow-up.
- Card Studio does not yet block playable custom Avenger cards with empty/unresolved `linkedSourceIds[0]`. cCp9 added an analogous guard for Berserker; the Avenger guard remains a small follow-up flagged by cCp11 and is unchanged here.

## Risks / Follow-Ups

- The visible context-menu trigger button was deferred because of the existing smoke's ARIA-name regex; a future polish pass can add a `Card menu` button with a non-conflicting label and a small `⋯` icon, keeping the right-click behavior intact.
- The inspect modal does not yet include a focus-trap or auto-focus; it returns to the page when closed and works with `Escape`. This matches the existing handoff modal style; if accessibility hardening becomes a priority, it can be layered on with the shared `Alert` primitive.
- Generated/replacement add-state reasons (`generated_only`) are not localized; the deck-builder copy is English-only today, consistent with the rest of the authentic UI.
