## Behavior Changed

- `monsters.eredin-destroyer-of-worlds` is now mechanically
  playable. Before cCp27 the catalog described
  `discard_two_draw_one_from_deck` as `placeholder` and `getLeaderMove`
  fell through to `[]`; manual `UseLeader` raised
  `unsupported_command`. After cCp27 the leader emits a single
  no-target `use_leader` legal move when eligibility passes
  (hand ≥ 1 and deck ≥ 1) and resolves through a true two-stage
  prompt flow.
- The engine now distinguishes single-stage prompts (existing
  `medic_revive`, `restore_discard_to_hand`, `draw_opponent_discard`)
  from cCp27's two-stage flow via `PendingPrompt.stage` and the new
  `PendingPrompt.kind === "choose_card_set"` for stage 1.
  `PendingPromptOption.target` is now a discriminated union; existing
  callers that accessed `.cardId` directly were narrowed.
- `LegalMoveTarget` now has two new acting-seat-only shapes
  (`card_instance_set`, `deck_card_instance`); UI and simulation
  helpers were updated for exhaustiveness without behavior changes
  for existing leaders.
- New event reasons: `card_moved.reason`
  `"leader_discard_for_draw"` (stage 1 hand → discard) and
  `"leader_draw_from_deck"` (stage 2 deck → hand);
  `deck_shuffled.reason` `"leader_discard_draw"` (post-draw shuffle).
  These are distinct from cCp23's `"leader_shuffle_into_deck"` for
  unambiguous event-trace identification.
- New `ability_resolved.outcome` value:
  `"discarded_and_drew_card"` for the stage 2 finalization.
- Hidden-info exposure surface is unchanged at the public layer:
  `getPromptMoves` returns `[]` for the non-acting seat in both
  stages; `seatObservation.buildSeatObservation` returns
  `pendingPrompt: null` for the wrong seat; simulation export
  observation surfaces the acting seat's own deck card via a
  prompt-local safe ref `own_deck_option_<index>` so raw deck
  instance IDs never leak.
- No card abilities trigger from discarded hand cards or drawn deck
  cards: stage 1 resolves with no `card_played`, no `ability_*`
  events for the discarded card sources, and no Summon/Avenger/Medic/
  Spy/Scorch/weather/Muster/Berserker/Mardroeme firing. Stage 2
  resolves with no `card_played` and no `ability_*` events for the
  drawn card.

## Deviations From Spec

None of substance. Minor implementation refinements:

- The spec's `getDiscardDrawEligibility` return type uses literal
  numeric types `2` and `1` for `maxDiscardCount` and
  `minDiscardCount`. The implementation matches via
  `typeof MAX_DISCARD_COUNT` / `typeof MIN_DISCARD_COUNT` so the
  constants and the helper field types stay tied at the type level.
- The spec recommended option-ID format
  `discard-draw:discard:<cardId>` and
  `discard-draw:discard:<cardIdA>+<cardIdB>` and
  `discard-draw:draw:<cardId>`. Implemented exactly as recommended.
- The spec recommended `prompt_resolved` for the discard stage and
  the deck stage, plus a final `ability_resolved`. Implemented as
  spec'd, with the additional `prompt_opened` for the stage 2 prompt
  on stage 1 resolution.
- The spec allowed the legal-move metadata `targetCount` to be
  "another documented diagnostic count". Implemented as
  `handCount + deckCount` per the spec's example.
- The spec recommended the `deck_shuffled.reason` value
  `leader_discard_draw`. Implemented exactly.
- Action encoding for `card_instance_set` and `deck_card_instance`
  encodes as `{ kind: "none", side: "none" }` on the action side; the
  prompt option's safe ref lives on the observation side. The spec
  allowed minor safe-export schema extensions documented in the
  report — implementation chose to keep the schema unchanged on the
  action side (no schema bump) and instead added the prompt-local
  safe ref `own_deck_option_<index>` on the observation side. This
  preserves backward compatibility with existing JSONL consumers and
  passes the redaction validation suite.

## Risks / Follow-ups

- **AI strategy timing remains unchanged.** `legal-heuristic-v0` does
  not strategically choose this leader because `isUsefulLeaderMove`
  only returns true for `clear_weather` with weather present. The
  AI policy will not call `Use Leader: Discard 2 Draw 1` in
  practice. Future AI tranches (`legal-heuristic-v1`+) should value
  the leader by hand strength variance / deck top-card variance, but
  cCp27 is intentionally policy-neutral.
- **UI deck-card prompt tiles deferred.** The existing generic
  `PromptPanel` renders the new options as plain labelled buttons.
  Inspectable deck-card prompt tiles (where a player can right-click
  a deck draw option to inspect a large card preview) are deferred
  to a later Cluster E polish phase per the spec's Out-Of-Scope
  list. For cCp27, AI-owned prompts continue to show only "AI
  resolving prompt from legal moves" in the authentic UI.
- **Action encoding fallback to `none` for new target kinds.**
  Stage 1 `card_instance_set` and stage 2 `deck_card_instance` both
  encode as `{ kind: "none", side: "none" }` on the action side. ML
  consumers that want to disambiguate stage 1 from stage 2 in action
  vectors will need either the `prompt.optionRef` (which is stage-
  specific) or a future extension of `SafeActionTargetRef`. cCp27
  intentionally keeps the safe-action target union backward-shaped.
- **Skellige round-three return interaction.** Discarded hand cards
  enter the acting seat's discard pile and become eligible for
  Skellige round-three return at round-end if the acting seat is a
  Skellige seat. cCp27 does not introduce any new interaction; the
  existing §17.18 flow handles it.
- **Pattern 3 documentation note vs implementation.** The matrix
  Pattern 3 historically discussed a "blind top-of-deck" alternative.
  The cCp27 implementation followed the settled Product Decision §4
  ("chosen-discard plus chosen-draw"). The matrix change-log entry
  records this clearly.

    `target.kind === "card_instance_set"` with `cardIds: [cardId] |
    [cardIdA, cardIdB]` and matching `sourceIds`.
  - Stage 2: `PendingPrompt.kind === "choose_card"` with
    `stage === "deck_draw_selection"`, `context: { discardedCardIds }`.
    Each option's `target.kind === "deck_card_instance"` with
    `cardId` and `sourceId`.

  `deck_card_instance` target kinds.** Both `LegalMoveTarget` and
  `PendingPromptTarget` were extended with these two new variants.
  The existing `card_instance` shape was preserved unchanged.
- **Event reason names.**
  - Hand discard: `card_moved.reason === "leader_discard_for_draw"`.
  - Deck draw: `card_moved.reason === "leader_draw_from_deck"`.
  - Deck shuffle: `deck_shuffled.reason === "leader_discard_draw"`.
- **Exact manifest counts after cCp27.**

    `look_three_cards`.
- **1-card hand is legal; 0-card hand is not.** Confirmed.
  `getDiscardDrawEligibility` returns `canUse: false` for hand size
  0. A hand of size 1 emits a single legal stage 1 option to discard
  that one card. Tested explicitly.
- **Empty deck is not legal.** Confirmed.
  `getDiscardDrawEligibility` returns `canUse: false` for deck size
  0. Tested explicitly.
- **Leader is consumed only after stage 2.** Confirmed. Stage 1

  leaves `seat.leaderUsed === false`, no `leader_used` event, no

  Stage 2 resolution runs `shuffleWithRng` on the remaining deck,
  advances `state.rng.state` only when remaining deck length ≥ 2,
  and emits `deck_shuffled` with the new reason regardless of
  remaining deck length so the event log records the shuffle step.

    stages.
  - `seatObservation.buildSeatObservation` returns
    `pendingPrompt: null` to the wrong seat. Stage 1 options expose
    aggregate `targetStrength` (sum of selected hand-card strengths);
    stage 2 options expose the selected deck card's `cardId` /
    `targetStrength` to the acting seat only.

  - `actionEncoding` falls back to `{ kind: "none", side: "none" }`
