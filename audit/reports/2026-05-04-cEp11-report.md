## Behavior Changed

### Pure View-Model Helper

- New `buildSelectedCardTargetViewModel` helper in
  `src/components/gwent/matchViewModel.ts` consumes `{ selectedCard,
  selectedPlayMoves, cardLookup }` and returns a discriminated view model:
  - `state: "no-selection" | "no-targets" | "has-targets"`,
  - `selectedCardLabel` (the public name of the selected human hand card, or
    `null` when no card is selected),
  - `instructionLabel` (longer copy used in narrative regions),
  - `rowTargets` keyed by `seatId:row` with `{ moveId, seatId, row, side,
    sideLabel, rowLabel, badgeLabel: "play here", ariaLabel: "Play <card> on
    your close combat row" }`,
  - `cardTargets` keyed by visible `cardId` with `{ moveId, cardLabel,
    badgeLabel: "choose", ariaLabel: "Choose <card> for <selected card>" }`,
  - `rowHornTargets` keyed by own `seatId:row` with `{ moveId, seatId, row,
    rowLabel, badgeLabel: "horn slot", ariaLabel: "Place <card> on your <row>
    horn slot" }`,
  - `weatherTarget: { moveId, badgeLabel: "play weather", ariaLabel: "Play
    <card> on the weather panel" } | null`,
  - `fallbackActions` (compact right-rail actions for `target.kind === "none"`
    and any non-spatial PlayCard target shape that may be added later),
  - `rightRailLabel` (`no card selected.` / `no legal targets.` / `choose a
    highlighted row.` / `choose a highlighted card.` / `choose a highlighted
    row or card.` / `choose a highlighted horn slot.` / `target the weather
    panel.` / `use the action button below.`).
- The helper is pure and depends only on the selected card's `instanceId` and
  `name`, the legal `PlayCardMove[]`, and a `Map<CardInstanceId, { name }>`
  visible-card lookup. It never reaches into the engine, never computes
  legality, never invents a target, and never dispatches a command.
- `cardLabel` falls back to a public `card` literal when a card target is
  missing from the visible-card lookup, so opponents' hidden-info safety holds
  even when the visible-card lookup is incomplete.
- Old export `groupTargetActions` (in
  `src/components/game/engine/engineShellViewModels.ts`) remains exported for
  the diagnostic engine shell. `AuthenticMatchScreen.tsx` no longer imports
  it.

### `AuthenticMatchScreen` Target Rendering

- The board row container is now a non-interactive `<div
  data-testid="authentic-board-row">`. The row-level target affordance is a
  dedicated `<button data-testid="authentic-board-row-target">` overlay that
  appears only when the selected card has a legal `board_row` move on that
  row and dispatches the exact `PlayCard` move id. This eliminates the
  cEp10-era nested-interactive-element risk: visible legal `card_instance`
  targets remain `<button data-testid="authentic-board-card-target">` (so
  Decoy still works), and they are no longer wrapped inside another
  `<button>`.
- Visible board card targets render a `choose` badge anchored to the card
  surface (accent border + small badge). Clicks dispatch the exact
  `PlayCard` move; right-click still opens the existing inspect context menu
  via `event.preventDefault()` + `stopPropagation()` and never dispatches the
  target move. Non-target board cards remain inspectable but do not look
  actionable.
- Selecting Commander's Horn renders a small `<button
  data-testid="authentic-board-row-horn-target">` placeholder per legal own
  row inside the row's card strip with a `horn slot` label and the diamond
  glyph from the existing `commanders_horn` ability metadata. Clicks
  dispatch the exact `row_horn` PlayCard move.
- Selecting a weather card highlights the Weather panel and renders a
  `<button data-testid="authentic-weather-target">` whose click dispatches
  the exact `weather` PlayCard move whether the panel is empty or already
  populated. Existing weather card right-click inspection is unchanged.
- Global/no-target plays remain compact right-rail buttons (`<button
  data-testid="authentic-target-action">`) with safe lowercase labels like
  `play scorch` and aria `play scorch (global effect)`. The fallback panel
  is the only place those cards can be dispatched, and the helper never
  invents a fake spatial location for them.

### `ActionPanel` Right-Rail Refresh

- The `ActionPanel` now consumes the new `SelectedCardTargetViewModel`
  directly instead of `groupTargetActions`. It always renders a single `<p
  data-testid="authentic-target-hint">` whose text matches the helper's
  `rightRailLabel`, plus a compact fallback action group only when
  `selectedTargets.fallbackActions` is non-empty. The `data-target-state`
  attribute (`no-selection|no-targets|has-targets`) lets tests and styling
  react without re-deriving state.
- Existing leader status / leader action / pass / resolve-round / round-end /
  game-end / round-history / battle-log surfaces are unchanged.

### CSS Updates

- `.authentic-board-row` is now `position: relative` and the legacy
  `button.authentic-board-row` font-family override is removed.
- New `.authentic-board-row__target` (row overlay button), `.authentic-board-row__target-badge`,
  `.authentic-board-row__horn-target` (horn-slot placeholder), `.authentic-board-row__horn-target-icon`,
  and `.authentic-board-row__horn-target-label` styles use the existing
  `--accent`, `--bg-paper`, and `--font-display` tokens. Focus-visible state
  is wired with the existing accent.
- `.authentic-board-card.is-card-target` now also sets `cursor: pointer` and
  the `:hover` / `:focus-visible` state strengthens the accent ring. A new
  `.authentic-board-card__target-badge` hangs a `choose` badge below the
  card surface.
- `.authentic-weather` now supports an `is-legal-target` modifier and a new
  `.authentic-weather__target` button with focus-visible accent ring.
- `.authentic-target-groups__hint` styles the new right-rail hint line and
  switches to the accent state when `data-target-state="has-targets"`.
- The 390 px mobile breakpoint shrinks the new row, horn, weather, and
  card-target badges so they do not overlap card strength medallions, row
  labels, or the row score column.

### New Focused Coverage

`tests/components/gwent/authenticMatchViewModel.test.ts` adds an 11-test
`buildSelectedCardTargetViewModel (cEp11)` block:

- `no-selection` returns the neutral instruction copy and empty target sets.
- `no-targets` returns the no-legal-targets state when the selected card has
  no PlayCard moves.
- Row targets are keyed by `seatId:row` with safe labels and exact engine
  move ids.
- Board card targets are keyed by visible `cardId` with safe public labels
  and exact engine move ids.
- Row-horn targets are keyed by own `seatId:row` for `row_horn` moves.
- Weather target is emitted for `target.kind === "weather"` moves.
- Global/no-target plays produce compact right-rail fallback actions.
- User-facing labels (badges, aria, hint copy, fallback labels) never include
  raw `seat_a:...` / `seat_b:...` instance IDs or hidden opponent source IDs;
  the structural `key` field of `cardTargets` is the cardId itself, which is
  required for dispatch and is excluded from the user-facing label assertion.
- `cardLabel` falls back to a public `card` literal when a target is missing
  from the visible-card lookup.
- Recompute when a different card's legal moves are supplied.
- Mixed row + card targets emit the `choose a highlighted row or card.` hint.

## Acceptance Criteria Status

- Selecting a normal unit with legal row moves highlights the correct board
  row targets and clicking a highlighted row dispatches the exact existing
  `PlayCard` move: met. The new `cEp11` Chromium smoke prefers the spatial
  row target and asserts the activity log shows `Human played`. The pure
  helper test asserts the row target's `moveId` matches the legal move id.
- Selecting a card with `card_instance` targets highlights only visible
  legal board cards and clicking one dispatches the exact existing move:
  met. `cardTargets` are produced only from `card_instance` legal moves and
  the click handler dispatches the helper-supplied `moveId`.
- Selecting Commander's Horn or an equivalent `row_horn` card shows
  explicit horn-slot targets and dispatches the exact existing move: met.
  `rowHornTargets` are produced only from `row_horn` legal moves and the
  horn-slot button dispatches the helper-supplied `moveId`.
- Selecting a weather card shows an explicit Weather panel target and
  dispatches the exact existing move: met. `weatherTarget` is produced only
  from `weather` legal moves and the weather button dispatches the
  helper-supplied `moveId`.
- Selecting a global/no-target card play shows a compact right-rail action
  and does not create a fake board target: met. Global plays produce
  `fallbackActions` with safe `play <card>` labels; the helper never
  populates `rowTargets`, `cardTargets`, `rowHornTargets`, or
  `weatherTarget` for them.
- The right rail no longer depends on the diagnostic engine-shell
  `groupTargetActions` helper for authentic selected-card target
  presentation: met. `AuthenticMatchScreen.tsx` no longer imports
  `groupTargetActions`. The diagnostic engine shell still imports it (for
  the `?engine=1` diagnostic shell), so the helper itself is kept.
- No nested interactive elements are introduced in board rows: met. The new
  `authentic match avoids nested interactive elements on board rows
  (cEp11)` smoke locks down `authentic-board-row` as `<div>` and the row
  target as a sibling button, and the row-target overlay has no
  `closest("button[data-testid='authentic-board-row']")` ancestor.
- Right-click inspect behavior remains intact on visible cards: met. The
  `cEp11` smoke right-clicks a placed board card after a target dispatch and
  asserts the inspect context menu still opens. The cEp5.3 inspect smoke
  continues to pass.
- Hidden AI hand/deck identities remain hidden: met. The visible-card
  lookup is built from `humanHand`, `weatherCards`, both seats' public
  discards, and `boardRows.flatMap(... units, horn ...)` only, so AI hand
  / deck names never reach the helper. The page-text `instanceId|sourceId|
  seat_a:NNN:|seat_b:NNN:` regression check still passes after every
  target interaction.
- Desktop and 390 px mobile layouts avoid target badge/text overlap: met.
  The mobile breakpoint shrinks the row-target badge, horn target, weather
  target, and card-target badge so they fit alongside the row score column
  and the card strength medallion.
- `docs/PROJECT_STATE.md`, `docs/ui/authentic-product-flow.md`, and the
  phase report are updated: met.

## Deviations

- The dedicated weather-target browser smoke was deferred. Reaching a
  deterministic weather-card hand without changing engine seed semantics
  needs the same cEp8-style custom-deck workload, and the unit tests
  already cover the pure weather target shape (badge label, aria, exact
  legal `weather` move id). The cEp8 weather-leader smoke continues to
  cover the leader-side weather flow. A deterministic weather-card
  selected-target smoke is a Cluster E follow-up.
- The legacy `groupTargetActions`, `getBoardRowTargetsByKey`, and
  `getBoardCardTargetsById` helpers are kept exported (the latter two
  remain in `matchViewModel.ts`; `groupTargetActions` lives in the
  diagnostic shell). They are no longer referenced from
  `AuthenticMatchScreen.tsx`. Existing focused unit tests still cover the
  legacy helpers, which keeps the diagnostic shell behavior locked down.
- The right-rail panel does not introduce a second `Card targets` heading
  even when both row and card targets exist; instead a single hint line
  reads `choose a highlighted row or card.`. The spec asks for "compact
  fallback buttons for accessibility and for non-spatial targets, but do
  not make a bulky duplicate target panel the primary presentation,"
  which this implementation satisfies by reserving the right rail for
  fallback-only.

## Risks / Follow-Ups

- The hint line is short and self-contained, but a future product polish
  slice could fold the hint into the inspector card or the top status
  banner if the right rail becomes too dense.
- A deterministic weather-card hand fixture would let the cEp11 smoke
  exercise the spatial weather target. cEp8 already includes the
  custom-deck pattern; reusing that for cEp11 weather coverage is a
  natural next step.
- The board row target overlay sits above the row score column on mobile;
  if a future row redesign moves the score column elsewhere, the overlay's
  `right` offset will need a matching update.
- The `authentic-board-row__horn-target` placeholder reuses the
  `commanders_horn` diamond glyph (◊) for visual continuity with the
  `Horn` ability. If a future engine change introduces non-Commander's
  Horn `row_horn` plays, the icon may need a tweak — but the helper does
  not gate on the source ability so the existing wiring will still
  dispatch the correct legal move.
- After cEp11 and once a `cEp11` deterministic weather smoke + match-end
  ledger smoke are added, the next product phase candidate is full
  drag-and-drop card play.
