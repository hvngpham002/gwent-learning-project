# cFp20 Report - Batch B Evaluation Ladder Decision Note

## Summary

cFp20 synthesizes the evaluation-facing annotations into a compact
decision artifact. This phase did not read new source PDF pages and did
not change runtime behavior. It used only the completed annotation files
for `timbers2022approxexploitability`, `herbrich2006trueskill`, and
`glickman1995glicko`.

The decision is to build an evaluation ladder before implementing
search or model training. The ladder should start with deterministic
validity/regression metrics, fixed-suite head-to-head matchup matrices,
and uncertainty-aware ratings over raw match-result ledgers; approximate
best-response / exploitability-style probes come later as robustness
diagnostics, not as exact exploitability claims.

## Risks And Follow-Ups

- Batch B is an evaluation decision, not a benchmark implementation.
- Glicko/TrueSkill ratings must not be used as substitutes for matchup
  matrices, hidden-info validation, or exploitability-style robustness
  probes.

  match-result ledger and fixed-suite matrix exist.
- Public/product difficulty tiers remain out of scope; research ratings
  are internal evidence until calibrated against a product policy.
