# cCp32.1: Scoia'tael Post-Mulligan First-Player Choice — Implementation Report

## Summary
cCp32.1 corrects the timing of the Scoia'tael first-player faction ability from pre-game setup (cCp32) to post-mulligan engine prompt. The pre-game `ScoiataelFirstPlayerChoice` type, `MatchConfig.scoiataelFirstPlayerChoice`, pre-game UI selector, and adapter threading have been removed. Scoia'tael choice now triggers after both mulligans complete via an engine-owned `pendingPrompt` with `scoiatael_first_player_choice` stage.

## Files Changed

### Core Engine
- `src/game/core/types.ts` — Removed `ScoiataelFirstPlayerChoice` interface and `MatchConfig.scoiataelFirstPlayerChoice` field. Kept `"scoiatael_first_player_choice"` in `PendingPromptStage`.
- `src/game/core/setup.ts` — Replaced pre-game scoia'tael logic with `getScoiataelFirstPlayerEligibility` helper. `startMatch` now always uses seeded `initial_roll` for all matches.
- `src/game/core/commands.ts` — `chooseMulligan` opens `scoiatael_first_player_choice` prompt after both mulligans when Scoia'tael eligible. `choosePromptOption` resolves the prompt, setting `roundStarter`/`currentTurn`, emitting `faction_ability_resolved` + `turn_set(scoiatael_override)`, and transitioning to `playing`. Fixed variable naming typo (`scoiState` vs `scoiState`).

### UI and Adapter
- `src/components/gwent/preGameViewModel.ts` — Removed `scoiataelFirstPlayerChoice` from `AuthenticMatchSetupConfig`, removed `shouldShowScoiataelFirstPlayerChoice` and `getDefaultScoiataelFirstPlayerChoice` functions, simplified `buildSetupConfig` and `setupConfigToStartEngineOptions`.
- `src/components/gwent/AuthenticPreGameScreen.tsx` — Removed scoia'tael state, `showScoiataelChoice` visibility, first-turn selector UI, and footer summary text.
- `src/store/thunks/engineThunks.ts` — Removed `ScoiataelFirstPlayerChoice` import and `scoiataelFirstPlayerChoice` from `StartEngineMatchOptions` and `createDefaultConfig`.

### Tests
- `tests/game/coreSetup.test.ts` — Rewrote scoia'tael tests: setup now uses seeded `initial_roll` for all matches; removed pre-game override validation tests.
- `tests/game/coreCommands.test.ts` — Added post-mulligan scoia'tael prompt tests: prompt opens after both mulligans, self/opponent options resolve correctly with proper events.
- `tests/components/gwent/authenticPreGameViewModel.test.ts` — Removed scoia'tael pre-game test suite.
- `tests/store/engineAdapter.test.ts` — Updated scoia'tael adapter test to verify seeded `initial_roll` at setup (no pre-game override).

## Behavior Changed
- **Before**: Scoia'tael first-player choice was configured at pre-game setup, passed through `MatchConfig`, applied in `startMatch`, and shown in the pre-game UI.
- **After**: `startMatch` always uses seeded `initial_roll`. After both mulligans complete, if exactly one seat is Scoia'tael, the engine opens a `pendingPrompt` (`scoiatael_first_player_choice`). Resolving `"self"` sets `currentTurn` to Scoia'tael seat; `"opponent"` sets it to opponent seat. Both emit `faction_ability_resolved` (policy: `post_mulligan_choice`) and `turn_set` (reason: `scoiatael_override`).
