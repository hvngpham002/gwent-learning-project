# Cluster D Phase 9 Report - Batch Simulation Seed Suites And Diagnostics

## Batch API Shape

Public entrypoint:

```ts
runHeadlessSimulationBatch(input?: HeadlessSimulationBatchInput): HeadlessSimulationBatchResult
```

Input resolution:

- `suite` wins over `suiteId`.
- `suiteId` resolves through `getSimulationSeedSuite`.
- `seeds` runs an ad hoc ordered seed list.
- no input defaults to `currentSimulationSmokeSuite`.
- `maxSteps` prefers explicit input, then suite default, then `300`.
- `verifyReplay` defaults to `true`.
- `includeRawResults` defaults to `false`.

Unknown suite ids and empty seed lists throw clear programmer errors. Per-seed policy and engine failures stay in run records.

## Replay Diagnostics

Replay diagnostics wrap `replayHeadlessMatchCommands` in a non-throwing result. They compare final phase, winner, gems, round history, and current round. Replay failures are counted in per-run diagnostics and `summary.replayFailedCount` instead of aborting the batch.

Replay is still current-catalog command replay. It does not promise cross-version compatibility, intermediate-state hashes, or replay viewer semantics.

## Output Redaction And Hidden-Info Boundary

Default batch records include compact run facts only: seed, match id, terminal status, winner, counts, final gems, structured error, replay diagnostics, and fingerprints.

Default batch output does not include raw cDp8 `finalState`, `commandLog`, full events, observations, hand arrays, or deck order. `includeRawResults: true` is supported for debugging only. Raw results can contain card instance/source identifiers and must not be treated as a hidden-info-safe ML dataset.

Future ML export still needs explicit observation redaction or hashing, action encoding, legal masks, reward design, and stable export rows.

## Aggregate Metrics Shape

The batch summary includes:

- status counts and seeds by status;
- winner counts;
- completion and max-step rates;
- replay checked and failed counts;
- prompt run and prompt resolution counts;
- average steps, commands, rounds resolved, and legal moves;
- policy ids by seat;
- failure-code counts.

Failure aggregation distinguishes `max_steps_exceeded`, `policy_failed` via policy error codes such as `policy_select_failed`, `engine_error` via engine error codes, and replay failures through `replay_failed`.

## Deviations / Limits

- No CLI or JSONL writer was added.
- No random policy, tournament matrix, worker pool, Elo, reward shaping, observation/action encoding, Python tooling, notebook, or ML export was added.
- Replay diagnostics compare final essentials only; they do not validate every intermediate state.
- The suite is intentionally small and fixed for normal unit-test runtime.

## Risks And Follow-Ups

- Raw debug output remains unsafe for ML export because it exposes final state and command logs.
- Future policies can still max out bounded runs; keep max-step rates visible in every batch entrypoint.
- Prompt coverage currently depends on `sim-smoke-001`; future prompt-heavy suites should pin broader prompt kinds.
- Fingerprints compare compact sequences and summary essentials, not hidden-info-safe observation hashes.
