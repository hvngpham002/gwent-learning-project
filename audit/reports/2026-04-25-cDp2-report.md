# Cluster D Phase 2 Report - Engine UI Shell and Mulligan/Pass Flow

## Summary

Added an opt-in engine-backed UI shell beside the legacy playable app. The default route still renders `ReduxGameManager`; the engine shell renders only when enabled with `?engine=1` or `VITE_ENGINE_UI=1`.

The shell starts an engine match through the Redux engine adapter, displays engine selector view models, supports human mulligan selection, uses a scripted preview AI for zero-card mulligan and pass only, dispatches human pass and round resolution through engine commands, renders generic prompts, and shows game-end/new-game controls without auto-starting another game.

Full card play and strategic AI remain explicitly out of scope.

## UI Flag / Query Behavior

- Default: `http://127.0.0.1:5173/` renders the legacy `ReduxGameManager`.
- Engine shell: `http://127.0.0.1:5173/?engine=1&seed=dp2-smoke`.
- Environment flag: `VITE_ENGINE_UI=1 npm run dev -- --host 127.0.0.1 --port 5173`.
- The flag is not persisted to localStorage.
- The optional `seed` query parameter is passed to `startEngineMatch`; if omitted, the Phase 1 default seed policy remains in place.

## Engine Shell Behavior Implemented

- Starts a match on shell mount only when no engine match exists.
- Uses engine thunks/selectors only for rules and state: `startEngineMatch`, `dispatchEngineCommand`, `resolveEngineRoundEnd`, and `engineSelectors`.
- Does not import legacy `gameSlice`, `gameThunks`, `gameSelectors`, `useReduxAI`, `GameBoard`, `calculateTotalScore`, `calculateRowStrength`, or `src/utils/gameHelpers.ts`.
- Renders both seat statuses, factions/leaders, gems, phase, round, current turn, hand counts, human hand details, AI hand count only, board rows, weather cards, deck/discard counts, and `selectEngineScoreBreakdown` totals.
- Provides human mulligan selection for zero, one, or two cards using engine UI selection state; confirmation dispatches `ChooseMulligan`.
- Provides human `Pass` only when the engine legal moves expose pass.
- Provides `Resolve Round` only when the engine legal moves expose `resolve_round_end`; resolution dispatches `ResolveRoundEnd`.
- Renders `match.pendingPrompt` options generically and dispatches `ChoosePromptOption`.
- Shows game-end winner from engine state and a `New Game` button; it does not auto-new-game.

## Scripted Preview AI Policy

- This is a scripted preview AI, not strategic AI.
- During mulligan, after the human mulligan is complete, it dispatches `ChooseMulligan` for the AI seat with `cardIds: []`.
- During playing, if the AI seat owns the current turn, has not passed, no prompt is pending, and no lock blocks action, it dispatches `Pass`.
- It does not use `useReduxAI`, `AIStrategyCoordinator`, legacy score helpers, timers, or strategic evaluation.

## Deviations / Limits

- `audit/07-ai-integration.md` was listed as required reading but is absent from this checkout. Available audit files and AI code context were used instead.
- Browser click-through smoke was not run; route serving and the required vertical flow were verified through local dev-server checks and Redux/helper tests.
- Ordinary card play, legal row targeting, weather targeting, Horn placement, Decoy selection, Medic revive selection, Scorch targeting, leader use beyond generic prompt display, full card play UI, and strategic AI migration remain out of scope.
- The engine shell uses a small purpose-built engine card tile instead of adapting engine state into legacy `GwentCard`, avoiding legacy score-helper imports.
