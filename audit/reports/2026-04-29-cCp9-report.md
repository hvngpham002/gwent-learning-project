# Cluster C Phase 9 Report - Official Card Rule Gaps (Mardroeme / Berserker / Skellige Storm)

## Summary

Implemented cCp9 by promoting Skellige Storm metadata from `placeholder` to `implemented`, adding special Mardroeme legal `board_row` targets, and adding a centralized pure helper that settles Mardroeme on a row by transforming Berserkers through the controlling seat's side deck. Settlement is hooked into PlayCard, Decoy bounce-and-place, Medic prompt resolution, Muster placement, and Skellige round-three return so Mardroeme/Berserker behavior comes from the engine rather than UI timing.

The Berserker transform link convention reuses the existing `CatalogCardSource.linkedSourceIds` field — the first linked source ID is the replacement source ID that must be present in the controlling seat's side deck. Missing transform links and missing side-deck replacements are explicit `ability_resolved` outcomes (`missing_transform_link`, `missing_transform_replacement`) that do not crash and do not remove the Berserker.

Official porting classification was updated to stop counting Mardroeme, Berserker, and Skellige Storm as unsupported abilities; combined official Berserker scrape candidates remain conservatively flagged with non-rule data issues `transform_link_required` and `catalog_split_required` until promotion. Card Studio validation now blocks non-draft custom Berserkers from being playable when the transform link is empty or unresolved.

No official Game8 candidates were promoted into runtime decks or `currentCatalogCards`/`currentCatalogLeaders`. Leader abilities, Summon, and Avenger remain deferred. No card images were downloaded or committed.

## Behavior Changed

- Skellige Storm catalog metadata reports `implemented`, matching its already-correct legal-move and scoring behavior.
- Special Mardroeme cards now expose three legal `board_row` `play_card` moves targeting the acting seat's own close, ranged, and siege rows; they no longer target the shared weather zone, Special Scorch global slot, or row horn slots.
- Playing a special Mardroeme card to a row places it as a row occupant and immediately transforms every Berserker on that row.
- Playing a unit/hero with the Mardroeme ability triggers row settlement on placement.
- Playing a Berserker onto a row that already has a Mardroeme card transforms the Berserker immediately.
- Reviving a Berserker via Medic onto a row with active Mardroeme transforms it through the same helper.
- Skellige round-three return calls the same helper for each returned card; round-three Mardroeme/Berserker scenarios are no longer ad-hoc deferrals.
- Berserker transform sends the original Berserker to `removed_from_game` (not discard) and brings the linked replacement card from the controlling seat's side deck onto the same board side and row, preserving row position when practical and setting the replacement's controller to the Berserker's controller.
- Two new movement reasons or events are visible in event logs: `card_moved.reason: "mardroeme_transform"` and the new `card_transformed` event including `triggerCardId`, `fromCardId`, `fromSourceId`, `toCardId`, `toSourceId`, `seatId`, `row`, and `abilityId: "berserker"`.
- Missing transform link and missing side-deck replacement now emit explicit `ability_resolved` events with `outcome: "missing_transform_link"` or `outcome: "missing_transform_replacement"`; the Berserker is not removed and the engine does not crash.
- Mardroeme settlement that finds zero Berserkers emits `ability_resolved` with `outcome: "no_targets"` for each Mardroeme source on the row.
- `handoffTurn` in PlayCard still occurs after settlement because settlement is synchronous; no UI timer was added.
- Hidden-information boundaries are preserved: every event uses public source IDs; settle never reads or writes opponent hidden hand or deck identities.

## Mardroeme/Berserker Rule Decisions Implemented

- Mardroeme is treated as an ongoing row ability. Whether a Mardroeme is a special, unit, or hero card, the helper `settleMardroemeRow({ state, events, catalogLookup, boardSeat, row, triggerCardId })` runs after any board entry on the affected row and processes Berserkers on that row.
- Settlement is invoked from: PlayCard `board_row` placement, PlayCard Decoy bounce-and-place, Medic prompt resolution, Muster placement, and Skellige round-three return. Settlement is not invoked from `row_horn` placements (horn slot is not a row occupant) or weather plays.
- Settlement first emits one `ability_triggered mardroeme` per Mardroeme source on the row, then transforms each Berserker, then emits one `ability_resolved mardroeme` per Mardroeme source with `outcome: "transformed" | "no_targets"`.
- Each Berserker that transforms emits a `card_transformed` event plus `ability_resolved berserker outcome: "transformed"`. The `card_moved` events for the Berserker (board_row → removed_from_game) and the replacement (side_deck → board_row) both use `reason: "mardroeme_transform"`.
- Berserker controller policy: replacement uses the Berserker instance's `controller` to choose the side deck; the replacement card lands on the same board side and row as the Berserker; the replacement card's owner is unchanged; the replacement card's controller is set to the Berserker's controller.
- Determinism: settlement snapshots Berserkers in row order and processes them in that order. To support transformed-replacement chains where a replacement happens to also be a Berserker, settlement runs additional bounded passes (limit `16`) over Berserkers that were not visited yet, terminating the moment a pass transforms zero cards or the row no longer contains a Mardroeme.
- Skellige interaction: a transformed Berserker is in `removed_from_game` and is therefore never returned by Skellige round-three return; a transformed replacement that later reaches discard is a normal unit and is eligible for Skellige round-three return; Scorch destroying a transformed replacement sends it to the board-side discard pile per existing rules.
- Medic interaction: revived Berserkers settle through the same helper after Medic places them onto the chosen row.

## Transform Link Convention Used

- Convention: the Berserker's `linkedSourceIds[0]` is the replacement source ID. The replacement instance is found by scanning the controlling seat's `sideDeck` for a card whose `sourceId` equals that linked source ID, taking the first match.
- A new catalog field was not added; `linkedSourceIds` was sufficient. This is consistent with `Muster`/`muster_roach`/`avenger` usage of the same field.
- Card Studio validation requires `linkedSourceIds[0]` to resolve against `currentCards ∪ customCards` for non-draft custom Berserkers; otherwise `playable` is false with structural code `berserker_requires_side_deck`.
- Official porting issues `transform_link_required:berserker` and `catalog_split_required:berserker` flag scrape candidates that lack a transform link or appear to be combined base/replacement rows so promotion remains conservative.

## Deviations From Spec

- Spec section 4 suggested an example shape for `card_transformed` and recommended a `mardroeme_transform` movement reason; both were added with the exact field names from the spec.
- Spec section 3 suggested either `ability_deferred` or `ability_resolved` for missing-replacement cases. The implementation uses `ability_resolved` with explicit outcome strings `missing_transform_link` and `missing_transform_replacement` so consumers can detect the failure without parsing deferred reasons.
- Spec section 7 suggested keeping custom Berserker records draft-only with a clear validation issue if side-deck authoring is not yet supported. Instead, this phase keeps Card Studio Berserker validation tied to the transform-link guard. Custom records can still be saved as drafts; non-draft records require a resolvable `linkedSourceIds[0]`. Side-deck authoring is not added in this phase, so practically a custom Berserker remains saveable but its replacement card must already exist in the catalog or in another custom record before the Berserker becomes playable.
- The settle helper accepts a `triggerCardId` for context (used in the new `card_transformed.triggerCardId` field) but emits its `ability_triggered`/`ability_resolved` events from the actual Mardroeme card sources on the row, not from the trigger card. This is the cleanest mapping to existing event semantics and is documented in the rule-decisions section above.

## Risks / Follow-Ups

- A transformed-replacement card that itself opens a prompt on play (for example, hypothetical Medic on the replacement) is not exercised by current catalog content. The bounded settlement loop guards against infinite loops, but prompts opened mid-settlement would currently be opened in event order. If a future Skellige replacement carries Medic or another prompt-opening ability, a follow-up phase should decide whether to defer settlement until prompts close or to interleave them.
- Card Studio side-deck authoring is still out of scope. Custom Berserkers must reference a known catalog or playable custom card via `linkedSourceIds[0]`; there is no UI to add the replacement to a side deck. Promotion of full custom Skellige decks requires that follow-up.
- `legal-heuristic-v0` AI policy will now see special Mardroeme as a play with three row targets. This is intentional; AI strategy beyond what naturally follows from legal moves is out of scope per the spec.
- Official Berserker scrape candidates remain unpromoted; promotion is the focus of `cBp4` and depends on resolving `transform_link_required:berserker` and `catalog_split_required:berserker` data work.
- `npm run ci` passed after staging the intended cCp9 files. The pre-existing untracked `.claude/` directory and `handoff-alerts/` folder remain outside the commit.
