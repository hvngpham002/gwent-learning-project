# Cluster D Phase 7 Report - Engine Browser Smoke Harness

## Summary

Added a Playwright Chromium smoke harness for the opt-in engine shell. The suite verifies that `/` stays on the legacy app, `/?engine=1&seed=dp6-smoke` supports the current mulligan and first legal card play flow, hidden AI hand details stay out of visible browser text, and the mobile shell avoids horizontal overflow.

## Behavior Changed

- Legacy `/` remains the default route.
- Engine UI remains opt-in through `?engine=1` or `VITE_ENGINE_UI=1`.
- The engine status banner now repeats seed and active AI policy context so browser tests can assert the deterministic harness state in the shell itself.
- Engine shell visible regions and controls now expose stable browser-test selectors without exposing hidden AI card identity.
- Mobile shell layout now uses scoped `box-sizing: border-box`, eliminating the 390px viewport horizontal overflow caught during browser verification.
- CI now has a separate browser gate: `npm run ci` stays the fast local gate, while GitHub Actions installs Chromium and runs `npm run ci:browser`.

## Browser Smoke Coverage

- Default route: opens `/`, asserts the engine shell is absent, and checks broad legacy Gwent content is rendered.
- Engine route: opens `/?engine=1&seed=dp6-smoke`, asserts shell/status/AI seat rendering, completes zero-card human and AI mulligans, selects the first enabled human hand card, clicks the first legal target action, and verifies recent activity records the human play without adapter error.
- Hidden-info guard: asserts the AI seat has hand count only, no AI hand card tiles; recent activity and visible page text do not expose `instanceId`, `sourceId`, or generated `seat_b:000:`-style hidden card IDs.
- Mobile smoke: runs at `390x900`, checks shell/status visibility, confirms no document-level horizontal overflow before mulligan, after mulligan, and after legal target actions appear.

## Hidden-Info Assertion Strength

The browser assertions are stronger than cDp6 helper-only coverage because they inspect rendered visible text after the real UI, Redux adapter, AI effect loop, command summaries, and browser layout all run together.

The guard is still intentionally scoped: it rejects internal identifiers and AI hidden-hand tiles, but it does not ban all AI card names after the AI acts because public board/weather/discard cards may legitimately become visible. This matches the hidden-information rule without creating false failures for public card state.

## Selector Brittleness

Selectors use `data-testid` only on visible regions and direct controls: shell, status banner, seats, controls, human hand, target groups/actions, activity lines, round history, and key command buttons. They avoid class names and hidden state, but they are still coupled to the current button-driven engine shell. A future spatial board or drag/drop UI should revise the selectors around user-visible roles and keep this suite as a smoke-level guard rather than a full interaction contract.

## Playwright Install Issues

Local browser installation writes outside the repository to the Playwright cache under `/Users/viethungpham/Library/Caches/ms-playwright`. In this sandbox, the first `npx playwright install chromium` failed with `EPERM` until explicitly approved. GitHub Actions handles this with `npx playwright install --with-deps chromium`; local contributors should run `npx playwright install chromium` once before `npm run test:e2e`.

Loopback server startup also requires permission in this environment. Non-escalated `npm run ci:browser` failed with `listen EPERM 127.0.0.1:4173`, then passed when the preview server was allowed to bind the fixed Playwright port.

## CI Runtime Concerns

`npm run ci` remains unchanged and fast. The browser gate is separate and runs after it in GitHub Actions. `npm run ci:browser` currently performs another production build before three Chromium tests, so the test runtime is short but CI cost includes browser installation and a second build. If browser coverage grows, the likely next optimization is reusing the existing build artifact or splitting install caching explicitly rather than folding Playwright into `npm run ci`.

## Deviations / Limits

- Browser smoke is not folded into `npm run ci`; it remains in `npm run ci:browser` and GitHub Actions runs it after the fast gate, matching the safer default from the spec.
- Only Chromium is configured.
- The suite does not finish a full game, test drag/drop, add screenshot approval, run a multi-browser matrix, or cover AI-vs-AI simulation.
- The hidden-info assertion checks visible browser text and rendered AI seat structure; it does not inspect every DOM attribute because human hand card titles intentionally include public source IDs for the human’s own cards.

## Risks And Follow-Ups

- Hidden-info: current assertions are meaningful at browser level, but future activity summaries should keep distinguishing hidden AI hand choices from public AI board/discard state.
- Selector brittleness: current `data-testid` hooks fit the button-driven smoke surface; revise them when the engine UI becomes spatial or drag/drop-driven.
- CI runtime: Playwright browser install and the second production build can dominate cold runs even though the test suite itself is small.
- Environment permissions: local browser install and loopback preview binding can require approval in sandboxed environments.
