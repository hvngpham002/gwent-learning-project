# Cluster D Phase 1 Report - Redux Engine Adapter Foundation

## Summary

Added a parallel Redux engine lane beside the legacy playable UI. The store can now hold a pure engine `MatchState`, start a deterministic current-catalog match, dispatch stateful engine commands, record command/event history, surface serializable adapter errors, expose lock/status state, and provide selectors for legal moves, scoring, prompts, and future UI view models.

The live UI migration is explicitly out of scope for this phase. `ReduxGameManager.tsx`, legacy `gameSlice`, legacy thunks/selectors, `useReduxAI`, and legacy card models were not switched to the engine.

## Files Changed

- `src/store/slices/engineSlice.ts`: new serializable engine adapter state, command history, event log, errors, selection state, status derivation, and action locks.
- `src/store/thunks/engineThunks.ts`: new start-match thunk, stateful command thunk, serializable error conversion, and `ResolveRoundEnd` helper.
- `src/store/selectors/engineSelectors.ts`: new engine selectors for match/status/locks/prompts/legal moves/scoring/history/winner/errors plus UI-friendly card, board, weather, deck, discard, leader, and hidden-info view models.
- `src/store/index.ts`: registers the new `engine` reducer while preserving existing `game` and `ui` reducers and existing legacy serializable-check ignores.
- `tests/store/engineAdapter.test.ts`: focused adapter coverage without mounting React components.

## Behavior Implemented

- Default engine startup uses current Northern Realms as human `seat_a` and current Nilfgaard as AI `seat_b`.
- Callers can provide deterministic seeds, match IDs, seat mapping, player IDs, and controller kinds.
- Match startup resets command history, errors, selection state, prompt-derived lock state, event log, and last transaction events.
- Stateful commands call `executeCommand` with `currentCatalogCards` and `currentCatalogLeaders`; Redux does not reimplement rules.
- Applied commands append a serializable command record, append engine events, update `match`, and derive adapter status from engine phase/prompt state.
- Rejected commands append a rejected command record, preserve the current match reference, and store plain `{ code, message, details? }` errors.
- Prompt state is derived only from `match.pendingPrompt`; prompt locks identify owner and prompt ID.
- Presentation locks for animation and AI thinking are available, but no timers were added.
- `ResolveRoundEnd` dispatches through the same command thunk; Redux does not compute round winner, gem loss, cleanup, or game winner.
- Human-facing selectors hide AI hand details by default, exposing only count; a debug selector exposes AI hand card details by name.

## Deviations / Limits

- No live UI migration was performed in this phase.
- No broad serializable-check ignore was added for the engine lane; existing legacy ignores remain unchanged.
- The default live seed uses `Date.now()` only when a caller does not provide a seed. Tests pass explicit deterministic seeds.
- Selector factories such as `selectEngineLegalMovesForSeat(seatId)` are provided for arbitrary seats; non-factory selectors cover the default human and AI lanes.
- Adapter state currently holds in-memory seed, history, and events only; no persistence was added.
