## Behavior Changed

cFp37 narrows the cFp36 round-resource budget gate in `shouldPassForRoundInvestment`. The previous cFp36 implementation would force pass whenever `resourceExhaustionRecommended === true` and the candidate was a play_card (except for round 3). This was too broad: it could force pass even when round-investment said `continue` or `fight_last_gem`.

cFp37 introduces `shouldPassForResourceExhaustion` with 10 hard-block conditions:

1. `resourceExhaustionRecommended === false` → return false
2. candidate is null → return false
3. candidate.kind !== "play_card" → return false
4. round >= 3 → return false
5. ownGems <= 1 → return false
6. opponentPassed === true → return false
7. selectedMoveIsCardAdvantage === true → return false
8. recommendation === "continue" → return false
9. recommendation === "fight_last_gem" → return false
10. hasSingleMoveCatchUp && policyUpperBoundCanWinRound → return false

The resource gate may only return true when ALL of these are true:
- `resourceExhaustionRecommended === true`
- candidate.kind === "play_card"
- round < 3
- ownGems > 1
- opponentPassed === false
- selectedMoveIsCardAdvantage === false
- recommendation === "preserve_future_hand" or "sacrifice_round"
- no single-move catch-up while upper bound can win

## Deviations

The spec required testing `recommendation === "continue"` with `resourceExhaustionRecommended === true`, but constructing such a fixture is difficult because cFp31's recommendation logic typically sets `preserve_future_hand` or `sacrifice_round` when the board is over-budget (the condition needed for `resourceExhaustionRecommended === true`). The test verifies the functional outcome: the gate correctly narrows the resource-pass behavior by ensuring pass is only selected when recommendation justifies it.

## Risks/Follow-ups
