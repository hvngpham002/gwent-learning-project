## Hidden-Info Safety Notes

The artifact layer consumes only `BenchmarkRunResult.records`,
`BenchmarkRunResult.summary`, `BenchmarkRunResult.suite`, and public
diagnostics. It never reads or serializes `unsafeDebugResults`.

Default artifacts exclude raw `MatchState`, `cardsById`, command logs,
full event logs, hand arrays, deck arrays/order, observations,
`ownHand`, `opponentHand`, and raw `seat_a:` / `seat_b:` runtime card
instance ids. Diagnostic messages included in the Markdown report pass
through a small runtime-id and hazard-token redactor.

## Determinism Notes

`latest/` uses stable run id `benchmark-smoke-v1:latest` and contains no
wall-clock timestamp. JSON output is recursively key-sorted before
serialization; JSONL contains one stable public record per line.

Two immediate `npm run benchmark:smoke` runs produced matching artifact
hashes.

## Deviations From Spec

- The implementation handoff left generated artifacts and source changes
  unstaged for review. They are ready for the normal orchestrator
  review-and-commit step.
- The script uses `tsx` to run TypeScript and Vite SSR module loading for
  the benchmark module so existing Vite aliases continue to resolve
  without changing source imports.

## Risks And Follow-Ups

- The generated smoke suite is intentionally small and should not be
  treated as a strength rating.
- Broader matchup matrices, Glicko/TrueSkill, approximate best response,
  search policies, `legal-heuristic-v1`, Python tooling, browser
  benchmark execution, AI Lab artifact loading, and product difficulty
  tiers remain deferred.
- `includeDebugResults: true` still exists on the in-memory benchmark API
  as an unsafe diagnostic escape hatch; the CLI intentionally does not
  expose it.
