# Cluster E Phase 7 Report - In-Game Card Studio And Custom Catalog Workflow

## Summary

Implemented cEp7 for the opt-in authentic UI. Card Studio now supports browser-local custom cards and leaders, live authentic previews, validation, draft/playable saves, JSON import/export, path and local-upload image modes, and integration with deck builder, pre-game, and engine-backed match start.

Custom cards are genuinely playable through engine match start when they use already-implemented abilities. Draft/unplayable custom content can be saved and exported, but it is blocked from playable decks and match start.

No new engine abilities, AI strategy, repository file writes, route promotion, backend service, or Card Studio backend behavior were added.

## Behavior Changed

- Added the authentic Card Studio route at `/?engine=1&ui=authentic&view=card-studio`, with pre-game and deck-builder entry points and back navigation to the prior authentic surface.
- Added browser-local custom catalog storage under `gwent_custom_catalog_v1` with schema `custom-catalog-v1`, normalized reads, corrupt-storage fallback, and in-memory fallback warnings when localStorage is unavailable.
- Added custom card and leader creation, editing, duplication, deletion confirmation, reset, draft save, playable save, library search/filter, and live authentic card/leader preview.
- Added Card Studio validation for source ID shape/uniqueness, faction/kind/row rules, ability applicability, implemented ability status, deck limits, leader faction/ability rules, image validity, and linked-source warnings.
- Implemented image path mode for `/images/...` references and upload mode for PNG/JPEG/WebP data URLs with a 1 MB size guard. Uploaded images remain browser-local and may be exported as data URLs.
- Implemented JSON export schemas `custom-catalog-record-v1` and `custom-catalog-bundle-v1`, selected/all copy/export, pasted/file import, malformed/unknown-schema errors, collision-safe source ID/name suffixing, and intra-bundle `linkedSourceIds` remapping after import renames.
- Merged playable custom sources into deck builder and pre-game source sets. Draft/unplayable custom sources are blocked from deck readiness with explicit validation reasons instead of being silently deleted.
- Updated deck-builder import/export validation to resolve local deck JSON against the explicit current-plus-playable-custom source set.
- Extended `StartEngineMatchOptions` and authentic setup config with runtime `catalogCards` and `catalogLeaders`.
- Stored the active runtime catalog snapshot in the Redux engine adapter, then used it for match start, command execution, legal move selectors, scoring selectors, card/leader view models, and mulligan card resolution.
- Updated `legal-heuristic-v0` AI controller observation/legal-move lookup to use the active runtime catalog, with a current-catalog fallback for older adapter-state fixtures.
- Preserved hidden-info behavior: custom AI hand/deck identities remain hidden from the human view until cards become public through normal engine exposure.

## Deviations

- Card Studio does not author deck presets. Existing deck JSON import/export was only extended enough to validate against the merged custom source set, matching the cEp7 scope boundary.
- Existing built-in current catalog planned/placeholder ability behavior remains warning-only. The stricter playable gate applies to custom Card Studio records.
- Some `currentCatalogCards` / `currentCatalogLeaders` references intentionally remain outside product runtime or as defaults: Card Studio collision/current-catalog merge helpers, deck-builder/pre-game helper defaults for tests and no-custom fallback, component foundation/harness samples, engine adapter no-custom defaults, and the out-of-scope headless simulation/export paths.
- `npm run ci` cannot end cleanly in this working session because `check:worktree-clean` requires no unstaged changes.

## Risks / Follow-Ups

- Card Studio V1 is localStorage-backed. Users should export bundles for backup, especially when using data URL images.
- Uploaded data URLs can make custom catalog JSON large and should be migrated to stable `/images/custom/...` paths before permanent catalog commits.
- Browser smoke covers the short import-to-deck-builder path, not every form branch, delete confirmation branch, or full match with a custom deck. The deeper behavior is covered by helper/adapter unit tests.
- Headless simulation/export custom catalog support remains out of scope.
- New custom ability behavior still requires separate engine/catalog specs before it can become playable.
