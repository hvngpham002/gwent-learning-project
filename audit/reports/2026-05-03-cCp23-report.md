# Cluster C Phase 23 — Shuffle Discards Into Decks Active Leader

- Spec: `docs/spec/2026-05-03-cCp23-specs.md`
- Branch: `dev`
- Date: 2026-05-03

## Summary

cCp23 implements the next narrowly scoped leader-rule tranche from the
cCp18 Leader Ability Matrix: `shuffle_discards_into_decks` for
`skellige.crach-an-craite` (Crach an Craite). It is the fourth Tranche
2 member to land, after cCp20's `double_spies` whole-match passive,
cCp21's `optimize_agile_rows` active one-shot auto-place / tied-row
choice, and cCp22's `restore_discard_to_hand` active one-shot prompt-
based restore.

The implementation follows Pattern 10 from the cCp18 matrix: an active
one-shot leader resolved without any prompt or UI choice. The settled
local rule contract from the spec is honored:

- active one-shot leader, no prompt, no UI choice;
- legal only if at least one seat has at least one card in discard;
- per-non-empty-discard: cards move to that same seat's deck;
- a card moves to the deck of the seat whose discard it currently
  occupies, **not** necessarily back to its original owner's deck (off-
  owner Spy-like cards recycle into the discard-pile seat's deck);
- each affected deck is shuffled with the existing seeded RNG;
- empty-discard seats are not shuffled (no hidden no-op deck mutation);
- removed-from-game, side deck, hand, board, weather, row horn, and
  leader zones are not touched;
- recycled cards do not resolve their abilities — they return to deck
  and behave normally only if drawn and played later;
- deterministic RNG: a single `SeededRng` instance is built from
  `state.rng.seed` / `state.rng.state` and reused across all affected
  shuffles, with `state.rng.state` updated to the RNG's final state at
  the end;
- stable seat order: `["seat_a", "seat_b"]`;
- no deck-order leakage in legal-move metadata, AI observation, or
  event payloads;
- if both discard piles are empty, `getLeaderMove` emits no move and a
  manual `UseLeader` rejects with `EngineRuleError` without setting
  `leaderUsed` or mutating state.

- `src/game/core/leaderDiscardRecycle.ts` — **New.** Pure helper module.
  Exports `DiscardRecycleSeatPlan`, `DiscardRecyclePlan`, and the

## Behavior Changed

Engine pure helper:

- `getDiscardRecyclePlan({ state })` is the new pure plan function.
  Pure, deterministic, stable-seat-ordered output, only-non-empty-seat
  output, skips missing instances safely, no hidden-info reads.

Engine legal moves:

- `getLeaderMove` now emits one no-target `use_leader` move with
  `targetRequirement === "none"`, `targetCount === plan.totalCardCount`,
  and `targetLabel === "discard piles"` when the leader is Crach an
  Craite and at least one seat has at least one card in discard. Both-
  empty discards emit no `use_leader` move. After the leader is
  consumed, no further `use_leader` move is emitted.

Engine command execution:

- `executeLeader`'s `shuffle_discards_into_decks` branch validates the
  target shape (rejects non-`none` targets), recomputes the recycle
  plan, rejects empty-plan execution, then clones state, emits
  `ability_triggered`, and processes affected seats in stable order
  through one `SeededRng` instance built from `state.rng.seed` /
  `state.rng.state`. For each affected seat: cards move to the seat's

  `controller` reset to the destination seat (with `owner` unchanged),
  followed by `shuffleWithRng` and a `deck_shuffled` event with
  `reason === "leader_shuffle_into_deck"`. Empty-discard seats are not
  shuffled and emit no event. After all affected shuffles,
  `state.rng.state` is updated. The transaction emits `ability_resolved`
  with `outcome === "shuffled_discards"`, `leader_used`, sets
  `seat.leaderUsed = true`, and hands off the turn. Recycled cards are
  not "played" — `resolveCardAbilities` is not called and no
  `card_played` event fires.

## Deviations From The Spec

None of substance. Two notes:

1. **Helper input shape.** The spec recommended
   `getDiscardRecyclePlan({ state }: { state: MatchState }):
   DiscardRecyclePlan`. The implementation matches that exactly,
   exposing `GetDiscardRecyclePlanInput` for ergonomics without
   widening the contract. No `catalogCards` parameter was needed
   because the helper does not look up catalog metadata — it returns
   raw card-instance IDs in stable seat order, which is sufficient for
   both the legal-move emitter and the command branch.

2. **`controller` reset before vs after `moveCard`.** The spec allowed
   either ordering. The command branch sets `controller` immediately
   before calling `moveCard`, which mirrors the cCp14 weather-pulling
   leader path and the cCp22 restore-resolver path. `moveCard` itself
   does not touch `controller`; `owner` is left alone end-to-end.

No other deviations. Out-of-scope behaviors
(`draw_opponent_discard`, `random_medic`,
`discard_two_draw_one_from_deck`, `draw_extra_card`,
`look_three_cards`, `cancel_leader`, hidden deck browser, AI strategy
tuning beyond legal-move plumbing, Card Studio work, deck-builder
work, new UI surfaces, legacy Redux/gameplay rule-path changes,
broader shuffle infrastructure beyond what Crach needs) were not
implemented.

## Reporting Notes For The Coding Agent

The spec asked for the report to call out specifically:

- **Whether no legal move is emitted when both discard piles are
  empty.** Yes. The `getLeaderMove` `shuffle_discards_into_decks`
  branch calls `getDiscardRecyclePlan({ state })` and returns `[]` when
  `plan.totalCardCount === 0`. A manual `UseLeader` in that state
  rejects with `EngineRuleError("invalid_target", "Shuffle Discards
  Into Decks has no recyclable discard cards.")` before cloning state,
  so neither `state.seats.<seat>.leaderUsed` nor `state.rng.state`
  changes. Verified by the
  `"emits no use_leader move when both discard piles are empty"` and
  `"rejects a manual UseLeader when both discards are empty (without
  setting leaderUsed or mutating state)"` tests.
- **Whether a single non-empty discard pile is enough to enable the
  leader.** Yes. The legal-move emitter emits exactly one
  `use_leader` move when only the acting seat's discard is non-empty,
  exactly one when only the opponent's discard is non-empty, and
  exactly one when both are non-empty. Verified by the three legal-
  move integration tests in the new suite.
- **Whether unaffected empty-discard seats are not shuffled.** Yes.
  The `executeLeader` branch processes only `plan.seats`, which
  contains only seats whose discard had at least one resolvable card.
  Empty-discard seats are not appended to `plan.seats`, so they are
  not iterated, are not shuffled, and emit no `deck_shuffled`. The
  test `"emits deck_shuffled only for affected seats; an empty-discard
  seat is not shuffled and emits no event"` snapshots the opponent's
  deck order before the command and asserts it is byte-identical
  after.
- **Whether off-owner cards recycle into the discard pile seat's deck
  with owner preserved and controller reset to the destination seat.**
  Yes. The dedicated test
  `"recycles an off-owner card (e.g. a Spy-like fixture in the
  opposite discard) into the discard pile seat's deck, with owner
  preserved and controller reset to the destination seat"` constructs
  a card with `owner: seat_a` physically in `seat_b.discard`, runs
  `UseLeader`, and asserts the recycled card lands in `seat_b.deck`
  with `controller === "seat_b"` and `owner === "seat_a"`.
- **Whether deck order stays hidden from UI / AI / export surfaces.**
  Yes. The new `card_moved.reason "leader_shuffle_into_deck"` event
  carries only `cardId`, `sourceId`, `from`, `to`, and `reason` —
  never deck order. The new `deck_shuffled.reason
  "leader_shuffle_into_deck"` event carries only `seatId` and
  `reason`. Legal-move metadata for the new `use_leader` move
  exposes only `targetCount` (an aggregate count of recyclable
  cards) and `targetLabel === "discard piles"`. No deck instance IDs
  or shuffled order surface in legal-move metadata, AI observation,
  or simulation export rows.
- **Whether RNG state and post-command deck order are deterministic
  for identical pre-command states.** Yes. The dedicated determinism
  block builds two independent scenarios with the same seed, runs
  `UseLeader` on each, and asserts byte-equal `seats.seat_a.deck`,
  `seats.seat_b.deck`, and `rng.state` post-command. The companion
  test verifies that different seeds produce different post-command
  deck orders when the affected deck has enough cards to shuffle.
  Implementation uses one `SeededRng` instance built from
  `state.rng.seed` / `state.rng.state` for the whole command, and
  updates `state.rng.state` to the RNG's final `getState()` after all
  affected shuffles.
- **Whether moved cards return to deck without resolving abilities.**
  Yes. The dedicated test
  `"does not resolve restored Medic / Scorch / weather card abilities
  (no card_played, no Medic prompt, no Scorch destruction, no weather
  zone entry)"` places Yennefer (Medic), the Scorch special, and a
  Frost weather card into the acting seat's discard pile, runs the
  command, and asserts: no `pendingPrompt` (no Medic chain), no
  `card_played` event for any recycled card, no `scorch_resolved`
  event, the Frost card is not in `state.weather.entries`, and all
  three cards land in `seat_a.deck`. The implementation does not call
  `resolveCardAbilities` on recycled cards.
- **Whether any UI or AI compatibility changes were required.** No
  UI changes. The existing leader action button renders the new
  no-target `use_leader` move through the same path it already uses
  for `clear_weather` and the cCp16 row-Scorch leaders. No new CSS,
  modal, prompt, card-tile UI, or test ID was needed. No AI strategy
  tuning beyond compile/type compatibility — `legal-heuristic-v0`
  inherits the new legal move automatically. The
  `tests/components/gwent/authenticMatchViewModel.test.ts` placeholder
  fixture was repointed from Crach an Craite (now implemented) to
  Emhyr var Emreis: Emperor of Nilfgaard with `look_three_cards` so
  the "marks used leaders as used regardless of ability status" test
  continues to assert `inspection.ability.status === "placeholder"`.
