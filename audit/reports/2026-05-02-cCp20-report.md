# Cluster C Phase 20 — Double Spies Whole-Match Passive

- Spec: `docs/spec/2026-05-02-cCp20-specs.md`
- Branch: `dev`
- Date: 2026-05-02

## Summary

cCp20 implements the next narrowly scoped leader-rule tranche from the
cCp18 Leader Ability Matrix: `double_spies` for
`monsters.eredin-breacc-glas-the-treacherous` (Eredin Breacc Glas: The
Treacherous).

The post-cCp18 product decision is authoritative and the spec required
implementation as a **whole-match passive**: while the leader is the
seat's leader, every battlefield non-hero card whose source includes
the `spy` ability receives a ×2 multiplier on every scoring tick, on
both board sides and all rows, regardless of owner / controller, for
the entire match. Hero Spies remain immune (Hero immunity, §17.1).

The implementation mirrors cCp15's King Bran passive and cCp19's
row-horn passives: a pure helper `getDoubleSpiesPolicyBySeat` derives a
per-seat boolean policy from leader source identity, and
`calculateScores` reads the policy to apply a non-stacking ×2 multiplier
between the weather step and the tight-bond step. The score breakdown
records `CardScoreEntry.spyMultiplier` and
`CardScoreEntry.afterSpyMultiplier` for transparency, and the modifier
list adds a distinct `"leader_double_spies"` marker.

The leader emits no `use_leader` legal move, never sets
`seat.leaderUsed`, and never emits a `leader_used` event under normal
play. Manual `UseLeader` attempts continue to raise the existing
`unsupported_command` rule error without consuming the leader.

## Behavior Changed

Engine scoring:

- `calculateScores` now derives a per-seat double-spies policy from
  leader source identity through
  `getDoubleSpiesPolicyBySeat(state, leaders)` whenever a
  `catalogLeaders` array is supplied. The derived policy can be
  overridden by an explicit `doubleSpiesPolicyBySeat` argument,
  mirroring the cCp15 weather override and the cCp19 row-horn
  override patterns.
- Non-hero unit cards whose source includes the `spy` ability receive
  a ×2 multiplier between the weather step and the tight-bond step
  whenever at least one seat has the double-spies policy. Heroes
  remain unaffected as receivers (`hero_immune` modifier is still
  present).
- The score breakdown's `modifiers` list adds the marker
  `"leader_double_spies"` when the multiplier applies.
- The new fields `CardScoreEntry.spyMultiplier` and
  `CardScoreEntry.afterSpyMultiplier` make the factor and intermediate
  strength explicit for transparency and test fixtures.
- The multiplier is non-stacking. If both seats have the policy
  (a fixture-only scenario; no normal game has two Treacherous
  leaders), every Spy is still multiplied ×2, never ×4.
- All score-dependent paths inherit the policy automatically because
  they go through `calculateScores`:
  - Normal score totals and row totals;
  - Round resolution / round winner / Nilfgaard tie / gem loss /
    `roundHistory.scoreBySeat`;
  - Special Scorch target evaluation (uses effective strength per the
    cCp7 pipeline);
  - Unit row-Scorch target evaluation (`scorch_close` / `scorch_range`
    / `scorch_siege` on Toad / Schirru / unit-source whole-board
    Scorch);
  - Foltest row-Scorch leaders — already use `calculateScores` per
    cCp16.

Engine legal moves and commands:

## Deviations From The Spec

None of substance. Two notes:

1. **Helper signature.** The spec recommended
   `getDoubleSpiesPolicyBySeat(state, catalogLeaders)`. The cCp15 King
   Bran helper and the cCp19 row-horn helper both accept only
   `readonly CatalogLeaderSource[]`, so cCp20 follows the existing
   local convention and exposes the new helper with the same simple
   array signature. This is consistent with the spec's "Exact
   signatures may vary to fit local type patterns" allowance and
   keeps `getDoubleSpiesPolicyBySeat` directly callable everywhere
   `getWeatherPolicyBySeat` and `getRowHornPolicyBySeat` are.
2. **Helper export surface.** `getDoubleSpiesPolicyBySeat` is exported
   from `src/game/core/scoring.ts` and reaches the public surface via
   the existing `export * from "./scoring"` in `src/game/core/index.ts`.
   No new entry was added to `src/game/core/index.ts` — the same
   wildcard re-export already covers `getWeatherPolicyBySeat` and
   `getRowHornPolicyBySeat`.

The Foltest row-Scorch leader test that the spec recommended ("Foltest
row-Scorch leader targeting uses double-spies effective strength") was
covered indirectly through the unit row-Scorch (Schirru) test — the
spec's coverage requirement is "Unit row-Scorch and/or Foltest
row-Scorch", and Schirru exercises the same `findUnitScorchRowTargets`
helper that Foltest's row-Scorch leaders consume per cCp16. Adding a
Foltest-specific test would have required setting up a row composition
where `double_spies` causes the row total to cross the 10 threshold
and produce a tied-highest spy target; this was achievable but
duplicates the row-Scorch evaluation path already covered by the
Schirru test and the cCp16 row-Scorch coverage.

No other deviations. Out-of-scope behaviors (`cancel_leader`,
`optimize_agile_rows`, `random_medic`, `restore_discard_to_hand`,

## Risks / Follow-Ups

- **Inspector UI may want all three horn-style modifiers.** Code
  reading `CardScoreEntry.modifiers` to render horn / spy provenance
  should consider `"commanders_horn"` (physical horn, cCp7),
  `"leader_horn"` (cCp19 row-horn passive), and
  `"leader_double_spies"` (cCp20). The existing cEp5.3 inspector
  renders the modifier list verbatim, so it is unaffected, but new UI
  surfaces that hard-code a single modifier name may miss the spy
  case.
- **Cancel-leader interaction deferred.** The double-spies helper is
  structured so a future `seat.leaderCancelled` flag can short-circuit
  the policy without touching scoring math, but cCp20 does not
  implement the cancel state. When `cancel_leader` lands (Tranche 4),
  the helper's first guard should check the cancel flag — same
  approach the cCp19 row-horn helper notes.
- **Hero Spy hypotheticals.** No production hero Spy with non-zero
  strength exists in the current catalog (`neutral.mysterious-elf` has
  strength 0). The cCp20 hero-immunity test uses a small file-local
  catalog fixture (`test.cCp20.hero-spy`, printed 6 hero spy) so the
  hero-immunity path is exercised end-to-end. If a future production
  hero Spy ships with non-zero strength, no engine code needs to
  change — `double_spies` already gates by `!isHero`.
- **Other §C entries from cCp18.** §C-3 (`random_medic` ID misnomer
  description), §C-5 (`look_three_cards` description count), §C-6 /
  §C-9 (Nilfgaard leader source description gaps), §C-8 (Game8 staging
  provenance note), and §C-10 (Witcher Fandom scrape coverage gap)
  remain documentation-only follow-ups for the relevant later tranche
  (most likely Tranche 2's `random_medic` / `look_three_cards`
  implementations).
- **Pre-existing lint warning.** `src/hooks/useReduxAI.ts` still
  reports a `react-hooks/exhaustive-deps` warning. Unrelated to
  cCp20; not surfaced to the cCp20 scope.

## Recommended Next Step

Proceed with the next member of **Tranche 2** from the cCp18 leader
matrix. Recommended ordering, by ambiguity / prompt complexity /
hidden-info exposure:

1. **`optimize_agile_rows`** (Francesca: Hope of the Aen Seidhe) —
   auto-place per the cCp19 settled product decision §3 (catalog
   wording wins; no row-choice prompt). Single command transaction,
   no prompts, no hidden-info concerns.
2. **`restore_discard_to_hand`** (Eredin: Bringer of Death) —
   single-step `choose_card` prompt over the acting seat's discard
   pile. Reuses the existing `pendingPrompt` machinery and the cEp3
   discard browser visuals.
3. **`shuffle_discards_into_decks`** (Crach an Craite) — bulk
   discard-to-deck recycle with a deterministic seeded shuffle. Per
   the settled product decision §10, the leader is unusable when both
   discard piles are empty (no `use_leader` move emitted).
4. **`draw_opponent_discard`** (Emhyr var Emreis: The Relentless) —
   single-step `choose_card` prompt over the **opponent**'s discard
   pile, per the settled product decision §C-2 (catalog wins).
5. **`random_medic`** (Eredin: Destroyer of Worlds — but see §C-3 ID
   misnomer) — passive Medic mutation per the settled product
   decision §5: while the leader is the seat's leader, every Medic
   effect selects a random non-hero unit from the discard pile rather
   than letting the player choose.

Defer multi-step / hidden-info / suppression leaders
(`discard_two_draw_one_from_deck`, `draw_extra_card`,
`look_three_cards`, `cancel_leader`) to Tranche 3 / 4 because they
introduce engine surfaces (multi-stage prompts, observation manifests,
suppression flags) that should not be bundled into the prompt-light
Tranche 2 phases.
