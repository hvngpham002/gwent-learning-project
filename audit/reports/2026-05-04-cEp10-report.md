## Behavior Changed

### Pure View-Model Helpers

- New `buildMatchLedgerViewModel` helper in `matchViewModel.ts` consumes `RoundResult[]`, the engine `winner` (`SeatId | "draw" | null`), public seat gem counts, the `canReturnToSetup` callback flag, and an optional `matchRunKey` (defaulted to `activeMatchKey` so rematch and setup transitions invalidate the dismissal cache). It returns:
  - `key` (`round|round-N|<runKey>` or `match-end|round-N|<runKey>`),
  - `round` number,
  - `kind` (`"round"` or `"match_end"`),
  - `eyebrow` (`round N resolved` for non-game-end, `match concluded · X to Y` for game-end),
  - `title` (`You hold the field.` / `<opponent> holds the field.` / `Neither side yields.` for round; `Victory over <opponent>.` / `Defeat against <opponent>.` / `Draw.` for match-end),
  - `summaryRows` (round only: your-score, opponent, gem-loss-human/gem-loss-ai with `◆ before → after`, or `gem loss: none`),
  - `nextStarterLabel` (`next to lead: <opponent>`),
  - `historyRows` (match-end only: round, humanScore, aiScore, win/loss/draw markers, no card identities),
  - `standingRows` (match-end only: result/rounds/gems from real engine state; `gems: unknown` when data is unavailable),
  - `actions` (round: one `next round →` primary; game-end with setup: `change deck` ghost + `rematch` primary; game-end without setup: `close` ghost + `rematch` primary),
  - `escapeDismisses` (`true` for round only),
  - `humanRoundWins`, `aiRoundWins`, `matchResult`.
- New `buildResolveRoundActionViewModel` helper returns `{ visible, enabled, label, disabledReason }` so the round-end action is not rendered outside `round_end`, the label stays compact (`resolve round`), and the disabled state is explained inline (`prompt pending`, `waiting for opponent`, `waiting for round resolution`) without introducing a second action panel.
- Existing `buildRoundOverlayViewModel` and `buildGameEndNavigationActions` are kept for backward compatibility (their unit tests are unchanged); the production `RoundOverlay` no longer reads them.

### `RoundOverlay` Component

- `RoundOverlay` now consumes a single `MatchLedgerViewModel`. The component is purely declarative: it renders the eyebrow, title, summary rows, next-starter label, history rows, standing rows, and action buttons exactly as the view-model dictates and never derives win/loss state, score, gem loss, or next starter from board cards or events.
- The dialog wrapper keeps `role="dialog"` and `aria-modal="true"`, and now sets `aria-labelledby="authentic-round-overlay-alert-title"` to tie the accessible name to the rendered ledger title (the Alert component renders the `<h2>` with that id via its `testId` prefix).
- For non-game-end ledgers the component installs a `keydown` listener that dismisses on `Escape`. Match-end ledgers do not install the listener because the same outcome (`rematch` / `change deck` / `close`) is only reachable through the explicit action buttons.
- Click-outside (the modal scrim area) is intentionally inert: there is no overlay handler that dispatches a gameplay command. Game-end dismissal does not destroy the underlying engine match state, so the final standing remains inspectable in the right rail.

### `ActionPanel` Component

- The right-rail action panel now consumes the `ResolveRoundActionViewModel`. When the engine is in `round_end` and exposes a legal `resolve_round_end` move, it renders one primary `resolve round` button that dispatches `resolveEngineRoundEnd(humanSeat)` exactly. When the engine is not in `round_end`, the action is not rendered at all (no stale copy). When the action is visible but disabled, a single compact reason line (`authentic-resolve-round-reason`) explains why; no second action panel is added.

### Dismissal Lifecycle

- `dismissedRoundOverlayKey` is cleared in three places that already cleared related ephemeral state: the initial `setupConfig`/`activeSetupKey` effect, `startNewGame` (rematch), and `returnToPreGame` (setup). Because the ledger key now incorporates `activeMatchKey` (which embeds `matchPresentationRun`), rematch deterministically reopens the overlay for the new match's first resolved round even if a state reset is missed.
- Dismissing the round ledger only sets the dismissed-key state. It does not dispatch any engine command, mutate any selector, hide the actual `roundHistory`, or re-trigger round resolution.

## Acceptance Criteria Status

- Round-end action remains engine/legal-move-driven: met. The resolve-round action only appears when `match.phase === "round_end"`, respects `canResolveRound` (the `humanMoves.some(move => move.kind === "resolve_round_end")` flag), and dispatches `resolveEngineRoundEnd(humanSeat)` exactly.
- Non-game-end round ledger clearly shows outcome, scores, gem loss, next starter, and one `next round →` dismissal action: met by `buildMatchLedgerViewModel` summary rows, `nextStarterLabel`, and the single-primary action list.
- Match-end ledger clearly shows outcome, real round history, real standing, and correct `rematch` / `change deck` / `close` navigation: met. History rows come from `RoundResult[]`; standing rows come from `winner`, `roundHistory` counts, and public seat gem counts only.
- Round overlay dismissal does not mutate engine state and does not reopen for the same round: met. Dismissal only updates `dismissedRoundOverlayKey` local state, the engine event log and round history are unchanged, and the ledger key is stable for a given round within a match run.
- Rematch and setup/change-deck clear stale overlay state and return through the expected authentic flow: met. `startNewGame`, `returnToPreGame`, and the active-setup-key effect each clear the dismissed-overlay key, and the key now embeds `activeMatchKey` so rematch keys diverge even before the explicit reset runs.
- No hidden AI hand/deck identities are rendered: met. The new tests assert no card source IDs, instance IDs, or hidden hand names appear in any ledger field, and the round/match ledger surfaces only public scores, gem counts, round results, and seat labels.
- `docs/PROJECT_STATE.md`, `docs/ui/authentic-product-flow.md`, and the phase report are updated: met.

## Deviations

- `docs/overhaul-plan/cluster-e-ui-plan.md` was not edited. The cEp10 description in that file already matches the implemented scope (round resolution polish, match-end ledger polish, navigation polish, no engine changes). The next phase ordering is unaffected.
- The legacy `buildRoundOverlayViewModel` and `buildGameEndNavigationActions` helpers remain exported for backward-compat with their existing focused tests. The production `RoundOverlay` consumes the new `buildMatchLedgerViewModel` helper exclusively.
- Match-end Escape dismissal is intentionally not wired. The same outcome (`rematch` / `change deck` / `close`) is only reachable through visible buttons, and silent Escape dismissal would put the user back at a frozen final board with no obvious next action; explicit buttons stay required.
- Click-outside dismissal is not implemented for either ledger because the existing authentic match modal vocabulary does not have a click-outside dismissal path (the `LookThreeCardsRevealDialog`, `DiscardBrowser`, and inspect modals all require explicit close buttons). Adding it asymmetrically to the round ledger would surprise users.

## Risks / Follow-Ups

- A deterministic match-end ledger browser smoke would tighten coverage. The current Chromium smoke does not play a full Bo3 to game end, so the match-end branch of the ledger is exercised only in unit tests and manual play. A future phase could add a long seeded match-end smoke once the AI policy or fixture decks make it tractable.
- The right-rail informational `Round End` panel and `Game End` panel are intentionally kept (per spec point 2 about not introducing a second action panel; they are display-only). A later product polish slice could fold them into the ledger or remove the redundancy.
- Click-outside dismissal across the match modals (`LookThreeCardsRevealDialog`, `DiscardBrowser`, inspect modals, round ledger) could be unified in a separate authentic-modal accessibility phase. cEp10 keeps existing behavior to avoid regressions.
