## Behavior Changed

- **No-target Medic delay penalty:** When a Medic with zero revive candidates is selected as a play_card move AND a useful non-Medic line exists (score >= 25) AND no tactical exception applies, a -260 delay penalty is applied to the Medic's score.
- **Round-investment analysis (conditional compensation):** Medic scores are adjusted (+260) in `positiveUnitSourceCardIds` computation ONLY when `shouldApplyNoTargetMedicDelayPenalty(features, move)` returns true. Medic cards that do not trigger the cFp39 penalty (e.g. no useful non-Medic line exists) are scored at their raw `scoreMove` value for this computation. This prevents the timing penalty from indirectly distorting round-investment decisions for non-Medic plays.
- **Emergency Medic exception (ordering):** A Medic play that clearly puts the AI ahead when behind is allowed before the resource exhaustion gate. This exception is placed before `shouldPassForResourceExhaustion` in `shouldPassForRoundInvestment` so emergency Medic tempo plays are never blocked by resource exhaustion.
- **Six exceptions** to the delay penalty: only play, last-gem catch-up, match-winning, round-3 low hand, opponent passed, and no useful non-Medic line.

## Behavior NOT Changed

- Engine rules, legal move generation, command execution
- Prompt UI, product routes, catalog data, deck presets
- Benchmark suite definitions, v0 behavior
- Medic prompt-based target ranking
- Strong revive-target Medic behavior

## Risks / Follow-ups

1. **Penalty magnitude calibration:** `MEDIC_NO_TARGET_DELAY_PENALTY = 260` is a new constant. If future scenarios show Medic being too aggressively delayed or not delayed enough, this value may need tuning.
2. **Conditional Medic score adjustment:** The +260 compensation is now gated behind `shouldApplyNoTargetMedicDelayPenalty`. This is correct but creates a dependency between round-investment analysis and the delay-penalty logic. If the delay-penalty exceptions change, the compensation path may need to be reviewed.
3. **Failure mining top queue:** `medic_no_target_timing` remains in the failure mining top queue (rank 3, count 4). This is expected — cFp39 reduces findings from 5 to 4 but does not eliminate them. The remaining 4 findings are all no-target Medic selections from `official-nilfgaard-starter` that still pass through exception gates.
