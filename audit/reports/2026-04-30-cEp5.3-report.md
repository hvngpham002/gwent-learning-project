# Cluster E Phase 5.3 Report — In-Match Card Inspection

## Summary

`docs/spec/2026-04-30-cEp5.3-specs.md` is implemented end-to-end. The authentic match screen now ships read-only in-match card and leader inspection. Right-clicking a visible card surface opens a small `inspect`-only context menu, and selecting `inspect` (or pressing the right-rail `inspect details` button on the selected human hand card) opens a read-only modal that shows the full card profile plus current match context. Right-clicking either score-card leader opens a leader-specific inspect modal.

Existing left-click gameplay is unchanged. AI hidden hand/deck card identities are not exposed in normal product routes. No engine rules, legal moves, AI policy, deck validation, or asset paths were modified. The user-modified `public/images/scoiatael/Elven_Skirmisher.png` is untouched.

## Behavior Changed

- Right-clicking a visible card surface (human hand card, public board unit card, row horn card, public weather card, public discard browser card, Medic prompt option card with a known target) opens a small context menu with a single `inspect` action.
- Right-clicking either score-card leader opens a leader-specific context menu with a single `inspect` action.
- Selecting `inspect` opens a read-only modal:
  - Card modal: large `AuthenticCard` (size `lg`), source ID, instance ID, faction, kind, rows, deck-side facts (origin, side, board row when relevant), printed strength for unit/hero cards, effective strength + state + modifier list for board cards, tags, image path, and a complete abilities list with display name / status / glyph / description.
  - Leader modal: `AuthenticLeaderCard` (size `match`), source ID, faction, ability name, ability status (`used` overrides `placeholder`/`planned`/`implemented`), side label, ability description, and image path.
- The existing right-rail `InspectorPanel` keeps its compact summary and now shows an `inspect details` button when a human hand card is selected; the button opens the same read-only modal as the context menu.
- The card context menu, leader context menu, card inspect modal, and leader inspect modal close on `close`, click-outside (overlay), `Escape`, `inspect`, opening another menu, rematch, or setup return.

Existing left-click gameplay is preserved exactly:

- Human hand left-click still selects/deselects through `engineSelectedCardSet`.
- Board row left-click still dispatches row target moves; board card left-click still dispatches `card_instance` target moves; right-click never triggers a target click because the handler calls `event.stopPropagation()` and `event.preventDefault()`.
- Discard pile buttons still open/close the discard browser; right-click on cards inside the browser does not close the browser.
- Medic prompt left-click still chooses the prompt option; right-click on a prompt option card opens inspect without resolving the prompt.
- The leader use, pass round, resolve round, and setup/rematch buttons are unchanged.

## Deviations From Spec

- The spec listed optional stable selectors `authentic-match-card-context-menu`, `authentic-match-context-inspect`, `authentic-match-card-inspect`, `authentic-match-inspect-source-id`, `authentic-match-inspect-instance-id`, `authentic-match-inspect-effective-strength`, and `authentic-match-inspect-modifiers`. All seven are implemented. Two additional leader-specific selectors were added (`authentic-match-leader-context-menu`, `authentic-match-leader-context-inspect`, `authentic-match-leader-inspect`, `authentic-match-leader-inspect-source-id`, `authentic-match-leader-inspect-close`) so the leader inspect surface has equally stable hooks; the smoke uses them.
- Per the spec's "no visible buttons if they crowd the match table" guidance, no visible context-menu trigger button (`⋯`) was added on each card. Right-click and long-press on touch devices are the inspect entry points. A future polish pass can add an opt-in trigger button with a non-colliding ARIA name without disturbing the existing smoke selectors.
- The spec recommended either extracting a shared `AuthenticCardInspectModal` component or keeping the modal match-specific. cEp5.3 keeps the modal match-specific to avoid entangling deck-builder add/remove semantics with the match surface; the CSS namespace mirrors the deck-builder vocabulary so a later shared-component refactor stays cheap.
- Leader inspection is included rather than deferred. Leaders have a separate view-model helper and modal because their data shape (single ability, no rows/strength) differs enough from card inspection to share the modal cleanly.

## Risks / Follow-Ups

- The card context menu currently offers only `inspect` (per the spec "do not add deck-builder actions such as add/remove in the match screen"). When the future leader-ability specs land, the leader menu may want a `use leader` shortcut alongside `inspect`; this is tracked as a follow-up.
- Inspect modals reuse `Escape`/click-outside without a focus trap. The existing handoff modals use the same approach and the modal returns focus to the body on close. If accessibility hardening becomes a priority, the shared `Alert` primitive could be layered on later.
- The match context menu and inspect modal CSS lives next to the existing `authentic-match.css` styles. Extracting a shared `AuthenticCardInspectModal` between deck builder and match remains a deferred cleanup.
- The smoke covers hand, leader, and board inspection. Discard inspection is covered by unit tests and `data-source-id` wrappers on the discard card surface. Weather and Medic prompt inspection are covered by unit tests; they are not yet exercised by the smoke because doing so deterministically would require additional gameplay setup. This matches the spec's "If discard inspection requires too much brittle gameplay setup, document the deviation and cover discard inspection with component/unit tests instead." guidance.

## Hidden-Information Notes

- Hand context menus are wired to `<HandStrip>` only, which renders from `selectEngineHumanHand`. AI hand backs use `AuthenticCardBack` and never expose an `EngineCardViewModel` in the runtime card lookup, so right-click on an AI back has no inspectable target through normal product routes.
- Public board cards, weather cards, and discard browser cards are public information per the engine selectors. Their inspect modal shows the same source/instance IDs that already appear in the engine view-model output.
- The smoke includes a final `expect(matchPageText).not.toMatch(/instanceId|sourceId|seat_b:\d{3}:|seat_a:\d{3}:/)` after the inspect modal is closed, asserting no raw debug strings or hidden-side instance IDs appear in the visible product text.
- The `debugAiMulligan=1` route remains as-is. cEp5.3 does not extend it.
