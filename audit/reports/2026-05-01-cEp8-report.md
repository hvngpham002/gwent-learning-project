# Cluster E Phase 8 Report — Weather Leader Choice UI

This phase implements the authentic match UI for leaders that expose more than
one legal `use_leader` move, starting with Eredin: King of the Wild Hunt
(`play_any_weather`). It implements `docs/spec/2026-05-01-cEp8-specs.md`.

## 1. Executive Summary

cCp14 already emitted one hidden-info-safe `deck_card_source` legal move per
eligible weather source for `play_any_weather`. The authentic match screen,
however, collapsed every legal `use_leader` move to `leaderMoves[0]`, so
Eredin always fired the first engine-sorted weather target without user
choice. cEp8 closes that UI gap without changing the engine contract.

The phase adds:

- A pure `buildLeaderActionViewModel(moves)` helper in
  `src/components/gwent/matchViewModel.ts` that classifies `UseLeaderMove[]`
  into `"none" | "single" | "choice"` while preserving engine legal-move
  order.
- A compact authentic-styled choice menu rendered inline near the existing
  leader action in `AuthenticMatchScreen.tsx`. The menu only appears when
  more than one legal `use_leader` move is available; single-action leaders
  still dispatch directly through their existing `use leader` button.
- Focused CSS hooks in `src/components/gwent/authentic-match.css`.
- 7 focused unit tests in `tests/components/gwent/authenticMatchViewModel.test.ts`.
- One Playwright Chromium browser smoke in `tests/e2e/engine-shell-smoke.spec.ts`
  exercising a real `play_any_weather` match path.

No engine rule, legal-move generation, command execution, AI policy,
simulation engine, deck-builder, Card Studio, official porting, or catalog
promotion changes were required.

## 4. Behavior Changed

### 4.1 Leader action classification

`buildLeaderActionViewModel(moves)` is the new product-side contract:

- 0 legal `use_leader` moves → `{ kind: "none" }`.
- 1 legal `use_leader` move → `{ kind: "single", option }`.
- 2+ legal `use_leader` moves → `{ kind: "choice", options }`, in the order
  the engine emitted them. cCp14 already sorts `play_any_weather` moves
  Frost → Fog → Rain → Storm; the helper does not re-sort or dedupe.

Each option carries `moveId`, the original `UseLeaderMove`, a label, and
optional `sourceId`/`targetCardName`/`ability` metadata. The label fallback
is `metadata.targetCardName → metadata.targetLabel → target.sourceId
(deck_card_source) → move.label`. Raw deck instance IDs cannot reach the
label because legal-move metadata never carries them.

### 4.2 Authentic match action panel

- No-target leaders (Foltest Lord Commander `clear_weather`, Foltest
  row-Scorch leaders `scorch_range`/`scorch_siege`) and single-source
  weather leaders (Foltest King of Temeria `play_fog`, Francesca
  Pureblood Elf `play_frost`, Emhyr His Imperial Majesty `play_rain`)
  continue to render a single `use leader` button that dispatches the
  legal move directly.
- When `play_any_weather` (or any future leader emitting multiple legal
  `use_leader` moves) yields a `"choice"` view model, the trigger label
  becomes `choose weather` and clicking it opens the inline popover. The
  trigger advertises `aria-haspopup="menu"` and the appropriate
  `aria-expanded` / `aria-controls` values while the menu is open.
- Selecting an option dispatches the exact `UseLeader` command using that
  move's `target` (e.g. `{ kind: "deck_card_source", seatId, sourceId }`)
  and closes the menu. The single-action path also routes through the same
  selected-move dispatch helper so direct and choice actions cannot diverge.
- The menu closes on selection, click-outside (window `mousedown` listener
  scoped via the leader-action container ref), Escape, the leader becoming
  disabled (`choiceMenuOpen: leaderChoiceMenuOpen && !disableLeaderAction`),
  or the legal-move classification leaving `"choice"` (e.g. on round
  resolution or a leader becoming used).

### 4.3 Hidden information

The authentic match screen still reads only `selectEngineLegalMovesForHuman`
to derive the leader action. cCp14's `deck_card_source` shape exposes only
the catalog source ID and acting seat, never raw deck instance IDs. The
fallback labels never reach `seat_[ab]:\d{3}:` ID territory because no
metadata channel surfaces them. The browser smoke continues to assert the
existing `instanceId|sourceId|seat_b:\d{3}:|seat_a:\d{3}:` pattern is
absent from visible page text after the human leader action.

### 4.4 Targets that do not change

- Pure engine legal-move generation, `getLeaderMove`, and the
  `deck_card_source` target shape are unchanged.
- `executeLeader` is unchanged; the choice menu dispatches the same
  `UseLeader` command shape it always dispatched.
- AI policy is unchanged. `legal-heuristic-v0` continues to pick whichever
  legal `use_leader` move it prefers without UI involvement.
- Catalog promotion, official porting, deck builder, Card Studio,
  simulation export/JSONL boundary, and the legacy `/` route are
  untouched.
- Eredin/Emhyr tutor/restore placeholder leader rules remain placeholder.
- Animation polish beyond the simple open/close affordance was avoided per
  the spec's hard scope boundary.

## 7. Deviations From Spec

None. Notes worth flagging without being deviations:

- The spec mentioned `commandForMove` as a possible existing pattern. No
  such helper exists in the current shell — the existing diagnostic shell
  builds command shapes inline. cEp8 instead introduces
  `dispatchLeaderMove(move)` inside `AuthenticMatchScreen.tsx` to keep the
  selected-move dispatch path unified.
- The browser smoke uses a small fixed seed list and a seeded
  `local-eredin-cep8` Monsters deck rather than relying on the catalog's
  Official Monsters Starter, because that starter ships only Frost + Fog.
  Adding Rain + Storm to the local deck made it far more likely a
  deterministic seed leaves at least two distinct eligible weather sources
  in deck after the initial draw. The seed loop is bounded (5 seeds) and
  deterministic; no random behaviour is introduced.

## 8. Risks / Follow-Ups

- No engine, AI, simulation, or hidden-info regressions are introduced.
- The choice helper is generic. Future leader rules that emit multi-target
  legal moves with their own target shapes (e.g. tutor-style leaders that
  pick from hand or discard) will pass through the same helper. The label
  fallback chain works for any current `LegalMoveTarget` because it ends in
  `move.label`. Distinct target families may want their own labelling
  refinements in later phases, but cEp8's contract does not block that.
- AI policy still picks whichever legal `use_leader` move it prefers.
  `legal-heuristic-v0` does not have weather-leader-aware preference; this
  was deferred by cCp14 and is unaffected by cEp8.
- The seed list in the smoke is bounded for determinism. If the engine's
  deck-shuffle behaviour or the local-deck schema changes, the list may
  need revisiting. The existing `npm run ci:browser` gate will catch that.
- Two `it.todo` placeholders remain in `tests/catalog/linkedAbilityInvariants.test.ts`,
  scoped to placeholder leader tutor/restore effects. Promoting those is
  the recommended next implementation work.

## 9. Recommended Next Implementation Step

Per the spec's own recommendation:

1. **Eredin / Emhyr tutor / restore placeholder leader rules** —
   `discard_two_draw_one_from_deck`, `restore_discard_to_hand`,
   `double_spies`, `optimize_agile_rows`, `double_close`, `double_ranged`,
   `draw_extra_card`, `shuffle_discards_into_decks`. Would let the final
   remaining `it.todo` become an active engine regression. cEp8's choice UI
   helper will surface these once they emit multiple legal `use_leader`
   moves; per-leader prompt UI may still be needed for tutor-style targets
   that pick from hand/discard.
2. **Gameplay polish pass around leader action discoverability** once more
   leader types are executable (out of scope for cEp8).
