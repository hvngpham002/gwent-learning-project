## Effective Strength Notes

Board effective strength is sourced only from `selectEngineScoreBreakdown`.
`matchViewModel.ts` builds a score-entry lookup keyed by engine card instance id
and maps board unit cards to `finalStrength`, `printedStrength`, `strengthState`,
and scoring modifiers. Hand, discard, weather, and prompt cards continue to use
printed strength. If a board card has no score entry, the UI falls back to
printed strength; that fallback is covered by helper tests.

## Discard Browser Notes

Both public discard piles open a modal browser grouped as Heroes, Close Combat,
Ranged, Siege, Specials, and Other. Empty piles show a quiet empty state. Closing
the browser is local UI state only. Discard cards render with printed strength,
not effective board strength.

Spy cleanup and Scorch discard-side behavior were not changed in this phase.
The browser reads the engine discard piles, so Spy/Scorch public discard
placement follows the already-fixed engine behavior from the
`spy-round-cleanup` and `battlefield-discard-side` reports.

## Prompt And Target Notes

Human prompt options continue to come only from legal `choose_prompt_option`
moves. Medic prompts render option cards and metadata from public discard lookup
and dispatch the exact legal prompt command. AI-owned prompts render a pending
message and do not expose hidden AI hand/deck data.

Decoy is handled through legal `play_card` moves with `card_instance` targets:
visible targets are highlighted/clickable on board cards, and the action-panel
buttons remain as fallback.

## Round Overlay Notes

The overlay maps the latest engine `roundHistory` entry to product copy:
round number, final score, winner/draw, gem loss, next starter, and game-end
winner/draw when present. It does not compute round results and does not dispatch
`ResolveRoundEnd`. Dismissal is local UI state.

## Animation Hook Notes

Recent public `card_moved` events add `data-card-motion` values for `played`,
`discarded`, `prompt-revived`, and `scorched`. These hooks only affect styling;
they do not add timers, delay AI, delay prompts, or sequence engine rules.

## Browser Smoke Details

The browser smoke covers default legacy route, diagnostic shell, authentic
harness, and the authentic match route at `ep3-smoke`. The match smoke opens
both discard browsers, verifies the empty public discard state, completes
mulligan, plays a card, verifies effective-strength markers, observes AI action,
passes, checks hidden-info text, and checks mobile overflow with the discard
browser open.

The smoke does not cheaply force Medic, Decoy card-instance targeting, or a
resolved round overlay. Those are covered by focused helper tests and remain
good candidates for a future deterministic scenario harness.
