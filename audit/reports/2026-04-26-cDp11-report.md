# Cluster D Phase 11 Report - Safe Export Validation And JSONL Boundary

## Summary

Added runtime validation and deterministic in-memory JSONL serialization/parsing for `sim-export-v1`.

This phase keeps the cDp10 export contract pure and hidden-info-safe while making misuse easier to catch before data leaves memory. No engine rules, legal move behavior, AI strategy, UI behavior, filesystem writer, CLI, Python bridge, tensorization, model training, storage, compression, or reward shaping changed.

## Validation API Shape

Public exports:

```ts
validateSimulationExportDataset(value, options?): SimulationExportValidationResult
assertValidSimulationExportDataset(value, options?): asserts value is SimulationExportDataset
```

Options:

- `allowSystemActions`: defaults to `true`; `false` rejects system rows and `resolve_round_end`.
- `requireNoWarnings`: defaults to `false`; `true` makes warnings invalidate the result.

Validation checks top-level schema/generator metadata, seeds, policies, row/match counts, summary consistency, row id uniqueness, row scalar fields, observation/action/reward schema versions, legal action counts/masks, row-local action ids/indexes, chosen action alignment, terminal reward values, final gem counts, and system-action policy.

## JSONL API And Record Shape

Public exports:

```ts
SIMULATION_EXPORT_JSONL_SCHEMA_VERSION = "sim-export-jsonl-v1"
serializeSimulationExportDatasetToJsonl(dataset, options?): string
parseSimulationExportDatasetJsonl(jsonl): ParseSimulationExportJsonlResult
```

Default serializer behavior:

- validates first;
- emits one `dataset_header` record;
- emits one `decision_row` record per dataset row;
- uses `\n` separators with no required trailing newline;
- keeps records in deterministic field order by constructing stable record objects.

Parser behavior:

- parses JSONL in memory;
- ignores one trailing blank line;
- returns structured issues for malformed JSON, unknown record type, missing header, row-count mismatch, schema-version mismatch, and reconstructed dataset validation errors;
- reconstructs a `SimulationExportDataset` when a header exists.

## Redaction Checks Implemented

The recursive scanner flags:

- forbidden keys: `finalState`, `commandLog`, `cardsById`, `instanceId`, `moveId`, `rawResult`, `ownHand`, `opponentHand`;
- raw event arrays;
- `deck` arrays;
- raw generated instance id strings matching `seat_a:` or `seat_b:`;
- raw engine action refs starting with `play:`, `mulligan:`, or `leader:`;
- opponent `cardsInHand`;
- own/opponent deck arrays;
- prompt `targetStrength` without visible `target`.

Safe fields such as `sourceId`, `deckCount`, opponent `cardCountInHand`, and acting-seat `own.cardsInHand` remain allowed.

## Deviations / Limits

- No runtime schema library was added; validation is hand-written and contract-focused.
- Validation is not a replay checker and does not prove game correctness, legal-move correctness, strategic quality, reward quality, or cross-version compatibility.
- JSONL serialization is in memory only; there is no writer, CLI, Python bridge, storage format, compression, upload path, or learner integration.
- The `sim-export-v1` row shape was not changed.
- Parser returns a reconstructed dataset when a header exists even if validation issues are present, so callers can inspect partial malformed input.

## Risks And Follow-Ups

- Future file writing needs explicit storage/versioning policy and should keep raw cDp8 debug outputs out of exported JSONL.
- Per-row legal action lists still need a later tensorization/action-vector design before model training.
- Reward placeholders remain sparse terminal outcomes only.
- Validation may need additional allowed/forbidden fields if future safe observation shapes expand.
