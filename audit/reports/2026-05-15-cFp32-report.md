## Behavior Changed

- v1 now passes (stop-loss sacrifice) in non-elimination rounds when:
  - behind (`scoreDelta < 0`),
  - no single-move catch-up exists,
  - `policyUpperBoundCanWinRound === false` (or last useful unit would be burned),
  - hand count ≤ 4 (or weathered low-tempo placement, or medium-or-worse Medic target).
- The Trace 9-style diagnostic anchor pattern (behind by ~12, 4 cards in hand, no catch-up, upper-bound cannot win) now triggers `pass` with `recommendation: "sacrifice_round"` instead of playing a card into a lost round.
- Explanation traces show `"stop-loss — sacrifice round — ..."` reason strings with `reasonKind: "policy-round-investment"`.

## Diagnostic Anchor Summary

The motivating pattern came from `gwent-diagnostics-ep4-mp6cglwp.json`:
- Round 1, `ownScore: 28`, `opponentScore: 40`, `scoreDelta: -12`
- `ownHandCount: 4`, `ownGems: 2`, non-elimination round
- `hasSingleMoveCatchUp: false`, `policyUpperBoundCanWinRound: false`
- v1 chose to play a card instead of passing
- cFp32 makes this pattern trigger a stop-loss pass

## Repair: Review Blocker Fixes (2026-05-15)

Two review blockers were addressed post-cFp32 implementation:

### Fix 1: `use_leader` suppressed by stop-loss

- **Problem:** `shouldPassForRoundInvestment` checked `analysis.stopLossRecommended` for all candidates, including `use_leader`. Since `use_leader` is a free action that doesn't spend a hand card, stop-loss should not suppress it.
- **Fix:** Added `&& candidate.kind === "play_card"` guard to the stop-loss return in `shouldPassForRoundInvestment` (`legalHeuristicPolicyV1.ts`).
- **Test:** Added `"use_leader remains selected when stop-loss conditions are met"` regression test (cFp32 test #11).

### Fix 2: Weathered-row reason evaluated wrong row

- **Problem:** The weathered-row reason detection in `buildLegalHeuristicV1RoundInvestmentAnalysis` iterated over all `playMoves` for the same `sourceCardId`, checking if ANY row option was weathered. For agile/multi-row cards, the selected move might target a non-weathered row while another option was weathered, causing incorrect `weathered_low_tempo` reasons.
- **Fix:** Replaced the loop with a direct check on `selectedMove.target` — only evaluating the selected move's actual target row (`legalHeuristicPolicyV1.ts`).
- **Test:** Added `"agile card selected for non-weathered row does not trigger weathered stop-loss reason"` regression test (cFp32 test #12).
