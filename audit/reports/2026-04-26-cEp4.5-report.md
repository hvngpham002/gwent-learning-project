# Cluster E Phase 4.5 Report - Pre-Game Visual Fidelity Follow-Up

## Summary

Implemented the narrow cEp4.5 visual follow-up. The authentic pre-game route keeps
the cEp4 setup behavior, but now reads much closer to the handoff's tactical table
composition: centered parchment surface, strong paper top/bottom bars, two balanced
panels, larger horizontal deck tiles, 2x2 mode tiles, opponent/round/format/seed
controls, and a stronger Begin Match action. The match score-card leader frame now uses the
foundation medium card dimensions on desktop.

## Visual Fidelity Changes

- Reworked the pre-game surface into a centered 1200-ish by 780-ish table with
  top bar, scrollable two-column body, and bottom action bar.
- Added a restrained 120px parchment dot/grid flourish using CSS gradients.
- Reworked deck options into prototype-shaped horizontal tiles with a shared
  small leader thumbnail, compact deck copy, and optional selected checkmark.
  Deck tile copy is limited to deck name, faction label, and readiness line.
- Added the full-width disabled deck-builder placeholder at the bottom of the
  deck panel.
- Changed the visible enabled mode label to `Casual`, while preserving the
  underlying `human-vs-ai` setup and `legal-heuristic-v0` policy.
- Reworked mode tiles into a desktop 2x2 grid with compact glyph, display name,
  11px-scale description, and availability note.
- Reduced and normalized pre-game text scale: 22px top title, 18px deck names,
  16px mode names, 11px descriptions, and 9-10px mono labels/notes, with the
  top ghost buttons kept at the prototype's compact 11px scale.
- Removed inherited uppercase/letter-spaced button typography from utility
  buttons, nested mode content, seed copy, and the format segmented controls so
  labels wrap and fit consistently.
- Scoped pile count typography to direct children so discard pile count styling
  no longer leaks into nested `AuthenticCard` strength/nameplate spans.
- Added catalog-derived opponent descriptions under the opponent select.
- Split setup into title-only Round and Format selectors. `Standard` and `Bo3`
  are the only enabled current options; `Instant Death`, `Bo1`, and `Training`
  are visible but disabled. `Standard` and `Bo3` are selected by default, so
  Begin Match is enabled immediately when the default ready decks are valid.
  Round/Format button text is set to 10px and kept on one visual row.
- Kept seed controls in the lower setup area.
- Strengthened the bottom summary/action bar with a top rule and primary accent
  Begin Match button.

These were CSS/markup changes plus view-model label/description additions. The
pre-game setup config now carries selected `roundId` and `formatId` values for
the current supported pairing, but `startEngineMatch` and engine rules were not
changed.

## Prototype Details Intentionally Not Ported

Did not port prototype stub decks, prototype `GAME_MODES`, prototype `OPPONENTS`,
`loadSavedDecks`, localStorage persistence, browser-global registration, inline
style blocks, free mulligans, undo, Bo1/Bo3 behavior, training behavior, or
seed-suite/simulation wiring. The compact mode glyphs follow the prototype's
visual rhythm only; availability and setup behavior still come from the
production view model.

## Catalog And Setup Behavior Preserved

Deck and opponent options still come from current catalog presets through
`buildPreGameDeckOptions`. Begin Match still builds a serializable setup config
and passes selected preset IDs into the existing match start path. `startEngineMatch`
behavior was not changed.

## Disabled Modes And Formats

Only the current Human vs AI path is enabled, now displayed as `Casual`. Ranked,
Training, and Seed Suite mode tiles are disabled and non-interactive. `Standard`
is the only enabled round selector. `Bo3` is the only enabled format
selector; `Instant Death`, `Bo1`, and `Training` controls are disabled and
non-interactive.

## Seed Behavior

URL seed prefill, lowercase `copy` control, blank-seed visible generation on Begin Match,
and match top-bar seed display are preserved. Browser smoke uses `ep4-smoke`
for the pre-game transition and `ep4-direct` for the direct match route.

## Leader Sizing Notes

Pre-game leader thumbnails now use the shared small frame from
`dimensionsForSize("sm")` with `object-fit: contain` preserved. Match score-card
leaders now pass `size="match"` to `AuthenticLeaderCard`, which derives from
`dimensionsForSize("md")`. Desktop browser smoke verifies a medium match leader
frame with contained leader images.

## Responsive / Mobile Evidence

The pre-game body stacks below tablet width and the bottom action bar stacks on
mobile. Chromium smoke verified no document-level horizontal overflow at 390px
for pre-game, pre-game-to-match, discard browser, and direct match routes.

## Hidden-Info And Rule Boundary Review

No engine/core, legal move, AI policy, scoring, prompt, hidden-zone, or rule code
was changed. Pre-game still displays only catalog setup data before a match exists.
The match screen continues to hide AI hand identities and browser smoke checks
visible text for raw runtime ids/debug fields.
