# cFp21 Report - Benchmark Ledger And Fixed-Suite Harness

## Summary

cFp21 adds the first in-memory benchmark/evaluation harness for Gwent AI
policies. The harness converts headless simulation results into
versioned, hidden-info-safe raw match ledger rows and deterministic
fixed-suite summaries.

The built-in suite is `benchmark-smoke-v1`. It uses the existing six
simulation smoke seeds and mirrors `legal-heuristic-v0` versus the new
benchmark-only deterministic weak comparator `legal-first-v0`, producing
12 benchmark records by default.

## Behavior Changed

- `runHeadlessMatchSimulation({ seed })` remains backward compatible and
  still defaults to current Northern Realms versus current Nilfgaard
  with `currentCatalogCards` / `currentCatalogLeaders`.
- `runHeadlessMatchSimulation(...)` now accepts optional explicit AI
  seat configs, including faction and catalog deck preset per seat.
- `replayHeadlessMatchCommands(...)` accepts the same optional seat
  configs so benchmark replay checks work for non-default deck
  matchups.
- `runBenchmarkSuite(...)` returns in-memory `benchmark-match-v1` ledger
  rows, `benchmark-summary-v1` summaries, diagnostics, and optional
  explicitly unsafe debug results.
- `benchmark-smoke-v1` and `legal-first-v0` are available through
  `src/game/benchmark/`.

No engine rules, legal-move semantics, scoring, command execution, UI,
routes, CSS, catalog data, custom catalog support, file writers, Python
tooling, ratings, search policies, model training, or product
difficulty behavior changed.

## Hidden-Info Safety Notes

Default benchmark output excludes raw `finalState`, `cardsById`,
`commandLog`, raw event logs, hand arrays, deck arrays/order,
`ownHand`, `opponentHand`, and raw `seat_a:` / `seat_b:` runtime card
instance prefixes. Stable fingerprints are generated from public,
deterministic fields plus command/event type sequences, not raw command
payloads.

`includeDebugResults: true` is an explicit unsafe/debug escape hatch and
returns raw headless simulation results under `unsafeDebugResults`.

## Batch A / Batch B Relationship

Batch A kept search in scope but required hidden-info-safe evaluation
and determinization-risk guardrails before implementing search. Batch B
made the evaluation ladder the immediate next implementation-adjacent
step and required raw result ledgers plus fixed matchup matrices before
ratings or robustness probes.

cFp21 implements that first ledger/matrix substrate. It does not claim a
search baseline, strength rating, robustness score, or product
difficulty tier.

## Deferred Methods

Glicko, TrueSkill, Elo, and approximate best response were not
implemented because this phase establishes the raw ledger and fixed
suite they should consume. ISMCTS, determinized search, NFSP, Deep CFR,
ReBeL, OSFP, `legal-heuristic-v1`, Python tooling, tensor export, and
model training remain out of scope for the same reason.

## Deviations

- No large official starter tournament was added. The built-in suite is

- The deterministic weak comparator is benchmark-local rather than a
  product AI export; this keeps it scoped as a benchmark baseline.
