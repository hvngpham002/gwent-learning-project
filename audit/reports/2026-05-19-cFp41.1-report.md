## Root Cause

`hasUsefulNonMedicLine` in `legalHeuristicPolicyV1.ts` called `scorePlayMove(candidate)` for each non-Medic play-card candidate. `scorePlayMove` calls `shouldApplyNoTargetMedicDelayPenalty`, which calls `hasUsefulNonMedicLine` — creating a direct recursion loop.

Similarly, `hasClearlyBetterNonWeatheredLine` called `scoreMove(candidate)` for different-card alternatives. `scoreMove` → `scorePlayMove` → `shouldExemptFromWeatheredLowTempoPenalty` → `hasClearlyBetterNonWeatheredLine` — creating a second recursion path.

Combined, the expanded benchmark's deeper game states triggered these loops at sufficient depth to exceed the JavaScript call stack.

## Risks / Follow-ups

- `scorePlayMoveForAlternativeScan` is a simplified score that does not include Medic utility, Spy bonuses, or Muster bonuses. This is intentional — the helper only needs to determine whether an alternative line is "useful enough" (>= MIN_USEFUL_MOVE_SCORE). If the simplified score produces different ordering than full scoring in edge cases, the cFp38/cFp39 guards might make slightly different decisions, but this should not meaningfully change v1 strength.
- The `buildLegalHeuristicV1RoundInvestmentAnalysis` function still calls `scoreMove` for computing `positiveUnitSourceCardIds`. This path is safe because the recursion chain is now broken at `hasUsefulNonMedicLine` (which uses the non-recursive helper), but it remains a point to watch if future changes re-introduce recursion.
- Recommended next step: continue expanding benchmark volume (additional seeds, mechanics decks, competitive lists) now that the recursion guard is in place.
