## Behavior Changed

cFp77 adds a new benchmark-only, read-only public-action identity artifact
(`public-action-identity-artifact-v0`) derived from committed cFp68/cFp69/
cFp76 artifacts. It does not:

- Modify any existing cFp68-cFp76 artifact directory.
- Execute candidate actions, rebuild sampled states, or materialize hidden
  worlds.
- Run rollout search, PIMC evaluation, or ISMCTS/MCTS.
- Compute action values, expected values, reward targets, win
  probabilities, payoff tables, or principal variations.
- Rank actions or select best/chosen actions.
- Change gameplay behavior, engine rules, legal moves, AI policy behavior,
  sampler behavior, deck/catalog data, benchmark suite definitions, or
  rating artifacts.
- Expose raw move IDs, card instance IDs, card source IDs, source IDs,
  card/leader names, deck order, sampled hands/decks, or hidden payloads.

`runPublicActionIdentitiesV0` re-observes benchmark roots at the same
position as cFp69 (after legal move generation, before policy selection),
filters observed roots to the cFp68 eligible-root key set (so cFp68/cFp69
skipped roots are not double-observed), and builds public action buckets
using the existing `buildPublicActionAbstraction` /
`buildDeterminizedPimcActionAvailabilityV0PublicActionBucketKey` contract
without modification.

The only metadata effect is the `productPolicies.ts` update, which points
`legal-heuristic-v1` at cFp77 as the latest read-only benchmark
infrastructure phase, without changing `legal-heuristic-v1` or
`legal-heuristic-v0` gameplay behavior.

## rootRef Compaction Redesign

A literal implementation of the spec's per-row action identity schema
(repeating the full cFp69 root identity on every action identity row)
produced a robust `action-identities.jsonl` of 169,049,225 bytes — over the
spec's 90 MB hard stop. Per the spec's own redesign instruction for
over-budget artifacts, cFp77 replaced the repeated root-identity fields with
a compact `rootRef` (`root_NNNNNN`) join key into `root-summaries.jsonl`
(which carries one row per eligible root with the full root identity),
dropped the derivable `actionFamily`/`bucketSizeClass` per-row fields (still
computable via pure helper functions and still reported in `summary.json`
count summaries), and omitted `targetKind`/`targetSide` from a row entirely
when the value is `"none"`. This reduced the robust
`action-identities.jsonl` to 54,892,627 bytes (~54.89 MB) — below the 90 MB
hard stop, though still above the 50 MB soft target. See the decision note's
"rootRef Compaction Redesign" section for full details.

## Deviations

The per-row action identity schema deviates from the literal field list in
`docs/spec/2026-06-15-cFp77-specs.md` (see "rootRef Compaction Redesign"
above and in the decision note): action identity rows use a compact `rootRef`
join key into `root-summaries.jsonl` instead of repeating the full root
identity on every row, and omit the derivable `actionFamily`/`bucketSizeClass`
per-row fields and `"none"`-valued `targetKind`/`targetSide` fields. This is
the exact mitigation the spec anticipates for an over-budget artifact (the
literal-schema implementation produced a 169,049,225-byte robust
`action-identities.jsonl`, over the 90 MB hard stop), preserves every safe
field's information via the `rootRef` join and documented pure helper
functions, and was required to bring the robust artifact under the 90 MB
hard stop.

Two pre-existing TypeScript errors in `src/game/benchmark/publicActionIdentitiesV0.ts`
and `src/game/benchmark/index.ts` were discovered and fixed during this
phase (see "Pre-Existing Issues Fixed" below); both fixes were internal to
cFp77's own new files and did not change any cFp68-cFp76 file's public
exports' usage.

No other deviation from the spec.

Review repair: the cFp77 CLI originally compared the cFp76 root-feature row
count against the cFp76 summary's self-reported count. It now reads and
counts `root-features.jsonl` directly, includes that artifact in the source
SHA-256 reference list, and regenerates current/robust artifacts with source
artifact reference count 15. Row counts and action identity hashes are
unchanged; manifest/summary/report hashes changed because the source
reference set is stricter.

## Pre-Existing Issues Fixed

1. **Generic constraint bug in root-key helper functions.** The original
   implementation constrained `keyByRootKey`/`duplicateKeyCount`/
   `missingFromCount`/`rootKeyFor` to `T extends PublicActionIdentitiesV0RootIdentity`,
   which requires a `rootPublicFingerprint` field. `PublicActionIdentitiesV0ObservedRoot`
   omits that field and therefore did not satisfy the constraint, causing
   `npm run typecheck` (`tsc -b --pretty false`) to fail with many
   TS2345/TS2339/TS7006 errors. Fixed by introducing
   `PublicActionIdentitiesV0RootKeyFields = Omit<PublicActionIdentitiesV0RootIdentity, "rootPublicFingerprint">`
   and re-constraining all four helper functions to that narrower type.
2. **Barrel-export name collision.** `src/game/benchmark/index.ts` re-exports
   both `publicActionIdentitiesV0Artifacts.ts` and the existing cFp76
   `searchConsumerActionFeaturesV0Artifacts.ts` via `export *`; both files
   independently defined an internal `sha256` helper, and both were
   exported, causing a `TS2308` duplicate-export error. Fixed by removing
   the unused `export` keyword from cFp77's `sha256` helper (confirmed not
   imported by any other file).
3. **Artifact-size label inaccuracy.** The "Artifact Sizes" table in
   `report.md` previously had a static label for `action-identities.jsonl`
   reading "below 50 MB robust target, below 90 MB hard stop" regardless of
   actual size. Fixed by computing the label from the actual byte count
   (`actionIdentitiesTargetLabel`), so the robust report now correctly reads
   "at or above 50 MB robust target (cFp78 compaction recommended), below
   90 MB hard stop".

Both fixes (1) and (2) were pre-existing bugs in code written earlier in
this phase, caught by `tsc -b` before any artifacts were committed; no
committed cFp68-cFp76 source file was modified.

## Risks And Follow-Ups

- Robust `action-identities.jsonl` (54.89 MB) is at or above the 50 MB
  robust target, though below the 90 MB hard stop. cFp78 should compact the
  row projection further (e.g. additional field sharing via `rootRef`, or a
  deterministic casebook subset) before joining cFp76 root features to
  cFp77 action identities.
- `root-summaries.jsonl` (40.93 MB robust) is comfortably below the 90 MB
  hard stop but is now the largest single artifact in the cFp77 family;
  worth monitoring if cFp78 widens root-summary fields.

## Recommended Next Step

Per the cFp77 decision note and the spec's "Expected cFp78 Decision Logic":
because cFp77 action identity rows are complete and source consistency is
`ready` for both suites, but the robust `action-identities.jsonl` (54.89 MB)
is at or above the 50 MB robust target (below the 90 MB hard stop), cFp78
should first compact the cFp77 action row projection or create a
deterministic casebook subset, and then repair
`search-consumer-action-features-v0` by joining cFp76 root features to cFp77
public-action identities to produce nonempty `action-features.jsonl` rows
without action values or ranking. cFp78 should not recommend rollout, value
estimation, action ranking, best-action selection, win probability, or
reward targets from cFp77 alone.
