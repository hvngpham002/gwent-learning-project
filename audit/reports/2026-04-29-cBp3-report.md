# Cluster B Phase 3 Report - Official Gwent Catalog Porting Pipeline

## Summary

Implemented cBp3 as a separate official-card staging lane over the Game8 scrape. The project now exposes official card, leader, image, and summary candidates from `audit/scrapes/2026-04-29-game8-gwent-cards.json`, plus an opt-in authentic authoring route for review metadata, crop values, approvals, notes, and review-bundle import/export.

Official candidates are not Card Studio custom records, do not use `custom_*` IDs, are not stored in `gwent_custom_catalog_v1`, and are not promoted into `currentCatalogCards`, `currentCatalogLeaders`, deck presets, deck-builder source sets, or match runtime in this phase.

## Deviations

- The UI stores optional browser-local data URL previews in the review bundle only when the reviewer explicitly uploads one. Stable `/images/...` paths remain the preferred workflow.
- Public image existence is based on the repo image path manifest with exact path casing, not case-insensitive local filesystem lookup. This avoids treating case-mismatched paths as production-ready.
- cBp3 does not generate final committed catalog TypeScript packs from the review bundle, matching the out-of-scope list.

## Risks / Follow-Ups

- 148 preferred image paths are missing, so image review/promotion remains substantial.
- 5 card candidates and 21 leader candidates have rule gaps before full official-deck playability.
- Official review state is localStorage-backed; reviewers should export bundles for handoff.
- The official staging data currently imports the scrape JSON from `audit/scrapes/`, so that input artifact must be tracked alongside the staging code.
- Large scrape-derived staging data increases the production bundle for the opt-in route; a later phase may code-split authoring tools if route promotion or bundle size becomes important.
