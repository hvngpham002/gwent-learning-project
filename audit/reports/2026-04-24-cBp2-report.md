# Cluster B Phase 2 Report - Current Card Migration And Card Studio Plan

## Summary

Migrated the existing neutral, Northern Realms, and Nilfgaard source cards and leaders into catalog-compatible TypeScript packs. Added current Northern Realms and Nilfgaard deck presets that mirror the existing hardcoded deck assembly, plus inert placeholder packs for Monsters, Scoia'tael, and Skellige. Added aggregate catalog exports, a deck preset resolver, validation/regression tests, authoring documentation, and a Card Studio implementation plan. Live gameplay code was not intentionally changed.

## Files Changed

- `src/data/catalog/cards/*`: added migrated card packs and empty future-faction card packs.
- `src/data/catalog/leaders/*`: added migrated leader packs and empty future-faction leader packs.
- `src/data/catalog/deck-presets/*`: added current Northern Realms and Nilfgaard presets.
- `src/data/catalog/index.ts`: added stable aggregate exports and `resolveCatalogDeckPreset`.
- `tests/catalog/currentCatalogData.test.ts`: added migrated catalog validation, uniqueness, preset reference, placeholder, and count regression tests.
- `docs/card-authoring/current-catalog-workflow.md`: documented image, source ID, card detail, preset, and validation workflow.
- `docs/card-authoring/card-studio-plan.md`: documented planned Card Studio fields, validation, preview, draft save, JSON import/export, ability warnings, and preset integration.
- `audit/reports/2026-04-24-cBp2-report.md`: created this report.

## Audit Findings Touched

This phase only created foundation for `F-2.1`, `F-2.7`, `F-7.2`, `R-010`, and `R-011`. It did not directly change live gameplay, deck construction, faction abilities, mulligan behavior, side-deck state, ability resolution, or existing audit defects.

## Risks / Follow-ups

- Current presets intentionally preserve audited hardcoded deck omissions instead of correcting them.
- Legacy default decks use counts above normal deck-limit expectations for `Dun Banner Medic` and `Young Emissary`; those counts are preserved for current-playability parity.
- Image paths are validated as strings only; missing or misspelled legacy asset paths are not checked by validators yet.
- Catalog data is not yet used by live gameplay. A later phase should switch deck construction only after equivalence tests are in place.
- Card Studio remains documentation-only in this phase.

## Recommended Next Step

Proceed to the next engine/data phase only after reviewing whether deck-limit validation should intentionally accept the current hardcoded preset counts or introduce a separate "legacy preset" policy.
