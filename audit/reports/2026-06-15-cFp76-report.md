## Behavior Changed

cFp76 adds a new benchmark-only, read-only feature consumer
(`search-consumer-action-features-v0`) over committed cFp68-cFp74
artifacts. It does not:

- Modify any existing cFp68-cFp74 artifact directory.
- Re-observe benchmark roots or rebuild sampled states.
- Execute any benchmark command or count third-ply legal surfaces.
- Add rollout, value, action ranking, best-action selection, win
  probability, reward targets, product AI wiring, or AI Lab runner buttons.
- Change gameplay behavior, engine rules, legal moves, AI policy behavior,
  sampler behavior, deck/catalog data, benchmark suite definitions, or
  rating artifacts.
- Fabricate per-action identities. The audit found that committed
  cFp69-cFp74 artifacts expose only aggregate per-root count maps, not
  durable per-public-action identities, so cFp76 reports
  `action_feature_source_gap` rather than inventing a `publicActionRef`.

The only metadata effect is the `productPolicies.ts` update, which points
`legal-heuristic-v1` at cFp76 as the latest read-only benchmark
infrastructure phase, without changing `legal-heuristic-v1` or
`legal-heuristic-v0` gameplay behavior.

## Deviations

None. All implementation follows the spec exactly. The audit confirmed
`action_feature_source_gap` is the correct readiness status: committed
cFp69-cFp74 artifacts carry only aggregate per-root count maps
(`publicActionKindCounts`, `targetKindCounts`, `targetSideCounts`,
transition-kind counts, and budget aggregates) and no durable
per-public-action identity, so per-root-public-action feature rows are not
derivable without new command execution — which is out of scope for cFp76.

One pre-existing-pattern lint fixup was required during this phase: a test
fixture initially used an underscore-prefixed destructured binding
(`_droppedSuiteId`) to drop the `suiteId` field for a join-compensation
test; this repo's ESLint config has no `varsIgnorePattern` exception for
underscore-prefixed unused variables, so the fixture was rewritten to use
`delete` on a shallow-copied record instead. This is a test-only change with
no effect on cFp76 production code or artifacts.

## Risks And Follow-Ups

- cFp76's `action-features.jsonl` schema is defined but unpopulated. cFp77
  must add a durable `publicActionRef` source (per the cFp76 decision note's
  recommendation: a narrow public-action-identity artifact derived from
  cFp69/cFp70 sources) before any future phase can populate
  `action-features.jsonl` without fabricating identities.
- Robust `root-features.jsonl` is 79.68 MB, comfortably below the 90 MB
  hard stop but worth monitoring if cFp77 widens root-level rows; the spec's
  recommended mitigation (deterministic casebook subset) was not needed this
  phase.
- The `action-feature-gaps.jsonl` `affectedActionFeatureCountEstimate` is
  only populated for the cFp69 gap row (derived from cFp69
  `publicActionKindCounts` totals); the other four gap rows
  (cFp70/cFp71/cFp72/cFp74) have no comparable scalar estimate in their
  source artifacts.
