# Cluster D Phase 10 Report - Hidden-Info-Safe Simulation Export Contract

## Summary

Added the first deterministic, in-memory, hidden-info-safe simulation export contract over the cDp9 batch runner.

The new export layer replays raw simulation commands from the seed, derives each row from the engine state immediately before command execution, encodes perspective-specific safe observations, preserves per-row legal move order, records the chosen legal action index, and attaches sparse terminal reward placeholders.

No engine rules, UI behavior, Redux adapter behavior, catalog content, JSONL writing, Python bridge, model training, fixed neural action vector, or reward shaping changed.

## Export API Shape

Public entrypoint:

```ts
buildSimulationExportDataset(input?: SimulationExportDatasetInput): SimulationExportDataset
```

Schema constants:

- `SIMULATION_EXPORT_SCHEMA_VERSION = "sim-export-v1"`
- `SAFE_OBSERVATION_SCHEMA_VERSION = "safe-observation-v1"`
- `LEGAL_ACTION_SCHEMA_VERSION = "legal-action-v1"`
- `SIMULATION_REWARD_SCHEMA_VERSION = "reward-v1"`

The dataset includes generator metadata, suite id, seeds, policies by seat, row/match counts, compact summary, per-match diagnostics, and `SimulationDecisionRow[]`.

## Observation Schema Shape

Observations are perspective-specific. The acting seat sees own hand card summaries, own discard summaries, public board/weather cards, public opponent discard, scores, prompt details visible to that seat, and count-only deck/hidden hand data.

Visible cards use catalog `sourceId` and row-local `cardRef` values such as `own_hand_0`, `own_board_close_1`, `opponent_board_ranged_0`, and `weather_0`. Raw engine card instance ids are not emitted.

## Action Encoding Schema Shape

Legal actions are encoded as a per-row ordered list. The encoder preserves `getLegalMoves` order, assigns row-local ids (`action_0`, `action_1`, ...), records compact source/target/prompt metadata, and excludes raw `moveId`.

`chosenActionIndex` points at `legalActions[chosenActionIndex]`, and tests assert that this equals `chosenAction` for every row.

## Reward Placeholder Behavior

Rewards are sparse terminal placeholders only:

- `1` for the completed match terminal policy row when the row seat won;
- `-1` when that row seat lost;
- `0` for a draw;
- `null` for intermediate rows and all non-completed runs.

No score-delta, round-level, shaped, or policy-evaluation reward was added.

## Row Generation / Replay Behavior

Rows are generated by replaying from `startMatch(createHeadlessSimulationConfig(seed))`.

For each command, before applying it:

1. Determine the acting seat.
2. Call `getLegalMoves` for that state and seat.
3. Match the recorded command back to one legal move.
4. Build the safe observation and legal action encodings.
5. Emit a row unless the action is a system action excluded by default.
6. Apply the command through `executeCommand`.

The implementation exposed two narrow simulation helpers from `runHeadlessMatch.ts`: `createHeadlessSimulationConfig` and `getHeadlessActingSeat`. No rule helper, Redux, UI, browser, timer, filesystem, or legacy AI dependency was added.

## Hidden-Info Redaction Guarantees And Test Evidence

Default export rows exclude raw `finalState`, `commandLog`, `cardsById`, full events, `instanceId`, raw generated card ids, opponent hand card arrays, opponent deck arrays/order, and own deck arrays/order. Prompt target strength is emitted only when the prompt target card is visible to the acting seat.

Tests assert:

- JSON output does not contain `finalState`, `commandLog`, `cardsById`, `"instanceId"`, or raw `seat_a:` / `seat_b:` generated card id patterns.
- Opponent hand is represented by `cardCountInHand` only.
- Own hand visible source ids are preserved.
- Public board/discard/weather card refs can appear through visible summaries.
- Default rows do not include `resolve_round_end`.

## Deviations / Limits

- No JSONL writer, CLI, Python bridge, notebooks, self-play workers, training code, fixed neural action vector, or shaped reward was added.
- `use_leader` action encoding exists, but the current deterministic smoke suite does not assert a naturally selected leader row.
- Command-to-legal-move matching compares structured command fields and stable stringified targets. It is narrow and tested for current command shapes, but future target shapes should add direct match tests.
- The export has TypeScript types and tests, not runtime schema validation.
- `npm run ci` could not fully pass without staging or committing because the script intentionally enforces a clean tracked worktree as its final step.

## Risks And Follow-Ups

- Downstream ML still needs an explicit serialization boundary and schema validation before data leaves memory.
- Per-row legal action lists are correct for contract clarity but are not a fixed model action vector.
- Sparse terminal rewards are intentionally minimal; reward design remains a separate ML task.
- Broader prompt and leader export coverage should be pinned by future deterministic seed suites.
- Replay diagnostics still compare final essentials, not every intermediate observation hash.
