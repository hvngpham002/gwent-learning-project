## Legal Move Model Summary

Move kinds are `choose_mulligan`, `play_card`, `pass`, `use_leader`, and placeholder `choose_prompt_option`. Targets are explicit serializable objects: `board_row`, `row_horn`, `weather`, `card_instance`, or `none`.

Move IDs are stable strings built from action kind, seat, source instance, and target identity. The generator accepts `catalogCards` and `catalogLeaders`, builds source-ID lookups, and uses runtime instances only for `instanceId`, `sourceId`, controller/owner, and zone. Returned moves include acting-seat hand cards and public board targets only; opponent hand IDs and deck order are not returned.

## Rule Surface Covered

| Surface | Supported? | Notes |
|---|---|---|
| Mulligan 0/1/2 choices | Yes | Emits all combinations over acting-seat hand IDs. |
| Wrong-turn gate | Yes | Non-current seats receive no playing moves. |
| Passed-seat gate | Yes | Passed seats receive no pass/card/leader moves. |
| Pass | Yes | Current unpassed seat gets one `pass` move in playing phase. |
| Normal unit/hero rows | Yes | Uses catalog `rows`. |
| Agile/multi-row cards | Yes | One move per catalog row. |
| Spy placement | Yes | Targets opponent board rows. |
| Special Horn | Yes | Targets only own empty `row_horn` slots. |
| Decoy | Yes | Targets own non-Hero unit instances only. |
| Weather and Skellige Storm | Yes | Target shared weather. |
| Clear Weather no-op board | Yes | Legal even with no active weather entries. |
| Special Scorch | Yes | Uses `none` target because effect resolution is future work. |
| Leader use | Yes | Gated by phase, turn, pass, leader existence, `leaderUsed`, and known catalog ability metadata. Targeted/placeholder leader abilities are represented with `future_prompt` metadata, not resolved. |
| Planned/unimplemented special placement | Partial | Unsupported special cards with no placement semantics are omitted from legal executable moves. |

## Risks / Follow-ups

- Legal moves are queries only; command execution for `PlayCard`, `Pass`, `UseLeader`, `ChooseMulligan`, and prompts remains future work.
- Leader moves are intentionally minimal. Non-`clear_weather` abilities are exposed with `future_prompt` metadata because target/effect resolution is out of scope.
- Medic, Muster, Scorch Close, Unit Horn, leader target selection, and ability prompts still need Phase 6 resolver semantics before moves become executable commands.
- The generator omits unsupported special cards with no current placement semantics rather than returning executable moves.
