# cFp24.2 Report - Legal Heuristic v1 Pass Safety Patch

Date: 2026-05-11

## Summary

cFp24.2 narrows `legal-heuristic-v1`'s voluntary pass behavior after the
first product playtest found v1 passing while merely ahead against an
active opponent with a large hand. The patch replaces the old card
disadvantage shortcut with a deterministic hand-pressure helper, adds
focused policy tests for the observed failure shapes, refreshes v1
benchmark artifacts, and updates the v1 policy note plus project state.

No engine rules, legal moves, scoring, prompts, command payloads, UI,
routes, Redux adapter shape, product policy selector behavior, catalog
deck data, ratings, search, Python tooling, browser benchmark execution,
ML training, or product difficulty tiers changed.

## Behavior Changed

`legal-heuristic-v1` no longer treats being ahead and down on cards as a
standalone reason to pass. When the opponent is still active, opponent
hand size now increases the score lead required for a voluntary pass.

The policy still preserves the existing safe pass behavior:

- if the opponent has passed and v1 is ahead, v1 passes;
- if v1 is behind on its last gem and the visible immediate upper bound
  cannot catch up, v1 passes;
- if there is no useful playable card or leader move, v1 can still fall
  back to pass.

## Exact Pass-Safety Rule

Before cFp24.2:

```ts
if (passMove && features.scoreDelta > 12 && features.ownHandCount < features.opponentHandCount) {
  return passMove;
}
```

After cFp24.2:

```ts
const estimateOpponentHandPressure = (features: LegalHeuristicV1Features) => {
  const perCardPressure = features.ownGems <= 1 ? 8 : 6;
  return features.opponentHandCount * perCardPressure;
};

const canVoluntarilyPassWithLead = (features: LegalHeuristicV1Features) => {
  if (features.scoreDelta <= 0) return false;
  if (features.opponentPassed) return true;
  const requiredLead = Math.max(features.ownGems <= 1 ? 36 : 24, estimateOpponentHandPressure(features));
  return features.scoreDelta > requiredLead;
};
```

`choosePlayingMove(...)` now returns `passMove` only when
`canVoluntarilyPassWithLead(features)` is true in the active-opponent
voluntary-pass branch.

## Playtest Regression Coverage

`tests/game/engineAiPolicy.test.ts` now covers both observed playtest
shapes with synthetic `EnginePolicyInput`:

- `does not pass on last gem just because it is ahead while opponent has a large hand`
  sets `ownGems: 1`, a 24-point v1 lead, opponent hand count 9, and a
  useful unit move; v1 chooses the play, not pass.
- `does not pass in the round-one large-opponent-hand playtest shape`
  sets more than one gem, a 26-point v1 lead, opponent hand count 12,
  and a useful unit move; v1 chooses the play, not pass.

The same test block also locks the preserved safe cases: opponent already
passed and v1 ahead, impossible last-gem catch-up, and an overwhelming
lead beyond the hand-pressure threshold.
