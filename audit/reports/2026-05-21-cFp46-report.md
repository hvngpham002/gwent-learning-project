## Formulas / Configuration Used

Glicko-1 rating-period update:

```
q = Math.log(10) / 400 = 0.005756...
default rating = 1500
default RD = 350
RD floor = 30

g(RD_j) = 1 / sqrt(1 + 3 * q^2 * RD_j^2 / pi^2)
E_i = 1 / (1 + 10^(-g(RD_j) * (r_i - r_j) / 400))
d^2 = 1 / (q^2 * sum(g(RD_j)^2 * E_j * (1 - E_j)))
r' = r + (q / (1/RD^2 + 1/d^2)) * sum(g(RD_j) * (s_j - E_j))
RD' = sqrt(1 / (1/RD^2 + 1/d^2))
```

Outcome scores: win = 1, draw = 0.5, loss = 0.

Report interval: `rating ± 1.96 * RD`
Conservative rating: `rating - 2 * RD`

## Repair

### Portability and determinism repair
The original cFp46 implementation stored absolute filesystem paths (e.g. `C:\Users\...`) as `sourceRecordsPath` in the rating artifacts, making them machine-local and non-deterministic across developers/CI.

**Fix:**
- `scripts/run-benchmark-rating-report.ts` now resolves `--records` paths to repo-relative paths with forward slashes.
- Paths resolving outside the repository root are rejected with a `CliUsageError`.
- Default source path format: `docs/research/literature/ai/benchmark-results/<suiteId>/latest/records.jsonl`
- `ratings.json` now includes top-level `schemaVersion`, `ratingSchemaVersion`, `suiteId`, and `sourceRecordsPath` for self-description.

**Tests added:**
- Path safety: no `C:\`, `/Users/`, backslash Windows paths, or absolute repo paths in any artifact output.
- Self-describing `ratings.json`: asserts all top-level metadata fields are present.
- Portable repo-relative paths: asserts `manifest.json`, `ratings.json`, and `report.md` all share the same repo-relative source path.

**Tests removed from report:**
- None. All original tests pass plus the new ones.

## Risks / Follow-ups

- **High RD with few games**: The Glicko layer correctly reports high RD (uncertainty) for entities with few games. Future phases should monitor whether RD drops to acceptable levels as more benchmark data accumulates.
- **Single-rating-period design**: cFp46 treats the entire artifact as one rating period. Multi-period rating updates (carrying forward ratings across benchmark refreshes) are future work.
- **No inactivity RD growth**: cFp46 does not implement inactivity RD growth. This is deferred to a future phase.
- **TrueSkill compatibility**: The Glicko-1 implementation is not compatible with TrueSkill (which handles multiple players and draws natively). TrueSkill remains deferred per the spec.
