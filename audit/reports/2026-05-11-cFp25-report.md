## Diagnostic Schema Summary

### Decision Trace (`ai-decision-trace-v1`)

```ts
{
  schemaVersion: "ai-decision-trace-v1",
  policyId: "legal-heuristic-v1" | string,
  seatId: SeatId,
  decisionIndex: number,
  phase: string,
  round: number,
  publicState: {
    // score, gems, hand/deck/discard counts, pass flags
    // board rows (unitCount, horn sourceId), weather count
  },
  passAnalysis: {
    passLegal, scoreDelta, opponentHandPressure,
    requiredLead, isVoluntarilySafe, isOpponentPassed,
    isLastGem,
    diagnosticApproxUpperBound: number,  // heuristic: ownScore + opponentHandCount * 50
    policyLastGemUpperBound: number,     // ownScore + uniqueCardTempoUpperBound (real policy bound)
    lastGemSurrenderAllowed: boolean     // based on policyLastGemUpperBound, not heuristic
  } | null,
  selected: {
    kind, label, actionRef, targetKind, targetLabel, optionRef?, abilityId?
    // label is redacted via safeSelectedMoveLabel:
    //   play_card → "hidden hand play"
    //   choose_mulligan → "mulligan hidden card" or "keep hand"
    //   choose_prompt_option → "resolve prompt option"
    //   use_leader → "use leader"
    //   pass → "pass"
    //   resolve_round_end → "resolve round end"
    // optionId replaced with deterministic local optionRef values, e.g. "option_0"
  } | null,
  candidates: [{
    kind, label, score, targetKind, targetLabel,
    reason, cardLabel  // redacted for hidden AI hand
  }],
  reasonKind: string  // "phase", "none", "policy", "policy-last-gem", etc.
  reason: string  // human-readable explanation
}
```

## Product Export Storage Policy

Product diagnostics are **explicit copy/download only**. No silent persistence to:
- localStorage
- IndexedDB
- Repository files
- A server

The user must click "copy diagnostics" or "download diagnostics" to generate and export diagnostic data. The data accumulates only in memory (Redux `diagnosticTraces` array) during a match session and is reset on rematch/setup.

## Hidden-Info Safety Notes and Scan Results

### Hidden-Info Validator

The `scanForHiddenInfoHazards` function scans exported diagnostics for forbidden tokens:
- Structured keys: `cardsById`, `finalState`, `commandLog`, `ownHand`, `opponentHand`
- String values: `seat_a:`, `seat_b:`, raw card instance IDs
- Special patterns: `"hand"`, `"deck"` (avoids false positives on `deckCount`, `handCount`)

### Redaction Strategy

- **Candidate card labels**: Unplayed AI hand card names are redacted to `"hidden hand play"`.
- **Public card labels**: Only cards visible through battle log events, board state, or revealed prompts are named.
- **Move IDs**: Raw engine instance IDs (`seat_a:card:0`) are never included in trace fields. Replaced with safe `actionRef` (e.g., `"action_0"`).
- **Selected move labels**: All selected move labels are redacted via `safeSelectedMoveLabel` — no card names from the AI's hidden hand appear. `play_card` → `"hidden hand play"`, `choose_mulligan` → `"mulligan hidden card"` or `"keep hand"`, `choose_prompt_option` → `"resolve prompt option"`.
- **Selected move IDs**: raw `optionId` is not exported in `AiDecisionSelectedMove`. Prompt selected moves use deterministic local `optionRef` values such as `"option_0"` so raw prompt option IDs that embed instance tokens cannot leak.
- **Pass analysis**: Uses `policyLastGemUpperBound` (computed as `ownScore + uniqueCardTempoUpperBound`) for `lastGemSurrenderAllowed`. Also includes `diagnosticApproxUpperBound` (heuristic: `ownScore + opponentHandCount * 50`) for diagnostic reference. The `reasonKind` field distinguishes exact-policy reasoning (`"policy-last-gem"`) from approximate diagnostics.

### Scan Results

All test cases pass the hidden-info hazard scan. No raw engine instance IDs, hand arrays, deck arrays, `cardsById`, or `finalState` appear in exported diagnostics. Selected moves use `actionRef` instead of raw move IDs, deterministic local `optionRef` values instead of raw `optionId`, and `safeSelectedMoveLabel` ensures no card names from the AI's hidden hand appear in any trace field. Semantic tests verify that known card names like "Spy" and "Draug" do not leak through `JSON.stringify(trace)`.

## Risks/Follow-Ups

1. **Trace collection overhead**: The explanation function runs `selectMove` internally, then builds trace data. For long matches, this doubles the per-decision work. Profile if performance becomes an issue.
