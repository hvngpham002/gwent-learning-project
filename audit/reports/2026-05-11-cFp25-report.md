## Product Export Storage Policy

Product diagnostics are **explicit copy/download only**. No silent persistence to:
- localStorage
- IndexedDB
- Repository files
- A server

The user must click "copy diagnostics" or "download diagnostics" to generate and export diagnostic data. The data accumulates only in memory (Redux `diagnosticTraces` array) during a match session and is reset on rematch/setup.

## Hidden-Info Safety Notes and Scan Results

### Hidden-Info Validator

The `scanForHiddenInfoHazards` function scans exported diagnostics for forbidden tokens:
- Structured keys: `cardsById`, `finalState`, `commandLog`, `ownHand`, `opponentHand`
- String values: `seat_a:`, `seat_b:`, raw card instance IDs
- Special patterns: `"hand"`, `"deck"` (avoids false positives on `deckCount`, `handCount`)

### Redaction Strategy

- **Candidate card labels**: Unplayed AI hand card names are redacted to `"hidden hand play"`.
- **Public card labels**: Only cards visible through battle log events, board state, or revealed prompts are named.
- **Move IDs**: Raw engine instance IDs (`seat_a:card:0`) are never included in trace fields.
- **Pass analysis**: Uses approximate upper-bound estimates (scoreDelta + handCount * 50) rather than exact deck inspection.

### Scan Results

All test cases pass the hidden-info hazard scan. No raw engine instance IDs, hand arrays, deck arrays, `cardsById`, or `finalState` appear in exported diagnostics.

## Benchmark Trace Behavior

- **Default artifacts unchanged**: `npm run benchmark:v1-smoke` and `npm run benchmark:v1-starter-matrix` produce the same output as before (no `decisionTraceSummary` field).

## Risks/Follow-Ups

1. **Trace collection overhead**: The explanation function runs `selectMove` internally, then builds trace data. For long matches, this doubles the per-decision work. Profile if performance becomes an issue.
2. **Candidate count in traces**: Top 5 candidates are included. For matches with many moves, this is reasonable. Consider capping at N if trace size becomes a concern.
3. **Playwright browser tests**: Missing Playwright coverage for the diagnostics controls. A future phase should add this.
4. **Resolvable field**: `lastGemUpperBound` in pass analysis uses an approximation (`scoreDelta + handCount * 50`). The exact upper bound requires iterating play moves — a future enhancement could compute this properly.
