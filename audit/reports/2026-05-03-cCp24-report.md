# Cluster C Phase 24 — Draw Opponent Discard Active Leader

- Spec: `docs/spec/2026-05-03-cCp24-specs.md`
- Branch: `dev`
- Date: 2026-05-03

## Summary

cCp24 implements the next narrowly scoped Tranche 2 leader-rule member
from the cCp18 Leader Ability Matrix: `draw_opponent_discard` for
`nilfgaard.emhyr-var-emreis-the-relentless` (Emhyr var Emreis: The
Relentless). It is the fifth Tranche 2 member to land, after cCp20's
`double_spies` whole-match passive, cCp21's `optimize_agile_rows`
active one-shot, cCp22's `restore_discard_to_hand` active one-shot
prompt-based restore, and cCp23's `shuffle_discards_into_decks` active
one-shot bulk recycle.

The implementation follows Pattern 4 from the cCp18 matrix as a
**companion** to cCp22: the same single-step `choose_card` prompt
machinery, but the candidate pile is the **opponent's** discard pile,
the prompt-target side is `opponent`, and the resolved card moves to
the acting seat's hand. The settled local rule contract from the spec
is honored:

- active one-shot leader, no prompt-build delay;
- empty opponent discard emits no legal `use_leader` move (even with
  cards in own discard);
- any card kind in opponent discard is eligible — units, heroes,
  specials, weather, side-deck-only / generated, and off-owner cards
  (acting-seat-owned cards physically in the opponent discard pile);
- `UseLeader` opens a prompt without consuming the leader; `currentTurn`
  stays on the acting seat while the prompt is pending;
- `ChoosePromptOption` resolves the move, sets the leader used, and
  hands off the turn;
- the chosen card moves opponent-discard → acting-hand;
- the chosen card's `controller` becomes the acting seat;
- the chosen card's immutable `owner` is preserved;
- drawn cards do not resolve their abilities;
- `getPromptMoves` selects target side by `prompt.abilityId`:
  opponent-side `card_instance` for `draw_opponent_discard`, own-side
  for cCp22 restore (preserved), with row preserved for Medic;
- AI-owned prompt options remain hidden from the human UI through the
  existing prompt-move gate; `summarizeEvents` does not leak option
  labels.

The cCp18 §C-2 conflict (catalog vs printed-rulebook tutor) is
**settled in favor of the catalog**: The Relentless draws from opponent
discard, not from the acting deck. The deck-tutor reading is
superseded.

- `src/game/core/abilities.ts` — Extended `resolvePromptOption` with a
  `choose_card` / `draw_opponent_discard` branch parallel to the

  in the opponent's discard pile (defense-in-depth — the wrapper
  already validated; the resolver early-returns on stale state), sets
  the chosen card's `controller` to the acting seat (leaving `owner`

  `card_moved.reason === "leader_draw_opponent_discard_to_hand"`,

  `outcome === "drew_opponent_discard"`, sets `state.pendingPrompt =

  `handoffTurn` call on the wrapper then runs the turn handoff).
  Drawn card abilities are **not** invoked — `resolveCardAbilities`
  is not called on the drawn card and `card_played` is not emitted.

## Behavior Changed

Engine pure helper:

- `getOpponentDiscardDrawCandidates({ state, seatId, catalogCards })`
  is the new candidate function. Pure, deterministic, opponent-
  discard-order output, opponent discard only, skips missing
  instances / missing catalog sources safely, no hidden-info reads.

Engine legal moves:

- `getLeaderMove` now emits one no-target `use_leader` move with
  `targetRequirement === "future_prompt"` when the leader is Emhyr
  var Emreis: The Relentless and the helper returns at least one
  candidate. Empty opponent discard (with or without own-discard
  cards) emits no `use_leader` move. After the leader is consumed,
  no further `use_leader` move is emitted.
- `getPromptMoves` now selects target side by `prompt.abilityId`:
  - `choose_card` + `draw_opponent_discard` → opponent-side
    `card_instance` target with `seatId: opposingSeatOf(seatId)`.
  - `choose_card` + `restore_discard_to_hand` → own-side
    `card_instance` target (cCp22 contract preserved).
  - Other prompts (Medic `medic_revive`, future `choose_card`
    abilities) continue to use the existing own-side path; row is
    preserved when present.

Engine command execution:

- `executeLeader`'s `draw_opponent_discard` branch validates the
  target shape (rejects non-`none` targets), recomputes the
  candidate set, rejects empty-opponent-discard execution, then
  opens the `pendingPrompt` (`kind === "choose_card"`,
  `abilityId === "draw_opponent_discard"`, one option per candidate)
  without consuming the leader. The transaction emits
  `ability_triggered` and `prompt_opened`, leaves
  `seat.leaderUsed === false`, emits no `leader_used`, moves no
  card, emits no `card_played`, and keeps `currentTurn` on the
  acting seat.
- `choosePromptOption` adds a stale-target check for the new
  prompt before mutation: if the chosen card is no longer in the
  opponent's discard pile, throws
  `EngineRuleError(invalid_target)` and never consumes the leader.
  The pre-mutation check guarantees the rejection path never mutates
  input state.
- `resolvePromptOption`'s new `choose_card` /
  `draw_opponent_discard` branch moves the chosen card from
  opponent discard to acting hand with `card_moved.reason ===
  "leader_draw_opponent_discard_to_hand"`, sets the chosen card's
  `controller` to the acting seat (leaving `owner` unchanged),
  emits `prompt_resolved` and `ability_resolved.drew_opponent_discard`,

  `seat.leaderUsed = true`, and emits `leader_used`. The wrapper

  opponent. Drawn card abilities are **not** invoked —

## Risks / Follow-Ups

- **`card_moved.reason` union grew.** The new
  `"leader_draw_opponent_discard_to_hand"` movement reason is part
  of the typed event union. JSONL export and replay infrastructure
  inherits the new variant automatically through the typed union;
  no schema bump is needed. The `motionByCardId` helper in
  `AuthenticMatchScreen.tsx` does not register a special motion
  class for this reason — drawn cards land in `hand`, which is
  hidden by default; no visible motion regression.
- **`getPromptMoves` now branches on `prompt.abilityId`.** The
  branch is narrow (one-line condition selecting target side and
  seat) and is covered by both cCp24 opponent-side tests and a
  cCp22 restore own-side regression test. Future `choose_card`
  prompts should explicitly extend this branch as they're added,
  rather than relying on the default own-side mapping.
- **Current Nilfgaard preset warning consequence.** The default
  `currentNilfgaardDeckPreset` uses Emhyr var Emreis: The Relentless,
  which is now implemented. The preset is no longer flagged with a
  `leader_ability_not_implemented` warning. Two deck-builder tests
  that exercised that warning path were updated to override the
  preset's leader to Emperor of Nilfgaard
  (`look_three_cards`, still placeholder). The preset itself was
  intentionally not changed (catalog promotion is out of scope).
- **`legal-heuristic-v0` AI policy.** The existing prompt policy
  ranks options by `option.targetStrength ?? 0` with deterministic
  moveId fallback. For draw-opponent-discard prompts,
  `targetStrength` is the catalog source's printed strength (units
  / heroes carry their printed strength; specials and weather carry
  strength 0 by catalog convention). The AI will therefore prefer
  to draw the highest-strength card in the opponent's discard pile,
  breaking ties by `moveId` (which is `draw-opponent-discard:<cardId>`).
  This is acceptable for cCp24 — strategic AI tuning is explicitly
  out of scope. A future AI tranche could prefer specific kinds
  (e.g. weather > unit, or "deny opponent's best Spy") by weighting
  `option.target.sourceId`'s catalog metadata.
- **Tranche 2 remaining members.** After cCp24, only one Tranche 2
  leader remains: `random_medic` (Eredin: Destroyer of Worlds under
  settled §5 — passive Medic mutation). The recommended next phase
  is `random_medic` because it is the last Tranche 2 placeholder
  and unlocks Tranche 3 (`draw_extra_card` setup-time event,
  `discard_two_draw_one_from_deck` multi-stage prompt) and Tranche 4
  (`look_three_cards` reveal, `cancel_leader` suppression).
- **Pre-existing lint warning.** `src/hooks/useReduxAI.ts` still
  reports a `react-hooks/exhaustive-deps` warning. Unrelated to
  cCp24; not surfaced to the cCp24 scope.
- **Coverage backfill candidates remain open.** Decoy + replay
  regression, Decoy + Mardroeme regression, ranged-row Berserker
  round-3 return, and Monsters keep with no eligible units are
  still untouched. cCp24 did not address them; they remain
  candidates for a focused regression phase.

## Reporting Notes For The Coding Agent

The spec asked for the report to call out specifically:

- **Whether The Relentless follows the settled catalog-wins
  opponent-discard rule.** Yes. The cCp24 implementation reads from
  `state.seats[opponentSeat].discard` and moves the chosen card to
  `state.seats[actingSeat].hand`. The deck-tutor reading from the
  printed rulebook is superseded; `docs/gwent-rules.md` §16 and
  `docs/leader-ability-matrix.md` §C-2 are updated to reflect the
  catalog-wins decision. Verified by the
  `"reads opponent discard, not own discard"` test plus the
  full-transaction success test that asserts the chosen card lands
  in `seat_a.hand` after the opponent had it in `seat_b.discard`.
- **Whether no legal move is emitted when opponent discard is
  empty, even if own discard has cards.** Yes. The legal-move
  emitter calls `getOpponentDiscardDrawCandidates({ state, seatId,
  catalogCards })` and returns `[]` when the helper returns zero.
  The dedicated test
  `"emits no use_leader move when opponent discard is empty even
  if own discard has cards"` constructs an own-discard non-empty
  + opponent-discard empty state and asserts no `use_leader` move
  is emitted. Manual `UseLeader` in that state rejects with
  `EngineRuleError("invalid_target", ...)` before cloning state,
  so neither `seat.leaderUsed` nor any other field changes.
- **Whether prompt-open leaves `leaderUsed === false` and keeps
  current turn on the acting seat.** Yes. The `executeLeader`
  branch emits `ability_triggered` and `prompt_opened`, sets
  `state.pendingPrompt`, and returns the transaction without ever
  setting `seat.leaderUsed`, emitting `leader_used`, moving any
  discard card, emitting `card_played`, or calling `handoffTurn`.
  `currentTurn` stays on the acting seat while the prompt is
  pending. Verified by the
  `"emits ability_triggered and prompt_opened, does not move a
  card, does not set leaderUsed, does not emit leader_used, and
  keeps current turn"` test.
- **Whether prompt options preserve opponent discard order.** Yes.
  The helper `getOpponentDiscardDrawCandidates` iterates the
  opponent discard array in insertion order. The dedicated test
  `"opens a choose_card prompt with one option per opponent-discard
  card in discard order"` asserts the prompt options'
  `target.cardId` array equals the discard insertion order
  exactly, with stable option IDs (`draw-opponent-discard:<cardId>`).
- **Whether `getPromptMoves` uses opponent-side targets for
  `draw_opponent_discard` but preserves cCp22 restore target
  behavior.** Yes. `getPromptMoves` branches on
  `prompt.abilityId`: opponent-side
  (`{ kind: "card_instance", side: "opponent",
  seatId: opposingSeatOf(seatId), cardId }`) for
  `draw_opponent_discard`, and own-side
  (`{ kind: "card_instance", side: "own", seatId,
  cardId }`) for `restore_discard_to_hand`. Medic prompts (with
  `row`) continue through the existing own-side path with the row
  preserved. Verified by the cCp24 prompt-move-shape test plus the
  cCp22 restore own-side regression test inside the cCp24 suite.
- **Whether stale prompt targets reject without consuming the
  leader.** Yes. `commands.choosePromptOption` performs a stale-
  target check before cloning state for the new prompt: if the
  chosen card is no longer in `state.seats[opponentSeat].discard`,
  it throws `EngineRuleError("invalid_target", ...)` with no
  mutation. The test
  `"rejects a stale target no longer in opponent discard without
  consuming the leader"` simulates drift (a card leaves opponent
  discard and reappears in the opponent's deck) and asserts the
  resolution throws and `state` is byte-identical before and
  after. `seat.leaderUsed` remains `false`.
- **Whether the chosen card moves to acting hand with owner
  preserved and controller reset to the acting seat.** Yes. The
  resolver explicitly sets `drawn.controller = seatId` (acting)
  before `moveCard(..., { kind: "hand", seat: seatId },
  "leader_draw_opponent_discard_to_hand")`, leaving `owner`
  untouched. Verified by the `owner unchanged` assertion in the
  full-success test and the dedicated off-owner test, where a
  card with `owner: "seat_a"` physically in `seat_b.discard` lands
  in `seat_a.hand` with `owner: "seat_a"` preserved and
  `controller: "seat_a"`.
- **Whether moved cards enter hand without resolving abilities.**
  Yes. `resolvePromptOption`'s new branch moves the chosen card
  from opponent discard to acting hand and emits the standard event
  sequence, but does **not** call `resolveCardAbilities`. The test
  suite verifies that a drawn Yennefer (Medic) does not fire Medic
  and does not open a Medic prompt, and that drawn Frost weather
  lands in hand rather than the weather zone. No `card_played`
  event fires in either case.
- **Whether AI / UI hidden-info boundaries remain intact.** Yes.
  `getPromptMoves` returns `[]` for any seat that does not own the
  prompt, so AI-owned draw-opponent-discard prompts produce no
  `choose_prompt_option` moves visible to the human's legal-move
  list. `summarizeEvents` only exposes `prompt.seatId` /
  `prompt.abilityId` for `prompt_opened`, never option labels or
  card identities. `seatObservation` returns
  `pendingPrompt: null` for the non-prompt-owning seat. Opponent
  discard contents themselves are public per §13 / §17.5, so
  exposing them in prompt options to the prompt owner does not
  leak hidden information.
- **Whether any UI or AI compatibility changes were required.** No
  UI changes. The existing generic `PromptPanel` (in
  `src/components/gwent/AuthenticMatchScreen.tsx`) renders
  `medicOptions.length > 0` only when `prompt.kind ===
  "medic_revive"`; for `choose_card` prompts with non-Medic
  ability IDs, it falls through to the plain labelled-button path
  that uses `option.label` (the human-readable
  `"Draw <card name> from opponent discard"` strings).
  `playMoveHelpers.describePlayTarget` already treats
  `target.row` as optional. `matchViewModel.buildLeaderActionViewModel`
  classifies the new single `use_leader` move as `kind: "single"`,
  so no choice-menu is rendered. No CSS, modal, test-id, or
  AI-policy code changes were necessary.
