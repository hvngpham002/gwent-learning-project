# Cluster C Phase 10 Report - Implemented Engine Ruleset Audit

This is a documentation-only audit per `docs/spec/2026-04-29-cCp10-specs.md`. No implementation code, tests, catalog data, UI, AI policy, simulation code, scripts, or config were changed. The only edits are this report and a `docs/PROJECT_STATE.md` update.

## 1. Executive Summary

The pure engine in `src/game/core/` implements the rule areas listed in `docs/spec/2026-04-29-cCp10-specs.md` for the current Northern Realms vs Nilfgaard preset and resolves the post-cCp9 Mardroeme/Berserker pipeline correctly. Setup, identity, zones, mulligan, normal play, Spy, weather, Clear Weather (card and leader), Decoy, Medic with prompt chains, Special Scorch, Unit Scorch Close, scoring modifier order, board-side discard for Spies and Scorched cards, round resolution, gem decrement, game end, and the four implemented faction passives all line up with `docs/gwent-rules.md` for currently playable matches.

The audit found **0 P0** and **0 P1** issues that block continued rule work for the current default Northern Realms vs Nilfgaard match. Three **P2** divergences appear only when an official starter preset that was added by cBp5 is selected:

- Heroes that print Morale Boost do not boost others on their row (Isengrim Faoiltiarna in the official Scoia'tael starter).
- Units that print Scorch do not actually fire whole-board Scorch (Schirru in the official Scoia'tael starter, plus the catalog-only Clan Dimun Pirate).
- Hero Cerys carries `muster` but no `linkedSourceIds`, so her Muster always resolves with `no_linked_sources` (in the official Skellige starter, deckLimit 1, so it's an effective no-op rather than a wrong-pull bug).

A handful of **P3** documentation/coverage notes are recorded below. None block adding new rule effects, and the recommended next implementation specs are listed at the end.

## 5. Findings (severity-ranked)

No `P0` and no `P1` findings were identified. The three `P2` findings below all surface only when an official starter preset (a cBp5 addition) is selected; the default Northern Realms vs Nilfgaard preset is unaffected.

### [P2] F-1 Hero with `morale_boost` does not boost its row

- Rule reference: `docs/gwent-rules.md` §12 (Morale Boost: "Add +1 Strength to all units on the row excluding itself"); §17.1 ("A Hero's *own* abilities still function").
- Implementation reference: [src/game/core/scoring.ts:233-237](src/game/core/scoring.ts:233) computes `moraleSourceCount = rowSources.filter((source) => source?.kind === "unit" && hasAbility(source, "morale_boost"))`. The `kind === "unit"` filter excludes hero sources, so a hero whose printed ability is Morale Boost contributes zero to the row's morale count.
- Existing tests: [tests/game/coreScoring.test.ts:100-127](tests/game/coreScoring.test.ts:100) covers the unit-source case with Olgierd (kind: `unit`); no test currently covers a hero source with Morale Boost.
- Scenario trace: Play Isengrim Faoiltiarna (`scoiatael.isengrim-faoiltiarna`, `kind: "hero"`, `abilities: ["morale_boost"]`) on close, with two non-hero units already on close. Expected each non-hero unit gets +1 from Isengrim. Observed: zero +1.
- Expected: Isengrim's printed Morale Boost ability adds +1 to other non-hero units on his row (heroes on the row remain immune to receiving the +1 because of §17.1).
- Observed / likely: Isengrim contributes nothing; row total is 1 lower per non-hero ally than the rulebook prescribes.
- Risk: Affects the official Scoia'tael starter (`scoiatael.isengrim-faoiltiarna` count 1 in [official-scoiatael-starter.ts:9](src/data/catalog/deck-presets/official-scoiatael-starter.ts:9)). Worst-case scoring impact is ~+3 strength on close row totals, large enough to flip close-row-only round outcomes. Same class of bug would apply if any future hero prints `tight_bond` or `commanders_horn` (none exist in the current catalog).
- Proposed follow-up: A focused engine spec that drops the `kind === "unit"` filter at [scoring.ts:233](src/game/core/scoring.ts:233) (`unitHornSourceIds` at [scoring.ts:237-241](src/game/core/scoring.ts:237) and `tightBondMultiplier` membership at [scoring.ts:178-193](src/game/core/scoring.ts:178) similarly) so a hero source can emit row-level effects, while keeping receivers gated by `isUnit && !isHero` so heroes remain immune to receiving morale/horn/tight-bond boosts. Add tests asserting Isengrim's row total includes the +1 propagation and that Isengrim himself remains immune.

### [P2] F-2 Unit with `scorch` ability does not fire whole-board Scorch

- Rule reference: `docs/gwent-rules.md` §16 (Clan Dimun Pirate's Scorch follows whole-battlefield Special Scorch rules); §13 (Special Scorch destroys highest non-hero units on the entire battlefield); §17.21 (Clan Dimun Pirate Self-Protection).
- Implementation reference: [src/game/core/legalMoves.ts:328-330](src/game/core/legalMoves.ts:328) routes any `kind === "unit"` or `"hero"` card through `getUnitOrHeroMoves`, which only generates `board_row` moves; [src/game/core/commands.ts:453-457](src/game/core/commands.ts:453) only invokes `resolveSpecialScorch` when `target.kind === "none" && source.kind === "special"`. [src/game/core/abilities.ts:623-625](src/game/core/abilities.ts:623) handles unit `scorch` only by emitting `ability_triggered` plus `ability_deferred("requires_special_resolution")` — no board destruction occurs.
- Existing tests: None. `coreCommands.test.ts:437-487` covers `kind === "special"` Scorch; no test exercises `kind === "unit"` with `scorch` ability.
- Scenario trace: Play Schirru (`scoiatael.schirru`, `kind: "unit"`, `abilities: ["scorch"]`, strength 8, siege) onto own siege when opponent has the highest-strength non-hero unit on the battlefield. Expected: opponent's highest non-hero unit is discarded; Schirru remains at 8. Observed: Schirru lands at 8 strength, the opponent's high unit stays, and event log shows `ability_deferred scorch reason: requires_special_resolution`.
- Expected: Schirru and Clan Dimun Pirate fire a Special-Scorch-equivalent global highest-discard pass on play. Per §17.21, Clan Dimun Pirate cannot discard itself, so the engine must apply a self-protection rule for that source ID.
- Observed / likely: Schirru's scorch does nothing. Clan Dimun Pirate's would also do nothing if anyone played it.
- Risk: `scoiatael.schirru` is in the official Scoia'tael starter ([official-scoiatael-starter.ts:22](src/data/catalog/deck-presets/official-scoiatael-starter.ts:22), count 1). `skellige.clan-dimun-pirate` exists in the catalog ([skellige.ts:200-210](src/data/catalog/cards/skellige.ts:200)) but is not yet in any current playable preset. Both cards advertise abilities to the user that the engine silently does not perform.
- Proposed follow-up: Spec that adds a unit-Scorch path in `commands.ts` for `target.kind === "board_row"` placements where `source.abilities.includes("scorch") && source.kind !== "special"`. Reuse `findSpecialScorchTargets` after placement, with a self-protection filter for `skellige.clan-dimun-pirate`. Update `resolveCardAbilities` to stop emitting `ability_deferred("requires_special_resolution")` for the unit-scorch path. Add focused tests for Schirru and Clan Dimun Pirate (including the self-protection FAQ case).

### [P2] F-3 Catalog Cerys hero is missing `linkedSourceIds`, so her Muster is a no-op

- Rule reference: `docs/gwent-rules.md` §12 (Muster: find all specified cards in hand and deck); §17.11; §17.1 (a hero's own abilities still function).
- Implementation reference: [src/data/catalog/cards/skellige.ts:7-18](src/data/catalog/cards/skellige.ts:7) defines `skellige.cerys` with `abilities: ["muster"]`, `tags: ["hero", "muster"]`, but no `linkedSourceIds`. [src/game/core/abilities.ts:271-279](src/game/core/abilities.ts:271) treats an empty linked set as `outcome: "no_linked_sources"` and does not pull anything.
- Existing tests: None directly. `coreAbilities.test.ts:373-416` covers Crones, Vampires, Arachas, etc., but not Cerys.

## 11. Recommended Next Implementation Specs (ranked)

These are the specs the audit recommends as the next implementation phases. None of the cCp10 findings should block moving on — F-1 / F-2 / F-3 are localized to the cBp5 official starters, while the default Northern Realms vs Nilfgaard match is conformant.

5. **Weather-pulling leaders (`play_frost`, `play_fog`, `play_rain`, `play_any_weather`).** Reuse the existing weather pipeline: leader use places the chosen weather card from deck onto the shared weather zone. Card-search legality is a known surface from `commands.ts` patterns.
