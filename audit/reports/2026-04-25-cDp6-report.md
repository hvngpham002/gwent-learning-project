# Cluster D Phase 6 Report - Engine Shell Playability Polish

## Summary

Improved the opt-in engine shell as a human-vs-AI smoke surface without changing engine rules, legal move generation, command semantics, AI strategy, or the default legacy route.

The shell now uses pure view-model helpers for status copy, hand disabled reasons, grouped target actions, hidden-info-safe command/event summaries, round-end context, and round history rows.

## Files Changed

- `src/components/game/engine/engineShellViewModels.ts`: adds React-free shell view-model helpers.
- `src/components/game/EngineGameManager.tsx`: wires the shell to the new status banner, card affordances, grouped targets, prompt ownership display, recent activity summaries, and round history.
- `src/styles/components/engine-game.css`: adds mobile-safe banner, grouped action, playable/disabled-card, activity, and round-history styles.
- `tests/components/engineShellViewModels.test.ts`: adds focused helper coverage for cDp6 view models.
- `docs/PROJECT_STATE.md`: records cDp6 as implemented and updates status, risks, and next step.
- `audit/reports/2026-04-25-cDp6-report.md`: this report.

## Behavior Changed

- Legacy `/` remains the default app.
- Engine shell remains opt-in through `?engine=1` or `VITE_ENGINE_UI=1`.
- The shell now shows a compact status banner with phase, round, actor/prompt owner, adapter state/lock, and next human action.
- Human hand cards now distinguish playable, selected, and disabled states with safe disabled reasons.
- Selected-card actions are grouped by target kind: rows, horn slots, weather, cards, and global.
- Prompt UI now identifies the prompt owner and distinguishes human options from AI-owned prompt resolution.
- Recent command/event output now uses human-readable, hidden-info-safe summaries.
- Round end now shows score context on the resolve action, and resolved rounds appear in a compact history list.

## Shell Status / Next-Action UX

Added banner messages for startup, mulligan, waiting for AI mulligan, human playing turn, AI playing turn, human prompt, AI prompt, round end, game end, and adapter error.

The banner includes `legal-heuristic-v0` for AI turns so a tester can tell that immediate AI actions come from the current deterministic policy.

## Hand / Target / Prompt Polish

- Hand disabled reasons are derived from phase/status/legal moves: not your turn, prompt pending, no legal move, already passed, not in playing phase, and mulligan complete.
- No React rule recomputation was added; legal moves remain the only executable action contract.
- Target grouping preserves exact legal move targets and dispatches the selected move target unchanged.
- Human prompt option buttons still come from legal `choose_prompt_option` moves.
- AI prompt text avoids option/card details unless already exposed through public shell state.

## AI Action Visibility And Hidden-Info Checks

- The shell shows the active AI policy id.
- AI mulligan summaries show only the number of cards selected, not card IDs or names.
- AI `PlayCard` summaries show a card name only if that card is already visible through public shell card view models; otherwise the summary says the AI played a card.
- The default shell still uses AI hand count only and does not import `selectEngineDebugAiHandCards`.

Hidden-info concern for orchestrator review: verify in browser that Recent Activity remains safe after AI weather/special plays that immediately move to discard. The helper intentionally falls back to generic card labels when the card is not visible in public board/weather/human-hand view models.

## Round / Game Progression Clarity

- Round-end resolve button now includes the current score comparison.
- Game-end panel includes winner/draw plus final gem counts.
- Round history appears after at least one round resolves, with winner/draw, score, and gem loss summary.
- Round end is still explicit; no auto-resolve and no auto-new-game behavior was added.

## Deviations / Limits

- No engine rule, scoring, legal move, command, or AI policy strategy changes were made.
- Browser click-through is documented through route smoke plus helper/Redux coverage rather than full visual browser automation.
- AI action pacing remains immediate and effect-driven; no timers or presentation delays were added.
- The shell is still button-driven and not the final spatial board UX.

## Risks And Follow-Ups

- Hidden-info: Recent Activity intentionally refuses to name AI cards unless visible through public shell view models; browser review should verify this after AI special-card flows.
- AI action loop: `legal-heuristic-v0` can still act immediately after human commands. The new summaries make the result legible, but step-by-step pacing should be a future explicit UX decision.
- Mobile layout: CSS now wraps status chips, action buttons, target groups, and card grids, but final mobile board ergonomics need visual review in a browser.
