## Deck Builder Details

Implemented the handoff's top bar, left deck list, center searchable/filterable card pool, and right validation/stats/deck panel. Controls include `+ New`, `Import`, `Export .json`, lowercase `copy`, `Save`, and `Play ->`. Search was implemented. File upload import and paste import were both implemented.

Prototype details intentionally not ported: stub `CARD_POOL`, `LEADERS_NR`, prototype localStorage shape/key, inline styles, browser globals, toy validation, Card Studio fields, and any repo file writing from browser code.

The card pool derives from `currentCatalogCards`; leaders derive from `currentCatalogLeaders`; local decks use the `CatalogDeckPreset` shape. Future catalog cards automatically appear when their faction is the selected deck faction or `neutral`.

## Persistence And Import/Export

LocalStorage key: `gwent_authentic_decks_v1`.

When storage is empty, the app seeds browser-local editable copies from current catalog presets using `local-` preset IDs. Edits auto-save through the deck-builder update path, and the `Save` button also writes explicitly with a compact notice. Storage failures fall back to in-memory state with a warning.

Export and clipboard copy use:

```json
{
  "schemaVersion": "catalog-deck-preset-v1",
  "preset": {
    "presetId": "...",
    "name": "...",
    "faction": "northern_realms",
    "leaderSourceId": "...",
    "mainDeck": [{ "sourceId": "...", "count": 1 }],
    "sideDeck": []
  }
}
```

Import accepts that wrapper or a raw `CatalogDeckPreset`. Duplicate imported preset IDs receive a new `-imported` ID instead of overwriting.

Review follow-up: import validation now runs before normalization so invalid entries, such as non-positive counts, are rejected instead of being dropped silently. The Play-from-builder path also explicitly persists the active deck before starting the match.

## Validation Rules

Errors block play:

- empty deck name;
- unknown or neutral deck faction;
- missing or wrong-faction leader;
- unknown card references;
- invalid counts;
- wrong-faction cards;
- count above `deckLimit`;
- fewer than 22 battlefield cards, where `unit` and `hero` count;
- more than 10 `special` cards;
- duplicate main-deck entries;
- non-array or non-empty side deck.

Warnings do not block play:

- card ability metadata with `status !== "implemented"`;
- leader ability metadata with `status !== "implemented"`.

Placeholder/planned abilities are warnings only because the current catalog intentionally contains incomplete content, and cEp5 is not allowed to change engine rules. Blocking them would prevent valid current catalog decks, such as Nilfgaard's placeholder leader, from starting even though the engine already treats unsupported leader moves conservatively.

## Pre-Game And Play

Pre-game lists current catalog presets plus browser-local decks. Local decks are subtly marked `local`; invalid local decks are disabled with their first validation error. Opponent choices remain built-in catalog presets only.

`Play ->` starts a match directly from the builder. It saves the current deck, uses the URL seed when present or generates a visible `ep5-*` seed, chooses a built-in opponent by faction, and passes the human deck as an inline `CatalogDeckPreset` to `startEngineMatch`. It does not route back through pre-game and does not add the local deck to `currentDeckPresets`.

## Hidden-Info And Rule Boundary Review

No `src/game/core` rule behavior changed. The deck builder only validates catalog/deck structure and does not compute match legal moves or outcomes. The authentic UI/adapter path still avoids legacy rule helpers, legacy AI, legacy Redux game paths, and `GameBoard`. Browser smoke verifies hidden AI hand cards remain count/back-only after Play-from-builder match start.

## Deviations

Deck faction editing is not exposed in V1; new decks default to Northern Realms as allowed by the spec. Side deck editing remains unsupported and non-empty side decks are validation errors. The deck builder auto-saves on edit while still keeping an explicit Save button.

## Risks / Follow-Ups

- Visual polish can be tightened further after cEp6 content workflows define larger card populations.
- Local decks are browser/profile local only; no cloud/account persistence exists.
- Placeholder/planned abilities remain gameplay limitations until scoped engine specs implement them.
- Card Studio, permanent card authoring, image uploads, and repository file writes remain deferred.
