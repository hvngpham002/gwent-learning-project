## Policy Architecture

`src/game/ai/legalHeuristicPolicyV1.ts` keeps v1 pure over
`EnginePolicyInput`. It builds cheap features from the acting-seat
observation and legal moves, then chooses an existing legal move by
deterministic score ordering with move-id tie-breaks.

The policy branches in this order: prompt, mulligan, round-end, playing
move/pass, deterministic fallback. It never constructs a move.

## Hidden-Info Safety Notes

The policy uses own hand identities, public board/weather cards, public
score breakdowns, public leader status, prompt-exposed options, and
public catalog metadata present in the observation. It does not import
catalog globals, deck presets, raw `MatchState`, `cardsById`, command
logs, event logs, opponent hidden hand identities, opponent deck
identities/order, or unsafe debug benchmark output.

## Mulligan Strategy Details

v1 uses `linkedSourceIds` only:

- redraws `neutral.roach` when a `muster_roach` caller is in hand;
- keeps one-way callers and redraws linked targets such as Darkness or
  Shield Maidens;
- keeps one same-source Muster copy and redraws duplicates;
- treats base Gaunter as the preferred Darkness caller;
- treats Darkness without base Gaunter as same-source Muster;
- keeps hand when no linked target is clearly worse than replacement
  uncertainty.

## Pass And Last-Gem Strategy Details

If the opponent has passed, v1 passes when ahead, otherwise chooses the
cheapest known move that gets ahead. If no known catch-up exists, it
passes unless the AI is on its last gem and a simple visible upper-bound
estimate says catch-up might still be possible.

If the AI is on its last gem outside an opponent-passed state, it passes
only when the same upper-bound estimate cannot catch the opponent. The
estimate is intentionally simple and does not simulate future turns, but
the reviewed implementation counts visible linked hand targets for
Muster callers so the AI does not surrender when a known hand summon can
close the score gap.

## Prompt And Leader Strategy Details

Prompt handling improves over v0 for Medic, restore/draw discard, and
discard/draw stages by scoring strategic card value instead of raw
strength only. `cancel_leader` keeps v0's blunt cancel preference.
`look_three_cards` uses legal order for acknowledgement. Unknown prompts
fall back to exposed target strength and then move id.

Leader handling is conservative: no-value leaders are held. Clear
Weather, weather-pulling leaders, row Scorch leaders, restore/draw,
discard/draw, look-three, cancel, shuffle, and agile leaders receive
value only when legal metadata and visible state show useful current
context.

## Deviations From Spec

- No v1-vs-`legal-first-v0` benchmark suite was generated because the
  spec only required v1-vs-v0 suites and treated v1-vs-legal-first as
  optional context.
- `/ai-lab` remains visually stale about v1 by design; UI updates were
  out of scope and documented as a follow-up.
- Review correction before commit: the first implementation's catch-up
  upper bound did not count visible linked Muster targets already in the
  AI hand. The final version includes those known linked hand targets in
  immediate tempo and adds a focused regression so last-gem/full-send
  behavior does not pass when a visible summon can catch up.

## Risks And Follow-Ups

- v1's upper-bound, weather, Scorch, Decoy, and leader estimates are
  simple visible heuristics; they can miss sacrifice, bait, and
  multi-turn lines.
- v1 may overcommit because it prefers useful positive-scored plays in
  normal rounds unless the hand-count/ahead condition trips.
- v1 may over-pass in some opponent-passed states because unknown future
  value is not modeled.
- Starter matrix results show deck imbalance and should not be reported
  as ratings.
- Recommended next step: review v1 ledgers for narrow v1.1 tuning or add
  mechanics stress suites for Spy, Medic, Muster, Weather, Scorch, Decoy,
  and leader reactions.
