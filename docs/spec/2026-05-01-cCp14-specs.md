# Implementation Spec: Cluster C, Phase 14 - Weather-Pulling Leader Commands

## Intent

Implement the first tranche of non-clear-weather leader commands: leaders that pull weather cards from the acting player's deck and play them into the shared weather zone.

cCp13 closed the linked-Muster cleanup. The next highest-value rules work is to make currently cataloged weather leaders executable while preserving the existing pure-engine contract:

- legal moves enumerate exactly what the engine can execute;
- `UseLeader` dispatches exact legal commands;
- the engine, not UI or Redux, owns the rule outcome;
- hidden information is not leaked through opponent state or raw deck instance IDs.

This phase should support:

- Foltest: King of Temeria (`play_fog`);
- Francesca Findabair: Pureblood Elf (`play_frost`);
- Emhyr var Emreis: His Imperial Majesty (`play_rain`);
- Eredin: King of the Wild Hunt (`play_any_weather`).

It should not implement King Bran, row-Scorch leaders, leader-cancel effects, discard/draw tutors, or generic `summon`.

## User-Facing Rule Decision For This Phase

Weather-pulling leaders search the acting player's own deck for eligible weather cards and play one directly to the shared weather zone.

For cCp14:

- The source card must come from the acting seat's deck only.
- Matching weather cards in hand, discard, board, or already in the weather zone are not eligible.
- The leader is consumed only when a legal eligible deck card is successfully played.
- If no eligible card exists in deck, no `use_leader` move is generated.
- `play_any_weather` may choose among weather effect cards in the acting deck.
- `play_any_weather` must not choose `neutral.clear-weather`; Clear Weather is a special card but not a weather effect card.
- Do not introduce a deck shuffle in this phase. The existing rules docs explicitly mention shuffling for Muster; they do not currently require shuffling after a leader deck-weather search. Preserve the remaining deck order after removing the selected source. If a later rules audit says otherwise, handle it in a separate phase.

## Target Shape And Hidden-Info Contract

Do not expose raw deck instance IDs in legal moves for weather-pulling leaders.

Add a source-level legal target shape, for example:

```ts
{ kind: "deck_card_source"; seatId: SeatId; sourceId: string }
```

Use this target for weather-pulling leader moves.

Rationale:

- The command needs to know which weather source to pull.
- The target should not expose a raw deck card instance ID through legal moves, simulation export, or UI helpers.
- If there are multiple copies of the selected weather source in deck, the command may pull the first matching card in the current deck order.
- The target must include `seatId` and it must equal the acting seat.

Update any target equality, type narrowing, test helpers, or export redaction tests affected by the new target kind.

- `play_fog`

- `play_any_weather`

Keep all other placeholder leader abilities unchanged.

Update tests that currently assert only `clear_weather` is implemented. After cCp14, the implemented leader ability set should be:

```text
play_fog

```

### 2. Weather Source Mapping

Implement a small pure mapping/helper in an appropriate core/catalog-adjacent location.

Required mapping:

- `play_frost` -> `neutral.biting-frost`
- `play_fog` -> `neutral.impenetrable-fog`
- `play_rain` -> `neutral.torrential-rain`
- `play_any_weather` -> any eligible weather effect source in deck:
  - `neutral.biting-frost`
  - `neutral.impenetrable-fog`
  - `neutral.torrential-rain`
  - `neutral.skellige-storm`

Eligibility should be validated against catalog card data, not only hardcoded IDs:

- card exists in `catalogCards`;
- card kind is `special`;
- card is a weather effect source (`abilities` includes `frost`, `fog`, `rain`, or `skellige_storm`, or tags include `weather` and ability is one of those effects);
- `neutral.clear-weather` is excluded.

For the single-weather leaders, the specific source must be present in deck to generate a legal move.

For `play_any_weather`, generate one legal move per eligible weather **source ID** currently present in the acting seat's deck. Do not generate duplicate moves for duplicate copies of the same weather source.

Sort generated `play_any_weather` moves deterministically by source ID or by a documented fixed weather order. Tests should not rely on object iteration order.

### 3. Legal Move Generation

Extend `getLeaderMove` in `src/game/core/legalMoves.ts`.

Keep existing gates:

- phase must be `playing`;
- acting seat must be current turn;
- seat must not have passed;
- no pending prompt;
- leader must exist;
- leader must not already be used;
- ability metadata must be `implemented`.

Current `clear_weather` behavior must remain unchanged:

- target `{ kind: "none" }`;
- legal even when no weather is currently active, matching existing behavior.

Add weather leader behavior:

- If leader ability is `play_frost`, `play_fog`, or `play_rain`, generate one `use_leader` move only when the required source exists in the acting deck.
- If leader ability is `play_any_weather`, generate one `use_leader` move per eligible weather source in the acting deck.
- Each move target should be the source-level deck target described above.
- Move label and metadata should identify the leader and selected weather source enough for diagnostics/UI labels. Add optional metadata fields if useful, such as:
  - `targetRequirement: "deck_weather_source"`;
  - `targetSourceId`;
  - `targetCardName`;
  - `targetLabel`.

If adding metadata fields, update tests/helpers using `UseLeaderMove.metadata`.

Do not generate moves for non-weather placeholder leaders.

### 4. Command Execution

Extend `executeLeader` in `src/game/core/commands.ts`.

Required behavior for weather-pulling leaders:

1. Validate the command through the legal-move path as today.
2. Clone state only after validation, consistent with existing command style.
3. Resolve the leader source and target.
4. Confirm target kind is `deck_card_source`.
5. Confirm target `seatId` equals command `seatId`.
6. Confirm target `sourceId` is eligible for the leader ability.
7. Find the first matching card instance in `state.seats[seatId].deck`.
8. Remove that card from deck and move it to `{ kind: "weather" }`.
9. Set the moved card's `controller` to the acting seat.
10. Emit existing movement/card events in a clear order:
    - `card_moved` with a new reason such as `"leader_weather"` or a documented existing reason;
    - `card_played` with `target` set to the card's weather zone;
    - `leader_used` with the leader ability ID.
11. Mark `seat.leaderUsed = true`.
12. Handoff turn exactly as `clear_weather` does.

If adding a new `card_moved.reason`, update `src/game/core/types.ts` and any affected tests.

Command must reject:

- unsupported/placeholder leader abilities;
- wrong target kind;
- target seat mismatch;
- target source not eligible for the leader ability;
- target source absent from the acting deck;
- attempts while pending prompt exists;
- already-used leader;
- wrong-turn/wrong-phase/passed-seat command, via existing legal validation.

Do not move a weather card from hand/discard/weather/board. Only deck instances are eligible.

### 6. Rules Documentation

Update `docs/gwent-rules.md` with a concise weather-leader note near the weather section or leader section.

- single-weather leaders require their specific weather card in deck;
- `play_any_weather` can choose Frost/Fog/Rain/Skellige Storm from deck;

## Acceptance Criteria

- `play_frost`, `play_fog`, `play_rain`, and `play_any_weather` leader metadata are `implemented`.
- Legal moves expose executable weather-pulling leader actions only when eligible weather source cards exist in the acting deck.
- Legal moves use a source-level deck target, not raw deck card instance IDs.
- `UseLeader` executes weather-pulling leaders through the pure engine and exact legal command path.
- Weather cards pulled by leaders move from acting deck to shared weather zone and become controlled by the acting seat.
- The leader is marked used only after successful execution.
- Turn handoff after leader use matches existing Clear Weather behavior.
- `play_any_weather` can choose Frost/Fog/Rain/Skellige Storm and cannot choose Clear Weather.
- Weather card copies outside deck are ignored.
- Existing Clear Weather leader behavior remains unchanged.
- Non-weather placeholder leaders remain non-executable.
- Official-porting rule-gap classification reflects the newly implemented leader abilities.
- Card Studio validation, if affected by metadata status, now treats the four weather-pulling abilities as implemented.
- `docs/gwent-rules.md`, `docs/PROJECT_STATE.md`, and the cCp14 report are updated.
