# Implementation Spec: Cluster C, Phase 28 - Look Three Cards Leader

## Intent

Implement Tranche 4's first member from `docs/leader-ability-matrix.md`:
`look_three_cards` for `nilfgaard.emhyr-var-emreis-emperor-of-nilfgaard`
(Emhyr var Emreis: Emperor of Nilfgaard).

This phase is the engine's first explicit hidden-info disclosure. The settled
product decision is:

- active one-shot leader;
- usable only in the normal playing phase, like existing active leaders;
- legal only when the opponent has at least one card in hand;
- reveal up to three random opponent hand cards to the acting seat;
- show the revealed cards once in a modal-style acknowledgement surface;
- once dismissed, the reveal cannot be reopened from engine state or product
  UI;
- do not make opponent hand cards persistently face-up after dismissal;
- do not expose revealed card identities to the non-acting seat.

Keep this phase focused on the rule, hidden-info-safe observation/export, the
minimal product UI surface needed for the one-time modal, tests, and living
docs. Do not bundle `cancel_leader`, AI strategy tuning, deck-builder work,
Card Studio work, route promotion, broad match UI redesign, or ML pipeline
changes.

## Rule Semantics For cCp28

### Leader Classification

`look_three_cards` is an implemented active one-shot leader. It should be
derived from the acting seat's leader identity and catalog metadata:

```text
state.seats[seatId].leaderSourceId === "nilfgaard.emhyr-var-emreis-emperor-of-nilfgaard"
catalog leader ability === "look_three_cards"
```

It should emit one legal `use_leader` move only when all normal active leader
gates pass and the opponent has at least one card in hand:

- phase is `playing`;
- current turn is the acting seat;
- acting seat has not passed;
- acting leader is not used;
- no `pendingPrompt`;
- opponent hand length is at least 1.

It should emit no legal move during setup, mulligan, round end, or game end.

It should emit no legal move when the opponent has zero cards in hand. This
avoids consuming the once-per-game leader for a no-op.

### Reveal Count

Reveal count is:

```text
min(3, opponentHand.length)
```

If opponent hand length is 1, reveal that one card.

If opponent hand length is 2, reveal both cards.

If opponent hand length is 3, reveal all three cards.

If opponent hand length is greater than 3, select exactly three cards uniformly
without replacement using the engine's deterministic RNG state.

### Randomness And Ordering

Use the existing deterministic RNG helpers. Recommended shape:

```ts
const rng = createSeededRngFromState(state.rng.seed, state.rng.state);
const shuffledCandidates = shuffleWithRng(opponentHandIds, rng);
const selectedSet = new Set(shuffledCandidates.slice(0, 3));
state.rng.state = rng.getState();
```

Then return the selected cards in the opponent's original hand order for
display and event determinism.

Do not use `Math.random`.

Do not advance RNG when there is no random choice to make:

- opponent hand length 1, 2, or 3 reveals all cards in hand order and leaves
  `state.rng.state` unchanged;
- opponent hand length greater than 3 uses RNG and advances state.

If the implementation chooses to advance RNG for hand length 2 or 3 anyway,
that is a deviation and must be documented. The recommendation above is to
avoid hidden RNG churn for deterministic no-op choices.

### One-Time Disclosure Contract

The reveal is a one-time acknowledgement modal, not persistent face-up opponent
hand state.

Use a pending prompt to block the turn while the acting seat sees the cards:

```text
pendingPrompt.kind === "choose_option"
pendingPrompt.abilityId === "look_three_cards"
pendingPrompt.stage === "opponent_hand_reveal"
pendingPrompt.context.revealedCardIds === selected card ids
pendingPrompt.options === [{ optionId: "look-three-cards:acknowledge", ... }]
```

The prompt option should have a target that carries no card identity, for
example:

```ts
{ kind: "none" }
```

If `PendingPromptTarget` does not currently support `kind: "none"`, add it.

The leader effect succeeds as soon as `UseLeader` selects the reveal and opens
the acknowledgement prompt. Therefore:

- `UseLeader` should set `seat.leaderUsed = true`;
- `UseLeader` should emit `leader_used`;
- `UseLeader` should emit the reveal event;
- `UseLeader` should set `pendingPrompt`;
- `UseLeader` should not hand off the turn because the pending prompt blocks
  handoff.

The acknowledgement command should:

- validate the prompt still exists;
- validate the acting seat owns the prompt;
- validate the single acknowledgement option;
- emit `prompt_resolved`;
- clear `pendingPrompt`;
- hand off the turn through the existing `ChoosePromptOption` path.

After acknowledgement, there should be no remaining `MatchState` field that
lets the UI reopen the same revealed cards. Raw internal events may remain in
the Redux/engine event log like other rule events, but product UI and
hidden-info-safe observation/export surfaces must not provide a reopen path.

### Event Contract

Add a new engine event for the disclosure. Recommended aggregate event:

```ts
{
  type: "opponent_hand_revealed";
  seatId: SeatId;          // seat that used the leader and may see the cards
  opponentSeatId: SeatId;  // seat whose hand was sampled
  cardIds: CardInstanceId[];
  sourceIds: string[];
  reason: "look_three_cards";
}
```

The event log is internal/raw. Hidden-info-safe summaries must not render the
revealed card names or IDs to the opponent.

Recommended event sequence for `UseLeader`:

```text
ability_triggered
opponent_hand_revealed
ability_resolved (outcome: "revealed_opponent_hand")
leader_used
prompt_opened
```

Recommended event sequence for acknowledgement:

```text
prompt_resolved
turn_set (turn_handoff, unless opponent already passed)
```

If a different event order is easier to fit into the command machinery, keep
the same behavior and document the event order in the report and tests.

### Card Eligibility

Every card physically in the opponent hand is eligible:

- Units;
- Heroes;
- Specials;
- Weather;
- generated / side-deck-only cards if they somehow reached hand;
- off-owner cards if they physically sit in the opponent hand.

Missing card instances should be skipped defensively by the helper. Missing
catalog sources should either be skipped or surfaced as a controlled
`EngineRuleError` before mutation; choose one policy and test it. Prefer
skipping missing catalog sources when building display/source ID lists so the
engine does not crash from stale test fixtures.

The leader does not move cards and does not trigger card abilities.
