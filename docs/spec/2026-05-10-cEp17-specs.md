# Cluster E Phase 17 Specs: AI Lab UI Foundation

## Phase ID

`cEp17`

## Purpose

Implement the first product-facing AI Lab route at `/ai-lab`.

This phase turns the cEp15 reserved path into a real authentic UI surface for research status, benchmark-suite visibility, and future experiment entry points. It is a read-only control-plane foundation. It must not run benchmarks, simulations, training, search, ratings, Python tooling, file exports, or unsafe debug output from the browser.

The goal is to make the AI/ML work discoverable from the product shell while preserving the cFp21 boundary: benchmark execution remains a headless/research concern until a later spec defines a safe runner.

## Current Context

cEp15 promoted the authentic UI route contract:

- `/` opens authentic pre-game.
- `/match`, `/deck-builder`, `/card-studio`, `/official-porting`, `/components`, and `/ui-harness` open authentic product/support surfaces.
- `/engine-diagnostic` opens the diagnostic engine shell.
- `/legacy` opens the quarantined legacy route.
- old `/?engine=1` and `/?engine=1&ui=authentic&view=...` URLs remain compatibility aliases.
- `/ai-lab` was reserved but not implemented.

cEp16 moved legacy gameplay under `src/legacy/**` and tightened import boundaries. New product/authentic UI must not import from `@/legacy/...`.

cFp21 added the first benchmark harness under `src/game/benchmark/`:

- suite id: `benchmark-smoke-v1`;
- policies: `legal-heuristic-v0` and benchmark-only `legal-first-v0`;
- six seeds, mirrored, producing twelve records;
- hidden-info-safe default output;
- no file writers, ratings, search, model training, Python tooling, or product UI execution.

The AI Lab should surface this status without pulling benchmark execution into the browser.

## Implementation Requirements

### 1. Add the canonical AI Lab route

Update `src/appMode.ts`:

- extend `AuthenticUiView` with `"ai-lab"`;
- map `/ai-lab` to `{ surface: "authentic", view: "ai-lab" }`;
- keep `/`, `/legacy`, `/engine-diagnostic`, and all cEp15 canonical paths unchanged;
- keep old query aliases unchanged;
- add compatibility support for `/?engine=1&ui=authentic&view=ai-lab` if it fits the existing resolver cleanly.

Update `src/App.tsx` / `src/components/gwent/AuthenticGameApp.tsx` so the authentic app renders a new AI Lab screen when `routeView === "ai-lab"`.

Do not add a router dependency.

### 2. Create an authentic AI Lab screen

Create a product UI surface under the authentic component namespace, for example:

- `src/components/gwent/AuthenticAiLabScreen.tsx`
- `src/components/gwent/aiLabViewModel.ts`
- `src/components/gwent/authentic-ai-lab.css`

Use the existing authentic visual language:

- parchment/paper/rule/accent tokens;
- compact operational layout, not a marketing landing page;
- no nested cards inside cards;
- buttons should follow the established lowercase ghost/primary style from the current authentic UI;
- text should stay within containers on mobile and desktop;
- avoid decorative gradient/orb backgrounds.

Expected layout:

- top bar with `← back`, title `AI Lab`, and a route back to setup;
- benchmark-suite panel for `benchmark-smoke-v1`;
- policy/baseline panel;
- evaluation-ladder panel;
- research decision links panel;
- disabled future actions panel.

The screen should be useful even before execution exists. It should show the current research status plainly and avoid fake metrics.

### 3. Keep benchmark execution out of the browser

The product UI must not call:

- `runBenchmarkSuite`;
- `runHeadlessMatch`;
- `runHeadlessSimulationBatch`;
- training/search/model code;
- Python or filesystem output;
- unsafe/debug benchmark output.

Prefer static/read-only metadata in `src/components/gwent/aiLabViewModel.ts` or a sibling UI data file that mirrors the cFp21 docs:

- suite id: `benchmark-smoke-v1`;
- six seeds;
- mirrored runs enabled;
- twelve expected match records;
- current Northern Realms vs current Nilfgaard;
- `legal-heuristic-v0`;
- `legal-first-v0` as benchmark-only comparator;
- status: available in headless code, browser execution deferred.

If the implementation imports any value from `src/game/benchmark`, the report must justify why that import does not bundle or execute simulation/runtime engine work in the product UI. The preferred implementation is no runtime benchmark import from the AI Lab screen.

### 4. AI Lab content contract

The screen must include these sections.

Benchmark suites:

- show `benchmark-smoke-v1`;
- show 6 seeds, mirrored, 12 records;
- show matchup: current Northern Realms vs current Nilfgaard;
- show status: headless/in-memory available, browser run deferred;
- show disabled `run benchmark` action with a concise reason.

Policy registry:

- show `legal-heuristic-v0` as current product/headless heuristic;
- show `legal-first-v0` as benchmark-only comparator;
- show planned `legal-heuristic-v1` as not implemented;
- make it clear that product difficulty tiers are not implemented yet.

Evaluation ladder:

- show current layer: deterministic smoke/regression ledger;
- show next layers as deferred: fixed-suite matchup matrices, ratings, robustness/search probes, self-play/ML;
- keep this aligned with Batch B's decision that raw ledgers and fixed-suite matrices precede ratings and training.

Research decisions:

- link or reference:
  - `docs/research/literature/ai/decisions/2026-05-09-batch-a-search-baseline.md`;
  - `docs/research/literature/ai/decisions/2026-05-09-batch-b-evaluation-ladder.md`;
  - `docs/research/literature/ai/benchmark-harness.md`;
  - `docs/overhaul-plan/ai-ml-roadmap.md`.

Future actions:

- render disabled controls for `run benchmark`, `export ledger`, `ratings`, `search prototype`, and `training`;
- each disabled control should expose a short reason in accessible text or adjacent compact copy;
- disabled controls must not dispatch benchmark, simulation, or file operations.

### 5. Add navigation from product setup

Update `AuthenticPreGameScreen` so AI Lab is reachable from the main product setup screen.

Place `ai lab →` beside the existing `open deck builder →` and `card studio →` actions in the top bar. Keep the controls compact and consistent with existing button styling.

Do not make the setup screen taller than necessary. If spacing becomes tight, group the secondary tools in a compact right-aligned action cluster.

### 6. Preserve boundaries

No cEp17 code may:

- import from `@/legacy/...`;
- change engine rules, legal moves, scoring, prompts, round resolution, game end, or command transactions;
- change AI policy behavior;
- change simulation or benchmark execution behavior;
- change deck validation, catalog records, Card Studio schema, or official-porting staging data;
- add timers for rule or benchmark transitions;
- expose hidden engine state, raw command logs, raw event logs, hand/deck arrays, or runtime card instance ids.

The AI Lab may show static policy ids, suite ids, deck preset names, and documentation links.

## Out Of Scope

- `legal-heuristic-v1`.
- Running benchmarks from the browser.
- Benchmark result persistence.
- JSONL/file export from the UI.
- Glicko, TrueSkill, approximate best response, search policies, or training.
- Python tooling or notebooks.
- Product difficulty tiers.
- Engine rule, scoring, prompt, round, game-end, or command changes.
- AI policy behavior changes.
- Catalog/deck/Card Studio/official-porting data changes.
- Legacy deletion or route removal.
- Large visual redesign outside the AI Lab and its setup-screen entry point.
