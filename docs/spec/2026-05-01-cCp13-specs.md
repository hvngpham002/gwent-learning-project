# Implementation Spec: Cluster C, Phase 13 - Linked Muster Cleanup And Starter Visibility

## Intent

Resolve the confirmed low-severity linked-effect follow-ups from cCp12 without broadening into a general ability implementation phase.

cCp12 found no P0/P1/P2 issues. It did surface a few player-visible or documentation-risk gaps:

- `skellige.light-longship` has `muster` but no `linkedSourceIds`, so it no-ops in the official Skellige starter.
- `neutral.geralt-of-rivia` and `neutral.cirilla-fiona-elen-riannon` correctly use `muster_roach`, but active starter decks that include them often omit `neutral.roach`, making the printed effect invisible in normal starter play.
- Arachas Behemoth directionality should be explicitly locked: Behemoth pulls regular Arachas; regular Arachas does not pull Behemoth.
- Hemdall is an ability-less hero stat card and should remain that way.
- Crones and Vampires are symmetric family Muster groups, but this should be documented/tested as explicit catalog links rather than runtime string-prefix matching.

This phase should make the official starter experience more faithful and harden the rule taxonomy so future agents do not reintroduce brittle name-prefix behavior.

## User-Confirmed Decisions

Treat these as source-of-truth for cCp13:

- `skellige.light-longship` should behave as same-source Muster: playing one Light Longship pulls other Light Longship copies from the player's hand and deck.
- Starter decks that include Geralt and/or Ciri should include Roach so `muster_roach` can visibly resolve in normal starter play.
- Arachas Behemoth Muster is one-way:
  - playing `monsters.arachas-behemoth` calls regular `monsters.arachas` copies from hand/deck;
  - playing regular `monsters.arachas` does **not** call `monsters.arachas-behemoth`.
- Hemdall is an ability-less hero card, pure strength/stat value.
- Crones and Vampires are symmetric family Muster groups:
  - Crones correspond to the `Crone:` title family;
  - Vampires correspond to the `Vampire:` title family;
  - production engine behavior must remain explicit `linkedSourceIds`, not runtime name-prefix matching.

## Required Implementation

### 1. Light Longship Same-Source Muster

Update the permanent Skellige catalog source:

- `sourceId: "skellige.light-longship"`
- keep current faction/kind/strength/row/image unless a local test proves those fields are already inconsistent;
- keep `abilities: ["muster"]`;
- add `linkedSourceIds: ["skellige.light-longship"]`;
- keep tags aligned with existing Muster/self-source conventions.

Remove Light Longship from any deferred/allowlist path in tests that currently permits `muster` without `linkedSourceIds`.

Add active tests:

- Catalog invariant: Light Longship is part of the known same-source Muster set and links to itself.
- Engine regression: playing one Light Longship pulls other Light Longship copies from hand and deck.
- Engine regression should also prove the resolver does not pull Light Longships already on board or already in discard. This can share the same style as the existing Nekker test.
- If the official Skellige starter contains 3 Light Longships, add/adjust a preset assertion proving the deck now has enough copies for the effect to be visible.

### 2. Roach Starter Visibility

Add `neutral.roach` to starter decks that include `neutral.geralt-of-rivia` and/or `neutral.cirilla-fiona-elen-riannon`, unless that preset already contains Roach.

Implementation rules:

- Do this for both `current-*` and `official-*` deck presets in `currentDeckPresets`, not only the official starters.
- Add one Roach copy per affected preset.
- Do not exceed `neutral.roach`'s deck limit.
- Do not remove Geralt or Ciri to make room unless a deck validation test proves a hard deck-size invariant requires it. The current deck validator cares about minimum battlefield count and caps, not a fixed total deck size.
- Do not add Roach to a deck that contains neither Geralt nor Ciri.
- Do not change Roach's own ability. Roach must remain non-recursive and must not summon Geralt or Ciri.

Add active tests:

- Catalog/deck preset test: every current deck preset containing Geralt or Ciri also contains at least one Roach.
- Catalog/deck preset test: Roach count never exceeds its deck limit.
- Engine `muster_roach` path already has coverage; add a starter-level smoke if useful, but avoid redundant engine tests unless an existing Roach regression gap is obvious.

### 3. Arachas Behemoth Directionality

Keep production behavior one-way:

- `monsters.arachas-behemoth.linkedSourceIds` must equal `["monsters.arachas"]`.
- `monsters.arachas.linkedSourceIds` must equal `["monsters.arachas"]`.
- `monsters.arachas` must not link to `monsters.arachas-behemoth`.

Convert the cCp12 ambiguity from a `todo` into active documentation/invariant coverage.

Add active tests:

- Catalog invariant explicitly asserting the one-way Behemoth relationship.
- Engine regression if not already present: playing Behemoth pulls regular Arachas copies from hand/deck.
- Engine regression or catalog assertion proving regular Arachas does not pull Behemoth. Prefer an engine regression if the helper setup is compact; catalog assertion is acceptable if the shared resolver path is already covered.

### 4. Hemdall Ability-Less Hero Lock

Keep Hemdall as:

- `sourceId: "skellige.hemdall"`;
- `kind: "hero"`;
- `abilities: ["none"]`;
- `tags` include `hero` and `side_deck_only`;
- linked only as Kambi's Avenger replacement.

Add or keep active invariant coverage:

- Hemdall has no implemented/on-play ability to fire.
- Hemdall remains `side_deck_only`.
- Kambi links to Hemdall through `linkedSourceIds[0]`.

Do not add an on-summon ability or trigger `resolveCardAbilities` for Hemdall when Avenger summons it.

### 5. Muster Taxonomy Documentation

Update `docs/gwent-rules.md` section 17.11 or nearby relevant text to distinguish the known Muster categories:

- **Exact-source copy Muster:** Arachas, Nekker, Ghoul, Havekar Smuggler, Dwarven Skirmisher, Elven Skirmisher, Light Longship.
- **Symmetric family Muster:** Crones and Vampires. The family is title-like (`Crone:` / `Vampire:`), but the engine must use explicit `linkedSourceIds`, not runtime string-prefix matching.
- **One-way linked Muster:** Cerys -> Shield Maidens, Arachas Behemoth -> Arachas, Gaunter -> Darkness, Geralt/Ciri -> Roach.
- **Non-reciprocal exceptions:** Darkness does not pull base Gaunter; regular Arachas does not pull Arachas Behemoth; Roach does not pull Geralt/Ciri.

Do not rewrite the whole rulebook.

### 6. Linked Invariant Cleanup

Update `tests/catalog/linkedAbilityInvariants.test.ts` so it reflects the now-confirmed decisions:

- Remove Light Longship from the "Muster without linked IDs" deferred allowlist.
- Remove or replace the Arachas Behemoth reciprocal-pull `it.todo` with active one-way assertions.
- Keep the `summon` resolver `it.todo`.
- Keep placeholder leader tutor/restore `it.todo` unless unrelated tests force movement.
- Add/clarify tests for Crones and Vampires as symmetric family groups over explicit links.

The test names should be readable enough that a future agent can infer the rule without reopening the report.
