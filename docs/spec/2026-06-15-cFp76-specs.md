## Summary

cFp75 paused blind third-ply execution and chose the next executable target:

> `search-consumer-action-features-v0`

cFp76 should implement that target as a benchmark-only feature-consumer
artifact layer over committed cFp68-cFp74 readiness artifacts. It should
extract compact root-level feature rows, audit whether true per-root-public-
action feature rows are derivable from committed scalar artifacts, and either:

1. emit hidden-info-safe action feature rows when durable public-action
   identities are actually present; or
2. stop at a deterministic `action_feature_source_gap` status and write an
   explicit gap artifact/report when committed sources only contain aggregate
   public-action counts.

cFp76 must not re-observe benchmark roots, rebuild sampled states, execute
commands, count third-ply surfaces, run rollouts, evaluate/rank/select actions,
or wire anything into product AI. This phase is the consumer contract test: can
future search code consume existing readiness evidence without new hidden-info
risk or another command-execution layer?

## Why This Phase Exists

The current determinized probe ladder is now mechanically mature:

- cFp68: valid-root-only determinized probe contract with explicit skipped-root
  accounting.
- cFp69: public-action root scaffold.
- cFp70: sampled-world action availability.
- cFp71: one-ply public-action outcome skeleton.
- cFp72: post-one-ply next-surface branching budget.
- cFp73: scalar casebook over cFp72 branching pressure.
- cFp74: bounded second-ply public-action scaffold.
- cFp75: search-consumer contract decision; paused third-ply execution and
  selected `search-consumer-action-features-v0` for cFp76.

cFp74 proved second-ply command execution can complete for in-cap roots with
zero failed/deferred pairs. It also showed the cost curve is already large:
robust cFp74 completed 5,101,445 second-ply pairs and wrote a compact 58.288 MB
root JSONL.

cFp76 should not deepen the probe. It should make the first consumer-facing
artifact boundary: feature rows a future PIMC/ISMCTS/evaluator can inspect
without touching raw states, private identities, command logs, event logs, or
sampled hands/decks.

## Scope

Implement a benchmark-only search-consumer feature artifact layer that:

1. reads committed cFp68-cFp74 artifact sets for current and robust starter
   suites;
2. validates source summaries and root/skipped row consistency;
3. computes SHA-256 source references for all consumed source artifacts;
4. emits one compact root-level feature row per cFp68 eligible root;
5. emits inherited skipped-root rows with skip counters;
6. audits whether per-root-public-action feature rows can be derived from
   committed scalar artifacts without new command execution;
7. emits action feature rows only if durable per-action identities exist in
   committed sources;
8. emits deterministic action-feature gap rows when durable per-action
   identities are missing;
9. writes deterministic hidden-info-safe artifacts under
   `search-consumer-action-features-v0/cFp76/`;
10. updates AI Lab metadata to cFp76 as feature-consumer infrastructure, not
    search gameplay;
11. updates docs and project state; and
12. creates the required cFp76 audit report.

cFp76 should add pure benchmark modules, artifact serializers, a CLI script,
npm scripts, and tests. It should not call `runBenchmarkSuite`, `executeCommand`,
`getLegalMoves`, sampler materialization, sampled-state rebuild, or any engine
command path.

## Action Feature Rows And Gap Handling

cFp76 must audit committed sources for durable per-public-action identities.

A durable action identity requires at least:

- a deterministic public action reference not derived from raw move ids;
- public action kind;
- target kind;
- target side;
- stable root linkage; and
- matching per-action availability/outcome/budget fields or an explicit source
  path showing how those fields are derived.

If committed artifacts only expose aggregate count maps such as
`publicActionKindCounts`, `targetKindCounts`, `targetSideCounts`, or transition
counts, that is not enough for true action-level feature rows.

When durable action identities are absent:

- write an empty `action-features.jsonl`;
- write `action-feature-gaps.jsonl` with deterministic rows describing the gap;
- set summary `consumerReadinessStatus` to `action_feature_source_gap`;
- set action feature counts to zero;
- record the source phases that lack durable action identities; and
- recommend cFp77 as a narrow public-action-identity artifact, not command
  execution, unless the user explicitly chooses otherwise.

When durable action identities are present:

- write one `action-features.jsonl` row per root-public-action pair;
- keep action rows scalar and hidden-info-safe;
- enforce the size limits below; and
- keep source derivation deterministic.

Do not fabricate `publicActionRef`. Do not derive it from raw move id, runtime
move id, command payload, card source id, card instance id, or raw labels.

## Action Feature Gap Rows

Each `action-feature-gaps.jsonl` row should include:

- `schemaVersion`
- `featureRunId`
- `suiteId`
- `gapKind`, expected `action_feature_source_gap`
- `gapScope`, such as `suite`, `phase`, or `source_artifact`
- `sourcePhase`, such as `cFp69`, `cFp70`, `cFp71`, `cFp72`, `cFp74`
- `missingFieldCategory`, such as `durable_public_action_identity`
- `affectedRootCount`
- `affectedActionFeatureCountEstimate` when derivable from aggregate counts
- `recommendedNextStep`

No hidden payloads may appear in gap rows.

## Budget And Size Limits

- Robust `action-features.jsonl` target: below 50 MB.
- Hard stop before writing if any single generated artifact would reach 90 MB.
- No gzip or binary artifact workaround.
- No full command/event/state payloads.
- Sparse count maps where applicable.
- Run/source constants belong in manifest/summary, not every row.

If action feature rows exceed the robust 50 MB target:

1. stop before committing artifacts;
2. report the projected size and row count;
3. recommend a deterministic action-feature casebook subset for the next phase;
4. do not silently trim evidence; and
5. do not add compression.
