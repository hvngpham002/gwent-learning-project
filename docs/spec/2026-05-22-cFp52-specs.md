# cFp52 Specs: Round-One Guard Fixture Reproduction Debug

## Summary

`cFp52` is a reproduction/debug phase over the two robust
`round_one_overinvestment` findings that cFp51 classified as
`guard_recommended_play_selected`.

cFp51 deliberately avoided a behavior patch because the public failure-mining
row is case-level aggregate evidence. cFp52 should now replay only the two exact
robust fixtures, extract a hidden-info-safe per-decision projection for the
target v1 seat, and decide whether the aggregate signal is:

1. a real policy contradiction, where a selected play-card decision had
   `roundOneOverinvestmentRecommended === true` but the policy still played;
2. a lossy case-level aggregation artifact, where the overinvestment finding
   combines earlier/later decisions in a way that does not imply a selected
   play contradiction;
3. an analyzer-calibration problem;
4. insufficiently explained by current telemetry, requiring one more narrow
   diagnostic field.

Do not change `legal-heuristic-v1` behavior in cFp52. If a real contradiction is
confirmed, write it down as the cFp53 behavior-repair scope.

The implementation may adjust names if the final API is cleaner, but it must
provide equivalent data.

Fixture reproduction requirements:

- Use the existing `benchmark-v1-starter-matrix-robust-v1` suite definition.
- For each fixture, find the exact matchup and seed.
- Apply the requested `mirrorIndex` exactly:
  - mirror `0` means the suite's original `seat_a` / `seat_b` assignment;
  - mirror `1` means swap the matchup seat definitions before running;
  - the debug run should execute exactly one match per fixture.
- Run with:
  - `includeDecisionTraces: true`;
  - `includeDebugResults: true`;
  - the suite default `maxSteps` unless an existing benchmark default is
    required.
- Filter decision traces to:
  - `trace.policyId === "legal-heuristic-v1"`;
  - `trace.seatId === fixture.targetSeatId`;
  - `trace.phase === "playing"`;
  - `trace.round === 1`;
  - `trace.roundInvestmentAnalysis` exists.

### 2. Hidden-Info-Safe Projection Only

Do not serialize raw `AiDecisionTrace`, raw `HeadlessMatchSimulationResult`,
`unsafeDebugResults`, `MatchState`, command logs, event logs, legal move arrays,
candidate card labels, hand arrays, deck arrays, discard arrays, raw card
instance ids, card source ids, card names, or action refs.

The debug projection may include only:

- public benchmark ids;
- seat id;
- policy id;
- faction;
- deck preset id;
- match outcome;
- scalar public state fields already used in product diagnostics;
- scalar `roundInvestmentAnalysis` fields;
- selected move kind / target kind / public target label;
- derived booleans listed above.

`selectedTargetLabel` is allowed only when it is a public coarse target such as
`own close`, `own ranged`, `own siege`, `weather`, or `none`. If the selected
trace target label is missing, card-like, source-id-like, instance-id-like, or
otherwise suspicious, store `null` instead.


5. Fixture A Per-Decision Debug
6. Fixture B Per-Decision Debug
7. Contradiction Assessment
8. Analyzer Calibration Assessment
9. Recommended cFp53 Scope

The decision note must answer:

- Did either fixture reproduce a selected play-card decision with
  `baseGeometryReached === true`,
  `roundOneOverinvestmentRecommended === true`, and
  `selectedKind === "play_card"`?
- If yes, which decision index or indices?
- Were the recommendations later paired with a selected pass, or did the policy
  continue playing afterward?
- Do the two cases support a behavior patch, a scanner/analyzer calibration, or
  more telemetry?

Decision rules:

- If both fixtures confirm selected-play contradictions, recommend a narrow
  cFp53 behavior repair against that exact public state shape.
- If one fixture confirms and one does not, recommend a cFp53 repair only if the
  confirmed fixture exposes a simple code-path bug; otherwise recommend
  analyzer calibration.
- If neither fixture confirms, recommend analyzer calibration and keep behavior
  tuning paused.
- Do not recommend threshold widening from cFp52 unless the decision note
  explicitly explains why the two fixtures prove a narrow threshold bug without
  reintroducing the cFp36 broad-resource regression.
