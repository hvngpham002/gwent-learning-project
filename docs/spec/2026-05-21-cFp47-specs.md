# cFp47 Specs: Rating Snapshot And Comparison Ledger

## Summary

`cFp47` builds directly on cFp46. cFp46 created deterministic Glicko-1 rating
artifacts for fixed benchmark suites, but those artifacts are still one-off
snapshots under `ratings/latest/`. The next evaluation gap is longitudinal:
when a future policy change or benchmark refresh happens, we need to compare
rating movement against a named baseline without manually eyeballing W/L totals.

This phase adds a deterministic, hidden-info-safe rating snapshot and comparison
ledger. It should freeze the current cFp46 rating artifacts as named baselines,
then generate comparison artifacts that can later compare `latest` against those
baselines within the same suite.

This phase must not change AI behavior.

## Research Grounding

Use the Batch B decision note as the controlling project decision:

- Raw fixed-suite match records remain the source of truth.
- Ratings are post-engine evaluation infrastructure.
- Ratings must keep suite, policy, deck, faction, sample count, and uncertainty
  visible.
- Rating movement must be interpreted with uncertainty; do not claim product
  difficulty or exploitability from a rating delta.
- Do not compare ratings across different suite pools unless the report clearly
  marks that comparison as invalid or unsupported.

Use the cFp46 outcome as the immediate input:

- cFp46 ratings are deterministic Glicko-1 reports over existing public
  `records.jsonl` artifacts.
- cFp46 artifacts use repo-relative source paths and are safe to commit.
- cFp46 artifacts are a baseline snapshot, not a trend line by themselves.

## Scope

In scope:

- Add a pure benchmark rating comparison module that compares two rating
  artifacts from the same suite.
- Add a deterministic snapshot/ledger artifact format for named rating
  snapshots.
- Freeze the current cFp46 `ratings/latest` artifacts as a named `cFp46`
  baseline for:
  - `benchmark-v1-starter-matrix-v1`
  - `benchmark-v1-starter-matrix-expanded-v1`
- Generate initial comparison artifacts comparing the cFp46 baseline to current
  `latest` for both suites. Because `latest` is expected to equal the new cFp46
  snapshot in this phase, all deltas should be zero. The value is the durable
  comparison boundary for future phases.
- Add CLI/npm commands for snapshotting and comparing rating artifacts.
- Update benchmark docs, v1 policy docs, AI Lab metadata, project state, and
  create the cFp47 report.

Out of scope:

- AI policy behavior changes.
- Engine rules, legal moves, scoring, prompts, command execution, UI gameplay
  behavior, catalog data, deck presets, benchmark suite definitions,
  failure-mining classifiers, long-run profiles, or product difficulty tiers.
- Re-running match simulations.
- Changing cFp46 Glicko formulas or rating values.
- TrueSkill, Elo-only ratings, multi-player ratings, online persistence,
  database storage, self-play, search, model training, exploitability probes, or
  browser execution of rating generation.

## Inputs

The snapshot/comparison layer must consume only cFp46 rating artifacts:

```text
docs/research/literature/ai/benchmark-results/<suiteId>/ratings/latest/manifest.json
docs/research/literature/ai/benchmark-results/<suiteId>/ratings/latest/ratings.json
docs/research/literature/ai/benchmark-results/<suiteId>/ratings/latest/report.md
```

It must not read:

- raw engine state;
- command logs;
- event logs;
- observations;
- hands;
- decks;
- deck order;
- unsafe debug results;
- runtime card instance ids;
- decision trace payloads.

It may read `records.jsonl` only indirectly through metadata already recorded in
the rating artifacts. cFp47 should not need to parse match records.

## Artifact Layout

Use a layout under each suite's existing rating directory.

Required named snapshot directory:

```text
docs/research/literature/ai/benchmark-results/<suiteId>/ratings/snapshots/cFp46/
  manifest.json
  ratings.json
  report.md
```

The snapshot may copy the cFp46 `latest` rating artifact content exactly, or it
may write an equivalent self-contained snapshot artifact with the same rating
entries. Prefer copying/normalizing the existing cFp46 rating artifact bundle
without changing rating values.

Required suite-level ledger:

```text
docs/research/literature/ai/benchmark-results/<suiteId>/ratings/ledger.json
```

`ledger.json` must be deterministic and should include:

- `schemaVersion`;
- `suiteId`;
- `snapshots[]`;
- for each snapshot:
  - `snapshotId`;
  - `label`;
  - `sourceRecordsPath`;
  - `sourceRecordCount`;
  - `eligibleRecordCount`;
  - `ignoredRecordCount`;
  - `ratingsJsonHash`;
  - `reportMdHash`;
  - `createdByPhase`;
  - `notes`.

Required comparison directory:

```text
docs/research/literature/ai/benchmark-results/<suiteId>/ratings/comparisons/cFp46-vs-latest/
  manifest.json
  comparison.json
  report.md
```

The comparison artifact must be self-contained and deterministic.

## Comparison Semantics

Only compare rating artifacts from the same `suiteId`.

If `base.suiteId !== candidate.suiteId`, fail with a clear error. Do not add a
flag to bypass this in cFp47.

Compare every matching scope/key pair:

- `policy`
- `policy_deck`
- `policy_faction`
- optional future scopes if present in both artifacts

For each entry, include:

- `scope`;
- `key`;
- `label`;
- `status`: `"common" | "new" | "removed"`;
- base fields:
  - `baseRating`;
  - `baseRd`;
  - `baseConservativeRating`;
  - `baseGames`;
- candidate fields:
  - `candidateRating`;
  - `candidateRd`;
  - `candidateConservativeRating`;
  - `candidateGames`;
- deltas:
  - `deltaRating`;
  - `deltaRd`;
  - `deltaConservativeRating`;
  - `deltaGames`;
- uncertainty:
  - `combinedRd = sqrt(baseRd^2 + candidateRd^2)` for common entries;
  - `deltaOverCombinedRd = deltaRating / combinedRd` when `combinedRd > 0`;
- interpretation:
  - `signal`: `"no_change" | "directional_gain" | "directional_regression" | "uncertain" | "new_entry" | "removed_entry"`;
  - `note`: concise plain-English caution text.

Suggested signal rules:

- `new_entry` for entries absent in base and present in candidate.
- `removed_entry` for entries present in base and absent in candidate.
- `no_change` when all rating/RD/conservative/game deltas are zero.
- `directional_gain` when `deltaConservativeRating > 0` and
  `deltaOverCombinedRd >= 0.5`.
- `directional_regression` when `deltaConservativeRating < 0` and
  `deltaOverCombinedRd <= -0.5`.
- `uncertain` for all other common-entry movements.

These are comparison labels, not statistical proof. The report must say that
`directional_*` is a heuristic comparison label, not exploitability or product
difficulty.

## Initial cFp47 Comparison Expectations

Because cFp47 freezes the current cFp46 `latest` artifacts and compares them to
the same current `latest` artifacts:

- all common entries should have zero `deltaRating`;
- all common entries should have zero `deltaRd`;
- all common entries should have zero `deltaConservativeRating`;
- all common entries should have zero `deltaGames`;
- all common entries should have `signal: "no_change"`;
- no entries should be `new` or `removed`.

If this is not true, stop and investigate before committing.

## CLI And NPM Commands

Add commands that future agents/users can run without hand-editing paths.

Required npm scripts:

```json
{
  "benchmark:ratings:compare:v1-starter-matrix": "...",
  "benchmark:ratings:compare:v1-expanded": "..."
}
```

The commands should:

1. ensure the `cFp46` snapshot exists for the suite;
2. write/update `ratings/ledger.json`;
3. compare `ratings/snapshots/cFp46` to `ratings/latest`;
4. write `ratings/comparisons/cFp46-vs-latest/manifest.json`;
5. write `ratings/comparisons/cFp46-vs-latest/comparison.json`;
6. write `ratings/comparisons/cFp46-vs-latest/report.md`.

The CLI may expose more flexible options, for example:

```bash
tsx scripts/run-benchmark-rating-comparison-report.ts \
  --suite benchmark-v1-starter-matrix-v1 \
  --base-snapshot cFp46 \
  --candidate latest
```

Path requirements:

- Store only repo-relative paths with forward slashes in artifacts.
- Reject paths outside the repository root.
- Do not store `C:\`, `/Users/`, backslash paths, or absolute checkout paths.

## Artifact Safety

Comparison artifacts must be hidden-info safe.

No generated artifact may contain:

- `cardsById`
- `finalState`
- `commandLog`
- `eventLog`
- `ownHand`
- `opponentHand`
- `seat_a:`
- `seat_b:`
- `unsafeDebugResults`
- absolute local paths such as `C:\` or `/Users/`

It is acceptable for comparison keys to include public policy ids, deck preset
ids, factions, suite ids, scope names, and benchmark artifact paths.

## Tests

Add focused tests for:

1. Pure comparison:
   - common entry with positive rating delta;
   - common entry with negative rating delta;
   - no-change self comparison;
   - new entry;
   - removed entry;
   - combined RD and `deltaOverCombinedRd` calculation.
2. Suite validation:
   - comparison rejects mismatched `suiteId`.
3. Signal labels:
   - `no_change`;
   - `directional_gain`;
   - `directional_regression`;
   - `uncertain`;
   - `new_entry`;
   - `removed_entry`.
4. Artifact serialization:
   - deterministic output across two builds;
   - manifest includes hashes and source labels;
   - `comparison.json` is self-describing;
   - report includes warnings about uncertainty and suite-local interpretation;
   - no hidden-info hazard strings;
   - no absolute local paths.
5. AI Lab:
   - metadata points at cFp47 after implementation;
   - capability text mentions rating snapshots/comparisons;
   - does not claim live/browser-run ratings or product difficulty.

Avoid brittle tests that require spawning `tsx` on Windows if that platform still
has known local spawn issues. Prefer pure serializer tests and script-level
tests only where they are robust.

## Acceptance Criteria

cFp47 is complete when:

- The current cFp46 rating artifacts are frozen as named `cFp46` snapshots for
  both required suites.
- `ledger.json` exists for both required suites and lists the `cFp46` snapshot.
- `cFp46-vs-latest` comparison artifacts exist for both required suites.
- Initial cFp46-vs-latest comparisons show zero deltas and `no_change` signals
  for common entries.
- Comparison artifacts reject cross-suite comparisons.
- Generated artifacts are deterministic and hidden-info safe.
- `/ai-lab` metadata points at cFp47 and does not claim live/browser-run ratings
  or product difficulty.
- No AI behavior, engine rules, legal moves, UI gameplay behavior, catalog data,
  deck presets, benchmark suite shape, failure-mining classifier, Glicko formula,
  search, training, or product difficulty changed.
