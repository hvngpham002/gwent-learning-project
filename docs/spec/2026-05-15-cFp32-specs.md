## Purpose

Patch one specific `legal-heuristic-v1` failure mode: v1 can still continue
investing into a non-elimination round after the current public state already
says the round is probably lost and the future hand should be preserved.

cFp31 added `roundInvestmentAnalysis`, but the latest playtest shows it is too
weak in a "behind, no clean catch-up, low hand" line. cFp32 should make v1 more
willing to sacrifice that non-elimination round before it burns its last useful
cards.

This is not a request to make v1 more passive in general. It is a stop-loss
patch.

## Goals

1. Refine cFp31 so `roundInvestmentAnalysis` recommends `sacrifice_round` for
   non-elimination rounds where catch-up is publicly impossible or too expensive
   and the selected move would spend scarce future hand.
2. Make the policy actually pass in that stop-loss state.
3. Keep the diagnostic explanation in parity with the policy decision.
4. Preserve existing last-gem behavior, Spy/card-advantage exceptions,
   single-card safeguards, cFp30 weather placement, cFp29 Medic timing, cFp28
   hand-shape calibration, cFp27 mulligan diagnostics, and hidden-info safety.
5. Refresh v1 benchmark artifacts and product AI metadata after the behavior
   change.

## Required Implementation

### 1. Modify The Existing Round-Investment Layer

Primary file:

```text

```

Prefer refining the existing cFp31 helper path instead of adding a separate
parallel pass system:

- `buildLegalHeuristicV1RoundInvestmentDecision(...)`
- `shouldPassForRoundInvestment(...)`
- the call site inside `choosePlayingMove(...)`

The policy and explanation must both use the same helper. Do not duplicate the
same thresholds in `explainLegalHeuristicV1Decision.ts`.

### 2. Use Pass Diagnostics For Stop-Loss

Use the existing pass diagnostics rather than recalculating them differently:

```ts
buildLegalHeuristicV1PassDecisionDiagnostics(features)
```

The stop-loss gate should consider:

- `hasSingleMoveCatchUp`
- `policyUpperBoundCanWinRound`
- `minimumScoreToWinRound`
- `ownWinsTiedRound`
- `lastGemSurrenderAllowed`

Do not implement a second incompatible estimate of "can still win the round."

### 4. Stop-Loss Gate Conditions

The new sacrifice-round pass should only be considered when all baseline
conditions hold:

- legal pass move exists;
- opponent has not passed;
- `ownGems > 1`;
- current phase is normal playing through the existing `choosePlayingMove`
  path;
- selected candidate would spend a hand card;
- selected candidate is not a clear card-advantage move;
- the AI is not on a single-card hand;
- existing last-gem fight/impossible-catch-up behavior is not being evaluated.

Then recommend `sacrifice_round` when the public catch-up diagnosis is bad and
the future-hand cost is meaningful:

```text
scoreDelta < 0
AND hasSingleMoveCatchUp === false
AND (
  policyUpperBoundCanWinRound === false
  OR selected move would leave no positive unit/hero future move
  OR selected move would leave no unit/hero tempo card
)
AND (
  ownHandCount <= 4
  OR selected move is a low-effective-tempo weathered placement
  OR selected move is a Medic with only none/weak/medium revive value
)
```

The diagnostic-anchor Trace 9 must satisfy this gate and choose `pass`.

### 5. Preserve These Exceptions

Do not block these cases with the new gate:

- Last gem:
  - existing last-gem fight / impossible-catch-up policy stays authoritative;
  - if `ownGems <= 1`, the new non-elimination sacrifice gate should not apply.
- Opponent already passed:
  - existing opponent-passed catch-up/preserve-hand logic stays authoritative.
- Spy/card-advantage:
  - do not suppress a Spy or clear card-advantage move merely because the round
    is behind.
- Single-card hand:
  - preserve the previous single-card safeguard. The AI may still play/pass
    through existing logic, but cFp32 should not add a new sacrifice block here.
- Clean catch-up:
  - if `hasSingleMoveCatchUp === true`, do not sacrifice the round.
- Upper-bound possible:
  - if `policyUpperBoundCanWinRound === true`, be conservative about sacrifice
    unless the future-hand risk is clearly critical.

### 6. Weather Interaction

cFp30 weather-aware placement remains intact.

If the selected move is into a weathered row and `selectedEffectiveStrengthBucket`
is `"low"`, that should be treated as extra evidence for stop-loss when catch-up
is already poor.

Do not make weathered-row placement globally illegal. There are valid cases
where every useful option is weathered or where the play is still correct.

### 7. Medic Interaction

cFp29 Medic timing remains intact.

If the selected move is a Medic and the best revive value bucket is `"none"`,
`"weak"`, or `"medium"`, that should be treated as extra evidence for stop-loss
when catch-up is already poor.

Do not globally ban medium-value Medic plays. The diagnostic-anchor case is
specifically:

- non-elimination round;
- behind;
- no single-move catch-up;
- upper-bound cannot win;
- low hand;
- medium-or-worse Medic value.

### 8. Explanation Parity

Update:

```text
src/game/ai/explainLegalHeuristicV1Decision.ts
```

The explanation must call the same round-investment helper as the policy.

When cFp32 triggers a pass, the selected trace should show:

- `reasonKind: "policy-round-investment"`
- `roundInvestmentAnalysis.recommendation: "sacrifice_round"`
- a hidden-info-safe reason string that mentions stop-loss / sacrifice / future
  hand in broad terms.

Do not generate "voluntary pass safe" text for a cFp32 sacrifice pass.

### Engine Policy Tests

Add focused tests for:

1. **Diagnostic anchor reproduction**
   - non-elimination round;
   - AI behind by roughly 12;
   - `ownHandCount` around 4;
   - no single-move catch-up;
   - upper-bound cannot win;
   - candidate spends hand;
   - expected selected move: `pass`;
   - expected reason kind: `policy-round-investment`;
   - expected recommendation: `sacrifice_round`.

2. **Last gem untouched**
   - same broad shape but `ownGems === 1`;
   - cFp32 non-elimination gate must not be the reason;
   - if catch-up is impossible, existing last-gem impossible-pass reason may
     still choose pass.

3. **Opponent-passed branch untouched**
   - opponent already passed;
   - existing catch-up/preserve-hand branch should decide.

4. **Spy/card-advantage exception**
   - selected card-advantage move remains playable and is not blocked solely by
     the stop-loss gate.

5. **Single-card safeguard**
   - with one card in hand, cFp32 does not add a new sacrifice-round block.

6. **Clean catch-up regression**
   - if a single move can win/tie as needed, the policy does not sacrifice.

7. **Upper-bound-possible regression**
   - if `policyUpperBoundCanWinRound === true`, cFp32 does not sacrifice unless
     an explicit critical future-hand case is being tested.

8. **Weathered low-tempo evidence**
   - behind/no-clean-catch-up/low hand plus a low-effective-tempo weathered-row
     candidate should sacrifice rather than spend into weather.

9. **Medic medium-target evidence**
   - behind/no-clean-catch-up/low hand plus medium-or-worse Medic target should
     sacrifice rather than spend Medic.
