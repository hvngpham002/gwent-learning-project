## Summary

cFp73 completed a benchmark-only casebook over the committed cFp72
post-one-ply branching budget artifacts. It found:

- source consistency ready in both current and robust suites;
- 0 status anomalies;
- 0 `very_large` or `extreme` cFp72 budget buckets;
- current: 1,291 casebook roots / 63 inherited skipped roots;
- robust: 10,721 casebook roots / 340 inherited skipped roots;
- robust casebook size comfortably below the artifact-size danger zone; and
- a recommendation to proceed with a bounded second-ply scaffold before any
  search, value, ranking, or product-AI claim.

cFp74 should implement that scaffold. It should execute a bounded second public
action only inside cloned sampled states, emit hidden-info-safe scalar
outcome/count artifacts, and report every skipped-over-budget root beside the
probe result.

This is still not search gameplay. cFp74 must not rank actions, choose a best
action, estimate value, estimate win probability, roll out, train, or wire
anything into product AI. It is a deterministic budget and transition-shape
probe for the second public action layer.

## Why This Phase Exists

The ladder has been intentionally incremental:

- cFp68: valid-root-only contract with explicit skipped-root accounting.
- cFp69: public-action root scaffold.
- cFp70: sampled-world root action availability.
- cFp71: one-ply public-action outcome skeleton.
- cFp72: post-one-ply next-surface branching budget.
- cFp73: scalar casebook over cFp72 branching pressure.

cFp72 proved that post-one-ply next surfaces can be measured. cFp73 showed the
surface is broad but not explosive: there are many large/transition-context
rows, but no status anomalies and no `very_large` or `extreme` roots.

cFp74 should answer the next mechanical question:

> If we cap the second public-action layer explicitly, can the benchmark
> execute that layer deterministically while preserving skip accounting and
> hidden-info safety?

This is not the point where search becomes "good." It is the point where the
second layer becomes mechanically observable with explicit budget boundaries.

## Scope

Implement a benchmark-only bounded second-ply public-action scaffold that:

1. reads committed cFp68 eligible/skipped contract artifacts;
2. reads committed cFp69 public-action scaffold artifacts;
3. reads committed cFp70 sampled-world action-availability artifacts;
4. reads committed cFp71 one-ply outcome skeleton artifacts;
5. reads committed cFp72 post-one-ply branching budget artifacts;
6. reads committed cFp73 post-one-ply branching budget casebook artifacts;
7. re-observes the matching benchmark roots using the established cFp69-cFp72
   observer path;
8. regenerates cFp61-style hidden source-multiset samples in memory;
9. rebuilds sampled root states in memory using the existing cFp70 sampled-root
   rebuild path;
10. executes the same deterministic first-ply representative public actions
    used by cFp71/cFp72 inside cloned sampled states;
11. computes the next public-action buckets after that first ply;
12. applies the cFp74 cap policy before any second-ply execution;
13. skips over-budget roots with explicit over-budget counters and rows;
14. for roots inside the caps, executes one deterministic representative
    concrete move for each second-ply public-action bucket in each sampled
    post-one-ply state;
15. records only scalar second-ply completion and transition-shape counts;
16. carries inherited skipped roots from cFp68/cFp69/cFp70/cFp71/cFp72;
17. attaches cFp73 casebook labels to cFp74 summaries where available; and
18. writes deterministic hidden-info-safe artifacts.

The implementation may reuse and export existing cFp70/cFp71/cFp72 helpers if
needed. Prefer small mechanical helper exports over creating a second sampled
state rebuild path.

## Cap Policy

Use these default constants:

- `SECOND_PLY_PAIR_CAP_PER_ROOT = 512`
- `ROOT_PUBLIC_ACTION_CAP = 16`
- `POST_ONE_PLY_PUBLIC_ACTION_CAP_PER_STATE = 16`
- `SAMPLE_COUNT_CAP_PER_ROOT = 8`
- `ROBUST_TOTAL_PLANNED_SECOND_PLY_PAIR_SOFT_CAP = 7_500_000`

Definitions:

- A "planned second-ply pair" is one sampled post-one-ply state plus one
  second-ply public-action bucket representative.
- The cFp72 row field `postOnePlyPublicActionBudgetTotal` is the source of
  truth for the planned second-ply pair count before cFp74 re-executes
  anything.
- If a cFp72 branching root has `postOnePlyPublicActionBudgetTotal >
  SECOND_PLY_PAIR_CAP_PER_ROOT`, cFp74 must not execute any second-ply command
  for that root. Emit it as an over-budget root with
  `overBudgetReason: "root_second_ply_pair_cap_exceeded"`.
- If `rootPublicActionCount > ROOT_PUBLIC_ACTION_CAP`, skip the root with
  `overBudgetReason: "root_public_action_cap_exceeded"`.
- If `nextPublicActionCountMax >
  POST_ONE_PLY_PUBLIC_ACTION_CAP_PER_STATE`, skip the root with
  `overBudgetReason: "post_one_ply_public_action_cap_exceeded"`.
- If `sampleCountChecked > SAMPLE_COUNT_CAP_PER_ROOT`, skip the root with
  `overBudgetReason: "sample_count_cap_exceeded"`.
- If a source consistency problem exists, mark the summary `not_ready` and do
  not claim scaffold readiness.
- If the robust planned in-cap pair total exceeds
  `ROBUST_TOTAL_PLANNED_SECOND_PLY_PAIR_SOFT_CAP`, stop and redesign the cap
  boundary before committing artifacts.

The cap policy must be deterministic and reported in `summary.json`,
`manifest.json`, and `report.md`.

Do not partially execute roots above cap. This first cFp74 scaffold is
root-bounded, not action-bounded. Partial within-root execution would make
interpretation harder and risks quietly hiding the high tail.

## Probe Algorithm

For each cFp72 branching root:

1. Validate matching cFp68/cFp69/cFp70/cFp71/cFp72/cFp73 source keys and
   artifact hashes.
2. Read the cFp72 scalar row.
3. Attach cFp73 casebook labels if the root appears in cFp73; otherwise attach
   `casebookPresence: "not_in_casebook"`.
4. Apply the cFp74 cap policy from cFp72 scalar fields.
5. If over budget, emit an `over-budget-roots.jsonl` row and do not execute any
   sampled command for that root.
6. If in budget:
   - re-observe the benchmark root;
   - regenerate cFp61-style hidden source-multiset samples in memory;
   - rebuild sampled root states through the established cFp70 path;
   - collapse root legal moves into public action buckets;
   - choose the same deterministic first-ply representative concrete move per
     root public-action bucket used by cFp71/cFp72;
   - execute the first-ply representative command inside a cloned sampled
     state;
   - compute the next legal move surface;
   - collapse that next legal move surface into second-ply public-action
     buckets;
   - choose one deterministic representative concrete move per second-ply
     public-action bucket;
   - execute that second-ply representative command inside a cloned
     post-one-ply sampled state;
   - record scalar completion, failure/deferred, and transition-shape counts.

Stop after the second-ply command. Do not compute a third-ply legal move
surface in cFp74.
