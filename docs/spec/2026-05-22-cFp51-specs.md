# cFp51 Specs: Round-One Guard Telemetry Casebook

## Summary

`cFp51` is an analysis-only phase over the cFp50 guard-state telemetry.

The goal is to use the newly-added scalar telemetry on
`round_one_overinvestment` findings to decide whether the next phase should be:

1. a narrow `legal-heuristic-v1` behavior patch;
2. failure-mining analyzer calibration;
3. more telemetry;
4. ratings/search/evaluation ladder work.

Do not change AI behavior in cFp51. This phase should produce a compact
decision artifact and update AI Lab metadata.

## Research Grounding

cFp49 recommended telemetry because public aggregate findings could not
distinguish threshold misses, exceptions, and intentional suppressed passes.
cFp50 added that telemetry.

cFp51 should now answer a narrower research question:

> Do the remaining robust `round_one_overinvestment` findings reveal a simple,
> safe, repeated behavior patch, or are they mostly late suppressed passes,
> analyzer artifacts, and edge cases?

Interpretation rules:

- Treat cFp50 telemetry as public artifact evidence.
- Use committed artifact files only.
- Do not infer card identities.
- Do not read raw engine state, command logs, event logs, private observations,
  hand/deck/discard arrays, deck order, runtime card instance ids, or raw
  decision traces.
- The decision should be evidence-led. Do not force a behavior-patch
  recommendation if the evidence is mixed.

## Required Analysis

Use only committed public artifact rows from the cFp50 failure-mining outputs.

The decision note must include the sections below.

List exact artifact files used:

- robust failure-mining summary;

### 2. cFp50 Telemetry Topline

Summarize the cFp50 artifact facts:

| Suite | Findings | `round_one_overinvestment` | Telemetry available | Base geometry | Recommended play count | Suppressed pass count |
|---|---:|---:|---:|---:|---:|---:|

Expected values from cFp50:

```text
current starter matrix: 300 findings, round_one_overinvestment=6, telemetry=6, baseGeometry=0, recommended=0, suppressedPass=1

robust starter matrix: 2301 findings, round_one_overinvestment=71, telemetry=71, baseGeometry=10, recommended=4, suppressedPass=48
```

If committed artifacts disagree, trust the artifacts and explain the mismatch
in the report.

### 3. Robust Classification

Classify each robust `round_one_overinvestment` finding into exactly one of the
following public categories:

```text
guard_recommended_play_selected
guard_base_geometry_exception_or_non_recommendation
guard_suppressed_late_pass_no_play_recommendation
board_floor_never_reached
hand_cap_never_reached
other_no_base_geometry
telemetry_unavailable
```

Suggested classification logic:

1. If `roundOneGuardTelemetryAvailable !== true`, classify as
   `telemetry_unavailable`.
2. Else if `roundOneGuardBaseGeometryCount > 0` and
   `roundOneRecommendedCount > 0`, classify as
   `guard_recommended_play_selected`.
3. Else if `roundOneGuardBaseGeometryCount > 0`, classify as
   `guard_base_geometry_exception_or_non_recommendation`.
4. Else if `roundOneSuppressedPassCount > 0`, classify as
   `guard_suppressed_late_pass_no_play_recommendation`.
5. Else if `roundOneBoardFloorReachedCount === 0`, classify as
   `board_floor_never_reached`.
6. Else if `roundOneHandCapReachedCount === 0`, classify as
   `hand_cap_never_reached`.
7. Else classify as `other_no_base_geometry`.

Expected robust counts from the current cFp50 artifact:

```text
guard_suppressed_late_pass_no_play_recommendation: 44
board_floor_never_reached: 20
guard_base_geometry_exception_or_non_recommendation: 4
guard_recommended_play_selected: 2
hand_cap_never_reached: 1
other_no_base_geometry: 0
telemetry_unavailable: 0
```

The decision note must include:

- category counts;
- category by outcome;
- category by faction;
- category by matchup id;
- sample finding ids for each non-empty category.

### 4. Guard-Recommended Play Cases

List every robust finding classified as `guard_recommended_play_selected`.

For each row include:

- finding id;
- faction;
- matchup id;
- seed;
- mirror index;
- `round1PlayCardCount`;
- `matchOutcome`;
- `roundOneGuardBaseGeometryCount`;
- `roundOneRecommendedCount`;
- `roundOneReasonBoardLimitCount`;
- `roundOneExceptionCardAdvantageCount`;
- `roundOneExceptionSingleMoveCatchUpCount`;
- `roundOneSelectedCardAdvantageCount`;
- `roundOneCatchUpSingleMoveCount`;
- `roundOneRecommendationContinueCount`;
- `roundOneRecommendationPreserveFutureHandCount`.

These are the highest-priority cases for potential behavior repair, because
the artifact says base geometry and recommendation appeared during selected
play-card decisions.

The note must say whether two cases are enough for a behavior patch or whether
they need manual trace reproduction first.

### 5. Base-Geometry Exception Cases

For robust findings classified as
`guard_base_geometry_exception_or_non_recommendation`, aggregate:

- exception counts;
- card-advantage selected counts;
- single-move catch-up counts;
- score-delta direction counts;
- recommendation counts.

This section must decide whether these are valid tactical exceptions,
instrumentation artifacts, or behavior candidates.

### 6. Suppressed-Late-Pass Cases

For robust findings classified as
`guard_suppressed_late_pass_no_play_recommendation`, aggregate:

- `round1PlayCardCount`;
- max board after selected move buckets;
- min hand after selected move buckets;
- suppressed pass count;
- reason board-limit count;
- recommendation preserve-future-hand count;
- outcome/faction/matchup.

This section should answer:

- Did cFp43 already intervene late?
- Did aggregate overinvestment remain because the guard fired after several
  earlier plays?
- Would a behavior patch need cumulative-spend state rather than a one-move
  threshold change?

### 7. Board-Floor / Hand-Cap Misses

For `board_floor_never_reached`, aggregate:

- `round1PlayCardCount`;
- max board after selected move;
- min hand after selected move;
- selected card-advantage count;
- catch-up single-move count.

For `hand_cap_never_reached`, list the one expected robust case and explain why
it does or does not suggest widening `ROUND_ONE_OVERINVESTMENT_HAND_AFTER_CAP`.

### 8. Patch-Shape Assessment

Evaluate these possible cFp52 shapes:

1. **Bug repair for guard-recommended play cases**
   - Only valid if `guard_recommended_play_selected` indicates a real policy
     contradiction.
2. **Cumulative spend guard**
   - Example concept: after N round-one play-card decisions, use a cumulative
     public budget even if one-move base geometry did not fire.
3. **Threshold widening**
   - Lower board floor or raise hand cap.
4. **Analyzer calibration**
   - If many findings are already suppressed late-pass cases or board-floor
     artifacts.
5. **No behavior patch**
   - Move toward search/ratings or mechanics/competitive benchmark decks.

The note must explicitly choose one recommendation and reject the others with
evidence.

### 9. Recommended cFp52 Scope

End with a concrete cFp52 recommendation.

Allowed recommendation shapes:

- behavior patch spec;
- reproduction/debug spec for the two guard-recommended play cases;
- cumulative-spend telemetry spec;
- analyzer calibration spec;
- pause v1 tuning and move to ratings/search/stronger benchmark decks.

If recommending a behavior patch, the note must name the exact public telemetry
pattern that justifies it and must explain why it is not expected to repeat the
cFp36 broad-resource-gate regression.
