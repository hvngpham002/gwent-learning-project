# Implementation Spec: Cluster D, Phase 11 - Safe Export Validation And JSONL Boundary

## Goal

Add runtime validation and deterministic in-memory JSONL serialization for `sim-export-v1`.

`cDp10` created a hidden-info-safe in-memory export contract. Phase 11 should make that contract harder to misuse before any data leaves memory:

- validate export datasets structurally and semantically;
- detect obvious hidden-info leaks and raw debug objects;
- serialize validated datasets to deterministic JSONL strings;
- parse JSONL strings back into records/datasets for tests and future tooling;
- keep all IO, CLI, Python, training, tensorization, and storage out of scope.

This is the serialization boundary, not the ML pipeline.

## Architecture Position

Current state after `cDp10`:

- `buildSimulationExportDataset` emits deterministic `sim-export-v1` datasets in memory;
- rows contain `safe-observation-v1`, `legal-action-v1`, chosen action index, sparse `reward-v1`, outcome metadata, and diagnostics;
- rows are generated from pre-command replay state and legal moves;
- default rows exclude raw `finalState`, `commandLog`, full events, `cardsById`, raw engine card instance ids, opponent hidden hand identities, opponent deck identities/order, and own deck order;
- `includeSystemActions: true` can include `resolve_round_end` diagnostic rows, but default policy datasets exclude them;
- there is no runtime schema validation and no JSONL boundary yet.

Phase 11 should validate and serialize the safe contract without expanding the contract into training infrastructure.

## Scope

### 1. Add pure validation and JSONL modules

Extend `src/game/sim/` with validation and serialization modules.

Suggested files:

- `src/game/sim/exportValidation.ts`
- `src/game/sim/exportJsonl.ts`
- updates to `src/game/sim/exportTypes.ts`
- updates to `src/game/sim/index.ts`

The exact split can differ, but keep the code pure and deterministic.

Allowed dependencies:

- `src/game/sim/*`
- TypeScript/standard JavaScript runtime functions such as `JSON.parse` and `JSON.stringify`

Forbidden dependencies:

- React;
- Redux store, slices, selectors, or thunks;
- engine UI components;
- browser APIs;
- timers;
- localStorage;
- Node filesystem APIs such as `fs`;
- path/process/environment-specific data;
- schema libraries unless the project already has one and the report justifies using it;
- legacy `src/ai/*`;
- legacy `src/utils/gameHelpers.ts`;
- legacy `gameSlice`, `gameThunks`, or `gameSelectors`.

Do not add a new dependency for validation or JSONL in this phase. A small hand-written validator is enough.

### 2. Define validation result types

Add structured validation types. Suggested:

```ts
export type SimulationExportValidationSeverity = "error" | "warning";

export interface SimulationExportValidationIssue {
  severity: SimulationExportValidationSeverity;
  code: string;
  path: string;
  message: string;
}

export interface SimulationExportValidationSummary {
  errorCount: number;
  warningCount: number;
  rowCount: number;
  matchCount: number;
  systemRowCount: number;
}

export interface SimulationExportValidationResult {
  valid: boolean;
  issues: SimulationExportValidationIssue[];
  summary: SimulationExportValidationSummary;
}
```

Add public helpers:

```ts
export const validateSimulationExportDataset = (
  value: unknown,
  options?: SimulationExportValidationOptions,
): SimulationExportValidationResult => ...

export const assertValidSimulationExportDataset = (
  value: unknown,
  options?: SimulationExportValidationOptions,
): asserts value is SimulationExportDataset => ...
```

Suggested options:

```ts
export interface SimulationExportValidationOptions {
  allowSystemActions?: boolean;
  requireNoWarnings?: boolean;
}
```

Defaults:

- `allowSystemActions: true`, because `includeSystemActions: true` is a valid diagnostic dataset;
- `requireNoWarnings: false`;
- `valid` should be false if there are errors, and also false if `requireNoWarnings` is true and warnings exist.

### 3. Validate top-level dataset invariants

The validator should check at least:

- top-level value is a plain object;
- `schemaVersion === "sim-export-v1"`;
- `generatedBy === "headless-simulation-export"`;
- `seeds` is an array of strings/numbers;
- `policiesBySeat` has string ids for `seat_a` and `seat_b`;
- `rows` is an array;
- `rowCount === rows.length`;
- `matchCount` is a non-negative number;
- `summary.schemaVersion === "sim-export-v1"`;
- `summary.rowCount === rows.length`;
- `summary.matchCount === matchCount`;
- `summary.policyRowCount + summary.systemRowCount === rows.length`;
- summary counts are internally consistent where practical;
- row ids are unique.

Do not try to prove game correctness in the validator. This is a contract validator, not a replay checker.

### 4. Validate each decision row

For every row, validate at least:

- `schemaVersion === "sim-export-v1"`;
- deterministic scalar fields exist: `rowId`, `matchId`, `seed`, `step`, `commandIndex`, `actorKind`, `seatId`, `policyId`;
- `actorKind` is `policy` or `system`;
- `seatId` is `seat_a` or `seat_b`;
- observation schema version is `safe-observation-v1`;
- legal actions is an array;
- `legalActionCount === legalActions.length`;
- `legalActionMask.length === legalActions.length`;
- all legal action mask values are `true`;
- `chosenActionIndex` is an integer inside legal action bounds;
- `chosenAction` deeply equals `legalActions[chosenActionIndex]`;
- every legal action has schema version `legal-action-v1`;
- every legal action id is row-local, for example `action_0`, `action_1`;
- every legal action index matches its array index;
- reward schema version is `reward-v1`;
- `terminalMatchReward` is `-1`, `0`, `1`, or `null`;
- `isTerminalMatchRow` is boolean;
- outcome contains a valid status and final gem counts.

System action handling:

- If `allowSystemActions` is false, rows with `actorKind === "system"` or `chosenAction.kind === "resolve_round_end"` should be validation errors.
- If `allowSystemActions` is true, system rows are allowed but should still count in the validation summary.

### 5. Validate hidden-info and raw-debug redaction

Add a recursive redaction scanner for the default safe dataset shape.

It should flag errors for forbidden keys anywhere in the dataset:

- `finalState`;
- `commandLog`;
- `cardsById`;
- `instanceId`;
- `moveId`;
- `rawResult`;
- `events` when it contains raw event arrays from cDp8;
- `ownHand`;
- `opponentHand`;
- `deck` when it is an array.

Be careful not to flag safe fields that are intentional:

- `sourceId` is allowed for visible cards;
- `deckCount` is allowed;
- `cardCountInHand` is allowed;
- `cardsInHand` is allowed for the acting seat's own observation.

It should flag suspicious string values:

- raw generated card instance id patterns such as `/seat_[ab]:/`;
- raw action ids or refs that look like engine move ids, for example strings starting with `play:`, `mulligan:`, or `leader:` in exported action ids/card refs.

It should specifically verify:

- `row.observation.opponent` does not contain `cardsInHand`;
- `row.observation.opponent` does not contain deck arrays;
- `row.observation.own` does not contain deck arrays;
- prompt option `targetStrength` is absent when `target` is absent;
- legal action `source`, `target`, and `prompt` refs do not include raw engine card ids.

Keep issue messages actionable and include paths such as:

- `rows[3].observation.opponent.cardsInHand`;
- `rows[12].legalActions[4].actionId`;

### 6. Add JSONL record types

Add explicit JSONL schema versioning. Suggested:

```ts
export const SIMULATION_EXPORT_JSONL_SCHEMA_VERSION = "sim-export-jsonl-v1";
```

Use a small record union:

```ts
export interface SimulationExportJsonlHeaderRecord {
  recordType: "dataset_header";
  jsonlSchemaVersion: typeof SIMULATION_EXPORT_JSONL_SCHEMA_VERSION;
  exportSchemaVersion: typeof SIMULATION_EXPORT_SCHEMA_VERSION;
  generatedBy: "headless-simulation-export";
  suiteId: string | null;
  seeds: readonly (string | number)[];
  policiesBySeat: Record<SeatId, string>;
  rowCount: number;
  matchCount: number;
  summary: SimulationExportSummary;
}

export interface SimulationExportJsonlDecisionRecord {
  recordType: "decision_row";
  jsonlSchemaVersion: typeof SIMULATION_EXPORT_JSONL_SCHEMA_VERSION;
  row: SimulationDecisionRow;
}
```

Header plus rows is preferred:

- first line: `dataset_header`;
- subsequent lines: one `decision_row` per dataset row.

Do not include raw debug data in JSONL records.

### 7. Serialize deterministic JSONL in memory

Add a public serializer. Suggested:

```ts
export interface SerializeSimulationExportJsonlOptions {
  validate?: boolean;
  includeHeader?: boolean;
}

export const serializeSimulationExportDatasetToJsonl = (
  dataset: SimulationExportDataset,
  options?: SerializeSimulationExportJsonlOptions,
): string => ...
```

Defaults:

- `validate: true`;
- `includeHeader: true`.

Behavior:

- if validation fails and `validate` is true, throw an error that includes validation issue codes;
- generate deterministic JSONL for the same dataset;
- use `\n` between lines;
- do not require a trailing newline;
- every line must be valid JSON;
- output must not contain raw debug keys or hidden-info patterns.

It is acceptable to use `JSON.stringify` on records constructed in stable field order. If the implementation adds a stable stringify helper, keep it local and dependency-free.

### 8. Parse JSONL in memory

Add a parser/round-trip helper. Suggested:

```ts
export interface ParseSimulationExportJsonlResult {
  header: SimulationExportJsonlHeaderRecord | null;
  rows: SimulationDecisionRow[];
  dataset: SimulationExportDataset | null;
  issues: SimulationExportValidationIssue[];
}

export const parseSimulationExportDatasetJsonl = (
  jsonl: string,
): ParseSimulationExportJsonlResult => ...
```

Behavior:

- parse line-delimited JSON;
- ignore one trailing blank line if present;
- return structured parse issues for invalid JSON, unknown record type, missing header, row-count mismatch, or schema-version mismatch;
- reconstruct a `SimulationExportDataset` when a valid header is present;
- validate the reconstructed dataset and return validation issues;
- do not throw for ordinary malformed input unless the implementation also provides an `assert` helper.

## Out Of Scope

- Do not write JSONL files to disk.
- Do not add a CLI.
- Do not add Python, notebooks, model training, self-play workers, tensorization, fixed neural action vectors, or reward shaping.
- Do not add a runtime schema library dependency.
- Do not add a database, storage format, compression, or upload path.
- Do not change the `sim-export-v1` row meaning except for narrow fixes needed to validate it safely.
- Do not change engine rules, legal move generation, scoring, command semantics, round resolution, or AI strategy.

## Acceptance Criteria

- `validateSimulationExportDataset` or equivalent API is exported from `src/game/sim`.
- `assertValidSimulationExportDataset` or equivalent assertion helper is exported.
- Validation catches structural dataset errors, row/action alignment errors, schema-version errors, and hidden-info/raw-debug redaction violations.
- Validation allows valid `sim-export-v1` datasets from cDp10.
- Validation can reject system-action datasets when `allowSystemActions: false`.
- JSONL schema version constant exists.
- Serializer emits deterministic in-memory JSONL strings with a header record and one decision-row record per dataset row by default.
- Serializer validates before emitting by default.
- Parser returns header, rows, reconstructed dataset, and structured issues without throwing for ordinary malformed input.
- JSONL round-trip preserves dataset rows and summary for a valid dataset.
- JSONL output does not contain `finalState`, `commandLog`, `cardsById`, `instanceId`, raw generated card ids, opponent hidden hand arrays, opponent deck arrays/order, or own deck arrays/order.
- Docs explain validation, JSONL shape, and the no-file-writing/no-training boundary.
- `docs/PROJECT_STATE.md` is updated.
- `audit/reports/2026-04-26-cDp11-report.md` exists.
- `npm test` passes.
- `npm run ci` passes.
- `npm run ci:browser` passes or is explicitly documented if local browser permissions block it.
- `git diff --check` passes.

## Required Tests / Checks

At minimum, add tests under:

- `tests/game/simulationExportValidation.test.ts`

Minimum test coverage:

- current `buildSimulationExportDataset({ batchInput: { suiteId: currentSimulationSmokeSuite.id } })` validates with zero errors;
- validation detects:
  - bad top-level schema version;
  - `rowCount` mismatch;
  - duplicate row id;
  - chosen action index out of bounds;
  - chosen action mismatch;
  - malformed action id;
  - forbidden `commandLog`, `finalState`, `cardsById`, or `instanceId` key;
  - raw generated `seat_a:` or `seat_b:` id string;
  - opponent `cardsInHand`;
  - deck arrays where only counts are allowed;
  - prompt `targetStrength` without prompt `target`;
- `allowSystemActions: false` rejects a dataset produced with `includeSystemActions: true`;
- JSONL serialization is deterministic for repeated calls;
- JSONL has one header line plus one line per row by default;
- every JSONL line parses as JSON;
- JSONL output passes the same redaction string checks as cDp10 export rows;
- parser round-trips a valid JSONL string into an equivalent dataset summary and rows;
- parser returns issues for malformed JSON, unknown record type, missing header, and row-count mismatch.
