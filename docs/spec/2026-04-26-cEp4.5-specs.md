# Implementation Spec: Cluster E, Phase 4.5 - Pre-Game Visual Fidelity Follow-Up

## Goal

Bring the cEp4 pre-game setup screen visually closer to the selected UI handoff prototype while preserving the cEp4 architecture and behavior.

This is a bounded visual-fidelity follow-up, not a new product phase. The production pre-game screen should feel much closer to `docs/ui-handoff/prototype/pre-game-screen.jsx`: a parchment-backed fixed-table composition adapted responsively, a strong top bar, two balanced paper panels, deck tiles with leader thumbnails and ready state, mode tiles with compact icon/name/description hierarchy, opponent/round/format/seed controls, and a bottom action bar.

This phase also tightens leader-card sizing consistency inside the actual match/gameboard: the leader card plus frame used by score cards in `AuthenticMatchScreen` should match the foundation's medium card dimensions.

## Architecture Position

Before this phase:

- `/?engine=1&ui=authentic` opens the cEp4 product pre-game setup screen.
- `/?engine=1&ui=authentic&view=match` opens the direct engine-backed match route.
- `/?engine=1&ui=authentic&view=harness` opens the cEp1 harness.
- Pre-game is already catalog-backed and starts matches through a serializable setup config.
- Current visual fidelity is functional but not close enough to the prototype layout.

After this phase:

- Route behavior above must remain unchanged.
- Pre-game should look materially closer to the handoff prototype.
- The match setup logic, catalog source, disabled future modes, seed behavior, and Begin Match transition must remain intact.
- cEp5 deck builder remains next after this visual correction.

## Scope

### 1. Preserve cEp4 Behavior Exactly

Do not change the product flow.

Requirements:

- `/` remains legacy.
- `/?engine=1` remains diagnostic shell.
- `/?engine=1&ui=authentic` remains pre-game.
- `/?engine=1&ui=authentic&view=pregame` remains pre-game.
- `/?engine=1&ui=authentic&view=match` remains direct match.
- `/?engine=1&ui=authentic&view=harness` remains harness.
- Begin Match still passes the selected setup config into `AuthenticMatchScreen`.
- `startEngineMatch` behavior must not change.
- Current catalog presets remain the only real deck/opponent data.
- Only the implemented Human vs AI path is enabled.
- Disabled future modes/formats stay disabled.
- Mulligan remains in-match.

### 2. Match The Handoff Composition More Closely

Rework `AuthenticPreGameScreen` markup and CSS toward the handoff's composition.

Target desktop composition:

- outer screen should read as a 1200-ish by 780-ish tactical table surface centered in the viewport;
- use `display: grid` with top bar, body, and bottom action bar;
- top bar should visually match:
  - left `Menu`/back ghost button;
  - centered or left-title block with `Prepare for Battle`;
  - right deck-builder ghost button;
  - `2px` strong bottom rule or equivalent;
  - `var(--bg-paper)` background;
- body should be a two-column grid with generous padding and gap, close to the prototype's `28px` padding and `24px` gap on desktop;
- left panel should be deck selection;
- right panel should be match configuration;
- bottom action bar should be a strong horizontal bar with summary left and primary Begin Match right.

Responsive requirement:

- keep the prototype's visual proportions on desktop, but do not lock production to exactly `1200px x 780px`;
- at tablet/mobile widths, stack panels and keep the action bar readable;
- no document-level horizontal overflow at `390px`.

### 3. Add The Prototype Parchment Flourish

The handoff prototype uses a subtle 120x120 dot/grid flourish.

Requirements:

- Add a subtle background pattern to the pre-game surface.
- Prefer CSS gradients or a small inline decorative SVG in React.
- If using inline SVG, it must be `aria-hidden`, `focusable="false"`, and pointer-events none.
- Opacity should be restrained, around the prototype's `0.06` visual weight.
- Do not add decorative orbs, bokeh, oversized gradients, or marketing-style hero art.

### 4. Deck Panel Visual Fidelity

Make deck choices look like the prototype while using current catalog data.

Requirements:

- Panel label should read close to `step 1 - choose deck` or `step 1 — choose deck`.
- Deck options should be tall horizontal buttons.
- Each option should show:
  - compact leader card/thumbnail on the left;
  - deck name in italic display type;
  - faction in uppercase/mono or compact label;
  - concise card readiness line such as `36 cards · ready`;
  - selected checkmark on the right.
- Selected state should use:
  - `2px` accent border;
  - `rgba(138,58,31,0.10)` or equivalent tint.
- Unselected state should use faint ink background and rule border.
- Keep detailed composition counts available only if they fit cleanly. If they make the tile cluttered, move them to title text or a secondary line.
- Keep disabled/unready deck behavior working.
- Deck builder entry should look like the prototype's full-width ghost button at the bottom of the deck panel and remain disabled/placeholder until cEp5.

Do not:

- import saved decks from localStorage;
- use prototype `loadSavedDecks`;
- hard-code stub deck card counts;
- hide the actual current catalog preset names unless replaced by an equivalent display label derived in the view model.

### 5. Mode Panel Visual Fidelity

Make the mode/configuration panel look like the prototype while keeping production availability honest.

Requirements:

- Panel label should read close to `step 2 - game mode`.
- Mode tiles should be a `2 x 2` grid on desktop.
- Each tile should have:
  - small icon/glyph;
  - display-font mode name;
  - italic short description;
  - compact note/policy/availability line.
- The enabled current mode may be labeled `Casual` if the view model makes clear it maps to current Human vs AI with `legal-heuristic-v0`.
- Future modes may visually mirror the handoff labels, but must be disabled:
  - Ranked;
  - Training;
  - Seed Suite or AI-vs-AI/research mode.
- Disabled modes must have disabled controls or `aria-disabled` plus click guards.
- Disabled modes must not change selected mode.

Do not:

- implement ranked/training/seed-suite behavior;
- add free mulligans, undo, or alternate match format behavior;
- wire the UI to headless simulation.

### 6. Opponent, Round, Format, And Seed Controls

Bring the lower right control group closer to the prototype.

Opponent:

- Use a full-width select styled like the handoff.
- Options must come from current ready catalog presets.
- Keep opponent equal-to-human deck disabled.
- Show a short italic opponent description under the select.
- Description may be generated from preset/faction/leader data, for example `Current Nilfgaard · Emhyr var Emreis...`.

Round:

- Use a compact title-only segmented/toggle-like row.
- `Standard` is the only enabled current round selector.
- `Standard` should be selected by default for the current product path.
- Future round selectors such as `Instant Death` can appear only if disabled or clearly unavailable.
- Do not implement new round behavior.

Format:

- Use a compact segmented/toggle-like row.
- `Bo3` is the enabled label for the current standard two-gem match.
- `Bo3` should be selected by default for the current product path.
- Bo1/training-like controls can appear only if disabled or clearly unavailable.
- Do not implement new format behavior.

Seed:

- Keep seed input and copy button.
- Use the compact lowercase `copy` label for the seed copy button.
- Style the label/input closer to the handoff.
- Preserve query seed prefill.
- Preserve visible generated seed on Begin Match when blank.
- Preserve match top-bar seed display after transition.

### 7. Bottom Action Bar Fidelity

Make the bottom action bar closer to the prototype.

Requirements:

- Strong top border/rule.
- Summary line in italic display text.
- Begin Match primary button on the right on desktop.
- Begin Match button should use accent fill, parchment text, uppercase/letter-spaced label, and a confident visual weight.
- On mobile, summary and action may stack, but they must remain readable and non-overlapping.
- Summary should include selected deck, opponent, enabled mode, format, seed state, and policy without becoming too long for mobile.
- Begin Match may be enabled on initial load when the default current deck, opponent, round, and format selections are all valid.

### 8. Leader Card Sizing In Pre-Game

The cEp4 leader component fixed cropping. cEp4.5 should tune the pre-game thumbnail size and tile fit.

Requirements:

- Pre-game leader thumbnails should look close to the prototype's `50px x 70px` scale, while still using the shared dimension source if practical.
- `object-fit: contain` must remain.
- Leader cards must not render strength, row, or unit ability badges.
- Text beside the leader thumbnail must align vertically and not wrap into the thumbnail.

### 9. Leader Card Sizing In The Match Gameboard

The actual match/gameboard score cards should use the same leader-card frame dimensions as the medium size in the cEp1 foundation card system.

Requirements:

- Update `AuthenticLeaderCard` sizing so the match score-card leader frame can use the foundation medium dimensions.
- "Medium" means the shared foundation/card dimension source, not a new magic number. Prefer `dimensionsForSize("md")` or an equivalent named leader size derived from the same source of truth.
- The score-card leader card plus frame in `AuthenticMatchScreen` should use that medium/foundation size on desktop.
- Preserve `object-fit: contain` for source leader images.
- Preserve no strength, row, or unit ability badges.
- Adjust the match left rail/score-card layout so the leader frame does not overlap score text, gems/hand/deck/discard metadata, pile controls, or the board.
- On narrow/mobile layouts, the frame may be responsively constrained only if necessary to prevent overflow, but the desktop target must be the foundation medium size.
- Keep `data-testid="authentic-leader-card"` and `data-testid="authentic-leader-card-image"` stable.

Testing guidance:

- Add or update a component test that confirms the match/compact leader size uses the foundation medium dimensions, not the old tiny thumbnail.
- Keep or add browser smoke coverage that a match score-card leader image is visible and `object-fit: contain`.
- Browser mobile smoke must still pass with no horizontal overflow after the gameboard leader frame update.

### 10. CSS And Component Quality

Requirements:

- Prefer CSS classes in `authentic-pregame.css`; do not replace production code with large inline style objects copied from the prototype.
- Keep `.gwent-authentic.gwent-authentic--pregame` scoped so legacy UI is unaffected.
- Keep small radius values, restrained borders, paper backgrounds, and tactical density.
- Do not add new dependencies.
- Do not add one-off global styles.
- Do not add UI cards inside cards beyond the existing panel/tile pattern.
- Ensure text in deck/mode/format buttons wraps or truncates professionally.

### 11. Hidden-Info And Rule Boundaries

This phase should not touch match rules.

Requirements:

- No engine/core rule changes.
- No AI policy changes.
- No match legal-move changes.
- No changes to hidden AI hand/deck rendering.
- Pre-game may show catalog preset composition because no match hidden zones exist yet.
- Do not expose raw engine `instanceId`, generated ids such as `seat_a:000:`, or debug field names in pre-game or match smoke text.

## Tests

Update focused tests only if helper output or labels change.

Suggested unit/component coverage:

- `tests/components/gwent/authenticPreGameViewModel.test.ts`
  - if mode labels change to `Casual`, assert the enabled mode still maps to `human-vs-ai`/`legal-heuristic-v0`;
  - if opponent descriptions are added, assert they derive from catalog data;
  - if summary helper is added, test seed/blank-seed summary text.
- `tests/components/gwent/authenticLeaderCard.test.tsx`
  - preserve no strength/row badges;
  - preserve `object-fit: contain`;
  - assert the match/score-card leader size derives from the foundation medium dimensions.
- `tests/appMode.test.ts`
  - no route behavior changes should be required.

Update Playwright smoke in `tests/e2e/engine-shell-smoke.spec.ts`.

Browser smoke should cover:

- `/?engine=1&ui=authentic` still opens pre-game.
- Pre-game top bar, deck panel, mode panel, and bottom action bar are visible.
- Deck option leader card is visible and contained.
- Match score-card leader card uses the foundation medium dimensions on desktop and remains contained.
- Enabled mode tile is visible; disabled future mode tile cannot be selected.
- Seed prefill still works for `ep4-smoke` or an updated deterministic seed.
- Begin Match still reaches match screen.
- Match can still complete mulligan and one card play.
- Hidden-info text checks still pass.
- No horizontal document overflow at 390px.

Because this is visual work, the report should include a short note on desktop and mobile visual inspection. If practical, include screenshot paths or mention Playwright/browser smoke evidence. Do not add snapshot image files to the repository unless explicitly useful and small.

## Boundary Rules

Product UI code may import:

- React;
- current catalog data through existing view-model helpers;
- authentic card/leader components;
- `ENGINE_AI_POLICY_ID` for display only;
- existing setup config helpers.

Product UI code must not import:

- prototype files under `docs/ui-handoff/`;
- legacy rule helpers;
- legacy game slice/thunks/selectors;
- legacy AI;
- `GameBoard`;
- engine core scoring/rule helpers for display math.

Do not add exceptions to `scripts/check-forbidden-imports.mjs`.

## Acceptance Criteria

This phase is complete when:

- The pre-game screen is visibly closer to the handoff prototype's layout and styling.
- Route behavior is unchanged from cEp4.
- Deck and opponent choices remain catalog-backed.
- Only Human vs AI / current standard match is enabled.
- Future modes/formats are disabled and cannot change setup.
- Seed prefill, copy, generated seed, and match seed display still work.
- Begin Match still starts a playable match through the setup config path.
- Pre-game leader thumbnails remain uncropped and better match the prototype scale.
- Match/gameboard leader card plus frame uses the foundation medium dimensions on desktop.
- Mobile width has no horizontal document overflow.
- Existing match smoke still passes after pre-game transition.
- `docs/PROJECT_STATE.md` is updated.
- A report exists at `audit/reports/2026-04-26-cEp4.5-report.md`.
