# cFp45 Specs: Remaining Round-One Overinvestment Calibration

## Summary

`cFp45` is a narrow Cluster F behavior phase for `legal-heuristic-v1`.
It follows the `cFp44` post-cFp43 casebook, which found that the remaining
expanded `round_one_overinvestment` signal is still strongly loss-correlated:
26 findings, 25 losses, 1 draw, 0 wins.

The goal is not to add another broad pass rule. The goal is to inspect those
26 remaining cases, classify why the cFp43 guard did not eliminate them, and
only then add a small rule if the evidence shows a simple repeated miss.

If the cases are heterogeneous, or if the best patch damages the benchmark
matrix more than the acceptance gates below allow, stop with an analysis-only
cFp45 report and do not merge behavior changes.

## Scope

In scope:

- Analyze the 26 remaining expanded `round_one_overinvestment` cases from the
  cFp44 casebook.
- Add a compact decision note documenting why those cases remain.
- Add a narrow `legal-heuristic-v1` rule only if the analysis identifies a
  repeated, public-state-visible policy miss.
- Add hidden-info-safe decision trace fields only if the new rule needs them.
- Add hidden-info-safe product diagnostic scanner coverage for any new trace
  fields or enum strings.
- Update AI Lab/product policy metadata to cFp45 after the phase is completed.
- Refresh current and expanded benchmark artifacts if behavior changes.

Out of scope:

- Engine rules, legal moves, command semantics, scoring rules, catalog data,
  deck presets, UI behavior, Redux adapter behavior, and route behavior.
- v0 behavior.
- Faction-specific hacks such as "Nilfgaard vs Skellige special case".
- Broad pass tuning based only on `suspicious_pass`.
- New ratings, Glicko, TrueSkill, search, self-play, model training, or product
  difficulty tiers.
- Further cFp38 weather, cFp39 Medic, or round-three-low-resource tuning unless
  a cFp45 test is explicitly proving non-regression.
- Failure-mining classifier reshaping, unless a new intentional cFp45 pass is
  otherwise reported as a false-positive and the report explains why.

## Mandatory Pre-Implementation Analysis

Before changing policy behavior, create or update this decision note:

`docs/research/literature/ai/decisions/2026-05-21-cfp45-round-one-overinvestment-calibration.md`

The note must include:

1. The 26 `round_one_overinvestment` findings from the cFp44 casebook.
2. A classification table with one row per finding.
3. For each row, classify why cFp43 did not stop the overinvestment.

Use these classification labels unless you have a better exact label:

- `guard_never_reached_board_below_floor`
- `guard_never_reached_hand_above_cap`
- `guard_reached_but_exception_opponent_passed`
- `guard_reached_but_exception_card_advantage`
- `guard_reached_but_exception_match_winning`
- `guard_reached_but_exception_single_move_catch_up`
- `guard_reached_but_exception_single_card_hand`
- `guard_reached_but_selected_non_play`
- `guard_triggered_but_later_overinvestment`
- `loss_not_clearly_round_one_resource_related`
- `needs_manual_trace_review`

For each classification, record only hidden-info-safe/public fields, such as:

- benchmark matchup id / seed / mirror index / v1 seat;
- v1 faction;
- round 1 play count;
- round 1 final hand count;
- whether cFp43 `roundOneOverinvestmentRecommended` ever became true;
- the most common `roundOneOverinvestmentReason` values in round 1;
- whether the selected move was `pass`, `play_card`, `use_leader`, or prompt
  resolution;
- `roundOneBoardAfterSelectedMove`;
- `estimatedHandCountAfterSelectedMove`;
- `scoreDelta`;
- `catchUpStatus`;
- `selectedMoveIsCardAdvantage`;
- `selectedMoveWouldLeaveNoPositiveUnitMove`;
- `futureRoundHandQuality`.

Do not write raw card instance ids, source ids, hand card names, deck contents,
or raw hidden-state snapshots into the decision note.

If no majority pattern emerges from this analysis, stop after writing the note,
report, docs, and AI Lab metadata. Do not add policy tuning just to move the
metric.

## Behavior Patch Rules

If the pre-analysis finds a repeated, simple miss, implement the smallest
public-state rule that addresses it.

Allowed patch shapes:

1. A one-step cFp43 threshold calibration, such as widening only one threshold
   by one unit, when most misses are clear threshold escapes.
2. A new cFp45 guard reason for a repeated public-state pattern, such as a
   late round-1 play that keeps spending hand after the board is already large
   and future hand quality is poor or thin.
3. A narrow exception correction if most misses came from an exception that is
   too permissive.

Forbidden patch shapes:

- Faction-specific or matchup-specific constants.
- Any rule that reads hidden opponent hand/deck data.
- Any rule that changes engine legality or command execution.
- Any broad "if round 1 then pass more" rule.
- Any rule that suppresses Spy/card-advantage plays unless the decision note
  proves the current exception is wrong and tests cover the replacement.
- Any rule that blocks leader use just because round-one investment is high.

Preserve these exceptions unless the decision note explicitly proves a bug:

- last gem;
- opponent already passed;
- non-play-card or `use_leader`;
- card-advantage/Spy;
- match-winning play;
- cheap single-move catch-up;
- single-card hand.

## Benchmark Acceptance Gates

If behavior changes, cFp45 is acceptable only if:

1. Expanded `round_one_overinvestment` drops below `26`, or the report explains
   why a behavior patch was reverted.
2. Expanded W/L does not fall below `302 win` and expanded losses do not exceed
   `93` against v0. This allows at most a small tradeoff from the cFp44
   baseline `305/90/5`.
3. Current starter matrix losses do not exceed `19` against v0, compared with
   cFp44 baseline `102/17/1`.
4. Expanded total findings do not increase by more than 10 percent from `878`
   unless the report explains a classifier false-positive.
5. Hidden-info scan remains clean.
6. No policy failures, engine errors, or replay failures appear in benchmark
   artifacts.

If a candidate behavior patch fails these gates, back out only your own policy
trial changes before the final commit and produce an analysis-only cFp45 report
with the failed result and recommendation.
