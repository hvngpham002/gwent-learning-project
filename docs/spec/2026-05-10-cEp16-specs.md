# Cluster E Phase 16 Specs: Legacy Quarantine And App Shell Cleanup

## Phase ID

`cEp16`

## Purpose

Quarantine the old Redux/legacy gameplay implementation now that cEp15 has promoted the authentic product UI to `/`.

After this phase, legacy code should be visibly isolated, intentionally reachable only through `/legacy`, and harder to import accidentally from authentic UI, engine UI, benchmark, simulation, or pure engine paths.

This is still not the deletion phase. Keep `/legacy` working. Do not rewrite legacy rules. Do not remove old query aliases from cEp15. Do not implement AI Lab.

## Current Context

- `/` now opens authentic pre-game.
- `/legacy` opens the legacy Redux UI.
- `/engine-diagnostic` opens the diagnostic shell.

- old `/?engine=1` and `/?engine=1&ui=authentic&view=...` URLs remain compatibility aliases.

## Strategy

Prefer a real source quarantine over a comments-only cleanup.

Use `git mv` for moved files so history is preserved. The preferred target namespace is:

```text
src/legacy/
  LegacyRoute.tsx
  README.md
  ai/
  components/
  data/
  hooks/
  store/
  types/
  utils/
```

If moving a specific file creates disproportionate churn, use a narrow compatibility shim at the old path only as a temporary exception, document it in the report, and add a TODO in `docs/legacy/README.md`. The expected default is that legacy-only files move under `src/legacy`.

## Implementation Requirements

### 1. Add a legacy route boundary

Create `src/legacy/LegacyRoute.tsx`.

It should be the only component that `src/App.tsx` imports for legacy gameplay. It can render the moved `ReduxGameManager` internally.

Update `src/App.tsx`:

- replace direct import of `ReduxGameManager` with `LegacyRoute`;
- keep `/legacy` behavior unchanged;
- do not change `/`, `/engine-diagnostic`, canonical authentic paths, or old query aliases.

### 3. Remove or reduce old top-level legacy folders where empty

After moves:

- remove empty `src/components/game`, `src/components/card`, `src/components/player`, `src/hooks`, `src/ai`, `src/utils`, `src/types`, or `src/data/cards` directories if they become empty;
- do not remove non-empty directories used by non-legacy code;
- do not delete tracked source content except obsolete compatibility shims that are no longer needed.

Do not remove `src/components/game/engine` if it remains there. That folder is the diagnostic engine shell helper path and is not legacy gameplay.

### 4. Add legacy documentation

Create:

`docs/legacy/README.md`

It must include:

- what `/legacy` is for;
- that legacy code is preserved for comparison/fallback only;
- a list of the main `src/legacy` subfolders;
- explicit warning that new product/engine work should not import `@/legacy/...`;
- known remaining legacy technical debt, including timers, legacy Redux state, old AI, and old helper scoring;
- deletion prerequisites for a future cleanup phase;
- any compatibility shims left at old paths.

Also add `src/legacy/README.md` with a shorter source-level warning.

### 5. Update import boundary checks

Update `scripts/check-forbidden-imports.mjs`.

Keep the existing engine/authentic forbidden scan, then add a source-boundary scan that fails if non-allowed production files import legacy modules.

Allowed production imports of `@/legacy/...`:

- `src/App.tsx`, but only `LegacyRoute`;
- `src/store/index.ts`, but only moved legacy reducers needed for `/legacy`;
- files under `src/legacy/**`.

Allowed test imports of `@/legacy/...`:

- `tests/baseline/**`;
- `tests/game/legacy*.test.ts`;
- any route smoke that explicitly tests `/legacy`.

All other imports from `@/legacy/...` should fail.

Also update the scan targets so authentic UI, engine UI, engine adapter, pure engine, simulation, benchmark, and AI policy paths remain protected from old legacy identifiers and from `@/legacy`.

The check should avoid scanning docs for plain words like `legacy`, because docs necessarily discuss legacy.

### 6. Update tests

Update imports in legacy-specific tests:

- `tests/baseline/gameHelpers.test.ts`
- `tests/game/legacyMuster.test.ts`

Add or update tests to verify:

- `resolveAppRoute({ pathname: "/legacy" })` still resolves to legacy;
- `/legacy` browser smoke still mounts the legacy app and not authentic pre-game;
- `npm run check:forbidden-imports` catches the new boundary if a protected source imports `@/legacy` (unit-test the script only if the repo already has a pattern for script tests; otherwise rely on running the script).

Do not add new behavior tests for legacy rule correctness beyond existing baseline coverage.

## Acceptance Criteria

- `/` still opens authentic pre-game.
- `/legacy` still opens the legacy Redux UI.
- `/engine-diagnostic` still opens the diagnostic engine shell.
- cEp15 canonical paths and old compatibility aliases still work.
- Legacy gameplay source is isolated under `src/legacy` where practical.
- `src/App.tsx` imports only a legacy route wrapper, not legacy game internals.
- Product/authentic UI, engine UI, pure engine, simulation, benchmark, and engine adapter code do not import `@/legacy/...`.
- Forbidden-import check enforces the new legacy boundary.
- Existing legacy baseline tests still pass after import relocation.
- No legacy gameplay behavior is intentionally rewritten.
- No engine rules, legal moves, scoring, AI policy, benchmark harness behavior, catalog data, deck validation, Card Studio schema, official-porting staging data, or hidden-info boundary changes.
- `AGENTS.md`, `docs/PROJECT_STATE.md`, `docs/legacy/README.md`, and the cEp16 report are updated.

## Out Of Scope

- Deleting `/legacy`.
- Removing legacy reducers from `src/store/index.ts`.
- Removing old query compatibility aliases.
- Rewriting legacy rules, timers, AI, scoring, or Redux state.
- Fixing the existing `useReduxAI` exhaustive-deps lint warning unless moving the file makes the warning path need updating only.
- Implementing AI Lab.
- Changing authentic product visual design.
- Changing engine behavior, benchmark behavior, or ML/research code.
- Adding React Router or any routing dependency.
