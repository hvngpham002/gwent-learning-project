# cFp22 Specs - Headless Benchmark Report Artifact

## Purpose

Add a headless benchmark report artifact boundary on top of the cFp21 in-memory benchmark harness.

cFp21 proved that `runBenchmarkSuite(...)` can produce hidden-info-safe `benchmark-match-v1` records and `benchmark-summary-v1` summaries in memory. cFp22 should make those results durable and reviewable from the command line without involving the browser AI Lab.

This phase should produce a repeatable local command that runs a small benchmark suite and writes safe artifacts:

- public JSON summary;
- public JSONL match ledger;
- human-readable Markdown report;
- small manifest describing the artifact set.

This is not a strategy-improvement phase. It is the first durable benchmark-output phase.

## Current Context

cFp21 added:

- `src/game/benchmark/`;
- `benchmark-smoke-v1`;
- benchmark-local `legal-first-v0`;
- `runBenchmarkSuite(...)`;
- public `benchmark-match-v1` records;
- public `benchmark-summary-v1` summaries;
- hidden-info-safe default output;
- explicit unsafe debug output only behind `includeDebugResults`.

cEp17 added `/ai-lab` as a read-only product dashboard that shows static benchmark status. It intentionally does not import `src/game/benchmark`, run simulations, export files, or train models.

cFp22 should keep that separation:

- headless command writes benchmark artifacts;
- browser AI Lab remains read-only;
- no browser execution is added.

## Non-Negotiable Boundaries

- No engine rule changes.
- No legal-move semantics changes.
- No AI policy strategy changes.
- No `legal-heuristic-v1`.
- No UI, route, React, CSS, browser, deck-builder, Card Studio, Official Porting, or legacy changes.
- No benchmark execution from `/ai-lab`.
- No Glicko, TrueSkill, Elo, approximate best response, ISMCTS, determinized search, NFSP, Deep CFR, ReBeL, OSFP, or model training.
- No Python tooling in this phase.
- No unsafe debug output in committed artifacts.
- No raw `MatchState`, `cardsById`, command logs, full event logs, hand arrays, deck arrays/order, `ownHand`, `opponentHand`, or raw `seat_a:` / `seat_b:` runtime card instance ids in default artifact files.
- Do not commit `unsafeDebugResults`.

## Desired Architecture

Add a small artifact layer that consumes `runBenchmarkSuite(...)` and serializes only the public result.

Recommended modules:

```text
src/game/benchmark/artifacts.ts
scripts/run-benchmark-report.ts
```

If the repo needs a TypeScript script runner, add the smallest practical dev dependency and npm script. `tsx` is acceptable if no existing runner is available. Do not add a large CLI framework.

Recommended package scripts:

```json
{
  "benchmark:smoke": "tsx scripts/run-benchmark-report.ts --suite benchmark-smoke-v1"
}
```

The exact script name may differ, but it must be documented and tested.

## Artifact Location

Write generated benchmark artifacts under:

```text
docs/research/literature/ai/benchmark-results/
  benchmark-smoke-v1/
    latest/
      manifest.json
      summary.json
      records.jsonl
      report.md
```

Keep `latest/` deterministic and reviewable. Do not include wall-clock timestamps in the committed file contents. If a timestamp is needed for ad hoc local runs, make it opt-in or exclude it from committed files.

Use a stable benchmark run id for the committed smoke artifact, for example:

```text
benchmark-smoke-v1:latest
```

Do not create a new dated folder on every run in this phase. That would make routine benchmark checks too noisy.

## Implementation Requirements

### 1. Add artifact serialization helpers

Create a pure module such as `src/game/benchmark/artifacts.ts`.

It should export functions close to:

```ts
interface BenchmarkArtifactBundle {
  manifestJson: string;
  summaryJson: string;
  recordsJsonl: string;
  reportMarkdown: string;
}

buildBenchmarkArtifactBundle(result: BenchmarkRunResult): BenchmarkArtifactBundle
```

Requirements:

- JSON should be pretty-printed deterministically.
- JSONL should contain one `benchmark-match-v1` record per line.
- Markdown should summarize:
  - suite id;
  - benchmark run id;
  - matchup ids;
  - policies;
  - deck preset ids;
  - total matches;
  - status counts;
  - replay checked/failed counts;
  - result counts by policy;
  - result counts by deck;
  - average steps/commands/legal moves;
  - diagnostics, if any.
- Manifest should include:
  - artifact schema version, for example `benchmark-artifact-v1`;
  - suite id;
  - benchmark run id;
  - file list;
  - record count;
  - summary schema version;
  - record schema version;
  - hidden-info safety note.

Do not include unsafe debug results or raw simulation results in any artifact helper.

### 2. Add a headless script

Create `scripts/run-benchmark-report.ts`.

Required behavior:

- default suite: `benchmark-smoke-v1`;
- default output directory: `docs/research/literature/ai/benchmark-results/<suite-id>/latest`;
- default benchmark run id: `<suite-id>:latest`;
- supports `--suite <id>`;
- supports `--out <dir>`;
- supports `--run-id <id>`;
- supports `--max-steps <number>`;
- exits non-zero for unknown suite, invalid max steps, or filesystem write failure;
- writes exactly:
  - `manifest.json`;
  - `summary.json`;
  - `records.jsonl`;
  - `report.md`;
- prints a concise completion line with suite id, record count, and output directory.

The script must not support `includeDebugResults`.

Prefer a tiny hand-written argument parser. Avoid adding a dependency only for argument parsing.

### 3. Add npm script

Update `package.json` with a script such as:

```json
"benchmark:smoke": "tsx scripts/run-benchmark-report.ts --suite benchmark-smoke-v1"
```

If adding `tsx`, add it as a dev dependency. Do not change Node/npm versions or unrelated scripts.

### 4. Commit one generated smoke artifact

Run the new script and commit the generated `latest/` artifact for `benchmark-smoke-v1`.

The committed artifact files must be hidden-info safe and deterministic across repeated runs on the same code.

Required files:

```text
docs/research/literature/ai/benchmark-results/benchmark-smoke-v1/latest/manifest.json
docs/research/literature/ai/benchmark-results/benchmark-smoke-v1/latest/summary.json
docs/research/literature/ai/benchmark-results/benchmark-smoke-v1/latest/records.jsonl
docs/research/literature/ai/benchmark-results/benchmark-smoke-v1/latest/report.md
```

If the generated artifact changes when rerun immediately without code changes, stop and fix determinism before reporting success.

### 5. Add tests

Add focused tests such as:

- `tests/game/benchmarkArtifacts.test.ts`

Required test coverage:

- artifact bundle contains the four expected outputs;
- `records.jsonl` line count equals `result.records.length`;
- each JSONL line parses as `benchmark-match-v1`;
- `summary.json` parses as `benchmark-summary-v1`;
- manifest parses as `benchmark-artifact-v1`;
- bundle generation is stable across repeated identical benchmark runs;
- generated strings do not contain hidden-info/debug hazards:
  - `cardsById`;
  - `finalState`;
  - `commandLog`;
  - `"hand"`;
  - `"deck"`;
  - `ownHand`;
  - `opponentHand`;
  - `seat_a:`;
  - `seat_b:`;
  - `unsafeDebugResults`;
- Markdown includes suite id, policy ids, deck preset ids, status counts, replay counts, and diagnostics section.

If practical, add one script-level test using a temporary output directory. Keep it fast and deterministic. Do not rely on the committed `latest/` artifact for the core serialization tests.

## Acceptance Criteria

- `npm run benchmark:smoke` writes hidden-info-safe benchmark artifacts.
- The command is deterministic when rerun with no code changes.
- `manifest.json`, `summary.json`, `records.jsonl`, and `report.md` exist under the expected `latest/` directory.
- `records.jsonl` contains only public `benchmark-match-v1` records.
- `summary.json` contains public `benchmark-summary-v1`.
- No artifact contains raw state, command logs, hand/deck arrays, runtime instance ids, or `unsafeDebugResults`.
- Tests cover serialization, JSONL parseability, hidden-info safety, and determinism.
- Existing cFp21 benchmark harness behavior remains backward compatible.
- `/ai-lab` remains read-only and does not execute benchmarks.
- Docs, `docs/PROJECT_STATE.md`, and the cFp22 report are updated.

## Out Of Scope

- Browser benchmark execution.
- AI Lab wiring to run or read generated artifacts.
- Large all-vs-all official starter tournaments.
- `legal-heuristic-v1`.
- Any AI policy strategy improvement.
- Ratings, TrueSkill, Glicko, Elo, approximate best response, search, self-play, or training.
- Python tooling or notebooks.
- Engine rule, legal-move, scoring, prompt, round, game-end, or command changes.
- UI, route, CSS, deck-builder, Card Studio, Official Porting, or legacy changes.
- Unsafe debug artifact persistence.
