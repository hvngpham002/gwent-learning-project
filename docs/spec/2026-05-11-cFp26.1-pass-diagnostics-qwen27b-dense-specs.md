## Context

cFp25 added hidden-info-safe product AI decision traces.

cFp26 repaired real v1 behavior:

- Nilfgaard tie-aware catch-up thresholds now match the engine.
- Diagnostic reason text no longer says "catch-up move" when the selected move is `pass`.
- Product diagnostic exports now populate `aiDeckFaction` when known.

A later product playtest export (`ep4-mp1cm68q`) showed a Round 1 pass that looked suspicious to the human tester. The trace showed:

- Human deck: `Current Nilfgaard`
- AI deck: `current-nilfgaard`
- AI policy: `legal-heuristic-v1`
- Round: `1`
- AI decision: `24`
- Human had already passed.
- AI score: `76`
- Human score: `122`
- Score delta: `-46`
- AI hand count: `5`
- Human hand count: `7`
- Both seats were Nilfgaard, so a tied score would be a draw, not an AI win.
- `policyLastGemUpperBound`: `102`
- The selected move was `pass`.

That pass appears defensible under current v1 policy: AI was not on its last gem, no one-card catch-up was available, and the policy upper bound was below the score needed to win the round. The problem is diagnostic clarity. The current reason:

```text
opponent passed, behind — no useful move, pass
```

is too vague. It can sound like the AI had no useful cards, while the real policy meaning is closer to:

```text
opponent passed, behind - no one-card catch-up; preserve hand
```

This phase must improve diagnosis, not policy strength.

## Goal

Make `legal-heuristic-v1` pass traces explain opponent-passed and last-gem pass decisions with policy-aligned, hidden-info-safe fields:

- score needed to win the round;
- whether the acting AI wins tied rounds;
- whether the policy upper bound can still reach a round win;
- whether any single known legal play/leader move can catch up immediately;
- whether the selected pass is a preserve-hand pass rather than a "no useful card exists" pass.

## Required Implementation

### 1. Add A Policy-Aligned Pass Diagnostics Helper

Refactor `src/game/ai/legalHeuristicPolicyV1.ts` so pass diagnostics can share policy logic instead of reimplementing it loosely in `explainLegalHeuristicV1Decision.ts`.

Preferred shape:

```ts
export interface LegalHeuristicV1PassDecisionDiagnostics {
  readonly ownWinsTiedRound: boolean;
  readonly minimumScoreToWinRound: number;
  readonly policyUpperBound: number;
  readonly policyUpperBoundCanWinRound: boolean;
  readonly hasSingleMoveCatchUp: boolean;
  readonly bestSingleMoveCatchUpScore: number | null;
  readonly bestSingleMoveCatchUpTempo: number | null;
  readonly bestSingleMoveCatchUpKind: "play_card" | "use_leader" | null;
  readonly preserveHandPassRecommended: boolean;
}

export const buildLegalHeuristicV1PassDecisionDiagnostics = (
  features: LegalHeuristicV1Features,
): LegalHeuristicV1PassDecisionDiagnostics => {
  // ...
};
```

Exact names may differ, but the exported information must be equivalent.

Implementation details:

1. Export or otherwise reuse the existing cFp26 `minimumScoreToWinRound(...)` and `ownWinsTiedRound(...)` logic.
2. The diagnostics helper must compute `policyUpperBound` as:

   ```ts
   features.ownScore + uniqueCardTempoUpperBound(features)
   ```

   This must match the v1 last-gem gate.

3. Compute `policyUpperBoundCanWinRound` as:

   ```ts
   policyUpperBound >= minimumScoreToWinRound(features)
   ```

4. Compute `hasSingleMoveCatchUp` from the same candidate logic used by `chooseCatchUpMove`.

   To avoid drift, prefer extracting a shared internal candidate-ranker that both `chooseCatchUpMove` and the new diagnostics helper call. The shared ranker may return internal moves, but only redacted numeric/enumerated data may leave the module through the diagnostic helper.

5. A single-move catch-up candidate is any play/leader candidate that satisfies the same gate as `chooseCatchUpMove`:

   ```ts
   features.ownScore + candidate.tempo >= minimumScoreToWinRound(features)
   candidate.score > -100
   ```

6. `bestSingleMoveCatchUpScore`, `bestSingleMoveCatchUpTempo`, and `bestSingleMoveCatchUpKind` should describe the first candidate that `chooseCatchUpMove` would select, without exposing card names, source IDs, instance IDs, move IDs, or raw targets.
7. `preserveHandPassRecommended` should be true only for the important diagnostic case:
   - `features.opponentPassed === true`
   - `features.scoreDelta <= 0`
   - no single-move catch-up is available
   - AI is not on its last gem (`features.ownGems > 1`)
   - pass is legal

Do not make `choosePlayingMove(...)` behave differently. If this helper changes behavior, the implementation fails the spec.

### 3. Improve Reason Text For Preserve-Hand Passes

Update `src/game/ai/explainLegalHeuristicV1Decision.ts`.

When:

- `features.opponentPassed === true`
- AI is behind or tied from its perspective (`features.scoreDelta <= 0`)
- selected move is `pass`
- no single-move catch-up exists
- `features.ownGems > 1`

the reason must be more precise than "no useful move".

Preferred wording:

```text
opponent passed, behind - no one-card catch-up; preserve hand
```

Requirements:

1. The reason must not imply the AI had no useful cards.
2. The reason must not imply the AI evaluated a multi-card line.
3. The reason must not leak hidden cards.
4. If selected move is a non-pass catch-up play/leader move, keep a catch-up reason.
5. If selected move is a last-gem impossible pass, keep a last-gem impossible reason.

### Engine/AI Policy Diagnostics Tests

Use `tests/game/engineAiPolicy.test.ts` or a nearby AI diagnostics test file.

Required cases:

1. **Diagnostic-like Round 1 preserve-hand pass**
   - Opponent has passed.
   - AI is behind.
   - AI has more than one gem.
   - No single known legal move can reach `minimumScoreToWinRound`.
   - Selected move is `pass`.
   - Assert:
     - `trace.passAnalysis?.preserveHandPassRecommended === true`
     - `trace.passAnalysis?.hasSingleMoveCatchUp === false`
     - `trace.passAnalysis?.policyUpperBoundCanWinRound === false` for the fixture
     - `trace.reason` includes either `preserve hand` or equivalent precise wording
     - `trace.reason` does not include `no useful move`

2. **Single-move catch-up available**
   - Opponent has passed.
   - AI is behind.
   - A legal play/leader move can reach `minimumScoreToWinRound`.
   - Assert:
     - selected move is not `pass`
     - `hasSingleMoveCatchUp === true`
     - `bestSingleMoveCatchUpKind` is `play_card` or `use_leader`
     - `bestSingleMoveCatchUpTempo` is not null
     - reason accurately says catch-up.

3. **Nilfgaard tie threshold appears in diagnostics**
   - Exactly one seat is Nilfgaard and AI is Nilfgaard.
   - Assert:
     - `ownWinsTiedRound === true`
     - `minimumScoreToWinRound === opponentScore`

4. **Double-Nilfgaard tie threshold appears in diagnostics**
   - Both seats are Nilfgaard.
   - Assert:
     - `ownWinsTiedRound === false`
     - `minimumScoreToWinRound === opponentScore + 1`

5. **Last-gem impossible remains distinct**
   - AI is on last gem.
   - Policy upper bound cannot reach `minimumScoreToWinRound`.
   - Assert:
     - selected move is `pass`
     - `preserveHandPassRecommended === false`
     - reason remains a last-gem impossible/catch-up impossible reason.

6. **Policy parity**
   - For every focused fixture above, assert:

     ```ts
     explainLegalHeuristicV1Decision(input).move === legalHeuristicPolicyV1.selectMove(input)
     ```

   - Deep equality is preferred if existing tests already compare moves that way.
