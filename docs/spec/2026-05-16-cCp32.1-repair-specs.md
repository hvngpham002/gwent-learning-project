## Repair 1 - Product UI Reachability

### Problem

`AuthenticMatchScreen.tsx` currently returns `AuthenticMulliganScreen` whenever:

```ts
match?.phase === "mulligan" || visibleMulliganExitAnimation
```

The cCp32.1 engine intentionally keeps `phase === "mulligan"` while the post-mulligan Scoia'tael prompt is pending. Therefore, the existing `PromptPanel` rendered in the match-board branch is unreachable for the human prompt owner.

### Required Behavior

When `match.pendingPrompt` is the Scoia'tael first-player prompt:

```ts
prompt.abilityId === "scoiatael_choose_first"
prompt.stage === "scoiatael_first_player_choice"
prompt.kind === "choose_option"
```

the human player must see and resolve it after both mulligans complete.

### Implementation Guidance

Add a small predicate in `AuthenticMatchScreen.tsx`:

```ts
const isScoiataelFirstPlayerPrompt =
  prompt?.abilityId === "scoiatael_choose_first" &&
  prompt.stage === "scoiatael_first_player_choice";
```

Then change the mulligan early return so it does **not** hide the prompt:

```ts
if ((match?.phase === "mulligan" && !isScoiataelFirstPlayerPrompt) || visibleMulliganExitAnimation) {
  return <AuthenticMulliganScreen ... />;
}
```

This is the simplest acceptable path because it lets the existing match-board branch render `PromptPanel`. If the board looks too early because phase is still `"mulligan"`, that is acceptable for this repair as long as the prompt is visible, actionable, and hidden-info safe.

If you choose to render a dedicated prompt modal over the mulligan screen instead, you must still:

- use existing `promptMoves`;
- dispatch exact `ChoosePromptOption` moves;
- keep hidden-info boundaries;
- add equivalent browser coverage.

### Required Prompt Copy

Update `buildPromptPresentationViewModel` in `src/components/gwent/matchViewModel.ts` so this prompt does not render a generic technical title.

For `abilityId === "scoiatael_choose_first"`:

- title: `Scoia'tael first turn`
- body: `Choose who starts round 1.`
- kind: `scoiatael_choose_first` if the type allows extending it; otherwise `generic` is acceptable but the copy must be correct.

Button labels should come from the prompt options and be:

- `go first`
- `opponent goes first`

## Repair 3 - AI Prompt Fallback

### Problem

`legal-heuristic-v1` currently has no explicit branch for `scoiatael_choose_first`. It falls through to generic prompt tie-breaking. Because `"scoiatael-first-player:opponent"` sorts before `"scoiatael-first-player:self"`, the AI likely chooses opponent first.

The original cCp32.1 spec says deterministic self is preferred for now.

### Required Behavior

In `src/game/ai/legalHeuristicPolicyV1.ts`, update `choosePromptMove`:

```ts
if (abilityId === "scoiatael_choose_first") {
  return moves.find((move) => move.optionId === "scoiatael-first-player:self") ?? moves[0] ?? null;
}
```

Place this before the generic fallback sorter.

Also add equivalent deterministic handling in `src/game/ai/legalHeuristicPolicyV0.ts` if v0 can own this prompt in benchmarks or product tests:

```ts
const scoiataelSelf = promptMoves.find(
  (move) =>
    move.metadata.abilityId === "scoiatael_choose_first" &&
    move.optionId === "scoiatael-first-player:self",
);
if (scoiataelSelf) return scoiataelSelf;
```

### Required Tests

Add focused tests in `tests/game/engineAiPolicy.test.ts`:

1. `legal-heuristic-v1 chooses self for scoiatael first-player prompt`.
2. If you update v0, add `legal-heuristic-v0 chooses self for scoiatael first-player prompt`.

Use synthetic legal moves if that is the existing pattern. You do not need to run a full match just to test prompt choice.

## Repair 4 - AI Observation Metadata

### Problem

The original cCp32.1 spec requires public metadata so future AI mulligan strategy can know whether the acting seat will own the post-mulligan first-turn choice. This was not added.

### Required Fields

Add to `SeatObservation` in `src/game/ai/types.ts`:

```ts
ownHasPostMulliganFirstPlayerChoice: boolean;
opponentHasPostMulliganFirstPlayerChoice: boolean;
```

Add derivation in `src/game/ai/seatObservation.ts`.

Rules:

- Exactly one Scoia'tael seat:
  - observing Scoia'tael seat: `ownHasPostMulliganFirstPlayerChoice: true`, `opponentHasPostMulliganFirstPlayerChoice: false`
  - observing non-Scoia'tael seat: `ownHasPostMulliganFirstPlayerChoice: false`, `opponentHasPostMulliganFirstPlayerChoice: true`
- No Scoia'tael seats:
  - both false
- Mirror Scoia'tael:
  - both false

This is public faction information only, so it is hidden-info safe.

### Required Tests

Add or update AI observation tests. If no dedicated observation test exists, add focused assertions to `tests/game/engineAiPolicy.test.ts` using whatever helper builds `SeatObservation`.

Required cases:

1. Own Scoia'tael vs non-Scoia'tael exposes `ownHasPostMulliganFirstPlayerChoice === true`.
2. Opponent Scoia'tael vs own non-Scoia'tael exposes `opponentHasPostMulliganFirstPlayerChoice === true`.
3. Mirror Scoia'tael exposes both false.
