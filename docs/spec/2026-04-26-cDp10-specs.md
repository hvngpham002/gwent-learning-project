# Implementation Spec: Cluster D, Phase 10 - Hidden-Info-Safe Simulation Export Contract

## Goal

Define and implement the first hidden-info-safe simulation export contract over the cDp9 batch runner.

This phase should produce deterministic in-memory export rows that future ML tooling can consume. Each row should represent one policy-owned decision with:

- a versioned observation for the acting seat;
- a versioned legal-action list;
- the chosen legal-action index;
- a sparse match-outcome reward placeholder;
- compact match/run metadata.

This is still not model training, not JSONL writing, not a Python bridge, and not a fixed neural action vector. The purpose is to make the data contract explicit and safe before any exporter or learner exists.

## Architecture Position

Current state after `cDp9`:

- legacy UI remains the default route;
- engine UI is opt-in through `?engine=1` or `VITE_ENGINE_UI=1`;
- the pure engine owns setup, legal moves, command execution, prompts, scoring, round resolution, game end, and deterministic RNG;
- `legal-heuristic-v0` selects from legal moves using hidden-info-safe seat observations;
- `src/game/sim` can run a single AI-vs-AI match and a fixed six-seed batch suite;
- cDp9 batch results are compact by default and keep raw single-run results behind `includeRawResults: true`;
- cDp9 replay diagnostics compare final essentials but do not export step-level observations or legal action masks;
- raw `commandLog`, `finalState`, and engine events remain debug/replay data, not ML-safe rows.

Phase 10 should build a safe data contract on top of these pieces without changing rule behavior.

### 2. Define schema versions and top-level dataset output

Add explicit schema version constants. Suggested:

```ts
export const SIMULATION_EXPORT_SCHEMA_VERSION = "sim-export-v1";
export const SAFE_OBSERVATION_SCHEMA_VERSION = "safe-observation-v1";
export const LEGAL_ACTION_SCHEMA_VERSION = "legal-action-v1";
```

Add a public dataset builder:

```ts
export interface SimulationExportDatasetInput {
  batch?: HeadlessSimulationBatchResult;
  batchInput?: HeadlessSimulationBatchInput;
  includeSystemActions?: boolean;
  includeDebugRaw?: false;
}

export interface SimulationExportDataset {
  schemaVersion: typeof SIMULATION_EXPORT_SCHEMA_VERSION;
  generatedBy: "headless-simulation-export";
  suiteId: string | null;
  seeds: readonly (string | number)[];
  policiesBySeat: Record<SeatId, string>;
  rowCount: number;
  matchCount: number;
  summary: SimulationExportSummary;
  rows: SimulationDecisionRow[];
}

export const buildSimulationExportDataset = (
  input?: SimulationExportDatasetInput,
): SimulationExportDataset => ...
```

Input rules:

- if `batch` is provided, use it;
- else run `runHeadlessSimulationBatch` with `batchInput`;
- internally obtain raw single-run results as needed, but do not expose raw results in export output;
- `includeSystemActions` defaults to `false`;
- `includeDebugRaw` should not be supported yet. Keep the type hard-false or omit it entirely. Raw exports belong to debug tools, not the safe dataset.

Output rules:

- JSON-serializable plain data only;
- stable field order where practical;
- no `Date.now()`, wall-clock duration, random IDs, file paths, or environment-specific data;
- deterministic for same suite, policies, max steps, and code version.

### 3. Generate rows by replaying decisions, not by trusting raw logs

Rows should be derived from engine state immediately before each command is applied.

Recommended approach:

1. Run cDp9 batch with raw results internally, or accept a batch that already includes raw results.
2. For each raw result, start the same deterministic simulation config from the seed.
3. Walk the command log in order.
4. Before applying each command:
   - determine the acting seat;
   - get legal moves for that seat;
   - build the acting seat observation;
   - find the legal move that converts to the recorded command;
   - encode the safe observation and legal actions;
   - record the chosen legal-action index;
   - execute the command to advance replay state.
5. Compare final replay essentials with the raw result and record export diagnostics.

If cDp8 internals such as simulation config or acting-seat logic need to be shared, expose a small pure helper from `src/game/sim/runHeadlessMatch.ts` instead of duplicating large config blocks. Keep the helper clearly simulation-scoped.

Policy-owned rows:

- include `choose_mulligan`;
- include `play_card`;
- include `pass`;
- include `use_leader`;
- include `choose_prompt_option`.

System rows:

- exclude `resolve_round_end` by default, because the simulation auto-resolver is not a policy decision;
- if `includeSystemActions: true` is implemented, mark those rows with `actorKind: "system"` and keep them out of policy training counts.

If a command cannot be matched back to a legal move, return a structured export diagnostic for that match and skip unsafe row emission for that command. Do not silently invent an action.

### 4. Define safe observation rows

Add a versioned observation shape designed for a model acting as one seat.

Suggested top-level shape:

```ts
export interface SafeSimulationObservation {
  schemaVersion: typeof SAFE_OBSERVATION_SCHEMA_VERSION;
  perspectiveSeatId: SeatId;
  opponentSeatId: SeatId;
  phase: MatchPhase;
  round: number;
  currentTurn: SeatId;
  own: SafeSeatPrivatePublicState;
  opponent: SafeOpponentPublicState;
  board: SafeBoardState;
  weather: SafeVisibleCardRef[];
  score: SafeScoreState;
  pendingPrompt: SafePromptState | null;
}
```

Minimum own-seat fields:

- hand cards visible to the acting seat;
- leader source id and used flag;
- deck count only, not deck order;
- discard count and, if already public/own-visible, discard card summaries;
- passed flag;
- gems.

Minimum opponent fields:

- hand count only;
- leader source id and used flag;
- deck count only;
- discard count and public discard card summaries if available from current state;
- passed flag;
- gems.

Minimum board fields:

- public units and row horns on both sides;
- row owner expressed relative to the perspective where useful: `own` or `opponent`;
- row type;
- visible card source ids, kind, strength, rows, and ability ids.

Minimum prompt fields:

- prompt id may be replaced with a row-local prompt ref if it contains engine instance ids;
- prompt kind;
- ability id;
- source card visible ref if visible to the acting seat;
- options encoded without exposing hidden opponent hand/deck details.

Do not include:

- `MatchState`;
- `cardsById`;
- full `events`;
- `commandLog`;
- raw engine `instanceId` values;
- opponent hand card identities;
- opponent deck card identities or order;
- own deck order;
- hidden zone source ids;
- debug-only prompt internals that are not visible to the acting seat.

Card references:

- prefer stable `sourceId` for visible cards, because source id is the catalog identity future policies can learn from;
- do not include raw engine `instanceId`;
- if a row needs to distinguish duplicate visible copies, add a row-local deterministic `cardRef`, such as `own_hand_0`, `own_board_close_1`, or `opponent_board_ranged_0`.

### 5. Encode legal actions as a per-row legal list

Do not define a fixed global neural action vector yet.

Encode the currently legal moves as an ordered list. Suggested shape:

```ts
export interface EncodedLegalAction {
  schemaVersion: typeof LEGAL_ACTION_SCHEMA_VERSION;
  actionIndex: number;
  actionId: string;
  kind: LegalMoveKind;
  label: string;
  source?: SafeActionCardRef;
  target?: SafeActionTargetRef;
  prompt?: SafeActionPromptRef;
  metadata: {
    cardKind?: string;
    abilities?: string[];
    row?: string;
    side?: "own" | "opponent" | "public" | "none";
    cardCount?: number;
    maxCards?: number;
  };
}
```

Action encoding rules:

- preserve the legal-move order from `getLegalMoves`;
- use `chosenActionIndex` to identify the selected action;
- include `legalActionCount`;
- include a simple `legalActionMask` if useful, but it can be an array of `true` values because the list already contains only legal moves;
- never include actions that were not produced by `getLegalMoves`;
- never allow an encoded action to mutate or construct engine commands.

Allowed action details:

- own hand source id for play/mulligan actions;
- visible board/weather target source id where public;
- row/side/ability metadata;
- prompt option index and visible target details.

Forbidden action details:

- raw `moveId` if it contains engine card instance ids;
- raw engine card instance ids;
- opponent hidden hand/deck source ids;
- full target objects copied from engine moves without redaction.

Use row-local action ids, for example:

- `action_0`;
- `action_1`;
- `action_2`.

If preserving raw move ids is useful for debugging, it must be behind an explicit debug-only path and must not appear in the default export dataset.

### 6. Define decision rows

Suggested row shape:

```ts
export interface SimulationDecisionRow {
  schemaVersion: typeof SIMULATION_EXPORT_SCHEMA_VERSION;
  rowId: string;
  matchId: string;
  seed: string | number;
  step: number;
  commandIndex: number;
  actorKind: "policy" | "system";
  seatId: SeatId;
  policyId: string;
  observation: SafeSimulationObservation;
  legalActions: EncodedLegalAction[];
  legalActionCount: number;
  legalActionMask: boolean[];
  chosenActionIndex: number;
  chosenAction: EncodedLegalAction;
  reward: SimulationRewardPlaceholder;
  outcome: SimulationOutcomeSummary;
}
```

`rowId` should be deterministic and not include raw engine card ids. Suggested:

```ts
`${matchId}:step:${step}:seat:${seatId}`
```

If `matchId` contains the seed, this is acceptable.

### 7. Add sparse reward placeholders

Do not over-shape rewards yet.

Add a minimal reward object that future training can expand:

```ts
export interface SimulationRewardPlaceholder {
  schemaVersion: "reward-v1";
  terminalMatchReward: -1 | 0 | 1 | null;
  isTerminalMatchRow: boolean;
  notes: readonly string[];
}
```

Rules:

- for completed matches, set `terminalMatchReward` relative to the row's `seatId`:
  - `1` if that seat won;
  - `-1` if that seat lost;
  - `0` for draw;
- for non-completed matches or failed runs, use `null`;
- `isTerminalMatchRow` should be true only for the last policy row of a completed match;
- keep intermediate shaped rewards out of scope.

### 8. Add export summaries and diagnostics

Minimum summary:

- system row count;
- rows by action kind;
- rows by seat;

## Acceptance Criteria

- A pure simulation export module exists under `src/game/sim`.
- `buildSimulationExportDataset` or equivalent public API is exported from `src/game/sim`.
- Export rows are generated from engine state plus legal moves before commands are applied.
- Default export rows include safe observation, encoded legal actions, chosen action index, sparse reward placeholder, and outcome summary.
- Default export rows exclude raw `finalState`, `commandLog`, full events, `cardsById`, engine `instanceId`, opponent hidden hand identities, opponent deck identities/order, and own deck order.
- Legal action encoding preserves legal move order and uses row-local action ids.
- `chosenActionIndex` always points at the encoded action corresponding to the executed command.
- `resolve_round_end` system actions are excluded by default.
- Same input produces deterministic dataset rows and summaries.
- Completed match rows include terminal match reward relative to each acting seat.
- Non-completed or failed runs do not get fake terminal rewards.
- Dataset summary counts rows by action kind, seat, policy id, and diagnostics.
- Docs explain the safe export contract and ML boundary.
- `docs/PROJECT_STATE.md` is updated.
- `audit/reports/2026-04-26-cDp10-report.md` exists.
- `npm test` passes.
- `npm run ci` passes.
- `npm run ci:browser` passes or is explicitly documented if local browser permissions block it.
- `git diff --check` passes.

## Notes For The Coding Instance

- Treat cDp10 as a contract layer, not a learner.
- Prefer explicit redaction over broad object spreading.
- Do not copy `SeatObservation` blindly if it contains fields you have not classified.
- Do not copy `LegalMove` blindly because move ids and target card ids can contain engine instance ids.
- Encode from known-safe fields and row-local refs.
- Keep raw replay/debug data separate from safe export rows.
- Keep the batch runner behavior unchanged unless a narrow helper export is needed.
