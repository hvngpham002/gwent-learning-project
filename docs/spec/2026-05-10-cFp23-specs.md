# cFp23 Specs - Benchmark Deck Taxonomy And Starter Matrix

## Purpose

Add a clear benchmark deck taxonomy and the first broader fixed-suite starter-deck matrix.

cFp22 made `benchmark-smoke-v1` durable through a safe artifact command, but the current smoke artifact measures only current Northern Realms versus current Nilfgaard. cFp23 should separate benchmark deck purposes so future AI work is not judged by one overloaded deck set.

The working taxonomy is:

1. `smoke`: tiny regression suites for harness and policy plumbing.
2. `starter`: stable official starter decks for broad, reproducible faction coverage.
3. `mechanics`: deliberately constructed decks that stress specific faction/rule mechanics.
4. `competitive`: curated strong deck lists for later strength benchmarking.

cFp23 should implement the taxonomy and add only the `starter` matrix. It should not create mechanics decks, competitive/best-in-faction decks, or improve AI strategy yet.

## Current Context

cFp21 added the in-memory benchmark harness and `benchmark-smoke-v1`.

cFp22 added:

- `npm run benchmark:smoke`;
- `scripts/run-benchmark-report.ts`;
- deterministic public artifact output under `docs/research/literature/ai/benchmark-results/<suite-id>/latest/`;
- artifact serialization that excludes unsafe debug output and hidden-info/runtime-state fields.

Current smoke output is useful but narrow. It currently shows `legal-heuristic-v0` beating `legal-first-v0` 12-0 over current Northern Realms versus current Nilfgaard. That is a plumbing/regression signal, not a strength benchmark.

The project has five official starter deck presets:

- `official-northern-realms-starter`;
- `official-nilfgaard-starter`;
- `official-monsters-starter`;
- `official-scoiatael-starter`;
- `official-skellige-starter`.

These should become the first broader fixed-suite matrix because they are stable and catalog-backed. They are not optimized competitive decks.

## Desired Architecture

Extend the benchmark layer rather than special-casing this in scripts.

Recommended additions:

```text
src/game/benchmark/decks.ts
src/game/benchmark/suites.ts
```

The deck taxonomy should be explicit data, not just prose in docs. Use names close to:

```ts
type BenchmarkDeckCategory = "smoke" | "starter" | "mechanics" | "competitive";

interface BenchmarkDeckDescriptor {
  deckPresetId: string;
  label: string;
  faction: CatalogFaction;
  category: BenchmarkDeckCategory;
  deckPreset: CatalogDeckPreset;
  notes?: string;
}
```

The exact shape can differ, but tests must be able to assert which starter decks are included in the starter matrix.

Keep the public benchmark output schema backward compatible unless a carefully documented optional metadata field is needed. Do not break existing cFp21/cFp22 tests or artifacts.

## Implementation Requirements

### 1. Add benchmark deck taxonomy

Add a small benchmark deck registry.

Required descriptors:

- smoke/current baselines:
  - `current-northern-realms`;
  - `current-nilfgaard`;
- starter decks:
  - `official-northern-realms-starter`;
  - `official-nilfgaard-starter`;
  - `official-monsters-starter`;
  - `official-scoiatael-starter`;
  - `official-skellige-starter`.

Category guidance:

- `current-northern-realms` and `current-nilfgaard` may be category `smoke`, or `smoke` plus a second doc-only "current baseline" note if the type stays single-category.
- the five official presets must be category `starter`.
- `mechanics` and `competitive` categories should exist in the type/documentation but have no deck descriptors yet unless a placeholder format is genuinely useful and does not enter benchmark suites.

Do not change catalog deck presets themselves.

### 2. Add `benchmark-starter-matrix-v1`

Add a new built-in suite:

```text
benchmark-starter-matrix-v1
```

Purpose:

- broader fixed-suite matrix over official starter decks;
- reproducible faction coverage;
- not a claim of optimized deck strength.

Required shape:

- use the five official starter presets;
- include every unordered pair of distinct starter decks;
- compare `legal-heuristic-v0` against `legal-first-v0`;
- enable mirroring on every matchup so each deck/policy pairing appears on both seats across the pair;
- use a bounded deterministic seed list with 3 seeds;
- expected record count: `5 choose 2 * 2 policy assignments * 3 seeds * 2 mirror runs = 120 records`;
- default max steps should stay bounded and can reuse the current smoke max step limit unless there is a clear reason not to.

Recommended matchup id format:

```text
starter-<deck-a-faction>-vs-<deck-b-faction>-legal-heuristic-v0-vs-legal-first-v0
```

Use stable ids. Do not include random order-dependent labels.

### 3. Keep `benchmark-smoke-v1` stable

Do not change the existing `benchmark-smoke-v1` suite semantics, seeds, matchup id, record count, or generated artifact unless a test reveals an unavoidable issue.

Existing cFp22 `benchmark-smoke-v1/latest` artifacts should not change in cFp23 unless the benchmark serialization schema changes, which should be avoided.

### 4. Add npm script for starter matrix artifacts

Add a package script:

```json
"benchmark:starter-matrix": "tsx scripts/run-benchmark-report.ts --suite benchmark-starter-matrix-v1"
```

Do not remove or change `benchmark:smoke`.

### 5. Generate starter matrix artifacts

Run the new script and commit:


Expected:

- `manifest.json` record count is 120;
- `summary.json` total matches is 120;
- `records.jsonl` has 120 lines;
- all five official starter preset ids appear in the summary deck preset ids;
- both policy ids appear;
- no unsafe debug or hidden-info hazard strings appear.

Run the script twice and verify no diff in `benchmark-starter-matrix-v1/latest`.

### 6. Add tests

Add or update focused tests.

Required benchmark suite coverage:

- `getBenchmarkSuite("benchmark-starter-matrix-v1")` returns the new suite;
- suite has 5 starter deck descriptors by category;
- suite has 10 matchup definitions;
- suite has 3 seeds;
- every matchup has `mirror: true`;
- running the suite returns 120 records;
- summary deck preset ids are exactly the five official starter ids, sorted;
- summary policy ids are `legal-first-v0` and `legal-heuristic-v0`;
- existing `benchmark-smoke-v1` tests still pass unchanged.

Required artifact coverage:

- `npm run benchmark:starter-matrix` generated artifacts are parseable;
- committed `records.jsonl` has 120 lines;
- committed `summary.json` has `schemaVersion: "benchmark-summary-v1"` and `totalMatches: 120`;
- committed `manifest.json` has `schemaVersion: "benchmark-artifact-v1"` and `recordCount: 120`;
- committed artifact strings do not contain:
  - `cardsById`;
  - `finalState`;
  - `commandLog`;
  - `"hand"`;
  - `"deck"`;
  - `ownHand`;
  - `opponentHand`;
  - `seat_a:`;
  - `seat_b:`;
  - `unsafeDebugResults`.

Avoid slow all-suite tests that run the matrix repeatedly. One focused run is acceptable; artifact parse tests can read committed files without rerunning the suite.
