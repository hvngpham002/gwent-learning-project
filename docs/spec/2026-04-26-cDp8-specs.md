# Implementation Spec: Cluster D, Phase 8 - Headless AI-vs-AI Simulation Smoke Harness

## Goal

Add the first headless AI-vs-AI simulation harness over the pure engine and existing legal-move AI policy.

The harness should prove that a match can run to completion without React, Redux, timers, browser APIs, or legacy rule helpers. It should use the same core engine transactions, legal move generator, seat observations, and policy interface that the engine UI uses.

This is the first simulation/ML foundation slice. It is not a tournament runner, not a training environment, and not a strategic AI upgrade.

## Architecture Position

Current state after `cDp7`:

- legacy UI remains the default route;
- engine UI is opt-in through `?engine=1` or `VITE_ENGINE_UI=1`;
- Playwright Chromium smoke now guards the opt-in shell at browser level;
- the pure engine owns setup, legal moves, command execution, prompts, scoring, round resolution, game end, and deterministic RNG;
- `legal-heuristic-v0` selects from legal moves using hidden-info-safe seat observations;
- `commandFromLegalMove` converts legal moves into exact engine commands;
- no headless AI-vs-AI runner exists yet.

Phase 8 should compose the existing pure modules into a deterministic simulation API.

## Scope

- `src/game/sim/`

Suggested files:

- `src/game/sim/runHeadlessMatch.ts`
- `src/game/sim/metrics.ts`

Forbidden dependencies:

### 2. Define simulation inputs and outputs

Add structured types for a single headless match run.

Minimum input:

```ts
interface HeadlessMatchSimulationInput {
  seed: string | number;
  maxSteps?: number;
  policies?: Partial<Record<SeatId, EnginePolicy>>;
}
```

Default behavior:

- `maxSteps` defaults to a conservative finite number, suggested `300`;
- both seats default to `legal-heuristic-v0`;
- current catalog presets are used:
  - `seat_a`: Northern Realms current preset;
  - `seat_b`: Nilfgaard current preset;
- both seats use `controllerKind: "ai"`;
- match id should be deterministic from the seed, for example `sim:${seed}`.

Minimum output:

```ts
interface HeadlessMatchSimulationResult {
  status: "completed" | "max_steps_exceeded" | "policy_failed" | "engine_error";
  seed: string | number;
  matchId: string;
  finalState: MatchState;
  winner: SeatId | "draw" | null;
  steps: SimulationStepLog[];
  commandLog: Exclude<EngineCommand, { type: "StartMatch" }>[];
  events: GameEvent[];
  summary: SimulationSummary;
  error?: {
    code: string;
    message: string;
    step?: number;
    seatId?: SeatId;
  };
}
```

The output can include additional fields, but do not serialize full hidden observations into the default step log.

### 3. Implement deterministic headless stepping

Add a runner function, suggested:

```ts
runHeadlessMatchSimulation(input: HeadlessMatchSimulationInput): HeadlessMatchSimulationResult
```

The runner must:

1. Start a match with `startMatch` and current catalog presets.
2. Repeatedly determine the next action until `game_end` or a terminal error.
3. For policy-owned actions:
   - call `getLegalMoves`;
   - build the acting seat's `SeatObservation`;
   - call the configured `EnginePolicy.selectMove`;
   - convert with `commandFromLegalMove`;
   - execute with `executeCommand`.
4. Record step logs, commands, and events.
5. Stop with `max_steps_exceeded` if the match does not end in time.
6. Never call `Math.random()`, timers, DOM APIs, or Redux.

Acting-seat policy:

- if `state.pendingPrompt` exists, acting seat is `pendingPrompt.seatId`;
- if `state.phase === "mulligan"`, act incomplete mulligans in fixed seat order `seat_a`, then `seat_b`;
- if `state.phase === "playing"`, acting seat is `state.currentTurn`;
- if `state.phase === "round_end"`, auto-resolve round end through the legal move path:
  - call `getLegalMoves` for a deterministic resolver seat, suggested `seat_a`;
  - select the legal `resolve_round_end` move;
  - convert with `commandFromLegalMove`;
  - execute with `executeCommand`;
- if `state.phase === "game_end"`, stop.

Round-end auto-resolution is required for simulation only. Do not change engine UI behavior.

### 4. Add compact, safe step logs

Add a compact step log that is useful for debugging and future ML work without dumping full hidden state.

Suggested shape:

```ts
interface SimulationStepLog {
  step: number;
  phase: MatchPhase;
  round: number;
  seatId: SeatId;
  policyId: string;
  legalMoveCount: number;
  chosenMoveId: string;
  chosenMoveKind: LegalMoveKind;
  commandType: Exclude<EngineCommand, { type: "StartMatch" }>["type"];
  eventTypes: GameEvent["type"][];
}
```

Allowed in the default step log:

- move IDs;
- command type;
- event types;
- legal move count;
- policy id;
- phase/round/seat.

Avoid in the default step log:

- full observations;
- opponent hand card names/source IDs;
- full deck order;
- full state snapshots per step.

The result may include `commandLog` because it is needed for deterministic replay/debugging, but do not market it as a hidden-info-safe training dataset yet.

Keep metrics deterministic and computed from the simulation result/state/events. Do not add reward shaping yet.

### 6. Add deterministic replay helper

Add a small replay helper or test-only utility that can replay a simulation command log from the same initial config.

Suggested public helper:

```ts
replayHeadlessMatchCommands(input: {
  seed: string | number;
  commandLog: readonly Exclude<EngineCommand, { type: "StartMatch" }>[];
}): MatchState
```

The replay helper should:

- start the same current catalog AI-vs-AI config;
- apply commands in order through `executeCommand`;
- return final state;
- throw or return a clear error if replay diverges.

This is not a full replay viewer.

### 7. Add focused tests

Create tests under:

- `tests/game/headlessSimulation.test.ts`

Minimum coverage:

- `runHeadlessMatchSimulation({ seed: "sim-smoke-001" })` reaches `completed` and `finalState.phase === "game_end"` within `maxSteps`.
- Same seed and policies produce the same:
  - winner;
  - command type sequence;
  - command log JSON;
  - summary metrics.
- Different max step limit can produce `max_steps_exceeded` without throwing, for example `maxSteps: 1`.
- Simulation resolves both seats' mulligans through policy moves.
- Simulation auto-resolves `round_end` without React/Redux.
- Simulation handles pending prompts owned by either seat through policy-selected `choose_prompt_option` moves when a prompt occurs. If no current deterministic seed naturally opens a prompt in a short run, add a narrow synthetic state/unit helper test or document why existing full-match completion covers prompt handling indirectly.
- Replay helper reproduces the final phase, winner, gems, and round history from the command log.
- Step logs do not include full observation payloads or obvious hidden opponent hand arrays.
- Forbidden import scan covers `src/game/sim`.

Do not make tests depend on a specific final winner unless necessary. If asserting a winner, use a fixed seed and document why it is stable.

## Out Of Scope

- Do not add batch/tournament simulation.
- Do not add a CLI that writes JSONL files.
- Do not add Python, notebooks, model training, reward shaping, or ML action encoding.
- Do not add random policies unless they are deterministic from engine RNG or an explicit seed.
- Do not change engine rules, scoring, legal move generation, command semantics, or AI strategy except for a narrowly documented bug fix.
- Do not change browser/UI behavior.
- Do not make engine UI the default route.
- Do not use React, Redux, browser APIs, timers, localStorage, or filesystem writes in `src/game/sim`.
- Do not import legacy AI or legacy rule helpers.

- A pure `src/game/sim` module exists and exports the headless match runner.
- The runner can complete a current Northern Realms vs Nilfgaard AI-vs-AI match using `legal-heuristic-v0` for both seats.

## Notes For The Coding Instance

- Treat this as an engine composition layer, not a new rule engine.
- Prefer a clear failure result over throwing for expected policy/no-move/max-step problems.
- Keep the simulation API small and testable. Batch runners and JSONL output can come next.
- `commandLog` may include card instance IDs for replay. Do not confuse that with the future hidden-info-safe ML dataset.
- Use `legal-heuristic-v0` as-is. Better AI decisions are out of scope.
- Keep browser smoke green; simulation work should not require UI changes.
