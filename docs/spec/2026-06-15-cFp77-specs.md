# Cluster F Phase 77 Specs - Public Action Identity Artifact v0

Date: 2026-06-15
Branch: `codex/cFp77-public-action-identity-artifact-v0`
Base: `dev`

## Summary

cFp76 proved that `search-consumer-action-features-v0` can emit
hidden-info-safe root feature rows from committed cFp68-cFp74 artifacts, but it
also proved that committed cFp69-cFp74 scalar artifacts do not contain durable
per-public-action identities. cFp76 therefore correctly stopped at:

```text
consumerReadinessStatus: action_feature_source_gap
```

cFp77 should close that gap by adding a narrow benchmark-only public-action
identity artifact at the earliest safe layer: the cFp69 root-observer layer,
where legal moves already exist before policy selection.

cFp77 should not add search. It should not execute candidate actions. It should
not rebuild sampled states, materialize hidden worlds, or evaluate actions. It
should only serialize stable, hidden-info-safe public-action bucket identities
for each eligible root, using the existing public action abstraction from
`samplerReadiness.ts` / cFp69-cFp70 infrastructure.

## Why This Phase Exists

cFp76's root feature artifact is useful, but future search consumers still
cannot join root-level evidence to a particular public action because no
committed artifact exposes action rows. The existing cFp69 and cFp70 artifacts
only preserve aggregate maps such as:

- public action count;
- public action kind counts;
- target kind counts;
- target side counts;
- largest bucket size; and
- collision count.

That is intentionally safe, but it is not enough for an action-level consumer.
cFp77 should add the missing action identity table without widening the search
claim:

- action identities are public bucket identities, not raw legal moves;
- rows contain broad public action categories and counts only;
- no raw move IDs, card IDs, source IDs, card names, or hidden payloads;
- no action value or rollout result; and
- no product AI behavior.

## Scope

Implement `public-action-identity-artifact-v0` as a benchmark-only artifact
family that:

1. observes benchmark roots using the same root-observer position as cFp69
   (after legal moves are generated, before policy selection);
2. builds public action buckets from legal moves with the existing
   `buildPublicActionAbstraction` /
   `buildDeterminizedPimcActionAvailabilityV0PublicActionBucketKey` contract;
3. emits one action identity row per collapsed public action bucket per cFp68
   eligible root;
4. emits one root summary row per observed eligible root;
5. carries cFp68/cFp69 skipped roots into skipped rows;
6. validates row counts against cFp68 and cFp69 committed artifacts;
7. writes deterministic hidden-info-safe artifacts for current and robust
   starter suites;
8. updates AI Lab metadata to cFp77 as public-action identity infrastructure,
   not search gameplay;
9. updates docs and project state; and
10. creates the required cFp77 audit report.

The new artifact may rerun the benchmark suite to observe legal moves at roots,
as cFp69 did. It must not execute any additional candidate action beyond normal
benchmark policy play. It must not execute public-action buckets in sampled
states. It must not mutate existing cFp68-cFp76 artifact directories.

## Required Source Consistency Checks

The cFp77 summary must include source consistency fields that prove:

- cFp68 summary eligible count equals actual `eligible-roots.jsonl` row count;
- cFp68 skipped count equals actual `skipped-roots.jsonl` row count;
- cFp69 summary probe count equals actual `probe-roots.jsonl` row count;
- cFp69 summary skipped count equals actual `skipped-roots.jsonl` row count;
- cFp76 root feature count equals actual cFp76 `root-features.jsonl` count when
  read or compared through summary/hash references;
- cFp76 skipped root count equals cFp68/cFp69 skipped count;
- cFp76 readiness is `action_feature_source_gap`;
- cFp76 action feature row count is 0;
- cFp76 action-feature-gap row count is greater than 0;
- observed cFp77 roots exactly match cFp68 eligible root keys;
- every observed root has a matching cFp69 probe root;
- every cFp69 probe root has a matching observed root;
- observed public action count equals cFp69 `publicActionCount` for every root;
- observed legal move count equals cFp69 `legalMoveCount` for every root;
- action identity row count equals the sum of cFp69 `publicActionCount`;
- duplicate root keys are 0;
- duplicate action identity keys are 0;
- skipped root keys match cFp68/cFp69 skipped roots; and
- source artifact hashes are nonempty.

If any check fails, the artifact must report:

```text
identityReadinessStatus: source_consistency_failed
```

and must not claim action identity readiness.

## Public Action Identity Row Schema

`action-identities.jsonl` must include only safe public bucket fields:

Required identity/root fields:

- `schemaVersion`
- `identityRunId`
- `suiteId`
- `matchupId`
- `seed`
- `mirrorGroupId` when present
- `mirrorIndex` when present
- `step`
- `decisionIndex`
- `phase`
- `round`
- `seatId`
- `policyId`
- `faction`
- `deckPresetId`
- `rootPublicFingerprint`

Required action identity fields:

- `publicActionRef`: deterministic root-local ref such as `public_action_000`.
  It must be derived from sorted safe bucket order, not from raw move IDs.
- `publicActionKeyHash`: SHA-256 hash of the safe public bucket key.
- `publicActionOrdinal`: zero-based sorted bucket ordinal.
- `publicActionKind`
- `targetKind`
- `targetSide`
- `targetRow` when present
- `actionPhase`
- `actionRound`
- `sourceClass`
- `strengthBucket` when present
- `optionIndexLabel` when present
- `moveCount`
- `collisionCountWithinBucket`: `moveCount - 1`, floored at 0.

Optional safe derived fields:

- `bucketSizeClass`: `single`, `small_collision`, `large_collision`.
- `actionFamily`: broad grouping such as `mulligan`, `unit_play`,
  `leader`, `prompt`, `pass`, `round_resolution`, `other`.

Do not include:

- raw public action bucket key string if it contains delimiter-heavy internal
  implementation detail; prefer component fields plus `publicActionKeyHash`;
- raw legal move objects;
- raw move IDs;
- card instance IDs;
- card source IDs;
- card names;
- leader names;
- source IDs;
- deck order;
- sampled hand/deck contents;
- final match state;
- command/event logs;
- decision traces;
- action values;
- rollout results; or
- selected/best action labels.

- root identity fields listed above;
- `identityReadinessStatus`;
- `cFp69ProbeStatus`;
- `legalMoveCount`;
- `publicActionCount`;
- `publicActionCollisionCount`;
- `largestPublicActionBucketSize`;
- `observedActionIdentityRowCount`;
- `cfp69PublicActionCount`;
- `cfp69LegalMoveCount`;
- `publicActionCountDelta`;
- `legalMoveCountDelta`;
- public action kind counts;
- target kind counts;
- target side counts;
- bucket size class counts;
- `rootPublicFingerprint`;
- `sourceConsistencyStatus`.

The root summary row must not include action values, selected action, raw move
payloads, or hidden/private card identities.

## Skipped Root Rows

`skipped-roots.jsonl` should carry cFp68/cFp69 skipped root metadata and safe
skip counters, matching the existing cFp68/cFp69/cFp76 skip accounting style.
Skipped roots must not be silently dropped.

## Public Action Ref Rules

`publicActionRef` must be:

- root-local;
- deterministic across repeated runs;
- based on sorted safe public bucket order;
- stable when the same safe bucket set is regenerated; and
- safe to expose in downstream cFp78 consumers.

Use a readable ref such as:

```text
public_action_000
public_action_001
...
```

Do not use:

- raw `moveId`;
- raw `actionRef`;
- card instance IDs;
- source IDs;
- source card IDs;
- raw labels;
- card names; or
- hashes of unsafe payloads.

## Hidden-Info Safety

Generated artifacts must reject exact hazard tokens and catalog-derived card or
leader identities. The scanner should cover at least:

- private state/map keys;
- final state payloads;
- command/event logs;
- own/opponent hand arrays;
- unsafe debug/decision trace payloads;
- raw move/action identifiers;
- card/source identifiers;
- deck order;
- sampled hand/deck/world payloads;
- hidden hand/deck payloads;
- action value/reward/search-strength fields;
- runtime seat-instance prefixes; and
- catalog card/leader names and source IDs.

Avoid writing the literal hazard substrings in the cFp77 decision note/report
if those files are included in the direct scan. Use descriptive prose instead.

## Acceptance Criteria

cFp77 is complete only if:

- current and robust cFp77 artifact directories exist;
- action identity rows are emitted for every public action bucket at every
  cFp68 eligible root;
- action identity row count equals the sum of cFp69 `publicActionCount`;
- root summary rows are emitted for every cFp68 eligible root;
- skipped root rows are emitted for every cFp68 skipped root;
- source consistency checks pass with explicit actual-row-count deltas;
- duplicate action identity keys are 0;
- robust artifacts are deterministic across repeat;
- hidden-info serializer and direct scans pass;
- artifact size limits pass;
- AI Lab metadata points at cFp77 and describes it as public-action identity
  infrastructure, not search gameplay;
- docs and report are updated;
- all required checks pass;
- worktree is clean;
- branch is committed and pushed.

## Expected cFp78 Decision Logic

Use this guidance in the cFp77 report/decision note:

- If cFp77 action identity rows are complete and source consistency is ready,
  cFp78 should repair `search-consumer-action-features-v0` by joining cFp76
  root features to cFp77 public-action identities, producing nonempty action
  feature rows without action values/ranking.
- If cFp77 source consistency fails, cFp78 should repair the cFp77 source chain
  before consumer work.
- If cFp77 artifacts exceed size limits, cFp78 should compact the action row
  projection or create a deterministic casebook subset.

Do not recommend rollout/value/search-play policy from cFp77 alone.
