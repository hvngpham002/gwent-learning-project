# cEp5.3 Specs - In-Match Card Inspection

## Purpose

Bring the cEp5.2 card inspection contract into the authentic match screen.

cEp5.2 made catalog cards inspectable in the deck builder through a right-click context menu and a read-only modal. cEp5.3 should make visible cards in an active match inspectable with the same level of information, while preserving the existing match controls:

- left-click on human hand cards still selects playable cards;
- left-click on legal board/card targets still dispatches exact engine commands;
- discard browser and prompt choices keep their current click behavior;
- hidden opponent hand/deck contents remain hidden;
- React does not compute rules or mutate game state.

This is a UI/product follow-up, not an engine rules phase.

## Current Baseline

As of cEp5.2:

- `/?engine=1&ui=authentic` opens pre-game.
- `/?engine=1&ui=authentic&view=match` opens a direct authentic match, starting at mulligan.
- The authentic match screen renders:
  - score cards and leader art;
  - public weather cards;
  - public board rows;
  - human hand cards;
  - discard browsers for each public discard pile;
  - Medic prompt option cards;
  - a selected-card inspector in the right rail;
  - action panels driven by engine legal moves.
- cEp5.2 added deck-builder helpers:
  - `buildGeneratedCardItems`
  - `buildDeckBuilderCardActions`
  - `buildDeckBuilderCardInspection`
  - a deck-builder context menu;
  - a deck-builder inspect modal.

There is currently one known user-modified asset in the worktree:

```text
public/images/scoiatael/Elven_Skirmisher.png
```

Do not stage, overwrite, regenerate, or otherwise touch this asset unless the user explicitly asks.

## Scope

Implement in-match inspection for visible match surfaces:

1. Human hand cards.
2. Board unit cards on both sides.
3. Row horn cards if present.
4. Weather cards.
5. Public discard-browser cards for either seat.
6. Medic prompt option cards when visible to the human player.
7. Leader cards in the score cards, if this can be done cleanly.

The inspect surface should be read-only.

## Product Behavior

### Card Context Menu

Add a match-specific context menu for visible cards.

Recommended behavior:

- Right-clicking a visible card opens a small context menu.
- The menu offers `inspect`.
- Do not add deck-builder actions such as `add` or `remove` in the match screen.
- The menu closes on:
  - clicking outside;
  - pressing `Escape`;
  - selecting `inspect`;
  - opening another menu;
  - leaving the current match view.
- Right-click must call `event.preventDefault()` so the browser context menu does not appear.
- Right-click must not dispatch engine commands.

Do not break existing left-click behavior:

- human hand left-click still selects/deselects through `engineSelectedCardSet`;
- board card left-click still dispatches target moves when the card is a legal target;
- row left-click still dispatches row target moves;
- Medic prompt left-click still chooses the prompt option;
- discard pile buttons still open/close the discard browser.

If a visible context-menu trigger button is easy to add without disrupting the current match layout, it may be added as an accessibility improvement. It must have a non-colliding accessible name such as `inspect <card name>` or `card menu <card name>`. Do not add visible buttons if they crowd the match table or make the current Playwright selectors brittle.

### Inspect Modal

Add a match inspect modal. It may share code/styles with the deck-builder inspect modal if that can be done without entangling deck-builder add/remove behavior.

The modal should show:

- large authentic card art;
- card name;
- source ID;
- instance ID, when inspecting an engine card instance;
- faction;
- kind;
- printed strength for unit/hero cards;
- effective strength and modifier list for board cards, when available from `selectEngineScoreBreakdown`;
- rows;
- abilities with display names, status, glyph, and description;
- tags when available;
- image path;
- current match context:
  - zone or surface, e.g. `hand`, `board`, `weather`, `discard`, `prompt`, `leader`;
  - owner/current side label when known;
  - board row label when inspecting a board card;
  - current-side discard owner for discard cards.

The modal must close on:

- `close`;
- click outside;
- `Escape`.

It must not include edit controls, deck-builder controls, add/remove controls, or Card Studio links.

### Selected-Card Inspector

The existing right-rail `InspectorPanel` should remain useful.

Improve it only if it helps consistency:

- It may keep the compact selected-card summary.
- It may include an `inspect` button for the selected human hand card.
- It should not become the full modal replacement if that makes the rail crowded.
- Do not show a second strength overlay outside the card art. If strength context is needed, show it as text in the modal or inspector facts.

### Leader Inspection

If leader inspection is included:

- Right-clicking the visible leader card in each score card should open a leader-profile modal or reuse the card modal with leader-specific fields.
- Show leader name, faction, ability display name/status/description, used/ready state, image path, and owner label.
- Do not make placeholder leader abilities executable.
- Do not change `legalMoves` or `commands`.

If leader inspection becomes awkward because leader view models differ too much from card view models, defer it explicitly in the report. Card inspection is the priority.

## Hidden-Information Rules

This phase must preserve hidden information.

Allowed inspect targets:

- human hand cards;
- public board cards;
- public weather cards;
- public discard cards;
- visible human prompt options;
- visible leader cards.

Forbidden inspect targets:

- AI hand card identities in normal routes;
- AI deck card identities;
- hidden deck contents for either side;
- command/event log IDs that are not already public card identities;
- raw `MatchState`;
- raw hidden observations.

The AI hand must remain backs/count only in normal product routes. Do not add context menus to card backs that can reveal card source IDs or instance IDs.

The debug-only `debugAiMulligan=1` route may continue to reveal AI cards for mulligan animation inspection, but cEp5.3 does not need to expand that debug surface.

## Recommended Implementation Shape

Prefer extracting small reusable view-model and UI pieces instead of copying the full deck-builder modal.

Recommended additions:

### View Model

Create match-specific helpers in `src/components/gwent/matchViewModel.ts`, or a new local helper if the file becomes too crowded:

- `buildMatchCardInspection(...)`
- optional `buildMatchLeaderInspection(...)`
- optional shared type such as `MatchCardInspectionViewModel`

Inputs should be engine/UI view models, not raw rule calculations.

For card inspection, prefer this input shape:

```ts
{
  card: EngineCardViewModel | AuthenticBoardRuntimeCardViewModel | AuthenticRuntimeCardViewModel;
  origin: "hand" | "board" | "weather" | "discard" | "prompt";
  ownerLabel?: string;
  row?: CatalogRow;
  boardState?: AuthenticBoardCardState;
}
```

The helper should return already-formatted facts where practical:

- source ID;
- instance ID if present;
- faction display;
- kind display;
- row display;
- ability display;
- printed/effective strength facts;
- modifier labels;
- origin/context labels.

Keep the helper pure and unit-testable.

### UI Components

Options:

1. Extract a reusable read-only `AuthenticCardInspectModal` component used by both deck builder and match, while keeping deck-builder add/remove action buttons outside or as optional slots.
2. Add a match-specific modal beside `AuthenticMatchScreen` and defer shared extraction.

Recommendation: choose option 1 only if it stays small. If extraction turns into a large refactor, keep cEp5.3 match-specific and document a later shared-component cleanup.

Good candidate files:

- `src/components/gwent/AuthenticCardInspectModal.tsx`
- `src/components/gwent/cardInspectionViewModel.ts`
- `src/components/gwent/authentic-card-inspection.css`

However, do not create new files just to create new files. If a small local implementation in `AuthenticMatchScreen.tsx` is clearer, use it.

### Context Menu State

Add match-screen state similar to cEp5.2:

- `contextMenu`
- `inspectTarget`
- `openCardContextMenu`
- `closeCardContextMenu`
- `inspectCard`
- `closeInspect`

Use fixed viewport positioning and clamp the menu to the viewport like the deck-builder implementation.

### Instrumentation

Add stable selectors:

- `authentic-match-card-context-menu`
- `authentic-match-context-inspect`
- `authentic-match-card-inspect`
- `authentic-match-inspect-source-id`
- `authentic-match-inspect-instance-id`
- `authentic-match-inspect-effective-strength`
- `authentic-match-inspect-modifiers`

Selectors may differ if a shared modal already has good stable hooks, but the browser smoke must not rely on fragile text-only selection.

## Specific Surfaces

### Human Hand

- Right-clicking a human hand card opens the context menu.
- Inspect modal shows source ID and instance ID.
- Left-click behavior is unchanged.
- Disabled/unplayable hand cards are still inspectable.

### Board Cards

- Right-clicking any visible board card opens the context menu.
- If the board card is a legal target button, right-click must not trigger the target click.
- Inspect modal shows:
  - printed strength;
  - effective strength;
  - boosted/reduced/normal state;
  - modifier list;
  - current board row;
  - current side/owner label if available.
- This is read-only display of engine score breakdown data. Do not recompute scoring in React.

### Row Horns

- Right-clicking a row horn card opens inspect.
- If horn cards do not have score-breakdown entries, show printed/card metadata without effective-strength facts.

### Weather Cards

- Right-clicking a weather card opens inspect.
- Inspect shows it is weather/special, the ability name, image path, and public surface `weather`.

### Discard Browser Cards

- Right-clicking a public discard card opens inspect.
- Left-click does not need to do anything unless it already does.
- Inspect shows discard owner label.
- Do not expose cards that are not already rendered in the discard browser.

### Medic Prompt Options

- Right-clicking a visible Medic prompt option card opens inspect.
- Left-click still chooses the prompt option.
- The modal should be inspect-only; choosing the prompt still happens through the existing prompt button action.

## Out Of Scope

Do not do these in cEp5.3:

- no engine rule changes;
- no legal-move generator changes;
- no AI policy changes;
- no deck-builder composition changes;
- no Card Studio editing changes;
- no default route promotion;
- no drag-and-drop card play;
- no full animation rewrite;
- no focus-trap library adoption unless already trivial;
- no image downloads or asset edits;
- no edits to `public/images/scoiatael/Elven_Skirmisher.png`;
- no hidden AI hand/deck inspection.

## Tests

Add risk-scaled tests.

### Unit Tests

Update or add tests under `tests/components/gwent/`.

Recommended coverage:

- human-hand inspection view model includes source ID, instance ID, faction, rows, abilities, and printed strength;
- board-card inspection includes printed strength, effective strength, strength state, modifiers, and row context;
- weather-card inspection includes weather/special ability metadata;
- leader inspection if implemented;
- hidden card backs are not represented as inspectable card identities.

If helper extraction is skipped and most logic stays in React, keep the unit coverage focused on whatever pure helper is introduced.

### Browser Smoke

Extend `tests/e2e/engine-shell-smoke.spec.ts` or add a focused authentic match smoke file.

Required smoke:

1. Open an authentic match route and progress through mulligan into the match table. Use an existing helper/pattern from current cEp6/cEp5 browser tests.
2. Right-click a human hand card.
3. Assert context menu appears with `inspect`.
4. Click `inspect`.
5. Assert modal appears with card name, source ID, instance ID, faction/row/ability facts.
6. Close with `Escape`.
7. Inspect a public board card after at least one card is on board, or use a route/seed state that already gets there.
8. Assert effective-strength context appears for board cards.
9. Open a discard browser when possible and inspect a public discard card, if the existing smoke can reach discard without becoming brittle.
10. Assert no AI hidden hand source IDs/names appear in normal product text.

If discard inspection requires too much brittle gameplay setup, document the deviation and cover discard inspection with component/unit tests instead.

## Acceptance Criteria

cEp5.3 is complete when:

- visible match cards can be right-click inspected without changing left-click gameplay behavior;
- inspect modal shows the card profile and match context;
- board-card inspection shows engine-derived effective strength/modifiers when available;
- weather/discard/prompt visible-card inspection works or explicitly documented deviations are covered by tests;
- no hidden AI hand/deck identities are exposed;
- no engine rules, legal moves, AI policy, or deck validation behavior changed;
- browser smoke covers in-match context menu and inspect modal behavior;
- `docs/PROJECT_STATE.md` and `docs/ui/authentic-product-flow.md` are updated;
- report exists at `audit/reports/2026-04-30-cEp5.3-report.md`;
- intended files are staged if the user asks for commit, excluding `.claude/`, build metadata, and `public/images/scoiatael/Elven_Skirmisher.png`.
