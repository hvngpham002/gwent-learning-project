# Implementation Spec: Cluster C, Phase 11 - Fandom Reconciliation Rule Patch

## Goal

Reconcile the implemented official-card engine/catalog state with the high-signal findings from the Witcher Fandom scrape and the cCp10 ruleset audit.

This is a focused engine + catalog rules phase. It should make the official starter decks more faithful without broadening into UI redesign, AI strategy, leader abilities, or new scraping.

Primary outcomes:

- Fix confirmed catalog metadata errors for Cerys, Kayran, Toad, Schirru, Triss, Siege Tower, and Kambi/Hemdall.
- Implement the rule behavior needed by those corrected cards:
  - hero-source row effects;
  - row-scoped unit Scorch variants;
  - self-including unit-source whole-board Scorch;
  - shared Cow/Kambi Avenger-style battlefield removal replacement.
- Add focused regression coverage so future catalog imports do not silently reintroduce these errors.

## User-Confirmed Decisions

Use these decisions as source-of-truth for this phase:

- Cerys's current Muster-style ability is conceptually correct. The target group is Shield Maidens: `skellige.clan-drummond-shield-maiden`.
- Skellige Storm is a special neutral weather card.
- Biting Frost, Impenetrable Fog, Torrential Rain, and Clear Weather are special neutral weather cards.
- Clear Weather must clear all active weather, including Skellige Storm.
- Bovine Defense Force has no ability. It is summoned by Cow.
- Cow's current `avenger` ability identity is correct. Avenger should share the same rule family as Kambi.
- Geralt/Ciri using the current `muster_roach` representation is correct.
- Triss Merigold should be Close Combat.
- Hero cards can source their printed row abilities while remaining immune as receivers.
- A hero with Tight Bond would be useless because heroes are immune to receiving Tight Bond; do not invent a functional hero-tight-bond rule.
- Schirru is Scorch - Siege:
  - destroys the enemy's strongest Siege Combat unit(s);
  - only fires if the enemy Siege row total is 10 or more.
- Clan Dimun Pirate is whole-board Scorch and includes itself:
  - if no card has more strength than Clan Dimun Pirate, it destroys itself;
  - if cards tie with Clan Dimun Pirate for highest strength, it destroys them and itself;
  - effective post-modifier strength is used.

## Current Context

cCp10 found three P2 issues:

- hero `morale_boost` sources do not boost their rows;
- unit-source `scorch` cards do not fire;
- Cerys has `muster` but no `linkedSourceIds`.

The Fandom scrape then added confirmed catalog reconciliation items:

- `skellige.kambi-hemdall` is a combined source that should be split into Kambi and Hemdall;
- `monsters.kayran` lacks Agile + Morale Boost and one legal row;
- `monsters.toad` lacks Scorch - Ranged;
- `scoiatael.schirru` is using generic Scorch instead of Scorch - Siege;
- `neutral.triss-merigold` is in the wrong row;
- `northern-realms.siege-tower` has a leading tab in its display name.

The scrape's raw comparator also produced false positives. Do not "fix" these:

- neutral weather card kind mismatches;
- Bovine Defense Force ability;
- Geralt/Ciri `muster_roach`;
- Cow's `avenger` ability identity;
- Villentretenmerth `scorch_close`;
- the 22 leader rows reported as missing by the card-only comparator.

### 4. Hero-Source Row Effects

Fix scoring so hero sources can emit row effects while heroes remain immune as receivers.

Required behavior:

- A hero with `morale_boost` adds +1 to other non-hero units on its row.
- The hero source itself does not receive the +1.
- Other heroes on the row do not receive the +1.
- Existing unit-source Morale Boost behavior remains unchanged.
- Existing Commander's Horn receiver immunity remains unchanged.
- Do not make hero Tight Bond functional. Tight Bond strength changes only apply to eligible non-hero unit cards with matching source names.

Recommended implementation shape:

- Separate "effect source has printed ability" from "card can receive strength modifier".
- Keep receiver checks based on `source.kind === "unit"` / `!isHero` or equivalent.
- Allow source checks for row-wide emitter abilities (`morale_boost`, row horn sources if applicable) to include heroes.

Add regression tests for Kayran and/or Isengrim as hero-source Morale Boost cards.

### 5. Row-Scoped Unit Scorch

Generalize the existing `scorch_close` behavior so row-scoped unit Scorch supports:

- `scorch_close` for Villentretenmerth;
- `scorch_range` for Toad;
- `scorch_siege` for Schirru.

Required behavior:

- The card is played normally onto its legal board row.
- After placement, its printed row-scoped Scorch ability checks the opponent's corresponding row.
- It only fires if that opponent row's total effective strength is 10 or more.
- It destroys all tied strongest non-hero units on that opponent row.
- It never destroys heroes.
- It uses post-modifier effective strength.
- The source card remains on its board row unless some separate rule removes it.
- If the threshold is not met or there are no valid targets, emit an explicit no-target or threshold-not-met resolved event.

Do not change Special Scorch behavior.

Do not implement Foltest leader Scorch abilities in this phase.

### 6. Unit-Source Whole-Board Scorch

Implement generic unit-source whole-board Scorch for cards like Clan Dimun Pirate.

Required behavior:

- A non-special card with generic `scorch` plays normally onto its legal board row.
- After placement, it resolves whole-board Scorch across all board rows.
- It considers all non-hero units on both sides, including the source card itself.
- It destroys every non-hero unit tied for the highest effective strength.
- If Clan Dimun Pirate is the only highest unit, it destroys itself.
- If Clan Dimun Pirate ties other cards for highest, it destroys itself and those tied cards.
- Effective strength is computed after weather, Tight Bond, Morale Boost, and Horn modifiers.

Keep Special Scorch separate:

- Special Scorch still targets the shared `none`/global path and discards itself after resolving.
- Special Scorch is not considered a unit and is never a Scorch target.

### 7. Avenger / Kambi Battlefield Removal Replacement

Implement shared Avenger-style battlefield removal replacement for Cow and Kambi.

Required behavior:

- A board-row card with `avenger` and `linkedSourceIds[0]` should summon its linked replacement when it is removed from the battlefield.
- Existing records:
  - `neutral.cow` -> `neutral.bovine-defense-force`;
  - `skellige.kambi` -> `skellige.hemdall`.
- The replacement is selected from the controlling seat's side deck.
- The replacement lands on the same board side and row that the Avenger source occupied.
- The Avenger source moves according to the original removal operation:
  - round cleanup normally sends it to the board-side discard pile;
  - Scorch sends it to the board-side discard pile;
  - Decoy returns it to hand if Decoy is legal;
  - other existing moves should keep their current destination unless the rule explicitly says otherwise.
- The replacement must not duplicate zone membership.
- If the linked source is missing, emit a structured resolved/deferred outcome and do not crash.
- If the linked replacement is not present in side deck, emit a structured resolved/deferred outcome and do not crash.

Round cleanup policy:

- During round cleanup, Avenger replacements should be placed after the row sweep for the departing round so they remain on the board for the next round.
- Do not immediately sweep the just-summoned replacement in the same cleanup pass.
- Round-end scoring/gem loss is based on the board state before cleanup; the replacement affects the next round, not the already-resolved round.

Active-round removal policy:

- During active-round removal, such as Scorch or Decoy, summon the replacement immediately after the source leaves the board.
- The replacement is then part of the current board state and can affect subsequent scoring/abilities.

Suggested implementation direction:

- Add a centralized helper rather than scattering Cow/Kambi special cases.
- Reuse the side-deck linked replacement pattern established by Berserker, but keep Avenger separate from Mardroeme transformation:
  - Berserker source goes to `removed_from_game`;
  - Avenger source follows the original removal destination.
- Add an explicit event or movement reason such as `avenger_summon` if useful for tests/activity logs.

If the current cleanup code shape makes "summon after sweep" unsafe, stop and document the conflict in the report rather than forcing a brittle implementation.
