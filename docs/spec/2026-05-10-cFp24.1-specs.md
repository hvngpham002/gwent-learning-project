# cFp24.1 Specs - Product Playtest Toggle For Legal Heuristic v1

## Purpose

Expose `legal-heuristic-v1` to the playable authentic Human vs AI flow
through a compact pre-game policy selector and a shareable URL override,
while keeping `legal-heuristic-v0` as the product default.

cFp24 made v1 benchmarkable. It did **not** make v1 playable through the
browser product flow. cFp24.1 should close only that wiring gap:

- `/` and `/match` should still default to `legal-heuristic-v0`;
- selecting `experimental · legal-heuristic-v1` in pre-game should make
  the AI controller use v1;
- adding `?ai=legal-heuristic-v1` should preselect v1 and make the AI
  controller use v1;
- the visible product labels should say which policy is active;
- invalid or absent `ai` query params should safely fall back to v0;
- benchmark-only `legal-first-v0` must remain unavailable in product play.

This is a playtest surface, not a finalized product difficulty system and
not a strategy tuning phase. The selector should be labelled as an AI
policy selector, not as a promise of player-facing difficulty balance.

## Current Context

cFp24 added `legal-heuristic-v1` and benchmark suites:

- `benchmark-v1-smoke-v1`: 12 records, v1 currently 8-4 versus v0.
- `benchmark-v1-starter-matrix-v1`: 120 records, v1 currently 88-32
  versus v0.

The product flow still uses v0 because:

- `ENGINE_AI_POLICY_ID` currently resolves to `legalHeuristicPolicyV0.id`;
- `AuthenticMatchSetupConfig.aiPolicyId` exists but is not threaded into
  `StartEngineMatchOptions` or the Redux engine adapter state;
- `getLegalHeuristicAiCommand(...)` imports and calls
  `legalHeuristicPolicyV0` directly.
- `/ai-lab` duplicates policy status in `aiLabViewModel.ts`, so it still
  says `legal-heuristic-v1` is "not implemented" even though cFp24 added
  the policy and artifacts. That duplication must be removed in this
  phase.

This phase should make the existing setup field real.

## Non-Negotiable Boundaries

- Do not change engine rules, legal moves, scoring, prompts, command
  payload semantics, round resolution, or game-end behavior.
- Do not tune `legal-heuristic-v1`.
- Do not alter cFp24 benchmark artifact contents unless tests require a
  harmless docs-only reference update. The product toggle should not
  regenerate benchmark artifacts.
- Do not add search, ML training, self-play, ratings, Glicko, TrueSkill,
  Python tooling, or browser benchmark execution.
- Do not make v1 the default.
- Do not expose `legal-first-v0` in product play. It remains
  benchmark-only.
- Do not add a full difficulty system. A compact pre-game AI policy
  selector is required, but it must not introduce rank/MMR/difficulty
  promises.
- Do not leak hidden information. The selected policy id is public; no
  hidden game state should become visible.
- Do not import from `src/game/benchmark` into product UI, adapter, or AI
  controller code. The AI Lab may show static benchmark artifact names and
  status, but it must not execute benchmarks or import benchmark runtime
  modules.
- New product/engine UI/adapter code must not import `@/legacy/...`.

## Required Behavior

### Product URL Contract

Support these URLs:

```text
/                         -> v0 default
/?ai=legal-heuristic-v0   -> v0 explicit
/?ai=legal-heuristic-v1   -> v1 playtest
/match                    -> v0 default direct match
/match?ai=legal-heuristic-v1 -> v1 direct match
/?engine=1&ui=authentic&ai=legal-heuristic-v1 -> old alias, v1 playtest
```

Invalid values must fall back to v0:

```text
/?ai=legal-first-v0       -> v0 fallback, because legal-first is benchmark-only
/?ai=unknown              -> v0 fallback
```

Use the exact policy ids as query values. Do not add abbreviated aliases
such as `?ai=v1` in this phase.

### Pre-Game AI Policy Selector

Add a compact selector to the product pre-game screen.

Recommended placement: inside Step 2 near the game-mode controls, after
or near the Casual mode tile. Keep it visually aligned with the existing
authentic form controls.

Required options:

```text
stable · legal-heuristic-v0
experimental · legal-heuristic-v1
```

Behavior:

- default selection is v0;
- `?ai=legal-heuristic-v1` preselects v1;
- invalid `?ai=...` preselects v0;
- changing the selector updates the setup config used by `begin match`;
- the footer summary reflects the selected policy id;
- the selector label must read `AI policy`, not `difficulty`;
- no `legal-first-v0` option appears.

The selector does not need to update the browser URL in this phase. URL
support is for deep-linking into an initial selection; the UI control is
for normal playtesting.

### Product AI Policy Registry

Add a product-safe policy registry under `src/game/ai/`, for example:

```text
src/game/ai/productPolicies.ts
```

It should export something like:

```ts
export const DEFAULT_PRODUCT_AI_POLICY_ID = "legal-heuristic-v0";
export const PRODUCT_AI_POLICY_IDS = ["legal-heuristic-v0", "legal-heuristic-v1"] as const;
export type ProductAiPolicyId = (typeof PRODUCT_AI_POLICY_IDS)[number];
export interface ProductAiPolicyMetadata { ... }
export const PRODUCT_AI_POLICIES: readonly ProductAiPolicyMetadata[] = ...;
export const resolveProductAiPolicyId = (value: unknown): ProductAiPolicyId => ...;
export const getProductAiPolicy = (policyId: ProductAiPolicyId): EnginePolicy => ...;
```

Implementation notes:

- The registry may import `legalHeuristicPolicyV0` and
  `legalHeuristicPolicyV1`.
- It must not import benchmark policies or `legalFirstPolicyV0`.
- Unknown values should resolve to `DEFAULT_PRODUCT_AI_POLICY_ID`.
- Add unit coverage proving `legal-first-v0` is rejected by the product
  resolver.

Metadata should be rich enough for both the pre-game selector and AI Lab,
for example:

```ts
{
  id: "legal-heuristic-v1",
  label: "legal-heuristic-v1",
  shortLabel: "experimental",
  productStatus: "playtest",
  benchmarkStatus: "benchmark artifacts available",
  productSelectable: true,
  description: "Experimental deterministic heuristic baseline from cFp24.",
}
```

Do not duplicate policy implementation status in the AI Lab. The AI Lab
must consume this shared metadata so future policy registration changes
cannot leave it stale.

### Setup Flow

Thread `aiPolicyId` through the setup flow:

- `AuthenticMatchSetupConfig.aiPolicyId` should become a product policy
  id, not `typeof ENGINE_AI_POLICY_ID`.
- Add a query parser, either in `preGameViewModel.ts` or the product
  policy module:

```ts
aiPolicyIdFromSearch(search: string): ProductAiPolicyId
```

- `getDefaultPreGameSelection(...)`, `buildPreGameModeOptions(...)`, and
  `buildSetupConfig(...)` should accept/use the selected product policy
  id.
- `AuthenticPreGameScreen` should initialize the selected AI policy from
  `search`, store it in local component state, and pass it to
  `buildSetupConfig(...)`.
- The Casual mode note and pre-game footer should show the selected id,
  so the player can verify whether the match will use v0 or v1.
- Add a pure view-model helper for the selector options if that matches
  existing pre-game patterns, for example `buildPreGameAiPolicyOptions()`.
- Changing the policy is done through the selector. URL query only sets
  the initial selection.

### Engine Adapter State

Store the selected product policy id in the engine adapter:

- Extend `StartEngineMatchOptions` with `aiPolicyId?: ProductAiPolicyId`.
- Extend `EngineAdapterState` with `aiPolicyId: ProductAiPolicyId`.
- Initialize it to `DEFAULT_PRODUCT_AI_POLICY_ID`.
- Include it in `engineMatchStarted(...)` payload and reset semantics.
- Add a selector if useful:

```ts
selectEngineAiPolicyId
```

Direct `startEngineMatch({ seed })` should also accept the URL-selected
policy id when called from `AuthenticMatchScreen`.

### AI Controller

Update `getLegalHeuristicAiCommand(...)` so it resolves the policy from
the engine adapter state instead of calling v0 directly.

Expected behavior:

- default adapter state uses v0;
- state with `aiPolicyId: "legal-heuristic-v1"` uses v1;
- any impossible / malformed value in state should still resolve to v0
  defensively.

Keep the existing gate behavior:

- no action while the human owns a prompt;
- no action while the adapter lock is non-AI;
- no action in `round_end`;
- no action after game end;
- no hidden information beyond `buildSeatObservation(...)`.

### Product Labels

Replace hard-coded policy labels in product match/mulligan surfaces:

- top bar policy id;
- status banner next-action copy when it is the AI turn;
- mulligan screen AI label;
- any setup/footer labels currently using `ENGINE_AI_POLICY_ID`.

The label should reflect the selected active policy for the match, not a
compile-time constant.

You may keep a renamed constant for the default policy if useful, but do
not keep a misleading `ENGINE_AI_POLICY_ID` constant that always says v0
while the controller may use v1.

### AI Lab Freshness

Update `/ai-lab` in this phase.

Current problem: `src/components/gwent/aiLabViewModel.ts` hard-codes
`legal-heuristic-v1` as `"not implemented"`. That is already stale after
cFp24.

Required fix:

- AI Lab policy rows must be built from the shared product policy
  metadata where applicable.
- `legal-heuristic-v0` should show as stable/default product policy.
- `legal-heuristic-v1` should show as implemented and experimental /
  playtestable, with benchmark artifact status.
- `legal-first-v0` may remain represented in AI Lab as a benchmark-only
  comparator, but it must come from a clearly separate benchmark-only
  metadata entry or local row labelled `benchmark-only`; it must not be
  part of `PRODUCT_AI_POLICY_IDS`.
- Add a unit test that fails if AI Lab marks any `PRODUCT_AI_POLICIES`
  entry as not implemented or omits it.
- Add a browser smoke assertion that `/ai-lab` displays
  `legal-heuristic-v1` with implemented/playtest wording and not
  `not implemented`.

This is the durable rule for future phases: if a policy exists in the
shared product policy registry, AI Lab must derive its status from that
registry rather than a manually duplicated string.

### Playtest Documentation

Update docs so a human tester can find the toggle:

- `docs/research/literature/ai/policies/legal-heuristic-v1.md`
- `docs/overhaul-plan/ai-ml-roadmap.md`
- `docs/PROJECT_STATE.md`
- optionally `docs/ui/authentic-product-flow.md` if that is where the
  current product route contract is documented.

Document that:

- v0 remains default;
- v1 is selectable in pre-game and deep-linkable with
  `?ai=legal-heuristic-v1`;
- v1 is experimental and not a difficulty tier;
- `legal-first-v0` remains benchmark-only.
- AI Lab policy status now consumes shared policy metadata and should be
  updated by policy registry changes rather than hand-edited duplicate
  strings.

## Tests Required

Add or update focused tests. Keep them deterministic and small.

### Unit Tests

Add coverage for the product policy registry:

- resolves v0;
- resolves v1;
- defaults unknown values to v0;
- rejects `legal-first-v0` into v0 fallback.
- exposes v0/v1 as product-selectable metadata.

Update pre-game view model tests:

- default selection is v0;
- `?ai=legal-heuristic-v1` sets setup config to v1;
- invalid `?ai=legal-first-v0` falls back to v0;
- mode note/footer-facing view model path uses the selected policy id.
- AI policy selector options include v0 and v1, with v0 stable and v1
  experimental/playtest wording, and exclude `legal-first-v0`.

Update AI Lab view-model tests:

- AI Lab includes every `PRODUCT_AI_POLICIES` entry;
- v1 is not labelled `not implemented`;
- `legal-first-v0` remains labelled benchmark-only and is not product
  selectable.

Update engine adapter tests:

- `startEngineMatch({ aiPolicyId: "legal-heuristic-v1" })` stores v1 in
  adapter state;
- a match started without `aiPolicyId` stores v0;
- rematch/start-new-game preserves the setup policy when `setupConfig`
  exists.

Update AI controller tests:

- with adapter `aiPolicyId` set to v0, the selected command matches v0
  for a controlled simple state;
- with adapter `aiPolicyId` set to v1, the controller delegates to v1.

If finding a natural state where v0/v1 choose different commands is too
fragile, test the resolver/adapter wiring directly and add a small
integration assertion that the v1 policy id reaches
`getProductAiPolicy(...)`. Do not introduce hidden-info hooks just to
test this.

### Browser Smoke

Add one Playwright smoke:

- open `/?ai=legal-heuristic-v1&seed=<fixed>`;

  `legal-heuristic-v1` and has it selected;

  `legal-heuristic-v1`;

Keep this smoke shallow. It is a wiring smoke, not a full quality test.

Also ensure an invalid product policy query falls back visibly to v0 in
unit tests; browser coverage for invalid query is optional.

Update the AI Lab smoke:

- open `/ai-lab`;
- assert `legal-heuristic-v1` appears as implemented / experimental /
  playtestable;
- assert the phrase `not implemented` does not appear for v1.

## Acceptance Criteria

- Pre-game renders an `AI policy` selector with stable v0 and
  experimental v1 options.
- Selecting v1 starts a playable authentic Human vs AI match whose AI
  controller uses `legal-heuristic-v1`.
- `/?ai=legal-heuristic-v1` preselects v1 and starts a playable
  authentic Human vs AI match whose AI controller uses v1.
- `/` and `/match` still default to `legal-heuristic-v0`.
- Invalid policy ids, including `legal-first-v0`, fall back to v0.
- Visible pre-game/match/mulligan labels reflect the selected policy id.
- `/ai-lab` no longer says `legal-heuristic-v1` is not implemented and
  derives product policy rows from shared policy metadata.
- Product UI/adapter/controller code does not import
  `src/game/benchmark`.
- No engine rules, legal moves, scoring, deck data, benchmark artifacts,
  or legacy route behavior changed.
- Hidden-info boundaries are unchanged.
- Required tests and docs are updated.
- `audit/reports/2026-05-10-cFp24.1-report.md` exists with the required
  sections.
