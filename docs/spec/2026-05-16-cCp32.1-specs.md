# cCp32.1 Specs - Scoia'tael Post-Mulligan First-Player Choice

## Summary

Repair the cCp32 Scoia'tael faction passive timing.

cCp32 implemented the right rule in the wrong place. It lets a human Scoia'tael player choose first turn in the pre-game setup and applies the choice inside `startMatch`. That is strategically incorrect: the player must choose after seeing the final mulliganed hand, immediately before round 1 begins.

This phase supersedes the setup-time and pre-game-selection parts of `docs/spec/2026-05-15-cCp32-specs.md`.

Correct rule:

> If exactly one player uses Scoia'tael, after both players finish mulligan and before round 1 begins, the Scoia'tael player chooses who takes the first turn.

The implementation must preserve cCp32's public event semantics (`turn_set.reason === "scoiatael_override"` and `faction_ability_resolved.ability === "scoiatael_choose_first"`), but those events must fire only after the post-mulligan choice resolves.

## Current Wrong Behavior

cCp32 currently does these things:

- Adds `MatchConfig.scoiataelFirstPlayerChoice`.
- Threads `scoiataelFirstPlayerChoice` through pre-game setup, `StartEngineMatchOptions`, and `MatchConfig`.
- Shows a first-turn selector on the authentic pre-game page when human is Scoia'tael.
- Applies the selected starter inside `startMatch`.
- Emits `faction_ability_resolved` and `turn_set.reason === "scoiatael_override"` during match setup, before mulligan.

That behavior must be removed or moved.

The final cCp32.1 behavior must not let the player choose before seeing the mulliganed hand.

## Product Decisions

Use these decisions exactly:

1. The Scoia'tael first-player choice happens after both mulligans are complete.
2. The choice happens before the first `phase_changed` event to `"playing"` for round 1.
3. The pre-game screen must not show a first-turn selector.
4. The pre-game setup config must not carry a human-selected first-turn value.
5. The engine must open a post-mulligan prompt when exactly one seat is Scoia'tael.
6. The prompt owner is the unique Scoia'tael seat.
7. The prompt has two options:
   - self starts
   - opponent starts
8. Resolving the prompt sets `currentTurn` and `roundStarter`, emits the cCp32 public events, then advances to `phase: "playing"`.
9. While the prompt is open, legal moves must be prompt choices only and visible only to the prompt owner.
10. If neither seat is Scoia'tael, keep the normal seeded initial-roll starter path.
11. If both seats are Scoia'tael, there is no unique chooser; keep the normal seeded initial-roll starter path.
12. For AI-owned Scoia'tael prompts, legal-heuristic-v1 may choose a deterministic simple fallback for now. Use "self starts" unless the existing policy structure makes a safer equally deterministic choice obvious.
13. Do not implement a sophisticated AI first-turn strategy in cCp32.1. The important requirement is that the AI prompt decision occurs after mulligan, so later AI work can reason from the final hand.
14. Mulligan observation should expose enough public metadata for future AI strategy to know that the acting seat will or will not own the post-mulligan first-turn choice.

## Required Engine Design

### 1. Remove Setup-Time Choice From `startMatch`

`startMatch` must no longer accept or apply an explicit pre-game first-turn choice.

Required changes:

- Remove or deprecate `MatchConfig.scoiataelFirstPlayerChoice`.
- Remove setup-time cCp32 validation that rejects or accepts `scoiataelFirstPlayerChoice`.
- Remove setup-time `faction_ability_resolved` for `scoiatael_choose_first`.
- Remove setup-time `turn_set.reason === "scoiatael_override"`.
- Preserve the existing seeded initial-roll behavior as the temporary starter before mulligan.

Important: do not break match determinism. The seeded roll can remain in `startMatch` because `MatchState.currentTurn` is already populated there, but exact-one Scoia'tael must override it only after mulligan completion and prompt resolution.

### 2. Add A Pure Helper For First-Choice Eligibility

Add a small pure helper in `src/game/core/setup.ts`, a new `src/game/core/scoiataelFirstPlayer.ts`, or another appropriate pure-engine file.

Required helper behavior:

```ts
type ScoiataelFirstPlayerEligibility =
  | { kind: "none"; reason: "no_scoiatael" | "mirror_scoiatael" }
  | { kind: "choice"; choosingSeatId: SeatId; opponentSeatId: SeatId };
```

The helper must:

- inspect only public faction identity;
- return `choice` only when exactly one seat has `faction === "scoiatael"`;
- return `none` for zero Scoia'tael seats;
- return `none` for two Scoia'tael seats.

Export it if tests or AI observation need direct access.

### 3. Open The Prompt After Both Mulligans Complete

Change `chooseMulligan` in `src/game/core/commands.ts`.

Current behavior:

```ts
if (state.seats.seat_a.mulliganComplete && state.seats.seat_b.mulliganComplete) {
  const from = state.phase;
  state.phase = "playing";
  events.push({ type: "phase_changed", from, to: state.phase, reason: "mulligan_complete" });
}
```

Required behavior:

- If both mulligans are complete and no unique Scoia'tael chooser exists:
  - preserve the existing transition to `phase: "playing"`;
  - emit `phase_changed` with `reason: "mulligan_complete"`;
  - do not emit `scoiatael_choose_first`.
- If both mulligans are complete and exactly one Scoia'tael chooser exists:
  - keep `state.phase` as `"mulligan"` while the prompt is pending;
  - create `state.pendingPrompt`;
  - emit `prompt_opened`;
  - do not emit `phase_changed` yet;
  - do not emit `turn_set.reason === "scoiatael_override"` yet.

Recommended prompt shape:

```ts
{
  promptId: `scoiatael-first-player:${state.matchId}:${state.round}`,
  seatId: choosingSeatId,
  kind: "choose_option",
  abilityId: "scoiatael_choose_first",
  stage: "scoiatael_first_player_choice",
  options: [
    {
      optionId: "scoiatael-first-player:self",
      label: "go first",
      target: { kind: "none" },
    },
    {
      optionId: "scoiatael-first-player:opponent",
      label: "opponent goes first",
      target: { kind: "none" },
    },
  ],
}
```

You may adjust labels to match the product tone, but keep option IDs deterministic and test them.

Add `"scoiatael_first_player_choice"` to `PendingPromptStage`.

### 4. Resolve The Prompt

Handle the prompt in `choosePromptOption` or in a small pure helper called by `choosePromptOption`.

Resolution rules:

- Only the prompt owner can resolve it.
- Only the two expected option IDs are accepted.
- The prompt target must be `{ kind: "none" }`.
- The prompt must still be in round 1 and phase `"mulligan"`.
- The prompt must still have `abilityId === "scoiatael_choose_first"` and `stage === "scoiatael_first_player_choice"`.

On `"scoiatael-first-player:self"`:

- `startingSeatId = choosingSeatId`
- `outcome = "chose_self"`

On `"scoiatael-first-player:opponent"`:

- `startingSeatId = opponentSeatId`
- `outcome = "chose_opponent"`

Then:

1. emit `prompt_resolved`;
2. clear `state.pendingPrompt`;
3. set `state.roundStarter = startingSeatId`;
4. set `state.currentTurn = startingSeatId`;
5. emit:

```ts
{
  type: "faction_ability_resolved",
  faction: "scoiatael",
  seatId: choosingSeatId,
  ability: "scoiatael_choose_first",
  outcome,
  policy: "post_mulligan_choice",
}
```

6. emit:

```ts
{ type: "turn_set", seatId: startingSeatId, reason: "scoiatael_override" }
```

7. transition phase:

```ts
const from = state.phase;
state.phase = "playing";
events.push({ type: "phase_changed", from, to: "playing", reason: "mulligan_complete" });
```

8. return the transaction without calling `handoffTurn`.

The first player selected by the prompt must act first in round 1.

### 5. Legal Moves

`getLegalMoves` already prioritizes pending prompts before phase checks. Preserve that contract.

Required legal move behavior:

- While the Scoia'tael prompt is pending, `getLegalMoves` for the chooser returns exactly the prompt option moves.
- While the prompt is pending, `getLegalMoves` for the non-chooser returns `[]`.
- No mulligan moves are legal after both seats have completed mulligan.
- No play/pass/leader moves are legal until the prompt resolves and phase changes to `"playing"`.

### 6. Product UI

Remove the pre-game first-turn selector.

Required removals:

- Remove the `authentic-pregame-scoiatael-first-you` and `authentic-pregame-scoiatael-first-opponent` UI.
- Remove first-turn selection state from `AuthenticPreGameScreen`.
- Remove `shouldShowScoiataelFirstPlayerChoice` and `getDefaultScoiataelFirstPlayerChoice` from the pre-game view model unless another use remains.
- Remove `scoiataelFirstPlayerChoice` from `AuthenticMatchSetupConfig`.
- Remove `scoiataelFirstPlayerChoice` threading through `setupConfigToStartEngineOptions`.
- Remove `scoiataelFirstPlayerChoice` from `StartEngineMatchOptions`.

Then support the post-mulligan prompt.

Preferred UI path:

- Use the existing prompt action surface if it can already render a `choose_option` prompt with `{ kind: "none" }` options.
- If existing generic prompt UI cannot present this clearly, add a small cCp32.1-specific prompt panel/modal on the mulligan-to-match boundary.

Required product copy:

- Eyebrow or status: `Scoia'tael first turn`
- Main text: `Choose who starts round 1.`
- Buttons:
  - `go first`
  - `opponent goes first`

The prompt must appear after both mulligans finish. It must not appear on the pre-game screen.

### 7. AI And Observation Contract

This phase must not tune legal-heuristic-v1's mulligan strategy, but it must make future tuning possible.

Add public observation metadata if it is natural in the existing AI observation shape:

```ts
ownHasPostMulliganFirstPlayerChoice?: boolean;
opponentHasPostMulliganFirstPlayerChoice?: boolean;
```

or an equivalent public enum.

Requirements:

- The value is derived only from public factions.
- It is available during mulligan observations.
- It does not reveal hidden cards.
- It is documented in the policy docs as a future hook, not as a tuned strategy.

For AI-owned Scoia'tael first-player prompts:

- legal-heuristic-v1 must select a legal prompt option.
- For cCp32.1, deterministic `"self"` is acceptable and preferred.
- Add a narrow test proving the AI can resolve the prompt and the match reaches `phase: "playing"`.

### 8. Event Summary

Keep the cCp32 battle-log/event-summary copy, but update assumptions:

- `chose_self` -> `Scoia'tael chose to take first turn`
- `chose_opponent` -> `Scoia'tael chose opponent to take first turn`
- There should no longer be a `defaulted_self` event for the cCp32.1 post-mulligan product path.

If you keep `defaulted_self` for a purely noninteractive fallback, document exactly where it can still occur. Preferred cCp32.1 design: no fallback event; use an actual AI prompt choice even for AI seats.

## Acceptance Criteria

- No first-turn selector appears in the authentic pre-game UI.
- Exact-one Scoia'tael match opens the first-player choice only after both mulligans complete.
- The choice is made with final hand knowledge.
- The prompt owner is the unique Scoia'tael seat.
- Non-chooser cannot see legal prompt moves.
- Resolving self/opponent choices sets `currentTurn` and `roundStarter` correctly.
- `faction_ability_resolved` and `turn_set.reason === "scoiatael_override"` fire only after prompt resolution.
- No-Scoia'tael and mirror-Scoia'tael matchups preserve seeded initial-roll behavior and do not open the prompt.
- AI-owned Scoia'tael prompt is resolved by legal-heuristic-v1 without hanging the match.
- Hidden-info boundaries remain intact.
- Benchmarks are refreshed or explicitly proven unchanged.
- cCp32 report/doc language that implied pre-game selection is superseded by cCp32.1 docs.

## Out Of Scope

Do not implement:

- a sophisticated AI first-turn strategy;
- new mulligan heuristics based on the first-turn choice;
- changes to legal-heuristic-v1 pass, weather, Medic, stop-loss, round-investment, or general card scoring;
- changes to faction abilities other than Scoia'tael first-player timing;
- leader ability changes;
- catalog/deck composition changes;
- new benchmark suites;
- model training, search, ratings, Python tooling, or UI difficulty tiers;
- legacy UI changes.
