# cFp43 Specs: Legal-Heuristic-v1 Round-One Overinvestment Guard

Date: 2026-05-20

## Summary

Implement a narrow `legal-heuristic-v1` behavior patch for the actionable half
of the cFp42 casebook: round-one overinvestment. The goal is to reduce cases
where v1 spends too many hand cards in round 1, enters later rounds with poor
resources, and loses.

This is not a broad suspicious-pass rewrite and not a broad cFp36 resource
budget retune. The new guard must be round-1-specific, hidden-info safe, and
heavily exception-gated.

## Required Behavior

Add a narrow round-one guard that can choose `pass` over a useful play only when
all core conditions are true:

1. phase is `playing`;
2. `features.round === 1`;
3. `features.ownGems > 1`;
4. `features.passMove` exists;
5. opponent has not passed;
6. candidate exists and is `play_card`;
7. selected card spends a hand card;
8. selected move is not card advantage;
9. current public board/hand state indicates overinvestment risk:
   - own board card count is already high, or
   - estimated board card count after this move is high, and
   - estimated hand count after this move is low enough to matter;
10. no tactical exception applies.

Recommended starting thresholds:

```ts
const ROUND_ONE_OVERINVESTMENT_BOARD_AFTER_FLOOR = 7;
const ROUND_ONE_OVERINVESTMENT_HAND_AFTER_CAP = 4;
```

Interpretation:

- `boardAfterSelectedMove = ownBoardCardCount + 1` for `play_card`.
- The guard is eligible when `boardAfterSelectedMove >= 7` and
  `estimatedHandCountAfterSelectedMove <= 4`.
- If tests show this is too weak to catch casebook fixtures, adjust only after
  recording the reason in the report. Do not make the guard broader than round 1
  without asking.

## Required Exceptions

The guard must return false and allow play when any of these apply:

- own last gem (`ownGems <= 1`);
- opponent already passed;
- round is not 1;
- candidate is `use_leader` or any non-hand-spending action;
- selected move is card advantage (`selectedMoveIsCardAdvantage === true`,
  e.g. Spy);
- candidate wins the match (`opponentGems <= 1` and candidate reaches
  `minimumScoreToWinRound(features)`);
- candidate is a cheap single-move catch-up:
  - `features.scoreDelta < 0`;
  - candidate reaches `minimumScoreToWinRound(features)`;
  - overkill is <= 3;
  - selected move does not leave no unit tempo;
- candidate is the only meaningful playable card:
  - `features.ownHandCount <= 1`, or
  - no pass move exists;
- prompt resolution, mulligan, Scoia'tael first-turn prompt, and all other
  non-playing phases.

Optional exception, if needed by tests:

- allow strong no-target/targeted Medic emergency tempo when it clearly puts the
  AI ahead while behind, mirroring the cFp39 clear-round-benefit exception.
  Prefer reusing the existing cFp39 helper/logic rather than adding a duplicate
  Medic scoring rule.

## Implementation Requirements

### 1. Add Hidden-Info-Safe Diagnostics

Extend `AiDecisionRoundInvestmentAnalysis` in `decisionTrace.ts` with fields
similar to:

```ts
readonly roundOneBoardAfterSelectedMove: number;
readonly roundOneOverinvestmentRecommended: boolean;
readonly roundOneOverinvestmentReason: AiDecisionRoundOneOverinvestmentReason;
```

Add a safe enum:

```ts
export type AiDecisionRoundOneOverinvestmentReason =
  | "none"
  | "round_one_board_limit"
  | "round_one_low_future_hand"
  | "exception_not_round_one"
  | "exception_last_gem"
  | "exception_opponent_passed"
  | "exception_non_play_card"
  | "exception_card_advantage"
  | "exception_match_winning_play"
  | "exception_single_move_catch_up"
  | "exception_single_card_hand";
```

The exact names can differ, but they must be enum-like lower_snake_case strings
and must not contain card names, source ids, card ids, ability arrays, or move
ids.

### 2. Add A Shared Decision Helper

In `legalHeuristicPolicyV1.ts`, add a pure helper such as:

```ts
export const buildRoundOneOverinvestmentDecision = (
  features: LegalHeuristicV1Features,
  analysis: AiDecisionRoundInvestmentAnalysis,
  selectedMove: PlayCardMove | UseLeaderMove | null,
  passDiagnostics: LegalHeuristicV1PassDecisionDiagnostics,
): AiDecisionRoundOneOverinvestmentReason => { ... };
```

Requirements:

- Use only `features`, public observations, legal moves, and the already
  hidden-info-safe analysis.
- Do not inspect raw `MatchState`, command logs, event logs, hidden opponent
  cards, deck order, or card instance ids beyond legal move source ids already
  available to the acting seat.
- Use `estimateImmediateTempo`, `minimumScoreToWinRound`, and existing
  pass-diagnostic helpers for match-winning / catch-up exceptions.
- Keep the helper exported for tests.

### 3. Wire The Guard Into `shouldPassForRoundInvestment`

Add the cFp43 guard inside `shouldPassForRoundInvestment(features, candidate)`.

Preferred order:

1. existing early returns and pass existence checks;
2. existing card-advantage and last-gem exceptions;
3. existing stop-loss / match-winning / cheap catch-up / Medic exception logic;
4. cFp43 round-one overinvestment guard;
5. existing cFp37 resource exhaustion gate;
6. existing cFp31 fallback preservation logic.

Do not place the cFp43 guard before card-advantage, match-winning, cheap-catchup,
or last-gem exceptions.

### 4. Explanation Parity

Update `explainLegalHeuristicV1Decision.ts` so selected `pass` decisions caused
by cFp43 emit a clear reason, for example:

```text
round-one overinvestment — preserve future hand
```

If a play is selected and the cFp43 analysis has an exception reason, the
explanation may say one of:

```text
round-one overinvestment ignored — card advantage move
round-one overinvestment ignored — match-winning play
round-one overinvestment ignored — single-move catch-up
```

Only add strings backed by tests. Do not expose card names/source ids.

## Required Policy Tests

Add focused tests to `tests/game/engineAiPolicy.test.ts`. Do not rely on raw
benchmark artifacts as fixtures. Build small public observations / feature
fixtures using existing test helper patterns in that file.

Minimum tests:

1. **Round-one overinvestment pass fires**
   - round 1;
   - ownGems > 1;
   - opponent not passed;
   - pass legal;
   - selected best useful move is a non-Spy `play_card`;
   - own board count before the candidate is high enough that
     `boardAfterSelectedMove >= 7`;
   - `estimatedHandCountAfterSelectedMove <= 4`;
   - policy selects `pass`;
   - trace has `roundOneOverinvestmentRecommended === true`;
   - reason mentions round-one overinvestment.

2. **Round-one overinvestment does not fire under threshold**
   - same as above but `boardAfterSelectedMove < 7` or hand after candidate > 4;
   - policy selects useful play.

3. **Spy/card-advantage exception**
   - same high board/low hand context;
   - selected best move is a Spy/card-advantage play;
   - policy selects play;
   - reason/analysis records exception.

4. **Leader/free-action exception**
   - useful `use_leader` candidate is best;
   - cFp43 does not suppress it.

5. **Last-gem exception**
   - ownGems <= 1;
   - high board/low hand context;
   - policy does not pass solely due to cFp43.

6. **Opponent-passed exception**
   - opponentPassed true;
   - existing opponent-passed logic remains unchanged.

7. **Round 2/3 exception**
   - same board/hand context in round 2 or 3;
   - cFp43-specific guard does not fire.

8. **Match-winning exception**
   - opponentGems <= 1 and candidate reaches minimum score to win;
   - policy selects play.

9. **Cheap single-move catch-up exception**
   - behind, candidate catches up with overkill <= 3, and does not leave no unit
     tempo;
   - policy selects play.

10. **Explanation parity**
    - `explainLegalHeuristicV1Decision(...)` and policy selection agree for the
      pass case and at least one exception case.

11. **v0 unchanged**
    - A cFp43-specific fixture must still show `legal-heuristic-v0` behavior is
      unchanged or at least that cFp43 helpers are not imported into v0.
