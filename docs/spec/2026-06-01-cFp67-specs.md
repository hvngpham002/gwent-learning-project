# Cluster F Phase 67 Specs - Post-cFp66 Invalid-Root Casebook

Date: 2026-06-01
Branch: `codex/cFp67-post-cfp66-invalid-root-casebook`
Base: `dev`

## Summary

cFp66 added benchmark-only, perspective-specific public-transfer memory to the sampler materialization pipeline. It repaired exactly one robust sampler invalid root and no current roots:

- Current cFp61 sampler-materialization remains 3,979 valid / 63 invalid roots.
- Robust cFp61 sampler-materialization improves from 32,146 valid / 341 invalid roots to 32,147 valid / 340 invalid roots.
- Current cFp62 remains 63 `public_zone_count_deficit` invalid roots.
- Robust cFp62 improves from 341 to 340 `public_zone_count_deficit` invalid roots.
- Remaining invalid roots have zero known hidden public-transfer cards at the invalid root.

cFp67 should create a decision casebook over the remaining post-cFp66 invalid roots. The goal is to decide whether the next search-readiness phase should:

1. define explicit valid-root-only skip accounting and proceed toward a determinized probe using only valid sampler roots; or
2. require a deeper public-state reconstruction phase before any determinized probe.

cFp67 is not search. It must not implement PIMC, ISMCTS, rollouts, root search, action ranking, action evaluation, search move selection, product AI behavior, or gameplay behavior.

## Problem Statement

The sampler materialization path is now strict and mostly usable, but not total:

- Current invalid rate: 63 / 4,042 roots, about 1.56%.
- Robust invalid rate: 340 / 32,487 roots, about 1.05%.

The remaining invalid roots may be acceptable to skip in a first determinized probe if the skip accounting is explicit, deterministic, hidden-info-safe, and small enough not to distort benchmark conclusions. They may also indicate a still-repairable public reconstruction gap.

cFp67 should not guess. It should classify the remaining invalid roots using scalar-only evidence and make a concrete recommendation for cFp68.

## Required Decision Questions

The casebook must answer these questions:

1. How many post-cFp66 roots remain invalid in current and robust suites?
2. What percentage of all roots do they represent?
3. Are remaining invalid roots concentrated in a small set of rounds, phases, matchups, factions, decks, mirror directions, or provenance labels?
4. Are the remaining deficits mostly one-card deficits or larger deficits?
5. Do remaining invalid roots show any scalar evidence that public-transfer memory should still apply?
6. Do remaining invalid roots show a concrete, narrow, public-only reconstruction pattern that could justify another repair phase?
7. If no narrow repair pattern exists, what exact skip counters must cFp68 expose before valid-root-only search is acceptable?
8. Would valid-root-only skipping exclude enough roots to undermine a first probe?

## Classification Taxonomy

Classify every remaining invalid root exactly once. Use names matching the implementation style, but preserve these meanings:

- `valid_root_not_in_casebook`: reserved only for consistency checks, not emitted as an invalid-root label.
- `no_known_hidden_transfer_at_invalid_root`: invalid root has zero public-transfer known hidden hand/deck cards.
- `public_transfer_memory_not_applicable`: invalid root has public-memory evidence, but no hidden transfer that can reduce unknown hidden counts.
- `persistent_public_zone_count_deficit`: cFp62 still reports `public_zone_count_deficit`.
- `one_card_deficit`: scalar deficit is one card.
- `multi_card_deficit`: scalar deficit is two or more cards.
- `playing_phase`: invalid root occurs during `playing`.
- `round_end_phase`: invalid root occurs during `round_end`.
- `mixed_public_zones`: cFp64 provenance label is `mixed_public_zones`.
- `single_zone_board`: cFp64 provenance label is `single_zone_board`.
- `single_zone_discard`: cFp64 provenance label is `single_zone_discard`.
- `round_end_public_zone`: cFp64 provenance label is `round_end_public_zone`.
- `candidate_valid_root_only_skip`: no concrete public-only repair pattern is visible, and the root should be counted as a skipped root if cFp68 proceeds with valid-root-only search.
- `candidate_deeper_reconstruction`: scalar evidence identifies a narrow public-state reconstruction target.
- `classification_unavailable`: required scalar evidence is missing.

The final casebook may use one primary classification plus secondary scalar fields, or a set of mutually exclusive buckets plus secondary dimensions. The report must make the mutually exclusive accounting clear.

## Required Scalar Readouts

The cFp67 decision note and report must include, at minimum:

- Current and robust total roots.
- Current and robust valid roots.
- Current and robust invalid roots.
- Current and robust invalid-root percentages.
- Count and percentage by phase.
- Count and percentage by round.
- Count and percentage by provenance label.
- Count and percentage by deficit size bucket.
- Count and percentage by faction/deck/policy perspective if available without hidden-info risk.
- Count and percentage by public-transfer scalar buckets:
  - zero known hidden transfer;
  - hidden hand transfer present;
  - hidden deck transfer present;
  - public-transfer adjustment present;
  - uncovered deficit present.
- Count of roots that would be skipped under a valid-root-only search probe.
- Explicit cFp68 recommendation.

Do not export source ids, card ids, card names, raw deck lists, raw hands, raw decks, raw moves, action refs, raw state, event logs, command logs, sampled hands, or sampled decks.

## Expected Recommendation Shape

The preferred recommendation, unless cFp67 finds a narrow repairable class, is:

> cFp68 should define a valid-root-only determinized probe contract. It must skip invalid sampler roots explicitly, count skipped roots by suite, phase, round, matchup, policy, faction, deck, provenance label, and invalid reason, and report skipped-root percentages next to every search-readiness/probe result. It must not treat skipped roots as wins/losses/draws and must not silently drop them.

If the casebook finds a clear public-only reconstruction class, recommend that as cFp68 instead and explain why it is likely to repair a meaningful portion of the remaining invalid roots.
