# Implementation Spec: Cluster C, Phase 7 - Scoring Pipeline and Scorch Resolution

## Goal

Add the pure scoring pipeline for normalized engine state, then use that pipeline to resolve Scorch correctly. Phase 6 intentionally deferred Scorch until effective strength existed; Phase 7 should make strength calculation authoritative and explainable.

The scoring pipeline must become the shared source for future UI totals, round resolution, AI evaluation, simulations, Scorch targeting, and ML observations.

## Architecture Position

The current core engine has:

- normalized card instances and board state;
- deterministic command transactions;
- centralized ability resolution for Spy, Medic, Muster, and prompt chains;
- Scorch explicitly deferred or rejected because scoring did not exist yet.

Phase 7 should add pure score calculation without migrating Redux/UI/AI. It may update the pure command/ability path to consume scoring for Scorch, but it must not implement round cleanup, gem loss, next round, faction round-end passives, or game-end logic.

## Scope

1. Add a scoring module.
   - Suggested file: `src/game/core/scoring.ts`.
   - Export it from `src/game/core/index.ts`.
   - Keep it pure: no React, Redux, DOM, localStorage, timers, `Math.random()`, mutation, or legacy helper imports.
   - Do not call old `src/utils/gameHelpers.ts` scoring functions.

2. Define score breakdown types.
   - Add serializable result types suitable for UI, AI, replay, and debugging.
   - Suggested top-level shape:
     ```ts
     calculateScores({
       state,
       catalogCards,
       catalogLeaders,
       weatherPolicyBySeat,
     }): MatchScoreBreakdown
     ```
   - `catalogLeaders` is optional if not needed yet, but leave a hook for leader/passive scoring context.
   - Suggested breakdown fields:
     - total per seat;
     - row totals per seat;
     - card-level effective strength entries;
     - active weather effects;
     - modifier trace per card;
     - diagnostics for invalid or unsupported scoring states.

3. Score only battlefield-relevant cards.
   - Include cards in board rows.
   - Include Heroes in totals at printed strength.
   - Include Unit cards in totals after modifiers.
   - Treat Decoy and any other Special placeholder in a board row as 0-strength non-unit placeholders.
   - Do not score row horn cards, weather cards, hand, deck, discard, side deck, removed cards, or leaders.
   - If a row array contains a non-card or missing catalog source, return a diagnostic or throw a typed error consistent with the existing engine style.

4. Detect active weather from normalized state.
   - Read `state.weather.entries`.
   - Resolve each weather card through `catalogCards`.
   - Active weather effects:
     - `frost` affects `close`;
     - `fog` affects `ranged`;
     - `rain` affects `siege`;
     - `skellige_storm` affects both `ranged` and `siege`.
   - Duplicate copies of the same weather effect do not stack.
   - Clear Weather cards should not be active because they should be in discard after resolution.
   - Weather affects both seats.

5. Implement Hero immunity.
   - Heroes keep printed strength.
   - Heroes ignore Weather, Commander's Horn, Morale Boost, Scorch target eligibility, Decoy targeting, Medic, and other external ability effects.
   - A Hero's own non-scoring ability may still have resolved in Phase 6, but score math should not apply external modifiers to Heroes.

6. Implement weather strength.
   - For non-Hero Units on weather-affected rows:
     - normal weather sets strength to 1;
     - Skellige Storm affects both ranged and siege;
     - Biting Frost, Fog, and Rain affect their matching rows.
   - Add a King Bran-compatible hook, even if no current catalog leader activates it yet.
   - Suggested hook:
     ```ts
     weatherPolicyBySeat?: Partial<Record<SeatId, "normal" | "king_bran">>
     ```
   - Under `king_bran`, a weathered friendly non-Hero Unit loses half printed strength rounded down: `printed - Math.floor(printed / 2)`.
   - If the implementation chooses a different hook shape, document it in the report and test it.

7. Implement Tight Bond.
   - Apply after weather.
   - Use the project rule policy from `docs/gwent-rules.md` section 17.8: count same-source allied units on the same side of the battlefield.
   - Use `sourceId` as the current stable proxy for same-name group. Do not use display-name string parsing.
   - Count only Unit cards with the `tight_bond` ability.
   - Count the scoring card itself.
   - Heroes are not externally modified; if a future Hero with Tight Bond appears, document and test the chosen policy before changing this.

8. Implement Morale Boost.
   - Apply after Tight Bond and before Horn.
   - Row-local only.
   - Each non-Hero Unit with `morale_boost` on the row gives +1 to other non-Hero Unit cards on that row.
   - A Morale Boost source excludes itself.
   - Multiple Morale Boost sources stack by source count.
   - Heroes and Special placeholders do not receive the bonus.

9. Implement Commander's Horn.
   - Apply last.
   - Special Horn:
     - row horn slot doubles all non-Hero Unit cards on that row;
     - does not affect Heroes;
     - does not score itself.
   - Unit Horn:
     - a non-Hero Unit with `commanders_horn` doubles other non-Hero Unit cards on that row;
     - the Unit Horn source is not doubled by its own Unit Horn effect.
   - Only one horn effect should apply per row.
   - Defensive policy for impossible states:
     - if a Special Horn row slot exists, use it as the row horn source;
     - otherwise use the first Unit Horn source in row order;
     - emit a diagnostic if multiple horn sources are present;
     - never multiply more than once.

10. Preserve modifier order exactly.
    - The required order is:
      1. Weather;
      2. Tight Bond;
      3. Morale Boost;
      4. Commander's Horn.
    - The audit found the old path applied Horn before Morale and could flip round outcomes. Add tests for the exact worked examples.

11. Add explainability.
    - Each card score entry should include enough information to explain the result:
      - printed strength;
      - base after weather;
      - tight bond multiplier;
      - morale bonus;
      - horn multiplier;
      - final strength;
      - modifier labels or flags.
    - This is important for future UI tooltips, AI debugging, and ML observations.

12. Add Scorch target helpers.
    - Export pure helpers or include them in the scoring module:
      - `findSpecialScorchTargets(...)`;
      - `findUnitScorchCloseTargets(...)`.
    - Special Scorch:
      - targets highest effective-strength non-Hero Unit cards across both sides of the battlefield;
      - includes tied highest targets;
      - excludes Heroes;
      - excludes Special placeholders such as Decoy;
      - can destroy the acting player's own units if they are highest.
    - Unit Scorch Close:
      - checks the row opposite the source card's controller/side;
      - only fires if that opposite close row total is at least 10 effective strength;
      - targets tied highest effective-strength non-Hero Unit cards on that row;
      - excludes Heroes and Special placeholders.
    - Use effective strengths from `calculateScores`, not printed strength.

13. Resolve Scorch in the pure command path.
    - Update Phase 6 Scorch deferral now that scoring exists.
    - Special Scorch:
      - allow legal Special Scorch commands to execute;
      - resolve targets with the scoring helper;
      - move scorched cards to their current `controller` discard piles, not physical board-side discard;
      - discard the Scorch card itself to the acting seat's discard pile;
      - emit `ability_triggered`, `card_moved`, `ability_resolved`, and useful Scorch events or outcomes.
    - Unit `scorch_close`:
      - after the unit is placed, resolve the effect with scoring helper;
      - if the opposite row total is below 10, resolve with a no-target or below-threshold outcome;
      - if targets exist, move targets to controller discard piles;
      - stop emitting generic `requires_scoring` deferral for this ability.
    - If a scorched card has a planned discard-trigger ability such as `summon` or `avenger`, emit a structured deferred event for that planned ability. Do not implement replacement unless fully tested.

14. Add movement/event types as needed.
    - Suggested movement reason:
      - `scorch_destroyed`;
      - `scorch_discard`.
    - Suggested event:
      - `scorch_resolved` with source card, ability ID, target card IDs, and outcome.
    - Keep events compact and serializable.

15. Do not implement round resolution.
    - Scoring totals are allowed to exist.
    - Do not decrement gems.
    - Do not choose round winner in authoritative state.
    - Do not sweep board.
    - Do not start next round.
    - Do not apply Nilfgaard draw-win, Monsters keeper, Northern Realms draw-on-win, or Skellige round-3 return.
    - Those belong to the next round/game resolver phase.

16. Add tests.
    - Add focused tests under `tests/game`.
    - Suggested file: `tests/game/coreScoring.test.ts`.
    - Update `coreAbilities.test.ts` or `coreCommands.test.ts` only for Scorch behavior changes.

17. Create the required implementation report:
    - `audit/reports/2026-04-25-cCp7-report.md`

## Out Of Scope

- Do not migrate Redux, React UI, or live AI strategy to this scoring pipeline.
- Do not implement round-end gem loss, cleanup, next-round setup, faction passives, or game end.
- Do not implement Summon/Avenger side-deck replacement from Scorch unless it is deliberately included and fully tested.
- Do not implement Mardroeme/Berserker transformation.
- Do not implement non-Clear-Weather leader abilities.
- Do not use legacy scoring helpers.

## Acceptance Criteria

- Core exports a pure scoring pipeline.
- Score results are deterministic, serializable, and explainable.
- Score calculation does not mutate input state.
- Weather, including Skellige Storm, is derived from normalized weather card instances.
- Heroes score printed strength and ignore external modifiers.
- Decoy and other Special placeholders score 0 and are not treated as Unit cards.
- Modifier order is Weather, Tight Bond, Morale Boost, Horn.
- Tight Bond, Morale Boost, Special Horn, and Unit Horn work according to the policy above.
- King Bran-style weather mitigation has a tested hook, even if no current catalog leader activates it by default.
- Scorch target helpers use effective strength and exclude Heroes/placeholders.
- Special Scorch and Unit Scorch Close are resolved in the pure command path using scoring.
- Scorched cards go to controller discard piles.
- Existing Spy, Medic, Muster, Decoy, weather, Clear Weather, pass, and prompt tests continue to pass.
- `npm test` passes.
- `npm run build` passes.
- Existing live gameplay behavior is not intentionally changed.

## Required Tests

At minimum, cover:

- Empty board totals are 0 for both seats.
- Plain Unit and Hero cards contribute printed strength.
- Heroes ignore weather, morale, and horn.
- Decoy placeholder on a board row scores 0 and is excluded from unit-only scoring/Scorch target helpers.
- Frost sets Close non-Hero Units to 1 for both seats.
- Fog affects Ranged.
- Rain affects Siege.
- Skellige Storm affects Ranged and Siege.
- Duplicate weather entries do not stack.
- Clear Weather in discard does not affect scoring.
- King Bran hook changes a weathered printed-strength 7 Unit to 4.
- Three Blue Stripes Commandos produce Tight Bond x3.
- Morale Boost excludes itself and stacks across multiple Morale sources.
- Special Horn doubles all non-Hero Units on the row.
- Unit Horn doubles other non-Hero Units on the row and not itself.
- Impossible multiple Horn sources do not stack beyond x2 and produce a diagnostic.
- Rulebook no-weather worked example: 3x Blue Stripes Commando, Olgierd, and Special Horn scores 90 on the row.
- Rulebook weather worked example: weathered Tight Bond plus Morale plus Horn produces 8 per affected bonded unit.
- Score breakdown includes per-card modifier trace.
- `calculateScores` does not mutate `MatchState`.
- Special Scorch picks highest effective non-Hero Units across both sides, including ties.
- Special Scorch ignores Heroes even when a Hero has the highest printed/effective strength.
- Special Scorch ignores Decoy placeholders.
- Special Scorch can destroy acting-side units if they are highest.
- Special Scorch sends destroyed Spy cards to their controller's discard pile.
- Unit Scorch Close does nothing below threshold.
- Unit Scorch Close destroys tied highest non-Hero Units on the opposite close row when row total is at least 10.
- Scorch command execution emits serializable events and leaves no duplicate zones.
- No core file calls `Math.random`.

## Things To Watch Out For

- Do not import or reuse old `gameHelpers` scoring. This is the replacement path.
- Do not apply Horn before Morale Boost.
- Do not count Decoy as a Unit just because it occupies a row array.
- Do not let Unit Horn and Special Horn stack.
- Do not discard Scorch targets by board side. Use `controller`.
- Do not mutate input state from score calculation.
- Do not make round-end decisions in this phase.
- Keep the score breakdown compact but sufficient for UI tooltips and AI debugging.
- Use `sourceId` for same-card grouping unless the catalog later gains an explicit bond group.
