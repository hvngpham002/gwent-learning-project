# Implementation Spec: Cluster B, Phase 4 - Official Non-Leader Catalog Promotion

## Goal

Promote engine-ready official non-leader Game8 candidates from the cBp3 staging layer into permanent catalog card source packs.

This phase should make the official non-leader card pool available as repo-owned catalog data while preserving the current playable defaults. It must not implement new rules, promote leaders, download images, or replace the product flow.

Target promotion shape:

- `159` official non-leader card candidates exist in cBp3 staging.
- Promote `157` engine-ready non-leader cards.
- Defer the `2` combined Berserker scrape candidates:
  - `skellige.young-berserker-young-vildkaarl`
  - `skellige.berserker-vildkaarl`
- Expected promoted-card count by faction:
  - Neutral: `22`
  - Northern Realms: `25`
  - Nilfgaard: `29`
  - Monsters: `35`
  - Scoia'tael: `24`
  - Skellige: `22`
- Expected promoted-card count by kind:
  - Heroes: `25`
  - Units: `123`
  - Specials/weather: `9`

## Current Context

cBp3 added the official Game8 staging layer under `src/data/catalog/official/` and the authoring route `/?engine=1&ui=authentic&view=official-porting`. cCp9 then completed the Mardroeme/Berserker/Skellige Storm engine gaps enough that those abilities are no longer counted as unsupported rule gaps.

The project now has a clear path to promote most non-leader official cards into normal catalog source files. The two remaining official Berserker rows are still combined base/replacement scrape candidates and should stay staged until their source data is split into separate base/replacement cards with `linkedSourceIds[0]` pointing to a side-deck replacement.

The current catalog files already contain the official Neutral, Northern Realms, and Nilfgaard card pools migrated from legacy data. Monsters, Scoia'tael, and Skellige card files are still empty placeholders even though source images for many of those cards already exist under `public/images/`.

## Product And Architecture Decisions

Use these decisions unless the user explicitly changes them later:

- Permanent catalog card packs must be repo-owned TypeScript data modules with plain JSON-compatible arrays/objects.
- Product catalog data must not import from `audit/scrapes/*` or from `src/data/catalog/official/game8OfficialGwent.ts` at runtime.
- Tests may import both permanent catalog data and cBp3 staging data to assert promotion coverage.
- `currentCatalogCards` should include the promoted official non-leader cards after this phase.
- Current Northern Realms and Nilfgaard deck presets must remain unchanged and continue to validate.
- Do not add official deck presets for Monsters, Scoia'tael, or Skellige yet.
- Do not promote official leaders yet. Leader abilities and full faction deck presets need their own scoped phase.
- Do not implement or reinterpret rules. If a candidate needs unimplemented or ambiguous rules, defer it.
- Do not download Game8 image binaries or commit scraped images.
- Do not change the default route, authentic route structure, deck-builder UI layout, or Card Studio behavior except for the data naturally exposed by `currentCatalogCards`.

## Scope

### 1. Add Permanent Official Card Packs

Update the existing card pack modules under:

```text
src/data/catalog/cards/
```

Requirements:

- Populate permanent card source arrays for all promoted official non-leader cards.
- Keep existing source IDs for already migrated current cards.
- Do not duplicate a source ID that already exists in Neutral, Northern Realms, or Nilfgaard.
- Preserve useful hand-authored current fields when a staged official candidate matches an existing current card:
  - `sourceId`
  - corrected `image` path
  - existing `description` when present
  - current `linkedSourceIds` when present
- Add missing official cards for Monsters, Scoia'tael, and Skellige into their faction files.
- Keep the data serializable: no functions, classes, Maps, Sets, Dates, or derived runtime lookups in the exported arrays.
- Add or update exports only through stable catalog entry points already used by the app.

Recommended implementation options:

- Manual curated arrays are acceptable if they are consistent and covered by tests.
- A local codegen helper is acceptable only if it is checked in as a deterministic developer helper and does not run at app runtime.
- If adding a helper, keep generated output under `src/data/catalog/cards/*`, not under `src/data/catalog/official/*`.

### 2. Define A Promotion Predicate

Add a small explicit promotion manifest or helper, preferably under:

```text
src/data/catalog/cards/official-promotion.ts
```

Use a different file name only if the local structure strongly suggests one.

The promotion manifest should document:

- promoted source IDs;
- deferred source IDs;
- deferred reason strings;
- expected promoted counts by faction and kind.

Requirements:

- Promote non-leader official candidates whose card abilities are implemented and whose data does not require split/link review.
- Defer candidates with any of these issues:
  - `ability_unknown:*`
  - `ability_status:*`
  - `rule_gap:*`
  - `catalog_split_required:*`
  - `transform_link_required:*`
  - `source_id_conflict:*`
- Specifically defer both combined Berserker candidates listed in the Goal section.
- Do not use image-missing status alone as a promotion blocker. Missing images should be tracked but should not prevent engine/data promotion because the UI already has deterministic card-art fallback.
- Do not promote leaders through this predicate.

### 3. Reconcile Image Paths Without Downloading Images

Promotion should reduce obvious image-path misses caused by the cBp3 preferred-path convention.

Requirements:

- Keep existing current catalog image paths for already migrated current cards when those paths are known-good.
- For new promoted cards, prefer an existing repo image path if one can be matched deterministically under `public/images/`.
- Common fallback patterns to support:
  - `/images/<faction>/<snake_case_name>.png`
  - `/images/<faction>/heroes/<Title_Case_Name>.png`
  - current explicit paths already used by legacy catalog files;
  - weather/special cards that live at faction root in the current image tree rather than under `/weather/` or `/specials/`.
- Do not download or commit Game8-hosted images.
- If no local image can be resolved, keep a deterministic `/images/...` path and rely on `AuthenticCard` fallback, but record the missing image count in tests/report.
- Do not modify crop metadata in the official porting localStorage store; crop review remains an authoring concern.

### 4. Keep Deck Presets Stable

Requirements:

- `currentNorthernRealmsDeckPreset` and `currentNilfgaardDeckPreset` must keep their current source references and counts.
- Existing default playable setup should still start Northern Realms vs Nilfgaard as before.
- Do not add Monsters, Scoia'tael, Skellige, or official full-deck presets in this phase.
- The deck builder may naturally expose the expanded `currentCatalogCards` pool because it consumes the shared catalog. That is acceptable.
- The pre-game setup should not gain new catalog preset tiles unless existing code already does so automatically from `currentDeckPresets`.

### 5. Update Official Porting Classification Docs

Update docs to distinguish:

- staged official candidates from cBp3;
- promoted permanent catalog card sources from cBp4;
- deferred Berserker split/link candidates;
- leader candidates still waiting for leader-rule phases;
- missing-image follow-up work.

Minimum docs to update:

- `docs/PROJECT_STATE.md`
- `docs/card-authoring/official-card-porting.md`
- `docs/card-authoring/current-catalog-workflow.md` if the "where to add card details" guidance changes.

### 6. Tests

Add focused tests that prove promotion is durable and bounded.

Recommended test file:

```text
tests/data/officialCatalogPromotion.test.ts
```

Coverage requirements:

- `currentCatalogCards` validates through `validateCardSources`.
- `currentDeckPresets` still validate through `validateDeckPresets`.
- `currentCatalogCards` has unique source IDs.
- Product catalog modules should remain static card packs, not wrappers around the Game8 scrape or candidate arrays.
- Promoted official non-leader count is exactly `157`.
- Permanent catalog includes all promoted source IDs from the cBp3 staging layer.
- Permanent catalog excludes the two deferred Berserker combined candidates.
- Deferred Berserker source IDs and reasons are present in the promotion manifest.
- Counts by faction match the Goal section.
- Counts by kind match the Goal section.
- Existing current source IDs still exist:
  - `neutral.decoy`
  - `neutral.commanders-horn`
  - `northern-realms.blue-stripes-commando`
  - `nilfgaard.impera-brigade-guard`
- Representative newly promoted cards exist:
  - one Monsters hero;
  - one Monsters non-hero unit;
  - one Scoia'tael hero;
  - one Scoia'tael non-hero unit;
  - one Skellige hero;
  - one Skellige non-Berserker unit;
  - `skellige.mardroeme`;
  - `neutral.skellige-storm`.
- Promoted cards with `mardroeme`, `skellige_storm`, `muster`, `medic`, `spy`, `tight_bond`, `morale_boost`, `commanders_horn`, `decoy`, `scorch`, weather, and `agile` validate against implemented ability metadata.
- If any promoted card has a missing local image path after reconciliation, tests should assert the count and the report should call it out. Missing images are allowed, but the number must be intentional and visible.

Update existing tests that still assume future faction card packs are empty.

Do not add browser smoke tests unless the implementation touches route/UI behavior. This phase should not need Playwright changes.

## Out Of Scope

- Do not promote official leaders.
- Do not implement leader abilities.
- Do not add Monsters, Scoia'tael, Skellige deck presets.
- Do not implement side-deck authoring.
- Do not split the combined Berserker candidates yet.
- Do not implement Avenger, Summon, or any new ability behavior.
- Do not alter Mardroeme/Berserker engine behavior from cCp9.
- Do not change AI policy.
- Do not change simulation/export schemas.
- Do not change authentic UI styling or layout.
- Do not download, scrape, crop, or commit card image binaries.
- Do not remove cBp3 staging exports or the official-porting route.

- Permanent catalog source files include `157` promoted official non-leader cards.
- The two combined Berserker candidates remain deferred with explicit reasons.
- `currentCatalogCards` exposes promoted official non-leader cards through normal catalog exports.
- Existing default deck presets are unchanged and valid.
- Product runtime catalog data does not import the Game8 scrape or official staging candidate arrays.
- Promoted source IDs are unique.
- Catalog validation passes for all cards, leaders, and presets.
- Official porting docs explain promoted vs staged vs deferred candidates.
- `docs/PROJECT_STATE.md` is updated.

## Things To Watch Out For

- The source pack files may become large. Keep them organized and consistent, but avoid inventing an abstraction that hides the actual card data.
- Do not accidentally add both the existing current record and the official staged record for the same source ID.
- Do not regress image paths that the current UI already renders correctly.
- Do not "fix" official card abilities by changing engine metadata or rule behavior in this phase.
- Do not let staged Game8 candidate objects become the runtime source of product catalog data; staging is an import/review lane, not the permanent catalog.
- Adding Monsters, Scoia'tael, and Skellige card sources without leaders is expected to make those card pools visible before full faction decks are playable. Call this out clearly in the report.
