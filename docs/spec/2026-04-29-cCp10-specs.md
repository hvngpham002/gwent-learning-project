# Cluster C Phase 10 Specs - Implemented Engine Ruleset Audit

## Intent

Perform a comprehensive documentation-only audit of the current pure engine ruleset against `docs/gwent-rules.md`, limited to behavior that is already implemented or currently playable through the catalog.

This phase exists because several recent fixes were not missing-feature issues; they were incorrect assumptions at the engine/catalog boundary. The goal is to find those issues before adding more rule effects.

## Hard Constraint: No Code Changes

Do not change implementation code.
Do not change tests.
Do not change catalog data.
Do not change UI, AI policy, simulation code, scripts, or config.

Allowed edits only:

- Create `audit/reports/2026-04-29-cCp10-report.md`.
- Update `docs/PROJECT_STATE.md` to record the audit outcome and recommended next step.

If you discover a clear bug, document it with evidence and a proposed fix/test plan. Do not implement it in this phase.

## Audit Method

For every audited rule area, produce a trace-driven finding or conformance note. Do not rely on "seems covered" unless you point to a test or exact implementation path.

For each area:

1. Cite the rule section from `docs/gwent-rules.md`.
2. Cite the relevant implementation file/function.
3. Cite existing test coverage, if any.
4. State one of:
   - `Conformant`
   - `Likely conformant, under-tested`
   - `Divergent / bug`
   - `Ambiguous rule, project decision needed`
   - `Intentionally deferred`
5. If not fully conformant, include:
   - severity (`P0`, `P1`, `P2`, `P3`);
   - exact scenario trace;
   - expected behavior;
   - observed or likely behavior;
   - proposed test coverage;
   - proposed implementation direction for a later spec.

Severity guide:

- `P0`: corrupts match outcome, breaks command transactions, leaks hidden information in normal play, or can crash/lock a match.
- `P1`: common legal play resolves incorrectly, wrong discard/owner/score/game-end behavior, or official starter deck rule path is materially wrong.
- `P2`: edge-case legal play wrong or under-tested, but unlikely in current starters.
- `P3`: documentation mismatch, naming/count issue, weak test coverage, or future-risk note.

## Required Audit Coverage

### 1. Setup, Identity, And Zones

Trace:

- `startMatch` / setup creates instance IDs distinct from source IDs.
- Main deck, hand, discard, side deck, board rows, weather, removed-from-game zones are initialized correctly.
- Owners/controllers are set correctly for normal units, spies, side-deck replacements, and revived cards.
- Official starter presets produce valid runtime state.

Questions to answer:

- Can source ID duplication or duplicate art paths affect runtime identity?
- Are side-deck-only cards excluded from main decks and still available to engine side decks?
- Are custom/catalog merged sources at risk of source ID collision in engine setup?

### 2. Legal Moves Vs Commands

Audit `legalMoves.ts` against `commands.ts`.

For each implemented command path, verify:

- Legal move exists only when the command can execute.
- Command rejects illegal or stale actions.
- Legal target payload matches command payload exactly enough for UI/AI to dispatch without inventing rules.

Include at least:

- mulligan select/confirm;
- pass;
- normal unit play;
- Agile row choice;
- Spy placement;
- weather cards;
- Clear Weather;
- Commander's Horn row target;
- Decoy target;
- Medic prompt option;
- Mardroeme row target;
- Scorch special;
- Scorch-close unit ability;
- leader Clear Weather;
- `ResolveRoundEnd`.

### 3. Scoring And Modifiers

Audit against `docs/gwent-rules.md` sections 10, 13, 14, 15, and 17.1.

Required traces:

- Weather sets applicable non-Hero units to 1.
- Skellige Storm affects ranged and siege rows.
- Heroes ignore weather, Horn, Morale Boost, and Scorch targeting.
- Tight Bond uses correct ally grouping.
- Morale Boost excludes itself and ignores Heroes.
- Unit Horn and Special Horn obey "only one horn effect per row".
- Modifier order is weather -> tight bond -> morale -> horn.
- Scorch uses current effective strength after modifiers.

Call out any mismatch between project assumptions and `docs/gwent-rules.md`, especially Tight Bond same-name grouping across rows vs row-local behavior.

### 4. Spy, Discard Ownership, And Control

Required traces:

- Playing a Spy places it on the opponent board side but keeps draw/control behavior for the acting player.
- Medic reviving a Spy places it on the opponent board side and draws for the reviving player.
- Round cleanup sends row cards to the discard pile for the side they currently occupy.
- Scorch sends row cards to the discard pile for the side they currently occupy.
- A Spy on opponent board goes to opponent discard on cleanup/Scorch.
- Decoy target rules for Spies match the project rule decision in `docs/gwent-rules.md` or are flagged as ambiguous.

This is a priority section. Recent bugs occurred here.

### 5. Medic And Prompt Chains

Required traces:

- Medic targets own discard only.
- Medic excludes Heroes.
- Medic with no legal targets still plays.
- Medic revives Medic and chains prompts if eligible.
- Medic revives Spy, Muster, Morale, Tight Bond, Horn, Berserker.
- Pending prompt blocks unrelated commands until resolved.
- Prompt options are legal-move-backed and cannot target hidden/illegal cards.
- Prompt ownership is enforced.

### 6. Muster

Required traces:

- Muster pulls all linked/specified cards from hand and deck.
- Muster does not pull from discard.
- Muster does not move already-boarded copies.
- Muster shuffles deck when pulling from deck.
- Muster uses explicit `linkedSourceIds` rather than name guessing where needed.
- Official Monsters starter groups work:
  - Crones;
  - Vampires;
  - Arachas / Arachas Behemoth;
  - Nekkers;
  - Ghouls.
- Official Scoia'tael groups work:
  - Havekar Smuggler;
  - Dwarven Skirmisher;
  - Elven Skirmisher.
- `muster_roach` behavior is either implemented, intentionally normalized, or accurately flagged as a risk.

This is a priority section. Recent bugs occurred here.

### 7. Scorch

Required traces:

- Special Scorch affects the whole battlefield.
- Special Scorch destroys all tied highest-strength non-Hero units, not just one.
- Special Scorch discards itself afterward.
- Heroes are skipped; next-highest non-Hero is chosen if highest unit is Hero.
- Scorch-close unit ability only checks the opposite row and only if opponent's opposite row total is at least 10.
- Clan Dimun Pirate behavior is correct if its catalog ability is implemented as whole-board Scorch and self-protection; if not, flag exact status.
- Scorch discard routing follows board side, including Spies.
- Scorch uses effective strength after weather/bond/morale/horn.

### 8. Decoy

Required traces:

- Decoy targets only non-Hero units on the acting player's side.
- Decoy returns target to the acting player's hand.
- Decoy occupies the row with strength 0 or the engine's equivalent representation.
- Decoyed unit can replay and retrigger on-play abilities.
- Decoy cannot target special row cards, weather, Heroes, or opponent-side cards unless project rules intentionally allow a Spy-on-own-side case.
- Decoy with Mardroeme/Berserker after placement settles correctly.

### 9. Mardroeme And Berserker

Audit cCp9 behavior.

Required traces:

- Special Mardroeme has legal own-row targets.
- Unit/hero Mardroeme settles the row on placement.
- Existing Berserker transforms when Mardroeme lands.
- New Berserker transforms when entering a row that already has Mardroeme.
- Multiple Berserkers transform deterministically.
- Berserker is removed from game, not discarded.
- Replacement comes from controlling seat's side deck using `linkedSourceIds[0]`.
- Missing link/replacement is explicit and non-crashing.
- Replacement lands on same board side and row.
- Replacement participates in later Scorch/round cleanup/Skellige return correctly.
- No hidden-info read/write occurs during settlement.

### 10. Weather And Clear Weather

Required traces:

- Weather cards enter shared weather zone.
- Multiple weather cards can coexist.
- Clear Weather removes all active weather, including Skellige Storm.
- Clear Weather discards itself.
- Clear Weather with no active weather is legal/illegal according to current project decision; flag if unclear.
- Leader Clear Weather uses the same engine behavior as card Clear Weather where appropriate.

### 11. Round Resolution And Game End

Required traces:

- Round ends only when both players have passed.
- `ResolveRoundEnd` is idempotent or protected against double decrement.
- Lower score loses one gem.
- Draw causes both players to lose one gem unless Nilfgaard draw-win applies.
- Nilfgaard vs Nilfgaard draw handling is documented or flagged as ambiguous.
- Both players at 1 gem in a true draw ends in game draw.
- Single winner game score increments correctly, and draw game score does not.
- Winner starts next round.
- Board cleanup discards to the correct side.
- Weather cleanup and non-row special cleanup are correct.
- Round history records enough data for UI and audit.

This is a priority section because previous R-008/F-5.19 work found game-end/round-end hazards.

### 12. Faction Passives

Audit all implemented faction passives:

- Monsters:
  - exactly one non-Hero unit can persist;
  - Heroes cannot persist;
  - no unit means none persists;
  - kept unit loses external row effects after cleanup;
  - deterministic RNG is used and replayable.
- Nilfgaard:
  - wins tied rounds against non-Nilfgaard;
  - Nilfgaard vs Nilfgaard tie behavior is documented or flagged.
- Northern Realms:
  - draws on round win;
  - empty deck behavior is safe.
- Scoia'tael:
  - if implemented, start-player choice matches rule;
  - if not implemented, classify clearly as deferred/bug depending on current catalog exposure.
- Skellige:
  - round-three return selects up to two random non-Hero units from discard;
  - returns to legal rows;
  - returned abilities fire or do not fire according to current project decision;
  - returned Spy handling is documented or flagged;
  - returned cards interact with active Mardroeme.

### 13. Catalog Rule Data Audit

Audit current playable catalog data for implemented-rule correctness:

- Every implemented ability on current cards has an engine path.
- Every current official starter card with `muster` has correct `linkedSourceIds`.
- Every Berserker has `linkedSourceIds[0]` and a matching side-deck replacement in relevant presets.
- `side_deck_only` cards are not in main decks.
- Deck limits match official physical-copy representation where known from the local staging/manifest corrections.
- Rows are plausible for promoted official cards; explicitly spot-check cards recently corrected:
  - Dwarven Skirmisher;
  - Heavy Zerrikanian Fire Scorpion;
  - Menno Coehoorn;
  - Elven Skirmisher;
  - Skellige Berserker/Vildkaarl split cards.
- `officialPromotionManifest` counts align with current catalog.

If the audit cannot prove an official row/ability from local sources, list it as "needs source confirmation" rather than silently accepting scrape data.

### 14. Test Coverage Inventory

Inventory existing tests relevant to implemented rules.

Required output:

- table of implemented rule areas vs test files;
- list of high-value missing tests;
- list of skipped/todo tests that overlap this audit;
- list of existing tests that appear too shallow or are testing implementation details rather than rules.

Do not add tests in this phase.

### 15. Hidden Information And Determinism

Audit only as it relates to engine rules:

- Engine events/logs used by UI/AI should not leak opponent hand/deck identities into default human-facing surfaces.
- Legal moves for a seat should include only that seat's legal private information plus public board state.
- RNG-dependent rules should be seeded/deterministic under replay:
  - shuffle;
  - Monsters carryover;
  - Skellige return;
  - any deck-sourced Muster shuffle.
