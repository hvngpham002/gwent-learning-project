## Rule Semantics For cCp21

### Eligible Cards

The leader affects only current battlefield cards that satisfy all of these:

- the card occupies the acting seat's **own board side**;
- the catalog source is a non-hero `unit`;
- the catalog source has the `agile` ability;
- the catalog source has at least two legal board rows;
- the destination row being evaluated is legal for that card.

Do not affect:

- heroes, even if a future hero source has `agile` (Hero immunity);
- opponent-board-side cards;
- Spies occupying the opponent board side, even if their controller or owner is
  the acting seat;
- hand, deck, discard, removed, weather, horn, or side-deck cards.

Add a focused invariant or test-local fixture if useful to make the
opponent-board-side / hero-exclusion behavior explicit. Current official
catalog data is expected to have no `spy + agile` production card, but the
engine should still define the boundary.

### One Common Destination Row

This ability does **not** independently optimize every Agile card. It chooses
one destination row and moves every eligible Agile unit to that same row.

Compute candidate destination rows as the intersection of the eligible units'
legal source rows. For the current official catalog, this should normally be
`close` and `ranged`. Do not hard-code that assumption; use source rows.

A candidate row is executable only if at least one eligible card would actually
move to that row. This prevents consuming the leader on a pure no-op.

Score all candidate rows before filtering for executable movement. If the
highest-scoring row is a no-op and every row that would move cards scores
strictly lower, emit no legal move. Moving to a worse row must not be offered
just because it is the only row that changes board state.

### Strength Evaluation

For each executable candidate row:

1. Simulate moving every eligible Agile unit to that row.
2. Run the central `calculateScores` pipeline against the simulated state with
   the current `catalogCards` and `catalogLeaders`.
3. Compare `breakdown.totalBySeat[actingSeatId]`.

The helper must use the central scoring pipeline so weather, King Bran,
row-horn passives, double-spies, Tight Bond, Morale Boost, physical Horn, and
future scoring policies are all observed consistently.

Do not add one-off strength calculations.

### Auto vs Choice

If there is exactly one best executable row:

- legal moves should expose one `use_leader` move with `target.kind === "none"`;
- command execution should recompute the same plan and move to the unique best
  row.

If multiple executable rows tie for the best score:

- legal moves should expose one `use_leader` move per tied best row;
- each tied move should use `target.kind === "board_row"` with
  `seat === actingSeatId` and the tied destination row;
- the existing cEp8 leader-choice UI should be able to render these moves from
  their `metadata.targetLabel`; do not add new UI layout in cCp21;
- command execution should accept only a tied best row target and reject any
  non-best or non-acting-seat board-row target.

If no executable candidate exists:

- `getLegalMoves` emits no `use_leader` move;
- manual `UseLeader` attempts continue to raise a structured rule error;
- `leaderUsed` remains false.

### Mutation And Event Contract

When the command succeeds:

- clone state; never mutate the input state;
- emit `ability_triggered` for the leader;
- move each affected card in deterministic board order:
  `close -> ranged -> siege`, preserving unit order within each row;
- append moved cards to the destination row using the existing `moveCard`
  helper pattern;
- use new `card_moved.reason === "leader_optimize_agile"`;
- emit `ability_resolved` with outcome `"moved"` after movements;
- set `seat.leaderUsed = true`;
- emit `leader_used`;
- hand off the turn through the existing turn-handoff helper.

If the selected destination row is already occupied by some of the eligible
cards, those cards do not need a `card_moved` event; only cards whose row
changes should move.

## Required Implementation Work

### 1. Pure Planning Helper

Add a focused pure helper module, recommended path:

```text
src/game/core/leaderOptimizeAgile.ts
```

The exact exported type names may vary, but the helper should expose one
deterministic planning function similar to:

```ts
export interface OptimizeAgileRowsCandidate {
  row: CatalogRow;
  score: number;
  movedCardIds: readonly CardInstanceId[];
}

export interface OptimizeAgileRowsPlan {
  outcome: "no_eligible" | "no_candidate_row" | "no_executable_row" | "auto" | "choice";
  currentScore: number;
  bestScore?: number;
  eligibleCardIds: readonly CardInstanceId[];
  candidates: readonly OptimizeAgileRowsCandidate[];
  bestCandidates: readonly OptimizeAgileRowsCandidate[];
}

export function planOptimizeAgileRows(input: {
  state: MatchState;
  seatId: SeatId;
  catalogCards: readonly CatalogCardSource[];
  catalogLeaders: readonly CatalogLeaderSource[];
}): OptimizeAgileRowsPlan
```

Requirements:

- pure and deterministic;
- no hidden-info reads beyond public board state;
- no mutation of `state`;
- uses `calculateScores`;
- exports through `src/game/core/index.ts` if current public-export patterns
  require it for tests.

Recommended row order for ties and deterministic output:

```text
close -> ranged -> siege
```

Tie handling:

- `outcome: "auto"` when exactly one best executable candidate exists;
- `outcome: "choice"` when more than one best executable candidate exists;
- `bestCandidates` should contain only executable candidates that move at least
  one card **and** tie the highest score across all candidate rows, including
  no-op rows.

### 4. Command Execution

Extend `executeLeader` in:

```text
src/game/core/commands.ts
```

Use the same planning helper as legal moves.

Acceptance requirements:

- reject if the helper says no eligible / no executable plan;
- for `outcome: "auto"`, accept only no target or `target.kind === "none"`;
- for `outcome: "choice"`, require `target.kind === "board_row"`, acting-seat
  target seat, and a row contained in `bestCandidates`;
- reject board-row targets that are not tied best rows;
- reject targets for another seat;
- never consume the leader on rejection;
- successful command moves all eligible cards to the selected row, emits the
  event contract above, sets `leaderUsed`, and hands off the turn.

represented directly by multiple legal `use_leader` moves, matching cEp8's
existing menu contract.
