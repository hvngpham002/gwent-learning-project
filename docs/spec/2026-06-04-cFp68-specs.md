# Cluster F Phase 68 Specs - Valid-Root-Only Determinized Probe Contract

Date: 2026-06-04
Branch: `codex/cFp68-valid-root-only-determinized-probe-contract`
Base: `dev`

## Summary

cFp67 classified the remaining post-cFp66 sampler invalid roots and recommended proceeding toward search-readiness probes only through an explicit valid-root-only contract:

- Current starter matrix: 4,042 total roots, 3,979 valid, 63 invalid, 1.559% invalid.
- Robust starter matrix: 32,487 total roots, 32,147 valid, 340 invalid, 1.047% invalid.
- Every remaining invalid root is `candidate_valid_root_only_skip`.
- No remaining invalid root is `candidate_deeper_reconstruction`.
- Remaining invalid roots must not be silently dropped and must not be scored as wins, losses, draws, sampled failures, policy failures, or engine failures.

cFp68 should implement the contract layer that future determinized probes must consume. It should create deterministic, hidden-info-safe artifacts that split every sampler root into exactly one of:

1. `eligible_valid_root`; or
2. `skipped_invalid_root`.

cFp68 is still not search gameplay. It must not run PIMC, ISMCTS, MCTS, rollouts, action evaluation, action ranking, or search move selection.

## Problem Statement

The project now has enough sampler infrastructure to start search probes on valid roots, but a search probe without explicit skip accounting would be misleading. If invalid sampler roots are silently excluded, every downstream result becomes hard to interpret.

cFp68 should make the root eligibility boundary a first-class artifact:

- valid sampler roots are eligible for future determinized probe work;
- invalid sampler roots are explicitly skipped;
- skip counts and percentages are reported beside every contract summary;
- skipped roots keep enough public scalar dimensions for analysis;
- future probes can fail fast if they do not account for skipped roots.

This phase should provide the plumbing and contract, not the search algorithm.

## Contract Record Requirements

Every cFp61 sampler-materialization root must map to exactly one cFp68 contract record.

Eligible records must come only from cFp61 roots where:

- `materializationStatus === "valid"`;
- `priorStatus === "prior_available"`;
- `sampleCountRequested > 0`;
- `sampleCountGenerated === sampleCountRequested`;
- `sampleCountValid === sampleCountRequested`;
- `sampleCountInvalid === 0`;
- `invalidReasonCounts` is empty.

## Source Consistency Rules

The builder must fail or mark the contract invalid if:

- a cFp61 valid root appears in `skipped-roots.jsonl`;
- a cFp61 invalid root appears in `eligible-roots.jsonl`;
- a cFp61 invalid root has no matching cFp67 casebook record;
- a cFp67 casebook record has no matching cFp61 invalid root;
- duplicate cFp61 root keys are detected;
- duplicate cFp67 casebook root keys are detected;
- eligible-root sample counts are not internally valid;
- hidden-info scanner detects forbidden payloads.

If the implementation chooses to emit mismatch counts instead of throwing, the report must clearly mark the contract as not probe-ready. Committed current/robust artifacts should be probe-ready.

## Future Probe Contract

cFp68 should define, but not execute, the future probe contract:

- A future determinized probe may read only `eligible-roots.jsonl` as the root list.
- It must also read `skipped-roots.jsonl` and include skip counters in every result.
- It must not report result tables without skipped-root count and percentage.
- It must not score skipped roots as wins, losses, draws, policy failures, engine failures, sampled failures, or no-op results.
- It must fail fast if `skipped-roots.jsonl` is missing for a suite with skipped roots.
- It must fail fast if eligible/skipped counts do not sum to the cFp61 materialization root count.
