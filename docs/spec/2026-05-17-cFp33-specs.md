# cFp33 Specs - Legal-Heuristic-v1 Scoia'tael First-Turn Choice Strategy

## Summary

cCp32.1/cCp32.2 moved the Scoia'tael faction passive to the correct timing: after both mulligans complete, exactly one Scoia'tael seat chooses who starts round 1. The current AI behavior is intentionally safe but strategically inert: both `legal-heuristic-v0` and `legal-heuristic-v1` choose `scoiatael-first-player:self` for AI-owned prompts.

cFp33 makes **legal-heuristic-v1 only** choose between `go first` and `opponent goes first` using its post-mulligan hand shape. The goal is a simple, deterministic, hidden-info-safe first-turn heuristic, not a full faction expert. `legal-heuristic-v0` remains the stable fallback and should keep its current deterministic `self` behavior.

## Goals

1. Teach `legal-heuristic-v1` to make a deterministic Scoia'tael first-player choice after mulligan.
2. Base the decision only on legal prompt moves, the AI's own hand summary, and public state already present in `SeatObservation`.
3. Prefer **go first** for proactive hands: Spy opener, strong tempo opener, or Muster/thinning opener.
4. Prefer **opponent goes first** for reactive hands: Scorch/weather-heavy hands with weak proactive tempo, or hands that benefit from seeing the opponent commit first.
5. Emit hidden-info-safe diagnostics explaining the decision using counts, buckets, and enum reason kinds only.
6. Update AI Lab/product metadata and policy docs so `/ai-lab` stays current.

## Non-Goals

- Do not change engine rules, legal-move generation, prompt timing, cCp32.1/cCp32.2 command flow, or Scoia'tael mirror behavior.
- Do not change `legal-heuristic-v0`.

- Do not expose AI hand card names, source IDs, instance IDs, or raw ability arrays in product diagnostics.
- Do not add ML/search/self-play.
- Do not regenerate broader benchmark artifacts unless the spec's required checks explicitly call for them or the implementation changes benchmark-visible v1 behavior. If regenerated, record exact totals and hashes in the report.

### 2. Implement v1 first-turn choice helper

File: `src/game/ai/legalHeuristicPolicyV1.ts`

Replace the current unconditional v1 branch:

```ts
if (abilityId === "scoiatael_choose_first") {
  return moves.find((move) => move.optionId === "scoiatael-first-player:self") ?? moves[0] ?? null;
}
```

with a small helper that returns both the selected move and the analysis:

```ts
export const buildScoiataelFirstTurnChoiceDecision = (
  features: LegalHeuristicV1Features,
): {
  readonly selectedMove: ChoosePromptOptionMove | null;
  readonly analysis: AiDecisionScoiataelFirstTurnAnalysis | null;
};
```

Use the existing `features.promptMoves`, `features.observation.ownHand`, and `features.observation.pendingPrompt`.

The helper should:

1. Confirm the pending prompt / prompt moves are for `abilityId === "scoiatael_choose_first"`.
2. Find the legal self option by `optionId === "scoiatael-first-player:self"`.
3. Find the legal opponent option by `optionId === "scoiatael-first-player:opponent"`.
4. If only one of those exists, select it and set `reasonKind: "only_legal_option"`.
5. Otherwise compute aggregate hand features from `features.observation.ownHand`.

Ability IDs to inspect:

- Spy: `"spy"`
- Muster/thinning: `"muster"` and `"muster_roach"`
- Medic: `"medic"`
- Weather: `"frost"`, `"fog"`, `"rain"`, `"skellige_storm"`
- Scorch/reactive removal: `"scorch"`, `"scorch_close"`, `"scorch_range"`, `"scorch_siege"`
- Decoy: `"decoy"`
- Commander's Horn: `"commanders_horn"`

Use `card.kind`, `card.printedStrength`, and `card.abilities` from `SeatCardSummary`. These are AI-own-hand summaries and are valid for policy logic, but the exported diagnostics must reduce them to counts/buckets only.

Recommended tempo buckets:

- `"none"`: no proactive unit/hero opener.
- `"low"`: best proactive printed strength `1-4`.
- `"medium"`: `5-7`.
- `"high"`: `8+`.

Suggested scoring:

```ts
let initiativeScore = 10; // default go-first bias
let reactionScore = 0;

if (spyCount > 0) initiativeScore += 35;
if (musterCount > 0) initiativeScore += 25;
if (bestOpeningStrength >= 8) initiativeScore += 25;
else if (bestOpeningStrength >= 5) initiativeScore += 12;
if (hornCount > 0 && proactiveUnitOrHeroCount >= 3) initiativeScore += 8;

if (scorchCount > 0) reactionScore += 28;
if (weatherCount >= 2) reactionScore += 24;
else if (weatherCount === 1) reactionScore += 10;
if (decoyCount > 0 && spyCount === 0) reactionScore += 8;
if (medicCount > 0) reactionScore += 6; // early Medic is usually worse before discard exists
if (bestOpeningStrength <= 4 && reactiveSpecialCount >= 2) reactionScore += 18;
```

Decision threshold:

```ts
const chooseOpponent = reactionScore >= initiativeScore + 12;
```

Tie/default must choose `self`, not opponent. This keeps the fallback stable and avoids over-reactive behavior.

Recommended reason selection:

- `only_legal_option` if one option is missing.
- `spy_or_card_advantage_opener` if `spyCount > 0` and choosing self.
- `muster_or_thinning_opener` if `musterCount > 0` and choosing self.
- `strong_tempo_opener` if best opening tempo is high and choosing self.
- `reactive_weather_or_scorch` if choosing opponent and `scorchCount > 0 || weatherCount > 0`.
- `weak_proactive_reactive_hand` if choosing opponent because low proactive tempo plus reactive density.
- `default_go_first` otherwise.

Keep the helper pure and export it for tests and explanation parity.
