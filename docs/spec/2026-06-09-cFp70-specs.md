Date: 2026-06-09

## Summary

cFp69 proved the first benchmark-only `determinized-pimc-probe-v0`
scaffold over cFp68 eligible roots. It re-observed benchmark roots, collapsed
legal moves into public action buckets, carried cFp68 skipped roots into
probe accounting, and wrote deterministic hidden-info-safe artifacts without
rollouts, values, ranking, move selection, or product AI behavior.

cFp70 should add the first sampled-world action-availability probe over those
same cFp68/cFp69 eligible roots. The probe should materialize the existing
cFp61 hidden opponent hand/deck source-multiset samples in memory, rebuild
sampled-world root legal moves in memory, collapse those sampled legal moves
into the same public action abstraction used by cFp69, and report whether the
cFp69 root public action buckets remain available across sampled worlds.

This is still not search gameplay. It is a legality/availability stability
probe before any rollout, value estimate, action ranking, or move
recommendation.

## Why This Phase Exists

The project is now moving from heuristic tuning toward hidden-information
search infrastructure. The immediate risk is not weak play; it is accidentally
building a search path that:

- peeks at hidden information;
- treats invalid sampler roots as silently dropped rows;
- uses sampled worlds inconsistently;
- serializes private hidden card identities;
- or claims strength before the action space is stable under determinization.

cFp70 should answer this narrow question:

> When the opponent's hidden hand/deck is replaced by each valid sampled
> source multiset, do the root's public action buckets remain available?

If every cFp69 public action bucket remains available across every sample,
that is good evidence that the current root legal move surface is stable under
the sampler. If some buckets disappear or new buckets appear under samples,
that is a search-readiness finding to study before any rollout/value layer.

## Scope

Implement a benchmark-only artifact generator that:

1. reads committed cFp68 eligible/skipped contract artifacts;
2. reads committed cFp69 public-action scaffold artifacts;
3. re-runs the matching benchmark suite through the root observer;
4. regenerates cFp61-style hidden multiset samples in memory for each root;
5. filters probe work to cFp68 eligible roots only;
6. builds sampled-world legal move surfaces in memory for each valid sample;
7. collapses sampled legal moves into hidden-info-safe public action buckets;
8. compares sampled public action buckets against the cFp69 root buckets;
9. reports scalar availability/agreement/disagreement counts;
10. carries cFp68/cFp69 skipped-root accounting beside every summary; and
11. writes deterministic hidden-info-safe artifacts.

The implementation must not change game behavior, benchmark match records,
policy selection, UI behavior, product AI behavior, deck data, rules, legal
move generation, rating formulas, or existing cFp68/cFp69 artifacts.

## Sampled-World Construction Contract

cFp70 may create probe-only sampled root states in memory. The intended
strategy is:

1. Clone the root `MatchState`.
2. Identify the acting `seatId` and opponent seat.
3. Use the same sampler accounting path as cFp61/cFp68 to regenerate
   `MaterializedHiddenMultisetSample[]` for the root.
4. For each valid sample:
   - preserve public zones exactly;
   - preserve acting-seat private zones exactly;
   - preserve card instance count and zone shape for the opponent hidden hand
     and deck;
   - replace only the opponent hidden hand/deck card instances' `sourceId`
     values in the clone to match the sampled `handSourceCounts` and
     `deckSourceCounts`;
   - do not mutate the original benchmark state;
   - do not execute commands;
   - do not advance RNG;
   - do not run policy selection.
5. Run `getLegalMoves` for the same root acting seat on the sampled clone.
6. Collapse those legal moves through the same cFp60 public action abstraction
   used by cFp69.
7. Compare sampled public action bucket keys to the original cFp69 root action
   bucket keys.

If the implementation finds that exact clone/source remapping is unsafe or too
large for this phase, it may implement a conservative `exact_state_rebuild_deferred`
status for affected roots. That status must be reported explicitly with counts
and must not be hidden as success.

Do not include raw move IDs, card instance IDs, source IDs, card names, option

The implementation may add a stable hash of this public bucket key if useful.
If so, the hash input must be limited to the public fields listed above, and
the raw private input must never be serialized.

## Availability Status Semantics

For each root:

- `allRootActionsAvailableInAllSamples` is true only if every cFp69 root
  public action bucket appears in every checked sample's public action set.
- `rootActionBucketsMissingInAnySample` counts unique cFp69 root public action
  buckets absent from at least one checked sample.
- `sampleActionBucketsExtraInAnySample` counts unique sampled public action
  buckets that were absent from the cFp69 root public action set.
- `availabilityDisagreementCount` should be the sum of missing plus extra
  unique bucket counts, unless the implementation chooses a more conservative
  documented formula.
- `availabilityDisagreementBucket` must be one of:
  - `none`
  - `one`
  - `two_to_three`
  - `four_plus`
- `availabilityRiskBucket` must be one of:
  - `none`
  - `low`
  - `medium`
  - `high`
  - `deferred`
  - `failed`

Suggested mapping:

- `none`: no missing or extra buckets.
- `low`: one disagreement bucket.
- `medium`: two to three disagreement buckets.
- `high`: four or more disagreement buckets.
- `deferred`: exact state rebuild was deferred.
- `failed`: sample/legal/public-action processing failed.

## Hidden-Info Safety Rules

Forbidden in cFp70 artifacts, reports, diagnostics, and decision notes:

- raw `cardsById`
- `finalState`
- `commandLog`
- `eventLog`
- `ownHand`
- `opponentHand`
- `handSourceCounts`
- `deckSourceCounts`
- `sampledHand`
- `sampledDeck`
- `sampledWorld`
- `hiddenHand`
- `hiddenDeck`
- `sourceId`
- `sourceCardId`
- `cardId`
- `moveId`
- `actionRef`
- `rawMove`
- `rawLabel`
- runtime card instance prefixes like `seat_a:` / `seat_b:`
- card names from private hidden zones
- raw sampled source maps
- action value / ranking fields

The implementation should add a cFp70 artifact scanner and focused tests that
prove unsafe injected payloads are rejected.

Allowed:

- public action kind labels;
- public target kind/side/row labels;
- source class labels (`unit`, `hero`, `special`, `weather`, `leader`,
  `prompt`, `none`);
- strength buckets (`empty`, `weak`, `medium`, `strong`);
- option index labels like `option_index_0`;
- scalar counts;
- percentages;
- hashes of public-only bucket keys;
- root public fingerprints already present in cFp68/cFp69 artifacts.
