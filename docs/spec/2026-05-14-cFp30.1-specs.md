# cFp30.1 Specs - Legal-Heuristic-v1 Metadata Hygiene And AI Lab Sync

## Purpose

Clean up the source-of-truth metadata around `legal-heuristic-v1` after the
rapid cFp24-cFp30 tuning sequence. The executable policy is current through
cFp30, but product metadata and AI Lab copy still contain cFp24-era wording.

This phase is documentation/metadata/UI-readout hygiene only. It must not
change AI behavior.

## Context

`docs/PROJECT_STATE.md` correctly records cFp30 as the latest Cluster F
implementation:

- cFp27: mulligan diagnostics and conservative redraw scoring
- cFp28: hand-quality pass calibration
- cFp29: Medic timing calibration
- cFp30: weather-aware unit placement

However:

- `src/game/ai/productPolicies.ts` still describes `legal-heuristic-v1` as
  "Experimental deterministic heuristic baseline from cFp24."
- `/ai-lab` derives implementation status from the shared registry, but it
  does not expose the latest phase, latest docs/report paths, latest benchmark
  totals, or the cFp27-cFp30 capability chain.
- `docs/research/literature/ai/policies/legal-heuristic-v1.md` has a stale
  top-level date/framing even though later sections document cFp28-cFp30.

## Goals

1. Make the shared product policy registry the durable source of truth for the
   latest public metadata of playable policies.
2. Make `/ai-lab` show the current `legal-heuristic-v1 @ cFp30` status without
   duplicating stale strings.
3. Make the v1 policy doc's top section agree with the latest cFp30 state.
4. Add tests that fail if AI Lab or registry copy regresses to stale cFp24-era
   language.

## Non-Goals

- Do not tune `legal-heuristic-v1`.
- Do not change `legal-heuristic-v0`.
- Do not add `legal-heuristic-v1.1`, `v1.2`, or any new selectable policy ID.
- Do not update benchmark artifact contents.
- Do not run benchmarks unless needed for verification; cFp30 artifact totals
  are already current.
- Do not wire browser benchmark execution, ratings, search, training, Python
  tooling, or file writers into AI Lab.
- Do not change engine rules, legal moves, prompt behavior, UI match behavior,
  deck data, or catalog data.

## Required Implementation

### 1. Extend Product Policy Metadata

Update `src/game/ai/productPolicies.ts`.

Add stable metadata fields to `ProductAiPolicyMetadata`, sufficient for AI Lab
and pre-game copy to avoid hand-maintained cFp24 wording. Use readonly arrays
where appropriate.

Required fields:

- `latestPhase: string | null`
- `latestSpecPath: string | null`
- `latestReportPath: string | null`
- `latestPolicyDocPath: string | null`
- `latestBenchmarkSummaries: readonly { suiteId: string; label: string; result: string }[]`
- `capabilities: readonly string[]`

For `legal-heuristic-v0`:

- `latestPhase: null`
- `latestSpecPath: null`
- `latestReportPath: null`
- `latestPolicyDocPath: null`
- benchmark summaries may stay empty
- capabilities should describe stable deterministic legal play at a high level

For `legal-heuristic-v1`:

- `latestPhase: "cFp30"`
- `latestSpecPath: "docs/spec/2026-05-14-cFp30-specs.md"`
- `latestReportPath: "audit/reports/2026-05-14-cFp30-report.md"`
- `latestPolicyDocPath: "docs/research/literature/ai/policies/legal-heuristic-v1.md"`
- latest benchmark summaries:
  - `benchmark-v1-smoke-v1`: `9 win / 3 loss / 0 draw vs v0`
  - `benchmark-v1-starter-matrix-v1`: `96 win / 23 loss / 1 draw vs v0`
- capabilities must mention:
  - linked-card mulligan diagnostics
  - tie-aware and pass diagnostics
  - hand-quality pass calibration
  - Medic timing calibration
  - weather-aware unit placement

Update the v1 `description` so it does not say "from cFp24". It should make
clear that v1 is still one playable product policy ID, currently tuned through
cFp30.
