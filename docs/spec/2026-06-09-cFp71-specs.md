# Cluster F Phase 71 Specs - One-Ply Public Action Outcome Skeleton

Date: 2026-06-09
Branch: `codex/cFp71-one-ply-public-action-outcome-skeleton`
Base: `dev`

## Summary

cFp70 proved that the current sampled-world reconstruction path can regenerate
hidden opponent hand/deck source-multiset samples in memory and preserve the
root public action surface across every valid sampled world in both current and
robust starter suites. Every cFp68 eligible root completed, every cFp69 root
public action bucket remained available in every sampled world, and all skipped
invalid roots remained explicitly accounted for.

cFp71 should add the next benchmark-only scaffold: a one-ply public action
outcome skeleton. For each cFp68/cFp69/cFp70 eligible root, the probe should
execute deterministic representative concrete legal moves from each public
action bucket inside cloned sampled worlds, classify the resulting public
transition shape, and aggregate those shapes into hidden-info-safe scalar
records.

This is still not search gameplay. cFp71 must not rank actions, estimate
action values, estimate win probability, run rollouts, choose moves for a
policy, or expose a product AI.

## Why This Phase Exists

The project is now building toward hidden-information search without making
premature strength claims. cFp69 checked the public action surface at the true
root. cFp70 checked that those public actions stayed available under sampled
hidden worlds. cFp71 should check the next mechanical layer:

> Can each available public action bucket be executed for one ply inside each
> sampled world, and can its public transition shape be summarized without
> leaking hidden information or implying action quality?

This answers a search-readiness question, not a gameplay-strength question.
If one-ply execution is stable, cFp72 can decide whether to add a deeper
branching/budget probe or a casebook. If one-ply execution finds substantial
deferred/failure/divergence counts, cFp72 should be a repair/casebook phase.

## Scope

Implement a benchmark-only artifact generator that:

1. reads committed cFp68 eligible/skipped contract artifacts;
2. reads committed cFp69 public-action scaffold artifacts;
3. reads committed cFp70 sampled-world action-availability artifacts;
4. re-runs the matching benchmark suite through the root observer;
5. regenerates cFp61-style hidden multiset samples in memory for each cFp68
   eligible root;
6. rebuilds sampled root states in memory using the cFp70 sampled-state helper
   path;
7. collapses sampled legal moves into cFp60/cFp69/cFp70 public action buckets;
8. for each root public action bucket and each valid sampled world, selects a
   deterministic representative concrete legal move from the sampled bucket;
9. converts that move to an engine command using the existing
   `commandFromLegalMove` helper;
10. executes that command against the sampled cloned state with
    `executeCommand`;
11. classifies only the public transition shape;
12. aggregates root-level scalar counts and buckets;
13. carries skipped roots forward with cFp68/cFp69/cFp70 skip accounting; and
14. writes deterministic hidden-info-safe artifacts.

The implementation must not change game behavior, benchmark match records,
policy selection, UI behavior, product AI behavior, deck data, rules, legal
move generation, rating formulas, sampler behavior, or existing cFp68/cFp69/cFp70
artifacts.

## One-Ply Execution Contract

For each cFp68 eligible root:

1. Re-observe the benchmark root and verify it matches cFp68/cFp69/cFp70
   contract identity and public fingerprint.
2. Regenerate the valid materialized hidden multiset samples in memory.
3. Rebuild one sampled root state per valid sample using the cFp70 sampled-state
   rebuild path.
4. Compute sampled legal moves for the root acting seat.
5. Collapse sampled legal moves into public action buckets.
6. For each cFp69/cFp70 root public action bucket:
   - find sampled legal moves in the matching sampled bucket;
   - if no sampled move exists, count `sample_action_missing`;
   - otherwise pick one deterministic representative concrete move from that
     bucket for internal execution only;
   - convert that move to an engine command with `commandFromLegalMove`;
   - execute the command on the sampled cloned state with `executeCommand`;
   - classify the public transition shape from the transaction result;
   - discard the cloned post-command state and command payload.
7. Aggregate root-level counts across all public action/sample pairs.

Representative move selection must be deterministic and internal-only. It may
sort concrete moves by an internal stable key, but that key must never be
serialized if it includes card instance ids, source ids, labels, or command
payload details.

Do not execute commands against the original benchmark root state. Do not
advance benchmark RNG. Do not run policy selection. Do not mutate cFp68/cFp69
/cFp70 artifacts.

## Public Outcome Shape Semantics

The goal is a public transition skeleton, not value.

Allowed public outcome shape labels:

- `mulligan_selection`
- `prompt_resolution`
- `pass`
- `card_play`
- `leader_use`
- `round_end_resolution`
- `unknown_public_transition`

Allowed transition labels:

- `same_phase_same_round`
- `phase_changed_same_round`
- `round_advanced`
- `match_completed`
- `transition_unknown`

Allowed execution status labels:

- `completed`
- `sample_action_missing`
- `move_command_conversion_failed`
- `engine_command_rejected`
- `engine_command_exception`
- `sampled_world_rebuild_failed`
- `sampled_legal_move_generation_failed`
- `public_action_abstraction_failed`
- `outcome_classification_failed`
- `one_ply_execution_deferred`

Allowed divergence buckets:

- `none`
- `one`
- `two_to_three`
- `four_plus`
- `deferred`
- `failed`

Suggested semantics:

- `completed` means a representative sampled move was converted and the engine
  transaction applied without exception.
- `sample_action_missing` should be 0 if cFp70 stays valid.
- `engine_command_rejected` covers a transaction that returns a rejected status
  without throwing, if the engine exposes that shape.
- `engine_command_exception` covers thrown command execution.
- `one_ply_execution_deferred` is allowed only as a conservative fallback and
  must be counted honestly.
- `outcomeDivergenceCount` should count unique public transition shapes beyond
  the first observed shape for the same root/action bucket across samples.

Do not interpret divergence as good or bad action quality. It is only a
search-readiness signal that one public action can lead to different public
one-ply transition shapes under different hidden samples.

## Non-Claims

cFp71 does not choose actions.

cFp71 does not compare action quality.

## Recommended cFp72 Decision Rule

If cFp71 reports:

- zero or near-zero execution failures/deferred pairs;
- zero sample-action-missing pairs;
- source consistency ready;
- deterministic robust hashes;
- hidden-info scan clean;
- and a manageable divergence profile;

then cFp72 may add a benchmark-only casebook or budget probe over one-ply
public transition divergence.

If cFp71 reports substantial failures, deferred execution, sample-action
missing, contract drift, hidden-info scan issues, or artifact-size pressure,
cFp72 should be a repair/casebook phase before any deeper probe.

Do not jump directly to rollout/value/search-play policy from cFp71.
