# Implementation Spec: Cluster C, Phase 6 - Ability Resolver V1

## Goal

Add the first centralized ability resolver for the pure engine. Phase 5 made legal moves executable; Phase 6 should route on-play and prompt-based abilities through one deterministic resolver path instead of leaving `ability_deferred` as the normal outcome for current cards.

This phase should resolve state-changing abilities that can be implemented correctly without the future scoring pipeline. Score-dependent destructive abilities, especially Scorch, must remain explicitly deferred until scoring exists rather than being approximated.

## Architecture Position

The current core engine has:

- deterministic setup in `src/game/core/setup.ts`;
- normalized state and events in `src/game/core/types.ts`;
- legal move generation in `src/game/core/legalMoves.ts`;
- stateful command transactions in `src/game/core/commands.ts`;
- `ability_deferred` events for abilities that Phase 5 intentionally did not resolve.

Phase 6 should add a resolver layer used by command execution. The resolver must remain pure, deterministic, catalog-driven, and free of React/Redux/UI/AI dependencies.

## Scope

1. Add a resolver module.
   - Suggested file: `src/game/core/abilities.ts`.
   - Export public resolver types only if useful; keep low-level mutation helpers private when possible.
   - The resolver should be called from `commands.ts` after a card/leader action has been placed/executed and before turn handoff.
   - Keep it pure: no React, Redux, DOM, localStorage, timers, `Math.random()`, or direct UI/AI imports.

2. Refactor command turn lifecycle.
   - In Phase 5, `PlayCard` hands off the turn immediately after placement.
   - In Phase 6, turn handoff must happen only after all immediate ability work is complete.
   - If an ability opens a prompt, the turn must not hand off yet.
   - If an ability has no effect or completes synchronously, hand off normally.
   - This is the core engine fix for the class of legacy bugs where a player could pass or act while a modal ability was still unresolved.

3. Add pending prompt state.
   - Add a core state field such as `MatchState.pendingPrompt?: PendingPrompt | null`.
   - Upgrade `PendingPrompt` from string-only options to structured, serializable options if needed.
   - A prompt should include at least:
     - `promptId`;
     - `seatId`;
     - `kind`;
     - source `cardId` or leader ID where applicable;
     - `abilityId`;
     - structured options with stable `optionId`;
     - enough target metadata to execute the selected option without UI recalculation.
   - `EngineTransaction.prompt` may still mirror `state.pendingPrompt`, but authoritative pending prompt state should live in `MatchState`.

4. Implement prompt legal moves.
   - Update `getLegalMoves`:
     - if `state.pendingPrompt` exists, return only `choose_prompt_option` moves for the prompt seat;
     - the non-prompt seat receives no moves;
     - play/pass/leader/mulligan moves must be suppressed while a prompt is pending.
   - `choose_prompt_option` moves must not leak hidden opponent hand/deck information.
   - Include option labels/metadata sufficient for UI/AI adapters.

5. Implement `ChoosePromptOption`.
   - Update `EngineCommand` so `ChoosePromptOption` is executable in the stateful command path.
   - Include `seatId` in the command if needed for validation.
   - Validate that:
     - a prompt is pending;
     - the command seat matches the prompt seat;
     - the option exists;
     - the command cannot be used during ordinary play without a prompt.
   - Resolve the option, clear `state.pendingPrompt`, emit events, then continue resolver processing if the option causes another ability prompt.
   - If no further prompt remains, hand off the turn.

6. Add ability resolver events.
   - Keep events serializable.
   - Suggested additions:
     - `ability_triggered`;
     - `ability_resolved`;
     - `ability_deferred` with a `reason`;
     - `card_drawn`;
     - `prompt_opened`;
     - `prompt_resolved`;
     - `deck_shuffled`.
   - Preserve existing Phase 5 events unless there is a clear reason to rename them.
   - `ability_deferred.sourceId` must remain the catalog source ID; `cardId` remains the runtime instance ID.

7. Centralize draw helpers.
   - Add an internal helper for drawing from deck to hand.
   - It should:
     - draw up to the requested count;
     - move cards from deck to hand in deck order;
     - update each card zone;
     - emit `card_moved` and `card_drawn` events;
     - avoid revealing or serializing more deck order than the drawn cards.
   - Use this helper for Spy and any leader/card draw effects implemented in this phase.

8. Resolve Spy.
   - When a Spy is played:
     - the Spy should already be on the opponent board from Phase 5 placement;
     - keep `controller` as the acting seat;
     - draw up to 2 cards from the acting seat's deck into the acting seat's hand;
     - emit `ability_triggered`, draw/move events, and `ability_resolved`;
     - do not open a prompt;
     - hand off the turn after drawing.
   - Add tests for full deck, one-card deck, and empty-deck behavior.

9. Resolve Medic with prompts.
   - When a Medic unit is played:
     - find legal revive targets in the acting seat's discard pile;
     - targets must be non-Hero unit cards only;
     - exclude Specials, Weather, Leaders, Heroes, and non-unit placeholders;
     - include one prompt option per legal card placement row.
   - If no legal target exists:
     - emit `ability_triggered` and `ability_resolved` with a no-target outcome;
     - hand off the turn normally.
   - If legal targets exist:
     - open a prompt and keep `currentTurn` with the acting seat;
     - do not allow pass/play/leader while the prompt is pending;
     - resolving the prompt moves the selected discard card to the selected board row;
     - set the revived card's `controller` to the acting seat while preserving `owner`;
     - emit prompt and card movement events.
   - Chain behavior:
     - if the revived card also has `medic`, resolve its Medic ability too;
     - if that chained Medic has legal targets, open the next prompt;
     - if the revived card is not a Medic, stop the chain and hand off the turn;
     - prevent infinite loops by ensuring the just-revived card is no longer in discard before computing the next prompt.
   - This directly targets the legacy Medic skip/cancel/chaining findings.

10. Resolve Muster and Muster Roach for current catalog links.
   - Use catalog `linkedSourceIds` as the source of truth.
   - For a played card with `muster`:
     - find all acting-seat hand/deck cards whose `sourceId` is linked to the played card's source ID;
     - play all matching cards immediately;
     - remove each card from its actual source zone;
     - place each card on its catalog row when it has exactly one row;
     - if any matching card needs a row choice, defer that specific placement with a clear `ability_deferred` reason rather than guessing;
     - if any card was pulled from deck, shuffle the remaining deck with engine RNG and update `rng.state`.
   - For `muster_roach` on eligible Heroes:
     - use the hero's `linkedSourceIds` to find Roach or equivalent linked cards from the acting seat's hand/deck;
     - play linked cards immediately under the same single-row rule;
     - shuffle if deck-sourced cards were moved.
   - Do not pull from discard, side deck, removed, weather, board, or opponent zones.
   - Do not recursively re-trigger Muster from cards pulled by the same Muster group; collect and play the linked set once.

11. Classify ongoing modifier abilities as resolved-by-state.
   - These abilities do not need immediate state mutation after placement:
     - `tight_bond`;
     - `morale_boost`;
     - Unit `commanders_horn`;
     - `agile` after placement.
   - Do not keep emitting generic `ability_deferred` for these once the resolver exists.
   - Emit `ability_resolved` or a compact event indicating that the ability is represented by board state and will be scored later.
   - The future scoring pipeline will calculate their numeric effects.

12. Preserve existing immediate special behavior.
   - Phase 5 already executes:
     - Special Horn placement;
     - Decoy replacement;
     - Weather placement;
     - Clear Weather from card;
     - Clear Weather from leader.
   - Keep those behaviors working.
   - Route Clear Weather through the resolver if that makes the architecture cleaner, but do not regress:
     - card Clear Weather discards itself;
     - leader Clear Weather does not discard the leader;
     - active weather cards go to their controllers' discard piles.

13. Keep Scorch explicitly deferred until scoring.
   - Do not implement Special Scorch or Unit Scorch using printed strength only.
   - Rule-correct Scorch depends on current effective strength after weather, horn, morale, tight bond, and Hero immunity.
   - Until the scoring pipeline exists:
     - Special Scorch may continue to reject with `unsupported_command`, or may place/discard itself only if it emits `ability_deferred` with a `requires_scoring` reason and the report explains the tradeoff;
     - Unit `scorch_close` should emit `ability_deferred` with a `requires_scoring` reason after the unit lands.
   - Add tests that lock this deferral behavior so it cannot silently become a wrong implementation.

14. Add planned ability hooks without full implementation.
   - Add structured resolver entries or explicit deferrals for:
     - `summon`;
     - `avenger`;
     - `mardroeme`;
     - `berserker`;
     - non-Clear-Weather leader abilities.
   - Do not implement side-deck replacement or Berserker transformation unless it is trivial and fully tested.
   - If a discard hook is introduced, it must not make Decoy trigger Summon/Avenger, because Decoy returns to hand rather than discard.

15. Update legal move and command validation for prompts.
   - While a prompt is pending, ordinary commands should reject with a specific error such as `prompt_pending` or `illegal_command`.
   - `ChoosePromptOption` should be the only legal command for the prompt seat.
   - Hidden information rules still apply.

16. Preserve immutability and zone invariants.
   - Resolver execution must not mutate the input state.
   - Cards must not remain in multiple zones after Spy draw, Medic revive, Muster pull, prompt resolution, Clear Weather, or Decoy.
   - Use or extend the Phase 5 zone movement helpers rather than creating ad hoc array manipulation.

17. Add tests.
   - Add focused tests under `tests/game`.
   - Suggested file: `tests/game/coreAbilities.test.ts`.
   - Existing `coreCommands.test.ts` should remain useful; update it only where Phase 6 intentionally changes event behavior.

18. Create the required implementation report:
   - `audit/reports/2026-04-25-cCp6-report.md`

## Out Of Scope

- Do not implement the full scoring pipeline.
- Do not implement rule-correct Special Scorch or Unit Scorch destruction before scoring exists.
- Do not implement round winner, gem decrement, board cleanup, next round, game end, or faction passives.
- Do not migrate Redux, React UI, AI strategy, or live gameplay paths to the new engine.
- Do not add Card Studio or deck builder UI.
- Do not implement all official future cards.
- Do not approximate unknown target selection with hidden random behavior.

## Acceptance Criteria

- Core has a centralized ability resolver used by command execution.
- Turn handoff occurs after ability resolution, not before.
- Pending prompts are represented in core state and legal moves.
- `ChoosePromptOption` executes prompt choices and rejects invalid prompt usage.
- Spy draws up to 2 cards for the acting controller and preserves Spy controller ownership.
- Medic opens prompts for legal revive choices, resolves selected revives, supports Medic chains, and never allows pass/play during a pending prompt.
- Muster and Muster Roach use `linkedSourceIds`, move cards from hand/deck exactly once, remove deck-sourced cards from deck, and shuffle remaining deck deterministically.
- Ongoing modifier abilities are classified as state/scoring-resolved instead of generic unresolved effects.
- Scorch remains explicitly deferred with a `requires_scoring` reason, not silently no-oped or approximated.
- Clear Weather card and leader behavior still pass.
- Commands remain immutable.
- Zone invariants hold after all tested resolver flows.
- Events are serializable and ordered.
- `npm test` passes.
- `npm run build` passes.
- Existing live gameplay behavior is not intentionally changed.

## Required Tests

At minimum, cover:

- Spy draws two cards from the acting seat's deck after placement.
- Spy draws one card when only one deck card remains and zero when the deck is empty.
- Spy on opponent board keeps `controller` as the acting seat.
- Medic with no legal discard target completes and hands off turn.
- Medic with legal targets opens a pending prompt and suppresses ordinary play/pass/leader legal moves.
- `getLegalMoves` returns only `choose_prompt_option` for the prompt seat while a prompt is pending.
- `ChoosePromptOption` rejects wrong seat, missing prompt, and invalid option ID.
- Medic prompt resolution moves the selected non-Hero unit from discard to the selected row, updates controller, clears prompt, and hands off turn.
- Medic excludes Heroes, Specials, Weather, Leaders, and opponent discard cards.
- Medic chain opens a second prompt when a revived Medic has legal targets.
- Medic chain stops after a revived non-Medic card.
- Muster pulls linked cards from hand and deck, places them on their catalog single rows, removes deck-sourced cards from deck, and shuffles deterministically.
- Muster does not pull linked cards from discard, board, side deck, removed zone, or opponent zones.
- Muster Roach pulls linked Roach-style cards for current linked Hero catalog entries.
- Ongoing modifier abilities such as Tight Bond, Morale Boost, Unit Horn, and Agile no longer produce generic unresolved ability events.
- Unit Scorch Close remains deferred with a `requires_scoring` reason after placement.
- Special Scorch remains rejected or explicitly deferred according to the chosen policy, with no silent no-op.
- Clear Weather card and leader behavior from Phase 5 still pass.
- Resolver flows do not mutate the input `MatchState`.
- Resolver flows leave no duplicate card zones.
- No core file calls `Math.random`.

## Things To Watch Out For

- Do not reintroduce the legacy Medic modal bug in the pure engine. Pending prompts must block ordinary play/pass.
- Do not hand off the turn before a prompt chain is complete.
- Do not route discarded or cleared cards by physical board side. Use `controller`.
- Do not mutate input state while resolving chains.
- Do not let Muster duplicate deck cards. Moving from deck must remove the instance from deck.
- Do not recursively explode Muster groups. Collect the linked group once for the triggering ability.
- Do not make Scorch wrong just to make it executable. Its rule-correct target selection belongs after scoring.
- Keep prompt option IDs stable; they will become UI keys and AI/ML action IDs.
- Keep resolver events compact. They should support replay/debugging without dumping whole state.
- Do not wire this engine path into live UI yet.
