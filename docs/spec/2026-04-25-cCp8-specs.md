# Implementation Spec: Cluster C, Phase 8 - Round Resolution and Game End

## Goal

Add the pure engine transaction that settles a completed round after both seats have passed. Phase 7 made score calculation authoritative; Phase 8 should consume that scoring pipeline to determine round winner, decrement gems, apply round-end faction passives, sweep the battlefield, start the next round, or end the game.

This phase is the core fix for the legacy round/game-end bug class: game end must be derived only from post-resolution gem state inside the engine, never from component closures, timers, or pre-decrement guesses.

## Architecture Position

The current core engine has:

- normalized match state with ID-based zones;
- deterministic setup, mulligan, play, pass, prompt, ability, and Scorch transactions;
- a pure scoring pipeline with card-level score traces;
- `Pass` moving the match into `round_end` when both seats have passed.

Phase 8 should add an explicit stateful command to resolve the `round_end` phase. Keep the resolver pure and deterministic. Do not migrate React, Redux, UI timers, legacy AI, or localStorage.

## Scope

1. Add an explicit round-resolution command.
   - Add `ResolveRoundEnd` to `EngineCommand`.
   - Suggested shape:
     ```ts
     { type: "ResolveRoundEnd"; seatId?: SeatId }
     ```
   - The command should execute only when:
     - `state.phase === "round_end"`;
     - both seats have `passed === true`;
     - `state.pendingPrompt === null`;
     - the current logical round has not already been resolved.
   - `seatId` should be optional because this is an engine/system transition, not a player decision. If included by a caller, validate it is one of the seats but do not make winner logic depend on it.
   - Keep `Pass` behavior from Phase 5/6: the second pass changes `phase` to `round_end`; it should not directly decrement gems or sweep the board in this phase.

2. Add idempotency state.
   - Add enough state to prevent settling the same logical round twice.
   - Suggested fields on `MatchState`:
     - `roundStarter: SeatId`;
     - `roundHistory: RoundResult[]`;
     - `resolvedRoundIds: number[]` or `lastResolvedRound: number | null`.
   - `roundStarter` should be initialized in setup from the initial turn roll and updated whenever a new round starts.
   - A second `ResolveRoundEnd` for the same round should fail with a typed `EngineRuleError` or return a no-op transaction with a clear event. Prefer throwing `EngineRuleError("illegal_command" | "invalid_phase", ...)` so callers notice duplicate dispatch.
   - This directly targets audit finding `F-5.19`: duplicate end-round dispatch must not decrement gems twice or skip a round.

3. Define round result state.
   - Add serializable types suitable for replay, AI, and ML.
   - Suggested shape:
     ```ts
     interface RoundResult {
       round: number;
       scoreBySeat: Record<SeatId, number>;
       outcome: "seat_a_win" | "seat_b_win" | "draw";
       winner: SeatId | "draw";
       loserGemLoss: Partial<Record<SeatId, number>>;
       factionOutcome?: "nilfgaard_draw_win" | "normal";
       nextStarter?: SeatId;
     }
     ```
   - Store score totals from `calculateScores`, not a recomputed legacy helper.
   - Do not add legacy match-level `gameScore` unless an existing core need requires it. The engine winner is enough for this phase.

4. Determine the round winner from effective scores.
   - Use `calculateScores({ state, catalogCards, catalogLeaders })`.
   - If one seat has a higher total, that seat wins and the lower-scoring seat loses 1 gem.
   - If totals tie:
     - if exactly one seat's faction is `nilfgaard`, that seat wins by faction ability and the other seat loses 1 gem;
     - if both seats are Nilfgaard, the abilities cancel and the round remains a draw;
     - if neither seat is Nilfgaard, the round remains a draw.
   - On a true draw, both seats lose 1 gem.
   - Defensive gem policy: decrement with `Math.max(0, gems - loss)` and detect game end with `gems <= 0`, not exact equality.

5. Apply game end from post-decrement state only.
   - After gem loss, if either seat has `gems <= 0`, record a game-end outcome from that post-decrement state.
   - Winner rules:
     - if only one seat has no gems, the other seat wins the game;
     - if both seats have no gems, the game winner is `"draw"`.
   - Round cleanup should still run for a final round, but next-round passives should not.
   - After cleanup, set `state.phase = "game_end"` and emit `game_ended` with winner.
   - Do not start a new round after game end.
   - Do not dispatch or schedule `initializeNewGame`.
   - Do not use timers, `setTimeout`, UI flags, localStorage, or component-derived life checks.
   - Regression trace required: player at 1 gem beats opponent at 2 gems. The opponent drops to 1, the winning player remains at 1, `phase` continues to the next round, and no game-end event is emitted. This is the new-core guard against legacy `R-008`.

6. Handle simultaneous last-gem draw correctly.
   - Required trace: both seats start the round with 1 gem and the round is a true score draw with no Nilfgaard override.
   - Both seats drop to 0.
   - `state.phase` becomes `game_end`.
   - `game_ended.winner` is `"draw"`.
   - No seat receives a game win counter or equivalent side effect.
   - The report must explicitly say which branch executed and how this maps to `docs/gwent-rules.md` section 17.14.

7. Add round-start continuation when the game does not end.
   - Increment `state.round` by 1.
   - Set `state.phase = "playing"`.
   - Reset both seats' `passed` flags to `false`.
   - Clear `pendingPrompt`.
   - Set `currentTurn` and `roundStarter`:
     - winner starts the next round;
     - if true draw, use deterministic project policy: previous `roundStarter` starts again;
     - emit `turn_set` with reason `"round_winner"` or `"draw_policy"`.
   - Emit `round_started` or equivalent event after cleanup/passives.

8. Sweep battlefield cards to controller discard.
   - Move every non-kept battlefield card to its current `controller` discard pile.
   - Cleanup runs for both continuing rounds and final rounds.
   - If the game is ending, sweep all battlefield cards and skip next-round keeper/draw/return passives.
   - Battlefield cards include:
     - board row units and row placeholders;
     - row horn cards;
     - active weather cards.
   - This must preserve Spy ownership/controller semantics:
     - a Spy physically on the opponent side but controlled by the acting seat goes to the acting seat's discard pile.
   - This directly targets audit findings `F-5.5` and `F-5.12`.
   - Emit `card_moved` for every moved card with a round cleanup reason.
   - Add movement reasons as needed, such as:
     - `round_cleanup`;
     - `monsters_keep`;
     - `northern_realms_draw`;
     - `skellige_return`.

9. Implement Monsters round-end keeper.
   - If the game continues and a seat's faction is `monsters`, keep exactly one eligible card on that seat's board when the round is swept.
   - Eligible card policy:
     - source kind must be `unit`;
     - card must not be a Hero;
     - card must be physically on that Monsters seat's own board;
     - card `controller` must equal the Monsters seat, so opponent-controlled Spies on the Monsters side are not eligible.
   - If zero eligible cards exist, keep none.
   - If one eligible card exists, keep it.
   - If multiple eligible cards exist, choose one with the engine RNG and update `state.rng.state`.
   - All other battlefield cards, including Heroes, Specials, Weather, Horns, and non-kept Units, go to controller discard.
   - Kept units must lose external ongoing bonuses naturally because weather/horns/other cards are discarded. Do not mutate printed strength.
   - Emit a structured faction event that records eligible count and kept card ID, without exposing hidden deck order.

10. Implement Northern Realms draw-on-round-win.
    - If the game continues, and a seat's faction is `northern_realms` and that seat won the round, draw 1 card from that seat's deck into hand after gem loss is determined.
    - If the deck is empty, draw nothing and emit a no-card outcome event.
    - If the round is a true draw, Northern Realms does not draw.
    - If Nilfgaard wins a tied round by faction ability against Northern Realms, Northern Realms does not draw.
    - Use the same central draw helper behavior as Spy: move from top of deck to hand, update card zone, emit `card_moved` and `card_drawn`.

11. Implement Nilfgaard draw-win.
    - Apply during round winner determination, before gem loss.
    - Exactly one Nilfgaard seat converts a tied score into a win for that seat.
    - Both Nilfgaard seats in a tied score produce a true draw by project policy.
    - Emit a structured faction event for the Nilfgaard override.

12. Implement Skellige round-3 return.
    - At the start of round 3 only, after resolving round 2 and only if the game continues, each Skellige seat returns up to two random non-Hero Unit cards from its discard pile to its battlefield.
    - Use engine RNG, not `Math.random()`, and update `state.rng.state`.
    - Eligible cards:
      - source kind is `unit`;
      - not Hero;
      - currently in that seat's discard pile.
    - Placement policy:
      - if the catalog card has one row, place it there;
      - if the card is Agile or has multiple rows, use the first row in catalog row order for now and emit a diagnostic/faction event noting the deterministic row policy.
    - Do not trigger on-play abilities from Skellige returns in this phase. Emit `ability_deferred` with reason `skellige_return_on_play_pending` for returned cards with on-play abilities. This keeps round start deterministic and prevents unhandled prompts from opening during cleanup.
    - This policy must be documented in the report as a deliberate Phase 8 limit.

13. Leave Scoia'tael setup choice out of this phase.
    - Scoia'tael first-player choice belongs to setup/mulligan flow and likely needs a prompt.
    - Do not implement it inside round resolution.
    - If touched, only add a clear TODO/diagnostic in the report.

14. Add round/game events.
    - Keep events compact and serializable.
    - Suggested additions:
      - `round_resolved` with round number, score totals, winner, gem loss, and faction outcome;
      - `gems_changed` with before/after values and reason;
      - `board_swept` with moved count and kept card IDs;
      - `round_started` with round and starting seat;
      - `faction_ability_resolved` with faction, seat, ability, and outcome;
      - `game_ended` with winner.
    - Existing `round_ended` and `game_ended` may be reused if the type shape is expanded cleanly.
    - Event order should explain the transaction:
      1. score/round resolved;
      2. gems changed;
      3. board cleanup, including Monsters keeper only when the game continues;
      4. game ended if applicable, otherwise Northern Realms draw, next-round start, and Skellige round-3 return.

15. Add legal move support.
    - `getLegalMoves` should return a `resolve_round_end` legal move when:
      - `state.phase === "round_end"`;
      - both seats have passed;
      - no prompt is pending.
    - If the team prefers to keep system commands out of player legal moves, document that choice and add a helper such as `getSystemMoves` instead.
    - The command still must be validated in `commands.ts`; legal move generation is not a substitute for command validation.

16. Preserve immutability and zone invariants.
    - `ResolveRoundEnd` must not mutate input state.
    - A card must not remain in multiple zones after cleanup, faction passives, NR draw, or Skellige return.
    - Weather entries must be empty after cleanup.
    - Row horn slots must be empty after cleanup.
    - A Monsters kept unit must remain in exactly one board row.
    - Discard piles must receive cards by current controller, not physical board side.

17. Add tests.
    - Add focused tests under `tests/game`.
    - Suggested file: `tests/game/coreRoundResolution.test.ts`.
    - Use current catalog data where practical, but small purpose-built catalog fixtures are acceptable for Monsters/Skellige scenarios not represented by current presets.
    - Keep tests deterministic by using fixed seeds and avoiding `Math.random()`.

## Out Of Scope

## Acceptance Criteria

- `ResolveRoundEnd` exists and is the only new-core path that decrements gems.
- Round resolution uses `calculateScores`, not legacy helpers.
- Tied scores apply Nilfgaard draw-win correctly, including both-Nilfgaard cancellation.
- Lower-scoring loser loses 1 gem; true draw makes both seats lose 1 gem.
- Game end is derived only from post-decrement gem state.
- The R-008 regression trace passes: a 1-gem player who wins the round does not trigger game end or reset.
- Duplicate round-end resolution cannot decrement gems twice.
- Both-at-1 true draw produces `game_end` with winner `"draw"`.
- Winner starts the next round; true draw uses the deterministic previous-starter policy.
- Battlefield cleanup moves cards to controller discard, including Spies.
- Monsters keep one eligible non-Hero Unit deterministically when the game continues.
- Northern Realms draws one card only when it wins a round and the game continues.
- Skellige returns up to two eligible discard Units at start of round 3 with deterministic RNG.
- Cleanup clears weather and row horns.
- Commands remain immutable and events are serializable.
- `npm test` passes.
- `npm run build` passes.
- Existing live gameplay behavior is not intentionally changed.

## Required Tests

At minimum, cover:

- `Pass` by both seats moves to `round_end` but does not decrement gems.
- `ResolveRoundEnd` rejects before both seats pass.
- `ResolveRoundEnd` rejects or no-ops if the same logical round is resolved twice.
- Higher score wins and the lower scorer loses exactly 1 gem.
- Winner starts the next round.
- True draw makes both seats lose 1 gem and uses previous `roundStarter` if the game continues.
- Nilfgaard wins a tied score against a non-Nilfgaard faction.
- Both Nilfgaard seats tied score remains a true draw.
- R-008 trace: seat A has 1 gem, seat B has 2 gems, seat A wins the round, seat B drops to 1, game continues.
- F-5.19 trace: starting from 2 gems, duplicate settlement cannot drop a seat to 0 in one logical round.
- Section 17.14 trace: both seats have 1 gem, tied score, both drop to 0, game winner is `"draw"`.
- Spy cleanup goes to the Spy controller's discard pile, not the physical board side.
- Row horns and weather cards go to controller discard during cleanup.
- Monsters keeps exactly one eligible controlled non-Hero Unit and discards the rest.
- Monsters keeps no opponent-controlled Spy on the Monsters board.
- Northern Realms draw-on-win draws one card, and empty deck draws nothing without error.
- Skellige start-of-round-3 return pulls up to two random eligible discard Units deterministically.
- Skellige does not return Heroes, Specials, Weather, or opponent discard cards.
- `ResolveRoundEnd` does not mutate its input state.

## Notes For The Coding Instance

- Prefer small internal helpers for movement, drawing, cleanup, and faction passives instead of duplicating array operations.
- Watch event order carefully. The report should be able to reconstruct the full settlement from emitted events.
- Do not let legal move generation become the only safety check. `commands.ts` must still validate `ResolveRoundEnd`.
- Avoid tying round settlement to UI animation timing. Animation/adapters can observe `round_end`; the engine transaction should be explicit and replayable.
- Keep this phase pure. Any temptation to touch `ReduxGameManager.tsx` for auto-new-game behavior belongs to a later adapter migration phase.
