# cFp38 Specs - Weathered Row Low-Tempo Tuning

Date: 2026-05-18
Cluster: F - AI / Behavior
Phase: cFp38
Status: Spec Ready
Target branch for implementation: `codex/cFp38-v1-weathered-row-low-tempo`

## Summary

cFp30 made `legal-heuristic-v1` weather-aware by using weather-adjusted
effective strength for board-row placement tempo. That fixed the first obvious
weather-placement bug, but calibrated failure mining still reports
`weathered_row_low_tempo` as the next visible tuning queue item after cFp37:

```text
cFp37 starter matrix: 102 win / 16 loss / 2 draw vs v0
cFp37 failure mining: 295 findings
cFp37 suspicious_pass: 222
weathered_row_low_tempo: 21 findings
```

cFp38 should not rewrite weather strategy. It should add a narrow second-pass
guard against spending meaningful non-hero unit cards into the AI's own
weathered rows when a clearly better legal line exists.

The key distinction:

- cFp30 made weather affect immediate tempo.
- cFp38 should stop strategic/card-value bonuses from overpowering that weather
  penalty in obvious low-tempo placements.

## Evidence

The current cFp37 failure-mining queue ranks:

| Rank | Cluster | Count | Recommendation |
|---:|---|---:|---|
| 1 | `round_resource_exhaustion` | 44 | Already addressed by cFp37 pass-decision alignment. |
| 2 | `weathered_row_low_tempo` | 21 | Review weather-adjusted unit placement where printed medium/high strength collapses to low/no effective tempo. |
| 3 | `medic_no_target_timing` | 5 | Defer until weathered-row behavior is reviewed. |

The failure-mining condition for `weathered_row_play` is already
hidden-info-safe and concrete:

```ts
weather.selectedMoveIntoWeatheredRow === true
&& selectedPrintedStrengthBucket in {"medium", "high"}
&& selectedEffectiveStrengthBucket in {"none", "low"}
```

This means the selected move is spending a visible medium/high printed-strength
card into a weathered row where the policy's own weather-adjusted effective
strength bucket is low.

## Goals

1. Reduce obvious `weathered_row_low_tempo` findings without broad pass-policy
   changes.
2. Keep cFp30 weather-adjusted tempo behavior.
3. Add a narrow penalty or rejection path for own-side, non-hero, low-effective
   weathered board-row placements when a clearly better legal line exists.
4. Preserve tactical exceptions: Spy/card-advantage, strong Medic value, Muster
   callers, useful leaders, match-winning lines, last-gem catch-up, and cases
   where every useful line is weathered or poor.
5. Keep selected-move parity between `legalHeuristicPolicyV1.selectMove(input)`
   and `explainLegalHeuristicV1Decision(input).move`.
6. Keep diagnostics hidden-info safe.
7. Refresh benchmark and failure-mining artifacts after the behavior change.

## Required Behavior Design

### 1. Define A Narrow Weathered Low-Tempo Risk

File: `src/game/ai/legalHeuristicPolicyV1.ts`

Add a pure helper near the existing weather helpers. Exact names may vary, but
keep the logic small and testable.

Suggested shape:

```ts
export const isOwnWeatheredLowTempoUnitPlacement = (
  features: LegalHeuristicV1Features,
  move: PlayCardMove,
): boolean => { ... };
```

It should return `true` only when all are true:

1. `move.kind === "play_card"`.
2. `move.target.kind === "board_row"`.
3. `move.target.side === "own"`.
4. The source card exists in `features.ownHandByCardId`.
5. The source card is a normal non-hero unit:
   - `card.kind === "unit"`;
   - not `card.kind === "hero"`.
6. The target row is weathered according to `isRowWeatheredForPolicy`.
7. `effectivePlacedStrengthForPolicy(features, card, move.target) <= 3`.
8. `card.printedStrength >= 6`.

The printed-strength threshold intentionally targets meaningful cards, not
low-value filler.

### 2. Define A Clearly Better Alternative

Add a helper that answers whether the selected low-tempo weathered placement has
a better legal line available.

Suggested shape:

```ts
export const hasClearlyBetterNonWeatheredLine = (
  features: LegalHeuristicV1Features,
  selectedMove: PlayCardMove,
): boolean => { ... };
```

It should use public legal moves only. Do not inspect raw `MatchState`.

Treat an alternative as clearly better when any legal candidate meets one of
these conditions:

1. Same card, own-side non-weathered row option:
   - candidate is `play_card`;
   - `candidate.sourceCardId === selectedMove.sourceCardId`;
   - candidate target is `board_row`;
   - candidate target side is `own`;
   - candidate target row is not weathered;
   - candidate effective placement strength is at least `selectedEffective + 4`.

2. Different card or leader with materially better immediate tempo:
   - candidate is not the same selected move;
   - candidate does not itself satisfy `isOwnWeatheredLowTempoUnitPlacement`;
   - `estimateImmediateTempo(features, candidate) >= selectedTempo + 5`;
   - `scoreMove(features, candidate)` is not deeply negative. Suggested floor:
     `scoreMove(features, candidate) >= MIN_USEFUL_MOVE_SCORE`.

Avoid recursive scoring loops. If this helper is called from `scorePlayMove`,
do not call a scoring function that re-enters the same helper indefinitely. The
safe approach is:

- use `estimateImmediateTempo(...)` for most comparison;
- if using `scoreMove(...)`, gate it so it never scores the original
  `selectedMove` through the same penalty path, or add a private
  no-weather-penalty option.

If recursion risk is hard to avoid, use only `estimateImmediateTempo(...)` plus
card-kind/leader-kind checks for the alternative test and document the simpler
choice in the report.

### 3. Preserve Tactical Exceptions

The weathered low-tempo guard must not penalize or reject the selected move when
any of these is true:

1. Source card has `spy`.
   - Spy behavior is already card advantage and normally targets opponent rows.
2. Source card is a Medic with meaningful revive value:
   - use existing cFp29 Medic utility helpers;
   - do not penalize when best revive bucket is `strong`;
   - it is acceptable to penalize no-target/weak/medium Medic lines, because
     cFp29/cFp32 already treat those as risky.
3. Source card is a Muster or linked-caller card:
   - `muster`, `muster_roach`, or `isMusterCaller(card)`;
   - this preserves tactical linked-card value even when the source body lands
     in a weathered row.
4. The move can win the match:
   - opponent has one gem;
   - `features.ownScore + estimateImmediateTempo(features, move) >= minimumScoreToWinRound(features)`.
5. The AI is on its last gem and this is the best visible catch-up line:
   - `features.ownGems <= 1`;
   - `features.scoreDelta < 0`;
   - no clearly better legal line exists.
6. No clearly better legal line exists.

### 4. Scoring Change

Preferred implementation: keep this as a scoring penalty, not a hard legal-move
filter.

In `scorePlayMove(...)`, after computing base strategic score and contextual
bonuses, apply a penalty only when:

- `isOwnWeatheredLowTempoUnitPlacement(features, move)` is true;
- tactical exceptions do not apply;
- `hasClearlyBetterNonWeatheredLine(features, move)` is true.

Suggested penalty:

```ts
const lostStrength = Math.max(0, card.printedStrength - effectiveStrength);
score -= 180 + lostStrength * 22;
```

The exact constants can be adjusted, but the tests must prove the behavior:

- meaningful cards stop choosing weathered low-tempo rows when a better line
  exists;
- the AI can still choose the weathered row when it is genuinely the best/only
  useful line.

Do not globally punish all weathered-row plays. The policy can still accept
weathered-row placement when it is tactically justified.

### 5. Explanation / Trace Update

Existing `weatherPlacementAnalysis` is useful but too thin for cFp38 debugging.
Extend `AiDecisionWeatherPlacementAnalysis` with hidden-info-safe fields:

```ts
readonly selectedMoveLowTempoWeatherRisk: boolean;
readonly betterNonWeatheredAlternativeAvailable: boolean;
readonly weatheredLowTempoPenaltyApplied: boolean;
```

All three are booleans. They must not include card names, source IDs, card IDs,
ability arrays, row totals by hidden identity, raw move IDs, or raw labels.

Update:

- `src/game/ai/decisionTrace.ts`
- `src/game/ai/explainLegalHeuristicV1Decision.ts`
- `src/components/gwent/matchDiagnostics.ts`
- `tests/game/productDiagnostics.test.ts`

Reason text in `explainLegalHeuristicV1Decision.ts` should distinguish:

- selected low-tempo weathered move with no better alternative:
  - example: `weathered row penalty accepted — no better visible line (...)`
- selected move avoided the risk:
  - no special reason required if it falls through to `best useful move`;
  - candidate summaries can remain generic and hidden-info safe.

Do not put card identity in the reason string.

### 6. Failure-Mining Behavior

Do not delete or loosen the existing `weathered_row_play` finding rule in
`src/game/benchmark/failureMining.ts`.

After the policy changes, rerun failure mining. The expected improvement is
that fewer selected moves satisfy the existing weathered-row finding condition.

If the count does not decrease, stop and inspect the top findings before adding
more code. Do not fake improvement by changing the analyzer.

## Required Tests

Add focused tests in `tests/game/engineAiPolicy.test.ts`.

Minimum coverage:

1. **Same-card agile row choice**
   - A non-hero agile card has legal own close and own ranged targets.
   - Ranged is weathered; close is not.
   - Printed strength is at least 6; effective ranged strength <= 3.
   - v1 selects the non-weathered row.

2. **Different-card alternative**
   - A high printed-strength non-hero unit can only play into a weathered row.
   - Another legal card/leader has materially better immediate tempo.
   - v1 selects the better non-weathered/non-risk line.

3. **No better line**
   - The only useful legal play is a medium/high printed-strength non-hero unit
     into a weathered row.
   - v1 may select it.
   - Trace says `selectedMoveLowTempoWeatherRisk === true`,
     `betterNonWeatheredAlternativeAvailable === false`,
     and `weatheredLowTempoPenaltyApplied === false`.

4. **Hero exception**
   - Hero on weathered row is not treated as low-tempo risk.
   - Effective strength bucket remains medium/high as appropriate.

5. **Muster exception**
   - Muster/linked caller can still be selected even if its source body lands in
     a weathered row.
   - The test should assert it is not penalized by the cFp38 low-tempo guard.

6. **Strong Medic exception**
   - Medic with a strong revive target can still be selected despite weathered
     source placement.
   - No-target or weak-target Medic remains eligible for existing cFp29/cFp32
     caution and can be penalized if it also meets cFp38 risk.

7. **Last-gem catch-up exception**
   - AI on last gem, behind, no better line.
   - Weathered low-tempo move may be selected if it is the best visible catch-up
     line.

8. **Policy/explanation parity**
   - For a cFp38 fixture, `legalHeuristicPolicyV1.selectMove(input)` and
     `explainLegalHeuristicV1Decision(input).move` select the same move.

9. **Diagnostic hidden-info shape**
   - Trace includes the three new booleans.
   - Trace/export scanner rejects unsafe injected strings or arrays inside the
     weather placement analysis subtree.
   - Safe full product diagnostic export passes.

10. **v0 unchanged**
    - Add or keep a small assertion that cFp38 logic is not wired into
      `legal-heuristic-v0`.
