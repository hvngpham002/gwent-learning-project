## Root Cause

`src/game/ai/legalHeuristicPolicyV1.ts` has helper functions whose purpose is
to inspect alternative lines while scoring a candidate:

- `hasUsefulNonMedicLine(features)`
- `hasClearlyBetterNonWeatheredLine(features, selectedMove)`

Those helpers currently call full recursive scoring:

- `hasUsefulNonMedicLine` calls `scorePlayMove(features, candidate)`.
- `hasClearlyBetterNonWeatheredLine` calls `scoreMove(features, candidate)`.

Full scoring calls back into the cFp38/cFp39 guards:

- `scorePlayMove` can call `shouldApplyNoTargetMedicDelayPenalty`.
- `shouldApplyNoTargetMedicDelayPenalty` calls `hasUsefulNonMedicLine`.
- `scorePlayMove` can call `hasClearlyBetterNonWeatheredLine`.
- `hasClearlyBetterNonWeatheredLine` calls `scoreMove`, which can call
  `scorePlayMove`.

The comment above `hasClearlyBetterNonWeatheredLine` says it avoids recursive
scoring, but the implementation still calls `scoreMove`. The repair must make
that statement true.

## Required Work

### 1. Add a non-recursive alternative-line score helper

Add a helper in `src/game/ai/legalHeuristicPolicyV1.ts` for scoring candidate
alternatives from inside cFp38/cFp39 guard logic.

Acceptable shapes:

- extract a shared base-score helper used by `scorePlayMove`; or
- add a small internal helper such as
  `scorePlayMoveForAlternativeScan(features, move)`; or
- add an options parameter to `scorePlayMove`, as long as default behavior is
  unchanged and recursive guard penalties can be disabled.

The helper used by alternative-line scanners must not call any of these:

- `scoreMove`
- `scorePlayMove` with full/default recursive behavior
- `hasUsefulNonMedicLine`
- `shouldApplyNoTargetMedicDelayPenalty`
- `hasClearlyBetterNonWeatheredLine`
- `shouldExemptFromWeatheredLowTempoPenalty` if doing so can re-enter a
  full-score path

The helper may call non-recursive primitives already used by scoring:

- `estimateImmediateTempo`
- `scoreLeaderMove`
- `scoreWeatherPlayMove`
- `scoreScorchMove`
- `scoreDecoyMove`
- `cardStrategicValue`
- `medicSourceUtilityScore`
- `isMedicSource`
- `isMusterCaller`
- public observation/feature fields

The helper should preserve the existing rough threshold meaning for
`MIN_USEFUL_MOVE_SCORE`; it does not need to include cFp38/cFp39 contextual
penalties because it is only deciding whether an alternative line exists.

### 2. Make cFp39 non-Medic alternative detection non-recursive

Update `hasUsefulNonMedicLine(features)` so non-Medic play-card candidates are
checked with the new non-recursive helper.

Keep these semantics:

- Medic source cards are skipped.
- Leader moves may still use `scoreLeaderMove` because leader scoring does not
  recurse into play-card guard helpers.
- A useful alternative exists when a non-Medic play or leader score is
  `>= MIN_USEFUL_MOVE_SCORE`.

Do not change `MEDIC_NO_TARGET_DELAY_PENALTY` or its tactical exceptions.

### 3. Make cFp38 better-line detection non-recursive

Update `hasClearlyBetterNonWeatheredLine(features, selectedMove)` so different
candidate alternatives do not call full `scoreMove`.

Keep these semantics:

- Same-card non-weathered row check still uses effective strength delta
  (`candidateEffective >= selectedEffectiveStrength + 4`).
- Different-card play alternatives still require materially better tempo
  (`candidateTempo >= selectedTempo + 5`) and a useful score threshold.
- Low-tempo weathered candidate alternatives are skipped.
- Leader alternatives can continue using `estimateLeaderTempo` and
  `scoreLeaderMove`.

Do not change the cFp38 penalty constant/formula:

```text
180 + lostStrength * 22
```

Do not change cFp38 exception policy except as needed to avoid recursion.
