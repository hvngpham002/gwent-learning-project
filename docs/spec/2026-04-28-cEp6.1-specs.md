# Implementation Spec: Cluster E, Phase 6.1 - Mulligan Flow Stabilization Patch

## Goal

Stabilize the cEp6 authentic mulligan and product-navigation flow before adding Card Studio or any new product surface.

cEp6.1 is a hardening patch, not a new feature phase. It should make the current dedicated mulligan screen, hidden-safe AI mulligan presentation, start-match confirmation, return-to-setup behavior, and browser smoke coverage more reliable after the recent cEp6 iteration.

Do not add AI strategy in this phase. The current `legal-heuristic-v0` policy may continue to keep hand during normal mulligan. Animation testing should use the existing debug-only forced AI mulligan route behavior, not random behavior in the AI policy.

## Architecture Position

Before this phase:

- `/` remains the legacy UI.
- `/?engine=1` remains the diagnostic engine shell.
- `/?engine=1&ui=authentic` opens authentic pre-game.
- `/?engine=1&ui=authentic&view=deck-builder` opens the authentic deck builder.
- `/?engine=1&ui=authentic&view=match` starts a direct authentic match and shows the cEp6 mulligan screen first.
- `AuthenticMulliganScreen` owns the product mulligan surface.
- `AuthenticMatchScreen` coordinates AI mulligan dispatch, hidden-safe AI presentation, start-match modal, match table, and setup/rematch navigation.
- Debug animation inspection is available through:
  - `debugAiMulligan=1`
  - `debugAiMulliganCount=0`
  - `debugAiMulliganCount=1`
  - `debugAiMulliganCount=2`

After this phase:

- Normal product behavior is unchanged.
- Debug-only AI mulligan forcing is reliable enough to test all three presentation cases: zero-card keep wave, one-card slide/replacement, and two sequential slide/replacements.
- Presentation timers/effects cannot dispatch stale AI or navigation actions into a new setup after return-to-setup, rematch, or route change.
- Browser smoke coverage captures the cEp6 visual/navigation regressions that are most likely to recur.
- `docs/PROJECT_STATE.md` and the cEp6.1 report clearly mark Card Studio as still deferred to cEp7.

## Scope

### 1. Stabilize Debug AI Mulligan Presentation Controls

Audit and harden the existing debug path:

```txt
/?engine=1&ui=authentic&view=match&debugAiMulligan=1&debugAiMulliganCount=0
/?engine=1&ui=authentic&view=match&debugAiMulligan=1&debugAiMulliganCount=1
/?engine=1&ui=authentic&view=match&debugAiMulligan=1&debugAiMulliganCount=2
```

Requirements:

- `debugAiMulliganCount=0` must force a legal zero-card AI mulligan when the AI is in mulligan, then show the hidden-back wave presentation.
- `debugAiMulliganCount=1` must force one legal one-card AI redraw if one exists, then show exactly one sliding replacement presentation.
- `debugAiMulliganCount=2` must force two sequential legal one-card AI redraws if legal moves permit them, then show two sequential sliding replacement presentations.
- Debug forcing must still dispatch legal engine `ChooseMulligan` commands. It must not mutate hand/deck state directly.
- Debug forcing must be gated behind `debugAiMulligan=1`. Normal product routes must keep using `legal-heuristic-v0`.
- Do not add random mulligan behavior to `legal-heuristic-v0`, `legal-heuristic-v1`, or any normal AI policy.
- If the current first-legal-card debug forcing is too brittle for browser inspection, an optional deterministic query param may be added:

```txt
debugAiMulliganIndexes=0,4
```

  If implemented, it must:
  - work only when `debugAiMulligan=1`;
  - refer to current AI hand display/debug order, not source IDs or instance IDs in normal UI;
  - fall back to the first legal one-card redraw if an index is invalid;
  - remain documented as temporary QA-only behavior.

Do not expose AI hand names, source IDs, or instance IDs in the default non-debug route.

### 2. Guard Against Stale Presentation Effects

The cEp6 mulligan animations use presentation timers after engine commands have already resolved. That is acceptable, but stale effects must not leak into a fresh match.

Requirements:

- Returning to setup during human mulligan, during the AI choosing buffer, during AI animation, or while the start-match modal is open must cancel or harmlessly ignore all pending cEp6 presentation effects.
- Starting a new match after return-to-setup must begin from a fresh engine mulligan state and must not inherit:
  - prior `mulliganExitAnimation`;
  - prior AI debug decision text;
  - prior start-match modal open state;
  - prior hidden-hand frozen slot state;
  - prior AI command dispatch effects.
- Rematch must restart the same setup/seed through the mulligan screen without stale animation or modal state.
- AI mulligan command dispatch must happen at most once per relevant AI mulligan decision window. It must not loop because React re-rendered during presentation state changes.
- The start-match modal should open once after AI presentation/review completes. `review hand` should dismiss the modal and keep the mulligan screen stable; the footer `start match` action should reopen the same modal rather than transitioning directly.
- Do not use timers for rule transitions. Presentation timers may gate UI display and dispatch locks only.

Implementation guidance:

- Prefer keying presentation state by a stable active setup/match key already present in `AuthenticMatchScreen`.
- Use effect cleanup or key checks to ignore stale timer callbacks.
- If the component currently holds too much ad hoc animation state, extract small pure helpers only where it reduces risk. Do not perform a broad component rewrite.

### 3. Preserve The Reviewed Visual Contract

This patch must not redesign the mulligan screen, card visuals, deck builder, or pre-game screen.

Requirements:

- Preserve the current shared authentic button styling for `keep hand`, `confirm mulligan`, `start match`, and modal actions.
- Do not enlarge or restyle these buttons unless fixing a concrete breakage.
- Do not reintroduce duplicate card names under cards.
- Do not reintroduce duplicate strength overlays outside the authentic card face.
- Do not dim human cards during the redraw animation unless the current reviewed behavior is explicitly broken.
- Keep the AI hand hidden in normal product mode as backs/count only.
- Keep the hidden-back wave for zero-card AI keeps.
- Keep sliding replacement animation for one-card and two-card debug redraw presentations.
- Keep the `Start the match?` and `Return to setup?` modals as transparent-shell overlays over the current screen, not full parchment pages.
- Maintain no horizontal overflow at `390px` for pre-game, deck builder, mulligan, direct match, and post-confirm match.

If any visual adjustment is necessary, keep it minimal and call it out in the report with before/after rationale.

### 4. Tighten Browser Smoke Around cEp6 Regressions

Update Playwright smoke coverage to make the stabilization measurable.

Required browser coverage:

- Normal non-debug flow:
  - pre-game `begin match ->`;
  - mulligan screen;
  - human keep or one-card redraw;
  - AI presentation;
  - `Start the match?` modal;
  - `review hand`;
  - footer `start match`;
  - modal confirmation;
  - match table.
- Debug forced AI keep:
  - `debugAiMulligan=1&debugAiMulliganCount=0`;
  - hidden-back wave is visible;
  - no redrawn AI slots are shown.
- Debug forced one-card AI redraw:
  - `debugAiMulligan=1&debugAiMulliganCount=1`;
  - exactly one redrawn AI slot is visible during presentation.
- Debug forced two-card AI redraw:
  - `debugAiMulligan=1&debugAiMulliganCount=2`;
  - two redrawn AI slots are visible during presentation;
  - presentation remains sequential/staggered enough to inspect.
- Return-to-setup stale-state regression:
  - start a match;
  - enter/complete human mulligan far enough to trigger AI presentation or start-modal state;
  - choose setup return and confirm;
  - begin the same setup/seed again;
  - assert the new flow starts at fresh mulligan and does not show old AI debug text, old modal state, or old completed-mulligan state.
- Hidden-info scan:
  - default non-debug mulligan and AI presentation visible text must not contain `instanceId`, `sourceId`, runtime seat-card ID patterns, or AI card names/source IDs.
- Mobile overflow:
  - `390px` smoke for mulligan and post-confirm match.

Do not make the browser suite long by playing a full match to game end. If match-end navigation is touched, cover it through unit/component tests unless a short deterministic fixture already exists.

### 5. Add Focused Helper Coverage Where It Reduces Fragility

Add or refine unit/component tests around pure helpers when feasible.

Recommended coverage:

- legal mulligan selection still maps selected IDs to exactly one legal `choose_mulligan` move;
- zero-card, one-card, and two-step debug AI mulligan forcing chooses legal moves only;
- presentation-batch helpers, if extracted, produce hidden-safe display state for 0/1/2 redraw cases;
- start-match modal state and return-to-setup state are reset by setup key changes or explicit adapter clearing;
- default mulligan view model does not expose AI hand identity fields.

Do not add broad snapshot tests for entire screens. Prefer stable `data-testid`, helper, and behavioral assertions.

## Out Of Scope

Do not implement:

- AI mulligan strategy.
- `legal-heuristic-v1`.
- random AI mulligan behavior in any production policy.
- Card Studio.
- card creation, card editing, image upload, image path authoring, catalog code generation, or permanent repo writes.
- deck-builder redesign.
- pre-game redesign.
- route promotion to `/`.
- new modes such as PvP, AI-vs-AI product mode, ranked, Bo1, training, free mulligans, undo, or seed suite UI.
- drag-and-drop card play.
- new rule behavior.
- broad `AuthenticMatchScreen` rewrite unrelated to stale-effect hardening.
- full-game browser smoke unless a short deterministic fixture already exists.

## Acceptance Criteria

This phase is complete when:

- normal product cEp6 behavior is unchanged except for bug fixes;
- AI mulligan animation QA can reliably inspect 0, 1, and 2 forced AI redraw cases through debug routes;
- default non-debug routes still hide AI hand identity during mulligan and AI presentation;
- stale presentation effects do not survive setup return, rematch, or new match start;
- reviewed button/card/modal styling is preserved;
- browser smoke covers the cEp6 regressions listed above;
- `docs/PROJECT_STATE.md` and the cEp6.1 report are updated;
- full validation passes.
