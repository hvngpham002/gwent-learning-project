# Cluster E Phase 13: Pre-AI Weather Row Overlays

Date: 2026-05-05

## Phase Goal

Add product-facing weather overlays to the authentic match board rows before the next AI phase. The work is visual/UI-only: active public weather cards should make the affected rows visibly feel frozen, fogged, rained on, or storm-struck, with Skellige Storm distinct from the other weather effects.

This phase starts from the approved Imagegen concept sheet:

- Source concept: `/Users/viethungpham/.codex/generated_images/019dbf87-6d2f-71e1-bd77-61e1c18debf0/ig_0d53d1f0ca20501c0169f963b5e0e48191bf201d8fd9aafdcf.png`

Persist any project-used derived assets under the repository. Do not leave a runtime-referenced image only in the Codex generated-images directory.

Post-review iteration note: if the approved row strips or adjacent match-table affordances are refined after hands-on review, keep those refinements inside this cEp13 spec/report instead of spawning patch specs. Runtime assets may be SVG rather than PNG as long as they stay project-bound, remain presentation-only, and preserve the weather mapping and hidden-info-safe DOM contract below.

## Scope

1. Create project weather overlay assets derived from the approved concept sheet.
   - Biting Frost: icy pale cyan/blue-white row strip.
   - Impenetrable Fog: grey-green/ivory low mist row strip.
   - Torrential Rain: deep blue/slate rain row strip.
   - Skellige Storm: teal-black/violet lightning sea-storm row strip, visibly distinct from rain.
2. Add a pure UI/view-model helper that maps visible weather-zone cards to affected row overlay effects.
   - `frost` / `neutral.biting-frost` affects close rows.
   - `fog` / `neutral.impenetrable-fog` affects ranged rows.
   - `rain` / `neutral.torrential-rain` affects siege rows.
   - `skellige_storm` / `neutral.skellige-storm` affects ranged and siege rows.
   - `clear_weather` must not produce a row overlay.
3. Render overlays in `/?engine=1&ui=authentic` board rows.
   - Overlay must be driven by public `selectEngineWeatherCards` data.
   - Overlay must be presentation-only, behind row contents and legal target controls.
   - Active-weather row label, row score, and empty-state text must remain readable against the overlay.
   - Cards, strength badges, row labels, row scores, target buttons, drag/drop, and right-click inspection must remain usable.
   - Multiple active weather effects on the same row may stack visually; Skellige Storm should render above ordinary Fog/Rain when both apply.
4. Add focused tests.
   - Unit coverage for weather-card to row-effect mapping, including Skellige Storm affecting ranged + siege and Clear Weather no-op.
   - Browser smoke or equivalent product-level test that plays a weather card and observes the affected board-row overlay without hidden-info leakage.
5. Update docs and report.
   - Update `docs/PROJECT_STATE.md`.
   - Update `docs/ui/authentic-product-flow.md`.
   - Update `docs/testing/browser-smoke.md` if browser coverage is added.
   - Create `audit/reports/2026-05-05-cEp13-report.md`.
6. Post-review selected-card target affordance cleanup.
   - Remove the visible row-level `play here` button when selecting a card.
   - Keep legal board rows visibly highlighted and clickable.
   - Make the whole legal board row the drag/drop target instead of requiring the pointer to land near the old button area.
   - Remove the visible Weather-panel `play weather` button and make the highlighted Weather panel itself the click/drop target.
   - Remove visible `choose` badges from board-card `card_instance` targets while keeping the card itself clickable/drop-targetable.
   - Make card-flight destination rectangles land in the actual row/weather card strip insertion area for broad row and Weather panel targets.
   - Preserve board-card `card_instance`, row-horn, and Weather-panel target behavior.
   - When a card's score modifiers include active weather, make the card's visible strength text red even if the final strength equals printed strength.
   - Replace the visible Commander's Horn target button/label with a persistent icon-only row horn slot immediately after the row label. The slot must carry the exact legal `row_horn` move id only when Commander's Horn is selected, must accept click/drop like other spatial targets, and must not render visible `horn slot`, `choose`, or `play here` text.
   - Size the row horn slot from the shared authentic card `xs` dimensions so the slot frame is exactly 8px wider and 8px taller than the Commander’s Horn card rendered inside it.
   - Remove button-like border/background styling from leader status state labels such as `unavailable`; the state should read inline with the rest of the score-card status text.
   - Render a normal dot separator between the leader status state and category, matching the existing separator before the reason text, e.g. `unavailable · active · waiting for turn`.
   - Replace score-card `gems N` text with two project-bound gem icons derived from the approved Imagegen sheet. The active gem and broken/spent gem assets must be cropped, alpha PNGs with the parchment background removed; the UI should expose hidden-safe life-gem test attributes and accessible remaining-gem copy.
   - Place the life-gem icons directly underneath the score-card faction name, with a slightly larger icon size than the first gem pass.

## Out Of Scope

- No engine rule, scoring, legal-move, command, Redux adapter, AI policy, catalog, deck-builder, Card Studio, route-default, or legacy UI behavior changes.
- No timer-driven rule transitions.
- No touch-drag redesign.
- No weather animation loop requirement. Static or CSS-only presentation is acceptable.
- No hidden AI hand/deck/card identity exposure.
- No replacement of weather card art or weather rules.

## Acceptance Criteria

- Active Frost visually marks both close-combat rows.
- Active Fog visually marks both ranged rows.
- Active Rain visually marks both siege rows.
- Active Skellige Storm visually marks both ranged and siege rows and is visually distinguishable from Rain.
- Clear Weather never renders a row overlay.
- Overlay DOM exposes stable test attributes that do not include hidden card instance IDs.
- Existing click/drag/drop/legal-target controls remain functional.
- Weather-affected unit strength text renders red based on score modifiers, not only final strength comparison.
- Commander's Horn targets render as icon-only row horn slots rather than visible target buttons or labels.
- A placed Commander’s Horn sits inside a horn slot whose measured width and height are 8px larger than the rendered card.
- Leader status state labels render as inline text, not bordered tags.
- Leader status state, category, and reason read as dot-separated inline text, e.g. `ready · active · waiting for turn`.
- Score cards show two cropped transparent gem icons for remaining/spent lives instead of the old `gems N` text.
- Life-gem icons sit underneath the faction name and are large enough to read as the primary life indicator.
- Existing hidden-info browser assertions still pass.
- Project-bound image assets live inside the repository.
- Required docs/report are updated.
