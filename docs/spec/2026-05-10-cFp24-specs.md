# cFp24 Specs - Legal Heuristic v1

## Purpose

Implement `legal-heuristic-v1`, the first real strategic AI baseline.

This is not the ML agent, not search, and not a faction-specialist model.
It is the deterministic hand-authored policy that later ML/search systems
must beat. The policy must still choose only from engine legal moves, but
it should reason from the same strategic objects a human player watches:
hand contents, visible board state, score delta, card advantage, gems,
round number, public weather, leader status, and prompt context.

The target is a pragmatic generalist baseline:

- rules-correct through the existing legal-move boundary;
- hidden-info safe;
- deterministic;
- benchmarkable against `legal-first-v0` and `legal-heuristic-v0`;
- structured enough that later faction profiles, search, and ML can reuse
  the same feature vocabulary.

## Current Context

cDp5 introduced `legal-heuristic-v0` as a small legal-move-driven policy.
It currently:

- keeps all mulligan cards;
- resolves prompts mostly by highest visible `targetStrength`;
- always cancels when it owns a `cancel_leader` reaction prompt;
- passes only when the opponent has passed and the AI is already ahead;
- otherwise plays the highest printed-strength legal card;
- uses only useful Clear Weather leader moves;
- does not reason about round economy, card advantage, muster mulligan,
  leader timing, weather/scorch/spy/medic/decoy timing, or last-gem
  survival.

cFp21-cFp23 created the benchmark foundation:

- `benchmark-smoke-v1`: tiny current Northern Realms versus Nilfgaard
  policy plumbing regression.
- `benchmark-starter-matrix-v1`: five official starter decks, 10
  unordered pairings, both policy assignments, 3 seeds, mirrored seat
  runs, 120 public records.

cFp24 should implement a better deterministic policy and benchmark it.
It should not mutate engine rules or use hidden information.

## Non-Negotiable Boundaries

- No engine rule changes.
- No legal-move semantics changes.
- No command payload changes unless required only for typed AI
  observation support and fully backward compatible.
- No product UI, route, CSS, deck-builder, Card Studio, Official
  Porting, legacy, or browser benchmark execution changes.
- Do not switch the product match AI default from `legal-heuristic-v0` to
  `legal-heuristic-v1` in this phase. cFp24 creates and benchmarks v1;
  product adoption is a later decision.
- No search, minimax, MCTS, CFR, neural model, Python tooling, self-play
  training, ratings, Glicko, TrueSkill, Elo, approximate best response,
  or exploitability probes.
- No online lookup or scraping.
- No benchmark deck data changes.
- No mechanics or competitive deck construction.
- No hidden-info leaks. The policy may use:
  - its own hand identities;
  - public board/weather/discard counts and visible board cards;
  - public leader status;
  - public score breakdown;
  - prompt options exposed to the acting seat by the engine;
  - public catalog metadata for visible cards, including
    `linkedSourceIds`.
- The policy must not inspect opponent hand identities, opponent deck
  identities/order, raw `MatchState`, `cardsById`, command logs, raw
  event logs, or runtime instance ids outside legal moves and the
  acting-seat observation.
- Do not import `currentCatalogCards`, `currentCatalogLeaders`, or deck
  presets from `src/game/ai`. AI policy code must work from
  `EnginePolicyInput` and public observation data.

## Desired Architecture

Add `legal-heuristic-v1` as a pure policy module under `src/game/ai/`.

Recommended structure:

```text
src/game/ai/legalHeuristicPolicyV1.ts
src/game/ai/legalHeuristicPolicyV1Features.ts       optional
src/game/ai/legalHeuristicPolicyV1Mulligan.ts       optional
src/game/ai/legalHeuristicPolicyV1Scoring.ts        optional
```

Keep helpers pure and deterministic. A single file is acceptable if it
stays readable, but avoid a monolithic opaque ranking function.

Export the policy from `src/game/ai/index.ts`:

```ts
export const legalHeuristicPolicyV1: EnginePolicy = {
  id: "legal-heuristic-v1",
  selectMove(input) {
    // ...
  },
};
```

Register the policy in `src/game/benchmark/policies.ts` so benchmark
suites can reference it by id.

### Observation Extension

Muster-aware mulligan requires public catalog linkage. Extend
`SeatCardSummary` in `src/game/ai/types.ts` with public catalog fields
needed by policy reasoning:

```ts
linkedSourceIds?: readonly string[];
deckLimit?: number;
```

Only add fields that are public catalog metadata. Do not add hidden
zone-location information. Update `buildSeatObservation(...)` to populate
them from the card source.

This avoids brittle name-prefix matching and avoids importing global
catalogs into the AI policy.

### Legal-Move Rule

`legal-heuristic-v1.selectMove(...)` must return either `null` or an
object from `input.legalMoves` by identity/value. It must not construct
new legal moves or commands.

Tie-break deterministically by `moveId` after all strategic scoring.

## Implementation Requirements

### 1. Add Strategic Feature Extraction

Create a small, testable feature layer over `EnginePolicyInput`.

It should derive at least:

- `ownScore`, `opponentScore`, `scoreDelta`;
- `round`;
- own/opponent gems;
- own/opponent hand counts;
- own/opponent deck counts;
- own/opponent discard counts;
- own/opponent passed flags;
- current turn and phase;
- public row totals and row occupancy from `observation.boardRows`;
- weather source ids and affected rows, if cheaply derivable from known
  weather cards;
- own leader used/cancelled status and opponent leader used/cancelled
  status;
- own hand summaries grouped by ability/kind/source;
- legal move groups by kind.

Keep feature extraction cheap. Do not simulate future turns in cFp24.

### 2. Implement Muster-Aware Mulligan v1

Current v0 keeps everything. v1 must select legal mulligan moves using a
catalog-link-aware strategy.

Important engine constraint: current legal mulligan moves redraw at most
one card per `ChooseMulligan` command. v1 should pick the best single
legal redraw candidate each mulligan step, or keep hand when no candidate
is strategically worse than replacement uncertainty.

Mulligan rules:

1. Prefer redrawing cards that are expected to be summoned for free by a
   playable caller in hand.
2. Use explicit `linkedSourceIds`; do not infer by name prefix.
3. `muster_roach`:
   - if Geralt/Ciri or any other `muster_roach` caller is in hand,
     redraw `neutral.roach` when it is also in hand;
   - do not redraw the caller just because Roach is in hand.
4. One-way linked Muster:
   - keep the caller;
   - redraw linked targets in hand if the caller is also in hand;
   - examples: base Gaunter should make `Gaunter O'Dimm: Darkness`
     redrawable; Cerys should make Shield Maidens redrawable; Arachas
     Behemoth should make regular Arachas redrawable.
5. Same-source Muster:
   - keep one playable copy;
   - redraw duplicate copies beyond the first because extra copies can be
     pulled by the first played copy;
   - examples include Light Longship, regular Arachas, Crone family and
     Vampire family through their explicit links.
6. Gaunter/Darkness guard:
   - base `neutral.gaunter-odimm` links forward to Darkness and should be
     treated as the preferred caller;
   - `neutral.gaunter-odimm-darkness` must not be treated as a caller for
     base Gaunter;
   - if only Darkness copies are present, treat Darkness as same-source
     Muster and keep one, redraw extras.
7. Avoid redrawing:
   - heroes unless they are a linked summoned target and there is an
     explicit policy reason; current official target cases are non-hero;
   - the only playable caller in a summon group;
   - the only high-value unit in an otherwise weak hand, unless it is a
     clear linked target.
8. Tie-break redraw candidates by:
   - summoned-target confidence first;
   - lower standalone strategic value next;
   - lower printed strength next;
   - `cardId` or move id last for determinism.

Add focused tests for:

- Roach with a `muster_roach` caller;
- base Gaunter plus Darkness;
- Darkness without base Gaunter;
- same-source duplicate Muster;
- one-way linked caller/target;
- no redraw when only the caller is present;
- fallback keep-hand behavior.

### 3. Implement Prompt v1

v1 should improve prompt resolution without changing engine prompt
semantics.

Required prompt behavior:

- `cancel_leader`: keep v0 behavior initially. When AI owns the reaction
  prompt, choose cancel deterministically. This is intentionally blunt
  and can be refined later.
- `look_three_cards`: choose the acknowledgement option deterministically
  by legal move order.
- Medic-style revive prompts:
  - prefer highest strategic revive value, not raw printed strength only;
  - value non-hero units with active abilities such as Spy, Medic,
    Tight Bond, Morale Boost, Muster, and Scorch variants;
  - prefer rows where the revived card contributes immediately;
  - tie-break by printed strength then move id.
- `restore_discard_to_hand` / `draw_opponent_discard` prompts:
  - prefer high strategic value cards;
  - include heroes and specials if the prompt legally allows them;
  - do not assume restored cards immediately trigger abilities.
- `discard_two_draw_one_from_deck`:
  - stage 1: discard the lowest strategic-value legal hand set, not the
    strongest set;
  - stage 2: choose the highest strategic-value deck option;
  - preserve hidden-info boundaries by using only prompt-exposed options.
- Unknown prompt kinds:
  - deterministic fallback by existing visible `targetStrength`, then
    move id;
  - never throw because a prompt is unfamiliar.

Add tests for at least Medic, discard/draw stage 1, discard/draw stage
2, restore/draw discard prompt, look-three acknowledgement, and unknown
prompt fallback.

### 4. Implement Round And Pass Strategy v1

This is the most important improvement over v0.

Required behavior:

#### Opponent Has Passed

If opponent has passed:

- If AI is already ahead, pass.
- If AI is behind, prefer the cheapest legal play that is likely to get
  ahead.
- If no known legal play can get ahead and AI is not on last gem, concede
  by passing when spending cards would be wasteful.
- If no known legal play can get ahead and AI is on last gem, pass only
  when the catch-up is conservatively impossible.

“Conservatively impossible” means a simple upper-bound estimate from the
AI's visible hand plus current score still cannot exceed the opponent.
If the estimate is uncertain, v1 should play rather than surrender.

#### AI On Last Gem

User decision for cFp24:

- If the AI is down to its last gem and cannot catch up, pass/surrender
  to save time.
- If it can catch up, might catch up, or the estimate is uncertain, full
  send: play useful legal cards until ahead, out of useful plays, or out
  of cards.
- Do not implement baiting, bluffing, weather/scorch bait lines, or
  long-horizon sacrifice planning in cFp24.

#### Normal Active Round

When neither side has passed:

- Consider card advantage:
  - being behind in hand count should increase willingness to pass or
    avoid overcommitting;
  - being ahead in hand count can tolerate spending a card to pressure.
- Avoid large overkill when a cheaper play maintains pressure.
- Prefer high-impact low-tempo cards such as Spies early when not in an
  immediate must-win state.
- Avoid playing obviously harmful weather when it hurts own rows more
  than opponent rows.
- Avoid global Scorch when own highest units are the likely victims.
- Prefer Decoy only when it targets a useful own unit such as Spy, Medic,
  or a high-value replay target.

These are heuristic requirements, not perfect-play requirements. Keep
the implementation simple and measurable.

Add scenario tests for:

- opponent passed and AI ahead -> pass;
- opponent passed and AI behind but cheap catch-up exists -> play that
  cheaper catch-up, not the highest card;
- opponent passed and catch-up impossible with non-last gem -> pass;
- last gem and catch-up impossible -> pass/surrender;
- last gem and catch-up possible/uncertain -> play, not pass.

### 5. Implement Card/Move Scoring v1

Add a deterministic scoring function for legal moves.

At minimum, recognize:

- `pass`;
- `play_card`;
- `use_leader`;
- `choose_prompt_option`;
- `choose_mulligan`.

Card/move heuristics should account for:

- printed strength;
- hero immunity/value;
- unit versus special versus weather;
- Spy card advantage, with risk adjustment for current score/round;
- Medic/restore value;
- Muster and `muster_roach` caller/target distinction;
- Decoy replay value;
- Commander's Horn row value;
- weather row value based on visible row units;
- Scorch/self-harm risk based on current visible score breakdown when
  possible;
- leader action usefulness;
- overkill/underkill when opponent has passed;
- preserving cards when round sacrifice is strategically acceptable.

Do not add deep lookahead or recursive engine simulation in cFp24.

### 6. Leader Usage v1

v0 only has special handling for Clear Weather. v1 should score all
legal leader moves generically.

Requirements:

- Use only legal `use_leader` moves.
- Do not use a leader just because it is legal.
- Score leader moves by current tactical value:
  - Clear Weather when weather materially hurts AI more than opponent;
  - weather-pulling leaders when selected weather hurts opponent more
    than AI;
  - row Scorch leaders when legal targets appear favorable;
  - restore/draw/shuffle/discard-draw/look-three leaders when useful
    under current hand/round context.
- Keep `cancel_leader` reaction behavior from prompt logic.
- If leader move scoring is uncertain, prefer holding the leader.

Add tests that v1 does not blindly use a legal leader when it has no
visible value, and does use a clearly useful legal leader scenario.

## Acceptance Criteria

- `legalHeuristicPolicyV1.id === "legal-heuristic-v1"`.
- v1 is exported from `src/game/ai/index.ts`.
- v1 is registered in benchmark policies.
- v1 never returns a move outside `input.legalMoves`.
- v1 is deterministic for identical input.
- v1 has muster-family mulligan behavior based on `linkedSourceIds`, not
  card-name prefix matching.
- v1 implements the last-gem policy:
  - impossible catch-up -> pass/surrender;
  - possible or uncertain catch-up -> play/full-send.
- v1 improves prompt handling beyond v0 for Medic and discard/draw.
- v1 scores leader moves by usefulness and does not blindly fire legal
  leaders.
- v1 benchmark suites produce deterministic artifacts:
  - `benchmark-v1-smoke-v1`: 12 records;
  - `benchmark-v1-starter-matrix-v1`: 120 records.
- Existing cFp22/cFp23 artifacts remain stable unless explicitly
  documented.
- No artifact contains hidden-info hazard strings.
- No engine rules, legal-move semantics, UI routes, product AI default,
  catalog deck presets, mechanics decks, competitive decks, search,
  ratings, Python tooling, or ML training are changed.
- `docs/PROJECT_STATE.md`, policy docs, benchmark docs, and the phase
  report are updated.
