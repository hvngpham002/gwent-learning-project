## Context

`legal-heuristic-v1` has recently been tuned around pass behavior:

- cFp25 added hidden-info-safe decision traces.
- cFp26/cFp26.1 made catch-up and pass reasons Nilfgaard tie-aware.
- cFp27 added hidden-info-safe mulligan diagnostics and conservative redraws.
- cFp28 added hidden-info-safe hand-shape analysis and pass buffers for poor/thin future hands.

A product playtest against `current-nilfgaard` exposed a different v1 issue:

- The AI played a Medic source, likely Yennefer, very early in round 1.
- Its own discard pile had no meaningful revive target yet.
- The selected move reason was `best useful move`.
- The candidate score was very high because `cardStrategicValue(...)` gives every Medic card a flat `+260` bonus.
- That flat bonus is correct only when Medic can actually convert the current discard pile into value.

This is not a cFp28 pass-safety bug. cFp28 appears to be doing the intended work in later traces. cFp29 should focus on Medic timing and diagnostics.

## Why This Is `cFp29`

This phase changes a new v1 policy surface:

- contextual valuation for cards with the `medic` ability;
- observation support for own-discard public summaries;
- hidden-info-safe Medic timing diagnostics.

It must not be folded into cFp28, because cFp28 was about voluntary pass safety and future-hand quality.

## Goal

Make `legal-heuristic-v1` less likely to burn a Medic source before the AI has a legal revive target in its own discard pile.

The patch should:

1. Value Medic source plays based on current own-discard revive target availability and quality.
2. Preserve Medic prompt resolution and prompt target ranking.
3. Preserve emergency ability to play a Medic as raw tempo when truly needed.
4. Add hidden-info-safe Medic timing diagnostics to decision traces.
5. Preserve selected-move parity between `explainLegalHeuristicV1Decision(input).move` and `legalHeuristicPolicyV1.selectMove(input)`.

## Existing Rule Contract To Preserve

Confirm from `src/game/core/abilities.ts` before implementing:

- A normal Medic source opens a prompt over cards in the acting seat's own discard pile.
- Legal Medic revive targets are catalog cards with `kind === "unit"`.
- Heroes, specials, weather cards, and leaders are not Medic revive targets.
- Agile revived units produce one prompt option per legal row.
- Revived Spies are placed on the opponent board side, matching existing engine behavior.
- Prompt-based Medic can chain if the revived card itself has an implemented ability; do not suppress this.
- Emhyr `random_medic` is a leader passive mutation for non-hero Medic sources and must remain engine-owned.

## Required Implementation

### 1. Extend Seat Observation With Own Discard Summaries

Update `src/game/ai/types.ts` and `src/game/ai/seatObservation.ts`.

Add a new field to `SeatObservation`:

```ts
ownDiscard: SeatCardSummary[];
```

Populate it with summaries for `state.seats[seatId].discard`, preserving the engine discard order.

Important hidden-info boundary:

- `ownDiscard` is safe for the acting AI policy because it is that seat's own discard pile and is public game information.
- Do **not** add opponent hand identities.
- Do **not** add opponent deck identities.
- Do **not** expose `ownDiscard` identities in product diagnostic exports by default.
- Product traces may include aggregate Medic timing counts/buckets derived from `ownDiscard`, but not names, source IDs, instance IDs, raw card IDs, ability arrays, or linked source IDs.

Also update `collectPublicCards(input)` in `legalHeuristicPolicyV1.ts` to include `observation.ownDiscard`, because prompt-target and policy helpers may need a consistent lookup for public own-discard cards.

### 2. Add Medic Revive Candidate Helpers

Update `src/game/ai/legalHeuristicPolicyV1.ts`.

Add pure helpers near the other scoring helpers:

```ts
const isMedicSource = (card: SeatCardSummary | undefined) =>
  hasAbility(card, "medic");

const isMedicReviveCandidate = (card: SeatCardSummary) =>
  card.kind === "unit" && card.rows.length > 0;

const medicReviveCandidates = (features: LegalHeuristicV1Features) =>
  features.input.observation.ownDiscard.filter(isMedicReviveCandidate);
```

Do not import `getRandomMedicCandidates(...)` from the engine helper. Reuse the same rule shape locally to keep the AI policy independent from engine internals beyond its observation contract.

### 3. Split Generic Strategic Value From Contextual Medic Source Value

The current issue is the flat `case "medic": score += 260` inside `cardStrategicValue(...)`.

Refactor carefully so that:

- `scorePlayMove(...)` does **not** give every Medic source a flat `+260` regardless of discard state.
- `promptCardValue(...)` still values a Medic card as a good prompt target when it is actually being revived, because that can chain into another Medic prompt.
- `chooseLowestPromptSetValue(...)` for discard-cost prompts still uses a stable value function and does not accidentally discard high-value Medic cards more often than before.

One acceptable implementation:

```ts
const cardStrategicValue = (
  card: SeatCardSummary | undefined,
  options: { includeMedicAbilityBonus?: boolean } = {},
) => {
  // existing base logic
  // ...
  case "medic":
    if (options.includeMedicAbilityBonus ?? true) {
      score += 260;
    }
    break;
};
```

Then use:

- `cardStrategicValue(card, { includeMedicAbilityBonus: false })` inside `scorePlayMove(...)` for cards with `medic`, with the contextual Medic source utility added separately.
- `cardStrategicValue(card)` or an explicit `includeMedicAbilityBonus: true` in `promptCardValue(...)` and discard-cost prompt ranking.
- No behavior change for non-Medic cards.

If you choose a different implementation, tests must prove that source-play scoring is contextual while prompt target ranking still preserves Medic value.

### 4. Add Contextual Medic Source Utility

Add a helper with exported tests if useful:

```ts
export type LegalHeuristicV1MedicTimingBucket =
  | "none"
  | "weak"
  | "medium"
  | "strong";

export interface LegalHeuristicV1MedicTimingInfo {
  readonly sourceIsMedic: boolean;
  readonly reviveCandidateCount: number;
  readonly bestReviveValue: number;
  readonly bestReviveStrength: number;
  readonly bestReviveValueBucket: LegalHeuristicV1MedicTimingBucket;
  readonly hasReviveTarget: boolean;
  readonly noTargetPenaltyApplied: boolean;
}
```

Recommended constants:

```ts
const MEDIC_NO_TARGET_UTILITY = -140;
const MEDIC_WEAK_TARGET_UTILITY = 70;
const MEDIC_MEDIUM_TARGET_UTILITY = 180;
const MEDIC_STRONG_TARGET_UTILITY = 320;
```

Recommended bucket thresholds based on best revive value:

```ts
none: no candidates
weak: 1..139
medium: 140..279
strong: >= 280
```

Recommended revive value:

```ts
const medicReviveCandidateValue = (candidate: SeatCardSummary) => {
  let value = candidate.printedStrength * 10;
  if (hasAbility(candidate, "spy")) value += 360;
  if (hasAbility(candidate, "medic")) value += 220;
  if (hasAbility(candidate, "muster") || hasAbility(candidate, "muster_roach")) value += 170;
  if (hasAbility(candidate, "tight_bond")) value += 95;
  if (hasAbility(candidate, "morale_boost")) value += 70;
  if (hasAbility(candidate, "scorch") || hasAbility(candidate, "scorch_close") || hasAbility(candidate, "scorch_range") || hasAbility(candidate, "scorch_siege")) value += 140;
  if (candidate.deckLimit === 1) value += 15;
  return value;
};
```

For `scorePlayMove(...)`:

1. Compute the base card value with the flat Medic bonus removed for Medic sources.
2. Add `medicSourceUtility(features, card)` only when the played card has `medic`.
3. Preserve all existing Spy, Muster, opponent-passed, and card-count pressure logic.

Required behavior:

- Medic with zero revive candidates should lose the flat Medic bonus and receive the no-target utility penalty.
- This must not make Medic illegal or impossible to play; raw strength/hero value still counts.
- If the AI has no better useful move and needs tempo, it may still play a Medic with no target.
- Medic with a strong target should remain highly attractive.
- Medic with only weak targets should be playable but should not dominate clearly better non-Medic plays.

### 5. Include Medic Revive Tempo In Play Scoring

`estimateImmediateTempo(...)` currently counts the source card and linked Muster hand tempo, but not the expected Medic revive.

Add a conservative Medic revive tempo estimate for `board_row` Medic source plays:

```ts
const medicReviveTempoForSource = (features: LegalHeuristicV1Features, card: SeatCardSummary) => {
  if (!isMedicSource(card)) return 0;
  const candidates = medicReviveCandidates(features);
  // Use the best non-negative printed-strength contribution.
  // Spy targets are strategic value, not positive board tempo, because they
  // move to the opponent board.
};
```

Guidance:

- For non-Spy candidates, use the best printed strength across candidates.
- For Spy candidates, do not add positive board tempo here; their value belongs in `medicReviveCandidateValue(...)`.
- For Agile candidates, count the candidate once, not once per row.
- For no candidates, return `0`.

Then include this in `estimateImmediateTempo(...)` for own-side `board_row` Medic source plays.

This is intentionally approximate. Do not inspect hidden deck contents or run command simulation.

### 6. Add Hidden-Info-Safe Medic Timing Diagnostics

Update `src/game/ai/decisionTrace.ts` and `src/game/ai/explainLegalHeuristicV1Decision.ts`.

Add a new trace field:

```ts
readonly medicTimingAnalysis: AiDecisionMedicTimingAnalysis | null;
```

Preferred shape:

```ts
export type AiDecisionMedicTimingBucket =
  | "none"
  | "weak"
  | "medium"
  | "strong";

export interface AiDecisionMedicTimingAnalysis {
  readonly medicPlayLegal: boolean;
  readonly medicPlayCandidateCount: number;
  readonly ownDiscardReviveCandidateCount: number;
  readonly bestReviveStrengthBucket: AiDecisionTempoBucket;
  readonly bestReviveValueBucket: AiDecisionMedicTimingBucket;
  readonly noTargetMedicRisk: boolean;
  readonly selectedMedicWithNoTarget: boolean;
}
```

Definitions:

- `medicPlayLegal`: true when at least one legal `play_card` move has a Medic source card.
- `medicPlayCandidateCount`: number of unique Medic source cards in legal play-card moves. Count a card once even if Agile/row options create multiple moves.
- `ownDiscardReviveCandidateCount`: count of unique own-discard cards that are valid Medic revive candidates.
- `bestReviveStrengthBucket`: bucketized best non-Spy printed strength using existing `AiDecisionTempoBucket` thresholds.
- `bestReviveValueBucket`: `none` / `weak` / `medium` / `strong` from the contextual Medic helper.
- `noTargetMedicRisk`: true when `medicPlayLegal && ownDiscardReviveCandidateCount === 0`.
- `selectedMedicWithNoTarget`: true when the selected move is a Medic source play and `ownDiscardReviveCandidateCount === 0`.

Trace construction rules:

- For mulligan decisions, set `medicTimingAnalysis: null`.
- For prompt decisions, set it to null unless the prompt itself is a Medic prompt and you can populate aggregate prompt target counts safely. Simpler acceptable behavior: null for all prompt decisions in cFp29.
- For playing decisions, include it whenever `medicPlayLegal` is true. It may be null when no Medic play is legal.

Hidden-info rules:

- Do not include Medic source card names.
- Do not include revive target names.
- Do not include source IDs.
- Do not include instance IDs.
- Do not include raw card IDs.
- Do not include ability arrays.
- Do not include linked source IDs.
- Do not include prompt option IDs.

### Empty Discard: Medic No Longer Dominates

Fixture:

- AI has a legal Medic source card in hand.
- AI own discard pile is empty.

Expect:

### Empty Discard: Medic Can Still Be Played As Emergency Tempo

Fixture:

- AI has a Medic source card in hand.
- AI own discard pile is empty.
- AI has no better useful play and no safe pass.

Expect:

- Medic may be selected.
- `selectedMedicWithNoTarget === true`.
- Reason text should not claim the Medic ability has target value.

### Strong Revive Target: Medic Is Attractive

Fixture:

- AI has a Medic source card in hand.
- AI own discard has a strong non-hero unit, a Spy, or a high-value ability unit.
- AI has at least one other reasonable play.

Expect:

- Medic scoring includes contextual value.
- Medic can be selected if it is the best useful play.
- `ownDiscardReviveCandidateCount > 0`.
- `bestReviveValueBucket` is `medium` or `strong`.

### Weak Revive Target: Medic Is Not Overvalued

Fixture:

- AI has a Medic source card in hand.
- AI own discard has only a weak low-strength non-ability unit.
- AI has a stronger normal unit in hand.

Expect:

- Medic does not dominate the stronger normal unit only because it has the `medic` ability.
- `bestReviveValueBucket === "weak"`.

### Agile Target Count Is Unique

Fixture:

- AI own discard has one Agile unit with two legal rows.

Expect:

- `ownDiscardReviveCandidateCount === 1`, not `2`.
- No policy or trace field counts one Agile unit once per row.

### Prompt Ranking Still Values Medic Targets

Fixture:

- AI is already resolving a Medic prompt.
- A target card with `medic` is available alongside a plain low-value unit.

Expect:

- Prompt target ranking still prefers the Medic target if its strategic value is higher.
- This proves removing the source-play flat bonus did not accidentally erase prompt-target Medic value.

## Acceptance Criteria

- `legal-heuristic-v1` no longer gives Medic source plays an unconditional flat `+260` source-play bonus.
- Medic source play value depends on own-discard revive candidates.
- Empty own discard makes Medic source plays materially less attractive but not illegal.
- Strong own-discard revive targets make Medic source plays attractive.
- Weak own-discard revive targets do not overvalue Medic versus clearly stronger non-Medic plays.
- Prompt target ranking still values Medic targets when resolving a Medic prompt.
- Agile revive targets count as one unique candidate in diagnostics.
- Product diagnostic exports include hidden-info-safe Medic timing aggregates.
- Product diagnostic exports still reject raw card names, source IDs, instance IDs, raw card IDs, raw ability arrays, linked source IDs, and raw move/option IDs.
- `explainLegalHeuristicV1Decision(...)` and `legalHeuristicPolicyV1.selectMove(...)` remain move-identical.
- Benchmark artifacts are refreshed deterministically.
- Documentation and phase report are updated.
