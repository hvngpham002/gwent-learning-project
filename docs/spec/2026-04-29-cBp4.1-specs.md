# Implementation Spec: Cluster B, Phase 4.1 - Official Combined-Card Data Cleanup

## Goal

Clean up the combined-card tail left by cBp4 before building official faction starter decks.

This phase is a narrow catalog/data correction:

- split the two combined Skellige Berserker scrape candidates into real catalog base/replacement source records;
- link Berserker base cards to their side-deck replacements with `linkedSourceIds[0]`;
- mark replacement forms as side-deck-only so Deck Builder V1 cannot put them in a main deck by accident;
- remove the extra combined `neutral.cow-bovine-defense-force` source that cBp4 promoted;
- keep the existing legacy split `neutral.cow` and `neutral.bovine-defense-force` records, but document that Avenger remains unimplemented.

Do not implement new engine rules, leaders, faction starter decks, side-deck authoring UI, Avenger, Summon, or route/UI redesigns in this phase.

## Current Context

cBp4 promoted 157 official non-leader candidates into permanent catalog files and intentionally deferred:

- `skellige.berserker-vildkaarl`
- `skellige.young-berserker-young-vildkaarl`

The cBp4 report also identified another combined scrape-style source:

- `neutral.cow-bovine-defense-force`

Unlike Skellige Berserkers, the Neutral Cow/Bovine pair already exists in the legacy catalog as separate records:

- `neutral.cow`
- `neutral.bovine-defense-force`

`neutral.cow` still uses the planned `avenger` ability, so it remains a future rules concern. The cBp4-added combined `neutral.cow-bovine-defense-force` is redundant and should be removed from permanent catalog promotion rather than treated as a long-term playable source.

cCp9 already implemented the engine behavior needed by Skellige Berserkers once data is split correctly: a Berserker's `linkedSourceIds[0]` points to a replacement source in the controlling seat's side deck, and Mardroeme transforms the card through that side-deck replacement.

## Product And Architecture Decisions

Use these decisions unless the user explicitly changes them later:

- Permanent catalog card packs remain plain TypeScript data.
- Product catalog data must not import Game8 scrape JSON or staging candidates at runtime.
- Split Skellige replacement forms should exist in `currentCatalogCards` so catalog validation and future presets can reference them.
- Replacement forms must not be addable to a main deck in Deck Builder V1.
- Use a data tag `side_deck_only` on replacement forms.
- Minimal deck-builder view-model filtering/validation is in scope only to prevent `side_deck_only` sources from entering the main deck.
- Do not add side-deck editing UI or full official Skellige presets yet.
- Do not remove the legacy `neutral.cow` or `neutral.bovine-defense-force` records.
- Do not implement Avenger in this phase.

### 5. Prevent Side-Deck-Only Main-Deck Leakage

Update Deck Builder V1 logic only enough to prevent side-deck-only replacement cards from entering a main deck.

Requirements:

- Add a narrow helper such as:

```ts
export const isSideDeckOnlyCard = (card: CatalogCardSource): boolean =>
  card.tags.includes("side_deck_only");
```

- `getDeckBuilderAddState` should return a blocked state for side-deck-only cards.
  - Suggested `reasonCode`: `side_deck_only`
  - Suggested visible reason: `side deck only`
- `validateDeckPreset` should emit an error if an imported/local deck has a side-deck-only card in `mainDeck`.
  - Suggested code: `side_deck_only_main_deck`
- `filterCardPool` or the card-pool construction path should hide side-deck-only cards from the normal main-deck pool.
- Do not add side-deck editing UI.
- Do not make side decks valid in Deck Builder V1; non-empty `sideDeck` remains unsupported.
