## Context

`legal-heuristic-v1` is now strong enough for useful product playtests, but a
new diagnostic export exposed a weather-placement weakness:

- Human deck: Official Monsters Starter.
- AI deck: `current-nilfgaard`.
- AI policy: `legal-heuristic-v1`.
- Seed: `ep4-mp5514al`.
- AI repeatedly played high-value non-hero unit cards into its own weathered
  row.
- In the user-observed game, two strong Infantry-like cards were effectively
  reduced from large printed value to very low effective board value because
  the row was under weather.

Relevant trace symptoms from the diagnostic:

- At decision indexes 11 and 13, AI selected `play_card` to `own ranged`.
- `publicState.weatherCardCount` was already `1`.
- AI's own ranged row already had a `neutral.commanders-horn`.
- Candidate scores still valued `own ranged` at `185`.
- This indicates the policy was scoring the unit primarily from printed
  strength / strategic value and not from weather-adjusted effective
  contribution.

This is not an engine rules bug. The engine correctly applies weather. This is
a policy-evaluation bug inside `legal-heuristic-v1`.

## Why This Is `cFp30`

cFp29 fixed Medic timing. cFp30 is a distinct v1 policy calibration:

- It changes how `legal-heuristic-v1` values unit placement into weathered rows.
- It adds hidden-info-safe diagnostics around weather-placement risk.
- It should not change general pass behavior, mulligan behavior, Medic timing,
  engine scoring, legal moves, UI, or benchmark suite definitions.

## Goal

Make `legal-heuristic-v1` avoid wasting high-value non-hero units into its own
weathered rows when better legal alternatives exist.

The patch should:

1. Estimate non-hero unit placement tempo using weather-adjusted effective
   strength for the target row.
2. Preserve hero immunity to weather.
3. Preserve existing special/weather/Scorch/Decoy/Medic/leader logic except
   where it depends on the shared immediate-tempo estimate.
4. Add hidden-info-safe weather-placement diagnostics to playing-phase traces.
5. Preserve selected-move parity between
   `explainLegalHeuristicV1Decision(input).move` and
   `legalHeuristicPolicyV1.selectMove(input)`.

## Existing Rule Contract To Preserve

Use `src/game/core/scoring.ts` only as a reference for the engine scoring order.
Do not modify the engine.

Important scoring facts:

- Heroes are immune to weather.
- Weather affects non-hero units on affected rows.
- Biting Frost affects close combat rows.
- Impenetrable Fog affects ranged rows.
- Torrential Rain affects siege rows.
- Skellige Storm affects ranged and siege rows.
- Clear Weather removes weather but is not itself an active row penalty.
- Commander's Horn can still double a weather-reduced non-hero unit after
  weather is applied, so a 10-strength non-hero in a normal weathered horn row
  should be approximated as roughly 2 effective points, not 20.
- King Bran reduces weather penalty for his side in engine scoring. If the
  necessary public leader ability information is already available to v1 policy
  code, approximate this. If not readily available, document it as deferred in
  the report rather than pulling hidden or engine-private data into the policy.

## Required Implementation

### 1. Add Weather-Aware Unit Placement Tempo

File: `src/game/ai/legalHeuristicPolicyV1.ts`

Current likely problem area:

- `estimateImmediateTempo(...)` handles `move.target.kind === "board_row"`.
- It currently uses `card.printedStrength` as the core signed strength.
- That ignores active weather on the target row.

Implement a pure helper near the existing weather helpers. Suggested names:

```ts
const activeWeatherRows = (features: LegalHeuristicV1Features): ReadonlySet<CatalogRow> => { ... };

const isRowWeatheredForPolicy = (
  features: LegalHeuristicV1Features,
  row: CatalogRow,
) => boolean;

const effectivePlacedStrengthForPolicy = (
  features: LegalHeuristicV1Features,
  card: SeatCardSummary,
  target: Extract<PlayCardMove["target"], { kind: "board_row" }>,
) => number;
```

Implementation details:

- Derive active weather rows only from `features.input.observation.weather`.
- Use card abilities or source IDs already present in the public-safe
  `SeatCardSummary` weather summaries.
- Do not count `clear_weather` as active weather.
- If a non-hero card is played to a weathered row, its base placed strength
  should be approximated as `1`.
- If a hero is played to a weathered row, keep printed strength.
- If the target row is not weathered, keep printed strength.
- If a physical Commander's Horn is already on that target row, approximate the
  placed card's effective contribution after weather by doubling the base placed
  strength.
- If target side is opponent, preserve signed negative tempo using the
  weather-adjusted strength.
- Do not alter linked Muster tempo, Medic revive tempo, Scorch bonuses, or
  strategic card-value bonuses in this phase except that their final score now
  uses the weather-adjusted placement tempo.

Acceptance examples:

- Non-hero strength 10 to own unweathered ranged row: base placement tempo
  remains about `10`.
- Non-hero strength 10 to own Fogged ranged row: base placement tempo becomes
  about `1`.
- Non-hero strength 10 to own Fogged ranged row with existing Commander's Horn:
  base placement tempo becomes about `2`.
- Hero strength 10 to own Fogged ranged row: base placement tempo remains about
  `10`.
- Spy strength 4 to opponent Fogged ranged row: signed base placement tempo
  should be about `-1`, not `-4`.

### 3. Add Hidden-Info-Safe Weather Placement Diagnostics

Add a playing-phase trace field. Suggested type names:

```ts
export type AiDecisionWeatherPlacementStrengthBucket =
  | "none"
  | "low"
  | "medium"
  | "high";

export interface AiDecisionWeatherPlacementAnalysis {
  readonly selectedMoveIntoWeatheredRow: boolean;
  readonly selectedMoveSide: "own" | "opponent" | "none";
  readonly selectedMoveRow: CatalogRow | "none";
  readonly selectedPrintedStrengthBucket: AiDecisionWeatherPlacementStrengthBucket;
  readonly selectedEffectiveStrengthBucket: AiDecisionWeatherPlacementStrengthBucket;
  readonly ownWeatheredRows: readonly CatalogRow[];
  readonly opponentWeatheredRows: readonly CatalogRow[];
  readonly candidateWeatheredOwnRowPlayCount: number;
  readonly candidateWeatheredOpponentRowPlayCount: number;
}
```

The exact field names may vary, but they must follow these constraints:

- No card names.
- No source IDs.
- No card IDs.
- No linkedSourceIds.
- No raw ability arrays.
- No raw move IDs.
- No hidden opponent hand data.
- Public row names are allowed.
- Counts and buckets are allowed.

Recommended bucket mapping:

- `"none"` for 0 or missing.
- `"low"` for 1-3.
- `"medium"` for 4-7.
- `"high"` for 8+.

Where to wire it:

- `src/game/ai/decisionTrace.ts`
- `src/game/ai/explainLegalHeuristicV1Decision.ts`
- `src/components/gwent/matchDiagnostics.ts` if a targeted scanner is needed.

If the existing product diagnostic hidden-info scan already covers the new
field, still add focused tests proving the new field does not leak raw unsafe
tokens.

### 4. Reason Text

Update `src/game/ai/explainLegalHeuristicV1Decision.ts` so selected-move
reasons can surface weather placement when relevant.

Examples:

- If a non-pass move is selected and the selected card avoids a weathered row
  because a better unweathered placement exists, reason text may stay generic.
- If the selected move is still into a weathered row because it is the best or
  only useful option, reason text should not claim full raw strength. Suggested
  wording: `weathered row penalty accepted — best useful move`.
- If a high printed-strength weathered-row play is rejected, diagnostics should
  make that visible through candidate counts/buckets; do not expose card names.

Reason text must remain deterministic and selected-move-aware.
