# Implementation Spec: Cluster E, Phase 5.2 - Deck Builder Generated Cards And Card Inspection

## Goal

Fix the deck-builder UX confusion around replacement/generated cards and add card-level context actions.

This phase should make the user-facing model match Witcher 3 Gwent:

- players add **Kambi**, **Cow**, **Berserker**, and **Young Berserker** to the main deck;
- cards like **Hemdall**, **Bovine Defense Force**, **Vildkaarl**, and **Young Vildkaarl** are generated/replacement cards, not manually deck-built cards;
- the engine may continue using `deck.sideDeck` internally as deterministic replacement storage, but the product UI must not present this as a player-managed "side deck" rule.

Also add a card context menu:

- right-click a card to show `add`, `remove`, and `inspect` actions where applicable;
- `inspect` opens a modal with complete card information.

## Product Decisions

- Do **not** expose "side deck" as a user-managed deck-building feature.
- Keep `CatalogDeckPreset.sideDeck` as an internal/persistence field for deterministic generated replacements. Do not rename this TypeScript field in this phase.
- User-facing label should be **generated cards** or **summoned replacements**, not "side deck".
- Generated/replacement cards are derived from main-deck linked cards and are not directly addable/removable.
- Hemdall should be visible in the deck builder when Kambi is present, but not in the main addable pool.
- The card inspect modal is read-only. Do not add editing here; Card Studio remains the edit/create surface.
- Right-click should not replace existing left-click behavior.

## Scope

### 1. Rename User-Facing "Side Deck" Language

Update deck-builder labels, copy, docs, and tests:

- Replace `side deck · linked replacements` with a clearer label such as `generated cards` or `summoned replacements`.
- Use supporting copy where space allows:
  - "Automatically created by cards in your deck."
  - "Not manually added."
- Update any visible validation/error copy that says "side deck" to a user-facing term where it appears in the UI.
- Keep internal validation codes such as `side_deck_only_main_deck`, `wrong_faction_side_deck_card`, and `side_deck_count_mismatch` unchanged unless there is a strong reason to migrate them.
- Update `docs/deck-builder/authentic-deck-builder-v1.md` to explain:
  - internal `sideDeck` is an engine/storage implementation detail;
  - UI presents these as generated cards;
  - examples: Kambi -> Hemdall, Cow -> Bovine Defense Force, Berserker -> Vildkaarl, Young Berserker -> Young Vildkaarl.

Acceptance detail:

- The UI must no longer display the phrase `side deck · linked replacements`.
- It is acceptable for developer docs to mention `sideDeck` when referring to the internal field.

### 2. Make Generated Cards Inspectable And Visually Clear

Current right-rail generated replacement entries are plain text rows. Improve them enough that a user can discover Hemdall.

Requirements:

- Render generated cards as compact inspectable entries using the actual card art, or a small authentic card thumbnail plus name/count.
- Generated entries must include Kambi/Hemdall and Berserker/Vildkaarl pairs when present.
- Generated entries should be read-only:
  - no direct add;
  - no direct remove;
  - context menu should offer `inspect` and may show disabled `add`/`remove` with clear reasons if the common menu always renders all actions.
- Clicking or context-clicking a generated card should be able to inspect it.
- The UI should make clear what main-deck source generated it when possible:
  - e.g. Hemdall: "generated by Kambi";
  - Bovine Defense Force: "generated by Cow";
  - Vildkaarl: "generated by Berserker";
  - Young Vildkaarl: "generated by Young Berserker".

Suggested implementation:

- Add a pure view-model helper that maps generated replacement cards to their generating main-deck sources:

```ts
buildGeneratedCardItems(deck, cards): Array<{
  card: CatalogCardSource;
  count: number;
  generatedBy: CatalogCardSource[];
}>
```

- Reuse `computeLinkedSideDeckRequirements` as the count source, but enrich it with the main-deck card(s) whose `linkedSourceIds` produce each replacement.

### 3. Add Card Context Menu

Add a deck-builder card context menu for card surfaces and card rows.

Trigger requirements:

- Right-click/contextmenu on a card in the main card pool.
- Right-click/contextmenu on a card in the "cards in deck" list.
- Right-click/contextmenu on a generated card.
- Prefer adding a keyboard/mobile fallback:
  - either a small menu button on list rows/thumbnail wrappers;
  - or support Enter/Space on a focused menu trigger.

Menu actions:

- `add`
  - enabled when the card is main-deck eligible and `getDeckBuilderAddState(...).canAdd` is true;
  - disabled or omitted when at deck limit, special cap, wrong faction, blocked source, side-deck-only/generated, etc.;
  - dispatches the existing `addCardToDeck` path.
- `remove`
  - enabled when the card exists in `activeDeck.mainDeck` with count > 0;
  - disabled or omitted for generated-only cards unless their source also exists in the main deck;
  - dispatches the existing `removeCardFromDeck` path.
- `inspect`
  - always enabled for any known `CatalogCardSource`;
  - opens the inspect modal.

Behavior requirements:

- Right-click must call `event.preventDefault()`.
- Menu should close when:
  - an action is selected;
  - clicking outside;
  - pressing `Escape`;
  - opening the inspect modal.
- Menu should be positioned near the pointer but clamped inside the viewport/container so it does not overflow offscreen.
- Menu must not break current left-click add behavior in the pool.
- Menu must not show opponent/hidden runtime data. This is a catalog deck-builder surface only.

Suggested implementation:

- Add local state in `AuthenticDeckBuilderScreen`:
  - `contextMenu: { sourceId, x, y, origin: "pool" | "deck" | "generated" } | null`.
- Add helpers:
  - `openCardContextMenu(event, sourceId, origin)`;
  - `closeCardContextMenu()`;
  - `inspectCard(sourceId)`.
- Keep action computation pure enough to unit test if it becomes non-trivial:

```ts
buildDeckBuilderCardActions({ deck, card, cards, blockedSources, origin })
```

### 4. Add Inspect Modal

Add a read-only inspect modal for catalog card sources in the deck builder.

Modal content should include:

- large authentic card art (`AuthenticCard` size `lg` or existing large foundation size);
- card name;
- source ID;
- faction;
- kind;
- strength for units/heroes;
- row(s);
- ability list with display names, status, glyph, and descriptions where available;
- tags;
- deck limit;
- image path;
- linked/generated relationships:
  - if the card has `linkedSourceIds`, list linked generated cards;
  - if the card is generated by other cards in the current catalog/deck, list source cards;
- current deck count;
- current generated count if applicable;
- add/remove availability and reason where useful.

Modal controls:

- `close`;
- optional `add` and `remove` actions using the same enabled/disabled rules as the context menu.

Style requirements:

- Use existing authentic modal/alert/deck-builder styling.
- Keep text compact; do not use oversized body copy.
- Must work at desktop and mobile widths without text overflow.

Accessibility:

- `role="dialog"` and `aria-modal="true"`.
- Modal title should be the card name.
- Close on Escape.
- Return focus sensibly if practical; at minimum do not trap focus in a broken way.

### 5. Tests

Add focused tests.

Unit/view-model tests:

- Generated card label/data:
  - Kambi produces Hemdall as a generated card.
  - Berserker produces Vildkaarl as a generated card.
  - Generated cards include a `generatedBy` source.
- Action availability:
  - pool card can `add` when legal;
  - deck card can `remove`;
  - generated Hemdall cannot be added directly;
  - generated Hemdall can be inspected.
- Existing side-deck internal validation tests should remain, but visible copy expectations should use generated-card language where applicable.

Browser smoke / Playwright:

- Update `tests/e2e/engine-shell-smoke.spec.ts` because this changes visible deck-builder behavior.
- Add or extend a deck-builder smoke:

  - assert Hemdall appears under generated cards when Kambi is present;

  - choose `inspect` and assert the modal shows source ID, ability/row/faction details;

Run mobile overflow smoke if the new menu/modal affects layout.

## Out Of Scope

Do not do these in cEp5.2:

- Do not change engine rules.
- Do not rename `CatalogDeckPreset.sideDeck` or rewrite persistence schema.
- Do not make Hemdall/Bovine/Vildkaarl manually selectable in the main pool.
- Do not add free-form generated-card editing.
- Do not change Card Studio editing semantics.
- Do not implement leader abilities.
- Do not change AI, simulation, or ML export.
- Do not modify card image assets unless the user explicitly asks.
- Do not touch the existing user-modified `public/images/scoiatael/Elven_Skirmisher.png` unless explicitly instructed.

## Acceptance Criteria

- Deck builder no longer presents generated replacements as a player-facing "side deck".
- Hemdall is visible and inspectable when Kambi is in the active deck.
- Generated replacement cards are clearly read-only/derived.
- Right-click card context menu works on pool cards, deck cards, and generated cards.
- Inspect modal shows complete catalog card details and closes correctly.
- Add/remove actions reuse existing deck mutation helpers and preserve validation.
- Browser smoke covers generated cards and inspect menu/modal behavior.
- Project state and deck-builder docs are updated.
