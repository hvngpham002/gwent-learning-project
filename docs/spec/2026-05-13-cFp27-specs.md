## Context

`legal-heuristic-v1` now has usable play/pass behavior and hidden-info-safe product decision diagnostics. Recent human playtests suggest the next weakness is the mulligan phase:

- v1 already redraws clearly-linked dead cards:
  - Roach when a `muster_roach` caller such as Geralt/Ciri is also in hand;
  - one-way linked Muster payloads when the caller is in hand;
  - duplicate same-source Muster payloads beyond the first copy.
- v1 currently keeps the hand when none of those linked cases fire.
- A product playtest (`ep4-mp3ex8vu`) suggested the AI may keep Roach or similar low standalone units even when no immediate caller is in hand. The current diagnostic export cannot prove the hidden hand identity, because cFp25 correctly redacts AI hand card names.
- The diagnostic trace for mulligan currently says only `"mulligan selection"` with selected label `"keep hand"` or `"mulligan hidden card"`. That is too thin for analyzing v1 policy behavior.

This phase should make mulligan policy slightly smarter and make mulligan diagnostics useful without exposing hidden AI hand identities.

## Why This Is `cFp27`, Not `cFp26.2`

`cFp26` and `cFp26.1` were repairs to pass/catch-up diagnostics. This phase adds a distinct capability slice:

- policy-aligned mulligan diagnostics;
- conservative redraw scoring beyond linked/Muster payloads;
- benchmark artifact refresh for a real selected-move behavior change.

Use a new phase number: `cFp27`.

## Goal

Improve `legal-heuristic-v1` mulligan behavior and diagnostics while preserving hidden-info safety.

The new policy should:

1. Preserve all existing linked/Muster mulligan behavior.
2. Add a conservative redraw category for low standalone no-ability units, catching cards like Roach when no Geralt/Ciri-style caller is currently in hand.
3. Avoid redrawing strategically important low-strength cards such as Spies, Medics, Decoys, Scorch/weather/specials, tight-bond pieces, morale pieces, Muster callers, Berserkers/Mardroeme pieces, and Heroes.
4. Explain mulligan decisions through hidden-info-safe diagnostic fields and redacted candidate summaries.
5. Keep `explainLegalHeuristicV1Decision(input).move` exactly equal to `legalHeuristicPolicyV1.selectMove(input)`.

```ts
type LegalHeuristicV1MulliganReasonKind =

const rankMulliganCandidates = (
  features: LegalHeuristicV1Features,

  // ...

```

Exact names may differ, but the structure must be equivalent.

Hard requirements:

1. `chooseMulliganMove(...)` must consume the shared ranker.
2. Existing sort semantics must stay deterministic:
   - higher confidence first;
   - lower standalone value first;
   - lower printed strength first;
   - `moveId` as final deterministic tie-breaker.
3. Existing linked/Muster behavior must be preserved:
   - Roach with a `muster_roach` caller remains the top redraw class.
   - One-way linked payloads remain higher confidence than same-source duplicate payloads.
   - Same-source Muster duplicates still keep the first deterministic copy and redraw extras.
   - Heroes are not redrawn unless they are explicit linked summoned targets under existing logic.

### 2. Add Conservative Low-Standalone Unit Redraw

Add one new redraw category: `"low_standalone_unit"`.

A card may receive this redraw category only when all of the following are true:

1. `card.kind === "unit"`.
2. `card.printedStrength <= 3`.
3. The card has no strategic positive ability:
   - abilities must be empty, absent, or exactly `["none"]`.
   - Do not treat `spy`, `medic`, `muster`, `muster_roach`, `tight_bond`, `morale_boost`, `agile`, `berserker`, `mardroeme`, `summon`, `avenger`, row-Scorch, whole-board Scorch, weather, Clear Weather, Commander's Horn, or Decoy as low-standalone redraws.
4. The card is not a Hero.
5. The card is not a special/weather card.
6. The card is not a one-way linked caller or same-source Muster caller.
7. There is a legal one-card `choose_mulligan` move for that card.

Recommended confidence:

```ts
low_standalone_unit: 80
```

This is intentionally below:

- Roach-with-caller linked payload confidence;
- one-way linked payload confidence;
- same-source Muster duplicate confidence.

This catches `neutral.roach` when it is simply a low standalone unit, without introducing a source-ID-specific `"redraw Roach"` branch. A future policy can add more nuanced card-specific mulligan profiles, but this phase should stay generic and conservative.

### 3. Add Hidden-Info-Safe Mulligan Diagnostics

Extend `src/game/ai/decisionTrace.ts` with a new optional trace field:

```ts
readonly mulliganAnalysis?: AiDecisionMulliganAnalysis | null;
```

Define a hidden-info-safe analysis shape. Suggested:

```ts
export interface AiDecisionMulliganAnalysis {
  readonly mulliganLegal: boolean;
  readonly selectedCardCount: number;
  readonly candidateCount: number;
  readonly selectedReasonKind:
    | "linked_payload"
    | "muster_duplicate"
    | "low_standalone_unit"
    | "keep_hand"
    | "unknown";
  readonly selectedConfidence: number | null;
  readonly selectedStandaloneValueBucket: "low" | "medium" | "high" | null;
  readonly topCandidateConfidence: number | null;
  readonly topCandidateReasonKind:
    | "linked_payload"
    | "muster_duplicate"
    | "low_standalone_unit"
    | null;
}
```

Exact field names may differ, but the exported information must be equivalent.

Hidden-info constraints:

1. Do not include card names.
2. Do not include source IDs.
3. Do not include instance IDs.
4. Do not include raw `moveId`.
5. Do not include raw `cardIds`.
6. Do not include exact ability lists for hidden cards.
7. Do not include `linkedSourceIds`.
8. Do not include a category so specific that it reveals a unique card identity in normal play, such as `"roach_without_caller"`.

Map internal reason kinds to broader exported reason kinds:

```ts
linked_roach_payload       -> linked_payload
one_way_linked_payload     -> linked_payload
same_source_muster_duplicate -> muster_duplicate
low_standalone_unit        -> low_standalone_unit
```

`low_standalone_unit` is allowed because it describes a broad card-quality class, not a named card.

Value bucket recommendation:

```ts
standaloneValue < 80    -> "low"
standaloneValue < 180   -> "medium"
otherwise               -> "high"
```

Tune bucket thresholds only if the existing `cardStrategicValue(...)` scale makes these obviously wrong; document any deviation in the report.

### 4. Wire Mulligan Diagnostics Into `explainLegalHeuristicV1Decision`

Update `src/game/ai/explainLegalHeuristicV1Decision.ts`.

Current non-playing-phase trace handling treats mulligan as a generic phase decision. Replace that for mulligan only:

- When `input.observation.phase === "mulligan"`, build `LegalHeuristicV1Features`.
- Reuse the policy's shared mulligan ranker/diagnostic helper.
- Add `mulliganAnalysis` to the trace.
- Keep `passAnalysis: null`.
- Keep selected move label redacted:
  - `"keep hand"` for zero-card mulligan;
  - `"mulligan hidden card"` for one-card mulligan.
- Reason text should become more useful but still hidden-info-safe:
  - selected redraw from linked payload: `"mulligan hidden card - linked payload"`
  - selected redraw from duplicate Muster: `"mulligan hidden card - duplicate muster payload"`
  - selected redraw from low standalone unit: `"mulligan hidden card - low standalone unit"`
  - keep: `"keep hand - no redraw target above threshold"`

Do not expose the hidden card's identity in the reason.

## Required Tests

### Policy Behavior Tests

1. Existing linked behavior still passes:
   - Roach with Geralt/Ciri-style `muster_roach` caller redraws Roach.
   - base Gaunter keeps base and redraws Darkness payload.
   - same-source Muster keeps first copy and redraws duplicate.
   - one-way linked caller keeps caller and redraws target.
   - no clear redraw target keeps hand.

2. New low-standalone behavior:
   - Low no-ability strength-3 unit is redrawn when no stronger redraw class exists.
   - `neutral.roach` with no `muster_roach` caller is redrawn through the generic low-standalone rule.
   - If both Roach-with-caller and a low standalone unit are available, Roach-with-caller wins because linked payload confidence is higher.

3. Non-redraw safeguards:
   - Strength-3 Spy is kept.
   - Strength-3 Medic is kept.
   - Strength-3 Tight Bond or Morale Boost unit is kept.
   - Strength-3 Agile-only unit is kept for now unless there is a stronger explicit linked redraw. This avoids damaging Scoia'tael/Skellige row-flexibility until a faction-aware mulligan phase exists.
   - Weather/special cards are kept by the low-standalone rule.
   - Heroes are kept unless existing linked-target logic applies.

4. Determinism:
   - Two equal low-standalone redraw candidates choose by lower standalone value, then lower printed strength, then move ID.
