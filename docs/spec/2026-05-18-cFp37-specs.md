Cluster: F - AI / Behavior

## Summary

cFp36 added a round-resource budget gate to `legal-heuristic-v1`.
cFp36.1 reviewed the benchmark artifacts and found that cFp36 improved the
narrow `round_one_overinvestment` signal, but caused a broader pass-policy
regression:

```text
cFp35 baseline starter matrix: 102/16/2
repaired cFp36 starter matrix: 89/29/2
cFp35 suspicious_pass findings: 222
repaired cFp36 suspicious_pass findings: 318
```

cFp37 must keep the useful cFp36 diagnostics but narrow the behavior gate so it
does not override existing "continue", "fight last gem", or single-move catch-up
signals. This is a behavior repair, not a new strategy feature.

## Evidence

cFp36.1 decision note:

- cFp36 improved `round_one_overinvestment`: `10 -> 5`.
- cFp36 did not improve total `round_resource_exhaustion` enough: `44 -> 40`.
- starter matrix regressed: `102/16/2 -> 89/29/2`.
- total failure-mining findings increased: `295 -> 397`.
- `suspicious_pass` increased: `222 -> 318`.
- new suspicious-pass findings often had:
  - `roundInvestmentRecommendation === "continue"`; or
  - `roundInvestmentRecommendation === "fight_last_gem"`.

Interpretation:

The resource budget helper is useful as a diagnostic, but the current
`shouldPassForRoundInvestment(...)` priority is too broad. It can select pass
even when other policy diagnostics say the AI should continue fighting.

## Goals

1. Keep cFp36 round-resource diagnostics in decision traces.
2. Prevent cFp36 resource budgeting from forcing pass when round-investment
   says `continue`.
3. Prevent resource-preservation pass on last-gem fight lines when the public
   upper bound can still win.
4. Prevent resource-preservation pass when a single-move catch-up exists and
   the public upper bound can still win.
5. Preserve legitimate cFp31/cFp32 pass behavior:
   - stop-loss sacrifice when catch-up is impossible;
   - future-hand preservation when the diagnostic recommendation is truly
     `preserve_future_hand`;
   - non-elimination sacrifice when the diagnostic recommendation is truly
     `sacrifice_round`.
6. Preserve all existing exceptions for Spy/card-advantage, useful leader,
   match-winning play, round 3, one-card hand, prompt resolution, and hidden
   information.
7. Refresh benchmark and failure-mining artifacts after the behavior change.

## Non-Goals

Do not change:

- engine rules, legal moves, scoring, prompts, round resolution, or faction
  rules;
- `legal-heuristic-v0`;
- mulligan strategy;
- Scoia'tael first-turn choice strategy;
- weather-aware placement scoring;
- Medic timing thresholds;
- catalog data, deck presets, benchmark suite membership, UI behavior, or route
  behavior;
- H100/Slurm workflow, ratings, search, self-play, ML training, or product
  difficulty tiers.

Do not "fix" the cFp36 regression by deleting all round-investment behavior.
cFp31/cFp32 pass behavior should remain; only the cFp36 resource gate should be
scoped down.

## Required Behavior Design

### 1. Split The cFp36 Resource Gate From Older Round-Investment Gates

In `shouldPassForRoundInvestment(...)`, cFp36 currently has a broad branch like:

```ts
if (analysis.resourceExhaustionRecommended && candidate.kind === "play_card") {
  if (features.round >= 3) return false;
  return true;
}
```

Replace that with a narrower helper. Suggested shape:

```ts
const shouldPassForResourceExhaustion = (
  features: LegalHeuristicV1Features,
  candidate: PlayCardMove | UseLeaderMove | null,
  analysis: AiDecisionRoundInvestmentAnalysis,
  passDiagnostics: LegalHeuristicV1PassDecisionDiagnostics,
): boolean => {
  // exact rules below
};
```

The name can differ, but the logic must be factored enough to test directly or
through focused fixtures.

### 2. Hard Blocks For Resource-Gate Pass

The cFp36 resource gate must return `false` when any of these is true:

1. `analysis.resourceExhaustionRecommended === false`.
2. `candidate` is null.
3. `candidate.kind !== "play_card"`.
4. `features.round >= 3`.
5. `features.ownGems <= 1`.
6. `features.opponentPassed === true`.
7. `analysis.selectedMoveIsCardAdvantage === true`.
8. `analysis.recommendation === "continue"`.
9. `analysis.recommendation === "fight_last_gem"`.
10. `passDiagnostics.hasSingleMoveCatchUp === true` and
    `passDiagnostics.policyUpperBoundCanWinRound === true`.

The important policy intent:

- cFp36 may say "resource pressure exists".
- It may not force pass unless the broader round-investment recommendation also
  says the round should be preserved or sacrificed.

### 3. Allowed Resource-Gate Pass

The cFp36 resource gate may return `true` only when all are true:

1. `analysis.resourceExhaustionRecommended === true`.
2. `candidate.kind === "play_card"`.
3. `features.round < 3`.
4. `features.ownGems > 1`.
5. `features.opponentPassed === false`.
6. `analysis.selectedMoveIsCardAdvantage === false`.
7. `analysis.recommendation === "preserve_future_hand"` or
   `analysis.recommendation === "sacrifice_round"`.
8. no single-move catch-up is available while upper bound can still win.

Do not weaken the existing stop-loss gate. If `analysis.stopLossRecommended`
is true and the candidate is a play-card, stop-loss may still pass.

### 4. Explanation Text Must Match Selection

`explainLegalHeuristicV1Decision.ts` must not claim a selected pass is from
resource pressure when cFp37 blocked the resource gate.

Required explanation behavior:

- If selected move is pass because resource gate is allowed:
  - reason kind should be `policy-round-investment`;
  - reason should mention resource budget / future hand / sacrifice.
- If selected move is a play-card while `resourceExhaustionRecommended === true`
  but cFp37 blocks the pass due to `continue`, `fight_last_gem`, or
  single-move catch-up:
  - reason must explain that resource pressure was ignored or subordinated;
  - do not use "round resource budget exceeded — preserve future hand" for a
    play-card unless the policy actually preserved by passing.

Suggested safe strings:

```text
round resource pressure ignored — continue recommendation
round resource pressure ignored — last-gem fight
round resource pressure ignored — single-move catch-up
```

Use different wording if cleaner, but keep it hidden-info-safe and test it.

### 5. Diagnostics

Prefer not to add new trace fields unless required. Existing fields
(`recommendation`, `catchUpStatus`, `resourceExhaustionRecommended`,
`resourceExhaustionReason`, pass-analysis fields) should be enough.

If the implementation adds a new safe enum such as `resourceGateOutcome`, then:

- define it in `src/game/ai/decisionTrace.ts`;
- populate it in both policy trace and explanation trace paths;
- update `scanRoundInvestmentAnalysis(...)` in `matchDiagnostics.ts`;
- add product-diagnostics hidden-info scanner tests.

Do not add card names, source IDs, source card IDs, action IDs, hand contents,
deck contents, ability arrays, or raw move labels to diagnostics.

## Required Tests

Add focused tests in `tests/game/engineAiPolicy.test.ts`.

Minimum required behavior tests:

1. `resourceExhaustionRecommended === true` with
   `recommendation === "continue"` selects play-card, not pass.
2. `resourceExhaustionRecommended === true` with
   `recommendation === "fight_last_gem"` and
   `policyUpperBoundCanWinRound === true` selects catch-up/play, not pass.
3. `hasSingleMoveCatchUp === true` and `policyUpperBoundCanWinRound === true`
   blocks the cFp36 resource-gate pass.
4. `recommendation === "preserve_future_hand"` with resource exhaustion still
   selects pass.
5. `recommendation === "sacrifice_round"` with resource exhaustion still
   selects pass.
6. stop-loss pass still works when upper bound cannot win and
   `analysis.stopLossRecommended === true`.
7. Spy/card-advantage still ignores resource pressure and plays.
8. useful `use_leader` still ignores resource pressure and plays.
9. match-winning play when opponent is on last gem still plays.
10. round 3 still does not pass due to cFp36 budget.
11. one-card hand still plays rather than preserving nothing.
12. explanation trace for play-card with blocked resource pressure uses a
    cFp37-appropriate reason and does not claim pass preservation.
13. explanation trace for allowed resource pass still uses
    `policy-round-investment`.

## Implementation Notes And Pitfalls

- Do not compute hidden opponent hand/deck information. Use only
  `EnginePolicyInput` observation summaries and legal moves.
- Do not inspect raw AI hand labels in diagnostics export.
- Do not change `rankCatchUpCandidates(...)` unless a test proves the alignment
  cannot be fixed at `shouldPassForRoundInvestment(...)`.
- Be careful with `canVoluntarilyPassWithLead(...)`; cFp37 targets
  round-resource pass priority, not voluntary safe-pass tuning.
- Avoid broad threshold changes. This is a priority/order fix, not a new
  strategy model.
- If you add helper functions, export only what tests need. Keep internal
  helpers internal where possible.
- Existing cFp36 exception reasons such as `exception_card_advantage`,
  `exception_leader`, `exception_last_gem`, `exception_match_winning_play`, and
  `round_three_no_budget` must continue to produce
  `resourceExhaustionRecommended === false`.

## Completion Criteria

cFp37 is complete only when:

1. cFp36 diagnostics remain present.
2. pass-decision priority is aligned with `continue`, `fight_last_gem`, and
   single-move catch-up diagnostics.
3. focused tests prove both blocked and allowed resource-gate pass cases.
4. benchmark artifacts are refreshed and deterministic.
5. report and project state are updated.
6. all required checks pass or any environment-specific failure is documented
   with an exact reason and an alternate successful command.
