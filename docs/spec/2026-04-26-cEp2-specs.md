# Implementation Spec: Cluster E, Phase 2 - Engine-Backed Authentic Match Table V1

## Goal

Build the first playable authentic match table on top of the pure engine and Redux engine adapter.

This phase should turn the `cEp1` visual foundation into a real human-vs-AI match screen behind:

```text
/?engine=1&ui=authentic
```

The new screen should support the current Northern Realms vs Nilfgaard engine setup through:

- engine match startup from the URL seed;
- human mulligan;
- human card selection and legal card play;
- implemented leader action where legal;
- pass;
- round-end resolution;
- game-end display;
- AI actions through the existing `legal-heuristic-v0` controller;
- hidden-info-safe rendering.

This is still V1. It should be playable and visually aligned with the handoff, but it should not attempt the full `cEp3` interaction set: no discard browser, Medic/Decoy modal polish, round-end overlay, card-flight animation, deck builder, or pre-game setup yet.

## Architecture Position

Current state before `cEp2`:

- `/` renders the legacy Redux UI.
- `/?engine=1` renders the diagnostic `EngineGameManager`.
- `/?engine=1&ui=authentic` renders the `cEp1` gallery harness only.
- Authentic card visuals exist under `src/components/gwent/`.
- The engine Redux adapter already supports match startup, legal moves, command dispatch, prompt options, AI policy execution, round resolution, and selection state.

After this phase:

- `/` must still render the legacy Redux UI.
- `/?engine=1` must still render the diagnostic `EngineGameManager`.
- `/?engine=1&ui=authentic` must render the new engine-backed authentic match table.
- The `cEp1` gallery harness must remain reachable through a documented development route, such as `/?engine=1&ui=authentic&view=harness`.
- The product UI must consume engine selectors/legal moves and dispatch engine commands. React must not compute rule outcomes.

## Scope

### 1. Route The Authentic Variant To A Match Screen

Add the new authentic match route without replacing existing routes.

Requirements:

- `/?engine=1&ui=authentic` renders the new match screen.
- `/?engine=1&ui=authentic&view=harness` or an equivalent documented flag renders the existing `AuthenticUiHarness`.
- `/?engine=1` continues to render `EngineGameManager`.
- `/` continues to render `ReduxGameManager`.
- `VITE_ENGINE_UI=1` keeps the same behavior as today: shell by default, authentic match when `ui=authentic`, harness only when the explicit harness view flag is present.

Suggested route helper shape:

```ts
export type EngineUiVariant = "shell" | "authentic";
export type AuthenticUiView = "match" | "harness";

export const getAuthenticUiViewFromSearch = (search = ""): AuthenticUiView => {
  const params = buildSearchParams(search);
  return params.get("view") === "harness" ? "harness" : "match";
};
```

Add route helper tests in `tests/appMode.test.ts`.

### 2. Add Authentic Match Components

Add a product match screen under `src/components/gwent/`.

Suggested files:

- `src/components/gwent/AuthenticMatchScreen.tsx`
- `src/components/gwent/authentic-match.css`
- `src/components/gwent/matchViewModel.ts` or similarly named pure helper module

Suggested component boundaries:

- `AuthenticMatchScreen`
- `MatchTopBar`
- `ScoreCard`
- `PilePair` / `DeckPile` / `DiscardPile`
- `WeatherSummary`
- `BoardRow`
- `BoardTable`
- `HandStrip`
- `InspectorPanel`
- `ActionPanel`
- `PromptPanel`
- `BattleLog`

Keep the first implementation pragmatic. Subcomponents can live in one file if the code is still readable, but pure mapping helpers should be separated and tested.

Visual requirements:

- Use the existing `.gwent-authentic` token wrapper and Direction A style.
- Follow the match handoff layout: top bar, left score/pile rail, center six-row tactical board, hand strip, right inspector/action/log rail.
- Use `AuthenticCard` for visible cards.
- Use `AuthenticCardBack` for hidden hand/deck cards.
- Use row glyphs from `displayMetadata.ts`.
- Keep small radii, parchment panels, mono labels, tabular score numbers, and restrained ink-red legal target highlights.
- Avoid nested card-in-card layouts. Panels can be bordered/recessed, but do not put decorative card containers inside decorative card containers.

Responsive requirements:

- Desktop should use a three-column table layout.
- Mobile/narrow widths may stack rails and board sections, but must not horizontally overflow at a 390px viewport.
- The hand strip may scroll horizontally within itself if needed; the document itself must not overflow.

### 3. Build Engine-To-Authentic View Models

Build thin view-model helpers that map the engine adapter state into product UI shapes.

Requirements:

- Convert `EngineCardViewModel` to `AuthenticCardViewModel` without exposing `instanceId` in visible text.
- Preserve `instanceId` only for React keys, selection, legal move lookup, and test-safe attributes when needed.
- Keep card conversion display-only. Do not compute strength, score, legal targets, winner, gem loss, or prompts in React helpers.
- Use `selectEngineScoreBreakdown` for row and total scores.
- Use `selectEngineLegalMovesForHuman` as the source of legal UI actions.
- Use existing selectors when they are adequate.
- Add selectors only when the product UI needs hidden-safe data not currently exposed, for example:
  - visible discard card view models by seat, if showing public discard top cards;
  - weather grouped by row/effect for display;
  - board rows in handoff order;
  - seat summary data.

Hidden-info rules:

- Do not use `selectEngineDebugAiHandCards` in the product UI.
- Do not render AI hand card names, images, source IDs, instance IDs, deck order, or deck identities.
- AI hand should render as count and/or card backs only.
- AI deck should render as count and/or card back only.
- Public board cards, weather cards, and discard cards may render as visible cards.
- Battle log and activity summaries must use public card lookup only. For AI hidden plays, prefer `"AI played a card"` until the card is visible on board/discard.

### 4. Reuse The Engine Command Path

The match table must drive the same engine command path as the diagnostic shell.

Requirements:

- Start the default match through `startEngineMatch({ seed })`.
- Get `seed` from `getEngineSeedFromSearch(window.location.search)`.
- Continue using `getLegalHeuristicAiCommand(engine, aiSeat, humanSeat)` for AI execution.
- Dispatch human commands through `dispatchEngineCommand` and `resolveEngineRoundEnd`.
- Use Redux selection actions such as `engineSelectedCardSet`, `engineSelectedCardIdsSet`, and `engineSelectionCleared` where useful.
- Do not create a second state store for rules.
- Do not copy or port prototype `match-engine.jsx`.
- Do not add timers for rule transitions. Presentation-only delays are out of scope for this phase.

The existing immediate AI effect from `EngineGameManager` may be copied into the authentic screen or extracted into a shared hook if doing so reduces duplication cleanly.

### 5. Implement V1 Match Actions

The authentic table must expose the same core actions as the shell, but in the product layout.

Mulligan:

- During `mulligan`, hand cards are selectable up to the legal max.
- Show selected count and a `Confirm` control.
- Dispatch the exact matching `ChooseMulligan` legal move.
- Stable selectors:
  - `authentic-confirm-mulligan`
  - `authentic-hand-card`

Card play:

- In `playing`, playable human hand cards are visually distinct.
- Selecting a playable hand card populates the inspector and action panel.
- Legal targets come from `play_card` legal moves for the selected card.
- Render target action buttons for every legal move.
- Stable selectors:
  - `authentic-target-groups`
  - `authentic-target-action`
- Board rows with legal `board_row` targets should be highlighted and clickable.
- Row horn and weather targets may remain action-panel buttons in V1 if row-click semantics are not obvious yet.
- `card_instance` targets, such as Decoy targets, may remain action-panel buttons in V1.

Leader:

- Show leader name, ability name/status, and used/ready state.
- Implement the existing legal `clear_weather` leader action through `UseLeader`.
- Do not invent UI for placeholder leaders.

Pass and round resolution:

- Show a pass control when legal.
- Dispatch `Pass` exactly.
- When `round_end` is reached, show the score summary and a `Resolve Round` control.
- Dispatch `ResolveRoundEnd`.
- In game end, show winner/draw and final gems.
- Round-end overlay is explicitly deferred to `cEp3`.

Prompts:

- Render a generic prompt panel when `match.pendingPrompt` exists.
- If the prompt belongs to the human, render legal `choose_prompt_option` buttons from legal moves.
- If the prompt belongs to AI, show a non-blocking "AI resolving prompt" message.
- Do not build the Medic/Decoy modals or discard browser in this phase.

### 6. Preserve Diagnostic And Foundation Surfaces

- `EngineGameManager` remains usable for debugging at `/?engine=1`.
- `AuthenticUiHarness` remains usable for visual card foundation review through the explicit harness view route.
- Existing tests for the shell should keep passing, although selectors may be expanded.

### 8. Add Browser Smoke For The Authentic Match

Extend `tests/e2e/engine-shell-smoke.spec.ts` or add a focused authentic match smoke file.

Keep the existing shell tests passing.

Required route smoke:

- `/` still shows the legacy app and not the engine shell/authentic match.
- `/?engine=1` still shows the diagnostic shell.
- `/?engine=1&ui=authentic&view=harness` still shows the harness.
- `/?engine=1&ui=authentic&seed=ep2-smoke` shows the authentic match and not the diagnostic shell.

Required authentic match flow:

- assert top-level selector `authentic-match-screen`;
- assert seed/policy/round/phase context is visible;
- assert both seat score cards render;
- assert AI hand is shown as count/back only, not as individual hidden card faces;
- confirm human mulligan with zero or selected cards;
- select the first enabled human hand card;
- assert target groups/action buttons appear;
- play the first legal target action;
- assert a human play is logged or visible on board;
- wait for at least one AI action/result after the human play;
- click pass when legal;
- wait for `round_end`/resolve control if the deterministic seed reaches it within a bounded timeout, then resolve the round;
- assert no adapter error appears.

Required hidden-info checks:

- visible page text must not contain `instanceId`;
- visible page text must not contain generated instance id patterns like `seat_a:000:` or `seat_b:000:`;
- visible page text must not expose AI hand/deck card identifiers before they become public board/discard cards;
- page-level runtime errors must fail the authentic route smoke.

Required responsive checks:

- run the authentic match at a 390x900 viewport;
- assert no horizontal document overflow;
- confirm at least the board, hand, and action surface remain reachable/visible.

If one deterministic seed is not enough to reach `round_end` quickly, the implementer should either find and document a better seed or cover pass/round resolution with a narrowly scoped integration/helper test. The report must be explicit about what browser smoke covers and what remains deferred.

## Acceptance Criteria

This phase is complete when:

- `/?engine=1&ui=authentic` is a playable engine-backed match screen, not a gallery.
- The gallery harness is still reachable through a documented route.
- A human-vs-AI match can progress through mulligan, at least one human card play, at least one AI response, pass, round resolution when reached, and game end display when reached.
- The UI dispatches engine commands and never computes rule outcomes.
- Hidden AI hand/deck identities are not visible.
- `/?engine=1` diagnostic shell and `/` legacy route still work.
- Browser smoke covers the authentic match route on desktop and mobile and fails on page runtime errors.
- `docs/PROJECT_STATE.md` is updated.
- A phase report exists at `audit/reports/2026-04-26-cEp2-report.md`.
