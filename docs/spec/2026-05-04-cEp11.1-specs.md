# Implementation Spec: Cluster E, Phase 11.1 - Browser Smoke Backfill

## Intent

Close the browser-level coverage gaps left by cEp10 and cEp11 without changing
game behavior.

cEp10 added the product round/match ledger. cEp11 added spatial selected-card
targets. Both are covered by focused view-model tests, and cEp11 has browser
coverage for normal row targeting, but two important product paths still need
deterministic Playwright coverage:

- a selected hand weather card should expose the Weather panel target and
  dispatch the exact legal `PlayCard` move;
- the authentic match-end ledger should be reachable through a real product
  flow and should expose real round history plus route-appropriate navigation.

This is a regression-smoke phase. Do not add new rules, new UI behavior, new
styling direction, or shortcuts that fabricate match state.

## Scope

### 1. Weather-Card Target Browser Smoke

Add deterministic Playwright coverage for selected hand-card weather targeting
in `tests/e2e/engine-shell-smoke.spec.ts`.

Requirements:

- Use the existing browser-local deck fixture pattern from the cEp8 weather
  leader smoke (`gwent_authentic_decks_v1` seeded through `page.addInitScript`)
  rather than changing engine shuffle semantics.
- Build a local deck that can start a valid authentic match and can reliably
  produce at least one weather card in the human hand within a small fixed seed
  search.
- Keep the seed search bounded and deterministic. If a seed list is used,
  keep it short and document why it is safe.
- Drive the normal product flow:
  - open authentic pre-game or direct match as appropriate;
  - select the local fixture deck if using pre-game;
  - begin match;
  - keep/confirm mulligan;
  - acknowledge `Start the match?`;
  - wait for the authentic match screen.
- Select a visible human hand weather card. Prefer locating by
  `data-source-id` for the fixture weather source, but do not parse or expose
  runtime instance IDs.
- Assert:
  - `authentic-target-groups` enters `data-target-state="has-targets"`;
  - `authentic-target-hint` contains `target the weather panel`;
  - `authentic-weather-target` is visible and has an aria label matching
    `Play <weather card> on the weather panel`;
  - clicking `authentic-weather-target` dispatches the exact legal weather
    `PlayCard` move;
  - the selected weather card appears in the weather zone through a public
    `data-source-id`;
  - recent activity contains `Human played`;
  - selection/target hint resets or otherwise no stale weather target remains
    dispatchable after the move;
  - visible page text does not contain `instanceId`, raw `sourceId`, or
    `seat_a:NNN:` / `seat_b:NNN:` runtime identifiers.

Do not satisfy this by clicking a right-rail fallback action. The purpose of
this smoke is to cover the cEp11 `authentic-weather-target` spatial affordance.

### 2. Match-End Ledger Browser Smoke

Add deterministic Playwright coverage for the cEp10 match-end ledger branch.

The test must reach `data-ledger-kind="match_end"` through real engine
commands and existing product controls. It must not set Redux state directly,
must not inject a fake `RoundResult`, and must not add an engine shortcut
command just for tests.

Requirements:

- Prefer the shortest product-real path that is stable in Chromium:
  - a browser-local fixture deck/opponent setup is allowed;
  - a bounded deterministic seed list is allowed;
  - helper functions that click visible legal product controls are allowed.
- If the current product flow cannot reach match end deterministically without
  fabricating state, stop and document the blocker in the report rather than
  adding a fake state injection. The expected outcome is still to implement the
  smoke, so exhaust the fixture/seed approach first.
- The smoke should be clear enough that a future failure tells us whether the
  product path broke, not just that an arbitrary long play script became
  brittle.

Assertions once the match-end ledger appears:

- `authentic-round-overlay` is visible with
  `data-ledger-kind="match_end"`;
- `authentic-round-overlay-alert` is visible and has dialog semantics through
  the overlay (`role="dialog"`, `aria-modal="true"`);
- title text matches one of:
  - `Victory over ...`;
  - `Defeat against ...`;
  - `Draw.`;
- eyebrow contains `match concluded`;
- `authentic-round-ledger-history` is visible and has at least two
  `authentic-round-ledger-history-row` rows;
- `authentic-round-ledger-standing-result`,
  `authentic-round-ledger-standing-rounds`, and
  `authentic-round-ledger-standing-gems` are visible;
- the ledger does not render placeholder progression labels such as `mmr`,
  `rank`, `streak`, `xp`, `reward`, or `elo`;
- pressing `Escape` does not dismiss a game-end ledger unless the
  implementation already exposes an equivalent visible navigation route. cEp10
  currently chose explicit buttons only, so the expected assertion is that the
  overlay remains visible after Escape;
- `authentic-game-end-rematch` is visible. Clicking it should route through a
  fresh mulligan/start-match flow and clear the old match-end overlay;
- If the test enters from pre-game and `authentic-game-end-setup` is present,
  click it in a separate assertion path or separate test and verify the
  pre-game screen returns without an abandon warning. If only one navigation
  branch can be covered cleanly in this phase, cover rematch and document the
  omitted branch in the report.

Keep the test hidden-info-safe: no raw instance IDs, raw source ID labels, or
AI hidden hand/deck identities should appear in visible text.

### 3. Test Helper Quality

It is acceptable to add local helper functions inside
`tests/e2e/engine-shell-smoke.spec.ts` when they reduce brittleness.

Suggested helper boundaries:

- seed a browser-local deck fixture;
- enter authentic match from pre-game;
- confirm mulligan and start match;
- play the first legal spatial row target or fallback global target only when
  the test is not specifically testing weather targeting;
- pass and resolve rounds until the match ends, with a hard step limit and
  failure message that includes the current visible status/banner text.

Requirements:

- Keep helpers test-local unless there is already a shared e2e helper module.
- Use public test IDs and visible controls. Avoid CSS/class selectors when a
  stable `data-testid` exists.
- Avoid `waitForTimeout` except where an existing animation/handoff path
  already requires it and no state-based wait exists.
- Any loop that advances gameplay must have a strict upper bound and a useful
  failure message.
- Do not make the browser suite substantially slower. If the full match-end
  smoke is long, keep it to one scenario and avoid duplicating the whole path
  for every navigation branch.

## Out Of Scope

- Engine rule, legal-move, scoring, prompt, AI, simulation, catalog, or Redux
  adapter behavior changes.
- New product UI behavior, new layout styling, drag/drop, card-flight
  animation, route promotion, or default-route changes.
- Changes to the diagnostic engine shell except where an existing smoke helper
  has to keep compiling.
- Fake game-end state injection, direct Redux state mutation from Playwright,
  hidden test-only engine commands, or timers that advance rules.
- Deck-builder UX changes beyond seeding localStorage in tests.
- New screenshots or visual approval baselines.

## Acceptance Criteria

- A cEp11.1 Playwright smoke proves that a selected hand weather card uses
  `authentic-weather-target` and ends up in the Weather panel through the exact
  engine legal move.
- A cEp11.1 Playwright smoke proves the authentic match-end ledger can be
  reached through product controls and shows real history/standing/navigation
  fields.
- Both new smokes preserve hidden-info assertions.
- `docs/testing/browser-smoke.md`, `docs/PROJECT_STATE.md`, and the phase
  report are updated.
- No implementation changes are made outside the narrow browser-smoke/test
  support scope unless explicitly documented as a necessary testability fix.
