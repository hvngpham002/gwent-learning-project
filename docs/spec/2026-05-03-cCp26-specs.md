# Implementation Spec: Cluster C, Phase 26 - Draw Extra Card Setup Leader

## Intent

Implement the first Tranche 3 leader-rule member from
`docs/leader-ability-matrix.md`: `draw_extra_card` for
`scoiatael.francesca-findabair-daisy-of-the-valley` (Francesca Findabair:

This leader is a setup-time hand-size modifier:

- it is not an active `use_leader` command;

`discard_two_draw_one_from_deck`, `look_three_cards`, `cancel_leader`, UI prompt
work, AI tuning, deck-builder work, Card Studio work, simulation/export schema

## Rule Semantics For cCp26

### Leader Classification

`draw_extra_card` is an implemented setup-time leader effect. It should be
derived from the seat's leader identity:

```text
state/config seat leaderSourceId === "scoiatael.francesca-findabair-daisy-of-the-valley"
catalog leader ability === "draw_extra_card"
```

The leader must not emit a legal `use_leader` move.

The leader must not set `seat.leaderUsed`.

The leader must not emit `leader_used`.

Manual `UseLeader` attempts for this leader may keep the existing
unsupported-leader rejection path. They must not mutate state or consume the
leader.

### Initial Draw Contract

During `startMatch`, each seat should draw an initial hand using this rule:

```text
base initial draw count = 10
if the seat's leader ability is draw_extra_card: draw count = 11
otherwise: draw count = 10
```

Apply the rule after the seat's main deck has been instantiated and shuffled,
using the existing deterministic seeded RNG flow.

The extra card is the next card from the top of the already-shuffled deck. Do
not choose a card by prompt, card kind, faction, strength, row, or ability.

If a malformed or custom test deck has fewer cards than the draw count, do not
throw solely because of `draw_extra_card`; draw the available deck cards using
the existing `slice` behavior.

### Mulligan Contract

The mulligan budget remains unchanged:

- `mulligansUsed` starts at `0`;
- a seat can redraw at most two cards total through the existing sequential
  one-card mulligan flow;
- `draw_extra_card` does not add a third redraw;
- keep-hand still completes mulligan normally;
- the match phase remains `mulligan` after setup.

Legal mulligan moves should naturally include one-card redraw options for all
11 hand cards. Do not change the legal-move shape unless necessary.

### Event Contract

Prefer reusing existing setup events:

- `card_moved` with `reason === "initial_draw"` for each drawn card;
- `initial_hand_drawn` with `cardIds.length === 11` for the affected seat.

Do not add a new event type unless the implementation genuinely needs it.

If adding diagnostic metadata to existing events would require broad event
schema churn, do not do it in this phase.

### Hidden-Info Contract

This phase does not create a new UI disclosure surface.

Raw engine setup events already include initial hand card IDs. Do not add any
new public observation, UI label, AI observation, recent-activity summary, or
simulation export field that leaks the opponent's extra card identity.

Seat observations and UI hand rendering should continue to expose:

- own hand identities to the acting/human seat;
- opponent hand count/backs only in default human-facing views.

### Determinism Contract

For a given seed and identical deck preset:

- non-Daisy setup remains byte-for-byte deterministic;
- Daisy setup remains byte-for-byte deterministic;
- Daisy's first 10 hand cards should match the equivalent non-Daisy shuffled
  top 10 when only the leader differs and the deck list is identical;
- Daisy's 11th card should be the next card that would otherwise have remained
  at the top of the deck.

Do not call `Math.random()`.

Do not shuffle again for `draw_extra_card`.

Do not advance RNG outside the existing shuffle and initial-turn roll flow.

## Implementation Guidance

### Setup Helper

Add a small pure helper rather than embedding string checks throughout setup.
Recommended shape:

```text
src/game/core/leaderSetup.ts
```

Suggested exports:

```ts
export const DRAW_EXTRA_CARD_LEADER_SOURCE_ID =
  "scoiatael.francesca-findabair-daisy-of-the-valley";

export const BASE_INITIAL_HAND_SIZE = 10;

export const getInitialHandDrawCountForLeader = (input: {
  leaderSourceId: string;
  catalogLeaders: readonly CatalogLeaderSource[];
  baseDrawCount?: number;
}) => number;
```

The helper should:

- look up the leader by source ID;
- return `baseDrawCount + 1` only when the resolved leader ability is
  `draw_extra_card`;
- return `baseDrawCount` for missing leader catalog entries, other leaders, or
  any inconsistent setup input;
- avoid faction/name-based logic.

Export the helper from:

```text
src/game/core/index.ts
```

If the implementation keeps the helper local to `setup.ts`, document why in the
report and still cover the behavior thoroughly in setup tests.

### `startMatch`

In `src/game/core/setup.ts`, replace the hard-coded `10` used for the initial
draw with the helper-derived draw count per seat.

The intended flow remains:

1. instantiate leader, main deck, and side deck;
2. shuffle the main deck once using existing seeded RNG;
3. compute seat-specific initial draw count;
4. move the first `drawCount` cards to hand with `initial_draw`;
5. leave the rest in deck;
6. emit `initial_hand_drawn`;
7. roll initial turn through the existing RNG path;
8. set phase to `mulligan`.

Do not change instance ID generation, deck instantiation, side-deck handling,
leader zone handling, or first-turn roll semantics.

### Manifest Classification

Do not put Daisy in `implementedPassiveLeaderSourceIds`. `draw_extra_card` is a
setup-time event, not a whole-match passive policy.

Extend `src/data/catalog/leaders/official-promotion.ts` with a distinct
setup-time bucket:

```ts
readonly implementedSetupLeaderSourceIds: readonly string[];
```

Recommended after cCp26:

```text
executableLeaderSourceIds: 11
implementedPassiveLeaderSourceIds: 7
implementedSetupLeaderSourceIds: 1
implementedLeaderSourceIds: 19
placeholderLeaderAbilityIds: 3
```

`implementedLeaderSourceIds` should become the sorted union of active
executable, passive implemented, and setup-time implemented leader source IDs.

`placeholderLeaderAbilityIds` should remove `draw_extra_card` and contain only:

```text

discard_two_draw_one_from_deck
look_three_cards
```

Update tests and docs to use the new setup-time bucket.

- clarify the description as a setup-time initial hand-size modifier;
