## Required Classification

Classify every one of the 70 findings into exactly one top-level bucket. Use the scalar evidence fields already present in each finding.

### Bucket A: `already_guarded_suppressed_pass`

Use when:

- `roundOneSuppressedPassCount > 0`, and
- `roundOneRecommendedCount > 0` or `roundOneReasonBoardLimitCount > 0` or `roundOneReasonLowFutureHandCount > 0`

Interpretation: the current guard is already firing at least once. This may be a late-pass or too-late intervention case, but it is not an active selected-play contradiction after cFp53.

### Bucket B: `board_floor_never_reached`

Use when:

- `roundOneBoardFloorReachedCount === 0`, or
- `roundOneMaxBoardAfterSelectedMove < 7`

Interpretation: the current cFp43/cFp53 board geometry never became true. This is not directly fixable by the existing selected-play guard.

### Bucket C: `hand_cap_never_reached`

Use when:

- `roundOneHandCapReachedCount === 0`, or
- `roundOneMinHandAfterSelectedMove > 4`

Interpretation: the current hand-cap geometry never became true. This is not directly fixable by the existing selected-play guard.

### Bucket D: `base_geometry_exception_or_nonrecommendation`

Use when:

- `roundOneGuardBaseGeometryCount > 0`, and
- `roundOneRecommendedCount === 0`

Sub-label with the strongest visible reason:

- `exception_card_advantage` when `roundOneExceptionCardAdvantageCount > 0`
- `exception_single_move_catch_up` when `roundOneExceptionSingleMoveCatchUpCount > 0`
- `exception_match_winning_play` when `roundOneExceptionMatchWinningPlayCount > 0`
- `exception_opponent_passed` when `roundOneExceptionOpponentPassedCount > 0`
- `exception_last_gem` when `roundOneExceptionLastGemCount > 0`
- `exception_single_card_hand` when `roundOneExceptionSingleCardHandCount > 0`
- `non_play_card_or_other_exception` when `roundOneExceptionNonPlayCardCount > 0`
- `continue_recommendation` when `roundOneRecommendationContinueCount > 0`
- `unknown_nonrecommendation` otherwise

Interpretation: geometry existed, but the policy analysis did not recommend a round-one overinvestment pass.

### Bucket E: `cumulative_spend_candidate`

Use only when A-D do not apply and public telemetry shows high round-one spending without a direct guard recommendation. Suggested evidence:

- `round1PlayCardCount >= 8`, or
- both `roundOneMaxBoardAfterSelectedMove >= 6` and `roundOneMinHandAfterSelectedMove <= 5`, or
- `roundOneSelectedWouldLeaveNoPositiveUnitMoveCount > 0`

Interpretation: possible cumulative-spend issue, not a proven selected-play guard bug. This bucket can support either a future instrumentation/debug phase or a carefully scoped cumulative-budget spec, but only if it is dominant.

### Bucket F: `telemetry_unavailable_or_other`

Use when no other bucket applies or `roundOneGuardTelemetryAvailable !== true`.

Interpretation: do not patch behavior from this row without more telemetry.

## Decision Rules

The casebook must end with one explicit recommendation:

- Recommend a cFp55 behavior patch only if one actionable bucket is clearly dominant (at least 60% of the 70 findings) and the proposed change can be expressed as a narrow rule using existing public telemetry.
- Recommend a cFp55 instrumentation/debug phase if the largest actionable bucket is below 60% or if the remaining signal depends on temporal/cumulative details not currently present in artifacts.
- Recommend pausing v1 heuristic tuning if the findings are mostly already-guarded, exception-backed, or not loss/actionable after classification.

If recommending behavior, include exact non-goals and exception preservation. If recommending instrumentation, name the missing fields.
