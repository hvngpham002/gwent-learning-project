# Cluster E Phase 15 Specs: Route Promotion And URL Contract

## Phase ID

`cEp15`

## Purpose

Promote the authentic product UI to the app's main address and replace the current query-heavy route surface with a clean, documented URL contract.

After this phase, `/` must open the authentic pre-match setup screen. Legacy gameplay must remain reachable at `/legacy`, the diagnostic engine shell must remain reachable at `/engine-diagnostic`, and the old `?engine=1&ui=authentic&view=...` URLs must continue to work as compatibility aliases while docs and tests shift to the new canonical paths.

This is the route-promotion phase only. Do not delete legacy code, do not redesign the screens, and do not implement the AI Lab UI beyond reserving/documenting its future path.

## Current Context

Historically:

- `/` rendered `ReduxGameManager` and was the legacy default route.
- `/?engine=1` rendered the diagnostic engine shell.
- `/?engine=1&ui=authentic` rendered the authentic pre-game setup.
- `/?engine=1&ui=authentic&view=...` selected authentic sub-surfaces.

The product UI is now sufficiently playable that the main address should open the match setup screen. This spec explicitly supersedes the older "legacy remains default" route policy for this phase. Legacy is not removed; it moves to a named route.

The worktree may already contain unrelated Cluster F research/benchmark changes. Preserve them. Do not revert, stage, or "clean up" unrelated files.

Unknown paths should fall back to the authentic pre-game setup for now. Do not add a router dependency or a full 404 page in this phase.

## Implementation Requirements

### 1. Centralize route resolution

Refactor `src/appMode.ts` so route selection is path-aware, not only query-aware.

Add a small typed route resolver, for example:

```ts
type AppRoute =
  | { surface: "authentic"; view: AuthenticUiView }
  | { surface: "engine-diagnostic" }
  | { surface: "legacy" };
```

The exact type name is up to you, but keep it simple and testable.

The resolver should accept `pathname`, `search`, and `envFlag` so it can be tested without reading globals. It should:

- map canonical paths to the contract above;
- preserve old query aliases;
- keep seed/debug query parsing separate from route selection;
- avoid leaking browser globals into unit tests.

Keep existing helpers such as `getEngineSeedFromSearch`, `getEngineUiVariantFromSearch`, `getAuthenticUiViewFromSearch`, and `shouldUseEngineUi` only if useful for compatibility. If retained, update their tests and comments so their legacy semantics are not mistaken for the new primary route contract.

### 2. Update `App.tsx`

`src/App.tsx` should use the new route resolver.

Required behavior:

- `/` renders `AuthenticGameApp` with pre-game setup.
- `/legacy` renders `ReduxGameManager`.
- `/engine-diagnostic` renders `EngineGameManager`.
- old `/?engine=1` still renders `EngineGameManager`.
- old `/?engine=1&ui=authentic...` still renders `AuthenticGameApp`.

Do not import legacy rule helpers into authentic or engine paths. `ReduxGameManager` may remain imported by `App.tsx` for `/legacy`.

### 3. Update `AuthenticGameApp`

`AuthenticGameApp` currently derives its route from `search` only. Update it to accept a route view or location input from `App.tsx`.

Required behavior:

- canonical paths select the same internal authentic surfaces as the old `view=...` values;
- old query aliases still work;
- existing in-app `viewOverride` behavior still works for:
  - opening deck builder from pre-game;
  - opening Card Studio from pre-game/deck-builder;
  - returning from Card Studio to the correct prior surface;
  - starting a match from pre-game or deck builder through `setupConfig`;
- seed and debug parameters keep flowing into pre-game/direct-match behavior.

Prefer a small explicit prop such as `routeView` over making `AuthenticGameApp` read `window.location.pathname` internally.

### 4. Update product navigation links/copy

Where the UI exposes navigation or docs-facing URLs, use canonical paths:

- Deck builder: `/deck-builder`
- Card Studio: `/card-studio`
- Official porting: `/official-porting`
- Component foundation: `/components`
- UI harness/gallery: `/ui-harness`
- Diagnostic shell: `/engine-diagnostic`
- Legacy UI: `/legacy`

Do not force every internal state transition to use `window.location`. Existing React state transitions are fine. The goal is that manually entering the canonical path works and docs/tests point to the clean path.

### 5. Keep AI Lab deferred

Document `/ai-lab` as reserved for the next Cluster E AI Lab UI phase. Do not wire benchmark execution, policy selection, file exports, Python tooling, or research charts in cEp15.

If you add a temporary placeholder route, it must:

- be visually minimal;
- use existing authentic tokens;
- state that AI Lab is not implemented yet;
- not run simulations or benchmarks;
- be covered by a basic smoke test only if implemented.

Prefer deferring the placeholder entirely unless route resolver ergonomics make it cleaner to include.
