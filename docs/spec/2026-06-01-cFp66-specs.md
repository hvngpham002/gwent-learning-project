# Cluster F Phase 66 Specs - Sampler Public-Transfer Memory

Date: 2026-06-01
Branch: `codex/cFp66-sampler-public-transfer-memory`
Base: `dev`

## Summary

cFp65 proved that root-local public-zone accounting is not enough to repair the remaining sampler invalid roots:

- Current cFp61 materialization remains 3,979 valid / 63 invalid.
- Robust cFp61 materialization remains 32,146 valid / 341 invalid.
- cFp62 classifications remain 100% `public_zone_count_deficit`.
- cFp64 provenance labels remain unchanged.
- cFp65 found side-deck-only public adjustments in some roots, but all invalid roots still had uncovered prior deficits.

cFp66 should add benchmark-only public-transfer memory to the sampler pipeline. The memory must track only cards that were already publicly visible or prompt-revealed to the perspective seat, then later moved into hidden opponent hand/deck zones. This lets the sampler account for known hidden cards from public history without peeking at never-seen hidden opponent cards.

cFp66 is still not search. It must not implement PIMC, ISMCTS, rollouts, search move selection, action ranking, product AI behavior, or any gameplay rule changes.

## Problem Statement

The current sampler materializer is root-local:

1. It reads current public zones.
2. It subtracts current public known cards from a known preset main-deck prior.
3. It uses public opponent hand/deck counts to determine how many hidden source-multiset samples are required.

This misses public history. A card can be visible earlier, then move into a hidden opponent zone later. If the sampler forgets that public transfer, it treats the hidden hand/deck slot as unknown and can report `insufficient_prior_remaining` even when a public-memory-safe known-hidden card should reduce the unknown draw requirement.

The cFp66 objective is to add that memory without crossing into oracle behavior.

## Non-Negotiable Safety Rules

Do not use true hidden opponent hand/deck identity unless the exact card instance was already visible to the perspective seat earlier in the same benchmark match or is currently prompt-revealed to that perspective.

Forbidden shortcuts:

- Do not scan all cards in opponent hidden hand/deck and use their source ids to repair roots.
- Do not infer hidden card identities from final state, full command logs, raw event logs, or debug payloads.
- Do not export raw card ids, source ids, source maps, card names, instance ids, raw moves, action refs, command logs, event logs, final state, sampled hands, sampled decks, or deck order.
- Do not add opaque placeholder cards.
- Do not weaken strict conservation checks.
- Do not mark a root valid unless every hidden hand/deck count is covered by known public-memory cards plus sampled prior cards.
- Do not change engine rules, legal moves, benchmark suite definitions, benchmark match records, catalog data, deck presets, UI behavior, product AI policy behavior, ratings, or failure-mining behavior.
- Do not implement search.

Allowed internal data:

- Prior and current `MatchState` snapshots inside a benchmark-only observer, if used only to track card instances that were public to the perspective seat.
- Runtime card ids for cards that were already public to the perspective seat, as internal memory keys only.
- Public-zone source ids for cards visible to the perspective seat.
- Prompt-revealed opponent-hand card ids when the prompt is for the perspective seat.
- Known preset main-deck and side-deck source counts.
- Scalar aggregate outputs.

## Design Direction

Add a benchmark-only public transfer memory layer, probably near `src/game/benchmark/samplerMaterialization.ts` or in a sibling module.

Recommended concepts:

- `SamplerPublicTransferMemory`
- `SamplerPublicTransferMemoryState`
- `buildSamplerPublicTransferMemoryUpdate(...)`
- `buildPublicTransferMemoryKnownHiddenCounts(...)`
- `applyPublicTransferMemoryToMaterialization(...)`

The exact names may follow local conventions, but keep the separation clear:

1. Memory update: discovers public-to-hidden transfers from state snapshots.
2. Materialization accounting: uses scalar known-hidden counts from memory.
3. Artifact serialization: writes scalar diagnostics only.

## Perspective-Specific Memory

Memory must be per benchmark match and per perspective seat.

Use a stable internal key such as:

- `suiteId`
- `matchupId`
- `seed`
- `mirrorIndex`
- `seatId`

The two seats do not share perspective memory. A card visible to one seat is not automatically visible to the other unless it was in a globally public zone or prompt-revealed to that seat.

## What Counts As Public To A Perspective

At a root, visible cards include:

- board units on either side;
- row horns on either side;
- discard piles on either side;
- removed-from-game piles if currently public in the engine model;
- weather cards;
- cards in the acting seat hand only when that hand belongs to the perspective seat;
- opponent-hand cards revealed by a pending prompt addressed to the perspective seat.

For sampler materialization from a perspective seat, the most important memory is opponent-owned cards that were once visible to that perspective and later moved into that opponent's hidden hand/deck.

## Public-To-Hidden Transfer Detection

Implementation should avoid raw event-log dependency if possible. The preferred approach is snapshot-based:

1. Before materializing each root, update memory with the current root state.
2. For each card instance already tracked as visible to the perspective:
   - inspect only that tracked card id's current zone;
   - if it is now in opponent hand, count it as known hidden hand;
   - if it is now in opponent deck, count it as known hidden deck;
   - if it is currently public again, count it as public, not hidden;
   - if it leaves the game or becomes irrelevant, update scalar counters accordingly.
3. Add new currently visible cards to memory after evaluating current zones.

This is allowed because the card id was previously public to the perspective. Do not inspect never-tracked hidden card ids.

If implementation needs event payloads, it must still derive memory only for previously public or currently prompt-revealed cards and must not serialize raw events.

## Materialization Integration

Extend cFp61 materialization accounting with optional public-transfer memory input.

The materializer should combine:

- current public known source counts;
- prompt/current fixed known hand source counts;
- public-transfer known hidden hand source counts;
- public-transfer known hidden deck source counts;
- side-deck-only/off-prior public-memory counts.

Expected accounting:

- Main-deck-attributable current public cards consume main-deck prior.
- Main-deck-attributable known hidden transfer cards consume main-deck prior.
- Side-deck-only known hidden transfer cards reduce hidden hand/deck count requirements but do not consume main-deck prior.
- Off-prior known hidden transfer cards reduce hidden hand/deck count requirements but do not consume main-deck prior.
- Unknown hidden hand/deck source samples are drawn only for remaining hidden counts after known public-memory hidden cards are accounted for.
- If known public-memory hidden counts exceed current hand/deck counts, mark invalid/incoherent with a safe reason.
- If prior remaining is still insufficient, keep the root invalid.

Do not serialize internal known source-count maps.

## Expected Outcomes

cFp66 may reduce invalid roots if the remaining deficits are explained by public-to-hidden transfers.

Acceptable outcomes:

- **Best case:** current/robust invalid counts decrease without hidden-info compromise.
- **Partial case:** only some invalid roots become valid; report remaining categories.
- **No-change case:** invalid roots remain 63/341; report that public-transfer memory did not explain the deficits and recommend a valid-root-only skip contract or a deeper explicitly specified public-state reconstruction phase.

Do not force success by weakening checks.

## Tests Required

Add focused tests before or with implementation.

Minimum coverage:

1. A card visible in public discard that later moves to opponent hand is tracked as known hidden hand for that perspective.
2. A card visible in public discard that later moves to opponent deck is tracked as known hidden deck for that perspective.
3. A prompt-revealed opponent hand card remains known-hidden for that perspective while it stays in hand.
4. The opposite seat does not receive prompt-specific memory unless the card was globally public or revealed to that seat.
5. Never-seen opponent hidden hand/deck cards are not inspected to repair materialization.
6. Main-deck-attributable transfer cards consume main-deck prior.
7. Side-deck-only transfer cards reduce hidden count requirements without consuming main-deck prior.
8. Off-prior transfer cards reduce hidden count requirements without consuming main-deck prior.
9. Incoherent memory, such as known hidden transfer count exceeding current hidden hand/deck count, stays invalid.
10. Artifacts reject unsafe payloads such as source maps, source ids, card names, runtime card ids, raw events, raw state, sampled hand/deck maps, and command logs.
11. AI Lab metadata reports cFp66.

If exact root fixtures are added from cFp65/cFp64 artifacts, keep them scalar and do not copy raw unsafe payloads.
