# cCp32 Specs - Scoia'tael First-Player Faction Ability

## Summary

Implement the missing Scoia'tael faction passive:

> Decides who takes first turn at the start of the game.

The current engine implements the other faction passives but still uses a seeded random `initial_roll` for every match. `GameEvent.turn_set.reason` already reserves `scoiatael_override`, and `docs/gwent-rules.md` already documents the rule, but `startMatch` does not honor it and the authentic pre-game UI gives no player choice.

This phase is an engine + product setup patch, with benchmark artifact refresh because official starter-matrix benchmarks include Scoia'tael.

## Current Gap

Known current behavior:

- `src/game/core/setup.ts` chooses initial `currentTurn` by seeded RNG:

  ```ts
  const currentTurn = rng.next() < 0.5 ? config.seats[0].seatId : config.seats[1].seatId;
  events.push({ type: "turn_set", seatId: currentTurn, reason: "initial_roll" });
  ```

- `src/game/core/types.ts` already includes `turn_set.reason === "scoiatael_override"`.
- `docs/gwent-rules.md` §17.15 says Scoia'tael overrides the coin flip.
- No setup config, pre-game UI, adapter path, or benchmark config can currently provide the choice.

Other faction passives are already implemented and must remain unchanged:

- Monsters: keeps one random non-hero unit between rounds.
- Nilfgaard: wins tied rounds.
- Northern Realms: draws on round win.
- Skellige: returns two random non-hero units at round 3 start.

## Product Decisions

Use these decisions exactly:

1. The passive applies only at match start / round 1 setup.
2. Later rounds continue to use existing starter policy: round winner starts next round; true draw uses existing draw policy.
3. If exactly one seat is Scoia'tael, that seat may choose either themselves or the opponent to start.
4. If both seats are Scoia'tael, there is no unique chooser; keep the existing seeded initial roll.
5. If neither seat is Scoia'tael, keep the existing seeded initial roll.
6. If exactly one Scoia'tael seat exists and no explicit choice is supplied, use a deterministic fallback: the Scoia'tael seat chooses themselves to start.
7. The fallback is required for direct `/match`, headless simulation, benchmarks, and tests that do not have a product pre-game choice.
8. The authentic pre-game UI must expose the choice when the human deck faction is Scoia'tael and the opponent deck faction is not Scoia'tael.
9. If the AI/opponent deck is Scoia'tael and the human deck is not, do not prompt the human. Use the deterministic fallback where the AI starts.
10. If both decks are Scoia'tael, do not prompt. Display or derive normal seeded roll behavior.
11. The choice uses only public faction identities and does not introduce any hidden-information risk.

## Implementation Requirements

### 1. Engine Config And Validation

Add a setup-specific choice field to `MatchConfig` in `src/game/core/types.ts`. Use a narrow name so this cannot be mistaken for a generic starting-player override.

Recommended shape:

```ts
export interface ScoiataelFirstPlayerChoice {
  readonly choosingSeatId: SeatId;
  readonly startingSeatId: SeatId;
}

export interface MatchConfig {
  // existing fields...
  readonly scoiataelFirstPlayerChoice?: ScoiataelFirstPlayerChoice;
}
```

Validation rules in `startMatch`:

- `choosingSeatId` must be one of the configured seat IDs.
- `startingSeatId` must be one of the configured seat IDs.
- The configured `choosingSeatId` must belong to the unique Scoia'tael seat.
- If no seat is Scoia'tael, reject the override.
- If both seats are Scoia'tael, reject the override or ignore it only if accompanied by an explicit test-covered rationale. Preferred: reject invalid override to avoid silent bad config.
- If exactly one seat is Scoia'tael and no override is supplied, create the deterministic fallback internally.

Use the project's existing error style for invalid match setup. If `startMatch` currently throws plain `Error` for setup validation, use that; do not introduce a new error hierarchy just for this phase.

### 2. Engine Starter Resolution

Refactor initial starter selection in `src/game/core/setup.ts` into a small pure helper, or at least a clearly isolated block:

- Compute the existing seeded roll first, so non-Scoia'tael and both-Scoia'tael matches preserve current deterministic seed behavior.
- Determine whether there is exactly one Scoia'tael seat.
- If exactly one Scoia'tael seat:
  - use explicit `config.scoiataelFirstPlayerChoice.startingSeatId` when valid;
  - otherwise use fallback `startingSeatId = scoiataelSeatId`;
  - set `currentTurn` and `roundStarter` to that starting seat;
  - emit `turn_set` with `reason: "scoiatael_override"`.
- If not exactly one Scoia'tael seat:
  - use the existing seeded rolled starter;
  - emit `turn_set` with `reason: "initial_roll"`.

Add or extend `faction_ability_resolved` event support:

- Add `ability: "scoiatael_choose_first"` to the existing `faction_ability_resolved` union.
- Emit this event only when exactly one Scoia'tael seat applies the override.
- `seatId` must be the Scoia'tael chooser seat.
- `outcome` must be one of:
  - `"chose_self"`
  - `"chose_opponent"`
  - `"defaulted_self"`
- Add `policy: "explicit_choice"` for explicit user/config choice and `policy: "fallback_self"` for fallback.

Do not emit the faction ability event for both-Scoia'tael or no-Scoia'tael matches.

### 3. Product Pre-Game UI

Expose a compact first-turn selector in the authentic pre-game flow.

Add view-model support in `src/components/gwent/preGameViewModel.ts`:

- Include a small public first-player-choice view model derived from selected human and opponent deck factions.
- Show options only when:
  - human deck faction is `scoiatael`;
  - opponent deck faction is not `scoiatael`;
  - the selected deck is otherwise valid enough to begin.
- Options:
  - `"you"` / starts human
  - `"opponent"` / starts opponent
- Default selection: `"you"`.
- If opponent is Scoia'tael and human is not, expose a non-interactive summary like `"opponent chooses first turn"` or leave the selector hidden. The engine fallback must still make opponent start.
- If both are Scoia'tael, expose no selector and preserve seeded roll.

Wire the selected value into `AuthenticMatchSetupConfig`, then into `setupConfigToStartEngineOptions`, then into `StartEngineMatchOptions`, then into `MatchConfig`.

Expected `AuthenticMatchSetupConfig` addition:

```ts
readonly scoiataelFirstPlayerChoice?: "human" | "opponent";
```

Expected `StartEngineMatchOptions` / `MatchConfig` shape after mapping:

```ts
scoiataelFirstPlayerChoice: {
  choosingSeatId: "seat_a",
  startingSeatId: "seat_a" | "seat_b",
}
```

Assume product authentic setup maps human to `seat_a` and AI/opponent to `seat_b`, unless the existing adapter says otherwise.

Use existing button styling patterns from the pre-game screen. Do not create a new visual language.

### 4. Direct Match / Headless / Benchmark Compatibility

Do not require every non-product caller to pass an explicit choice.

Direct `startEngineMatch({ seed })`, `/match`, engine diagnostic shell, simulation, and benchmarks must keep working. For exactly one Scoia'tael seat, fallback to the Scoia'tael seat choosing themselves to start.

This fallback means benchmark outputs may change for any suite that includes Scoia'tael. That is expected and must be reported.

## Out Of Scope

## Required Tests

### Engine Unit Tests

Add focused coverage, preferably in `tests/game/coreSetup.test.ts`.

Required cases:

1. Non-Scoia'tael vs non-Scoia'tael still uses seeded `initial_roll`.
2. Human/seat_a Scoia'tael with explicit self choice starts `seat_a`.
3. Human/seat_a Scoia'tael with explicit opponent choice starts `seat_b`.
4. Opponent/seat_b Scoia'tael with no explicit choice starts `seat_b` via fallback.
5. Exactly one Scoia'tael with no explicit choice emits `turn_set.reason === "scoiatael_override"` and `faction_ability_resolved.ability === "scoiatael_choose_first"`.
6. Explicit self/opponent choices produce the correct `outcome` and `policy`.
7. Both seats Scoia'tael use seeded `initial_roll` and do not emit `scoiatael_choose_first`.
8. Invalid override from a non-Scoia'tael chooser is rejected.
9. Invalid starting seat is rejected.
10. Same seed + same choice is deterministic.
11. Same seed + different valid choices changes only starter-sensitive fields/events, not deck shuffle order or initial hand contents.

### Product / Adapter Tests

Add or update tests in:

- `tests/components/gwent/authenticPreGameViewModel.test.ts`
- `tests/store/engineAdapter.test.ts`

Required cases:

4. Opponent-only Scoia'tael setup maps no user selector but engine fallback starts the opponent.

- Headless/direct/benchmark callers remain compatible without explicit choice.
- AI Lab benchmark totals are refreshed if the starter matrix changes.
