# Cluster F Phase 65 Specs - Sampler Public-Zone Accounting Repair Probe

Date: 2026-06-01
Branch: `codex/cFp65-sampler-public-zone-accounting-repair`
Base: `dev`

## Summary

cFp64 showed that every remaining cFp61 sampler-invalid root is associated with public-zone count pressure:

- Current suite: 63 invalid/provenance roots.
- Robust suite: 341 invalid/provenance roots.
- Labels: `mixed_public_zones`, `round_end_public_zone`, `single_zone_board`, `single_zone_discard`.
- Duplicate public references: 0.
- Duplicate fixed-known-hand references: 0.
- `zero_public_zone_unexpected`: 0.
- `provenance_ambiguous`: 0.

cFp65 is a narrow sampler accounting repair probe. It should attempt only repairs that can be justified from public zones, known preset deck lists, and scalar public counts. It must not fix sampler invalid roots by peeking at hidden opponent hand/deck identities, adding opaque placeholder cards, weakening conservation checks, or creating determinized search.

## Motivation

The sampler is still not ready for a determinized probe because cFp61 materialization has invalid roots:

- Current: 3,979 valid / 63 invalid.
- Robust: 32,146 valid / 341 invalid.

cFp64 classified those invalid roots by public-zone provenance, but the classification does not prove that the public zone is wrong. A one-card deficit can also be caused by public card-transfer mechanics, off-prior cards entering hidden zones, or a missing event-history memory. The cFp65 task is therefore:

1. Try a narrow public-zone accounting repair where it is safe.
2. Keep strict conservation.
3. Produce clear scalar evidence if no safe public-only repair exists.
4. Do not proceed to PIMC, ISMCTS, rollouts, or any search-playing policy.

## Non-Negotiable Safety Rules

Do not use true hidden opponent card identity to make invalid roots valid.

Forbidden repair shortcuts:

- Do not inspect `state.seats[opponentSeatId].hand` source ids, catalog ids, instance ids, abilities, or card names to subtract hidden off-prior cards.
- Do not inspect `state.seats[opponentSeatId].deck` source ids, catalog ids, instance ids, abilities, or card names to subtract hidden off-prior cards.
- Do not serialize hidden card ids, source ids, card names, instance ids, deck order, sampled hands, sampled decks, action refs, move ids, command logs, final state, or decision traces.
- Do not add opaque hidden placeholders such as `unknown_external_card` to force sample counts to match.
- Do not weaken `insufficient_prior_remaining` into `valid` unless the missing count is covered by a public-safe accounting adjustment.
- Do not change engine rules, legal moves, product AI behavior, benchmark match generation, deck presets, catalog data, route defaults, or UI behavior.
- Do not implement PIMC, ISMCTS, rollouts, search move selection, neural inference, ratings changes, or product AI wiring.

Allowed internal inputs:

- Current public zones already used by sampler materialization.
- Public hand/deck/discard/board/weather/horn counts.
- Known preset prior counts.
- Known preset side-deck counts.
- Public source ids for cards already in public zones, provided they never leave hidden-info-safe internals or artifacts.
- Scalar aggregate diagnostics derived from those public values.

## Required Investigation First

Before changing materialization behavior, add or update focused tests that prove the current accounting surface:

1. A cFp64-style one-card public-zone deficit remains invalid when no public-safe adjustment exists.
2. A public card whose source is not in the known main-deck prior does not consume main-deck prior.
3. A side-deck-only public source does not consume main-deck prior if it can be proven from the known preset.
4. A public source that is present in the main-deck prior still consumes that prior.
5. Duplicate public card references are still de-duplicated and do not create fake deficits.
6. Hidden hand/deck identity is not used to repair an invalid root.

The repair implementation should be driven by these tests. If a test cannot be expressed without hidden identity, rewrite it as a scalar public-count test.

## Target Repair

Implement a narrow public-zone accounting adjustment in the sampler materialization path.

Recommended shape:

- Add a pure helper near the cFp61/cFp63 sampler materialization accounting code, for example:
  - `buildPublicZonePriorAccounting(...)`
  - `buildSamplerPublicZoneAccountingAdjustment(...)`
  - or a name matching existing local conventions.
- Inputs should be public-zone source counts and known preset prior metadata.
- Output should be scalar and hidden-info-safe internally:
  - `mainDeckAttributablePublicCount`
  - `sideDeckOnlyPublicCount`
  - `offPriorPublicCount`
  - `duplicatePublicReferenceCount`
  - `publicAdjustmentCount`
  - `uncoveredPriorDeficitCount`
  - `adjustmentReasonCounts`
- The only repairable cases are public cards that can be proven not to belong to the known main-deck prior from public-zone information and the known preset prior.
- If a public-zone card can belong to the main-deck prior, it must continue to consume main-deck prior.
- If the remaining deficit is only explainable by hidden hand/deck contents, keep the root invalid and report the scalar deficit.

Expected behavior:

- Regenerated cFp61 artifacts may improve only if the public-zone adjustment truly covers some invalid roots.
- If all 404 invalid roots remain invalid, that is acceptable if the report proves that no public-only adjustment was available.
- The implementation must not introduce false `valid` roots.
