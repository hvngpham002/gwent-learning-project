# Implementation Spec: Cluster C, Phase 22 - Restore Discard To Hand Leader

## Intent

Implement the next focused leader-rule tranche from
`docs/leader-ability-matrix.md`: `restore_discard_to_hand` for
`monsters.eredin-bringer-of-death` (Eredin: Bringer of Death).

This is Pattern 4 from the cCp18 Leader Ability Matrix: an active one-shot
leader that opens a single-step prompt over the acting seat's own discard pile.
The player chooses one card from that discard pile and returns it to hand.

The settled local rule contract is:

- own discard pile only;
- any card in that discard pile is eligible: unit, hero, special, weather, or
  side-deck-generated card that reached discard;
- heroes are eligible because the leader text says "card" and does not contain
  Medic's non-hero unit restriction;
- empty discard means no legal leader move;
- the leader is consumed only after a legal prompt option resolves.

Do not bundle `draw_opponent_discard`, `shuffle_discards_into_decks`,
`random_medic`, `discard_two_draw_one_from_deck`, setup draw, cancel/reaction
work, deck-builder changes, AI strategy tuning, or product UI layout polish into
cCp22.

## Rule Semantics For cCp22

### Eligible Cards

The leader prompt options are exactly the cards currently in the acting seat's
own discard pile whose catalog source can be resolved.

Eligible:

- `unit`;
- `hero`;
- `special`;
- `weather`;
- generated / side-deck-only cards if they are physically in that discard pile.

Not eligible:

- cards in the opponent discard pile;
- cards in hand, deck, side deck, removed from game, weather zone, row horn, or
  board rows;
- discard entries whose card instance or catalog source is missing.

Do not apply Medic restrictions. Medic revives only non-hero units to the board;
Bringer of Death restores any own-discard card to hand.

### Legal Move Shape

`getLeaderMove` should emit exactly one `use_leader` move when:

- phase / turn / pass / prompt / leader-used gates allow leader use;
- the leader ability is implemented;
- the acting seat's own discard has at least one eligible card.

The move should use:

```ts
target: { kind: "none" }
metadata.targetRequirement: "future_prompt"
metadata.targetCount: eligible discard card count
metadata.targetLabel: "own discard"
```

If no eligible discard card exists, emit no `use_leader` move. A manual
`UseLeader` attempt in that state must reject without setting `leaderUsed`.

### Prompt Open

Successful `UseLeader` does not immediately move a card. It opens a
`pendingPrompt`:

```ts
kind: "choose_card"
seatId: acting seat
abilityId: "restore_discard_to_hand"
sourceId: leader.sourceId
sourceCardId: leader instance id
options: one option per eligible own-discard card
```

Prompt option requirements:

- preserve discard order for deterministic option order;
- option ID should be stable and card-specific, e.g. `restore:<cardId>`;
- label should be human-readable, e.g. `Restore Geralt of Rivia to hand`;
- target should identify the card instance and source ID without requiring a
  board row.

`PendingPromptOption.target.row` is currently required for Medic. cCp22 should
make that row field optional or turn the prompt target into a small union so
discard-to-hand options do not need a fake row.

`UseLeader` prompt-open transaction should:

- clone state;
- emit `ability_triggered` for the leader;
- set `state.pendingPrompt`;
- emit `prompt_opened`;
- leave `seat.leaderUsed === false`;
- emit no `leader_used`;
- not move any discard card yet;
- not emit `card_played`;
- not resolve any restored-card abilities;
- not hand off the turn until the prompt resolves.

If the implementation chooses to follow the older Medic play-card prompt pattern
and hand off immediately after prompt open, document that deviation clearly and
prove the final resolved turn is still correct. The preferred cCp22 behavior is
to keep `currentTurn` on the acting seat while the leader prompt is pending.

### Prompt Resolution

`ChoosePromptOption` for `kind === "choose_card"` and
`abilityId === "restore_discard_to_hand"` should:

- validate the prompt belongs to the command seat;
- validate the option ID is legal;
- validate the target card still exists in the acting seat's discard pile;
- clone state;
- move the chosen card from discard to the acting seat's hand;
- set the restored card's `controller` to the acting seat;
- leave `owner` unchanged;
- emit `prompt_resolved`;
- emit `card_moved` with new reason
  `"leader_restore_discard_to_hand"`;
- emit `ability_resolved` with outcome `"restored_card"`;
- set `seat.leaderUsed = true`;
- emit `leader_used`;
- clear `state.pendingPrompt`;
- hand off the turn through the existing turn-handoff helper.

Do not emit `card_played`. The card was restored to hand, not played.

Do not resolve the restored card's abilities. A restored Medic, Spy, Muster,
Scorch, Weather, or Hero should behave normally only if played later.

If the chosen card is no longer in the acting discard pile, reject with
`EngineRuleError` and do not consume the leader.
