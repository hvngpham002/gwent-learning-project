## Summary

Human playtests have found the obvious legal-heuristic-v1 issues, but manual playtesting is now too slow and too biased toward whichever matchups happen to be played. cFp34 adds a deterministic, hidden-info-safe failure-mining layer over benchmark/headless runs so future AI work starts from ranked, reproducible evidence instead of pasted logs.

This phase must not tune the AI policy. It should build the artifact and analysis boundary that will tell us what to tune next.

## Problem Statement

legal-heuristic-v1 is now strong enough that isolated human logs are not enough to guide the next tuning phase. We need automatic answers to questions like:

- Which matchups consistently fail?
- Does v1 over-invest in round 1?
- Does it enter round 3 with weak resources?
- Does it pass in suspicious score/card states?
- Does it still play high-value units into weather?
- Does it waste Medic before useful revive targets exist?
- Does a new heuristic improve one matchup while damaging another?

The answer should be a stable benchmark artifact that future Codex/local-model agents can inspect without seeing hidden information.

## Goals

1. Add an automated failure-mining pipeline for benchmark/headless runs.
2. Generate deterministic, hidden-info-safe artifacts from `benchmark-v1-starter-matrix-v1`.
3. Rank suspicious AI behaviors and matchup/deck skews as findings.
4. Produce a Markdown report readable by a human and JSON/JSONL files usable by future agents.
5. Preserve current benchmark artifacts and policy behavior unless explicitly running the new mining command.
6. Establish an artifact contract that future cFp35+ policy tuning can consume.

## Non-Goals

Do not change:

- legal-heuristic-v1 move selection behavior.
- v0 behavior.
- engine rules, legal moves, scoring, prompts, or round resolution.
- catalog data, deck presets, or benchmark deck taxonomy.
- UI behavior or AI Lab product UI.
- ML training, search, ratings, CFR, MCTS, or GPU/H100 execution.

Do not serialize:

- `finalState`
- `cardsById`
- `commandLog`
- raw event logs
- hand arrays or deck arrays
- `ownHand`, `opponentHand`, `hand`, or `deck` payloads
- raw `seat_a:` / `seat_b:` instance IDs
- `unsafeDebugResults`
- unredacted card names from AI hidden hand decisions

## Recommended Design

Use a mining-only internal path that may inspect richer headless simulation data in memory, then emits only safe aggregate findings.

Important boundary: it is acceptable for the mining implementation to call existing benchmark/headless APIs with debug data enabled internally. It is not acceptable to write that debug data to disk or include it in the public artifacts.

The safe output is findings, counts, rates, bucketed values, policy ids, deck ids, factions, matchup ids, seeds, mirror indexes, and short generated messages. No raw card instance ids, hidden card names, raw command logs, or final state dumps.

## Implementation Tasks

### 1. Add Failure Mining Types

Create `src/game/benchmark/failureMining.ts`.

Define at minimum:

```ts
export const BENCHMARK_FAILURE_MINING_SCHEMA_VERSION = "benchmark-failure-mining-v1" as const;

export type BenchmarkFailureFindingKind =
  | "matchup_skew"
  | "deck_skew"
  | "round_one_overinvestment"
  | "round_three_low_resource"
  | "suspicious_pass"
  | "weathered_row_play"
  | "medic_timing_risk"
  | "leader_underuse"
  | "max_steps"
  | "policy_failed"
  | "engine_error"
  | "replay_failed";

export type BenchmarkFailureFindingSeverity = "info" | "watch" | "warning";
```

Define `BenchmarkFailureFinding` with safe fields only:

```ts
export interface BenchmarkFailureFinding {
  readonly schemaVersion: typeof BENCHMARK_FAILURE_MINING_SCHEMA_VERSION;
  readonly findingId: string;
  readonly suiteId: string;
  readonly benchmarkRunId: string;
  readonly kind: BenchmarkFailureFindingKind;
  readonly severity: BenchmarkFailureFindingSeverity;
  readonly policyId?: string;
  readonly deckPresetId?: string;
  readonly faction?: string;
  readonly matchupId?: string;
  readonly seed?: string;
  readonly mirrorIndex?: number;
  readonly count: number;
  readonly rate?: number;
  readonly message: string;
  readonly evidence: Record<string, string | number | boolean | null>;
}
```

Define `BenchmarkFailureMiningSummary`:

```ts
export interface BenchmarkFailureMiningSummary {
  readonly schemaVersion: typeof BENCHMARK_FAILURE_MINING_SCHEMA_VERSION;
  readonly suiteId: string;
  readonly benchmarkRunId: string;
  readonly recordCount: number;
  readonly findingCount: number;
  readonly findingCountsByKind: Record<string, number>;
  readonly findingCountsBySeverity: Record<string, number>;
  readonly topFindings: readonly BenchmarkFailureFinding[];
  readonly deferredSignals: readonly {
    readonly kind: BenchmarkFailureFindingKind;
    readonly reason: string;
  }[];
}
```

If extra fields are needed, keep them aggregate and hidden-info safe.

### 2. Add Optional Headless Decision Trace Collection

Current benchmark trace summaries are too compact for useful failure mining. Add an opt-in path to collect legal-heuristic-v1 decision traces during headless simulation.

Modify `src/game/sim/types.ts` and `src/game/sim/runHeadlessMatch.ts` carefully.

Add an optional flag to the simulation input, for example:

```ts
readonly collectDecisionTraces?: boolean;
```

Add an optional result field, for example:

```ts
readonly decisionTraces?: readonly AiDecisionTrace[];
```

Rules:

- Default behavior must remain unchanged.
- The default `runHeadlessSimulationBatch(...)` result shape must remain backward compatible.
- Only collect traces when explicitly requested.
- For `legal-heuristic-v1`, use `explainLegalHeuristicV1Decision(...)` to get both selected move and trace from the same pre-command observation and legal-move set.
- For policies without an explanation function, either omit traces or emit a compact safe placeholder. Do not invent detailed traces.
- Preserve policy behavior. Add a regression test proving a traced v1 run selects the same moves/outcome as an untraced v1 run for at least one deterministic fixture.

This does not mean every trace must be serialized. The failure-mining report should consume traces in memory and emit only safe findings.

### 4. Required Finding Signals

Implement at least these signals in cFp34.

#### `matchup_skew`

Use public benchmark records.

Emit when a policy has a poor win rate in a matchup or when the two mirror directions strongly disagree.

Evidence examples:

```json
{
  "recordCount": 12,
  "winRate": 0.25,
  "lossRate": 0.75,
  "drawRate": 0,
  "policyId": "legal-heuristic-v1"
}
```

#### `deck_skew`

Use public benchmark records.

Emit when a deck/faction is overperforming or underperforming across the matrix.

Evidence examples:

```json
{
  "deckPresetId": "official-nilfgaard-starter",
  "faction": "nilfgaard",
  "winRate": 0.82,
  "recordCount": 24
}
```

#### `round_one_overinvestment`

Use in-memory headless `steps` and/or command summaries. Do not serialize commands.

Emit when a seat spends a high number of hand cards in round 1 and later loses the match or reaches a weak final round.

Conservative initial rule:

- warning if a seat has `round1PlayCardCount >= 8` and loses the match.
- watch if a seat has `round1PlayCardCount >= 7` and final match result is not a win.

Evidence examples:

```json
{
  "round1PlayCardCount": 8,
  "matchOutcome": "loss",
  "finalRound": 3
}
```

#### `round_three_low_resource`

Use in-memory decision traces when available.

Emit when a policy enters round 3 with no useful unit tempo and passes or loses. Use safe trace fields only:

- `handShapeAnalysis.unitCardCount`
- `handShapeAnalysis.heroCardCount`
- `handShapeAnalysis.positiveUnitMoveCount`
- `handShapeAnalysis.specialOnlyHand`
- `roundInvestmentAnalysis.futureRoundHandQuality`

Do not emit card names or source ids.

#### `suspicious_pass`

Use decision traces and step metadata.

Emit when v1 chooses pass while one or more of these are true:

- `passAnalysis.isVoluntarilySafe === false`
- `roundInvestmentAnalysis.recommendation === "continue"`
- `roundInvestmentAnalysis.stopLossRecommended === false`
- `passAnalysis.hasSingleMoveCatchUp === true` and the selected move is still pass

Evidence must include only safe booleans and buckets.

#### `weathered_row_play`

Use `weatherPlacementAnalysis` from traces.

Emit when:

- `selectedMoveIntoWeatheredRow === true`
- selected printed strength bucket is `medium` or `high`
- selected effective strength bucket is `low` or `none`

#### `medic_timing_risk`

Use `medicTimingAnalysis` from traces.

Emit when:

- `selectedMedicWithNoTarget === true`, or
- `noTargetMedicRisk === true` and selected move is a Medic play, or
- best revive value bucket is `none` or `weak` and selected move is a Medic play.

#### `leader_underuse`

Use traces and public move summaries.

Emit only as `info` in cFp34 when a leader is legal for multiple turns but not used by match end. If this cannot be implemented safely from current data, add it to `deferredSignals` in the summary instead of guessing.

#### `max_steps`, `policy_failed`, `engine_error`, `replay_failed`

Use existing simulation/benchmark result statuses.

Emit these whenever the benchmark result status indicates a failure or max-step stop.

## Acceptance Criteria

cFp34 is complete when all are true:

1. `npm run benchmark:v1-failure-mining` exists and runs locally.
2. It writes `manifest.json`, `summary.json`, `findings.jsonl`, and `report.md` under the required path.
3. Running it twice produces stable artifact hashes.
4. The artifact hidden-info scan passes.
5. The generated findings include at least matchup/deck skew and at least two behavior-level finding kinds, or explicitly list missing behavior kinds in `deferredSignals` with reasons.
6. No AI policy behavior changes are present.
7. No engine rules/legal moves/UI/catalog/deck changes are present.
8. Tests cover hidden-info safety, deterministic serialization, and at least three finding kinds.
9. Docs and `PROJECT_STATE.md` are updated.
10. `audit/reports/2026-05-17-cFp34-report.md` exists.
