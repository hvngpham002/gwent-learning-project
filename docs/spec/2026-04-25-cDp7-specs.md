# Implementation Spec: Cluster D, Phase 7 - Engine Browser Smoke Harness

## Goal

Add a repeatable browser smoke harness for the opt-in engine shell so future engine UI, AI, and simulation work has a real UI regression tripwire.

`cDp6` made the engine shell readable enough to click through, and an orchestrator CDP review of `/?engine=1&seed=dp6-smoke` found no immediate blocker: route loading worked, mulligan worked, the AI acted through `legal-heuristic-v0`, grouped target actions appeared, no hidden AI hand patterns were visible in inspected text, and desktop/mobile layout checks showed no horizontal overflow for the reviewed state.

That review was still ad hoc. Phase 7 should turn the important parts into committed browser tests that run consistently in CI.

## Architecture Position

Current state after `cDp6`:

- legacy UI remains the default route;
- engine UI is opt-in through `?engine=1` or `VITE_ENGINE_UI=1`;
- the engine shell can complete human and AI mulligan, show AI actions, select and play human cards through grouped legal targets, show prompt ownership, and display round history;
- hidden-info-sensitive activity summaries are covered by helper tests, but not yet by a browser test;
- mobile layout has CSS wrapping safeguards, but no committed browser-level overflow check;
- CI currently runs lint, unit tests, build, forbidden-import scan, project-state check, and worktree cleanliness, but no browser test.

Phase 7 should add browser smoke coverage without changing game rules or expanding match modes.

## Scope

### 1. Add Playwright browser testing

Add Playwright as the browser smoke harness unless there is a strong reason to choose another maintained browser test runner.

Expected additions:

- `@playwright/test` dev dependency;
- `playwright.config.ts`;
- npm scripts for browser smoke testing.

Recommended scripts:

```json
{
  "test:e2e": "playwright test",
  "test:e2e:headed": "playwright test --headed",
  "ci:browser": "npm run build && npm run test:e2e"
}
```

Use Chromium only for this phase unless adding more browsers is nearly free.

Do not silently fold browser tests into `npm run ci` unless the implementation also makes the local browser install path explicit and verifies it will not make the existing staged clean gate brittle. Preferred approach for this phase:

- keep `npm run ci` as the fast deterministic local gate;
- add `npm run ci:browser` for browser smoke;
- update GitHub Actions to install the Playwright Chromium browser and run `npm run ci:browser` after `npm run ci`.

### 2. Configure a stable local web server for Playwright

The browser tests should start the app through Playwright `webServer`.

Recommended configuration:

- fixed base URL: `http://127.0.0.1:4173`;
- strict port;
- web server command using either:
  - `npm run dev -- --host 127.0.0.1 --port 4173 --strictPort`; or
  - `npm run preview -- --host 127.0.0.1 --port 4173 --strictPort` if the script always builds first.

Prefer the simplest reliable configuration. If using preview, make sure `npm run ci:browser` builds first.

Set useful defaults:

- retries in CI only;
- screenshots/videos/traces on failure;
- test timeout long enough for Vite startup but not excessive.

### 3. Add stable test selectors

Add `data-testid` attributes to the engine shell where needed. Keep them low-noise and tied to user-observable regions, not internal implementation details.

Suggested test IDs:

- `engine-shell`;
- `engine-status-banner`;
- `engine-seat-ai`;
- `engine-seat-human`;
- `engine-controls`;
- `engine-human-hand`;
- `engine-target-groups`;
- `engine-recent-activity`;
- `engine-round-history`;
- `engine-new-game`;
- `engine-confirm-mulligan`;
- `engine-pass`;
- `engine-resolve-round`.

It is acceptable to add IDs to repeated items with useful prefixes, for example:

- `engine-hand-card`;
- `engine-target-action`;
- `engine-activity-line`.

Do not add selectors that expose hidden AI hand details.

### 4. Add default-route smoke coverage

Create an E2E spec under:

- `tests/e2e/engine-shell-smoke.spec.ts`

Required default-route test:

- open `/`;
- assert the engine shell is not rendered;
- assert the app rendered enough stable legacy content to prove the route is alive.

Keep this assertion broad. The goal is to preserve opt-in routing, not to lock the legacy UI structure.

### 5. Add engine shell smoke coverage

Use the deterministic URL:

- `/?engine=1&seed=dp6-smoke`

Required browser flow:

1. Open the engine URL.
2. Assert engine shell renders.
3. Assert status banner includes seed/policy context and a mulligan next action.
4. Assert AI seat shows hand count, not AI hand card tiles.
5. Confirm human mulligan with zero selected cards.
6. Wait for the shell to reach human playing turn.
7. Assert recent activity includes:
   - human mulligan completed;
   - AI mulligan completed;
   - at least one AI-applied legal action or visible AI status update.
8. Assert AI mulligan activity does not include card IDs, source IDs, or card names from hidden hand selection.
9. Select the first enabled human hand card.
10. Assert grouped target actions appear.
11. Click the first legal target action.
12. Assert recent activity updates with a human `PlayCard` summary and no adapter error.

Use robust Playwright locators. Avoid depending on exact card names except where the seed makes the card public and the assertion is intentionally about public visibility.

### 6. Add hidden-info browser guard

Add at least one browser-level hidden-info assertion.

Minimum acceptable checks:

- AI seat displays a hand count but no AI hand card buttons/list;
- AI mulligan summary does not include selected card IDs or source IDs;
- recent activity does not display raw instance IDs or source IDs for hidden AI choices;
- no visible text matches obvious internal hidden identifiers such as `instanceId`, `sourceId`, or generated AI hidden-card IDs.

Important nuance:

- Public AI board/weather/discard cards may show card names after they become public.
- Do not assert that all AI card names are absent from the page after AI plays a public card.

### 7. Add mobile layout smoke coverage

Add a mobile viewport smoke test for the engine shell.

Minimum viewport:

- width `390`;
- height `900`;

Required assertions:

- engine shell renders;
- status banner remains visible;
- controls and hand area do not create horizontal page overflow:
  ```ts
  document.documentElement.scrollWidth <= document.documentElement.clientWidth + 1
  ```
- target action buttons wrap without horizontal overflow after selecting a playable card.

Do not attempt final mobile UX polish here unless a clear bug is found.

### 8. Keep tests deterministic and bounded

Browser smoke should stay short. It does not need to finish a full game.

Allowed:

- one mulligan;
- one human card selection;
- one human card play;
- one AI response;
- one mobile overflow check.

Out of scope for this phase:

- full game browser automation;
- drag/drop;
- multi-browser matrix;
- screenshot approval testing;
- AI-vs-AI simulation;
- deck builder flows.

### 9. Update CI

Update `.github/workflows/ci.yml` so browser smoke runs in GitHub Actions.

Expected sequence:

1. `npm ci`
2. `npm run ci`
3. install Playwright Chromium browser, for example `npx playwright install --with-deps chromium`
4. `npm run ci:browser`
5. upload `dist` artifact as before

If the implementation chooses to include browser smoke inside `npm run ci`, document why and update local workflow docs accordingly. The safer default is keeping `npm run ci` fast and adding the separate CI browser step.

## Out Of Scope

- Do not change engine rules, scoring, legal move generation, command semantics, or AI strategy.
- Do not make the engine UI the default route.
- Do not replace or delete legacy `ReduxGameManager`.
- Do not build AI-vs-AI simulation, ML export, deck builder, Card Studio, PvP, persistence, or replay viewer.
- Do not add drag/drop or final spatial board UX.
- Do not add arbitrary sleeps to hide race conditions. Use Playwright locators and state-based waits.
- Do not expose AI hidden hand or deck details for test convenience.

## Notes For The Coding Instance

- Keep the first E2E suite small. A brittle full-game browser script would slow the project down.
- Prefer `data-testid` plus user-visible assertions over CSS class selectors alone.
- Avoid exact card-name assertions unless the card is public in the visible board/weather/discard state.
- Do not read Redux internals from the browser test as a shortcut. The point is to test the user-visible shell.
- The browser smoke harness is a guardrail, not a replacement for core engine tests.
- If Playwright dependency installation requires network approval, request it explicitly and continue with clear reporting.
