# Implementation Spec: Cluster C, Phase 27 - Discard Two Draw One Leader

## Intent

Implement the remaining Tranche 3 leader-rule member from
`docs/leader-ability-matrix.md`: `discard_two_draw_one_from_deck` for
`monsters.eredin-destroyer-of-worlds` (Eredin: Destroyer of Worlds).

This is the engine's first multi-stage prompt:

1. the leader opens a prompt to discard **one or two** cards from the acting
   seat's hand;
2. after the discard selection resolves, the engine opens a second prompt over
   all remaining acting-seat deck cards;
3. the acting seat chooses any one deck card to draw into hand;
4. the remaining acting-seat deck is shuffled through the existing seeded RNG;
5. the leader is consumed only after the deck card is drawn and the deck
   shuffle completes.

The settled product decision is already recorded in
`docs/leader-ability-matrix.md`:

> discard up to two cards from hand, then show all remaining deck cards, choose
> any one card to draw, then shuffle the remaining deck. Implementable with at
> least one card in hand; zero cards in hand makes it unusable. Hidden-info
> redaction must keep the deck identities visible only to the acting seat.

Keep this phase focused on the pure engine, legal moves, prompt plumbing,
hidden-info-safe observations/exports, tests, and living docs needed for this
leader. Do not bundle `look_three_cards`, `cancel_leader`, UI redesign,
AI strategy tuning beyond compatibility, deck-builder work, Card Studio work,
catalog card promotion, or legacy UI migration.

## Rule Semantics For cCp27

### Leader Classification

`discard_two_draw_one_from_deck` is an implemented active one-shot leader.
It should be derived from the acting seat's leader identity:

```text
state.seats[seatId].leaderSourceId === "monsters.eredin-destroyer-of-worlds"
catalog leader ability === "discard_two_draw_one_from_deck"
```

It should emit one legal `use_leader` move only when all normal leader gates
pass and the seat has:

- at least 1 card in hand;
- at least 1 card in deck.

Zero cards in hand makes the leader unusable.

An empty deck makes the leader unusable.

The leader is consumed only after the second prompt resolves successfully.
Opening either prompt must not set `seat.leaderUsed` and must not emit
`leader_used`.

### Discard Count

The discard cost is **up to two**, with a minimum of one.

For a hand of `N` cards, the discard-selection stage should offer:

- every legal 1-card discard option;
- every legal 2-card discard option when `N >= 2`;
- no 0-card option.

If the hand has exactly 1 card, the leader is legal and the only discard
selection should discard that one card.

Use acting-seat hand order for deterministic option generation:

1. one-card options in hand order;
2. two-card combinations in ascending hand-index order, preserving the two
   card IDs in hand order.

Do not sort by card name, strength, source ID, or instance ID unless the
implementation has a concrete reason and documents it in the report.

### Deck Draw

After the discard selection resolves, the second prompt should offer every
remaining card currently in the acting seat's deck.

The acting seat may choose **any** deck card, including:

- Units;
- Heroes;
- Specials;
- Weather;
- generated / side-deck-only cards if they somehow physically reached the
  acting seat's deck;
- off-owner cards if they physically sit in the acting seat's deck.

Missing card instances and missing catalog sources should be skipped when
building prompt options. A valid normal deck should not contain these, but tests
should cover defensive behavior.

The chosen deck card moves to the acting seat's hand. Its immutable `owner`
is preserved; its `controller` becomes the acting seat.

The chosen deck card does **not** resolve any card ability. There is no
`card_played`, Spy draw, Medic chain, Scorch, weather application, Muster,
Summon, Avenger, Berserker, or Mardroeme behavior when the card is drawn by
this leader.

### Deck Shuffle

After the chosen card is removed from deck and moved to hand, shuffle the
remaining acting-seat deck using the existing deterministic RNG helpers:

```text
createSeededRngFromState(state.rng.seed, state.rng.state)
shuffleWithRng(remainingDeck, rng)
state.rng.state = rng.getState()
```

Emit a `deck_shuffled` event with a new reason for this leader after the
final draw resolves. Use a reason name that distinguishes this from cCp23's
discard recycle, for example:

```text
leader_discard_draw
```

If the remaining deck has length 0 or 1, `shuffleWithRng` is a deterministic
no-op and RNG state should not advance. Still emit the `deck_shuffled` event so
the event log records that the leader's shuffle step completed.

Do not shuffle either deck before the final deck-card choice. The acting seat
must choose from the pre-shuffle remaining deck.

Do not touch the opponent deck.

### Hand Discard

When the first prompt resolves, move the selected hand card(s) from acting hand
to acting discard with a new `card_moved.reason`, for example:

```text
leader_discard_for_draw
```

The discarded cards' immutable `owner` is preserved; their `controller` should
remain/reset to the acting seat because they are physically in the acting seat's
hand and then acting seat's discard.

Discarding from hand does **not** trigger battlefield discard effects. Do not
trigger Summon, Avenger, Medic, Spy, Scorch, weather, Muster, Berserker,
Mardroeme, Skellige return, or any other card ability for cards discarded from
hand by this leader.

### Prompt Transaction Timing

Use a true two-stage prompt. Do not flatten discard-selection and deck-choice
into one large Cartesian-product option list.

Recommended sequence:

1. `UseLeader` validates no target or `target.kind === "none"`, hand >= 1,
   deck >= 1, and existing leader gates.
2. `UseLeader` clones state, emits `ability_triggered`, opens the discard
   selection prompt, and returns without handoff.
3. `ChoosePromptOption` for the discard stage validates the selected hand
   cards are still in the acting seat's hand.
4. Stage-1 resolution moves selected cards hand -> acting discard, emits
   `prompt_resolved` for the discard stage, then opens the deck draw prompt.
   Leader is still not consumed; no turn handoff.
5. `ChoosePromptOption` for the deck stage validates the selected deck card is
   still in the acting seat's deck.
6. Stage-2 resolution moves the selected deck card deck -> acting hand,
   shuffles the remaining acting deck, emits `prompt_resolved`,
   `ability_resolved`, `deck_shuffled`, `leader_used`, sets
   `seat.leaderUsed = true`, clears `state.pendingPrompt`, and hands off the
   turn through the existing `choosePromptOption` command path.

This means the engine may be in a partially resolved leader state between
stage 1 and stage 2: selected cards are already in discard, `pendingPrompt`
points at the deck draw stage, and the acting seat still owns the turn.
Document and test this explicitly.

### `choosePromptOption` Validation

Add command-side stale-state validation for both stages before cloning:

  seat's hand;
- discard stage: selected count is 1 or 2;
- discard stage: selected card IDs are unique;
- deck stage: selected card still exists and is still in the acting seat's
  deck.

If validation fails, throw `EngineRuleError` and do not mutate state.

### `resolvePromptOption`

Add resolver branches for `discard_two_draw_one_from_deck`.

Stage 1 should:

- move selected hand cards to acting discard with
  `card_moved.reason === "leader_discard_for_draw"` or the chosen equivalent;
- emit `prompt_resolved` for the discard prompt;
- open the deck-draw prompt over the acting seat's current deck;
- set `state.pendingPrompt` to the new deck prompt;
- emit `prompt_opened` for the new deck prompt;
- not emit `ability_resolved`;
- not set `leaderUsed`;
- not emit `leader_used`;
- not hand off.

Stage 2 should:

- move selected deck card to acting hand with
  `card_moved.reason === "leader_draw_from_deck"` or the chosen equivalent;
- set selected card `controller = actingSeat`;
- preserve selected card `owner`;
- shuffle the remaining acting deck through existing RNG helpers;
- update `state.rng.state`;
- emit `deck_shuffled` with a distinct reason;
- emit `prompt_resolved`;
- clear `state.pendingPrompt`;
- emit `ability_resolved` with an outcome such as
  `"discarded_and_drew_card"`;
- set `state.seats[seatId].leaderUsed = true`;
- emit `leader_used`;
- rely on `commands.choosePromptOption` to perform the final turn handoff.

Do not resolve abilities on discarded cards or drawn cards.
