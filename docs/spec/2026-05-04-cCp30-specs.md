# Implementation Spec: Cluster C, Phase 30 - Post-Leader Rules Regression Audit

## Intent

Run a focused post-leader regression and audit pass now that cCp29 completed
the official leader matrix.

cCp30 is not a new feature phase. Its purpose is to prove that the 22
implemented official leaders behave coherently when combined with scoring,
round resolution, prompts, AI observation, simulation export, and the new
`cancel_leader` suppression contract.

This phase should primarily add tests and an audit report. Production fixes are
allowed only when the new tests expose a confirmed, localized bug in the
post-leader interaction surface. If the issue is broad, ambiguous, or changes a
settled rule contract, stop and report it instead of expanding scope.

## Reporting Directive

Create:

```text
audit/reports/2026-05-04-cCp30-report.md
```

## Scope

### Primary Goal

Add regression coverage that answers this question:

> After cCp29, can every implemented leader category coexist with scoring,
> prompts, round resolution, hidden-info boundaries, simulation export, and
> current-round suppression without order bugs, stale state, or information
> leaks?

### Expected Shape

Prefer focused regression files over one enormous integration file. Suggested
new test files:

```text
tests/game/coreLeaderMatrixRegression.test.ts
tests/game/coreLeaderCancelInteractions.test.ts
```

Use existing test helpers and local fixture patterns. Do not introduce broad
new factories unless the duplication becomes materially harmful.

## Required Audit Coverage

### 1. Manifest And Metadata Invariants

Assert the completed leader matrix stays complete:

- exactly 22 official leader source records are implemented;
- `OfficialLeaderPromotionManifest.placeholderLeaderAbilityIds` is empty;
- every official leader source ID appears in exactly one primary behavior
  bucket:
  - executable;
  - passive;
  - setup-time;
- the union count is 22 with no duplicates;
- every leader ability ID used by official leaders has `status:
  "implemented"`;
- no placeholder leader fixture remains in tests except deliberately unknown
  custom-authoring validator paths such as `unknown_leader_ability`.

Also assert the public counts documented by cCp29 still hold:

```text
14 executable
7 passive
1 setup-time
22 implemented union
0 placeholder
```

### 2. Active Leader Gate Matrix

For each implemented active leader category, assert the standard gates hold:

- no legal `use_leader` move after `leaderUsed`;
- no legal `use_leader` move for the wrong turn unless the path is an owned
  pending prompt option;
- no legal `use_leader` move while any prompt is pending;
- no legal `use_leader` move after the acting seat has passed;
- manual command execution rejects through the normal engine rule path when no
  legal move exists;
- no mutation occurs on rejection.

Active categories to cover:

- clear weather;
- weather-pulling leaders;
- row-Scorch leaders;
- optimize agile rows;
- restore own discard to hand;
- shuffle discards into decks;
- draw from opponent discard;
- discard two, draw one from deck;
- look three cards;
- cancel leader.

This does not require testing every individual leader record if a category has
multiple equivalent sources. It does require every category above.

### 3. Cancel Leader Suppression Matrix

Add explicit current-round suppression coverage for:

- `weather_half_penalty` / King Bran;
- `double_close`;
- `double_ranged`;
- `double_siege`;
- `double_spies`;
- `random_medic`.

For each passive, prove:

- proactive White Flame use marks the opponent suppressed for the current
  round;
- the passive policy is absent while suppressed;
- the suppression changes the relevant outcome, not just the metadata;
- round transition clears suppression;
- the passive resumes in the next round if the leader is otherwise still
  applicable;
- setup-time `draw_extra_card` is not retroactively undone.

Add active-leader suppression coverage for at least one representative of each
active category listed in section 2:

- proactive suppression blocks legal moves for that round without consuming the
  target leader;
- the target leader becomes usable next round if it was never consumed;
- reaction cancel consumes both White Flame and the attempted active leader;
- reaction cancel prevents the attempted effect from firing;
- reaction decline resolves the attempted effect exactly once and does not
  re-open the same reaction prompt.

### 4. Prompt Coexistence And Hidden-Info Boundaries

Cover prompt leaders with and without White Flame available:

- restore own discard to hand;
- draw from opponent discard;
- discard two, draw one from deck;
- look three cards;
- cancel reaction prompt.

Assert:

- reaction prompt opens before the attempted leader's own prompt or effect;
- cancel path opens no attempted leader prompt;
- decline path opens or resolves the attempted leader path exactly once;
- prompt options are visible only to the prompt owner;
- opponent perspectives do not see hidden option identities;
- `seatObservation`, safe simulation observation/export, and action encoding do
  not expose raw hidden hand/deck/discard instance IDs outside the acting
  perspective.

For look-three-cards, keep the existing product rule intact:

- reveal is one-time only;
- revealed identities live only in the pending acknowledgement prompt;
- acknowledgement clears the reveal.

### 5. Scoring, Scorch, And Round-End Interactions

Add regression coverage proving score-dependent paths use the current policy
state:

- King Bran suppression changes weather-adjusted score;
- row-horn suppression changes row totals and round winner/gem loss where
  possible;
- Double Spies suppression changes spy score before tight bond / morale / horn;
- Special Scorch, unit global Scorch, row Scorch, and leader row Scorch compute
  against the suppressed policy state;
- round settlement clears `leaderCancelledRound` before the next round begins;
- `leaderUsed` remains once-per-match and is not reset by round transition.

If building a compact scenario for every Scorch shape is too costly, cover at
least two Scorch shapes and document the untested residual risk in the report.

### 6. Ability Interaction Backfill

Run focused sanity checks that leader completion did not regress core card
ability interactions:

- Muster linked-source behavior for Gaunter, Crones, Vampires, Arachas, Cerys,
  Light Longship;
- Mardroeme/Berserker replacement after row movement or row return;
- Summon and Avenger discard-trigger behavior under round cleanup and Scorch;
- Medic behavior with and without `random_medic` suppression.

Only add tests that are useful regression locks. Do not rewrite the existing
ability implementation or duplicate every existing unit test.

### 7. AI And Simulation Smoke

Add a small deterministic headless or transaction sequence covering:

- an AI-owned White Flame reaction prompt choosing cancel via
  `legal-heuristic-v0`;
- no non-termination when prompts are chained around cancel / decline;
- safe simulation export validation after at least one suppressed leader state;
- event summaries remain public and count-only where hidden information is
  involved.

This can be a focused unit/helper test rather than a broad batch simulation.

## Production Fix Policy

If tests reveal a confirmed bug:

1. Fix only the narrow bug.
2. Add a regression test that fails without the fix.
3. Document the bug in the cCp30 report with severity and impacted paths.
4. Update `docs/gwent-rules.md` or `docs/leader-ability-matrix.md` only if the
   current docs are wrong or incomplete.

Stop and ask instead of fixing when:

- rule interpretation is ambiguous;
- the fix requires a broad command/prompt rewrite;
- the fix changes public route behavior or product UI policy;
- the fix changes deck-building rules, catalog promotion policy, or the default
  route.

## Out Of Scope

Do not implement:

- new leader abilities (the official leader matrix is already complete);
- new card abilities not already implemented;
- broad AI strategy upgrades or `legal-heuristic-v1`;
- ML export/training pipeline changes;
- deck-builder or Card Studio features;
- official card scraping or promotion;
- visual UI polish, animations, or route promotion;
- legacy Redux UI migration;
- balance tuning or starter deck changes.

## Acceptance Criteria

- cCp30 adds regression coverage across all implemented leader categories.
- cCp30 explicitly covers `cancel_leader` proactive and reaction interactions
  against passive, active, prompt, scoring, and round-transition paths.
- Hidden-info boundaries remain intact for prompt, observation, export, and
  activity-summary surfaces.
- Production behavior changes, if any, are narrow, tested, and documented as
  findings.
- `docs/PROJECT_STATE.md` is updated.
- The phase report exists at
  `audit/reports/2026-05-04-cCp30-report.md`.
- The report includes a clear interaction matrix and severity-ranked findings.
