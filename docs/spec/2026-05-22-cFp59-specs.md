## Summary

cFp58 concluded that the next search-family phase should be a hidden-info-safe
root profiler, not a search-playing policy. The current engine, legal move
generation, `SeatObservation`, headless simulation, benchmark harness, and
rating ledger are good enough to measure root branching and budget pressure.
They are not yet enough to run safe hidden-state sampling, PIMC, or ISMCTS.

cFp59 implements the profiler cFp58 recommended. It collects public scalar
metrics at each decision root in selected benchmark suites, writes deterministic
public artifacts, and updates docs/AI Lab metadata. It must not run rollouts,
sample hidden worlds, implement search, or change AI behavior.

## Research Grounding

Use cFp58 as the controlling decision:

- cFp59 should implement a hidden-info-safe root-state profiler;
- it should collect branching and budget metrics from existing headless
  benchmark roots;
- it should write deterministic public artifacts under the benchmark-results
  tree;
- it should include no rollouts, no tree search, no PIMC, no ISMCTS, no
  oracle/debug search, and no product-selectable search AI;
- it should produce distributions that help decide whether a later
  `determinized-pimc-probe-v0` or `so-ismcts-probe-v0` is tractable.

Use Batch A guardrails:

- default search/profiler artifacts start from the acting seat's observation
  and legal moves, not raw full state;
- unsafe oracle/debug work must have different variant labels and artifact
  paths;
- branching instrumentation and runtime/budget reporting must be explicit
  before search strength claims.

Use Batch B guardrails:

- raw public ledgers and fixed suites remain source of truth;
- ratings are post-engine summaries, not robustness proof;
- search/readiness probes must record observation contract, budget, and
  uncertainty.

## Profiler Integration

Add an opt-in root observer path. The preferred design is:

- add an optional callback to the headless simulation loop that receives:
  - current `MatchState`;
  - acting `seatId`;
  - legal moves for that seat;
  - step/decision index;
  - public benchmark context passed from the benchmark runner;
- call the observer after legal moves are generated and before policy
  selection;
- the observer returns no command and cannot influence policy selection;
- default headless simulation and benchmark behavior is unchanged when the
  observer is absent.

If a different design is used, it must still prove:

- no policy behavior changes;
- no duplicate rule path;
- no raw full state or raw move payload is serialized;
- profiler collection is opt-in and benchmark-only.

## Root Record Schema

Use a versioned root row schema:

```ts
type SearchReadinessRootSchemaVersion = "search-readiness-root-v1";
```

Each committed `roots.jsonl` row must include only public scalar/count fields.
Required fields:

- `schemaVersion`
- `profileRunId`
- `suiteId`
- `matchupId`
- `seed`
- `mirrorGroupId` when present
- `mirrorIndex` when present
- `step`
- `decisionIndex`
- `phase`
- `round`
- `seatId`
- `policyId`
- `faction`
- `deckPresetId`
- `legalMoveCount`
- `moveKindCounts`
- `targetKindCounts`
- `targetSideCounts`
- `playCardMoveCount`
- `playCardSourceCount`
- `playCardTargetExpansionCount`
- `promptOptionCount`
- `mulliganOptionCount`
- `rowTargetMoveCount`
- `hornTargetMoveCount`
- `weatherTargetMoveCount`
- `cardTargetMoveCount`
- `passLegal`
- `leaderLegal`
- `rootPublicFingerprint`

Allowed `moveKindCounts` keys are the current public legal move kinds:

- `choose_mulligan`
- `play_card`
- `use_leader`
- `choose_prompt_option`
- `pass`
- `resolve_round_end`

Allowed `targetKindCounts` keys:

- `none`
- `board_row`
- `row_horn`
- `weather`
- `card`
- `deck_card_source`
- `card_instance_set`
- `deck_card_instance`

Allowed `targetSideCounts` keys:

- `own`
- `opponent`
- `public`
- `none`

Counting rules:

- `playCardSourceCount` counts distinct in-process `sourceCardId` values for
  `play_card` moves but serializes only the count, never the IDs.
- `playCardTargetExpansionCount = max(0, playCardMoveCount - playCardSourceCount)`.
- `promptOptionCount` counts `choose_prompt_option` moves.
- `mulliganOptionCount` counts `choose_mulligan` moves.
- `rowTargetMoveCount` counts moves whose target kind is `board_row`.
- `hornTargetMoveCount` counts moves whose target kind is `row_horn`.
- `weatherTargetMoveCount` counts moves whose target kind is `weather`.
- `cardTargetMoveCount` counts moves whose target kind is `card`.
- `passLegal` is true when any legal move has kind `pass`.
- `leaderLegal` is true when any legal move has kind `use_leader`.

Do not serialize:

- `moveId`
- `sourceCardId`
- `sourceId`
- `cardId`
- card names
- card labels
- raw target card IDs
- action refs
- prompt option labels
- command logs
- event logs
- final state
- raw state
- decision traces
- unsafe debug results

## Root Public Fingerprint

`rootPublicFingerprint` must be deterministic and hidden-info safe.

It may hash:

- schema version;
- suite id;
- matchup id;
- seed;
- mirror index;
- step;
- decision index;
- phase;
- round;
- seat id;
- policy id;
- faction;
- deck preset id;
- legal move count;
- move-kind counts;
- target-kind counts;
- target-side counts;
- scalar fields from the root record.

It must not hash raw private zones, raw card IDs, card names, source IDs, raw
move labels, command logs, event logs, full final state, or unsafe debug
payloads. If the implementation hashes a broader object and then omits it from
the artifact, that is still a violation.

## Determinism And Timing

Committed cFp59 artifacts must be deterministic across repeated runs.

Do not serialize wall-clock per-root timing in committed JSON/Markdown artifacts,
because it will make hashes unstable. cFp58 requested elapsed-time awareness;
cFp59 should record this as a deliberate timing-policy decision in the report:
root branching and structural budget metrics are committed now, while
wall-clock timing is deferred to a future non-deterministic local timing profile
or a carefully separated `.local` artifact.

The CLI may print a total elapsed time to stdout, but that value must not be
written into committed artifacts.
