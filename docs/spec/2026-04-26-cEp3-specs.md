# Implementation Spec: Cluster E, Phase 3 - Product Match Interactions

## Goal

Turn the current authentic match table from a playable V1 shell into a product-grade match interaction layer.

This phase must stay anchored to the existing Cluster E plan:

- spatial target interactions;
- selected-card inspector and legal target polish;
- discard pile browser;
- Medic and Decoy prompt/target presentation;
- round-end overlay;
- UI-only animation hooks.

Add one bounded refinement from recent playtesting: visible battlefield cards should show engine-derived effective strength and modifier state. This is a readability requirement, not a new rule implementation.

## Architecture Position

Before this phase:

- `/` renders the legacy Redux UI.
- `/?engine=1` renders the diagnostic engine shell.
- `/?engine=1&ui=authentic` renders the cEp2 engine-backed authentic match table.
- `/?engine=1&ui=authentic&view=harness` renders the cEp1 card foundation harness.
- `src/game/core/` owns rules, legal moves, scoring, prompts, command transactions, round settlement, and game end.
- `src/components/gwent/AuthenticMatchScreen.tsx` consumes engine selectors and dispatches engine thunks.

After this phase:

- Route behavior above must remain unchanged.
- The authentic match table must support richer product interactions without adding UI-side rule calculations.
- Discard pile browsing, board effective-strength display, prompt/target polish, and round overlay must all read from engine state and legal moves.

## Scope

### 1. Preserve Routes And Existing Surfaces

Do not replace or remove existing routes.

Requirements:

- `/` remains the legacy UI.
- `/?engine=1` remains the diagnostic engine shell.
- `/?engine=1&ui=authentic` remains the product match table.
- `/?engine=1&ui=authentic&view=harness` remains the visual foundation harness.
- No default-route promotion in this phase.

### 2. Add A Public Discard Browser

Add a product discard browser for both public discard piles.

Requirements:

- Clicking either discard pile opens a browser/drawer/modal for that seat's discard pile.
- The browser must show all public discard cards for that seat, not just the top card.
- It may group cards by card kind, row, faction, or ability. Keep the grouping simple and useful.
- It must render discard cards with printed strength, not battlefield effective strength.
- Empty discard piles should show a quiet empty state.
- Closing the browser must not alter engine state.
- The top discard card and count in the left rail should remain.
- The browser must not expose AI hand, AI deck, AI deck order, or hidden card instance/source identifiers.
- It is acceptable for opponent discard cards to be visible because discard is a public zone.

Suggested stable selectors:

- `authentic-discard-trigger-human`
- `authentic-discard-trigger-ai`
- `authentic-discard-browser`
- `authentic-discard-card`
- `authentic-discard-close`
- `authentic-discard-empty`

Implementation guidance:

- Prefer adding pure helpers to `src/components/gwent/matchViewModel.ts` for grouping and labeling.
- Avoid local duplication of discard state. Derive from `selectEngineDiscardCards` and current seat map.
- If a discard browser reuses `AuthenticCard`, pass a view model that displays printed strength.

### 3. Display Effective Strength On Visible Board Cards

Visible battlefield cards should show current engine-derived effective strength.

Requirements:

- Use `selectEngineScoreBreakdown` as the source of effective strength.
- Build a lookup keyed by engine card instance id from `score.cards`.
- For visible board cards only, display `finalStrength` from the scoring breakdown.
- Hand, deck, discard, prompt-option cards, and non-board inspector cards should still show printed strength.
- If selected card is currently on board, the inspector may show both printed and effective strength.
- Do not compute Weather, Horn, Tight Bond, Morale, Hero immunity, or Scorch eligibility in React.
- If a visible board card has no score entry, fall back to printed strength and make the report call out the fallback.
- Visual state should distinguish:
  - normal: effective equals printed;
  - boosted: effective greater than printed;
  - reduced: effective less than printed.
- Weather-reduced cards, Horn/Tight Bond boosted cards, and Morale-boosted cards should be readable without inspecting row totals.

Suggested component/view-model shape:

```ts
interface AuthenticBoardCardState {
  readonly effectiveStrength: number;
  readonly printedStrength: number;
  readonly strengthState: "normal" | "boosted" | "reduced";
  readonly modifiers: readonly string[];
}
```

The exact shape may differ, but keep it in a pure helper and keep rule math out of UI components.

Suggested stable selectors:

- `authentic-effective-strength`
- `authentic-strength-boosted`
- `authentic-strength-reduced`

Testing requirements:

- Unit/helper test that a board card with a score entry maps to effective strength.
- Unit/helper test that hand/discard cards keep printed strength.
- Browser smoke that exercises at least one visible effective-strength marker if the deterministic seed can reach it cheaply. If no cheap seed exists, add a focused component/helper test and document the browser limitation.

### 4. Improve Spatial Target Interactions

Keep legal target buttons as a fallback, but make the board itself more interactive where the legal move shape supports it.

Requirements:

- Row targets from `play_card` moves with `target.kind === "board_row"` should keep highlighted clickable rows.
- Card-instance targets from `play_card` moves with `target.kind === "card_instance"` should highlight valid board cards and allow clicking the valid card to dispatch that exact move.
- This primarily supports Decoy-style targeting in cEp3.
- Row horn, weather, and global/none targets may remain action-panel buttons if direct spatial semantics are unclear.
- The selected-card inspector and target/action panel should remain available and should explain the selected card's legal action set.
- If a card target is valid but hidden or not visible, keep the action-panel button fallback.

Suggested stable selectors:

- `authentic-board-row-target`
- `authentic-board-card-target`
- `authentic-target-groups`
- `authentic-target-action`
- `authentic-selected-card-inspector`

Boundary:

- Do not invent target validity in React.
- Do not compute Decoy rules in React.
- Do not dispatch commands not represented by engine legal moves.

### 5. Add Product Prompt Presentations

Improve prompt rendering while preserving legal-move ownership.

Requirements:

- Generic prompt fallback remains for unknown future prompt kinds.
- Human-owned prompt options must come from legal `choose_prompt_option` moves only.
- AI-owned prompts must not expose hidden AI hand/deck information.
- Medic prompts should get a product presentation over the current engine prompt options:
  - show the source card/ability where public;
  - show revive options grouped by target card where useful;
  - show printed target card strength, row, faction, and ability metadata;
  - show the engine option label or equivalent text, including Spy-to-opponent placement when applicable;
  - selecting an option dispatches the exact `ChoosePromptOption` command for that legal move.
- Medic chains must continue to work through the same prompt presentation.
- Decoy is not currently an engine prompt. Present Decoy through card-instance legal target highlights and target action buttons, not by inventing a new prompt state.

Suggested stable selectors:

- `authentic-prompt`
- `authentic-prompt-option`
- `authentic-medic-prompt`
- `authentic-medic-option`
- `authentic-ai-prompt-pending`

Boundary:

- Do not build a separate prompt reducer.
- Do not mutate engine state from prompt UI.
- Do not show ordinary play/pass/leader controls as active while a human prompt is pending, except prompt-option controls.

### 6. Add A Round-End Overlay

Add a product overlay or prominent panel for resolved round results.

Requirements:

- During `round_end`, continue to show a clear `Resolve Round` action driven by the existing legal `resolve_round_end` move.
- After `ResolveRoundEnd`, show the latest engine `roundHistory` entry as a dismissible overlay or prominent product panel.
- The overlay should include:
  - round number;
  - final score by seat;
  - winner or draw;
  - gem loss by seat;
  - next starter if the game continues;
  - game-end winner/draw if the game is over.
- The overlay observes engine state/history only.
- It must not compute round winner, gem loss, or game winner in React.
- It must not dispatch `ResolveRoundEnd` automatically.
- It must not delay or time engine transitions.
- Dismissing the overlay is UI-only state.

Suggested stable selectors:

- `authentic-round-overlay`
- `authentic-round-overlay-dismiss`
- `authentic-resolve-round`

Testing requirements:

- Helper/component test that a round-history entry maps to overlay display text.
- Browser smoke should reach round-end readiness or resolved round overlay if a deterministic seed can do so cheaply. If the short smoke cannot reach it, add a narrower integration/helper test and document the limitation.

### 7. Add UI-Only Animation Hooks

Add hooks for future motion without changing rule timing.

Requirements:

- Add classes/data attributes for recently moved/played/discarded/scorched cards when that can be derived safely from recent public events.
- Keep animation conservative. A subtle highlight is enough.
- Do not use timers to sequence engine state.
- Do not delay AI, prompt, pass, round settlement, or game-end transitions.
- Do not introduce Framer Motion or another animation dependency unless it is already used in the relevant path and the report justifies it.

Suggested stable attributes/classes:

- `data-card-motion="played"`
- `data-card-motion="discarded"`
- `data-card-motion="prompt-revived"`
- `data-card-motion="scorched"`

If reliable public event attribution is not available, implement only static hook classes and document what remains for a future animation phase.

### 8. Strengthen Hidden-Info And Public-Zone View Models

The new UI should make public zones richer without weakening hidden-info safety.

Requirements:

- AI hand remains count/back only.
- AI deck remains count/back only.
- Discard browser can show both discard piles because discard is public.
- Board, weather, and discard are public lookup sources.
- Activity/battle-log summaries may show card names only when the card is public or belongs to the human actor.
- Visible text and test snapshots must not include raw engine `instanceId` values, generated ids such as `seat_a:000:`, or debug-only field names.

Suggested helper additions:

- public discard grouping helper;
- board card effective-strength helper;
- round overlay view-model helper;
- visible card lookup helper that explicitly documents which zones are public.

### 9. Keep The Product Surface Mobile-Safe

Requirements:

- No horizontal document overflow at 390px width.
- Discard browser, prompt panel, target actions, and round overlay must fit or scroll within their own surfaces.
- Text inside buttons/cards must wrap or truncate cleanly without overlapping.
- Hand strip may scroll horizontally inside itself.

## Tests

Suggested unit/component tests:

- `tests/components/gwent/authenticMatchViewModel.test.ts`
  - discard grouping preserves public cards and no hidden hand cards;
  - board effective strength maps from score entries;
  - non-board cards keep printed strength;
  - card-instance target lookup marks only legal target cards;
  - round overlay view model maps round history without computing results.
- Add a component test file if helpers become too large for the existing test.

Update Playwright smoke in `tests/e2e/engine-shell-smoke.spec.ts` or split a focused e2e file.

Browser smoke should cover:

- `/` still legacy.
- `/?engine=1` still diagnostic shell.
- `/?engine=1&ui=authentic&view=harness` still harness.
- `/?engine=1&ui=authentic&seed=ep3-smoke` still match screen.
- discard browser opens for both seats and shows public discard counts/cards after at least one card reaches discard, if reachable cheaply;
- hidden-info checks still pass;
- selecting a playable card still shows legal target actions;
- card-instance target highlight if a deterministic short setup can expose Decoy; otherwise cover in helper tests and report the limitation;
- prompt panel ownership and prompt option buttons if a deterministic short setup can expose Medic; otherwise cover in helper tests and report the limitation;
- mobile viewport has no horizontal document overflow with discard/prompt/overlay surfaces.

Do not make the browser test brittle by depending on exact random hand contents unless a deterministic seed and sequence are documented in the report.

## Non-Goals

Do not:

- replace the default `/` route;
- remove `EngineGameManager`;
- remove `AuthenticUiHarness`;
- build pre-game setup;
- build deck builder;
- build Card Studio;
- add local PvP or AI-vs-AI product mode;
- change AI policy;
- add ML/export/tensorization work;
- add drag-and-drop;
- add full card-flight animation timing;
- introduce a new rule engine path;
- compute rule outcomes in React;
- port prototype `match-engine.jsx` logic;
- import legacy rule helpers, legacy game thunks/selectors/slice, legacy AI, or `GameBoard` into `src/components/gwent/`.

If implementation uncovers a rule bug, fix only if it blocks this phase, add a focused engine regression, update `docs/gwent-rules.md` and `docs/PROJECT_STATE.md`, and call it out as a deviation in the report. Otherwise report it for the orchestrator.

## Boundary Rules

Product UI code may import:

- React;
- Redux hooks;
- engine Redux selectors/thunks/slice selection actions;
- `src/game/core` types;
- current catalog display data;
- authentic card components;
- pure UI helper modules.

Product UI code must not import:

- `src/utils/gameHelpers`;
- `@/utils/gameHelpers`;
- `calculateTotalScore`;
- `calculateRowStrength`;
- `useReduxAI`;
- `AIStrategyCoordinator`;
- `gameSlice`;
- `gameThunks`;
- `gameSelectors`;
- `GameBoard`;
- prototype files under `docs/ui-handoff/`.

Do not add exceptions to `scripts/check-forbidden-imports.mjs` for product UI. If new product UI paths are added under `src/components/gwent/`, they must remain covered by the current forbidden-import scan.

## Acceptance Criteria

This phase is complete when:

- `/?engine=1&ui=authentic` remains playable and gains product interaction polish.
- Discard browser opens for both public discard piles and does not leak hidden hand/deck identity.
- Board cards display engine-derived effective strength and modifier state.
- Hand/deck/discard cards still display printed strength.
- Row and card-instance legal targets have spatial affordances where visible.
- Medic prompt presentation is legal-move backed and handles prompt chains.
- Decoy card-instance targets are visible/clickable when legal and visible.
- Round-end overlay displays engine round-history data without computing rule outcomes.
- UI-only animation hooks exist without timing engine transitions.
- Browser smoke covers the updated authentic match surface on desktop and mobile.
- `docs/PROJECT_STATE.md` is updated.
- A report exists at `audit/reports/2026-04-26-cEp3-report.md`.
