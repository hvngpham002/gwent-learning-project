# cFp31.1 Specs - Benchmark Refresh And AI Metadata Cleanup

## Purpose

Refresh the deterministic `legal-heuristic-v1` benchmark artifacts after cFp31
round-investment preservation and clean the public metadata/docs that still
carry cFp30 benchmark totals or duplicate cFp31 active-state text.

This phase is artifact/metadata/documentation hygiene only. It must not change
AI policy behavior.

## Context

cFp31 implemented round-investment and future-hand preservation for
`legal-heuristic-v1`, then received two repair passes. The merged `dev` branch
now has cFp31 behavior and tests, but:

- `benchmark-v1-smoke-v1` and `benchmark-v1-starter-matrix-v1` artifacts still
  reflect cFp30 totals.
- `src/game/ai/productPolicies.ts` still surfaces those cFp30 totals through
  `/ai-lab`.
- `docs/research/literature/ai/policies/legal-heuristic-v1.md` says cFp31
  benchmark totals are carried from cFp30.
- `docs/PROJECT_STATE.md` has duplicate "Active Cluster F behavior spec:
  cFp31" lines and should be collapsed into a completed/current-state summary.
- `audit/reports/2026-05-14-cFp31-report.md` records benchmark refresh as
  deferred due to the Windows `tsx` issue. This Mac environment should attempt
  the refresh directly.

## Goals

1. Regenerate current cFp31 v1 benchmark artifacts for:
   - `benchmark-v1-smoke-v1`
   - `benchmark-v1-starter-matrix-v1`
2. Confirm the artifact output is deterministic across repeated runs.
3. Update shared product AI policy metadata and AI Lab tests with the refreshed
   cFp31 totals.
4. Update the v1 policy doc and project state so cFp31 is no longer described
   as benchmark-stale.
5. Create a cFp31.1 phase report that records the exact artifact hashes and
   verification commands.

## Non-Goals

- Do not tune `legal-heuristic-v1`.
- Do not change `legal-heuristic-v0`.
- Do not add a new policy ID, difficulty tier, rating system, search policy,
  Python tooling, model training, or browser benchmark runner.
- Do not change engine rules, legal moves, prompts, scoring, catalog data,
  deck presets, product match UI behavior, or hidden-info boundaries.
- Do not rewrite the benchmark harness beyond what is necessary to run the
  existing suites.
- Do not remove historical cFp27-cFp31 policy-doc sections.
