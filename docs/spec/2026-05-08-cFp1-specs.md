# cFp1 Specs - Gwent AI Literature Sweep Triage

## Phase

Cluster F Phase 1: Literature Sweep Triage

## Goal

Turn the first multi-model Gwent AI literature sweep into a concrete,
source-status-aware triage result. This phase does not annotate papers
and does not change AI implementation code.

## Inputs

Read:

- `AGENTS.md`
- `docs/PROJECT_STATE.md`
- `docs/research/literature/ai/ANNOTATION_WORKFLOW.md`
- `docs/research/literature/ai/results/2026-05-08/queue.md`
- `docs/research/literature/ai/results/2026-05-08/triage.md`
- raw model outputs under
  `docs/research/literature/ai/results/2026-05-08/`

## Scope

1. Triage all available raw model outputs for the 2026-05-08 sweep.
2. Spot-check high-value candidates against primary or near-primary
   metadata pages where practical.
3. Update the sweep docs:
   - `triage.md`
   - `queue.md`
   - `brief.md`
   - `handoff.md`
   - `prompt.md` if the raw-output storage note is stale
4. Update `docs/overhaul-plan/ai-ml-roadmap.md`.
5. Update `docs/PROJECT_STATE.md`.
6. Create `audit/reports/2026-05-08-cFp1-report.md`.

## Out Of Scope

- No engine, UI, AI policy, simulation, catalog, test, route, CI, or
  package changes.
- No paper annotation yet.
- No source PDF download.
- No source package creation unless needed to support a clearly
  documented handoff.
- No implementation spec for `legal-heuristic-v1`, ISMCTS, RL, CFR,
  or evaluation tooling yet.

## Triage Rules

Classify candidates as:

- `Direct hit`
- `Partial hit`
- `Background-only`
- `Low-confidence lead`
- `Reject`

Use source status:

- `local-source-available`
- `url-only`
- `secondary-lead-only`
- `missing-source`

Treat raw model outputs as retrieval leads. Do not promote a model-only
claim to project guidance unless it is either independently verified or
explicitly marked as low confidence.

## Required Conclusions

The triage must answer:

1. What should be read first under the annotation workflow?
2. Which method family looks most plausible for the first practical
   Cluster F implementation after annotation?
3. Which sources are useful but too high-resource or too indirect for
   near-term implementation?
4. Which model-suggested leads look unreliable enough to reject or
   quarantine?
5. What is the recommended next phase?

## Required Checks

- `git diff --check`
- `npm run check:project-state -- --base HEAD~1`

## Reporting Directive

Create:

- `audit/reports/2026-05-08-cFp1-report.md`

The report must include files changed, behavior changed, checks run,
acceptance criteria status, deviations, risks/follow-ups, Project State
Update, and recommended next step.
