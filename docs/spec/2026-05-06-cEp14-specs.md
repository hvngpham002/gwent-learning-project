# Cluster E Phase 14: Pre-AI Responsive Stabilization

Date: 2026-05-06

## Phase Goal

Resolve the small visual issues surfaced by the cEp13 visual audit and bring the current mobile authentic UI closer to the desktop experience before moving to the next AI phase.

This is **not** the final mobile redesign. The goal is to make the current product routes respectable and usable at `390px` width, while preserving the desktop visual language and avoiding a broad navigation/product rethink.

Primary reference:

- Visual audit report: `audit/reports/2026-05-06-cEp13-visual-ui-audit-report.md`
- Screenshot evidence: `audit/screenshots/2026-05-06-ui-visual-audit/`
- Current active UI spec lineage: `docs/spec/2026-05-05-cEp13-specs.md`

## Context

The visual audit found that:

1. Authentic desktop surfaces are broadly coherent.
2. Mobile authentic match currently stacks too much secondary metadata before the board/hand.
3. Official Porting still behaves like a very long document instead of the newer bounded authoring workspace.
4. The legacy default route still has mobile horizontal overflow and a React DOM nesting warning.
5. Desktop match at `1440x900` slightly exceeds the viewport and partially pushes the hand below the fold.
6. Mobile Deck Builder and Card Studio no longer overflow horizontally, but their first-screen hierarchy is still too heavy.

This phase should address those issues narrowly, with tests and screenshots, without changing rules, AI, catalog data, or route defaults.

## Scope

### 1. Desktop Match First-Viewport Fit

Tighten the authentic match board at common laptop/desktop viewport heights.

Requirements:

- At `1440x900`, the active match board should show:
  - top match status;
  - both score-card columns or their current desktop side panels;
  - all six board rows;
  - at least the top of the human hand panel/cards without requiring body scroll.
- Reduce vertical waste rather than shrinking card faces aggressively.
- Prefer adjustments such as:
  - tighter top status/header spacing;
  - slightly more compact empty row padding;
  - reducing nonessential panel margin/gaps;
  - making the match shell more viewport-aware.
- Preserve desktop board readability and the cEp13 weather overlay behavior.

### 2. Mobile Match Board Hierarchy

Bring mobile match closer to the desktop play experience by prioritizing gameplay surfaces before secondary panels.

Requirements at `390x900`:

- No document-level horizontal overflow.
- The initial active-match viewport should include visible board content, not only score/resource/public-zone panels.
- Board rows must appear before or alongside secondary public-zone panels on mobile.
- Human hand should be reachable substantially earlier than it is in the cEp13 audit screenshot.
- Public deck/discard/weather information must remain available, but it may be compacted, reordered, or visually reduced.
- Score cards should stay hidden-info-safe:
  - AI hand details remain backs/counts only;
  - no AI hand card names/source IDs/instance IDs become visible.
- Existing interactions must remain usable:
  - selecting a hand card;
  - row targets;
  - Weather panel target;
  - row horn slots;
  - Decoy/card-instance targets;
  - right-click inspection on visible cards;
  - pass / leader / resolve round controls;
  - battle log access.
- Do not attempt a final mobile-specific game UI. Avoid introducing major new mobile navigation, swipable boards, or touch-drag redesign in this phase.

Implementation guidance:

- Prefer CSS/layout restructuring over engine/UI state rewrites.
- If needed, create mobile-only compact wrappers for public zones and actions, but keep data sourced from the existing authentic match view models/selectors.
- If a public-zone drawer/disclosure is introduced, it must default to a compact state that does not bury the board, and its controls must follow existing authentic button styling.

### 3. Official Porting Workspace Stabilization

Bring Official Porting in line with Deck Builder and Card Studio's cEp13 viewport-spanning authoring treatment.

Requirements:

- `/?engine=1&ui=authentic&view=official-porting` should use a full-viewport workspace shell rather than a very long document.
- Candidate list, review/editor panel, and preview/status rail should be bounded internal scroll regions.
- Use the shared hidden-native-scrollbar plus parchment fade-edge treatment where appropriate.
- Preserve all current review behavior, local storage behavior, candidate counts, approval/rejection/note/crop data, import/export controls, and no-promotion contract.
- Do not add virtualization unless it is simple and low-risk; bounded scroll is sufficient.

### 4. Legacy Default Route Minimal Fixes

Because `/` remains the default route, fix the obvious legacy-route technical visual debt without redesigning the legacy game.

Requirements:

- At `390x900`, `/` must not have document-level horizontal overflow.
- Fix the React `validateDOMNesting` warning found in the audit:
  - current warning: `<ul>` cannot appear as a descendant of `<p>`.
- Keep the disclaimer route behavior and legacy UI behavior unchanged.
- Do not port legacy UI to the authentic design language.
- Do not promote the authentic route to `/`.

### 5. Mobile Deck Builder And Card Studio First-Screen Cleanup

Make mobile authoring surfaces less awkward while deferring the full tabbed/drawer authoring redesign.

Deck Builder requirements at `390x900`:

- No document-level horizontal overflow.
- Header actions should not dominate the first viewport more than necessary.
- The selected deck context and central card pool should appear earlier than in the cEp13 audit screenshot.
- The deck list, card pool, stats rail, generated cards, and cards-in-deck surfaces should remain reachable and internally scrollable where appropriate.
- Preserve all current deck-builder behavior: add/remove, faction/leader changes, generated cards, validation, import/export/copy, Card Studio navigation, save, play, context menu, and inspect modal.

Card Studio requirements at `390x900`:

- No document-level horizontal overflow.
- Header actions should not dominate the first viewport more than necessary.
- The editor form should appear earlier and remain readable.
- Preview/validation should remain reachable without covering or obscuring editor fields.
- Preserve all current Card Studio behavior: custom card/leader creation, validation, save draft/playable, import/export/copy, image upload/path mode, delete/reset/duplicate, and deck-reference handling.

Implementation guidance:

- Prefer compact responsive layout and existing scroll-fade utilities.
- Avoid a new tabbed authoring workflow in this phase unless it is the smallest reliable way to meet the requirements.
- Keep button styling consistent with the authentic button style guide.

## Out Of Scope

- No engine rule, scoring, legal-move, command, prompt, round-resolution, or game-end changes.
- No Redux adapter behavior changes.
- No AI policy changes.
- No catalog data, deck preset, Card Studio schema, or official-porting staging data changes.
- No route promotion. `/` remains legacy; authentic remains opt-in through `?engine=1&ui=authentic`.
- No final mobile redesign, mobile tab architecture, touch-drag redesign, or swipe navigation.
- No new visual asset generation unless a tiny CSS/code-native icon is necessary.
- No hidden-info exposure.
- No broad legacy UI restyle.

## Acceptance Criteria

### Desktop Match

- At `1440x900`, active authentic match shows the human hand panel/cards in the first viewport.
- Desktop weather overlays, row labels, row scores, horn slots, card selection, drag/drop, right-click inspection, battle log, leader actions, and pass/resolve controls still work.

### Mobile Match

- At `390x900`, active authentic match has no document-level horizontal overflow.
- At `390x900`, the first viewport includes visible board rows/content.
- At `390x900`, the board/hand are not buried below deck/discard/weather meta panels as in the cEp13 audit screenshot.
- AI hand/card identities remain hidden; existing hidden-info assertions still pass.
- Mobile pass/leader/action controls remain reachable.

### Official Porting

- Official Porting desktop and mobile routes no longer produce a document scroll height in the tens of thousands of pixels.
- Candidate list, review/editor, and preview/status areas scroll internally.
- Candidate counts and review controls remain visible and functional.

### Legacy Default

- `/` at `390x900` has no document-level horizontal overflow.
- The React DOM nesting warning from the cEp13 audit is gone.
- Disclaimer route behavior remains unchanged.

### Mobile Authoring

- Deck Builder and Card Studio mobile screenshots are visibly closer to their desktop hierarchy: less first-screen action clutter, earlier access to the main editing/card surface, no horizontal overflow.
- Current Deck Builder and Card Studio workflows remain intact.
