## Summary

cFp61 successfully materialized hidden opponent source-multiset samples for the
large majority of official-starter benchmark roots, but it also left a small
set of safe invalid roots:

- `benchmark-v1-starter-matrix-v1`: 63 invalid roots out of 4,042.
- `benchmark-v1-starter-matrix-robust-v1`: 341 invalid roots out of 32,487.
- All invalid roots currently report `insufficient_prior_remaining`.

cFp62 is a diagnostic casebook phase. It must explain those invalid roots using
hidden-info-safe scalar evidence before the project attempts a determinized
probe. This phase should add a reusable invalid-root analyzer and deterministic
casebook artifacts. It must not change sampler materialization behavior unless
the analysis proves a narrow accounting bug and the report/spec are updated
first.

The goal is to decide whether cFp63 should:

1. refine the sampler for a narrow public-count edge case;
2. run `determinized-pimc-probe-v0` over valid roots only with explicit
   invalid-root skip accounting; or
3. add another instrumentation pass because the invalid-root evidence is still
   ambiguous.

## Research Grounding

cFp58 is still the controlling search-readiness decision. It says search work
must remain sampler-first, hidden-info-safe, and separate from product gameplay.

cFp60 built the known-preset prior and public action abstraction. cFp61 turned
the sampler from deferred into real in-memory hidden source-multiset samples.
The remaining invalid roots are not a reason to start search blindly. They are
the next research question.

Long-style determinization guardrail:

- invalid roots must be counted, not silently dropped;
- a determinized probe must disclose skipped roots before reporting any outcome;
- committed artifacts must not expose sampled hidden identities, source ids,
  runtime ids, raw state, or raw legal moves;
- a sampler casebook can only recommend next steps, not make strength claims.

## Analyzer Contract

### Input

The analyzer should use the same benchmark root-observer path as cFp61. Do not
parse cFp61 `roots.jsonl` as the only source of truth, because the committed
cFp61 rows intentionally bucketed or omitted the granular scalar evidence needed
for this casebook.

Allowed inputs:

- current headless benchmark roots from the two official-starter suites;
- public root metadata already used by cFp61;
- opponent-seat known preset prior metadata;
- public-zone card counts derived without inspecting hidden opponent hand/deck
  identities;
- cFp61 materialization status and invalid reason counts.

Forbidden inputs:

- true opponent hand card identities;
- true opponent deck card identities or order;
- hidden runtime card ids;
- raw `cardsById` serialized in artifacts;
- raw command logs, event logs, final state, raw legal moves, or unsafe debug
  payloads in artifacts.

### Required Scalar Evidence

For each invalid root record, include only scalar/count fields like these:

```ts
interface SamplerInvalidRootRecord {
  schemaVersion: "sampler-invalid-root-v1";
  samplerRunId: string;
  suiteId: string;
  matchupId: string;
  seed: string | number;
  mirrorGroupId?: string;
  mirrorIndex?: 0 | 1;
  step: number;
  decisionIndex: number;
  phase: MatchPhase;
  round: number;
  seatId: SeatId;
  policyId: string;
  faction: Exclude<CatalogFaction, "neutral">;
  deckPresetId: string;
  priorStatus: SamplerReadinessPriorStatus;
  materializationStatus: "invalid";
  invalidReason: SamplerInvalidRootReason;
  classification: SamplerInvalidRootClassification;
  opponentHandCount: number;
  opponentDeckCount: number;
  opponentHiddenCount: number;
  priorMainDeckCardCount: number;
  priorRemainingCardCount: number;
  publicKnownCardCount: number;
  fixedKnownHandCardCount: number;
  hiddenHandDrawCount: number;

}
```

Use this as a guide, not an exact required type name. Field names may differ if
they are clearer, but they must stay public, scalar, and hidden-info-safe.

### Public Zone Count Summary

Add a public-zone breakdown for diagnostic counts. It must contain only counts,
not identities:

```ts
interface PublicKnownZoneCountSummary {
  opponentBoardUnitCount: number;
  opponentRowHornCount: number;
  opponentDiscardCount: number;
  opponentRemovedFromGameCount: number;
  opponentWeatherCount: number;
  actingHandKnownOpponentOwnedCount: number;
  promptRevealedOpponentHandCount: number;
  otherPublicKnownCount: number;
}
```

If implementation details require slightly different buckets, document them in
the report. Do not include card names, source ids, runtime ids, or per-card
lists.

### Classifications

Classify every invalid root exactly once. Use deterministic first-match order:

1. `public_known_exceeds_prior_copy_count`
   - `buildPublicKnownSourceSubtraction` reports
     `public_known_exceeds_prior_copy_count`.
2. `fixed_hand_exceeds_observed_hand`
   - `fixedKnownHandCardCount > opponentHandCount`.
3. `prompt_revealed_hand_deficit`
   - invalid reason is `insufficient_prior_remaining` and
     `promptRevealKnownHandCount > 0`.
4. `public_zone_count_deficit`
   - invalid reason is `insufficient_prior_remaining` and
     `publicKnownCardCount > fixedKnownHandCardCount`.
5. `raw_hidden_count_exceeds_prior`
   - invalid reason is `insufficient_prior_remaining` and
     `publicKnownCardCount === 0`.
6. `prior_remaining_excess`
   - invalid reason is `prior_remaining_exceeds_observed_hidden_count`.
7. `negative_or_incoherent_public_count`
   - invalid reason is one of:
     - `negative_opponent_hand_count`
     - `negative_opponent_deck_count`
     - `public_known_hand_exceeds_opponent_hand_count`
8. `other_invalid_root`
   - fallback for any future safe invalid reason.

If the implementation discovers that these categories cannot classify all
roots exactly once, stop and revise this spec/report before proceeding.

- invalid root counts differ from cFp61 without a clear reason;
- classification cannot cover every invalid root exactly once;
