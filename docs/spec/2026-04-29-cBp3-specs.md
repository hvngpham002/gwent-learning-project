# Implementation Spec: Cluster B, Phase 3 - Official Gwent Catalog Porting Pipeline

## Goal

Build the first official-card porting pipeline from the Game8 scrape into the project catalog workflow.

cBp3 must turn `audit/scrapes/2026-04-29-game8-gwent-cards.json` into a reviewed, repo-owned official catalog staging layer, plus an opt-in authoring UI for image/crop and data review. These are official Witcher 3 Gwent cards, not Card Studio custom cards.

The end state should let the project see all scraped official cards and leaders as structured candidates, preserve duplicate physical card counts, preview each candidate with the authentic card components, record image/crop approval metadata, and export a catalog-ready approval bundle for a later source commit/codegen phase.

## Product And Architecture Decisions

Use these decisions unless the user explicitly changes them later:

- Official cards are not Card Studio custom records.
- Do not import official cards into `gwent_custom_catalog_v1`.
- Do not give official cards `custom_*` or `custom_leader_*` source IDs.
- Do not download or commit Game8-hosted images into `public/images/`.
- Game8 image URLs may be stored as provenance/reference fields only.
- The preferred production image workflow is local user-provided card faces under `public/images/<faction>/<kind-folder>/...`.
- The browser UI may preview uploaded/local data URL images for review, but it must not write image files into the repository.
- The browser UI may store review state in localStorage and export JSON, but permanent catalog source updates still happen through a later code/spec phase.
- cBp3 may add an opt-in development/authorship route. It must not promote the official full catalog into the default product deck builder unless the spec below explicitly says so.
- cBp3 must preserve cEp7 runtime-catalog behavior and must not regress Card Studio custom-card behavior.

## Scope

### 1. Preserve The Scrape As Source Input

The input artifact is:

```txt
audit/scrapes/2026-04-29-game8-gwent-cards.json
```

Requirements:

- Treat the file as factual import input and provenance, not runtime catalog source.
- Verify the expected scrape shape at test time:
  - `schemaVersion` is `game8-gwent-card-port-v1`;
  - `counts.totalInstances` is `254`;
  - `counts.uniqueCards` is `181`;
  - `instances.length` is `254`;
  - `uniqueCards.length` is `181`.
- If this file is missing, malformed, or count-mismatched, fail the relevant tests with a clear message.
- Do not embed long third-party prose in committed generated files. Keep factual card fields only: names, factions, rows, strength, effects/abilities, copy counts, acquisition rows, URLs, and image URL provenance.

### 2. Official Candidate Data Model

Add an official catalog staging model separate from both current source catalog and Card Studio custom records.

Recommended files:

- `src/data/catalog/official/officialTypes.ts`
- `src/data/catalog/official/game8OfficialGwent.ts`
- `src/data/catalog/official/game8Mapping.ts`
- `src/data/catalog/official/index.ts`

Use different names only if the existing structure strongly suggests a cleaner convention.

Recommended types:

```ts
export type OfficialPortingStatus =
  | "ready_for_catalog"
  | "needs_image"
  | "needs_rule"
  | "needs_leader_rule"
  | "needs_review";

export interface OfficialCardCandidate {
  readonly source: CatalogCardSource;
  readonly copyCount: number;
  readonly game8CopyIds: readonly string[];
  readonly game8Urls: readonly string[];
  readonly game8ImageUrl?: string;
  readonly acquisitionRows: readonly OfficialAcquisitionRow[];
  readonly portingStatus: OfficialPortingStatus;
  readonly portingIssues: readonly string[];
}

export interface OfficialLeaderCandidate {
  readonly sourceId: string;
  readonly name: string;
  readonly faction: Exclude<CatalogFaction, "neutral">;
  readonly mappedAbilityId?: CatalogLeaderAbilityId;
  readonly pendingAbilityId?: string;
  readonly game8Urls: readonly string[];
  readonly game8ImageUrl?: string;
  readonly leaderEffectText?: string;
  readonly portingStatus: OfficialPortingStatus;
  readonly portingIssues: readonly string[];
}

export interface OfficialImageCandidate {
  readonly sourceId: string;
  readonly preferredImagePath: string;
  readonly game8ImageUrl?: string;
  readonly existsInPublicImages: boolean;
  readonly crop: OfficialImageCrop;
  readonly approved: boolean;
}

export interface OfficialImageCrop {
  readonly fit: "contain" | "cover";
  readonly scale: number;
  readonly offsetX: number;
  readonly offsetY: number;
  readonly cropBottomPx: number;
}
```

Requirements:

- Candidate records must use official source IDs, e.g. `northern_realms.blue-stripes-commando`, not `custom_*`.
- Preserve existing hand-authored source IDs wherever a current catalog card or leader clearly matches by faction plus normalized name.
- For ambiguous names or duplicate same-name variants, generate deterministic source IDs and record a `portingIssues` note.
- Preserve duplicate physical copies as `copyCount` and `game8CopyIds`; do not create multiple identical `CatalogCardSource` records unless the source rows/abilities/strength differ.
- Preserve acquisition rows separately from `CatalogCardSource` because current runtime catalog does not need acquisition data.
- Convert Game8 rows:
  - `faction` -> `CatalogFaction`;
  - `UnitType`/`kind` -> `unit`, `hero`, `special`, or official leader candidate;
  - `Value` -> `strength`, with non-strength cards using `0` in `CatalogCardSource`;
  - `Range` -> `rows`;
  - `Effect1`/`Effect2` -> `CatalogAbilityId[]`, excluding `Hero` as an ability and using `kind: "hero"` instead;
  - no-ability units/heroes should use `abilities: ["none"]`;
  - Weather cards remain special cards with weather ability IDs;
  - Commander's Horn row-effect cards remain special cards with `commanders_horn`.
- Flag unsupported or incomplete rules through `portingStatus`/`portingIssues`, not by dropping cards.
- At minimum, flag:
  - `mardroeme`;
  - `berserker`;
  - any catalog ability whose metadata status is not `implemented`;
  - all leader candidates whose ability is not executable by the current engine.
- If `skellige_storm` is already functionally supported in legal moves/scoring, do not silently treat it as complete. Add a specific issue noting the metadata/implementation mismatch so a later rule pass can resolve it intentionally.

### 3. Image Manifest, No Image Download

Add an image manifest for every official card and leader candidate.

Requirements:

- Every official candidate must have a deterministic `preferredImagePath`.
- Preferred paths should follow the existing image convention:
  - `/images/<faction>/heroes/<Name>.png`
  - `/images/<faction>/units/<Name>.png`
  - `/images/<faction>/specials/<Name>.png`
  - `/images/<faction>/weather/<Name>.png`
  - `/images/<faction>/leaders/<Name>.png`
- Use ASCII-safe file names.
- Check whether the preferred path already exists under `public/images/` using repo-local filesystem checks in tests or generator logic.
- Store Game8 image URLs as `game8ImageUrl` provenance only.
- Do not download images into `public/images`.
- Do not commit scraped image binaries.
- If a helper script can optionally download images for local private reference, it must write only to an ignored scratch path such as `.cache/game8-card-images/` or `tmp/game8-card-images/`, and that behavior must be disabled by default. This optional helper is not required for acceptance.

### 4. Official Porting Store And Export Bundle

Add a browser-local official porting review store, separate from Card Studio custom storage.

Recommended storage key:

```txt
gwent_official_porting_v1
```

Recommended schema:

```ts
interface OfficialPortingStoreV1 {
  readonly schemaVersion: "official-porting-v1";
  readonly updatedAt: string;
  readonly imageOverridesBySourceId: Record<string, OfficialImageCandidate>;
  readonly dataOverridesBySourceId: Record<string, Partial<CatalogCardSource> | Partial<OfficialLeaderCandidate>>;
  readonly approvedSourceIds: readonly string[];
  readonly notesBySourceId: Record<string, string>;
}
```

Requirements:

- Normalize on read so corrupted localStorage cannot crash the app.
- Support import/export/copy of the review bundle.
- Exported review bundle must include:
  - schema version;
  - scrape metadata/count summary;
  - image crop/approval overrides;
  - data overrides;
  - unresolved issue summary.
- The review bundle must not include runtime engine instance IDs.
- The review bundle must not include AI hidden information or match state.
- The review bundle may include data URL preview images only if they are explicitly marked as browser-local previews; prefer paths.

### 5. Official Porting Studio UI

Add an opt-in authoring route:

```txt
/?engine=1&ui=authentic&view=official-porting
```

Requirements:

- Extend `AuthenticUiView` in `src/appMode.ts`.
- Add an entry point from Card Studio and/or pre-game only if it does not clutter the product flow. A small `official porting →` button in Card Studio is acceptable. Direct URL access is sufficient for acceptance.
- Keep `/`, `/?engine=1`, authentic pre-game, direct match, deck builder, Card Studio, harness, and component foundation behavior unchanged.
- The route must be an authoring/review tool, not the default product experience.

Recommended UI layout:

- top bar:
  - `← back`;
  - title `Official Porting`;
  - compact counts: total candidates, approved, missing images, rule gaps;
  - import/export/copy review bundle actions.
- left column:
  - search;
  - filters for faction, kind, status, missing image, rule gap, approved;
  - candidate list with source ID, name, faction, kind, and status.
- center panel:
  - editable factual fields for staging overrides:
    - name;
    - source ID only if not already matched to an existing current catalog ID;
    - faction;
    - kind;
    - strength;
    - rows;
    - abilities;
    - tags;
    - deck limit;
    - image path;
    - note.
  - fields should use the existing authentic controls and button style.
  - source ID edits for official cards should be strongly discouraged and visibly flagged.
- right panel:
  - live authentic `AuthenticCard` or `AuthenticLeaderCard` preview;
  - image/crop controls:
    - image path input;
    - optional local upload preview;
    - fit mode;
    - scale;
    - offset X;
    - offset Y;
    - bottom crop px;
    - reset crop;
    - approve image/data;
  - status/issues ledger.

Cropper requirements:

- This is a preview/edit metadata cropper, not an image editor that writes cropped image files.
- Use CSS transforms/object positioning around the existing authentic card/leader preview.
- All crop controls must have bounded numeric ranges to prevent broken layouts.
- The preview must stay within the authentic card frame and not resize the surrounding layout.
- The exported review bundle must contain crop values per `sourceId`.

### 6. Official Candidate Playability Classification

Add deterministic classification helpers.

Requirements:

- A candidate card can be `engineReady` only if:
  - it maps to a valid `CatalogCardSource`;
  - all ability IDs are known;
  - all non-`none` abilities have catalog metadata status `implemented`;
  - the existing engine can legally play the card class.
- A candidate leader can be `engineReady` only if:
  - it maps to a valid `CatalogLeaderSource`;
  - the ability ID is known;
  - the leader ability metadata is `implemented`;
  - the current legal move/command path can execute it. In current engine behavior, expect only `clear_weather`.
- Do not hide non-ready cards. They must remain visible with explicit reason codes.
- Do not silently downgrade official rules to `none` just to make cards playable.

### 7. Integration With Existing Catalog

Do not replace `currentCatalogCards`, `currentCatalogLeaders`, or current deck presets in this phase.

Requirements:

- Existing product decks remain playable exactly as before.
- Existing current catalog source IDs must remain stable.
- Existing Card Studio custom content remains independent and continues to use `custom_*`.
- Add exports that future phases can consume, for example:

```ts
export const game8OfficialCardCandidates = [...];
export const game8OfficialLeaderCandidates = [...];
export const game8OfficialImageCandidates = [...];
export const officialPortingSummary = {...};
```

- Do not add official staged cards to the default deck builder source set yet, unless they are explicitly current catalog entries already present today.
- A future phase may promote approved official cards into `src/data/catalog/cards/*` and deck-builder source sets after image/rule review.

- Adding a backend or filesystem write API from the browser.
- Promoting the full official catalog into the default deck builder.
- Replacing `currentCatalogCards` or current deck presets.
- Implementing new game rules.
- Implementing leader abilities beyond current behavior.
- Implementing Mardroeme/Berserker/Skellige rule fixes.
- Generating final committed catalog TypeScript files from the review bundle.
- Training/ML dataset changes.
- Route promotion of authentic UI.
- Any use of legacy rule helpers, legacy Redux game paths, or legacy AI.
