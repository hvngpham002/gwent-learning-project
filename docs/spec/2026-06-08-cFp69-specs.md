# Cluster F Phase 69 Specs - Determinized PIMC Probe v0 Sanity

Date: 2026-06-08
Branch: `codex/cFp69-determinized-pimc-probe-v0-sanity`
Base: `dev`

## Summary

cFp68 created the valid-root-only determinized probe contract. It split every cFp61 sampler root into either:

- `eligible_valid_root`; or
- `skipped_invalid_root`.

Current contract counts:

- 4,042 total roots.
- 3,979 eligible roots.
- 63 skipped roots.
- 1.559% skipped.
- 31,832 requested / valid samples across eligible roots.

Robust contract counts:

- 32,487 total roots.
- 32,147 eligible roots.
- 340 skipped roots.
- 1.047% skipped.
- 257,176 requested / valid samples across eligible roots.

cFp69 should implement the first benchmark-only `determinized-pimc-probe-v0` sanity probe over cFp68 eligible roots only. This is not a strength benchmark yet. It should prove that the project can:

1. consume cFp68 eligible and skipped contract artifacts;
2. re-observe the matching benchmark roots through the existing headless benchmark root observer;
3. filter probe work to eligible roots only;
4. attach cFp68 skipped-root counts and percentages to every probe summary/report;
5. run only shallow/no-op or one-ply public-action scaffolding; and
6. serialize hidden-info-safe deterministic probe artifacts.

cFp69 must not produce gameplay strength claims.

## Problem Statement

The project now has sampler materialization, invalid-root accounting, and a valid-root-only contract. The next risk is accidentally treating that contract as enough to claim "search strength" before the probe path itself is proven.

cFp69 should build a deliberately modest first probe:

- no rollout;
- no tree expansion past the current root;
- no hidden card identity serialization;
- no product AI policy;
- no action-value claim;
- no move selection claim.

The probe should answer: can we run a deterministic probe-shaped pipeline over valid sampler roots, with public action abstractions and skipped-root accounting attached, without hidden-info leakage?

## Definition: `determinized-pimc-probe-v0`

For cFp69, `determinized-pimc-probe-v0` means:

- valid-root-only benchmark probe over cFp68 eligible roots;
- sampler-backed budget accounting using cFp68 eligible-root `sampleCountRequested` / `sampleCountValid`;
- root-level public action abstraction using existing cFp60 `PublicSearchActionAbstraction` helpers where possible;
- no hidden-world action evaluation;
- no child-state rollout;
- no root move recommendation;
- no policy replacement;
- no product route/UI integration.

This is a probe scaffold, not a search player.

## Source Consistency Rules

The probe builder must fail or mark the probe `not_probe_ready` if:

- any cFp68 eligible root is not observed in the benchmark root stream;
- any cFp68 skipped root appears in `probe-roots.jsonl`;
- any observed probe root is absent from cFp68 eligible roots;
- eligible + skipped root counts do not sum to cFp68 total roots;
- duplicate observed root keys are detected;
- duplicate cFp68 eligible root keys are detected;
- duplicate cFp68 skipped root keys are detected;
- cFp68 contract status is not `probe_ready`;
- sample counts do not match cFp68 eligible-root sample counts;
- hidden-info scanner detects forbidden payloads.

Committed current/robust artifacts should be `probe_ready`.
