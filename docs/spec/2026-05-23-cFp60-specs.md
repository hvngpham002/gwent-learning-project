## Summary

cFp58 established the search guardrails: future search work must start from
the acting seat's observation and legal moves, not raw full state, and must
separate safe, sampler-required, and unsafe oracle/debug variants. cFp59 then
measured root branching over current and robust starter benchmark suites. The
branching profile is tractable enough to investigate a future
`determinized-pimc-probe-v0`, but not enough to run search yet.

cFp60 implements the missing sampler contract layer only:

- a `known_preset_decklist_prior` for official starter benchmark suites;
- a sampled-world validation/reporting contract that checks public count and
  visible-zone consistency without serializing sampled hidden identities;
- a public action abstraction for grouping legal moves without runtime ids,
  raw labels, card names, or source ids;
- deterministic benchmark-only sampler-readiness artifacts over selected
  suites.

cFp60 must not run rollouts, evaluate actions, build a tree, choose a move,
wire product search, or change any AI behavior. It is infrastructure for a
later cFp61/cFp62 determinized probe.

## Research Grounding

Use cFp58 and cFp59 as controlling decisions.

cFp58 says safe search starts from `SeatObservation`, acting-seat legal moves,
and named priors. It explicitly names `known_preset_decklist_prior` for
benchmark starter suites and warns that PIMC/ISMCTS must not silently consume
true hidden state.

cFp59 shows current and robust starter roots are not dominated by impossible
branching: robust p50 legal moves 9, p90 13, p95 15, max 32; target expansion
p50 0, p90 4, p95 6, max 26. That supports a sampler contract next, not a
search-playing policy.

Batch A / Long guardrail for cFp60:

- sampling must be labeled as a prior/sampled-world contract, not strength;
- sampled worlds must be validated against public observations;
- unsafe oracle/debug state must use a different future variant and artifact
  path;
- no action-value or rollout claim should appear before determinization-risk
  metrics exist.

Batch B guardrail for cFp60:

- raw fixed-suite public ledgers remain source of truth;
- sampler-readiness artifacts are evaluation infrastructure only;
- no product difficulty, benchmark rating, or policy-quality claim follows
  from a sampler validator alone.

## Prior Contract

Implement a versioned prior label:

```ts
type SamplerReadinessPriorId = "known_preset_decklist_prior";
```

This prior is valid only for benchmark contexts where both seats use catalog
deck presets with known official starter lists. It may use public benchmark
metadata:

- seat id;
- policy id;
- faction;
- deck preset id;
- known preset deck composition at catalog source level;
- public counts from the current root;
- visible cards allowed by the acting seat's observation contract.

It must not use:

- true opponent hand instance identities;
- true opponent deck order;
- hidden runtime card ids;
- hidden source ids in committed artifacts;
- raw `MatchState` in committed artifacts;
- product custom-deck assumptions.

If the prior cannot be constructed for a root, emit a safe aggregate status
such as `prior_unavailable` and do not fabricate sampled-world statistics.

## Sampled-World Contract

cFp60 is allowed to create sampled worlds in memory for validation only. A
sampled world is not used to select moves and is not serialized directly.

For each profiled root, generate a small deterministic sample count, e.g.:

```ts
const DEFAULT_SAMPLE_COUNT = 8;
```

The exact count can differ if justified in the report, but it must be small
enough for local repeat runs and robust suite artifacts.

Each sample must satisfy these public constraints:

- acting seat's visible hand remains fixed;
- public board, weather, discard piles, leaders, factions, scores, gems,
  round, phase, passed state, and prompt visibility remain consistent;
- opponent hand count matches the observed count;
- opponent deck count matches the observed count;
- sampled hidden cards are drawn from the known preset prior minus visible
  public/acting-seat-known cards;
- duplicate cards respect the preset deck's copy counts;
- no sampled card exists outside the prior's available multiset;
- revealed prompt-local cards, if present in the acting observation, stay
  consistent with the reveal contract;
- no sampled world mutates the real match state.

Validation should produce only scalar/status output, such as:

- `sampleCountRequested`
- `sampleCountGenerated`
- `sampleCountValid`
- `sampleCountInvalid`
- `rootValidationStatus`
- `invalidReasonCounts`
- `opponentHiddenPoolSizeBucket`
- `opponentHandCount`
- `opponentDeckCount`
- `knownVisibleCardCountBucket`
- `priorRemainingCardCountBucket`

Do not emit sampled card names, source ids, instance ids, or deck order.

If implementing real sampled `MatchState` clones is too risky in cFp60, stop at
a prior/validator abstraction that samples hidden source-multisets and reports
why full world materialization is deferred. Document that deviation and do not
claim `determinized-pimc-probe-v0` readiness.

## Public Action Abstraction

Add a public abstraction for legal root actions:

```ts
type PublicSearchActionKind =
  | "choose_mulligan"
  | "play_card"
  | "use_leader"
  | "choose_prompt_option"
  | "pass"
  | "resolve_round_end";
```

Each abstract action row must be hidden-info safe. It may include:

- action kind;
- public target kind;
- target side (`own`, `opponent`, `public`, `none`);
- target row when row is public;
- phase;
- round;
- coarse source class, e.g. `unit`, `hero`, `special`, `weather`, `leader`,
  `prompt`, `none`;
- coarse strength bucket for acting-seat visible own-hand cards only, if the
  current observation already exposes it to the acting policy;
- prompt option index only as `option_index_<n>`, never raw option ids;
- count of legal moves collapsed into the same abstraction.

It must not include:

- raw `moveId`;
- raw `optionId`;
- raw `sourceCardId`;
- raw `sourceId`;
- raw `cardId`;
- raw labels;
- card names;
- runtime seat prefixes such as `seat_a:` / `seat_b:`;
- opponent hidden card identity.

The artifact layer should report public action-abstraction counts only:

- `publicActionCount`
- `publicActionCollisionCount`
- `largestPublicActionBucketSize`
- `publicActionKindCounts`
- `targetKindCounts`
- `targetSideCounts`
