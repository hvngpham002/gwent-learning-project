# Cluster F Phase 80 Specs - Search Consumer Action Feature Dictionary v0

Date: 2026-06-26
Branch: `codex/cFp80-search-consumer-action-feature-dictionary-v0`
Base: `dev`

## Summary

cFp79 completed the first populated search-consumer action-feature join:

- artifact family: `search-consumer-action-features-v1/cFp79`;
- current rows: 3,979 root-feature rows, 18,820 action-feature rows, 63 skipped rows;
- robust rows: 32,147 root-feature rows, 153,842 action-feature rows, 340 skipped rows;
- current `action-features.jsonl`: 10,518,156 bytes;
- robust `action-features.jsonl`: 86,029,163 bytes;
- source consistency: `ready` for current and robust;
- consumer readiness: `features_ready` for current and robust.

cFp79 was correct but too large for the robust 50 MB soft target. The cFp79
report identified repeated per-row schema/readiness/join fields as the largest
size contributors:

- `schemaVersion`;
- `actionIdentityRef`;
- `consumerReadinessStatus`;
- `publicActionRef`;
- `sourceConsistencyStatus`.

cFp80 should implement a benchmark-only compact dictionary projection over
committed cFp79 artifacts:

```text
search-consumer-action-features-dictionary-v0/cFp80
```

The goal is not to create a new search policy. The goal is to preserve the
same public action-feature information in a more compact, source-consistent,
hidden-info-safe representation so future consumer casebooks can run without
large JSONL pressure.

## Decision

Create a new dictionary/compact artifact family instead of modifying cFp79:

- cFp79 remains the immutable full normalized feature-join artifact.
- cFp80 consumes cFp79 as source data.
- cFp80 emits a compact action-feature projection plus dictionaries.
- cFp80 must allow lossless reconstruction of the cFp79 action-feature rows
  for the public/scalar fields it claims to preserve.
- cFp80 must retain the cFp79 root-feature rows and skipped-root rows either
  by forwarding them unchanged with cFp80 schema metadata or by emitting
  deterministic compact equivalents with explicit source-consistency checks.

Prefer a simple, reviewable dictionary encoding over clever compression:

- keep one compact action row per cFp79 action row;
- replace repeated strings with deterministic integer dictionary ids;
- omit constant fields from every row and declare them once in `manifest.json`
  or `summary.json`;
- preserve row ordering deterministically;
- preserve `rootRef` and `publicActionRef` identity through compact refs or
  dictionary ids;
- write a machine-readable dictionary file that maps ids back to strings.

Do not use gzip, binary blobs, opaque compressed payloads, base64 packing, or
external archive formats. The artifact must remain plain JSON/JSONL and
reviewable in git.

## Scope

Build `search-consumer-action-features-dictionary-v0/cFp80` as a benchmark-only
artifact family that:

1. reads committed cFp79 artifacts;
2. validates cFp79 source consistency/readiness;
3. validates actual cFp79 JSONL row counts against cFp79 `summary.json`;
4. emits deterministic dictionary metadata for repeated action-feature strings;
5. emits one compact action-feature row per cFp79 action-feature row;
6. preserves enough data to reconstruct every cFp79 action-feature row's
   public/scalar fields;
7. forwards or compactly preserves cFp79 root-feature rows;
8. forwards or compactly preserves cFp79 skipped-root rows;
9. records SHA-256 references for all consumed cFp79 source artifacts;
10. writes deterministic hidden-info-safe artifacts for current and robust
    starter suites;
11. proves robust action-feature compact output is below the 50 MB soft target;
12. updates AI Lab metadata to cFp80 as search-consumer feature compaction
    infrastructure, not search gameplay;
13. updates benchmark docs, policy docs, roadmap, and `docs/PROJECT_STATE.md`;
14. creates the required cFp80 decision note and audit report; and
15. commits and pushes the implementation branch after checks pass.

## Dictionary Contract

`dictionaries.json` must be deterministic and self-describing.

Required dictionary groups:

- `schemaVersions`;
- `readinessStatuses`;
- `rootRefs`;
- `publicActionRefs`;
- `actionKinds`;
- `sourceClasses`;
- `targets`;
- `strengthBuckets`;
- `optionIndexLabels`;
- `moveCountBuckets`;

Represent absent optional values explicitly, for example with dictionary value
`"none"` or with a nullable compact field. Be consistent across current and
robust outputs.

Dictionary ids must be deterministic:

1. collect values from source rows;
2. sort values lexicographically unless a clear numeric/ref order is required;
3. assign zero-based integer ids;
4. record the dictionary's `count`, `values`, and `sha256` in
   `dictionaries.json` or `summary.json`.

## Compact Action Feature Row Schema

The compact action row must be one row per cFp79 action row.

Required fields:

```ts
type SearchConsumerActionFeatureDictionaryV0ActionRow = {
  schemaVersion: "search-consumer-action-features-dictionary-v0-action-v1";
  featureRunId: string;

  // Compact refs.
  rootRefId: number;
  publicActionRefId: number;

  // Action identity/features.
  kindId: number;
  ordinal: number;
  moveCount: number;
  sourceClassId: number;
  targetId: number;
  strengthBucketId: number;
  optionIndexLabelId: number;
  moveCountBucketId: number;
  collisionCountWithinBucket: number;
  hasCollision: boolean;
  hasTarget: boolean;
  hasStrengthBucket: boolean;
  hasOptionIndexLabel: boolean;
};
```

Do not include row-constant fields in every row:

- `sourceConsistencyStatus`;
- `consumerReadinessStatus`;
- full `actionIdentityRef`;
- `rootFeatureRef`;
- repeated schema/readiness strings.

Declare row constants once in `manifest.json` or `summary.json`.

## Root And Skipped Rows

Root rows and skipped rows may remain similar to cFp79 if changing them is not
necessary for the size target. However:

- they must use cFp80 schema/run metadata;
- their row counts must match cFp79 exactly;
- they must pass hidden-info scans;
- their artifact sizes must be included in summaries/reports;
- any compaction of root/skipped rows must be lossless for the public/scalar
  fields it claims to preserve.

Do not let root row compaction distract from the main cFp80 target unless the
implementation remains simple and fully tested.

## Reconstruction Contract

cFp80 must prove that compact action rows reconstruct the cFp79 public/scalar
action-feature rows.

At minimum, implement pure helpers and tests that:

1. build dictionaries from cFp79 action rows;
2. compact cFp79 action rows into cFp80 compact rows;
3. reconstruct cFp79-equivalent action rows from dictionaries plus compact
   rows;
4. compare the reconstructed rows to the original cFp79 rows for every
   preserved field.

The reconstruction check must not reintroduce hidden information, raw moves,
sampled worlds, values, rankings, or product AI behavior.

`summary.json` must include:

- `reconstructionStatus`;
- `reconstructedActionRowCount`;
- `sourceActionRowCount`;
- `reconstructionMismatchCount`;
- if mismatches exist, a bounded scalar-only mismatch summary.

Expected ready path:

```text
reconstructionStatus: "passed"
reconstructionMismatchCount: 0
```

## Source Consistency Requirements

cFp80 must fail with `consumerReadinessStatus: "source_consistency_failed"` if
any of these are false:

- cFp79 `consumerReadinessStatus` is `features_ready`;
- cFp79 `sourceConsistency.status` is `ready`;
- cFp79 `rootFeatureRowCount` equals loaded `root-features.jsonl` row count;
- cFp79 `actionFeatureRowCount` equals loaded `action-features.jsonl` row count;
- cFp79 `skippedRootRowCount` equals loaded `skipped-roots.jsonl` row count;
- every compact action row references a valid `rootRefId`;
- every compact action row references a valid `publicActionRefId`;
- compact action row count equals cFp79 action row count;
- compact root row count equals cFp79 root row count;
- compact skipped row count equals cFp79 skipped row count;
- duplicate compact action identity refs are 0 after reconstruction;
- reconstruction mismatch count is 0;
- source artifact reference count is nonzero;
- source artifact empty hash count is 0.

If source consistency fails, write no partial ready artifacts. Either stop the
CLI with a clear error or write an explicitly failed artifact bundle only if the
spec's hidden-info and size requirements are still met.
