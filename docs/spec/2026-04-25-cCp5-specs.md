# Implementation Spec: Cluster C, Phase 5 - Core Command Transactions

## Goal

Implement deterministic command execution for the normalized engine state. Phase 4 made the engine the source of legal moves; Phase 5 should make those moves executable as pure transactions.

This phase intentionally replaces the older high-level "Phase 5 scoring pipeline" placeholder. Scoring should come after executable command transitions, because score calculation needs authoritative board, weather, horn, pass, leader, and mulligan state to operate on.

## Architecture Position

Current Cluster C state has:

- normalized `cardsById`;
- zone arrays that store `instanceId[]`;
- explicit board rows, horn slots, weather area, hand, deck, discard, side deck, leader, and removed zones;
- pure legal move generation in `src/game/core/legalMoves.ts`;
- command types in `src/game/core/types.ts`, with only `StartMatch` currently implemented.

Phase 5 should add the state-transition layer between legal moves and later scoring/ability resolution. The engine must remain pure and deterministic.

## Scope

1. Add a command transaction module.
   - Suggested file: `src/game/core/commands.ts`.
   - Export it from `src/game/core/index.ts`.
   - Keep `startMatch` available.
   - Move or wrap the existing `executeCommand` so non-`StartMatch` commands can execute against an existing state.
   - Keep the engine free of React, Redux, DOM, localStorage, timers, and `Math.random()`.

2. Define a stateful command execution API.
   - The current `executeCommand(command: EngineCommand)` shape is only sufficient for `StartMatch`.
   - Add an API that supplies state and catalog data for stateful commands. Suggested shape:
     ```ts
     executeCommand({
       state,
       command,
       catalogCards,
       catalogLeaders,
     }): EngineTransaction
     ```
   - Preserve or update the `StartMatch` path cleanly. It is acceptable to keep `startMatch(config)` as the setup entry point and make `executeCommand` the stateful transition entry point.
   - Do not require callers to pass full catalog records inside `MatchState`.

3. Make transactions immutable.
   - Command execution must not mutate the input `MatchState`.
   - Return a new `state` object plus ordered `events`.
   - Add tests proving that the pre-command state remains unchanged for representative commands.
   - It is acceptable to use a small internal cloning helper for now. Do not introduce Immer unless the repo already has it or the implementation explains why it is needed.

4. Validate commands through legal moves.
   - Stateful commands must be rejected unless they correspond to a currently legal move from `getLegalMoves`.
   - Prefer comparing against legal move identity or equivalent canonical command shape.
   - Reject wrong turn, passed seat, wrong phase, invalid card ID, invalid target, occupied horn target, illegal Decoy target, leader reuse, and opponent hand references.
   - Do not trust UI/AI callers.

5. Add command/error results.
   - Either throw a typed `EngineRuleError` or return a structured failure result. Prefer a typed error if that fits the current engine style.
   - Include enough diagnostic data for tests and future UI adapters.
   - Suggested error codes:
     - `illegal_command`
     - `unsupported_command`
     - `invalid_phase`
     - `invalid_target`
     - `missing_card`
     - `missing_catalog_source`
   - Illegal commands must not partially mutate state.

6. Expand event types.
   - Add event coverage for stateful commands.
   - Suggested events:
     - `mulligan_chosen`
     - `phase_changed`
     - `card_moved`
     - `card_played`
     - `leader_used`
     - `player_passed`
     - `turn_set`
     - `weather_cleared`
     - `ability_deferred`
   - Extend `card_moved.reason` beyond setup-only reasons. Suggested reasons:
     - `mulligan_return`
     - `mulligan_draw`
     - `play_card`
     - `decoy_return`
     - `weather_cleared`
     - `discard_after_effect`
   - Keep events serializable.

7. Track mulligan completion.
   - Add a core-only state field such as `SeatState.mulliganComplete: boolean`, initialized to `false`.
   - Update `getLegalMoves` so a seat that has already completed mulligan receives no further mulligan moves.
   - `ChooseMulligan` should mark the acting seat complete.
   - When both seats complete, transition `phase` from `mulligan` to `playing`.
   - Preserve the `currentTurn` chosen during setup as the first playing turn.

8. Execute `ChooseMulligan`.
   - Validate that the command is in `mulligan` phase and selects 0, 1, or 2 unique cards from the acting seat's hand.
   - Use the rulebook baseline: each player may discard up to 2 cards and draw the same number; discarded cards are reshuffled back into the deck after the mulligan.
   - For this batch command, use this deterministic interpretation:
     - remove selected cards from hand into a temporary aside;
     - draw the same number of replacement cards from the top of the current deck;
     - move replacements to hand;
     - return selected cards to the deck;
     - shuffle the resulting deck with the engine RNG;
     - update `rng.state`.
   - This prevents immediately drawing the same card back within one batch command and remains compatible with a future one-at-a-time prompt model.
   - Update every moved card's `zone`.
   - Emit ordered move and mulligan events.

9. Execute basic `PlayCard` placement.
   - Validate against legal moves from Phase 4.
   - Remove the played card from the acting seat's hand.
   - For normal Unit and Hero placement:
     - place the card in the target board row;
     - normal cards target the acting seat's side;
     - Spy cards target the opponent side but keep `controller` as the acting seat.
   - For Special Commander's Horn:
     - place the card in the acting seat's target `row.horn` slot;
     - reject occupied horn slots via legal move validation.
   - For weather cards:
     - Frost, Fog, Rain, and Skellige Storm move to `state.weather.entries`;
     - the card's `controller` remains the acting seat.
   - For Clear Weather:
     - move every active weather card to its current controller's discard pile;
     - clear `state.weather.entries`;
     - move the Clear Weather card itself to the acting seat's discard pile;
     - this is legal even if no weather is active.
   - For Decoy:
     - replace the target unit in the exact board row position with the Decoy card;
     - Decoy occupies the board row as the 0-strength placeholder for later scoring;
     - move the replaced unit to the acting seat's hand;
     - set the replaced unit's `controller` to the acting seat, while preserving its `owner`;
     - do not target Heroes, opponent-side rows, row horn cards, weather cards, or non-unit placeholders.
   - For Special Scorch and other effect-heavy specials:
     - do not silently no-op the effect;
     - either reject execution with `unsupported_command`, or play to discard only if the transaction emits a clear `ability_deferred` event and the report explains why.
     - The preferred conservative behavior is to reject unsupported effect execution until the ability resolver phase.

10. Defer unresolved on-play abilities explicitly.
   - Phase 5 may place cards with abilities such as Spy, Medic, Muster, Tight Bond, Morale, and Unit Horn, but it must not pretend those effects are resolved.
   - If a command places a card whose ability is not implemented in this phase, emit `ability_deferred` with `abilityId`, `sourceId`, and `cardId`.
   - Do not draw Spy cards, revive Medic targets, pull Muster cards, or calculate Tight Bond/Morale/Horn score effects here.
   - Phase 6 will own ability resolution.

11. Execute `Pass`.
   - Validate `phase === "playing"`, current turn, and not already passed.
   - Set the acting seat's `passed = true`.
   - If the opponent has not passed, set `currentTurn` to the opponent.
   - If the opponent has already passed, set `phase = "round_end"`.
   - Do not resolve scoring, gem decrement, cleanup, next round, or game end in this phase.
   - Emit `player_passed`, optional `turn_set`, and optional `phase_changed`.

12. Execute minimal `UseLeader`.
   - Validate against Phase 4 legal leader moves.
   - For a leader ability that is known and executable in this phase, execute it.
   - Implement leader Clear Weather if present in current catalog:
     - clear active weather cards to their controllers' discard piles;
     - do not discard the leader card;
     - set `leaderUsed = true`;
     - consume the turn.
   - For leader abilities that need future target/effect resolution:
     - reject with `unsupported_command`;
     - do not mark `leaderUsed`;
     - do not advance the turn.
   - Using an executed leader ability replaces playing a card for that turn. Turn handoff is the same as after a normal card play.

13. Centralize zone movement helpers.
   - Add internal helpers so a card cannot exist in two zones after a command.
   - Helpers should:
     - remove the card from its previous zone array or slot;
     - add it to the destination zone array or slot;
     - update `cardsById[cardId].zone`;
     - emit `card_moved`.
   - Add invariant tests for representative commands.

14. Preserve hidden-information discipline.
   - Command results may include moved card IDs that are visible or belong to the acting seat.
   - Avoid emitting opponent deck order through diagnostics or events unless the command naturally reveals a card.
   - Mulligan events for one seat should not reveal the other seat's hand or deck.

15. Add tests.
   - Add focused tests under `tests/game`.
   - Suggested file: `tests/game/coreCommands.test.ts`.
   - See acceptance criteria for required surfaces.

16. Create the required implementation report:
   - `audit/reports/2026-04-25-cCp5-report.md`

## Out Of Scope

- Do not implement scoring.
- Do not implement round winner, gem decrement, board cleanup, next round, or game end.
- Do not implement full ability resolution.
- Do not implement Medic prompts, Muster pulls, Spy draws, Scorch destruction, Tight Bond scoring, Morale scoring, Unit Horn scoring, faction passives, or leader target prompts.
- Do not migrate Redux, React UI, AI strategy, or live gameplay paths to the new engine.
- Do not change legacy Redux behavior.
- Do not add Card Studio or deck builder UI.

## Acceptance Criteria

- Core exports a pure command transaction path for stateful commands.
- `StartMatch` remains available and existing setup tests still pass.
- `ChooseMulligan` executes deterministically, updates zones, advances to `playing` only after both seats complete, and updates RNG state.
- `PlayCard` executes implemented placement surfaces for units/heroes, Spy placement, weather, Clear Weather, Special Horn, and Decoy.
- Unsupported effect-heavy commands are rejected or explicitly marked with `ability_deferred`; they are never silently treated as resolved.
- `Pass` marks passed state, hands off turn correctly, and moves to `round_end` when both players have passed.
- Minimal leader Clear Weather execution works if the current catalog contains that leader ability; unsupported leaders are rejected without consuming use.
- Commands are validated against legal moves and cannot bypass Phase 4 legality.
- Command execution does not mutate the input state.
- Card zone invariants hold after tested commands.
- Events are serializable and ordered.
- `npm test` passes.
- `npm run build` passes.
- Existing live gameplay behavior is not intentionally changed.

## Required Tests

At minimum, cover:

- `ChooseMulligan` with 0 cards marks only that seat complete.
- `ChooseMulligan` with 1 or 2 cards draws replacements, returns selected cards to deck after draw, shuffles deterministically, updates zones, and leaves no duplicate zones.
- After both seats mulligan, `phase` becomes `playing` and setup-selected `currentTurn` is preserved.
- Illegal mulligan card IDs are rejected and do not mutate input state.
- Normal Unit play removes from hand, adds to own board row, updates zone, emits events, and hands off turn.
- Spy play places on opponent board row while preserving acting-seat controller, and emits `ability_deferred` for Spy draw.
- Special Horn occupies the row horn slot and occupied horn commands are rejected.
- Decoy replaces the target unit in-place, moves the target to acting hand, updates controller to acting seat, and leaves no duplicate zones.
- Weather card moves to shared weather entries.
- Clear Weather moves active weather cards to each controller's discard and discards itself, including no-weather no-op boards.
- `Pass` hands off to the opponent when only one seat has passed.
- Second `Pass` transitions to `round_end` without resolving the round.
- Leader Clear Weather clears weather, sets `leaderUsed`, leaves the leader in its leader zone, and consumes the turn.
- Unsupported leader ability rejects without marking `leaderUsed` or advancing turn.
- Wrong-turn, passed-seat, wrong-phase, invalid-target, and opponent-hand commands are rejected.
- Representative commands prove the original input `MatchState` was not mutated.

## Things To Watch Out For

- Do not duplicate legality rules in a second command-only model. The command executor should ask Phase 4 legal moves what is allowed.
- Do not route cards to discard by board side. Use `controller` for active weather cleanup and future Spy cleanup.
- Decoy is the first high-risk command in the new engine. Keep `owner`, `controller`, hand ownership, and board position explicit.
- Clear Weather from a card discards the Clear Weather card. Clear Weather from a leader does not discard the leader.
- A leader action consumes the turn only when it actually executes.
- Avoid accidental mutation from shallow clones. Tests should catch this.
- Keep event payloads compact. They should be useful for replay/debugging, not a dump of whole state.
- Do not wire this engine path into live UI yet. This phase is foundation.
