# Cluster F Phase 40 - Long-Run Benchmark Progress Runner

## Purpose

Add a reusable, user-invoked benchmark runner for longer automated AI
evaluation runs. The runner must be pasteable into a terminal, show clear
progress, write durable local logs and summaries, and avoid tying long
benchmark execution to an agent runtime.

This phase is tooling only. It must not change AI policy behavior, engine
rules, legal moves, UI behavior, benchmark suite semantics, catalog data,
or deck presets.

## Background

Manual playtests are now most useful as spot checks. For systematic v1
tuning, the project needs repeatable benchmark runs that the user can
launch directly, leave running in a terminal or SSH session, and then
point Codex to the result.

The user requested `rsalmei/alive-progress` as the progress UI reference.
The library is Python-based and provides a live progress bar with ETA,
throughput, final receipts, and print/logging integration. The repository's
benchmark commands are Node/TypeScript npm scripts, so this phase should
wrap those existing commands from Python rather than rewrite the benchmark
core.

## Requirements

1. Add a reusable long-run benchmark entrypoint.
2. The entrypoint must run existing benchmark npm scripts, not duplicate or
   reinterpret benchmark logic.
3. The entrypoint must use `alive-progress` when installed and fall back to
   readable plain progress when it is not installed.
4. The entrypoint must write local run artifacts under an ignored path.
5. Each run must produce at least:
   - full per-step logs;
   - `run.json`;
   - `summary.md`;
   - command names;
   - exit status;
   - duration;
   - pointers to benchmark artifact directories.
6. Add an npm launcher so the preferred command can be pasted as:

   ```bash
   npm run benchmark:long -- --profile v1-current
   ```

7. The launcher must work across macOS/Linux/Windows by finding a Python 3
   executable instead of assuming one platform-specific Python command.
8. Provide at least these profiles:
   - `smoke`;
   - `v1-current`;
   - `v1-current-repeat`;
   - `all-current`.
9. Add `--dry-run` for fast validation and future agent testing.
10. Document the policy that agents should ask the user to run long
    benchmark commands directly instead of running them inside an agent
    turn.

## Out Of Scope

- No new benchmark suite definitions.
- No expanded matrix volume yet.
- No Python package lockfile or mandatory Python dependency.
- No H100/Slurm job submission.
- No browser execution.
- No ratings, search, self-play, training, neural model code, or artifact
  upload.
- No AI Lab runtime integration.
- No committed `.local/` outputs.

## Acceptance Criteria

- `npm run benchmark:long -- --dry-run` succeeds.
- `npm run benchmark:long -- --profile smoke --dry-run` succeeds.
- Dry-run output writes a local summary and JSON run file under
  `.local/benchmark-runs/`.
- Missing `alive-progress` does not fail the runner.
- Documentation includes the recommended pasteable command and the
  "user-run long jobs" policy.
- `docs/PROJECT_STATE.md` records the phase.
- A phase report is created.
- Standard static checks pass.
