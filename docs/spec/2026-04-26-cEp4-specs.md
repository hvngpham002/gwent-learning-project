# Implementation Spec: Cluster E, Phase 4 - Pre-Game And Match Configuration

## Goal

Make match start a product flow instead of a query-param/debug setup.

This phase implements the handoff's pre-game setup screen over the current engine/catalog architecture. Users should be able to open the authentic product UI, choose a current catalog deck preset for the human seat, choose an implemented AI opponent preset, set or generate a deterministic seed, and begin a playable engine match without editing the URL.

This phase also includes one visual repair that cEp4 depends on: leader card display must be fixed so leader images are not cropped and too small in score cards and pre-game deck choices.

## Architecture Position

Before this phase:

- `/` renders the legacy Redux UI.
- `/?engine=1` renders the diagnostic engine shell.
- `/?engine=1&ui=authentic` renders the engine-backed authentic match table directly.
- `/?engine=1&ui=authentic&view=harness` renders the cEp1 card foundation harness.
- `AuthenticMatchScreen` starts a fixed Northern Realms human vs Nilfgaard AI match from URL seed/default seed.
- `startEngineMatch` is still biased toward the fixed current Northern Realms vs current Nilfgaard setup.

After this phase:

- `/` must still render the legacy UI.
- `/?engine=1` must still render the diagnostic engine shell.
- `/?engine=1&ui=authentic` should render the product pre-game setup screen by default.
- `/?engine=1&ui=authentic&view=pregame` should render the product pre-game setup screen explicitly.
- `/?engine=1&ui=authentic&view=match` should remain a direct-match development/smoke route that starts a match from query/default configuration.
- `/?engine=1&ui=authentic&view=harness` must keep rendering the foundation harness.
- Starting a match from pre-game should transition into `AuthenticMatchScreen` without requiring URL edits.
- The match screen should start from the selected setup config, not hard-coded deck presets.

Do not promote the authentic UI to `/` in this phase.

## Scope

### 1. Route And App Composition

Add a small authentic UI app/router layer instead of forcing `App.tsx` to choose directly between `AuthenticMatchScreen` and `AuthenticUiHarness`.

Suggested shape:

- `src/components/gwent/AuthenticGameApp.tsx`
- `src/components/gwent/AuthenticPreGameScreen.tsx`
- `src/components/gwent/preGameViewModel.ts`
- `src/components/gwent/authentic-pregame.css` or a clearly scoped addition to existing authentic CSS

Route requirements:

- `getAuthenticUiViewFromSearch("?engine=1&ui=authentic")` should return `pregame`.
- `view=pregame` should return `pregame`.
- `view=match` should return `match`.
- `view=harness` should return `harness`.
- Unknown authentic `view` values should fall back to `pregame`, not match.
- `App.tsx` should render the authentic app layer for `ui=authentic`; the app layer chooses pre-game, direct match, or harness.

Transition requirements:

- Clicking Begin Match on pre-game should render the match screen using the selected config.
- Prefer local React state for this transition. Do not require URL mutation.
- If the implementation updates the URL for shareability, it must preserve `engine=1&ui=authentic` and must not make direct URL edits mandatory for normal play.
- Direct `view=match` should continue to exist for smoke tests and debugging.

Stable selectors:

- `authentic-game-app`
- `authentic-pregame`
- `authentic-pregame-begin`
- `authentic-pregame-deck-option`
- `authentic-pregame-opponent-option`
- `authentic-pregame-mode-option`
- `authentic-pregame-seed`
- `authentic-pregame-copy-seed`
- `authentic-pregame-builder-placeholder`

### 2. Pre-Game Visual Layout

Build the pre-game screen from the handoff, adapted responsively.

Required regions:

- Top bar:
  - `Prepare for Battle` title.
  - A menu/back button may be inert or return to the legacy route only if existing app routing supports it safely.
  - A deck-builder entry button must be present but disabled or clearly marked "coming next" until cEp5.
- Main body:
  - Deck selection panel.
  - Mode/opponent/format/seed panel.
- Bottom bar:
  - Summary of selected deck, opponent, mode, seed, and policy.
  - Begin Match primary action.

Visual requirements:

- Use existing `gwent-authentic` scoped tokens.
- Use the parchment/paper, ink, dotted divider, and small-radius language from the handoff.
- Keep UI dense and tactical; do not turn this into a marketing landing page.
- No horizontal document overflow at 390px viewport width.
- The fixed-size prototype layout must be adapted to responsive React/CSS.
- Buttons and text must wrap/truncate cleanly without overlap.

Do not port `prototype/pre-game-screen.jsx` directly. Recreate it in TypeScript/React using current data and engine start APIs.

### 3. Catalog-Backed Deck Preset Selection

Use current catalog deck presets as the source of truth.

Requirements:

- Import from `src/data/catalog`, preferably `currentDeckPresets`, `resolveCatalogDeckPreset`, and `currentCatalogLeaders` as needed.
- Render each current preset as a selectable human deck option.
- Render opponent choices from current implemented presets as AI deck choices.
- Default should preserve the current playtest matchup:
  - human: `current-northern-realms`;
  - AI: `current-nilfgaard`.
- If the human chooses `current-nilfgaard`, the UI should keep or suggest a valid opponent preset. Prefer the other current preset when available.
- Preset cards should be summarized from catalog data:
  - faction;
  - leader name and ability;
  - card count;
  - unit/hero/special counts if easy through pure helpers;
  - readiness/unsupported state.
- A preset should be startable only if it can be resolved against the current catalog and its leader exists.
- Future or missing faction placeholders may be displayed only as disabled options. Do not invent Monsters/Scoia'tael/Skellige decks from prototype stubs.

Implementation guidance:

- Add pure helpers in `preGameViewModel.ts` to map catalog presets to UI cards.
- Keep helpers deterministic and unit-testable.
- Do not use prototype `loadSavedDecks`, `defaultDecks`, localStorage, or stub `CARD_POOL`.
- Do not implement deck editing in cEp4.

### 4. Match Configuration Contract

Create a small setup config type that can bridge pre-game UI to the engine adapter.

Suggested shape:

```ts
interface AuthenticMatchSetupConfig {
  readonly humanDeckPresetId: string;
  readonly opponentDeckPresetId: string;
  readonly modeId: "human-vs-ai";
  readonly formatId: "standard";
  readonly seed: string | number;
  readonly aiPolicyId: "legal-heuristic-v0";
}
```

The exact type may differ, but it must stay serializable at the UI boundary.

Requirements:

- Resolve preset IDs into `CatalogDeckPreset` objects only at the engine-start boundary.
- Extend `StartEngineMatchOptions` and/or add a dedicated helper so the engine adapter can start from selected seat deck presets instead of fixed defaults.
- Keep `startEngineMatch()` defaults compatible with existing callers and tests.
- Seat mapping should remain:
  - human UI role -> `seat_a` by default;
  - AI UI role -> `seat_b` by default.
- Seat controller kinds should be explicit:
  - `seat_a`: `human`;
  - `seat_b`: `ai`.
- Seat player IDs should remain debug-safe labels such as `human` and `ai`.
- The engine `MatchConfig` should derive faction from each selected deck preset.
- The engine catalog should still use `currentCatalogCards` and `currentCatalogLeaders`.

Tests should verify:

- `startEngineMatch()` still starts the old default config when called without options.
- selected deck presets are passed through to `startMatch` correctly;
- selected seed becomes `state.rng.seed`;
- direct match and pre-game Begin Match use the same start helper path.

### 5. Implemented Modes, Disabled Future Modes

The handoff includes mode tiles. In production, only implemented modes should be active.

Enabled in cEp4:

- `Human vs AI` using `legal-heuristic-v0`.

Disabled or hidden in cEp4:

- Local PvP.
- AI vs AI product mode.
- Ranked.
- Training/free mulligan/undo.
- Seed Suite UI.
- Any network/PvP mode.

Requirements:

- Disabled modes must look disabled and must not be clickable.
- Disabled modes should explain briefly why unavailable, using product copy such as `coming later`.
- Do not wire UI controls to headless simulation for AI-vs-AI in this phase.
- Do not expose ML/export controls in pre-game.
- Show the active AI policy ID in a debug-safe way: `legal-heuristic-v0`.

Format requirements:

- The current engine already models the standard two-gem match flow. Treat that as the enabled format.
- If Bo1/Bo3/training choices are shown to match the handoff, they must be disabled unless actually supported by the engine and UI.
- Do not implement a new best-of mode in React.

### 6. Deterministic Seed Handling

Seed handling should become a product control.

Requirements:

- Read `seed` from the URL and prefill the pre-game seed input when present.
- Allow the user to edit the seed.
- Blank seed is allowed, but the UI must make clear whether Begin Match will generate a seed.
- Prefer generating a visible seed before dispatching `startEngineMatch` if the input is blank, so the displayed match seed matches the actual engine seed.
- The active seed must be visible in the pre-game summary and match top bar.
- Add a copy seed button. Use `navigator.clipboard` when available; fall back to selecting/copying is optional. If clipboard support is omitted, keep the button disabled with clear copy.
- Do not store seeds in localStorage in this phase.

Testing requirements:

- app/pre-game helper test for query seed prefill.
- browser smoke should set or use a deterministic seed such as `ep4-smoke` before Begin Match.
- match smoke should assert the seed appears after transition.

### 7. Leader Display Repair

Fix leader presentation as part of cEp4. The current score-card leader image is cropped and too small.

Requirements:

- Add a leader-specific component or view model path instead of treating leader images as tiny cropped thumbnails.
- Suggested component: `AuthenticLeaderCard`.
- It should use the same card-dimension source of truth as `AuthenticCard` where practical.
- It must not render unit-card strength, row, or ability badges.
- It must show leader art without cropping:
  - use `object-fit: contain` for source images;
  - preserve aspect ratio;
  - use a paper/card frame instead of clipping the face.
- It must support at least two sizes:
  - compact/scorecard;
  - pre-game deck option.
- It should have a deterministic fallback when the leader image is missing or fails.
- Fallback should use faction styling and leader name/ability, not unit-card row glyphs.
- Score cards in `AuthenticMatchScreen` should use this leader display.
- Pre-game deck options should use this leader display.

Stable selectors:

- `authentic-leader-card`
- `authentic-leader-card-image`
- `authentic-leader-card-fallback`

Testing requirements:

- Component/helper test that leader view models map catalog leader source fields correctly.
- Browser smoke or component test should verify the score/pre-game leader image uses `object-fit: contain`.
- Browser smoke should verify leader cards are visible in both pre-game and match after Begin Match.

### 8. Mulligan Boundary

Do not build a separate mulligan route or separate full-screen pre-match mulligan screen in cEp4.

Mulligan remains part of the engine match flow:

- pre-game config -> Begin Match -> match screen starts in engine mulligan phase;
- mulligan choices must remain legal-move backed;
- AI mulligan remains policy-driven;
- no rule calculation moves into React.

Allowed cEp4 polish:

- You may make the existing match mulligan phase look more intentional, such as a compact in-match mulligan panel or clearer phase banner.
- You may improve the Begin Match transition copy so users understand the match opens at mulligan.

Not allowed:

- no separate `MulliganScreen` route;
- no bypassing engine legal `choose_mulligan` moves;
- no extra/free mulligan mode;
- no training undo behavior.

### 9. Match Screen Integration

`AuthenticMatchScreen` should accept the selected setup config instead of owning only URL/default setup.

Requirements:

- Direct `view=match` should still start a match if no setup config was passed.
- Pre-game Begin Match should pass an explicit setup config.
- Existing New Game behavior should be reviewed:
  - restarting with the same setup config is acceptable;
  - returning to pre-game is acceptable if clearly labeled;
  - do not silently change selected deck/opponent/seed.
- Match top bar should continue showing seed and AI policy.
- Match screen must preserve cEp2/cEp3 behavior:
  - human mulligan;
  - human card play;
  - AI responses;
  - leader action where legal;
  - prompts;
  - discard browser;
  - round overlay;
  - hidden-info boundaries.

### 10. Hidden-Info Boundaries

Pre-game can show selected deck presets because no match hidden zones exist yet. After Begin Match, match hidden-info rules still apply.

Requirements:

- AI hand remains count/back only.
- AI deck remains count/back only.
- Do not show AI hand/deck card identities in match logs, pre-game-derived labels, or debug summaries.
- Opponent deck preset name may appear as match configuration context, but not ordered deck contents or drawn hand identities.
- Visible text and test snapshots must not include raw engine `instanceId` values, generated ids such as `seat_a:000:`, or debug-only field names.

### 11. Responsive And Accessibility Baseline

Requirements:

- No horizontal document overflow at 390px width for:
  - pre-game screen;
  - match screen after Begin Match;
  - direct match route;
  - harness route.
- Interactive tiles/buttons must have accessible names.
- Disabled unavailable modes must use actual disabled controls or equivalent `aria-disabled` plus click guards.
- Inputs must have labels.
- Keyboard activation should work for Begin Match and deck/mode tiles where feasible.
- Text must not overlap inside deck cards, mode cards, seed controls, or bottom summary.

## Acceptance Criteria

This phase is complete when:

- `/?engine=1&ui=authentic` opens the product pre-game setup screen.
- `/?engine=1&ui=authentic&view=match` still opens a direct match for development/smoke.
- `/?engine=1&ui=authentic&view=harness` still opens the cEp1 harness.
- Users can start a current human-vs-AI match from pre-game without editing the URL.
- Current catalog deck presets drive human deck and AI opponent choices.
- Unimplemented modes/formats are disabled or hidden.
- Selected seed is visible before and after Begin Match.
- `startEngineMatch` can start from explicit selected deck presets while remaining backward compatible.
- Leader display is repaired in pre-game and match score cards: no tiny cropped leader thumbnails.
- Mulligan remains an in-match engine phase, not a separate route/screen.
- Existing cEp2/cEp3 match interactions still work after pre-game transition.
- Hidden-info checks still pass.
- Browser smoke covers pre-game -> match transition and mobile overflow.
- `docs/PROJECT_STATE.md` is updated.
- A report exists at `audit/reports/2026-04-26-cEp4-report.md`.
