# cFp39 Specs - Medic No-Target Timing Guard

Date: 2026-05-18

## Summary

cFp29 made `legal-heuristic-v1` Medic-aware by replacing the flat Medic
source bonus with contextual own-discard revive value. The remaining calibrated
failure-mining queue still reports `medic_no_target_timing` as the next narrow
tuning item:

```text
cFp38 starter matrix: 102 win / 16 loss / 2 draw vs v0
cFp38 failure mining: 295 findings
medic_timing_risk: 5 findings
all 5 medic_timing_risk findings are nilfgaard no-target Medic selections
```

The current `medic_timing_risk` findings all show:

```text
selectedMoveIsMedic: true
selectedMedicWithNoTarget: true
noTargetMedicRisk: true
ownDiscardReviveCandidateCount: 0
bestReviveValueBucket: none
bestReviveStrengthBucket: none
```

cFp39 should not rewrite the Medic system. It should add a narrow second-pass
guard that discourages spending Medic sources when the AI has no own-discard
revive target and a clearly useful non-Medic line exists, while preserving
emergency raw-tempo Medic plays.

## Required Behavior Design

### 1. Add A Narrow No-Target Medic Delay Guard

File: `src/game/ai/legalHeuristicPolicyV1.ts`

Add small, pure helpers near the existing cFp29 Medic helpers. Names may vary,
but keep the concepts explicit and testable.

Suggested shapes:

```ts
export const isNoTargetMedicSourcePlay = (
  features: LegalHeuristicV1Features,
  move: PlayCardMove,
): boolean => { ... };

export const hasUsefulNonMedicLine = (
  features: LegalHeuristicV1Features,
  selectedMove: PlayCardMove,
): boolean => { ... };

export const shouldApplyNoTargetMedicDelayPenalty = (
  features: LegalHeuristicV1Features,
  move: PlayCardMove,
): boolean => { ... };
```

`isNoTargetMedicSourcePlay` should return true only when:

1. `move.kind === "play_card"`.
2. The source card exists in `features.ownHandByCardId`.
3. The source card has the `medic` ability.
4. The current Medic utility has no revive target:
   - `medicSourceUtility(features, card).reviveCandidateCount === 0`;
   - or `bestReviveValueBucket === "none"`;
   - or `noTargetPenaltyApplied === true`.
5. The move is a source play, not prompt resolution.

`hasUsefulNonMedicLine` should inspect legal moves only. It should return true
when there is another useful line that does not spend the no-target Medic source:

- Any `play_card` move whose source card is not a Medic source and whose
  `scorePlayMove(features, candidate) >= MIN_USEFUL_MOVE_SCORE`.
- Any useful `use_leader` move whose `scoreLeaderMove(features, candidate) >=
  MIN_USEFUL_MOVE_SCORE`.
- Any prompt move is out of scope because this helper only runs in normal
  playing play-card scoring.

Be careful to avoid recursion:

- Do not call `scorePlayMove` on the selected no-target Medic move from inside
  its own penalty path.
- It is acceptable to call `scorePlayMove` for candidate non-Medic moves.
- It is acceptable to call `scoreLeaderMove` for leader candidates.

`shouldApplyNoTargetMedicDelayPenalty` should return true only when:

1. The move is a no-target Medic source play.
2. `hasUsefulNonMedicLine(features, move) === true`.
3. None of the tactical exceptions below apply.

### 2. Tactical Exceptions To Preserve

Do not apply the no-target Medic delay penalty when any of these is true:

1. No useful non-Medic line exists.
2. The Medic play is the only legal non-pass play.
3. The AI is on its last gem and the Medic play is part of the best visible
   catch-up attempt.
4. The play wins the match this round:
   - `features.opponentGems <= 1`;
   - `features.ownScore + estimateImmediateTempo(features, move) >= minimumScoreToWinRound(features)`.
5. Round 3 with very low hand count:
   - `features.round === 3 && features.ownHandCount <= 2`.
6. Opponent has already passed and the Medic play is needed to meet
   `minimumScoreToWinRound(features)`.

These exceptions should be conservative. If a fixture is ambiguous, prefer
holding the no-target Medic when a useful non-Medic move exists.

### 3. Apply A Scoring Penalty

In `scorePlayMove(...)`, after cFp29 Medic source utility and before final
return, apply a narrow delay penalty:

```ts
if (shouldApplyNoTargetMedicDelayPenalty(features, move)) {
  score -= MEDIC_NO_TARGET_DELAY_PENALTY;
}
```

Recommended constant:

```ts
export const MEDIC_NO_TARGET_DELAY_PENALTY = 260;
```

Rationale:

- cFp29 already uses `MEDIC_NO_TARGET_UTILITY = -140`.
- The remaining benchmark findings prove that `-140` is not enough in some
  starter Nilfgaard states.
- `260` roughly removes the old flat Medic bonus again when a no-target Medic
  still wins because of strategic/base strength value.

If you choose a different constant, the report must justify it with focused
test scores and benchmark results.


File: `src/game/ai/explainLegalHeuristicV1Decision.ts`

Populate the new booleans for the selected move only:

- `selectedNoTargetMedicDelayRisk`: selected play is a no-target Medic source
  play.
- `betterNonMedicAlternativeAvailable`: a useful non-Medic line exists.
- `noTargetMedicDelayPenaltyApplied`: selected no-target Medic risk with useful
  non-Medic line and no exception.

If the selected move is not a Medic source play, all three should be false.

Do not include card names, source IDs, card IDs, ability arrays, linked source
IDs, or row-specific hidden target details in the trace.

### 5. Explanation Text

In `explainLegalHeuristicV1Decision.ts`, when the selected move is a no-target
Medic:

- If no useful non-Medic line exists:
  - reason may say `no-target Medic accepted — no useful non-Medic line`.
- If an exception allows it:
  - reason may say `no-target Medic accepted — emergency tempo`.
- If a no-target Medic is selected despite the penalty:
  - reason must not claim a strong revive target.
  - reason may say `no-target Medic penalty applied — still best visible line`.

When the selected move is a non-Medic line because the Medic was delayed, a
generic best useful move reason is acceptable. Do not add unsafe card names.
