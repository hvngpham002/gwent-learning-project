# cFp48 Specs: Robust Starter Matrix Evaluation Suite

## Summary

`cFp48` is an evaluation-infrastructure phase. It should increase automated
playtest volume beyond the current 400-record expanded starter matrix without
changing `legal-heuristic-v1` behavior.

The goal is to create a larger deterministic robustness suite, generate the
same public artifact stack we now trust, then freeze that first robust rating
artifact as a named `cFp48` baseline through the cFp47 ledger/comparison layer.

This phase is deliberately not another heuristic patch.

## Research Grounding

Batch B established the evaluation ladder:

1. Deterministic headless fixed-suite ledgers.
2. Hidden-info-safe failure mining.
3. Rating/RD reports.
4. Rating snapshot comparisons.
5. Later robustness probes/search/model work.

cFp46 and cFp47 completed steps 3 and 4 for the current starter matrices. cFp48
should use that infrastructure to collect more automatic evidence before any
new hand-tuned policy behavior is attempted.

Interpretation rules:

- W/L totals are not enough by themselves.
- Rating movement must be read with RD/uncertainty.
- Failure-mining findings are triage signals, not proof of a defect.
- Do not compare ratings across different suite pools as if they share one
rating universe.
- A new suite needs its own baseline snapshot.

## Scope

In scope:

- Add a new deterministic suite:

```text
benchmark-v1-starter-matrix-robust-v1
```

- The robust suite must use:
  - the same five official starter deck descriptors used by the existing
    starter matrix suites;
  - the same 20 mirrored v1-vs-v0 starter matchups used by
    `benchmark-v1-starter-matrix-expanded-v1`;
  - 25 deterministic seed labels:

```text
starter-matrix-robust-001
...
starter-matrix-robust-025
```

- Expected record count:

```text
25 seeds * 20 matchups * 2 mirrored seats = 1000 records
```

- Add npm scripts:

```json
"benchmark:v1-starter-matrix-robust": "tsx scripts/run-benchmark-report.ts --suite benchmark-v1-starter-matrix-robust-v1",
"benchmark:v1-failure-mining-robust": "tsx scripts/run-benchmark-failure-mining-report.ts --suite benchmark-v1-starter-matrix-robust-v1",
"benchmark:ratings:v1-robust": "tsx scripts/run-benchmark-rating-report.ts --suite benchmark-v1-starter-matrix-robust-v1",
"benchmark:ratings:compare:v1-robust": "tsx scripts/run-benchmark-rating-comparison-report.ts --suite benchmark-v1-starter-matrix-robust-v1 --base-snapshot cFp48 --comparison-dir cFp48-vs-latest --phase cFp48"
```

- Extend the cFp40 long-runner with at least:

```text
v1-robust
v1-robust-repeat
```

`v1-robust` should run robust benchmark, robust failure mining, robust ratings,
and robust rating comparison. `v1-robust-repeat` should repeat the same sequence
twice to verify deterministic artifact hashes.

- Generate and commit public artifacts:

```text
docs/research/literature/ai/benchmark-results/benchmark-v1-starter-matrix-robust-v1/latest/
docs/research/literature/ai/benchmark-results/benchmark-v1-starter-matrix-robust-v1/failure-mining/latest/
docs/research/literature/ai/benchmark-results/benchmark-v1-starter-matrix-robust-v1/ratings/latest/
docs/research/literature/ai/benchmark-results/benchmark-v1-starter-matrix-robust-v1/ratings/snapshots/cFp48/
docs/research/literature/ai/benchmark-results/benchmark-v1-starter-matrix-robust-v1/ratings/ledger.json
docs/research/literature/ai/benchmark-results/benchmark-v1-starter-matrix-robust-v1/ratings/comparisons/cFp48-vs-latest/
```

- Update docs and AI Lab metadata to show cFp48 as the latest evaluation phase.

Out of scope:

- AI policy behavior changes.
- `legal-heuristic-v1` scoring constant changes.
- `legal-heuristic-v0` changes.
- Engine rules, legal moves, scoring, prompts, command execution, round
  resolution, setup, catalog data, deck presets, or product UI behavior.
- Changing cFp46 Glicko formulas.
- Changing cFp47 comparison signal thresholds.
- Failure-mining classifier tuning beyond making the new robust suite flow
  through existing classifiers.
- New mechanics decks or competitive decks.
- Search, self-play, ML training, rollout policies, product difficulty tiers,
  browser execution of benchmark jobs, or database storage.

### 2. Tests

Update `tests/game/benchmarkHarness.test.ts` with a focused suite-shape test:

- `getBenchmarkSuite("benchmark-v1-starter-matrix-robust-v1")` resolves.
- seed count is 25.
- matchup count is 20.
- all matchups have `mirror === true`.
- deck descriptor preset ids equal the five official starter presets.
- expected record count is 1000.
- a small filtered run over 1 seed and 1 matchup completes without policy
  failure. Do not run all 1000 records inside the unit test.

Update artifact/rating/comparison tests only if a type/API change requires it.

### 3. Rating Comparison CLI Generalization

`scripts/run-benchmark-rating-comparison-report.ts` currently auto-creates the
`cFp46` baseline snapshot from `ratings/latest` when the named cFp46 snapshot is
missing. cFp48 needs the same behavior for the new suite's first baseline.

Generalize this behavior without breaking existing cFp46 commands:

- If a requested non-`latest` snapshot already exists, use it.
- If it is missing and `snapshotId === createdByPhase`, copy the current
  `ratings/latest` bundle to `ratings/snapshots/<snapshotId>/`.
- If it is missing and `snapshotId !== createdByPhase`, fail with a clear
  usage error.
- Keep cFp47's default behavior intact:

```text
--base-snapshot cFp46 --phase cFp47
```

must still auto-create `cFp46` if that snapshot is missing for the existing
starter suites. This is a backwards-compatible special case.

Suggested helper naming:

```ts
ensureSnapshotExists(...)
```

instead of `ensureCfp46Snapshot(...)`.

### 6. Hidden-Info Safety

The robust artifacts must not contain:

```text
cardsById
finalState
commandLog
eventLog
ownHand
opponentHand
seat_a:
seat_b:
unsafeDebugResults
C:\
/Users/
```

Run a recursive scan over the committed robust artifact directory and record the
result in the report.

Allowed public fields include suite ids, matchup ids, policy ids, deck preset
ids, faction ids, status counts, result counts, ratings, RD, conservative
ratings, failure-mining public summary fields, and safe trace summary counts.
