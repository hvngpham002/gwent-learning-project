# Implementation Spec: Cluster C, Phase 17 - Generic Summon Discard Trigger

## Intent

Implement the generic `summon` discard-trigger ability for unit cards that
replace themselves with a linked side-deck card when they are discarded from the
battlefield.

This phase closes the remaining cCp12/cCp13 linked-effect TODO around
`summon`, but it must not broaden Avenger, Decoy, leader, UI, or catalog
promotion scope. The key rule distinction:

- `summon` triggers only when the source is discarded from a board row.
- `avenger` triggers when the source is removed from the battlefield under the
  Avenger policy already implemented in cCp11, including Decoy.

Keep the implementation pure-engine and narrow.

## Rule Decision

Implement the rule currently documented in `docs/gwent-rules.md` §17.10:

- A card with `summon` is "armed" while on the battlefield.
- `summon` triggers when that source card is discarded from a board row.
- The replacement comes from the controlling seat's `sideDeck`.
- The replacement source is `source.linkedSourceIds[0]`.
- The replacement lands on the same board side and row that the source occupied
  immediately before discard.
- If the linked source ID is missing, or the replacement is not present in the
  controlling seat's side deck, the engine emits a structured non-crashing
  `ability_resolved` outcome and continues.
- If the source is not leaving a board row for a discard zone, `summon` does not
  trigger.

Important negative cases:

- Decoy does **not** trigger `summon` because Decoy returns the source to hand,
  not discard.
- Playing a `summon` unit does **not** immediately summon the replacement.
- Medic revival of a `summon` unit does **not** immediately summon the
  replacement.
- Skellige round-three return of a `summon` unit does **not** immediately summon
  the replacement.
- Monsters keep does **not** trigger `summon` for the kept unit because the unit
  is not discarded.
- Berserker/Mardroeme is not `summon`; do not merge those paths.

Replacement behavior:

- Do not call `resolveCardAbilities` for the replacement in this phase. A
  replacement is summoned, not played from hand.
- Ongoing score effects apply naturally after the replacement is on the board
  because scoring reads board state.
- Do not introduce automatic row choice prompts. A `summon` replacement must
  land on the source's previous row.
- If a future replacement's printed row does not include the source's previous
  row, still follow the effect's replacement-row rule. Do not add row legality
  filtering in this phase.

## Required Implementation

### 1. Promote Ability Metadata

In `src/game/catalog/abilities.ts`, change `summon` from `planned` to
`implemented`.

Update description to distinguish it from Avenger:

- `summon`: discarded-from-battlefield replacement from linked side-deck source.
- `avenger`: battlefield-removal replacement, including Decoy per current
  project policy.

Update tests that assert planned/implemented metadata status.

### 2. Add A Pure Summon Resolver

Add an exported helper in `src/game/core/abilities.ts` or a small new helper
module under `src/game/core/` if that keeps dependencies cleaner.

Suggested shape:

```ts
export interface ResolveSummonInput {
  state: MatchState;
  events: GameEvent[];
  catalogLookup: ReadonlyMap<string, CatalogCardSource>;
  cardId: CardInstanceId;
  origin?: ZoneRef;
}

export type SummonResolutionOutcome =
  | "no_summon"
  | "missing_link"
  | "missing_replacement"
  | "missing_origin_row"
  | "summoned";

export const resolveSummonForCard = (...): SummonResolutionOutcome => { ... };
```

Behavior:

1. Look up the card instance and catalog source.
2. Return `"no_summon"` if the source does not have `summon`.
3. Read replacement source from `source.linkedSourceIds?.[0]`.
4. If missing, emit:

   ```ts
   {
     type: "ability_resolved",
     sourceId: source.sourceId,
     cardId,
     abilityId: "summon",
     outcome: "missing_link"
   }
   ```

5. Use `instance.controller` to choose the side deck to search.
6. Find the first side-deck card whose `sourceId` equals the replacement source.
7. If absent, emit `ability_resolved` with outcome `"missing_replacement"`.
8. Determine origin row from `origin` if it is a `board_row`, otherwise from
   the current instance zone if it is still a `board_row`.
9. If no board-row origin is available, emit `ability_resolved` with outcome
   `"missing_origin_row"`.
10. Move the replacement from side deck to `{ kind: "board_row", seat:
    originSeat, row: originRow }`.
11. Set `replacement.controller` to the source card's controller.
12. Emit `card_summoned` with `abilityId: "summon"`.
13. Emit `ability_resolved` with outcome `"summoned"`.
14. Return `"summoned"`.

Movement/event typing:

- Add `card_moved.reason: "summon_replacement"` unless a better already-used
  reason exists. Do not reuse `"avenger_summon"` for generic Summon.
- Widen `card_summoned.abilityId` from `"avenger"` to `"avenger" | "summon"`.
- Keep the existing Avenger event shape intact.

Do not remove `resolveAvengerForCard`.

### 3. On-Play Ability Handling

Update `resolveCardAbilities`:

- Current `summon` behavior emits `ability_deferred` with
  `reason: "planned_ability"`.
- Replace that with an implemented/armed outcome.

Preferred event pattern:

```ts
emitTriggered(events, source, cardId, "summon");
emitResolved(events, source, cardId, "summon", "armed_for_discard");
```

This mirrors Avenger's existing "armed" style without implying immediate
replacement.

Do not open prompts and do not move any side-deck card on play.

### 4. Wire The Resolver Into Discard-From-Board Paths

The helper must run only for board-row cards that are moved to a discard zone.

Wire into these existing paths:

1. **Special Scorch** in `src/game/core/commands.ts`.
   - For each Scorch target, capture origin board row before `moveCard`.
   - Move the target to `{ kind: "discard", seat: target.seatId }`.
   - Resolve Summon for that target using the captured origin.
   - Keep existing Avenger behavior unchanged.

2. **Unit-source row Scorch** in `src/game/core/abilities.ts`.
   - Existing `resolveScorchRow` targets already capture origin.
   - Resolve Summon after moving the target to discard, before or after Avenger
     is acceptable if documented and deterministic. Prefer before Avenger only
     if it keeps event order clearer; do not let one block the other.

3. **Unit-source whole-board Scorch** in `src/game/core/abilities.ts`.
   - Same as row Scorch.

4. **Foltest row-Scorch leaders** in `src/game/core/commands.ts`.
   - cCp16 added a local destruction loop. Add Summon resolution there too.

5. **Round cleanup** in `src/game/core/commands.ts`.
   - When sweeping board-row units, collect Summon origins for discarded
     non-kept units.
   - After the row sweep and the existing `board_swept` event, resolve Summon
     origins so replacements stay on the board for the next round, matching the
     Avenger round-cleanup policy.
   - Do not resolve Summon for Monsters-keep cards because they were not
     discarded.

Do not wire into:

- Decoy return-to-hand.
- Medic revive.
- card play.
- Skellige round-three return.
- weather cleanup.
- row-horn cleanup.
- Berserker/Mardroeme transform.

### 5. Clean Up Deferred Events

Current discard paths emit `ability_deferred` with
`reason: "discard_trigger_pending"` for `summon`.

After cCp17:

- implemented `summon` discard paths should emit `ability_resolved` outcomes,
  not unresolved planned/deferred events;
- existing Avenger `ability_deferred` behavior may remain unchanged if it is
  already part of event trace expectations;
- no `ability_deferred` with `abilityId: "summon"` and
  `reason: "planned_ability"` should be emitted by normal play.

If keeping any `ability_deferred` event for `summon` as an activity-log marker,
justify it in the report and update tests accordingly. The preferred path is no
deferred Summon event after implementation.

### 7. Rules Documentation

Update `docs/gwent-rules.md` §17.10 and/or nearby Avenger text to reflect that
generic Summon is now implemented.

Document explicitly:

- linked side-deck source is `linkedSourceIds[0]`;
- replacement uses the source's controller side deck;
- replacement lands on the same board side and row the source occupied;
- Decoy does not trigger Summon;
- Scorch and round cleanup do trigger Summon;
- Monsters keep prevents Summon for the kept unit only;
- missing link/replacement is non-crashing and emits structured outcomes;
- replacement is summoned, not "played", so on-play abilities are not resolved
  in cCp17.

Do not rewrite the full rulebook.

### Helper / Metadata

- `summon` ability metadata is `implemented`.
- `resolveSummonForCard` returns `"no_summon"` for non-Summon sources.
- missing `linkedSourceIds[0]` emits `ability_resolved` outcome
  `"missing_link"`.
- missing side-deck replacement emits `"missing_replacement"`.
- missing board-row origin emits `"missing_origin_row"`.
- successful replacement emits `card_moved.reason === "summon_replacement"`,
  `card_summoned.abilityId === "summon"`, and `ability_resolved.outcome ===
  "summoned"`.

### On-Play / Non-Trigger Cases

- Playing a `summon` unit puts it on the board and emits
  `"armed_for_discard"` (or the implemented equivalent chosen above), but does
  not move a side-deck card.
- Medic revival of a `summon` unit does not summon the replacement immediately.
- Skellige round-three return of a `summon` unit does not summon the
  replacement immediately.
- Decoy returning a `summon` unit to hand does not summon the replacement.
- A Monsters-kept `summon` unit during round cleanup does not summon a
  replacement.

### Trigger Cases

- Round cleanup discards a `summon` unit and summons the linked replacement
  after the sweep so the replacement persists into the next round.
- Special Scorch destroys a `summon` unit and summons the linked replacement on
  the same board side and row.
- Unit row-Scorch destroys a `summon` unit and summons the linked replacement.
- Unit whole-board Scorch destroys a `summon` unit and summons the linked
  replacement.
- Foltest row-Scorch leader destroys a `summon` unit and summons the linked
  replacement.
- Board-side discard is preserved: if a Summon unit occupies the opponent board
  side, the discarded source goes to that board side's discard, while the
  replacement comes from the controller's side deck and lands on the occupied
  board side/row.

### Interaction / Regression Cases

- Avenger Decoy behavior remains unchanged.
- Avenger Scorch/round-cleanup behavior remains unchanged.
- Berserker/Mardroeme transformation remains unchanged.
- Existing cCp13 linked-ability `it.todo` for Summon is promoted to an active
  assertion or removed with equivalent active coverage.
- The remaining placeholder leader tutor/restore `it.todo` stays deferred.

## Acceptance Criteria

- `summon` metadata is `implemented`.
- A reusable Summon resolver exists and is exported if useful for tests.
- Summon triggers only when a board-row Summon source is discarded.
- Summon does not trigger on play, Medic revive, Skellige return, Monsters keep,
  Decoy, weather cleanup, or non-discard movement.
- Successful Summon pulls `linkedSourceIds[0]` from the controlling seat's side
  deck.
- Replacement lands on the source's previous board side and row.
- Replacement uses a distinct movement reason such as `"summon_replacement"`.
- `card_summoned` supports `abilityId: "summon"` without breaking Avenger.
- Missing link/replacement/origin outcomes are structured and non-crashing.
- Scorch, Foltest row-Scorch leader, and round cleanup paths all resolve
  Summon.
- Board-side discard placement remains correct.
- Avenger behavior remains unchanged.
- The cCp13 Summon `it.todo` is promoted to active coverage or replaced by
  equivalent active coverage.
- `docs/gwent-rules.md`, `docs/PROJECT_STATE.md`, and the cCp17 report are
  updated.
