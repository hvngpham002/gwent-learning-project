# Implementation Spec: Cluster A, Phase 0 - Baseline Safety Net

## Goal

Establish a lightweight regression and smoke-test baseline before any architecture migration begins. This phase should make the project safer to change without fixing audited gameplay bugs yet.

## Scope

1. Add a minimal repeatable test command if the project has none.
   - Prefer the least disruptive tool compatible with Vite + TypeScript.
   - Keep config small and conventional.

2. Add baseline test scaffolding.
   - Create a place for regression tests covering audited root causes.
   - It is acceptable for many tests to be skipped or pending initially, but the list must be explicit.

3. Add a smoke checklist for the current playable app.
   - Capture the current human-vs-AI Northern Realms mirror flow.
   - Include setup, mulligan, playing a unit, playing weather, passing, round end, game end/reset risk, and AI move.
   - This may be markdown if automation is too large for this phase.

4. Add at least a small number of real tests that pass today.
   - Good candidates: pure helper tests for scoring basics, starting deck shape, or catalog/deck helper behavior.
   - Avoid tests that require large React UI setup unless that is already easy.

5. Create the required implementation report:
   - `audit/reports/2026-04-24-cAp0-report.md`

## Out Of Scope

- Do not fix gameplay bugs from the audit.
- Do not start the pure engine migration.
- Do not rewrite Redux slices or thunks.
- Do not refactor AI.
- Do not introduce deck builder or card catalog changes yet.
- Do not delete legacy code.

## Acceptance Criteria

- `npm run build` passes after the work.
- There is a test command in `package.json`, for example `npm test` or an equivalent documented command.
- The test command runs successfully.
- Regression placeholders exist for at least:
  - `R-001` deterministic RNG / starter
  - `R-004` Spy discard ownership
  - `R-005` Medic human/AI divergence
  - `R-006` AI seat hardcoding
  - `R-008` pre-decrement game-end reset
  - `R-009` Horn source tracking
  - `R-010` side deck
  - `R-011` mulligan duplicate/lost card
  - `R-012` Decoy double tracking
  - `F-3.15` Agile AI row choice
  - `F-5.11` modifier order score example
  - `F-10.4` Skellige Storm
- A human smoke checklist exists and is linked from the report.
- No intended gameplay behavior changes are made.

## Required Tests / Commands

Run and report:

```bash
npm run build
```

Also run the new test command, whatever you add:

```bash
npm test
```

If you choose a different command, document why.

## Things To Watch Out For

- The app currently has no test runner. Keep dependency and config churn minimal.
- Some audited bugs are real current behavior. Do not make failing tests active unless the phase explicitly fixes them. Use skipped tests, todo tests, or a markdown regression ledger for known broken cases.
- Be careful around `node_modules` and generated files. Do not commit build artifacts or temporary outputs.
- If adding Vitest, make sure TypeScript path aliases still resolve.
- The report must distinguish tests that pass today from regression tests intentionally pending because the engine overhaul will fix them later.
- Preserve the current playable path. This phase is a safety-net phase, not a behavior-change phase.
