## Summary

cFp62 classified every remaining cFp61 sampler invalid root as
`public_zone_count_deficit`:

- `benchmark-v1-starter-matrix-v1`: 63 invalid roots.
- `benchmark-v1-starter-matrix-robust-v1`: 341 invalid roots.
- All 404 invalid roots had `insufficient_prior_remaining`.
- Fixed-known hand and prompt-reveal buckets were zero.
- Public-known counts were nonzero for every invalid root.
- The deficit was narrow: current was always 1; robust was 340 roots with
  deficit 1 and one root with deficit 2.

cFp63 should repair the public-zone count path before any determinized probe.
The leading hypothesis is that cFp61/cFp62 public-known subtraction can count a
single public card instance more than once if it appears in more than one public
zone/list at a root. cFp63 must verify this through hidden-info-safe scalar
evidence, then implement unique-public-card-instance accounting for sampler
public-known subtraction and zone summaries.

cFp63 must not loosen the sampler's conservation checks, add opaque hidden
placeholder cards, skip invalid roots, run PIMC/ISMCTS/search, or change
gameplay. If unique public-card de-duplication does not explain the invalid
roots, stop with the evidence and revise the plan instead of forcing validity.

## Repair Hypothesis

The public-zone deficit likely comes from duplicated public card references in
the sampler's public-known collection path. The current cFp61 implementation
iterates public board rows, row horns, discard piles, removed-from-game piles,
the acting hand, weather entries, and prompt reveal ids. If the same runtime
card instance is reachable from more than one of those public lists, source
subtraction can count that instance multiple times even though conservation
should count it once.

cFp63 should fix sampler accounting defensively:

- internally track public card instance ids that have already contributed to
  public-known source subtraction;
- count each unique public card instance at most once in
  `publicKnownSourceCounts`;
- count each unique prompt-revealed opponent-hand card at most once in
  `fixedKnownHandSourceCounts`;
- expose only scalar duplicate-reference diagnostics, never the duplicated ids.

The repair should be localized to sampler/evaluation infrastructure. It should
not mutate `MatchState`, fix engine zone arrays, or change gameplay commands in
this phase.

## Public-Known Accounting Contract

### Internal Collection

Introduce a small internal collection state for public-known subtraction. It may
use runtime card instance ids in memory only:

```ts
interface PublicKnownCollectionState {
  publicKnownSourceCounts: Record<string, number>;
  fixedKnownHandSourceCounts: Record<string, number>;
  seenPublicCardIds: Set<CardInstanceId>;
  seenFixedKnownHandCardIds: Set<CardInstanceId>;
  duplicatePublicReferenceCount: number;
  duplicateFixedKnownHandReferenceCount: number;
}
```

Exact names may differ.

Rules:

- If a public card instance is not owned by the sampled opponent seat, ignore it.
- If its `sourceId` is not present in the known-preset main-deck prior, ignore
  it for source subtraction.
- If a public card instance has already been counted in
  `publicKnownSourceCounts`, do not count it again. Increment only a scalar
  duplicate-public-reference counter.
- If a prompt-revealed opponent-hand card has already been counted as fixed
  known hand, do not count it again. Increment only a scalar duplicate
  fixed-known-hand counter.
- Prompt-revealed opponent-hand cards should still be included in the general
  public-known set exactly once and the fixed-known-hand set exactly once.
- Do not serialize `seenPublicCardIds`, `seenFixedKnownHandCardIds`, card ids,
  source ids, or per-card lists.

### Public Zone Count Summary

Update cFp62 public-zone count summaries to distinguish raw observed references
from unique counted public cards, using scalar counts only. For example:

```ts
interface PublicKnownZoneCountSummary {
  opponentBoardUnitCount: number;
  opponentRowHornCount: number;
  opponentDiscardCount: number;
  opponentRemovedFromGameCount: number;
  opponentWeatherCount: number;
  actingHandKnownOpponentOwnedCount: number;
  promptRevealedOpponentHandCount: number;
  duplicatePublicReferenceCount: number;
  duplicateFixedKnownHandReferenceCount: number;
  uniquePublicKnownCardCount: number;
  uniqueFixedKnownHandCardCount: number;
  otherPublicKnownCount: number;
}
```

Do not include card names, source ids, runtime ids, raw zone paths, or lists.

### Conservation Must Remain Strict

Do not make invalid roots disappear by changing:

```text
remaining prior count < hidden hand draw count + opponent deck count
```

into a valid state. The only acceptable way for former invalid roots to become
valid in cFp63 is for unique public-card accounting to increase
`priorRemainingCardCount` by avoiding duplicate public subtraction.

If invalid roots remain after unique-public de-duplication, preserve them as
invalid with safe reason counts and document their scalar evidence.
