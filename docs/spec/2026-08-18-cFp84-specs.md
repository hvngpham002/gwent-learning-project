## Summary

cFp83 established a deterministic closed-root input contract for a first
search consumer. It emits complete public action surfaces only when every
action at the root is `consumer_ready` and exactly reconstructible from the
projected dictionaries:

- current: 663 selected roots, 1,488 selected actions, 63 inherited skips;
- robust: 5,314 selected roots, 12,109 selected actions, 340 inherited skips;
- closure mismatches: 0;
- projected-dictionary reconstruction mismatches: 0; and
- robust repeat hashes: identical.

cFp84 should implement the first bounded action-evaluation signal over those
selected complete roots. The signal is an immediate public-state delta from
executing exactly one public action in each of the established eight
determinized samples. It is not a rollout value, expected win rate, learned
value, equilibrium value, action rank, recommendation, or product policy.

The purpose of cFp84 is to prove that the closed cFp83 surface can feed a
deterministic evaluator with complete pair accounting and no hidden-world
serialization. It must evaluate every selected action, retain source order,
and refuse to claim readiness if any selected root, action, sample, command,
or aggregate is missing.

## Execution Boundary

cFp84 may re-observe benchmark roots only to execute the selected cFp83 public
actions. It must use the existing benchmark suite, root observer, public-action
abstraction, known-preset sampler, sampled-world rebuild, legal-move command
conversion, and engine transaction paths. Reuse established helpers; do not
copy or fork their rules.

For every cFp83 selected root:

1. Resolve its cFp80 root identity by `rootRef`.
2. Re-observe exactly one matching benchmark root using the full cFp80 public
   identity tuple and public fingerprint.
3. Materialize exactly eight hidden worlds in memory through the existing
   known-preset sampler path.
4. Rebuild legal moves independently in each sampled world.
5. Build public-action buckets with the established canonical abstraction and
   ordering used by cFp77/cFp78.
6. Match every cFp83 action to exactly one public-action bucket in every
   sample.
7. Require that bucket to contain exactly one legal move. cFp83 selected only
   non-collision actions; a zero- or multi-move bucket is a contract failure.
8. Convert that legal move to the exact engine command and execute it against
   a cloned sampled state.
9. Capture only the permitted public pre/post scalar metrics.
10. Discard the sampled state and all hidden assignments after aggregation.

Do not mutate a sampled state and reuse it for another action. Every
action/sample pair starts from an independent clone of the same sampled root.
Do not execute a second action, opponent reply, rollout, playout, or terminal
simulation beyond transitions caused atomically by the one command.

## Bounded Signal Formula

Implement the following fixed v0 formula as a pure exported function. All
components and the final signal are integers.

Definitions:

    beforeScoreDiff = beforeOwnScore - beforeOpponentScore
    afterScoreDiff = afterOwnScore - afterOpponentScore

    scoreSwing =
      clamp(afterScoreDiff - beforeScoreDiff, -60, 60)
      when phase and round are unchanged;
      otherwise 0

    handSwing = clamp(
      ((afterOwnHandCount - beforeOwnHandCount)
       - (afterOpponentHandCount - beforeOpponentHandCount)) * 8,
      -24,
      24
    )

    gemSwing = clamp(
      ((afterOwnGemCount - afterOpponentGemCount)
       - (beforeOwnGemCount - beforeOpponentGemCount)) * 25,
      -50,
      50
    )

    terminalComponent =
      100 for acting-seat match win;
      -100 for acting-seat match loss;
      0 for draw or incomplete match

    immediateSignal = clamp(
      scoreSwing + handSwing + gemSwing + terminalComponent,
      -200,
      200
    )

Rationale:

- `scoreSwing` measures immediate public tempo but becomes zero across a
  round/phase transition because board-score reset would otherwise appear as
  a large negative action outcome;
- `handSwing` records immediate public card-count cost or advantage;
- `gemSwing` records public round-loss/win consequences without a separate
  round bonus that would double count gems; and
- `terminalComponent` records only an observed public terminal result.

Do not add action-kind priors, faction priors, card strength estimates,
heuristic-v1 scores, future-hand estimates, continuation values, discounted
returns, or manually preferred action bonuses.

The formula is an immediate bounded diagnostic baseline. Its weights are a
declared v0 scale, not learned calibration and not evidence of optimal play.

## Aggregation Contract

For every selected action, aggregate the eight completed sample results. Emit:

- `rootRefId` and `publicActionRefId` using the immutable cFp83 projected
  dictionaries;
- public action `ordinal`;
- requested/completed/failed sample counts;
- sum, minimum, maximum, and mean-milli for each signal component;
- sum, minimum, maximum, and mean-milli for `immediateSignal`;
- count of distinct public outcome tuples across samples;
- `sampleSensitivity`: `stable` when one tuple is observed,
  `sample_sensitive` when more than one is observed, or `incomplete` on any
  failure; and
- count maps using only fixed public enums for phase/round transition and
  terminal outcome classes.

`meanMilli` is deterministic integer arithmetic:

    roundHalfAwayFromZero(componentSum * 1000 / completedSampleCount)

Do not serialize floating-point means.

The public outcome tuple used only for distinct-count calculation is:

    scoreSwing | handSwing | gemSwing | terminalComponent |
    phaseTransition | roundTransition | terminalOutcome

Do not serialize the per-sample tuples or per-sample signal rows.

For each selected root, emit aggregate accounting only:

- selected action count;
- expected/completed/failed pair counts;
- stable action count;
- sample-sensitive action count;
- minimum/maximum immediate signal observed at the root; and
- source branching/budget/cap buckets forwarded from cFp83.

Do not emit action ranks, sorted-by-signal lists, best/worst action refs,
pairwise action deltas, tie groups, thresholds for choosing actions, or a
recommended action.

exit nonzero, and make no readiness claim.

round, policy, faction, deck preset, and matchup. Do not include raw exception
messages, root payloads, commands, moves, or hidden identities.
