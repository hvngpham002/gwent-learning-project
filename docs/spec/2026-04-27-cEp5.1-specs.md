# Implementation Spec: Cluster E, Phase 5.1 - Deck Builder Composition And Identity Polish

## Goal

Tighten the cEp5 authentic deck builder so it behaves like an editor for clear, unique deck instances and prevents obvious composition mistakes before they become validation errors.

cEp5.1 should address the deck-builder issues found during manual testing:

- Step 1/pre-game should not show confusing duplicate same-name deck instances.
- Saved/local deck names should be unique and stay unique after create, duplicate, import, and rename.
- Editing a deck should update the selected saved deck in place, not create another same-looking instance.
- New deck creation should not silently lock the deck to Northern Realms.
- The card pool should prevent adds that would exceed hard composition caps, especially the 10-special-card limit.

This phase is still deck editing, not Card Studio. It must not add custom card creation, image uploads, source-ID authoring, ability authoring, permanent repo writes, or catalog code generation.

## Architecture Position

Before this phase:

- `/` remains the legacy UI.
- `/?engine=1` remains the diagnostic engine shell.
- `/?engine=1&ui=authentic` opens the authentic pre-game setup.
- `/?engine=1&ui=authentic&view=deck-builder` opens the catalog-backed local deck builder.
- Local decks are browser-local `CatalogDeckPreset` objects persisted under `gwent_authentic_decks_v1`.
- The builder can validate invalid decks, but it still allows some invalid add attempts before blocking Play.
- New deck creation currently has insufficient faction-selection UX.

After this phase:

- Local deck identity is predictable: unique names, unique preset IDs, and in-place edits for the selected deck.
- Pre-game presents one meaningful option for a catalog deck and its editable local counterpart, not two same-name instances.
- New deck creation requires an explicit faction choice or immediately exposes a required faction selector before the deck can be considered ready.
- Existing local decks expose a safe faction-change flow.
- Wrong-faction cards are hidden from the active card pool. Relevant cards that cannot be added due to hard composition limits are visually disabled and cannot be clicked into the deck.
- Validation remains as a backstop for imports, stale localStorage, and direct JSON edits.

## Scope

### 1. Deck Identity And Name Uniqueness

Make local deck identity unambiguous.

Requirements:

- Every browser-local deck must have a unique `presetId`.
- Every browser-local deck must have a unique display name after trimming and whitespace normalization.
- If localStorage contains duplicate IDs or names from older builds, normalize them on read/write without crashing.
- Create, Duplicate, Import, and Rename flows must use the same uniqueness rules.
- Renaming a deck to an existing local deck name should not leave two equal names. Recommended behavior:
  - either auto-suffix to `Name 2`;
  - or show an inline blocking message and keep the previous name until fixed.
- Choose one behavior and cover it with tests. Auto-suffix is recommended because it is already consistent with cEp5 follow-ups.
- Editing deck contents, leader, name, or faction must update the selected deck in place by stable `presetId`.
- Selecting a deck in the builder must not create a new deck.
- Returning from deck builder to pre-game must not duplicate the active deck.

Implementation guidance:

- Keep pure identity helpers in `deckBuilderViewModel.ts` or a small adjacent helper file.
- Keep persistence normalization in `deckBuilderStorage.ts`.
- Do not add runtime engine IDs or card instance IDs to local deck storage.

### 2. Pre-Game Local/Catalog Presentation

Make Step 1 "Choose Deck" show the player's editable deck list without duplicate same-name catalog/local confusion.

Requirements:

- If a local deck is the editable copy of a current catalog deck, pre-game should show the local copy in place of the catalog tile.
- A local editable copy should be detected by stable source where possible:
  - `local-${catalogPresetId}` seeded IDs;
  - or an explicit helper mapping when local name matches a catalog preset name.
- If two local decks would shadow the same catalog preset, show only one primary replacement and keep the other as a separately named local deck after uniqueness normalization.
- Pre-game selected state must use a UI option identity that cannot collide across catalog/local sources.
- Starting a match from a local pre-game deck must pass that exact local `CatalogDeckPreset` as the human deck.
- Starting a match from a catalog pre-game deck must not accidentally substitute a local deck with the same raw `presetId`.

### 3. Explicit Faction Selection

Remove the silent Northern Realms lock from new decks.

Requirements:

- New deck creation must include visible faction selection.
- Faction options should be derived from catalog data, not hard-coded button text:
  - known non-neutral catalog factions;
  - at least one available leader for the faction;
  - future factions may appear disabled until they have enough catalog data for editing.
- A new deck should get that faction's default leader.
- Existing local decks should expose a faction selector.
- Changing an existing deck's faction must be safe and explicit because it can invalidate cards.

Recommended faction-change behavior:

- When the user changes faction:
  - reset leader to the new faction's default leader;
  - keep neutral cards;
  - remove cards that belong to the old/non-matching faction;
  - show a compact notice like `Faction changed to Nilfgaard; removed 12 wrong-faction cards.`
- If the change would remove cards, require confirmation before applying.
- If the user cancels, no deck mutation should occur.

Required safeguards:

- Never leave a deck with a wrong-faction leader after faction change.
- Do not silently keep wrong-faction cards in the deck after faction change unless you intentionally choose a "block until fixed" UX and clearly document it in the report. Removal with confirmation is preferred.
- Do not change engine rules.

### 4. Add-State Enforcement In The Card Pool

Prevent add actions that would violate hard deck-building limits.

Requirements:

- Add a pure helper that computes whether a catalog card can be added to the active deck.
- Recommended shape:

```ts
interface DeckBuilderAddState {
  readonly canAdd: boolean;
  readonly reasonCode?: "deck_limit" | "special_cap" | "wrong_faction" | "unknown_card";
  readonly reason?: string;
}
```

- The helper must account for:
  - per-card `deckLimit`;
  - deck faction vs card faction;
  - special-card cap at `10`;
  - unknown/missing card references defensively.
- Once a deck has `10/10` special cards, all additional relevant special cards must be disabled/greyed out in the pool.
- Cards disabled by special cap must not add on card click or button click.
- Existing special cards in the deck list must remain removable.
- Disabled relevant pool cards should expose a clear reason in title text, selected-card detail, or another non-cluttering metadata path:
  - `3/3 limit`;
  - `special cap reached`;
  - similar concise labels are acceptable.
- Wrong-faction cards should be hidden by the pool filter, not shown as disabled cards.
- Validation must remain in place and still report hard errors for imported/stale invalid decks that already exceed limits.

Important:

- Do not hide relevant selected-faction or neutral cards just because they are disabled by deck-limit or special-cap rules. Wrong-faction cards are not relevant to the active faction and should remain hidden.
- Do not let UI-only disabled state replace validation. It is an interaction guard, not the source of truth.

### 5. Duplicate And Reset Actions

Add explicit recovery/copy actions so users do not need import/create workarounds.

Requirements:

- Add a `Duplicate` action for the active deck.
- Duplicate must:
  - create a new local deck with a unique `presetId`;
  - create a unique name, such as `Current Northern Realms 2`;
  - preserve faction, leader, `mainDeck`, and `sideDeck`;
  - select the duplicated deck after creation.
- Add a `Reset to catalog` action when the active local deck can be mapped to a current catalog preset.
- Reset must:
  - require confirmation;
  - replace the local deck's composition, faction, leader, and name with the current catalog preset values;
  - preserve the local deck's `presetId` so editing remains in place;
  - select the same local deck after reset.
- If a deck has no catalog source, hide or disable Reset with a clear label.

Implementation guidance:

- A pure helper such as `findCatalogSourceForLocalDeck(localDeck)` is acceptable.
- Prefer a conservative source match:
  - `local-${catalogPresetId}` first;
  - then normalized name match if needed for old localStorage compatibility.

### 6. Import Conflict UX

Make import conflict resolution visible to the user.

Requirements:

- Import must preserve the existing "do not overwrite" behavior.
- If import changes the deck ID or name because of conflicts, show a notice after successful import.
- The notice should name the final imported deck, for example:
  - `Imported as Current Northern Realms 2.`
- If the import was rejected, keep structured import errors visible as cEp5 does now.
- Imported deck names must pass the same uniqueness rules as create/duplicate/rename.

Implementation guidance:

- It is acceptable to extend `DeckBuilderImportResult` with a `notices` array.
- It is also acceptable to keep `parseDeckImport` focused on ID parsing and apply name uniqueness in the React layer, as long as tests cover the visible conflict outcome.

## Out Of Scope

Do not implement:

- Card Studio.
- Custom card creation.
- Card image upload or image management.
- Ability authoring.
- Source ID editing UI for cards.
- Repo file writes from browser code.
- Catalog code generation.
- New engine rules.
- New faction card content.
- Route promotion to make authentic UI the default route.
- Drag-and-drop deck editing.
- PvP, AI-vs-AI product mode, ranked, Bo1, or training mode.
- Cloud/account persistence.

## Tests

Add or update focused tests.

Required unit/helper coverage:

- unique local deck names and IDs after create/import/storage normalization;
- renaming to an existing name follows the chosen uniqueness or blocking behavior;
- editing active deck contents updates one existing deck, not multiple decks;
- pre-game replaces a seeded local copy over its catalog source;
- pre-game does not substitute a local deck when a catalog deck is selected;
- faction options derive from catalog leaders/factions;
- changing faction resets leader and removes wrong-faction cards with a pure helper;
- add-state helper disables special cards when the deck is already `10/10` specials;
- add-state helper disables cards at `deckLimit`;
- add-state helper still reports wrong-faction cards defensively, while the visible pool hides them;
- Duplicate preserves composition but gets unique ID/name;
- Reset to catalog preserves local ID and restores catalog composition;
- import conflict messaging or returned metadata is test-covered.

Required browser smoke coverage:

- pre-game Create Deck opens the builder and leads to a visible faction-selection path;
- deck builder Edit path still opens existing decks;
- after adding specials up to `10/10`, additional special cards are disabled/greyed out and do not increment total/special count;
- Duplicate creates a selected same-composition copy with a unique name;
- Reset to catalog is visible for a seeded local deck and restores catalog count after modification;
- no horizontal overflow at mobile width on pre-game and deck-builder routes.

Existing route and hidden-info browser smoke must continue to pass.

## Acceptance Criteria

cEp5.1 is complete when:

- New deck creation no longer silently locks to Northern Realms.
- Existing local deck faction can be changed safely with clear card-removal behavior.
- Local deck names are unique across the builder.
- Local deck IDs are unique across persisted storage.
- Editing a deck updates the selected deck in place.
- Pre-game no longer shows duplicate same-name catalog/local deck instances for seeded editable copies.
- Special cards are greyed out/disabled once adding them would exceed `10/10`.
- Disabled relevant add states expose clear non-cluttering reasons through metadata, title text, or selected-card detail.
- Duplicate action works and selects the duplicate.
- Reset to catalog works for seeded/catalog-derived local decks.
- Import conflict messages are visible.
- Deck validation still blocks invalid imported/stale data.
- Product routes remain unchanged:
  - `/` legacy default;
  - `/?engine=1` diagnostic shell;
  - `/?engine=1&ui=authentic` pre-game;
  - `/?engine=1&ui=authentic&view=deck-builder` deck builder;
  - `/?engine=1&ui=authentic&view=match` direct match;
  - `/?engine=1&ui=authentic&view=harness` foundation harness.
- No forbidden legacy imports are introduced.
- Project state and deck-builder docs are updated.
- The cEp5.1 report exists and includes the required sections.
