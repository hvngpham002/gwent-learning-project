## Summary

cFp60 added the safe sampler contract but intentionally stopped before
materializing hidden cards. Its artifacts prove that the opponent-seat
`known_preset_decklist_prior` is count-coherent over both starter benchmark
suites, but every root is still `deferred` with `sampleCountGenerated: 0` and
`sampleCountValid: 0`.

cFp61 is the next sampler-first step. It must materialize hidden opponent hand
and deck **multisets** in memory from the known preset prior, validate those
samples against public counts and duplicate limits, and serialize only
hidden-info-safe aggregate proof that samples were generated.

cFp61 must not evaluate actions, clone full determinized `MatchState`s for
rollouts, run PIMC/ISMCTS, choose moves, wire a product AI, or change
`legal-heuristic-v1`. This phase exists to turn cFp60's `deferred` sampler
contract into a real hidden-multiset sampler that a later cFp62/cFp63
determinized probe can consume.

## Research Grounding

Use cFp58, cFp59, and cFp60 as controlling decisions.

cFp58 says safe search starts from the acting seat's observation, legal moves,
and named priors. It explicitly separates safe sampler-required work from
oracle/debug variants that consume true hidden state.

cFp59 shows starter benchmark roots have tractable legal branching. That
supports a future determinized probe, but only after sampling is safe.

cFp60 proves official starter roots can construct an opponent-seat known preset
prior with public count consistency. It also establishes the public action
abstraction. Its explicit next step is hidden-multiset materialization before
`determinized-pimc-probe-v0`.

Batch A / Long guardrail for cFp61:

- determinized samples must be treated as samples from a prior, not truth;
- samples must be validated against public observation constraints;
- committed artifacts must not expose sampled hidden identities;
- no action-value claim can be made until a later probe measures action
  outcomes and determinization risk.

Batch B guardrail for cFp61:

- fixed-suite benchmark ledgers and rating ledgers remain source of truth;
- cFp61 artifacts are sampler correctness artifacts only;
- no product difficulty, policy strength, rating, or AI quality conclusion
  follows from materialized hidden multisets alone.

## Sampler Contract

### Prior Input

Reuse cFp60's opponent-seat known preset prior. The acting root still records
acting-seat metadata, but hidden-card materialization must sample from the
**opponent seat's** official starter deck preset.

Allowed inputs:

- root `MatchState`, but only for public zones and public scalar counts;
- benchmark seat metadata: seat id, policy id, faction, deck preset id;
- catalog deck preset composition;
- acting root phase, round, public score/gem/pass metadata as scalar context;
- legal moves only through the already-public cFp60 action abstraction.

Forbidden inputs:

- true opponent hand card identities;
- true opponent deck card identities or order;
- hidden runtime card ids;
- hidden source ids in artifacts;
- raw `cardsById`, `finalState`, command/event logs, or unsafe debug payloads
  in artifacts.

### Public Known Source Subtraction

Build an internal source-count multiset from the opponent preset's **main deck**
only. Then subtract public known main-deck cards visible at the root.

Public known zones may include:

- opponent board row units;
- opponent row horns;
- opponent discard pile;
- public weather zone cards that belong to the opponent's main deck if the
  engine can safely identify ownership/source from the public card instance;
- any prompt-revealed cards that the acting observation already exposes through
  the public/prompt contract.

Rules:

- Only inspect `state.cardsById` for card ids that are in public/visible zones.
- Do not iterate opponent hand or opponent deck card ids to discover source
  identities.
- Do not subtract side-deck-only/generated cards from the main-deck prior.
- If public known source counts exceed the prior's available copy count, mark
  the root invalid with a safe reason such as
  `public_known_exceeds_prior_copy_count`.
- If the remaining prior card count is less than
  `opponentHandCount + opponentDeckCount`, mark invalid with a safe reason such
  as `insufficient_prior_remaining`.

### Materialized Sample Shape

Materialized hidden multisets may exist in memory and in unit-test-local values,
but must not be serialized in committed artifacts.

Internal sample shape may include source ids, for example:

```ts
interface MaterializedHiddenMultisetSample {
  sampleIndex: number;
  handSourceCounts: Record<string, number>;
  deckSourceCounts: Record<string, number>;
}
```

Artifact records must not include those fields or their hashes. Do not serialize
`handSourceCounts`, `deckSourceCounts`, source ids, sample fingerprints, or
sampled card names. A hash of a small sampled multiset can be brute-forced
against official starter lists, so do not serialize sampled multiset hashes.

### Deterministic Sampling

For each root with an available valid prior:

- default `sampleCountRequested` should remain `8`;
- sample using a deterministic local PRNG seeded from public values only, such
  as `samplerRunId`, `rootPublicFingerprint`, and `sampleIndex`;
- expand the remaining source-count multiset into a sorted list, shuffle it
  deterministically per sample, then split:
  - first `opponentHandCount` cards into hidden hand multiset;
  - next `opponentDeckCount` cards into hidden deck multiset;
- validate each sample independently.

Validation per sample:

- hand count equals `opponentHandCount`;
- deck count equals `opponentDeckCount`;
- hand + deck count equals required hidden count;
- no source count across hand + deck exceeds the remaining prior count after
  public known subtraction;
- no sampled source falls outside the prior;
- duplicate cards respect preset copy counts;
- no mutation of real `MatchState`.

For official starter suites, expected output should be:

- all roots `prior_available`;
- all roots `materializationStatus: "valid"` unless the implementation finds a
  real public-zone/prior contradiction;
- `sampleCountRequested: 8`;
- `sampleCountGenerated: 8`;
- `sampleCountValid: 8`;
- `sampleCountInvalid: 0`.

If that expected output is not true, stop and explain the exact invalid reason
distribution before adding behavior on top of it.
