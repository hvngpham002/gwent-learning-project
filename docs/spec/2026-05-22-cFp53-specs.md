## Problem Statement

cFp52 directly reproduced two cFp51 robust failure-mining candidates:

- Fixture A: 3 selected-play contradictions, 0 suppressed passes.
- Fixture B: 1 selected-play contradiction, 1 later suppressed pass.

These contradictions have the shape:

- round is 1
- selected move is `play_card`
- cFp43 base geometry is reached
- `roundOneOverinvestmentRecommended === true`
- the policy still selects the card instead of passing

The likely root is that `choosePlayingMove(...)` has more than one path that can return a selected `play_card`. The cFp43 pass gate is present in the round-investment path, but cFp52 shows at least one live selected-play path can still bypass it. Do not assume the existing `buildLegalHeuristicV1RoundInvestmentDecision(...)` call covers all selected-play returns.

## Goals

1. Repair the actual selected-play policy path so a `play_card` with active cFp43 round-one overinvestment recommendation becomes a pass, unless an existing tactical exception applies.
2. Preserve the existing cFp52 debug artifacts as historical before-fix evidence.
3. Add new cFp53 debug artifacts showing the same fixtures after the repair.
4. Keep explanation traces in parity with policy decisions.
5. Keep hidden-info-safe diagnostics and AI Lab metadata current.

## Behavior Requirements

### Required Pass Behavior

For `legal-heuristic-v1`, when selecting a playing-phase move, the final selected move must be converted to `pass` when all of these are true:

- a legal pass move exists
- `features.round === 1`
- `features.ownGems > 1`
- `features.opponentPassed === false`
- the candidate selected move is `play_card`
- the candidate spends a hand card
- `buildLegalHeuristicV1RoundInvestmentAnalysis(...)` for that exact candidate reports:
  - `roundOneOverinvestmentRecommended === true`
  - `roundOneOverinvestmentReason` is either `round_one_board_limit` or `round_one_low_future_hand`

This must apply to the exact selected `play_card`, not only to whatever `bestUsefulMove(...)` returns inside one helper.

### Required Exceptions

Do not convert the move to pass for these cases:

- selected move is `use_leader`
- selected move is already `pass`
- selected move is not `play_card`
- opponent has already passed
- AI is on last gem
- selected play has card advantage, including Spy-style draws
- selected play is a match-winning play
- selected play is a cheap single-move catch-up line already covered by cFp43 exceptions
- selected play has a cFp43 `roundOneOverinvestmentReason` beginning with `exception_`
- selected play is the only card in hand

Do not weaken or remove existing cFp31-cFp39 exception behavior.

## Implementation Guidance

Prefer adding one shared finalization helper instead of spreading duplicate checks through the policy. Suggested shape:

```ts
function shouldPassInsteadOfSelectedPlayForRoundOneOverinvestment(
  features: LegalHeuristicV1Features,
  candidate: EngineMove,
): boolean
```

The helper should:

1. Return false early for all required exceptions.
2. Build the same `handShape` and `roundInvestmentAnalysis` used by traces.
3. Return true only for the two positive cFp43 reasons:
   - `round_one_board_limit`
   - `round_one_low_future_hand`
4. Never call `scoreMove(...)` or `scorePlayMove(...)` recursively from an alternative scan path.

Use the helper at every `choosePlayingMove(...)` return site that can return a `play_card` before the fallback pass is considered. The fix should cover catch-up-selected cards, best-useful cards, and round-investment candidates without changing opponent-passed or last-gem handling.

Explanation parity matters. `explainLegalHeuristicV1Decision(...)` must describe the same move that `legalHeuristicPolicyV1.selectMove(...)` selects. If the policy passes because of cFp53, the trace reason should communicate the round-one overinvestment pass, for example:

```text
round-one overinvestment - preserve future hand
```

If an exception allows a play, the existing exception reason should remain visible.
