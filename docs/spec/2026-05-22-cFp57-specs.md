Date: 2026-05-22
Owner: coding agent

## Summary

cFp56 closes the current round-one overinvestment investigation with a clear
decision: do not continue hand-tuned `legal-heuristic-v1` round-one behavior
patches from the current failure-mining signal. The next useful work is
evaluation depth.

cFp46 added deterministic Glicko-style rating artifacts, and cFp47 added a
snapshot/comparison ledger. Since then, benchmark and rating artifacts have been
refreshed across later phases, but the rating ledger is still closer to a
baseline scaffold than a phase-to-phase tracking tool. cFp57 turns the rating
layer into a multi-period ledger by freezing the current committed `ratings/latest`
artifacts as named `cFp57` snapshots, comparing them against the established
baselines, and verifying that each named `cFp57` snapshot matches current
`latest`.

This phase is evaluation-only. It must not change AI behavior.

## Decision Note Requirements

The cFp57 decision note must include:

1. Source artifact table:
   - suite id;
   - baseline snapshot id;
   - cFp57 snapshot id;
   - source record count;
   - eligible record count;
   - ignored record count;
   - ratings hash.
2. Baseline-to-cFp57 rating movement table by suite:
   - entry count;
   - common/new/removed counts;
   - signal counts;
   - largest positive `deltaRating`;
   - largest negative `deltaRating`;
   - largest absolute `deltaOverCombinedRd`.
3. `cFp57-vs-latest` consistency table:
   - all suites must show zero deltas and `no_change` only.
4. Interpretation:
   - state whether any movement is strong enough to treat as directional under
     existing comparison semantics;
   - explicitly warn when movement is below uncertainty and should not drive a
     behavior patch by itself.
5. Next-step recommendation:
   - prefer a search-readiness/ISMCTS probe spec if ratings are stable or
     uncertain;
   - only recommend new heuristic tuning if a named rating comparison shows a
     clear directional regression tied to a narrow public failure cluster.

Do not quote hidden-information fields or raw private payloads.

## Hidden-Info Safety

Rating comparison artifacts and decision notes may contain:

- suite ids;
- policy ids;
- deck preset ids;
- faction ids;
- rating values;
- RD values;
- sample counts;
- hashes;
- comparison signals.

They must not contain:

- card names;
- source ids;
- runtime card ids;
- instance ids;
- action refs;
- raw move labels;
- private hand/deck/discard/order details;
- command logs;
- event logs;
- raw traces;
- `cardsById`;
- `finalState`;
- `unsafeDebugResults`.

Run a text scan over newly generated cFp57 rating/comparison artifacts and the
decision note for obvious hidden-info hazards. Document the scan in the report.
