# cFp25 Specs - Hidden-Info-Safe AI Decision Diagnostics

## Purpose

Add an explicit, hidden-info-safe diagnostic layer for product AI
playtests and benchmark investigations, without changing AI behavior.

cFp24 added `legal-heuristic-v1`; cFp24.1 made it selectable in the
product flow; cFp24.2 addressed the first obvious over-pass bug. The next
problem is observability. The normal battle log tells us what happened,
but not why the AI chose a move. Human playtests now produce ambiguous
questions like:

- did v1 refuse to pass because the score was unsafe, because the
  opponent had too many cards, because it was on its last gem, or because
  the best useful move score beat pass?
- did v1 use a weather-pulling leader because it thought the weather
  hurt the opponent, or because the weather valuation is too shallow?
- did v1 spend a high-value card because it was behind, or because it
  does not understand round sacrifice?

cFp25 should add a diagnostic trace contract that answers those
questions from public-safe fields. It should also add an explicit product
match export/copy action so future playtest review does not require the
user to manually paste the visible battle log.

This is a diagnostics phase, not a tuning phase.

## Current Context

`legal-heuristic-v1` is deterministic and legal-move-first. It has useful
helpers for feature building, move scoring, catch-up choice, pass safety,
mulligan confidence, prompt choice, leader scoring, weather/scorch
valuation, and card strategic value.

Today those internals are opaque at playtest time:

- the product battle log records command/event summaries;
- benchmark artifacts record match-level outcomes;
- `/ai-lab` shows static/read-only policy and benchmark status;
- no surface records why v1 chose a specific move;
- product playtest review still requires manual battle-log copying.

The user explicitly does **not** want every browser match to silently
write files or accumulate permanent local history. Diagnostics must be
explicitly copied or downloaded by the user.

## Non-Negotiable Boundaries

- Do not change engine rules, legal moves, scoring, prompts, command
  payload semantics, round resolution, or game-end behavior.
- Do not change `legal-heuristic-v1` decisions in this phase. The same
  `EnginePolicyInput` must still produce the same selected legal move as
  cFp24.2.
- Do not tune pass, mulligan, prompt, leader, weather, Scorch, Decoy, or
  card-value constants.
- Do not add search, simulation lookahead, MCTS, CFR, ML, ratings,
  Python tooling, self-play, or browser benchmark execution.
- Do not silently persist every product game to repo files,
  `localStorage`, IndexedDB, or a server.
- Do not expose hidden information in product diagnostics. No AI hidden
  hand card identities, AI deck identities/order, raw engine card
  instance ids, `cardsById`, raw `MatchState`, full command logs, full
  event payloads, or `seat_a:` / `seat_b:` instance prefixes may appear
  in the default exported diagnostic JSON.
- Product diagnostics may include public facts visible after they happen
  (played card labels from public event summaries, public score, public
  board/weather/discard summaries, hand counts, deck counts, gem counts,
  pass flags), but candidate alternatives from the AI's hidden hand must
  remain redacted.
- Do not make `/ai-lab` run benchmarks or import benchmark runtime
  modules. AI Lab history/summary visualization is a later phase unless
  this phase only updates static copy to mention the new export.
- New product, engine UI, benchmark, and AI files must not import
  `@/legacy/...`.

## Required Architecture

### Decision Trace Contract

Add a versioned, hidden-info-safe decision trace type for AI decisions.

Recommended location:

```text
src/game/ai/decisionTrace.ts
```

Suggested top-level shape:

```ts
export const AI_DECISION_TRACE_SCHEMA_VERSION = "ai-decision-trace-v1";

export interface AiDecisionTrace {
  readonly schemaVersion: typeof AI_DECISION_TRACE_SCHEMA_VERSION;
  readonly policyId: ProductAiPolicyId | "legal-first-v0" | string;
  readonly seatId: SeatId;
  readonly decisionIndex: number;
  readonly phase: string;
  readonly round: number;
  readonly publicState: AiDecisionPublicState;
  readonly passAnalysis: AiDecisionPassAnalysis | null;
  readonly selected: AiDecisionSelectedMove | null;
  readonly candidates: readonly AiDecisionCandidateSummary[];
  readonly reason: string;
}
```

The exact field names may differ, but the trace must include:

- policy id;
- acting seat id;
- decision index;
- phase and round;
- public score totals by seat;
- AI gem count and opponent gem count;
- AI hand count and opponent hand count;
- AI deck count and opponent deck count;
- AI discard count and opponent discard count;
- pass flags for both seats;
- whether pass was legal;
- if v1 has a pass threshold/pressure helper, the public values used by
  it: score delta, opponent hand pressure, required lead, whether
  voluntary pass was considered safe;
- if v1 has last-gem catch-up logic, the visible upper-bound value and
  whether surrender/pass was considered allowed;
- selected move kind and a public-safe selected move label;
- compact top candidate summaries with score/rank/reason data, redacted
  where the candidate originates from hidden AI hand cards.

### Candidate Redaction

Candidate summaries are diagnostic, but they must not leak hidden AI
hand identities to the human player.

Allowed:

- `kind`: `pass`, `play_card`, `use_leader`, `choose_prompt_option`,
  `choose_mulligan`, `resolve_round_end`, etc.
- numeric score/tempo/value estimates;
- public target type: row/weather/visible board card/no target;
- public target label when the target is public;
- public selected card label after the move has resolved and the card is
  visible through the public battle log;
- a redacted label such as `hidden hand play` for unplayed AI hand
  candidate alternatives.

Forbidden:

- hidden AI hand card names/source IDs for candidate alternatives;
- AI deck card names/source IDs/order;
- raw `sourceCardId` / engine instance ids;
- raw `moveId` if it embeds `seat_a:` / `seat_b:` or another engine
  instance prefix;
- raw `MatchState`, `cardsById`, `commandLog`, full event payloads, or
  unsafe debug dumps.

### V1 Explanation API

Add a pure v1 explanation function without changing selected moves.

Recommended shape:

```ts
export const explainLegalHeuristicV1Decision = (
  input: EnginePolicyInput,
  options?: { readonly decisionIndex?: number },
) => {
  // returns { move, trace }
};
```

Acceptance requirement:

- `legalHeuristicPolicyV1.selectMove(input)` and
  `explainLegalHeuristicV1Decision(input).move` must return the same
  move id/kind for all focused test cases.
- If implementation refactors `legalHeuristicPolicyV1.selectMove(...)`
  to call the explanation helper, add regression tests proving behavior
  parity.
- If v0 has no rich internals yet, v0 may emit a minimal trace wrapper,
  but v1 must emit the richer pass/candidate diagnostics.

Do not import raw catalog globals, deck presets, benchmark runtime, UI,
Redux, or legacy modules into v1 to build traces.

## Product Playtest Diagnostics

### In-Memory Trace Accumulation

Add a product-safe place to accumulate AI decision traces during an
engine-backed match.

Possible locations:

- Redux engine slice diagnostic field; or
- a UI-owned diagnostic accumulator keyed by match run id.

The chosen location must:

- reset when a new match/rematch starts;
- append one trace per AI policy decision;
- avoid timers;
- avoid localStorage/IndexedDB/server writes;
- not affect command execution order or selected moves;
- remain serializable if stored in Redux.

### Explicit Export/Copy Only

Add an explicit product control in the authentic match surface, near the
battle log / right rail / diagnostics area:

```text
copy diagnostics
download diagnostics
```

At least one of copy or download is required. Prefer implementing both if
the codebase already has safe browser helpers; otherwise implement copy
first and document download as deferred.

The export must be generated only when the user clicks the control. Do
not write a file automatically.

### Diagnostic Export Schema

Add a versioned product diagnostic export type.

Recommended location:

```text
src/components/gwent/matchDiagnostics.ts
```

Suggested schema id:

```text
gwent-product-playtest-diagnostics-v1
```

Required fields:

- schema version;
- generated timestamp or deterministic placeholder if tests need stable
  output;
- route/mode context where available;
- match seed;
- human deck preset id/name/faction when public;
- AI deck preset id/name/faction when public;
- AI policy id;
- current phase/round/result summary;
- public command/event summary equivalent to the visible battle log;
- AI decision traces;
- hidden-info safety scan result;
- warnings, if any trace field was redacted.

The command/event summary must remain summarized. Do not dump raw command
objects or raw `GameEvent` objects unless a hidden-info validator proves
they are safe, and default to summaries rather than raw payloads.

### Hidden-Info Validator

Add a reusable diagnostic redaction/validation helper.

It should reject or flag exported diagnostics containing obvious hazards:

```text
cardsById
finalState
commandLog
"hand"
"deck"
ownHand
opponentHand
seat_a:
seat_b:
unsafeDebugResults
```

Adjust the exact token list if existing safe artifact validators already
define it. Prefer reusing or extending existing hidden-info scan helpers
from simulation/benchmark export code rather than duplicating ad hoc
regexes.

If the diagnostic includes legitimate user-facing labels with words like
`deck` or `hand`, scan structured keys and raw instance/id patterns
carefully enough to avoid false positives. The report must explain the
chosen scan boundary.

## Benchmark Diagnostics

Add optional trace support for headless benchmark investigation, but do
not change default artifact size unexpectedly.

Required:

- benchmark/simulation code can request decision traces for AI policies;
- default existing benchmark commands may either keep current artifact
  shape or add a small documented trace summary, but any changed artifact
  diffs must be intentional and reported;
- if full per-decision traces are large, provide an opt-in flag or helper
  rather than bloating every default artifact;
- hidden-info artifact tests must cover trace-enabled output.

Recommended:

- add an opt-in benchmark artifact mode or helper such as
  `includeDecisionTraces: true`;
- add focused tests that build one traced benchmark record and scan it
  for hidden-info hazards;
- do not regenerate every large artifact unless necessary for acceptance.

## AI Lab Boundary

Do not turn `/ai-lab` into a live benchmark runner in this phase.

Allowed:

- static copy update that says playtest diagnostics can be copied from
  the match screen;
- optional link/path text to the diagnostic schema docs.

Deferred:

- AI Lab reading latest benchmark artifact summaries;
- AI Lab listing product playtest exports;
- AI Lab running or exporting benchmarks from the browser;
- AI Lab ratings/search/training controls.

## Required Tests

Add risk-scaled tests. At minimum:

### AI Policy Trace Tests

Update or add tests under `tests/game/`.

Required cases:

1. `explainLegalHeuristicV1Decision(input).move` matches
   `legalHeuristicPolicyV1.selectMove(input)` for:
   - mulligan;
   - prompt;
   - pass;
   - normal play card;
   - leader move;
   - round-end resolution if exposed to policy.
2. Last-gem pass-safety trace includes:
   - `ownGems`;
   - `opponentHandCount`;
   - score delta;
   - pressure/required-lead values;
   - selected non-pass move in the cFp24.2 regression shape.
3. Opponent-passed safe pass trace records pass as selected and explains
   opponent-passed/ahead.
4. Candidate summaries do not contain raw engine instance IDs or hidden
   AI card labels for unplayed hand alternatives.

### Product Diagnostic Tests

Add component/view-model/store tests as appropriate.

Required cases:

1. Product diagnostic export includes setup metadata, public command/event
   summaries, AI policy id, and decision traces.
2. Export resets between rematches/new matches.
3. Hidden-info scan passes for a representative product match diagnostic.
4. Export does not include raw command objects, raw event payloads,
   `cardsById`, raw `MatchState`, or `seat_a:` / `seat_b:` instance IDs.
5. Copy/download control is disabled or explains why when no diagnostics
   exist.

### Browser Smoke

Because this phase adds a product UI control, add Playwright coverage:

1. Start a product match with `legal-heuristic-v1`.
2. Let at least one AI decision occur.
3. Use the diagnostic copy/download control.
4. Assert the exported text/blob contains the schema id, policy id, and a
   decision trace.
5. Assert it does not contain obvious hidden-info hazards.

### Benchmark Tests

Add focused tests for opt-in trace artifacts:

1. Trace-enabled benchmark output is deterministic for a fixed seed.
2. Trace-enabled output passes the hidden-info hazard scan.
3. Existing benchmark output remains backward compatible unless the phase
   intentionally updates artifact schemas.

## Acceptance Criteria

- `legal-heuristic-v1` decisions are unchanged relative to cFp24.2 for
  focused policy parity tests.
- A hidden-info-safe v1 decision trace exists and explains pass/catch-up
  thresholds, selected move, top candidate summaries, and reason strings
  from public-safe data.
- Product matches can explicitly copy and/or download a diagnostic export
  after AI decisions occur.
- Product diagnostics are not silently persisted.
- Product diagnostic exports include setup metadata, public command/event
  summaries, AI policy id, AI decision traces, and a hidden-info safety
  scan result.
- Exported diagnostics do not include AI hidden hand identities, AI deck
  identities/order, raw engine instance ids, raw `MatchState`,
  `cardsById`, full command logs, full event payloads, or unsafe debug
  dumps.
- Benchmark code can optionally produce trace-enabled diagnostics without
  breaking existing default benchmark consumers.
- `/ai-lab` does not become a live runner or artifact browser in this
  phase.
- Docs and report are updated.

## Recommended Next Step After cFp25

Use one or two exported playtest diagnostics to decide the first v1.1
tuning target. Likely candidates:

- pass threshold refinement;
- weather/leader valuation;
- Scorch valuation;
- round-sacrifice/card-economy strategy;
- mechanics or competitive benchmark decks.

Do not start v2 search or ML training until v1 diagnostics establish
which failures require sequence planning rather than simple valuation
fixes.
