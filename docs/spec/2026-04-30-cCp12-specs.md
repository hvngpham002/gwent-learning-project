# Cluster C Phase 12 Specs - Linked Ability Invariant Audit And Regression Coverage

## Intent

Audit and harden the catalog/engine boundary for every card effect that depends on `linkedSourceIds`, generated side-deck cards, or directional summon groups.

This phase exists because the earlier rules audit verified the general `linkedSourceIds` mechanism and the common forward path, but missed the reverse Gaunter case:

- `Gaunter O'Dimm` should Muster `Gaunter O'Dimm: Darkness`.
- `Gaunter O'Dimm: Darkness` should Muster other `Darkness` copies only.
- `Darkness` must not summon base `Gaunter O'Dimm`.

The fix now exists in commits `b195da7` and `59ceacf`, but the audit process needs a stronger invariant suite so this class of mistake does not recur.

This is not a new effect-implementation phase. It is an audit plus regression-coverage phase.

## Linked Effect Families

Audit every current catalog source that has one of these abilities or uses `linkedSourceIds`:

- `muster`
- `muster_roach`
- `avenger`
- `berserker`
- `summon` if present, even if still deferred
- any card with non-empty `linkedSourceIds`
- any card tagged `side_deck_only`

For every such source, classify:

- source ID;
- card name;
- faction;
- ability/abilities that consume `linkedSourceIds`;
- linked source IDs;
- whether the link is:
  - `same-source-copy`
  - `same-name-group`
  - `one-way-base-to-variant`
  - `one-way-variant-to-same-variant`
  - `one-way-side-deck-replacement`
  - `multi-card-named-group`
  - `ambiguous`
  - `deferred`
- whether linked cards live in main deck, side deck, or both;
- whether each linked card is allowed in a main deck;
- whether the current starter/local preset has enough copies to exercise it;
- current test coverage status.

## Explicit Expected Directionality

Do not infer behavior from substring matching alone.

For cCp12, these expectations are already confirmed and should receive active tests:

### Gaunter / Darkness

- `neutral.gaunter-odimm`:
  - ability: `muster`
  - expected targets: `neutral.gaunter-odimm-darkness`
  - direction: one-way base-to-variant
  - should pull Darkness copies from hand and deck
- `neutral.gaunter-odimm-darkness`:
  - ability: `muster`
  - expected targets: `neutral.gaunter-odimm-darkness`
  - direction: one-way variant-to-same-variant
  - should pull other Darkness copies from hand and deck
  - must not pull `neutral.gaunter-odimm`

### Roach Links

- `neutral.geralt-of-rivia` and `neutral.cirilla-fiona-elen-riannon`:
  - ability: `muster_roach`
  - expected target: `neutral.roach`
  - one-way hero-to-Roach
  - Roach must not reciprocally summon either hero

### Cerys

- `skellige.cerys`:
  - ability: `muster`
  - expected target: `skellige.clan-drummond-shield-maiden`
  - one-way named hero-to-group
  - Shield Maidens do not summon Cerys

### Avenger

- `neutral.cow` -> `neutral.bovine-defense-force`
- `skellige.kambi` -> `skellige.hemdall`

Both are one-way side-deck replacements:

- replacement comes from controlling side deck;
- replacement is tagged `side_deck_only`;
- replacement should not be allowed in the main deck;
- source remains subject to its normal movement destination.

### Berserker

- `skellige.berserker` -> `skellige.vildkaarl`
- `skellige.young-berserker` -> `skellige.young-vildkaarl`

Both are one-way side-deck transformations:

- replacement comes from controlling side deck;
- replacement is tagged `side_deck_only`;
- source moves to `removed_from_game`;
- replacement should not be allowed in the main deck.

### Same-Source Copy Muster

For Muster sources whose `linkedSourceIds` include their own source ID, active tests should prove they pull other copies of the same source from hand/deck and not from board/discard.

Known families include:

- Arachas;
- Nekker;
- Ghoul;
- Havekar Smuggler;
- Dwarven Skirmisher;
- Elven Skirmisher.

### Multi-Card Named Groups

For groups where distinct source IDs are intentionally linked to each other, active tests should prove the intended directionality.

Known families include:

- Crones;
- Vampires;
- Arachas Behemoth / Arachas relationship.

Important: do not assume Arachas Behemoth requires full symmetry. Determine current intended direction from local card text, `docs/gwent-rules.md`, and current catalog descriptions. If it remains ambiguous, document it as an ambiguous-rule note and add a `todo` test, not an active failing test.

### Catalog Invariant Tests

Add active tests that assert:

- every `linkedSourceIds` entry resolves to a current catalog source;
- every `side_deck_only` source is linked by at least one current source unless explicitly allowlisted with a comment;
- every `berserker` source has exactly one linked side-deck-only replacement;
- every `avenger` source has exactly one linked side-deck-only replacement;
- `muster_roach` sources link to `neutral.roach`;
- `neutral.gaunter-odimm-darkness` links only to itself, not to base Gaunter;
- `neutral.gaunter-odimm` links to Darkness;
- Cerys links to Shield Maiden;
- no source relies on string-prefix name matching in the pure engine catalog path.

These should be pure catalog tests with no React/browser involvement.

### Engine Regression Tests

Add active tests that assert:

- playing `neutral.gaunter-odimm` pulls Darkness from hand and deck;
- playing `neutral.gaunter-odimm-darkness` pulls other Darkness copies but not base Gaunter;
- playing Cerys pulls Shield Maidens from hand/deck;
- playing a same-source Muster card pulls matching copies from hand/deck and excludes board/discard copies;
- playing a multi-card group source such as a Crone pulls the intended other Crones;
- Avenger and Berserker replacement links still resolve from side deck after the cCp11/cCp9 implementations.

Avoid brittle full-game UI setup. Use pure engine setup helpers.

### Legacy Regression Tests

Because legacy default route still exists, keep `src/hooks/useGameLogic.ts` covered until the legacy path is retired.

Add or maintain tests that assert:

- base Gaunter pulls Darkness;
- Darkness pulls only other Darkness copies;
- Darkness does not pull base Gaunter.

If the legacy helper cannot represent a catalog-specific linked group beyond name variants, document the limitation. Do not expand legacy helper into a full catalog resolver unless a separate spec asks for it.

### Todo / Placeholder Tests

For ambiguous or deferred link behavior, add `it.todo` tests or report-only notes rather than active failing tests.

Candidates:

- Arachas Behemoth directionality if still ambiguous;
- future `summon` side-deck behavior if the implementation remains deferred;
- placeholder leader tutor/restore effects if they later use linked source IDs.

## Severity Guide

- `P0`: linked effect can crash/lock a match, corrupt card zones, or expose hidden information.
- `P1`: official/current playable deck has a linked effect that resolves to the wrong card, wrong side deck, or wrong zone.
- `P2`: linked effect is wrong in an edge case, an official starter, or a currently selectable but uncommon path.
- `P3`: missing regression coverage, unclear docs, ambiguous directionality, or future-risk note.

## Acceptance Criteria

cCp12 is complete when:

- every current `linkedSourceIds` source is represented in the report matrix;
- every current `side_deck_only` source is represented in the report matrix;
- active catalog invariant tests cover link resolution, side-deck-only replacement links, and confirmed directionality;
- active engine regression tests cover Gaunter/Darkness both directions, Cerys, at least one same-source copy Muster, at least one multi-card group Muster, Avenger replacement, and Berserker replacement;
- ambiguous cases are documented with severity and todo tests or report-only notes;
- no production behavior changes are made unless explicitly justified as a blocker;
- `docs/PROJECT_STATE.md` is updated;
- report exists at `audit/reports/2026-04-30-cCp12-report.md`;
- required checks pass.
