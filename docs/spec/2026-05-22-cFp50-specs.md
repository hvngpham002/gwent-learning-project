# cFp50 Specs: Round-One Overinvestment Guard-State Telemetry

## Summary

`cFp50` is an evaluation-infrastructure phase. It adds hidden-info-safe
guard-state telemetry to failure-mining artifacts so the next casebook can
explain the remaining `round_one_overinvestment` findings from the robust
starter matrix.

This phase must not change `legal-heuristic-v1` behavior. It should expose
public cFp43 guard-state summaries for existing round-one overinvestment
findings, regenerate the failure-mining artifacts that depend on that evidence,
and update AI Lab metadata so the product research surface stays current.

The immediate problem from cFp49:

- Robust `round_one_overinvestment` is durable and loss-correlated:
  71 findings, 69 losses, 2 draws.
- The current finding only records aggregate round-1 play count and match
  outcome.
- The current artifact cannot tell whether cFp43 missed the board/hand
  thresholds, hit a tactical exception, intentionally passed and was suppressed,
  or simply lacked the right per-decision evidence.

cFp50 should make that distinction possible without leaking hidden information.

## Research Grounding

cFp42/cFp44/cFp45/cFp49 all reached the same conclusion: aggregate public
failure rows are enough to identify round-one overinvestment as suspicious, but
not enough to decide a safe behavior patch.

cFp50 is therefore the missing telemetry layer. It should not tune constants or
add heuristics. It should record public guard-state summaries at the same
artifact boundary that already feeds failure mining.

Interpretation rules:

- Evidence must be public and bucketed/count-based.
- Do not write card names, source ids, runtime card instance ids, private hand
  arrays, deck order, raw `MatchState`, command logs, or raw decision traces.
- New fields must be deterministic across repeated runs.
- New fields must be directly explainable from existing
  `AiDecisionRoundInvestmentAnalysis` and selected-move public metadata.

## Required Implementation Details

### 1. Round-One Guard Telemetry Helper

In `src/game/benchmark/failureMining.ts`, add a small pure helper for
round-one overinvestment findings.

Suggested name:

```ts
buildRoundOneGuardTelemetry(...)
```

It should inspect only `result.decisionTraces` for the same `seatId` as the
finding.

Filter traces to:

- `trace.policyId === "legal-heuristic-v1"`;
- `trace.seatId === seatId`;
- `trace.phase === "playing"`;
- `trace.round === 1`;
- `trace.roundInvestmentAnalysis` exists.

Then separately count selected play-card traces:

- `trace.selected?.kind === "play_card"`.

Use only fields already present in `AiDecisionRoundInvestmentAnalysis`:

- `ownBoardCardCount`;
- `roundOneBoardAfterSelectedMove`;
- `currentRoundHandCount`;
- `estimatedHandCountAfterSelectedMove`;
- `selectedMoveSpendsHandCard`;
- `selectedMoveIsCardAdvantage`;
- `selectedMoveWouldLeaveNoPositiveUnitMove`;
- `selectedMoveWouldLeaveNoUnitTempoCard`;
- `scoreDelta`;
- `catchUpStatus`;
- `roundResourcePressure`;
- `resourceExhaustionRecommended`;
- `resourceExhaustionReason`;
- `roundOneOverinvestmentRecommended`;
- `roundOneOverinvestmentReason`;
- `recommendation`.

Do not copy the whole `roundInvestmentAnalysis` object into evidence.

### 2. Evidence Fields

Every `round_one_overinvestment` finding must include these scalar fields:

```ts
roundOneGuardTelemetryAvailable: boolean
roundOneTraceDecisionCount: number
roundOnePlayCardTraceCount: number
roundOneGuardBaseGeometryCount: number
roundOneBoardFloorReachedCount: number
roundOneHandCapReachedCount: number
roundOneRecommendedCount: number
roundOneSuppressedPassCount: number
roundOneMaxBoardAfterSelectedMove: number | null
roundOneMinHandAfterSelectedMove: number | null
roundOneFirstBaseGeometryDecisionIndex: number | null
roundOneFirstRecommendedDecisionIndex: number | null
roundOneScoreDeltaBehindCount: number
roundOneScoreDeltaTiedCount: number
roundOneScoreDeltaAheadCount: number
```

Reason counts:

```ts
roundOneReasonNoneCount: number
roundOneReasonBoardLimitCount: number
roundOneReasonLowFutureHandCount: number
roundOneExceptionNotRoundOneCount: number
roundOneExceptionLastGemCount: number
roundOneExceptionOpponentPassedCount: number
roundOneExceptionNonPlayCardCount: number
roundOneExceptionCardAdvantageCount: number
roundOneExceptionMatchWinningPlayCount: number
roundOneExceptionSingleMoveCatchUpCount: number
roundOneExceptionSingleCardHandCount: number
```

Additional tactical counts:

```ts
roundOneSelectedCardAdvantageCount: number
roundOneSelectedWouldLeaveNoPositiveUnitMoveCount: number
roundOneSelectedWouldLeaveNoUnitTempoCardCount: number
roundOneCatchUpSingleMoveCount: number
roundOneCatchUpImpossibleCount: number
roundOneRecommendationPreserveFutureHandCount: number
roundOneRecommendationSacrificeRoundCount: number
roundOneRecommendationContinueCount: number
```

Definitions:

- `roundOneGuardBaseGeometryCount`: play-card trace count where
  `roundOneBoardAfterSelectedMove >= ROUND_ONE_OVERINVESTMENT_BOARD_AFTER_FLOOR`
  and
  `estimatedHandCountAfterSelectedMove <= ROUND_ONE_OVERINVESTMENT_HAND_AFTER_CAP`.
- `roundOneBoardFloorReachedCount`: play-card trace count where board floor is
  reached.
- `roundOneHandCapReachedCount`: play-card trace count where hand cap is
  reached.
- `roundOneRecommendedCount`: play-card trace count where
  `roundOneOverinvestmentRecommended === true`.
- `roundOneSuppressedPassCount`: pass trace count where
  `roundOneOverinvestmentRecommended === true`. This should usually explain
  intentional cFp43 passes that are suppressed from suspicious-pass findings.
- `roundOneFirstBaseGeometryDecisionIndex`: first decision index among play-card
  traces meeting base geometry, else `null`.
- `roundOneFirstRecommendedDecisionIndex`: first decision index among play-card
  traces with `roundOneOverinvestmentRecommended === true`, else `null`.

If no trace data exists for the record/seat, set:

```ts
roundOneGuardTelemetryAvailable: false
roundOneTraceDecisionCount: 0
roundOnePlayCardTraceCount: 0
...
null for min/max/first-index fields
0 for all count fields
```

### 6. Hidden-Info Safety

The new telemetry fields must be scalar `number | boolean | null` values or
existing safe enum strings already present in decision-trace public analysis.

Do not include:

- card names;
- source ids;
- runtime card instance ids;
- move ids;
- action refs;
- hand/deck/discard arrays;
- full trace objects;
- command/event logs.

Update tests so the artifact scanner still fails on existing hazards and passes
for the new telemetry fields.

### 7. Tests

Update `tests/game/benchmarkFailureMining.test.ts`.

Required coverage:

1. A synthetic round-one overinvestment finding with decision traces includes
   `roundOneGuardTelemetryAvailable: true`.
2. The same finding exposes board/hand geometry counts:
   - base geometry count;
   - board floor reached count;
   - hand cap reached count;
   - recommended count;
   - first base-geometry decision index;
   - first recommended decision index.
3. Reason-count coverage proves at least:
   - `none`;
   - `round_one_board_limit`;
   - `exception_card_advantage`;
   - `exception_single_move_catch_up`.
4. Suppressed-pass count coverage: a pass trace with
   `roundOneOverinvestmentRecommended === true` increments
   `roundOneSuppressedPassCount`.
5. Missing trace data produces `roundOneGuardTelemetryAvailable: false` and
   zero/null telemetry fields.
6. Serialized artifacts remain hidden-info safe and do not contain raw private
   or runtime-id hazards.
7. Finding counts and tuning queue shape remain deterministic for the synthetic
   fixture.

Update `tests/components/gwent/authenticAiLabViewModel.test.ts` for cFp50
metadata.
