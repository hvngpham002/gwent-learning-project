# Implementation Spec: Cluster D, Phase 1 - Redux Engine Adapter Foundation

## Goal

Add a Redux adapter around the pure engine without switching the live UI over yet. Cluster C now owns match rules, legal moves, scoring, abilities, round resolution, and game end. Cluster D Phase 1 should make Redux capable of storing an engine `MatchState`, dispatching engine commands, recording command/event history, exposing engine selectors, and enforcing a UI-safe action lock.

This phase should create the migration bridge. React and the legacy Redux game slice may continue to drive the current playable screen until later phases, but the new adapter must prove that Redux can host the engine without reimplementing rules.

## Architecture Position

The current app still has:

- legacy `src/store/slices/gameSlice.ts` with rule logic and `Math.random()` in reducers;
- legacy thunks in `src/store/thunks/gameThunks.ts` that directly mutate game concepts;
- legacy selectors in `src/store/selectors/gameSelectors.ts` that recompute scores and game winners;
- `ReduxGameManager.tsx` orchestration that uses timers and pre-decrement life checks.

The pure engine now has:

- `startMatch` and `executeCommand`;
- normalized `MatchState`;
- legal moves;
- prompt state;
- scoring;
- explicit `ResolveRoundEnd`;
- serializable events and round history.

Phase 1 of Cluster D should add the engine-backed Redux lane beside the legacy lane. Do not remove or rewrite the current playable UI in this phase.

## Scope

1. Add an engine Redux slice.
   - Suggested file: `src/store/slices/engineSlice.ts`.
   - Register it in `src/store/index.ts` as `engine`.
   - Keep the existing `game` and `ui` reducers registered and behavior-compatible.
   - Store only serializable data.
   - Suggested state:
     ```ts
     interface EngineAdapterState {
       match: MatchState | null;
       status: "idle" | "ready" | "resolving" | "awaiting_prompt" | "animating" | "ai_thinking" | "game_end" | "error";
       lock: EngineActionLock | null;
       seatMap: { human: SeatId; ai: SeatId };
       commandHistory: EngineCommandRecord[];
       eventLog: GameEvent[];
       lastTransactionEvents: GameEvent[];
       lastError: EngineAdapterError | null;
       selectedMoveId: string | null;
       selectedCardId: CardInstanceId | null;
     }
     ```
   - The exact names can differ, but the state must cleanly separate engine state from UI-only selection and lock state.

2. Define adapter record types.
   - Add serializable records for command history and errors.
   - Suggested command record:
     ```ts
     interface EngineCommandRecord {
       sequence: number;
       command: Exclude<EngineCommand, { type: "StartMatch" }>;
       status: "applied" | "rejected";
       eventCount: number;
       error?: EngineAdapterError;
     }
     ```
   - Do not store `Error` instances in Redux. Store plain `{ code, message, details? }`.
   - Do not store `Map`, `Set`, functions, catalog source objects, or class instances in Redux.

3. Add engine thunks or action creators.
   - Suggested file: `src/store/thunks/engineThunks.ts`.
   - Add a thunk to start an engine match from catalog presets:
     - default to Northern Realms vs Nilfgaard current presets;
     - accept optional seed, seat config, player IDs, and controller kinds;
     - use `currentCatalogCards`, `currentCatalogLeaders`, `currentNorthernRealmsDeckPreset`, and `currentNilfgaardDeckPreset`.
   - Add a thunk to dispatch stateful engine commands:
     - reads current `state.engine.match`;
     - calls `executeCommand({ state: match, command, catalogCards: currentCatalogCards, catalogLeaders: currentCatalogLeaders })`;
     - applies the returned `state` and events to the engine slice;
     - records command history;
     - catches `EngineRuleError` and stores a serializable adapter error without mutating the match.
   - Add a focused helper thunk for `ResolveRoundEnd`, or make it a normal command passed through the same dispatch path.
   - Do not dispatch legacy `gameSlice` actions from these thunks.

4. Add action lock semantics.
   - The adapter should expose a single lock field that future UI/AI code can honor.
   - Suggested lock shape:
     ```ts
     interface EngineActionLock {
       kind: "resolving_command" | "prompt" | "animation" | "ai_thinking";
       owner?: SeatId;
       promptId?: string;
       sinceSequence: number;
     }
     ```
   - Lock policy:
     - while a command thunk is pending, status is `resolving` and ordinary new commands should reject or be ignored by the thunk with a stored adapter error;
     - if `match.pendingPrompt` exists after a transaction, status is `awaiting_prompt` and lock kind is `prompt`;
     - if `match.phase === "game_end"`, status is `game_end`;
     - otherwise status is `ready`;
     - expose actions for setting and clearing presentation locks such as `animation` and `ai_thinking`, but do not use timers in this phase.
   - This targets the legacy class where pass, play, AI, and modal choices could interleave.

5. Add engine selectors.
   - Suggested file: `src/store/selectors/engineSelectors.ts`.
   - Expose at least:
     - `selectEngineMatch`;
     - `selectEngineStatus`;
     - `selectEngineLock`;
     - `selectEnginePrompt`;
     - `selectEngineCurrentSeat`;
     - `selectEngineHumanSeat`;
     - `selectEngineAiSeat`;
     - `selectEngineLegalMovesForSeat`;
     - `selectEngineLegalMovesForHuman`;
     - `selectEngineCanHumanAct`;
     - `selectEngineCanAiAct`;
     - `selectEngineScoreBreakdown`;
     - `selectEngineRoundHistory`;
     - `selectEngineGameWinner`;
     - `selectEngineLastError`;
   - Use `getLegalMoves` for legal actions.
   - Use `calculateScores` for score selectors.
   - Do not use `src/utils/gameHelpers.ts` from engine selectors.
   - Selectors should return stable, serializable view data where practical.

6. Add minimal view-model selectors for future UI migration.
   - Add selectors that convert normalized engine zones into UI-friendly lists without changing engine state.
   - Suggested outputs:
     - human hand card view models;
     - AI hand count and optionally AI hand cards only in debug/test selectors;
     - board rows by seat and row;
     - weather cards;
     - discard counts;
     - deck counts;
     - leader status.
   - Card view models should include `instanceId`, `sourceId`, display name, kind, faction, rows, abilities, printed strength, owner, controller, and zone.
   - Hidden-info discipline:
     - the default human view should not expose AI hand card details beyond count;
     - a debug selector may expose full state if named clearly.

7. Add system-command support for round end.
   - The adapter must be able to dispatch `ResolveRoundEnd` through the same command path.
   - If `getLegalMoves` returns a `resolve_round_end` system move, expose it via selectors.
   - Do not use `setTimeout` to resolve a round.
   - Do not compute round winner, gem loss, game winner, or cleanup in Redux.
   - Do not auto-start a new game after `game_end`.

8. Add prompt support.
   - Prompt state should come from `match.pendingPrompt`.
   - `selectEnginePrompt` should return the prompt plus options needed by UI.
   - `ChoosePromptOption` must dispatch through the same engine command thunk.
   - `selectEngineCanHumanAct` should be false during a prompt unless the prompt belongs to the human seat, in which case only prompt-choice moves should be available.
   - Do not preserve legacy medic-chain UI state as authoritative for engine prompts.

9. Add initialization policy.
   - Provide a default start helper that can make a current playable match with incomplete catalog:
     - seat A: human, Northern Realms current preset;
     - seat B: AI, Nilfgaard current preset unless the implementer documents why NR vs NR is temporarily safer for current UI parity;
     - deterministic seed default such as `Date.now()` is acceptable for live startup, but tests must pass explicit seeds.
   - Store the chosen seed in `match.rng.seed` and expose it through selectors.
   - Do not use `Math.random()` in adapter reducers or thunks except for constructing an optional seed string before `startMatch`. Prefer caller-provided seed.

10. Keep Redux serializable checks healthy.
    - Update `src/store/index.ts` only as needed.
    - The new engine lane should not require broad serializable-check disables.
    - Existing legacy ignores may remain for now.
    - If an ignore is added, document why in the report and keep it narrowly scoped.

11. Add tests.
    - Add focused tests under `tests/store` or `tests/game`.
    - Suggested file: `tests/store/engineAdapter.test.ts`.
    - Tests may configure a store with the real reducer or a small test store.
    - Tests should not mount React components.

12. Create the required implementation report:
    - `audit/reports/2026-04-25-cDp1-report.md`

## Out Of Scope

- Do not switch `ReduxGameManager.tsx` to the engine yet.
- Do not delete or rewrite legacy `gameSlice`, `gameThunks`, `gameSelectors`, `useReduxAI`, or legacy card types.
- Do not fix the legacy auto-new-game timer in the live UI in this phase, except by documenting that the engine adapter avoids it.
- Do not build a full human play UI over engine legal moves.
- Do not migrate AI policy to engine legal moves.
- Do not build Deck Builder or Card Studio.
- Do not add networking, PvP, AI-vs-AI simulation, or ML export.
- Do not introduce persistence beyond optional seed/command history held in Redux state.

## Acceptance Criteria

- Store has a registered `engine` reducer with serializable state.
- A thunk/action can start a deterministic engine match from current catalog presets.
- A thunk/action can apply stateful engine commands and append command/event history.
- Invalid engine commands produce a serializable adapter error and leave `match` unchanged.
- The adapter exposes legal moves from `getLegalMoves`.
- The adapter exposes score breakdown from `calculateScores`.
- Prompt state and prompt-only legal moves are exposed from engine state.
- `selectEngineCanHumanAct` respects phase, turn, lock, pass state, and prompt ownership.
- `ResolveRoundEnd` can be dispatched through the adapter, and Redux does not recompute winner/gem/game-end logic.
- No new adapter code imports `src/utils/gameHelpers.ts`.
- No new adapter reducer or thunk calls `Math.random()` for rules or transitions.
- Existing live UI behavior is not intentionally changed.
- `npm test` passes.
- `npm run build` passes.

## Required Tests

At minimum, cover:

- `startEngineMatch` creates a non-null engine match with the requested seed and expected seat map.
- Starting a second engine match resets command history, event log, selection, prompt, and errors.
- Dispatching `ChooseMulligan` through the adapter updates match state, appends command history, and appends events.
- Dispatching an illegal command stores a plain adapter error and does not mutate the previous match.
- Legal move selectors return only prompt choices while `match.pendingPrompt` exists.
- `selectEngineCanHumanAct` is:
  - false with no match;
  - false while status is `resolving`;
  - false when it is not the human seat's turn;
  - false after the human seat has passed;
  - false during another seat's prompt;
  - true or prompt-choice-enabled during the human seat's prompt.
- Score selector uses engine scoring by asserting a simple played-card total.
- `ResolveRoundEnd` dispatch transitions through the engine and records `round_resolved` events without Redux score/game-end recomputation.
- View-model selectors do not expose AI hand card details in the default human view.
- Redux state remains JSON-serializable for the engine lane.

## Notes For The Coding Instance

- Treat Cluster C as authoritative. If Redux seems to need rule data, first ask whether a selector should derive it from engine state instead.
- Keep this phase thin. The goal is a reliable bridge, not a new parallel rules implementation.
- Prefer adding `engineSlice`, `engineThunks`, and `engineSelectors` over expanding the legacy `gameSlice`.
- Do not route engine command results into legacy `gameSlice`; that creates two truths.
- Use explicit seeds in tests so failures are reproducible.
- Be careful with `createAsyncThunk` error serialization. Store plain engine adapter errors, not thrown `Error` objects.
