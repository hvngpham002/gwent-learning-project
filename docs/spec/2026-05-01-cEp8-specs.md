# Implementation Spec: Cluster E, Phase 8 - Weather Leader Choice UI

## Intent

Implement the authentic match UI for leaders that expose more than one legal
`use_leader` move, starting with Eredin: King of the Wild Hunt
(`play_any_weather`).

cCp14 already implemented the engine rule: `play_any_weather` emits one legal
`use_leader` move per eligible weather source currently in the acting player's
deck, using the hidden-info-safe target shape:

```ts
{ kind: "deck_card_source"; seatId; sourceId }
```

The current authentic match screen collects all legal leader moves but collapses
them to `leaderMoves[0]`. That is acceptable for no-target leaders and
single-source weather leaders, but it makes `play_any_weather` fire the first
engine-sorted weather target without user choice. This phase must close that UI
gap without changing the engine contract.

## Hard Scope Boundary

Allowed changes:

- Authentic match UI and view-model helpers for choosing among multiple legal
  leader moves.
- Shared UI helper updates only if needed to describe `use_leader` moves.
- Focused CSS for a compact authentic leader-choice menu/popover/list.
- Focused unit tests and one browser smoke path for the real `play_any_weather`
  flow.
- `docs/PROJECT_STATE.md`, relevant UI/browser-smoke docs if behavior is
  documented there, and the cEp8 report.

Do not change:

- Pure engine legal move generation.

- `deck_card_source` target shape.

- Eredin/Emhyr tutor/restore placeholder leader rules.
- Animations beyond a simple open/close choice affordance.

## Current Gap To Fix

As of cCp17, `AuthenticMatchScreen.tsx` computes:

```ts
const leaderMoves = useMemo(() => getUseLeaderMoves(humanMoves), [humanMoves]);
const leaderMove = leaderMoves[0] ?? null;
```

and dispatches:

```ts
dispatch(dispatchEngineCommand({ type: "UseLeader", seatId: humanSeat, target: leaderMove.target }));
```

That means a leader with multiple legal `use_leader` moves loses the user's
choice. cEp8 must make the UI preserve and dispatch the exact selected legal
move.

## Required Behavior

### 1. Build A Leader Action View Model

Add pure helper coverage in `src/components/gwent/matchViewModel.ts` or a small
nearby helper file. Use existing `getUseLeaderMoves`, `describeLeaderMove`, and
`commandForMove` patterns where they fit, but the product UI should not be
forced to use the diagnostic shell wording.

The helper should classify legal leader moves into a product-friendly shape:

- `"none"`: no legal leader move is currently available.
- `"single"`: exactly one legal leader move is available.
- `"choice"`: more than one legal leader move is available.

For `"choice"`, expose ordered options that preserve the engine's legal-move
order. Each option must carry:

- `moveId`;
- the original `UseLeaderMove`;
- a compact label;
- optional metadata useful for rendering, such as `sourceId`,
  `targetCardName`, and `ability`.

Label requirements:

- Prefer `move.metadata.targetCardName`.
- Fall back to `move.metadata.targetLabel`.
- Fall back to `move.target.sourceId` for `deck_card_source`.
- Fall back to `move.label`.
- Do not expose raw deck card instance IDs.
- Do not invent options from the catalog. Only show legal moves emitted by the
  engine.

Expected labels for current weather sources are:

- `Biting Frost`
- `Impenetrable Fog`
- `Torrential Rain`
- `Skellige Storm`

The helper should be generic enough to support future multi-target leaders, but
do not implement future leader rules in this phase.

### 2. Keep Single-Move Leaders Direct

No-target and single-target leaders should remain a direct action button:

- Foltest Lord Commander (`clear_weather`)
- Foltest row-Scorch leaders (`scorch_range`, `scorch_siege`)
- single-weather leaders (`play_frost`, `play_fog`, `play_rain`) when exactly
  one legal deck source is available

For these, clicking `use leader` should dispatch the single legal move exactly
as before.

If a leader emits zero legal moves, the action remains disabled.

### 3. Add Product Choice UI For Multiple Moves

When multiple leader moves are legal, the authentic match action panel should
show a compact choice affordance near the existing leader action.

Recommended behavior:

- Main button text: `choose weather` or `use leader`.
- Clicking opens a menu/list/popover of legal options.
- Each option is a button using the existing authentic button language.
- Selecting an option dispatches the exact corresponding `UseLeader` command
  target.
- The menu closes after a successful click.
- The menu closes when the user clicks outside it or presses Escape.
- The menu cannot open while the leader action is disabled.
- If legal moves change, close any stale open menu.

Required test IDs:

- `authentic-leader-action`
- `authentic-leader-choice-menu`
- `authentic-leader-choice-option`

Use additional test IDs if helpful, but do not rename existing stable test IDs
unless the tests are updated and the report calls it out.

Accessibility requirements:

- The trigger must expose `aria-expanded` when it controls a menu.
- The trigger should use `aria-controls` while the menu exists.
- The menu should have an accessible label.
- Options must be keyboard-focusable buttons.
- Escape should close the menu without dispatching.

Visual requirements:

- Use existing `.authentic-button` styling and the current match panel visual
  language.
- Keep text compact and mobile-safe.
- Do not add decorative card-heavy UI here; this is an action picker, not a new
  screen.
- Avoid layout jumps in the right action rail.

### 4. Dispatch The Exact Legal Move

Do not reconstruct `deck_card_source` targets from names, source IDs, catalog
queries, or menu labels.

On option click, find the selected `UseLeaderMove` by `moveId` and dispatch:

```ts
dispatch(
  dispatchEngineCommand({
    type: "UseLeader",
    seatId: move.seatId,
    target: move.target,
  }),
);
```

For single-action leaders, prefer the same selected-move path so direct and
choice actions cannot diverge.

### 5. Hidden-Info Boundary

This UI may display the selected human leader's legal own-deck weather source
labels because cCp14 intentionally exposes catalog source IDs and target names
through legal moves.

Do not display:

- raw deck instance IDs;
- raw engine card instance IDs in default match text;
- opponent deck contents;
- opponent hand contents;
- any non-legal weather options inferred from catalog state.

The existing hidden-info smoke pattern should still pass:

```txt
instanceId|sourceId|seat_b:\d{3}:|seat_a:\d{3}:
```

If source IDs must appear inside developer-only inspect modals, keep that
behavior unchanged and do not surface source IDs in the normal leader-choice
menu.

## Required Tests

### Unit Tests

Add or extend focused tests in `tests/components/gwent/authenticMatchViewModel.test.ts`
or a nearby helper test:

1. Multiple `play_any_weather` leader moves produce a `"choice"` view model
   preserving engine order.
2. Option labels prefer `metadata.targetCardName`.
3. Missing `targetCardName` falls back safely without raw instance IDs.
4. A single no-target leader move produces a `"single"` action.
5. A single `deck_card_source` leader move produces a `"single"` action.
6. No legal leader moves produce `"none"`.
7. The selected option can be converted to the exact `UseLeader` command target
   without rebuilding the target manually.

If the helper belongs in `src/components/game/engine/playMoveHelpers.ts`, update
`tests/components/playMoveHelpers.test.ts` instead or as well.

### Browser Smoke

Add one Playwright smoke in `tests/e2e/engine-shell-smoke.spec.ts` that exercises
the product route with a real engine legal-move path.

Recommended route setup:

- Use `/?engine=1&ui=authentic` pre-game or direct match flow.
- Start a human Monsters deck with leader
  `monsters.eredin-king-of-the-wild-hunt`.
- Ensure the human deck has at least two distinct eligible weather source IDs
  still in deck after mulligan. The official Monsters starter already includes
  Frost and Fog; a localStorage seeded local deck with additional Rain/Skellige
  Storm copies is also acceptable if it makes the smoke deterministic.
- Use and document a deterministic seed that leaves at least two distinct
  eligible weather source IDs in deck after the initial draw.

Smoke assertions:

1. Confirm mulligan and enter match.
2. Human leader action is enabled on a human turn.
3. Clicking `authentic-leader-action` opens
   `authentic-leader-choice-menu`.
4. The menu contains at least two `authentic-leader-choice-option` buttons with
   human-readable weather labels.
5. Choose a non-first option when possible, for example `Impenetrable Fog` or
   `Skellige Storm`.
6. The menu closes.
7. The chosen weather card appears in the weather zone or recent activity in a
   way that proves the selected option, not just the first legal option, was
   dispatched.
8. The leader action becomes disabled/used afterward.
9. Default visible page text still does not leak raw instance IDs or opponent
   hidden card data.

If the deterministic seed search is annoying, write a tiny local helper in the
test file that tries a small fixed seed list and picks the first page state with
at least two options. Keep it bounded and deterministic; do not introduce random
test behavior.

## Acceptance Criteria

- The authentic match UI no longer silently uses `leaderMoves[0]` when multiple
  legal leader moves exist.
- `play_any_weather` presents legal weather choices to the human player.
- Selecting a choice dispatches that exact legal move's `UseLeader` target.
- Existing single-action leaders still behave as direct actions.
- No engine rule, legal-move, command, AI, simulation, catalog promotion, deck
  builder, or Card Studio behavior changes.
- Hidden-info smoke still passes.
- Browser smoke covers a real `play_any_weather` match path.
- `docs/PROJECT_STATE.md` and the cEp8 report are updated.
