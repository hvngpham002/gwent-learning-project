# cFp36.1 Regression Review Decision Note

Date: 2026-05-18
Phase: cFp36.1
Scope: analysis only

## Decision

Do not continue tuning cFp36 constants directly. The repaired cFp36 resource
budget gate improved the narrow `round_one_overinvestment` signal, but it
introduced a broad pass-policy regression. The next behavior phase should be
`cFp37` Pass Decision Alignment / Resource Gate Scope-Down.

Recommended cFp37 direction:

1. keep the cFp36 diagnostics fields;
2. either make the cFp36 budget gate diagnostic-only or restrict it to cases
   where round-investment already recommends `preserve_future_hand` or
   `sacrifice_round`;
3. ensure single-move catch-up and last-gem fight branches override resource
   preservation unless the public upper bound cannot win the round;
4. rerun starter matrix and failure mining before touching weathered-row or
   Medic timing tuning.

## Interpretation

The regression is primarily caused by round-resource pass behavior interacting
badly with existing pass/catch-up logic. It is not primarily weathered-row
placement, Medic timing, Skellige-only skew, or failure-mining noise.

Evidence:

- Starter matrix lost 13 net wins while smoke stayed stable.
- `suspicious_pass` rose by 96, far more than any other finding kind.
- The target `round_one_overinvestment` finding improved by only 5.
- `round_three_low_resource` slightly worsened.
- 224 suspicious-pass findings are new after cFp36.
- 108 of those new suspicious passes occurred when round investment said
  `continue`.
- 116 occurred when round investment said `fight_last_gem`.

## Rejected Next Steps

- **Do not immediately tune weathered-row behavior.** It worsened by 4 findings,
  but this is smaller than the pass regression and can be misleading while
  round-resource pass priority is unstable.
- **Do not immediately tune Medic timing.** It worsened by 1 finding and is not
  the current bottleneck.
- **Do not blindly increase cFp36 resource budgets.** That might recover some
  wins, but it does not address pass-priority contradictions.
- **Do not start v2/search/ML yet.** The v1 deterministic baseline still has a
  basic policy-ordering problem that the benchmark stack can now isolate.

## cFp37 Spec Seed

cFp37 should be a behavior phase with a narrow acceptance target:

- no new pass when `roundInvestmentRecommendation === "continue"` unless a
  stronger, explicit pass reason is present;
- no resource-preservation pass when `recommendation === "fight_last_gem"` and
  `policyUpperBoundCanWinRound === true`;
- no resource-preservation pass when `hasSingleMoveCatchUp === true` unless the
  selected catch-up line would create a documented future-hand failure;
- keep or improve cFp35 starter matrix baseline, with cFp36 diagnostics
  retained;
- failure mining should show `suspicious_pass` no worse than cFp35's 222 or
  explain every intentionally retained pass through a narrower safe enum.
